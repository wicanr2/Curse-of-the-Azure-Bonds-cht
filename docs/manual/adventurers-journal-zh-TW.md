## 第 59 則地圖的可用證據

中文掃描 `084.jpg`／印刷頁 52 清楚保存完整地圖。可直接讀出的圖例為門、拱門與
神壇；地圖標出德克薩姆神殿、牛頭人、咕嚕聲或喊叫聲、兩處獸聲、出口與未知區。
這份證據比 OCR 完整，但仍是非比例手繪圖，不含原版 16×16 GEO 座標。

地圖可證明的相對關係包括：

- 德克薩姆神殿是有神壇的封閉房間，具有多個門口／通道連接。
- 牛頭人／喊叫聲區位於神殿另一側的分支區域。
- 兩處獸聲分屬不同房間群。
- 出口位於地圖外緣，前方有一扇普通門；出口不是單憑圖面就能判定的傳送門。
- 未知區與主通道間畫有門／拱門，但圖面沒有標示必須 `SEARCH` 或 `LOOK`。

因此本圖是 `layout-only` 的「意圖拓撲」證據。要把某條線對到 GEO 邊，仍須同時
比對 `GEO4.DAX` block `0x25` 的四向牆、`ECL4.DAX` block `0x22` 的 terrain／事件
座標，以及原版移動 consumer。

## 反組譯與 DOSBox 抽樣原則

手札地圖、GEO 與 ECL 足以成為正常路徑的主要證據；不要求在 DOSBox 從新遊戲一路
玩到後期。靜態證據達成以下閉環且只剩唯一解時，可以直接實作並以 remake 正常
玩家路徑驗收：

1. 手札圖上的房間、門與出口鄰接關係。
2. GEO 每格的 terrain、四向牆型與 detail。
3. ECL 對座標、傳送、事件旗標與出口的 producer／consumer。
4. 原版移動／搜尋 routine 對目標牆型的實際判定。

只有兩條以上候選路徑同樣符合、或互動動詞與持久副作用無法由靜態資料判定時，
才需要 DOSBox 抽樣。抽樣不從頭重玩，而採原版存檔副本或非破壞性存檔修改，把
隊伍放到候選邊前一格，依序記錄：

1. 進入前座標、朝向、牆型、相關旗標與存檔雜湊。
2. `MOVE`、`LOOK`、`SEARCH` 各一次的畫面與記憶體／存檔差異。
3. 穿越、事件完成、離開再進入及存檔重載後的結果。

抽樣只能確認這一條候選邊的原版行為，不能擴大成所有 `wall=09` 或全部秘密門的
通則。若靜態閉環已唯一，則不為了形式上的「實機玩到」額外消耗時間。

## 重製資料界線

- 每則手札應有 stable `message_id`、原始編號、來源頁與繁中內容。
- 遊戲觸發手札後，玩家可在遊戲內立即閱讀並於 Journal 畫面重讀。
- 手札提示不直接成為 Go 規則；座標、選項與事件條件留在 CoAB game pack／原始
  ECL，作品中立 engine 只提供解鎖、分頁與重讀機制。
- 手札地圖可另做 renderer 資產，但必須標明原始掃描來源與重建等級；不以合成圖
  冒充原版 bitmap。
