# 驗證報告：逐格內容盤點

- 日期：2026-08-20
- 範圍：以地形碼分派每格事件的地城 block，其中密斯卓諾三區與古熔岩洞逐格驗過
- 結論：**通過**。全遊戲 25 個 block 裡 **14 個**用地形碼分派每格事件，
  對照表由 `cmd/ecl-cell-events` 產生（`docs/audit/ecl-cell-events.md`，
  **234 個場景對到格子**）。本報告涵蓋密斯卓諾三區 41 格與古熔岩洞 11 格的
  逐格內容，每一格對到一個 game pack 訊息 id。
- 全遊戲一次跑完的逐格實測見
  [`seg-23-cell-sweep-report.md`](seg-23-cell-sweep-report.md)：那一份用
  `cmd/cell-sweep` 掃 13 個 block、194 個分派索引，判定「演不演得出來、是不是
  中文」；這裡的 52 格再往下一層，逐格對到 game pack 的訊息 id。

## 一、方法：從 bytecode 反推「哪一格演哪一場」

三個 block 的每格事件都是同一個形狀：

```
AND  C04F, 0x7F → 7F79        { C04F 就是那一格的地形碼 }
ON GOTO 7F79                   { 0 起算，每個索引一個處理常式 }
```

所以只要把 `ON GOTO` 的表拆開，再拿 GEO 的地形碼反查格子，就得到完整的
「格子 ↔ 場景」對照。`cmd/ecl-cell-events` 把這件事做成全遊戲一次跑完的產物。

⚠ **遮罩不是固定的**：目前量到 `0x7F` 與 `0x3F` 兩種。第一版寫死 `0x7F`，
25 個 block 只認出 5 個；改成從指令裡讀遮罩之後變成 14 個。
**把常數寫死會讓另一半安靜地變成「沒有每格事件」。**

⚠ 另外 5 個 block 走的是**第二種形狀**：`GETTABLE <表>, <索引>` ＋ `ON GOTO`
（位置查表）。那要先解出表的內容與索引怎麼算，本輪不做，工具會標出來。

**這比在地圖上走便宜太多**：墓園與外城都不是連通的一整片，走錯一步就被送回
世界地圖，而每次試探要重跑十幾秒的 session。

## 二、覆蓋

| 區 | block | 驗過的格 | 備註 |
|---|---|---:|---|
| 墓園 | `ECL6/0x40` | 15 | 盜墓者那一格由 `RANDOM` 擋著（100 抽 32），換種子重進段最多 24 次 |
| 外城遺跡 | `ECL6/0x42` | 11 ＋ 1 條前置劇情 | 藏匿處要先救垂死者拿線索（`4CD5`）再 `SEARCH`（`7ECA`）|

## 三、⚠ 逐格盤點必須每格重新進段

第一版把墓園的掃描塞進連續 session，結果**把內城的房間測試弄紅了**——
once-only 旗標與戰鬥結果會互相污染。拆成獨立測試（每格重新進段）之後才乾淨。

⇒ 內容盤點與連續 session 是兩件事：前者驗「演不演得出來」，
後者驗「走不走得到」。混在一起兩邊都會失真。

## 四、⚠ 盤點用的隊伍可以撐，段測試不行

外城的垂死者要打贏一群地獄犬才拿得到線索，臨時建的一名角色打不贏。
盤點那一條把隊伍撐起來（與 `-inner-final-battle` 的觀察用隊伍同一個作法），
並在測試裡寫明**只給盤點用**。

段測試不准這樣做：那會把「這一段打得贏嗎」偷偷換成「這一段演得出來嗎」。

## 五、明確不宣稱

- 沒有宣稱三區的**每一個**索引都驗過：沒有對應地形碼的索引（例如只有從別的
  處理常式跳進去的續段）不在清單裡。
- 沒有宣稱這些格子在連續 session 裡都走得到——那是段測試的事，目前只有紅網、
  黛米爾公主與內城那批走得到。
- 沒有宣稱每一格的**後續分支**都驗過；驗的是那一格的第一句敘述。
