# 驗證報告：全遊戲逐格實測

- 日期：2026-08-20
- 範圍：全部以地形碼分派每格事件的 block，逐個分派索引站上去跑一次生命週期
- 結論：**通過**。14 個 block、**250 個分派索引**逐格實測，**235 格演出中文、
  落回原文 0 格、15 格沒演出來且每一格都說得出守衛**。產出
  [`docs/audit/cell-sweep.md`](../audit/cell-sweep.md)，由 `cmd/cell-sweep` 產生。

## 一、為什麼要再做一份

`cmd/ecl-cell-events` 只讀 bytecode，回答的是「站上那一格會跳到哪支處理常式」。
它答不了「跳過去之後演不演得出來、演出來是不是中文」——而那一段落差正是中文化
會漏的地方：**處理常式接上了、文字沒接，對照表照樣是滿的**。

手工的逐格盤點（讀對照表、把索引對到 game pack 的訊息 id、寫一條
`Test…CellEventsAreLocalized`）四輪累計 52 格，還剩十個 block——每一輪重複的是
同一件事，只是換一張地圖。

`cmd/cell-sweep` 把它變成一次跑完：對每個索引直接進段、把隊伍放到那個地形碼的
第一格、跑一次地城生命週期，記下玩家真的看到的字。**全遊戲一輪 27 秒。**

## 三、朝向：`C04D` ＝ 朝向 ÷ 2

邊界那一圈的處理常式是這個形狀：

```
COMPARE C04D, <方向>
IF <>
EXIT
```

**要面對那個方向才演**，所以逐格掃描一定要帶朝向這個維度。

⚠ **刻度要從消費端讀，不要從直覺假設。** 遊戲的朝向是 **0..7**，`C04D` ＝
朝向 ÷ 2，所以掃 `{0,1,2,3}` 只蓋得到 `C04D` 的 0 與 1——「四個方向」是對的，
「0..3」是錯的。要蓋滿四面得掃 `{0, 2, 4, 6}`。猶拉什四個出城口是這條規則的
證人：朝向缺席時整批沒內容，刻度錯一半時南、西兩面照樣沒內容，而**落空的格子
和「這一格沒有內容」長得一模一樣**，沒有任何東西會報錯。

## 四、抓到的五句英文

逐格實測第一次跑就抓到 5 句沒接的原文，全在猶拉什（`ECL3/0x10`）：

| 索引 | 原作 | 補的訊息 id |
|---:|---|---|
| 11 | `SHAMBLING MOUNDS ATTEMPT TO DRAG A CLERICS BODY AWAY.` | `yulash.shambling-mounds-drag-cleric` |
| 37 | `A RED PLUME GUARD GROWLS, 'NOBODY'S GOING TO MAKE US GO BACK INTO THE PIT.` | `yulash.red-plume-pit-refusal` |
| 6 | `...CHECKPOINT MANNED BY RED PLUME GUARDS TO THE SOUTH` | `yulash.checkpoint-to-the-south` |
| 2、7 | `...CHECKPOINT MANNED BY RED PLUME GUARDS TO THE WEST` | `yulash.checkpoint-to-the-west` |

⚠ 檢查哨那三句是**加上朝向之後才出現的**：先前那三格根本沒演，所以沒有東西可以
落回原文。**盤點的維度不夠，缺口會以「沒有內容」的形式藏起來。**

前兩句走的是 `ENCOUNTER MENU`（`29h`）的旁白，落在 `Prompt` 那條路上，不是
`Message`。⚠ 原作的 `ENCOUNTER MENU` 帶三段不同距離的旁白，**remake 固定取第一段**
（`internal/ecl/runtime.go` 取運算元 9..11 的第一個非空字串）。那是既有的行為
差異，不在本輪範圍，記在這裡。

## 五、9 格沒演出來，每一格都有名字

工具會把處理常式在講話之前的判斷一起印出來（`internal/eclcells` 的 `Guards`），
所以「沒演出來」不再是一句沒有下文的話：

| 段 | 索引 | 守衛 | 判讀 |
|---|---:|---|---|
| `ECL4/0x20` | 7、14、19、20 | `COMPARE 4C01 01 / IF >= / EXIT` | `4C00` 區的旗標跨地圖污染（spec 1142）|
| `ECL6/0x43` | 12 | `COMPARE AND 4C06 00 4C07 00` | 同上 |
| `ECL6/0x43` | 19、20 | `COMPARE 4C0E 01 / IF <>` | 同上 |
| `ECL3/0x10` | 27 | `COMPARE 4BF0 04 / COMPARE 4BF1 05` | 章節與進度，要走到那一步才演 |
| `ECL3/0x10` | 39 | `PICTURE FF` | 這一格只換圖，不出字 |

**15 格裡 12 格指向同一個成因：spec 1142 的 `4C00` 區跨地圖污染。**
先前只知道它壓掉密斯卓諾內城的 5 間房，現在知道散提爾堡城區的闖空門、客棧、
法官辦公室也在同一條線上。這是實作那個 bank 的價值第一次被量出來。

## 六、`ECL4/0x25` 掃不到

註冊表宣告 `ECL4/0x25` 從 `0x50` 進入，而那個入口是魔法商店：進去之後是
事件 → 地點 → 世界地圖，到不了它自己那張地圖（`GEO4/0x25` 的莊園，43 個分派
索引）。remake 的眼魔洞穴走的是 game pack 事件重建，不是這個 block 的每格分派
——這正是 `docs/plan/mainline-segmented-verification.md` §七 記著的未解項
「幾何怎麼換成 `GEO4/0x25`」，本輪從另一個方向撞到同一件事。

工具對這種段落**整段記一次原因**，不是每一格重複同一句：40 行一樣的「跑不動」
會把「沒演出來」的數字灌爆，看起來像有 40 個內容缺口。

## 七、兩份對照表的關係

| | `docs/audit/ecl-cell-events.md` | `docs/audit/cell-sweep.md` |
|---|---|---|
| 怎麼來的 | 讀 bytecode，拆 `ON GOTO` 的表 | 跑 VM，站上去演一次 |
| 回答 | 哪一格會跳到哪支處理常式 | 跳過去之後演了什麼、是不是中文 |
| 「第一句」 | **依位址往後找的推測** | 執行結果 |

⚠ 兩者不一致時以逐格實測為準。處理常式開頭可能是個 `GOTO`，依位址往後找就會撈到
位址相鄰、執行上無關的另一支的台詞——`ECL4/0x20` 索引 18 就是這樣：對照表寫
「闖進民宅」，實際演的是酒館的「要喝點什麼？」。
