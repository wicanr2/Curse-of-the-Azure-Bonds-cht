# 驗證報告：分派器怎麼認才不會漏，以及第二種分派形狀

- 日期：2026-08-20
- 範圍：`internal/eclcells` 的每格事件分派器偵測、`GETTABLE` 查表分派的解讀
- 結論：**通過**。以「目的地運算元相同」配對之後，有每格事件的 block 從 14 個變成
  **16 個**（新增 5 個、移除 3 個誤判）；第二種分派形狀解讀完成，剩下的 3 個
  block 逐個知道索引取自哪一格。逐格實測跟著從 194 個索引變成 **250 個**，
  **235 格演出中文、落回原文 0 格**。

## 一、配對條件錯了會兩頭出錯

原本的偵測是「`AND C04F, <遮罩>` 之後**緊接兩條之內**的 `ON GOTO`」。這個條件同時
產生兩種錯：

**漏掉真的分派器。** 提爾佛頓下水道（`ECL2/0x03`）長這樣：

```
0x02D8  AND      0x3F, C04F → 4C05
0x02E1  DIVIDE   4C05, 8    → 7F79
0x02EA  GETTABLE 0x9C38, 7F3F → 7F7A
0x02F4  ON GOTO  4C05
```

中間隔了兩條，`ON GOTO` 就在第三條——整個 block 被判成「沒有每格事件」。
**而落空跟「這個 block 本來就沒有內容」長得一模一樣。**

**把不相干的兩條湊成一對。** `ECL3/0x15`、`ECL5/0x35`、`ECL6/0x45` 的
`AND C04F, 0x3F → 7F79` 後面確實緊接著 `ON GOTO`，但那個 `ON GOTO` 分派的是
**`4C08`**，跟地形碼無關。三個 block 因此掛著兩三筆假的「每格事件」。

⇒ 配對條件改成**「`ON GOTO` 分派的那一格，就是 `AND` 寫進去的那一格」**。

⚠ `ON GOTO` 是變長指令，`Command.Arity` 是 0，所以 `Instruction.Operands` **是空的**
——被分派的那一格只能從 payload 的原始位元組讀。第一版忘了這件事，偵測數字直接
變成 0。

## 二、一個 block 有好幾組，要挑哪一組

改用目的地配對之後又冒出第二個問題：同一格（多半是 `7F79`）會被好幾條
`AND C04F, <遮罩>` 寫過，也會有好幾個 `ON GOTO` 分派它。

- `& 0x80` 那種是「這一格特別嗎」的位元測試，`ON GOTO` 只有兩三個目的地；
- 每格事件的分派器是**把地形碼逐個列出來**的那一組，表有二三十筆。

判準：**先列所有 `ON GOTO`，取表最大的那一個**，再回頭找「在它之前、離它最近、
寫進同一格」的 `AND`——遮罩要取最近的那一條，否則會拿到別組的遮罩。

## 三、第二種分派形狀

3 個 block 不用地形碼分派，改成多一層查表：

```
GETTABLE <表>, <索引格> → <格子>
ON GOTO  <格子>
```

| 段 | 索引取自 | 用途 |
|---|---|---|
| `ECL1/0x50` | `4C9D` | 世界地圖：路段編號 → 14 個旅途場景 |
| `ECL1/0x51` | `4C9D` | 同上（另一半世界地圖）|
| `ECL4/0x23` | `7F7C` | 散提爾堡酒館 |

表在 block 自己的資料裡（`位址 − 0x8000`），一個索引一個位元組。`ECL1/0x50` 的表
開頭是 `0→0`、`1→1`、`2→0`、`3→13`、`4→0`、`5→6`…，14 個場景包括暗影隘口、
山壁、天空的黑影、蜥蜴人、火刀伏擊、半人馬。

⚠ **判準是「查到的值要落在 `ON GOTO` 的範圍內」**，不是表的大小。同一個 block 有
好幾組 `GETTABLE` ＋ `ON GOTO`，光比大小會挑到不相干的一對——第一版就挑錯了，
表的內容是 `0→80`、`1→81`、`2→82`…，值全部超出 14 個目的地的範圍卻沒有被擋下來。

⚠ 表**沒有宣告長度**。對照表只探測前 48 個索引，超出表尾的部分是相鄰資料。

## 四、涵蓋範圍的變化

| | 改之前 | 改之後 |
|---|---:|---:|
| 有地形碼分派的 block | 14 | **16** |
| 走查表分派的 block | 5（其中 2 個是誤判）| **3** |
| 兩者都沒有的 block | 6 | 6 |
| 對到格子的場景 | 234 | **299** |
| 逐格實測的索引 | 194 | **250** |
| 演出中文 | 185 | **235** |
| 落回原文 | 0 | **0** |

新進來的五個 block：提爾佛頓醒來那一段（`ECL2/0x01`）、下水道（`ECL2/0x03`）、
猶拉什兩個子區（`ECL3/0x11`、`ECL3/0x12`）、法師塔（`ECL5/0x33`）。
**五個 block 逐格掃過去沒有一句落回原文**，第一到第三章的段內文字接得比預期完整。

## 五、掃不到的兩個

`ECL4/0x25`（莊園）與 `ECL5/0x33`（法師塔）有分派表，但從註冊表宣告的入口進去
分別是魔法商店與塔前庭院，到不了它們那張地圖。要掃到得先決定 remake 怎麼進去。

## 六、剩下的

1. **spec 1142**：換 bank 的時機已經排除 `NEWECL` 與 `LOAD FILES`，剩下兩種可能
   要拿原版當 oracle。15 格沒演出來裡有 12 格是這一區。
2. `ECL1/0x50`／`0x51` 的 `4C9D` 是誰在寫、怎麼算出來的——旅途場景要接上得先答這個。
3. 記憶法術／物品的跨段驗證（`SEG-31` 後半）。
