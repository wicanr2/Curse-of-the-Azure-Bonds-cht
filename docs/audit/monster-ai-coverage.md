# 敵方 AI 的輸入齊不齊：原版怪物資料逐筆盤點

由 `cmd/monster-ai-coverage` 產生，不要手改。理由與讀法見該檔的註解。

量的是**決策層的輸入**，不是「AI 打得像不像」——後者要對照原版實機，這裡不宣稱。

| 項目 | 數量 |
|---|---:|
| 原版怪物記錄 | 81 |
| 士氣位元組有效（bit 7 已設）| 81 |
| 士氣位元組無效 | 0 |
| **身上帶記憶法術的怪物** | **0** |
| `MON*SPC` 特殊能力記錄 | 119 |
| 其中相異的效果碼 | 52 |
| **戰鬥規則會理的** | **7** |
| 原作那一支就沒動作（`inert`，碼／記錄）| 1／1 |
| 還沒解讀（`unread`，碼／記錄）| 35／81 |
| 修正表裡還沒有這個碼（碼／記錄）| 5／7 |
| **真的缺口**（原作有動作、remake 沒有；碼／記錄）| **4／6** |

⚠ 四者不能混在一起數。`inert` 是**原作自己什麼都沒做**——remake 也不做才是對的；`unread` 與「表裡還沒有這個碼」則是**不知道**，同樣不是已知缺口。把它們算進缺口會憑空生出一個永遠補不完的待辦。

## ★ 這一款遊戲裡，怪物的 AI 施法路徑**沒有資料可跑**

全部 81 隻怪物的記憶法術槽（角色記錄 `+33h..+6Ah`）**逐位元組都是 0**。
也就是說 `AIChooseSpell` 那條路（門檻掃描、每輪抽 3 個、士氣閘門，spec 835／836／1116）在 CoAB **一次都不會被觸發**——規則實作了，但這一款遊戲沒有用到它。

⚠ 這不是「AI 壞了」，也不是「規則白做了」：同一顆引擎要跑別的 Gold Box 遊戲，而那些遊戲的怪物是有法術清單的。這裡只是把**本作的分母**講清楚——拿 CoAB 當樣本去驗證施法 AI，會得到一個永遠全綠而且什麼都沒驗到的測試。

⇒ 本作的敵方行為分母落在 `MON*SPC` 的特殊能力上，不在法術清單上。

## 真的缺口：每一個卡在哪

這四個碼在修正表裡**有解出來的動作**，但 `AffectKindIsInterpreted` 仍然回 false。三個條件（列在某個 timing 裡、那個 timing remake 有查、它動的那一格 remake 有讀）少了哪一條，決定了要補的是什麼工。

| 效果碼 | 出現在 timing | 動什麼 | 卡在哪 |
|---:|---|---|---|
| `4Fh` | `02`／`03` | 設暫存全域 `damage_element` | 那些 timing **找不到任何呼叫端**（`checkfx-callsites.md`） |
| `50h` | `02` | 設暫存全域 `damage_element` | 那些 timing **找不到任何呼叫端**（`checkfx-callsites.md`） |
| `54h` | `06` | 寫 `player` 的第 420 格 | 那一格 remake 還沒對應到 `Fighter` 的欄位 |
| `7Bh` | `02` | 設暫存全域 `damage_element` | 那些 timing **找不到任何呼叫端**（`checkfx-callsites.md`） |

⇒ 四個都**卡在反組譯，不是卡在接線**。

⚠ 其中三個（`4Fh`／`50h`／`7Bh`）落在時機 `02h`／`03h` 上，而 `cmd/checkfx-callsites` 掃過 30 處呼叫點之後，**這兩個時機一處呼叫端都沒有**。如果它們真的不會被問到，那這三個就**不是缺口**——原作也不會跑到。

⚠⚠ 但**現在還不能這樣結論**：那一支只看得到兩種呼叫形狀，常駐執行檔那一側因為重定位掃不到。**先把常駐側排除掉，再決定這三個是缺口還是死碼**——直接當成缺口去實作，等於為一段原作永遠不會執行的路寫程式。
