# PC-98 音訊狀態格的存取盤點（誰決定「什麼時候該響」）

掃的這六個位址名字都由 Borland 除錯符號直接讀出來（DOS 版沒有符號），
但**它們不是同一種東西**：

| 位址 | 符號 | 是什麼 | 種類 |
|---|---|---|---|
| `8BE1h` | `MUSICNUM` | 驅動程式手上的曲目編號（`255` ＝ 沒有曲子）| 狀態 |
| `8BE3h` | `MUSICSW` | 音樂開關（`1` ＝ 玩家關掉了）| 狀態 |
| `8BF3h` | `MUSICNO` | 這個場景該放第幾首 | 狀態 |
| `4838h` | `SOUNDHALT` | `SOUNDFX` 的選擇子 `255`：停掉手上那個音效 | **常數** |
| `483Ah` | `SOUNDOFF` | `SOUNDFX` 的選擇子 `0` | **常數** |
| `483Ch` | `SOUNDON` | `SOUNDFX` 的選擇子 `1` | **常數** |

⚠ **下面三個是常數不是狀態**：它們和 `CASTFX`…`CRASHFX` 排在資料段同一張表裡，
值在檔案裡就寫死了，全程式一處都沒有寫入。所以那三行的**寫入**永遠是零，
而**讀取**才是有意義的那一欄——讀它們的地方就是 `SOUNDFX` 的呼叫點。
把「零次寫入」讀成「這件事原作沒做」會整個反過來（spec 1192）。

播放常式在程式碼段 2195：`SOUNDFX` `0000h`、`INITSOUND` `010Dh`、`MSCPLAY` `0114h`、`BGMPLAY` `0177h`。

★ **這是「什麼時候該響」的分母**：寫這幾格的地方，就是原作決定換曲／開關音效的地方。

⚠ **這是 PC-98 的版面。** DOS 版沒有除錯符號，對應的格子要另外認——不能直接套用位址。

⚠ 這是**分母不是覆蓋率**：它說原作在幾個地方改音訊狀態，不是 remake 對了幾處。
