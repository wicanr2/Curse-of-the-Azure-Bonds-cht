# TPOV overlay 控制表（DOS `START.EXE` → `GAME.OVR`）

由 `START.EXE` 的常駐控制記錄逐筆解出，**用鏈驗證過**：第 0 段的
`code offset` 是 `000004h`，之後每一段的 `code offset` 都等於前一段的
`code offset ＋ code size ＋ reloc size`，最後一段結束於 **`04275Ah`**
＝ `GAME.OVR` 的檔案大小，逐位元組吻合。

記錄版面（見 `~/.claude/knowledge-base/retro/borland-tpov-overlay-re.md`）：

```
+00  CD 3F           INT 3Fh（overlay manager 觸發）
+04  u32  file offset  指向 .OVR 內的 code 起點
+08  u16  code size
+0A  u16  relocation size
+0C  u16  entry count
+20  entry stub 表，每筆 5 bytes：CD 3F, handler_local_offset:u16le, flags:u8
     第 i 筆的 stub offset ＝ 20h ＋ i×5
```

IDA 位址與檔案位移的換算：**IDA linear ＝ 檔案位移 ＋ `0F826h`**（36/36 驗證）。

## 每一段的 entry stub 表

`stub offset` 是**跨模組 far call 的目標**（`9A <off:u16> <seg:u16>` 的 off），
`handler offset` 才是該段 code 內的位址。兩者不可互換——
用 code offset 去查 stub 會整片查不到。
