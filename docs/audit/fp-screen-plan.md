# First-person fidelity: which screens are worth comparing

Generated by `cmd/fp-screen-plan`; do not hand-edit. Rationale: spec 1185.

A first-person screen is determined by the wall layout inside the view, so two cells with the same wall neighbourhood render the same picture and comparing the second one proves nothing new. The denominator for renderer fidelity is therefore the number of **distinct wall signatures**, not cells times facings.

The signature covers rows 1..3 ahead by lateral -1..+1, three walls per cell (front, left, right), sampled with the original 16x16 wrap, recording only whether a wall is **present**.

Presence and tile are two independent axes, so they get two denominators. Geometry (where a wall is drawn, how the perspective converges) depends only on presence. Which tile that wall uses is `LOADWALLSET` plus the map declaration and does not depend on which cell you stand in, so its denominator is the set of distinct wall-type values.

An earlier version folded the wall-type value into the signature and got 15,693 "distinct" signatures out of 17,684 screens -- deduplication did almost nothing, because the type differs in nearly every cell. That number was honest and useless: mixing the two axes measures neither.

Caveats: this is the denominator for the **renderer**, not for content, and not for reachability -- a cell counts as standable when at least one side has no wall, which is not the same as the party being able to walk there. Comparing every signature would still not prove the first-person view is correct: sky colour, wall-tile selection and palette follow the map declaration and need their own comparison (spec 1134's black ceiling was exactly that).
