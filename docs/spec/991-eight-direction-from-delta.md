# 991 — 由兩點差值算八方向：全專案唯一用到浮點的地方

- 證據等級：`exact`（逐條讀完；四個 6-byte real 常數由暫存器立即值解碼）
- 作法見 spec 783

## `pc98 overlay-22:01247h`（149 條，`retf 8`）

DOS 側沒有對應函式（`aligned_diff` 判為單邊）。

```pascal
dx := arg_2 − arg_6;
dy := arg_4 − arg_0;

if (dx <> 0) and (dy <> 0) then begin
    r := Real(dy) / Real(dx);                 { 0A65h:0CBEh 轉實數、0CB0h 相除 }
    if dx > 0 then 方向 := 0 else 方向 := 4;   { 有號 }
    if      r <  −3.0   then 方向 += 4        { 0A65h:0CBAh 比較 }
    else if r <= −1/3   then 方向 += 3
    else if r <   1/3   then 方向 += 2
    else if r <=  3.0   then 方向 += 1;
    if 方向 > 7 then 方向 := 0;                { 有號；base 4 ＋ 4 ＝ 8 會繞回 }
end
else begin                                     { 軸向 }
    if (dx = 0) and (dy = 0) then { ⚠ 什麼都不做 }
    else if dx > 0 then 方向 := 2
    else if dx < 0 then 方向 := 6
    else if dy > 0 then 方向 := 0
    else if dy < 0 then 方向 := 4
    else                方向 := 0FFFFh;        { ⚠ 不可達 }
end;
結果 := 低位(方向);
```

## ★ 四個常數是 ±3 與 ±1/3

Turbo Pascal 的 6-byte real 在暫存器裡是 `ax:bx:dx`（低到高），
記憶體順序是「指數 byte ＋ 5 個尾數 byte（LSB→MSB）」，
最後一個尾數 byte 的最高位是符號。四個立即值解出來是：

| 呼叫點 | `cx` | `si` | `di` | 位元組 | 值 |
|---|---|---|---|---|---|
| `12B2h` | `0082h` | `0000h` | `C000h` | `82 00 00 00 00 C0` | **−3.0** |
| `12D5h` | `837Fh` | `4C2Fh` | `AAA6h` | `7F 83 2F 4C A6 AA` | **−1/3** |
| `12F9h` | `837Fh` | `4C2Fh` | `2AA6h` | `7F 83 2F 4C A6 2A` | **＋1/3** |
| `131Dh` | `0082h` | `0000h` | `4000h` | `82 00 00 00 00 40` | **＋3.0** |

（`82h` ＝ 130 ⇒ `2^(130−129)` ＝ 2，尾數 `1.5` ⇒ 3.0；
`7Fh` ＝ 127 ⇒ `2^−2` ＝ 0.25，尾數 ≈ 1.3333 ⇒ 0.3333。
第三與第四個只差最高位的符號位元。）

## ★★ 方向編碼：0 ＝ 上，順時針

把兩個分支代進去，**軸向與斜向的結果互相咬合**：

| 方向 | 條件（斜向） | 條件（軸向） |
|---|---|---|
| **0 上** | `dx>0` 且 `r>3`；或 `dx<0` 且 `r<−3` | `dx=0`、`dy>0` |
| **1 右上** | `dx>0` 且 `1/3<r≤3` | — |
| **2 右** | `dx>0` 且 `−1/3≤r<1/3` | `dx>0`、`dy=0` |
| **3 右下** | `dx>0` 且 `−3≤r≤−1/3` | — |
| **4 下** | `dx>0` 且 `r<−3`；或 `dx<0` 且 `r>3` | `dx=0`、`dy<0` |
| **5 左下** | `dx<0` 且 `1/3<r≤3` | — |
| **6 左** | `dx<0` 且 `−1/3≤r<1/3` | `dx<0`、`dy=0` |
| **7 左上** | `dx<0` 且 `−3≤r≤−1/3` | — |

軸向的四個結果（0／2／4／6）與斜向在同一條件下的極限值**完全一致**
（例如 `dy=0` 時 `r=0` 落在 `(−1/3, 1/3)`，`dx>0` ⇒ 2，與軸向分支給的 2 相同），
所以這個對應不是猜的，是兩條路各自算出同一個答案。

`dy > 0` 對應「上」⇒ **這個座標系的 y 軸向上為正**，
與螢幕列號（往下遞增）相反。remake 換算時要注意。

## ★ 這是全專案目前唯一用到浮點的函式

`0A65h:0CBEh`（整數轉實數）、`0CB0h`（實數相除）、`0CBAh`（實數比較）
是 Turbo Pascal 的 6-byte real 執行期。整個 CoAB 的其他計算都是整數。

**remake 不需要浮點**：所有邊界都可以改寫成整數比較
（`r < −3` ⟺ `dy < −3·dx`，`dx > 0` 時直接比；`dx < 0` 時不等號反向）。
⚠ 但要保留**開閉區間的差別**：`< −3`、`≤ −1/3`、`< 1/3`、`≤ 3`
是三個 `<` 加一個 `≤` 的混合，剛好落在邊界上（例如 `dy = 3·dx`）的向量
歸哪一格由此決定。

## ⚠ 兩個原版缺陷

1. **`dx = 0` 且 `dy = 0` 時回傳值從未指派。** 兩個零的情況在第一道判斷就
   跳到結尾，`var_D` 是堆疊殘值。呼叫端若可能傳同一個點，結果是亂數方向。
   這與 spec 694（力量索引）、spec 741 記的是同一類「沒有預設值」。
2. **`0FFFFh` 那一行不可達。** 走到那裡的前提是 `dx = 0` 且 `dy = 0`，
   但那個組合在函式開頭就被送去結尾了。**作者寫了防護，卻被前面的路徑擋掉**
   ——與 spec 927 記的 PC-98 `−1` fallback 死碼同一類。
