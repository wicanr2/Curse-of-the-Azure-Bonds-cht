# 878 — `Load3DMap`：`GEO<n>.dax`，1026 bytes 讀進 `DS:7206h`

- 證據等級：`exact`（兩平台各自逐條讀完）
- 作法見 spec 783

## `overlay-30:0133Ah`（DOS 125 條）↔ `overlay-30:01253h`（PC-98 105 條）

`retf 2` ＝ 一個 byte（編號）。三個字串**兩平台完全相同**：
`'GEO'`、`'.dax'`、`'Unable to load geo in Load3DMap.'`。

**錯誤訊息裡直接寫著原始函式名 `Load3DMap`**——這是少數不必靠形狀推的命名。

```pascal
Str(DS:5BEEh, 寬度 1, var 數字);              { DOS 才有 }
檔名 := 'GEO' ＋ 數字;
副檔 := '.dax';
<far 0636h:08DEh>(var 檔案, var 大小, 編號);

if 大小 <> 402h then begin                     { 402h ＝ 1026 }
    <far 0297h:0107h>();
    <far 0A54h:173Bh>(0, 'Unable to load geo in Load3DMap.', @DS:8DB2h);
    <far 0A54h:1673h>();
    <far 06EAh:010Dh>();
    <far 0297h:0107h>();
    <far 06EAh:0000h>();                       { 收場 }
end;

o := 2;                                        { 跳過 2 bytes 標頭 }
Move(檔案^[o],        遠指標(DS:7206h)^,        100h);  o := o + 100h;
Move(檔案^[o],        遠指標(DS:7206h)^[100h],  100h);  o := o + 100h;
Move(檔案^[o],        遠指標(DS:7206h)^[200h],  100h);  o := o + 100h;
Move(檔案^[o],        遠指標(DS:7206h)^[300h],  100h);

FreeMem(檔案, 大小);                           { 0A54h:0364h，DOS 才有 }
遠指標(DS:4F99h)^[18Ah] := 編號;               { 記住現在載的是幾號 }
```

## `402h` 這個常數把檔案格式夾出來

唯一被接受的大小是 `402h` ＝ **1026 ＝ 2 ＋ 4 × 256**：
**2 bytes 標頭 ＋ 1024 bytes 資料**。搬運寫成四次 `Move(…, 100h)`
而不是一次 `Move(…, 400h)`，所以資料端是**四塊各 256 bytes**。

`FreeMem(檔案, 大小)` 用 `大小` 當釋放長度，反過來確認 `大小` 就是
`0636h:08DEh` 回填的檔案位元組數。

`'GEO'` ＋ 一位數 ＋ `'.dax'` ——`.dax` 是 SSI 的封裝資料檔副檔名；
DOS 版的數字來自 `DS:5BEEh`（spec 874 同一格，形狀上是磁碟／資料片編號）。

## PC-98：三處不同

| | DOS | PC-98 |
|---|---|---|
| 檔名 | `'GEO'` ＋ `Str(DS:5BEEh)` | **不接數字**，只有 `'GEO'` |
| 收尾 | `FreeMem(檔案, 大小)` | **`mov al, 0` ＋ `out 0A6h, al`** |
| 堆疊框 | `110h` ＝ 272 | `14h` ＝ 20 |

不接磁碟編號與 spec 874 讀到的一致——**PC-98 的檔案位置固定，
DOS 要拼出資料片編號**；堆疊框差 252 bytes 正是那個長檔名緩衝。

收尾換成寫 I/O port `0A6h` 是 PC-98 的圖形硬體控制（DOS 沒有對應動作）；
PC-98 的載入器 `0723h:0824h` 與 DOS 的 `0636h:08DEh` 記憶體處理方式不同，
所以沒有 `FreeMem`。**本規格不宣稱 `0A6h` 那一筆寫的是什麼**。

## 中文化

`'GEO'`／`'.dax'` 是檔名，不能翻。
`'Unable to load geo in Load3DMap.'` **是開發期的錯誤訊息**——
PC-98 原樣保留沒有翻，中文版照樣保留即可（玩家正常遊玩看不到）。

## 明確不宣稱

- 沒有宣稱那 1024 bytes 的內部結構（只知道被切成四塊 256 bytes）。
- 沒有宣稱 2 bytes 標頭裝什麼。
- 沒有宣稱 `far 0636h:08DEh` 的三個參數怎麼對應（回填檔案指標與大小）。
- 沒有宣稱 `遠指標(DS:4F99h)^[18Ah]` 之外還有沒有別的快取。
