# 968 — PC-98 的表面配置：主資料與遮罩一起要，四個特例不配遮罩

- 證據等級：`exact`（逐條讀完，來源是 `PC98-GAME.EXE.asm`）
- 位置：`PC98-GAME.EXE` 的 `139DDh`
- 作法見 spec 783

## `139DDh`（179 行，far，`retf 0Ch`）

`(@表面 arg_0, 旗標 arg_4, 張數 arg_6, 寬 arg_8, 高 arg_A)`。
DOS 的對應是 spec 934 的 `145C9h`；釋放端是 spec 947 的 `13B55h`。

```pascal
每張   := 高 × 寬 × 3;                              { ★ 三個平面 }
主資料 := 張數 × 每張;
遮罩   := 張數 × 高 × 寬;                           { 一張遮罩三平面共用 }

{ ── ★ 四個「不配遮罩」的特例 ── }
if 寬 > 16h                                   then 遮罩 := 0
else if (寬 = 16h) and (高 = 30h) and odd(旗標) then 遮罩 := 0
else if (寬 = 16h) and (高 = 28h)              then 遮罩 := 0
else if (寬 = 6)  and (張數 > 1) and not odd(旗標) then 遮罩 := 0;

<sub_18233h>(主資料 ＋ 17h ＋ 遮罩, @表面);         { spec 965，一次要齊 }
FillChar(表面^, 主資料 ＋ 17h, 0);

表面^[0]   := 高;
表面^[2]   := 寬;
表面^[11h] := 每張;
表面^[8]   := 張數;
表面^[13h] := NIL;                                  { 遮罩指標先清空 }

if not odd(旗標) then 離開;                         { 旗標 bit 0 ＝ 要不要遮罩 }

if 遮罩 <> 0 then begin
    { ★ 遮罩就接在同一塊的後面 }
    Move(表面, 暫, 4);
    暫 := 暫 ＋ 17h ＋ 主資料;
    Move(暫, 表面^[13h], 4);
end else
    <sub_18233h>(張數 × 高 × 寬, @表面^[13h]);      { 另外配一塊 }

FillChar(表面^[13h]^, 張數 × 高 × 寬, 0);
```

## ★ 這關掉 spec 947 的疑問

spec 947 記到釋放端 `FreeMem(表面, 甲 ＋ 17h ＋ 乙)`，其中
`甲 ＝ 張數 × +11h`、`乙 ＝ 高 × 寬 × 張數`，並註明
「與 DOS 的配置算式不一致，不宣稱兩邊相同」。

本支給出答案：**PC-98 的配置本來就是 `主資料 ＋ 17h ＋ 遮罩` 一次要齊**，
遮罩指標 `+13h` 指進**同一塊的後段**（偏移 `17h ＋ 主資料`）。
所以釋放時要把兩段都算進去——**釋放端與配置端是一致的**，
不一致的是 DOS 版（spec 934 的 `GetMem(總量 ＋ 17h)` 另外配遮罩）。

spec 947 的「明確不宣稱」該項可以關閉。

## 四個特例的形狀

`遮罩 := 0` 的四種情況之後會走「另外配一塊」那條路，
所以**不是「不要遮罩」，是「遮罩不接在主資料後面」**。
四個條件都在特定的尺寸上（`寬 > 22`、`22×48`、`22×40`、`寬 = 6` 且多張），
形狀上是**幾種固定用途的圖庫**（人像、圖塊、字模之類）走不同的配置路徑。

## `+11h` 是三個平面的總和

`每張 := 高 × 寬 × 3` 寫進 `+11h`。spec 949／956 的貼圖用
`來源^[11h] × 張號` 取主資料、用 `高 × 寬 × 張號` 取遮罩——
**兩個 stride 差三倍，正是「主資料三平面、遮罩一份」**。

## ⚠ 訂正：`sub_1C15Dh` 是 `Move` 不是 `BlockRead`

本支的兩次呼叫是 `<sub_1C15Dh>(來源遠指標, 目的遠指標, 位元組數)`，
兩端都是**記憶體位址**（`@表面`、`@暫`、`@表面^[13h]`），
所以它是 **`Move`**。

> ★ **`Move` 與 `BlockRead` 的呼叫形狀很像，判別點是第一個參數**：
> 兩端都是記憶體位址就是 `Move`；第一個參數是檔案控制區才是 `BlockRead`。
> spec 965（`18233h`）與 spec 966（`18407h`）那兩處都是從已在記憶體裡的
> 標頭抄幾個 byte 出來，屬前者。

## 明確不宣稱

- 沒有宣稱四個特例對應哪幾種圖庫。
- 沒有宣稱旗標 bit 0 以外的位元。
- 沒有宣稱 `+4`、`+6`、`+9`..`+10h` 那幾格（本支填 0 之後沒再寫）。
