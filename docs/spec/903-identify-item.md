# 903 — 鑑定物品：200 金幣，先扣角色的錢、不夠才動公用池

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側差異逐條列出）
- 作法見 spec 783

## `overlay-19:02A42h`（DOS 193 條）↔ `overlay-19:02A32h`（PC-98 199 條）

`retf 8` ＝ 4 個 word：`(var 有沒有鑑定成功, 物品遠指標)`。

```pascal
成功 := 0;
<far 14F5h>(0, 0, 0, 0, 物品, 遠指標(DS:4AF4h));      { 取物品顯示名 }
訊息(報價句 ＋ 物品名);
<far 0542h:04A4h>(1, 0, 0Eh, 16h, 26h, 15h, 1);

if <far 16ABh+3>(追問, 0Fh, 0Ah, 0Dh) <> 'Y' then goto 收尾;

錢 := <本模組 33ABh>(遠指標(DS:6506h));               { longint }
if 錢 >= 0C8h then begin                              { ★ 200 }
    成功 := 1;
    <far 116Bh>(錢 − 0C8h);                           { 從角色身上扣 }
end else begin
    池 := <far 1175h>(@DS:6F70h);                     { 公用池的總值 }
    if 池 >= 0C8h then begin
        成功 := 1;
        <far 1170h>(池 − 0C8h);                       { 從公用池扣 }
    end else
        訊息(錢不夠);
end;

if 成功 then begin
    if 物品^[35h] = 0 then
        訊息(本來就沒有魔法 ＋ 物品名)
    else begin
        物品^[35h] := 0;                              { 標成已鑑定 }
        <far 14F5h>(…);                               { 重取顯示名 }
        訊息(鑑定結果 ＋ 物品名);
        有沒有鑑定成功^ := 1;
    end;
    <far 0542h:0B33h>();
end;
<far 1ECDh>(16h, 26h, 15h, 1);
```

## 付款順序：角色 → 公用池

`0C8h` ＝ **200 金幣**。先算角色身上的錢（`本模組 33ABh`，回 longint），
不夠才去算 `DS:6F70h` 起那七個公用池的總值（`far 1175h`，與 spec 812
的身價計算同一種換算）。**兩邊都不夠才失敗。**

`DS:6F70h` 是 spec 858／863 的七格公用池，`far 1170h` 是它的扣款端；
`far 116Bh` 是角色錢包的扣款端。兩支都收「扣完之後應該剩多少」，
不是收「要扣多少」——`錢 − 0C8h` 先算好再傳。

## `物品^[35h]` ＝ 未鑑定旗標

PC-98 是 `+5Dh`（spec 832 的 `+28h` 位移）。

- `≠ 0`：未鑑定。付完錢後**清成 0**，重取一次顯示名（名字會從
  「未知的劍」變成真名），並把 `有沒有鑑定成功^` 設 1。
- `＝ 0`：已經鑑定過（或本來就不是魔法物品），付完錢只印一句
  「這東西沒有魔法」，**`有沒有鑑定成功^` 不設**。

⚠ **`= 0` 那條路一樣會扣 200 金幣**——付了錢才知道沒有魔法。
兩平台一致，是刻意的設計還是疏漏，本規格不判斷。

## PC-98 多一次清 `+5Dh`

PC-98 在流程中多一處 `物品^[5Dh] := 0`，位置與 DOS 那一處不同，
另外多一次字串串接。本規格不宣稱那一次清除的用意。

## 明確不宣稱

- 沒有宣稱四句訊息的內容（見台帳）。
- 沒有宣稱 `本模組 33ABh`／`far 1175h`／`116Bh`／`1170h` 的完整簽章。
- 沒有宣稱 `遠指標(DS:4AF4h)` 是什麼（spec 901 同一格）。
