# 1048 — 清除矩形區域（PC-98 側）：三個圖形平面 ＋ 文字層，一欄 ＝ 16 像素

- 證據等級：`exact`（PC-98 常駐段 179 條逐條讀完，`objdump` 路線見 spec 1046）
- 作法見 spec 783；DOS 對側見 spec 1046

## `pc98 PC98-GAME.EXE:12095h`（`retf 8`，373 bytes）

原本待解讀。呼叫端五處（`119E0h`、`11D77h`、`11E7Ch`、`11F81h`、`1224Ah`）。
參數與 DOS 對側**完全相同**：

```pascal
procedure 清矩形(左: byte;   { bp+0Ch }
                 上: byte;   { bp+0Ah }
                 右: byte;   { bp+08h }
                 下: byte);  { bp+06h }
```

> ★ PC-98 常駐段的 `objdump` 換算：`file = ea − 10000h ＋ 2464`
> （PC-98 的 MZ 標頭是 2464 bytes）。`12095h → 2A35h`，
> 開頭 `55 89 e5` 對上。

## ★★ 三個圖形平面

```pascal
if 上 > 下 then exit;
for 列 := 上 to 下 do
    for 子列 := 0 to 7 do begin                    { ★ 每列 8 條掃描列 }
        位址 := (列 × 8 ＋ 子列) × 50h ＋ 左 × 2;
        長度 := (右 − 左 ＋ 1) × 2;
        FillChar(A800h:位址, 長度, 0);             { 藍 }
        FillChar(B000h:位址, 長度, 0);             { 紅 }
        FillChar(B800h:位址, 長度, 0);             { 綠 }
    end;
```

★ 每條掃描列 `50h` ＝ **80 bytes** ＝ **640 像素**。
★ 每個「欄」佔 **2 bytes ＝ 16 像素**。
★ **`E000h`（輝度平面）沒有被清** ——只清三個平面。

## ★★ 文字層另外清

```pascal
位址 := (列 × 50h ＋ 左 × 2) × 2;                  { ＝ 列 × 0A0h ＋ 左 × 4 }
長度 := (右 − 左 ＋ 1) × 4;
FillChar(A000h:位址, 長度, 0);                     { 字碼 }
FillChar(A200h:位址, 長度, …);                     { 屬性 }
```

★ 文字層一列 `0A0h` ＝ **160 bytes** ＝ 80 個文字格 × 2 bytes。
★ 一個「欄」佔 **4 bytes ＝ 2 個文字格**——與圖形側的「16 像素」對上
（PC-98 半形文字格是 8 像素寬）。

> ★★★ **一個「欄」在 PC-98 是 16 像素、在 DOS 是 8 像素（spec 1046）。**
> ⇒ **同一組 `(左, 上, 右, 下)` 參數，PC-98 蓋掉的寬度是 DOS 的兩倍**
> ——這正是 PC-98 版能直接放全形字、DOS 版不能的原因。
>
> ⚠ 圖形側每「列」只走 **8** 條掃描列，而 PC-98 640×400 的半形文字格是 8×16。
> 兩者對不上，本規格**不解釋**（可能是 640×200 模式，也可能「列」是半列）。

## 中文化

| | DOS（spec 1046） | PC-98 |
|---|---|---|
| 一欄 | 8 像素 | **16 像素** |
| 一列 | 4 條掃描列 × 2 bank ＝ 8 | 8 條掃描列 |
| 平面／bank | CGA 2 個／Tandy 4 個 | **3 個（藍紅綠）**，不含輝度 |
| 文字層 | 無（畫在圖形上） | **有**（`A000h`／`A200h`） |

★ **中文全形字在 PC-98 佔 1 欄 × 2 列，在 DOS 佔 2 欄 × 2 列。**
所有寫死的欄座標（spec 1044 的 `20h`／`24h`、spec 1037 的欄位）都要照這個比例換算。
