# 1076 — DOS 存檔載入：存檔槽是 `'A'`..`'J'`、第 5 塊比 PC-98 少 65 bytes、角色欄位邊界收窄到 `143h`..`14Dh`

- 證據等級：`exact`（DOS 側 580 條逐條讀完，無匯出破洞）
- 作法見 spec 783；PC-98 對側見 spec 1072

## `dos overlay-16:03748h`（`retf`，無參數）

原本待解讀。範圍 `3748h`..`3D37h`。這是 spec 1072 的 DOS 對側，
但**多了選單那一段**——PC-98 把選單拆到 spec 1069，DOS 寫在同一支裡。

## ★★★ 一、存檔槽是字母 `'A'` 到 `'J'`，共十格

```pascal
選項 := '';
for 字母 := 'A' to 'J' do
    if <0636:04FFh>(DS:5BF0h ＋ 'savgam' ＋ 字母 ＋ '.dat') then
        選項 := 選項 ＋ 字母 ＋ ' ';        { 上限 14h ＝ 20 }
if 選項 = '' then exit;
Delete(選項, Length(選項), 1);              {★ 砍掉結尾多出來的那個空白 }

repeat
    提示 := 'Load Which Game: ';
    鍵 := <overlay-26 entry#3>(提示, 選項, 0, 0, 0Fh, 0Ah, 0Dh);
until (鍵 in ['A'..'J']) and 檔案存在(…鍵…) or (鍵 = 0);
if 鍵 = 0 then exit;
```

★ 合法鍵是 32 bytes 的**集合常數 `CS:36F4h`**，位元展開後正好是 `['A'..'J']`
（byte 8 ＝ `FEh` → `41h`..`47h`、byte 9 ＝ `07h` → `48h`..`4Ah`）。
⚠ IDA 把它標成字串 `aHichGame+0Bh`——**遇到 `0A54:08D4h`（`@Set@MemberOf`）
的運算元一律當 32 bytes 位元集合讀**（spec 1075 同一個坑）。

> ★★★ **十個存檔槽的代號是 `'A'`..`'J'`，檔名是 `savgam<字母>.dat`。**
> 這一併關掉 spec 1072 的讀法：那裡 `0A65:075Fh` 收的是**字母**不是數字，
> 是 `Chr` 不是 `Str`（DOS 對應的 `0A54:074Fh` 在 spec 1075 已確認是字元轉字串）。

## ★★★ 二、存檔區塊：與 PC-98 同構，但第 5 塊少 65 bytes

| 順序 | DOS 長度 | DOS 目標 | PC-98（spec 1072） |
|---|---|---|---|
| 1 | 1 | `DS:5BEEh`（資料片編號） | `DS:8BF4h` |
| 2 | `800h` | bank 0 ＝ `DS:4F99h`^ | `DS:7F05h` |
| 3 | `800h` | bank 1 ＝ `DS:4F9Dh`^ | `DS:7F09h` |
| 4 | `400h` | `DS:4FA1h`^ | `DS:7F0Dh` |
| 5 | **`1E00h` ＝ 7680** | `DS:4FA5h`^ | **`1E41h` ＝ 7745** |
| 6 | 5 | `DS:720Fh` | `DS:0A2A9h` |
| 7 | 1 | `DS:4FBBh` | `DS:7F28h` |
| 8 | 1 | `DS:4FBAh` | `DS:7F27h` |
| 9..14 | 2 × 6 | `DS:7210h ＋ i × 4`、`DS:7212h ＋ i × 4`，i ＝ 1..3 | `DS:0A2AAh`／`0A2ACh` |
| 15 | 1 | 隊伍人數 | 同 |
| 16 | `148h` ＝ 328 | 角色檔名表（8 × 41） | 同 |

> ★★★ **DOS 存檔合計 13,149 bytes（`335Dh`），PC-98 是 13,214（`33AEh`）
> ——差 65 ＝ `41h`，全部落在第 5 塊。**
> 其餘十五塊長度一模一樣。
> ⇒ **兩平台的存檔檔案不能互換**，remake 要按平台分別處理第 5 塊。
> ⚠ 這 65 bytes 差在哪個欄位，本規格不宣稱。

## ★★★ 四、角色記錄的「差 1」邊界收窄到 `143h`..`14Dh`

兩平台的圖示載入都用 **`+0F7h`、`+126h`、`+143h` 這三個位移，一格不差**。

> ★★★ spec 1034 只把邊界收窄到「`11Ch` 相同、`14Dh`／`14Eh` 差 1」。
> 這裡兩平台在 **`143h`** 仍然相同 ⇒ **邊界落在 `143h` 與 `14Dh` 之間**。
> ⇒ spec 1037 記的整組圖示欄位（DOS `+141h`..`+14Ah`）在 PC-98 是**同樣的位移**，
> 不必 ＋1；spec 1072 那條「沒有把 `126h`／`143h` 對到 DOS」的保留可以撤掉。

## 五、角色檔的載入

```pascal
for i := 1 to 人數 do begin
    名稱 := <0636:0549h ＋ 0618h>(檔名表[i], '.');   { 切掉副檔名，上限 28h }
    if <0636:04FFh>(DS:5BF0h ＋ 名稱 ＋ '.sav') then begin
        GetMem(角色, 1A6h);                          { 0A54:0329h，422 }
        <overlay-16:0228Eh>(名稱 ＋ '.sav', @角色, 1, 1);   { spec 1038 }
        <near 35A8h>(角色);                          { 掛進隊伍 }
    end;
end;
```

★ 檔名表的筆距一樣是 `29h` ＝ 41 bytes（`string[40]`），一樣 8 筆。
★ 一樣先 `DS:7584h := 0`（現行格式）再進門。

> ★★★ **這關掉 spec 1075 留下的 `.sav` 疑問，也修正 spec 1043 的讀法**：
> 存檔裡的隊伍成員**兩平台都存成 `.sav`，內容是現行長度的角色記錄**
> （DOS 422／PC-98 423），因為 `DS:7584h` 一律先設 0。
> ⇒ **副檔名不是格式判斷依據，`DS:7584h` 才是。**
> spec 1043 那張「副檔名 → 記錄長度」的表只在**匯入舊角色的掃描路徑**
> （`DS:0A816h` 類別）成立，不能套到存讀檔路徑。
> ⚠ 同一個 `.sav` 被兩條路徑當成兩種東西，這是原作設計上的重疊；
> 本規格不宣稱掃描路徑遇到存檔產生的 `.sav` 會怎樣。
