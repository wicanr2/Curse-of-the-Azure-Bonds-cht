# 1049 — 平面式點陣圖的矩形填色：先裁切，再逐平面依遮罩填 `0FFh`／`0`

- 證據等級：`exact`（PC-98 常駐段 224 條逐條讀完，`objdump` 路線見 spec 1046／1048）
- 作法見 spec 783

## `pc98 PC98-GAME.EXE:13BF4h`（`retf 12h`，542 bytes）

原本待解讀。**唯一的呼叫端是 `10000h`（程式進入點所在那一段）**。

`retf 12h` ＝ 18 bytes，對七個參數（宣告序 ＝ 由高位移到低）：

| `bp` | 內容 |
|---|---|
| `+16h` | 位移量（word，**有號**） |
| `+14h` | 另一個位移量（word，有號） |
| `+12h` | 寬度／範圍（word） |
| `+10h` | 高度／範圍（word） |
| `+0Eh` | **平面遮罩**（byte） |
| `+0Ah` | 遠指標（先被 `Move(…, 8)` 複製 8 bytes 出來） |
| `+06h` | **圖片記錄**的遠指標 |

`bp+06h` 為 NIL（兩個 word 或起來 ＝ 0）就直接離開。

## ★★ 裁切：正負位移分兩邊夾

```pascal
位移 := 位移 × 2;                                { bp+16h 先乘 2 }
if 位移 < 0 then begin 前裁 := abs(位移); 起點 := 0 end
            else begin 前裁 := 0;         起點 := 位移 end;
if 圖^[2] < 範圍 ＋ 位移 then 後裁 := (範圍 ＋ 位移) − 圖^[2]
                        else 後裁 := 0;
可填寬 := 範圍 − 前裁 − 後裁;
```

★ 同一套（正負分支 ＋ 與上界相減）在另一個軸（`bp+14h`）再做一次。
★★ `bp+16h` **先乘 2** ——與 spec 1048 的「一欄 ＝ 2 bytes」對得上：
呼叫端給的是**欄**，這裡換成 bytes。

## ★★★ 平面遮罩：一個 byte 決定四個平面各填什麼

```pascal
FillChar(填值[0..3], 4, 0);
for 平面 := 0 to 3 do
    if (byte[481Ch ＋ 平面] and 遮罩) <> 0 then 填值[平面] := 0FFh;
```

★ `DS:481Ch` 是一張**每個平面一個位元遮罩**的小表；
與參數 `bp+0Eh` 逐平面 `and`，中的就整條列填 `0FFh`，沒中的填 `0`。
> ★★★ **這就是「用一個 byte 指定 16 色其中一色」的作法**——
> 四個平面各填滿或清空，組出 0..15 的顏色。

## ★★ 圖片記錄的版面

```pascal
for 平面 := 0 to 3 do
    for 列 := 0 to 可填高 do
        FillChar(圖^[17h ＋ 平面 × 圖^[0] × 圖^[2] ＋ 列 × 圖^[2] ＋ 起點 ＋ …],
                 可填寬, 填值[平面]);
```

| 位移 | 內容 |
|---|---|
| `+0`（word） | **高（列數）** |
| `+2`（word） | **每列 bytes** |
| `+17h` 起 | 像素資料，**平面間距 ＝ 高 × 每列 bytes** |

★ `+17h` ＝ **23 bytes 的表頭**。
⚠ spec 1029 讀載入端時記的是 `+11h`（每張的 bytes），那是另一個欄位；
本規格只宣稱這一支用到的 `+0`／`+2`／`+17h`。

## 中文化

本支沒有字串。★ 但它決定了**背景色塊的畫法**：
中文化若要加寬對話框，寬度參數是**欄**（`× 2` 之後才是 bytes），
與 spec 1048 的欄／像素換算同一套。

## 明確不宣稱

- 沒有宣稱 `bp+0Ah` 那個遠指標（被複製 8 bytes 出來）是什麼。
- 沒有宣稱 `DS:481Ch` 那張平面遮罩表的實際位元值（只確定是「每平面一個 byte」）。
- 沒有宣稱 `+10h`／`+12h` 哪一個是寬、哪一個是高（兩軸的算式對稱）。
- 沒有宣稱圖片記錄 `+4`..`+16h` 那 19 bytes 是什麼。
- 沒有宣稱唯一呼叫端 `10000h` 在什麼時機叫它。
