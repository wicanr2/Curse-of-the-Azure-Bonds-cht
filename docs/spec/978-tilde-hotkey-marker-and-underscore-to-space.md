# 978 — DOS 用「大小寫」標熱鍵，`'~'` 是標記符；PC-98 因為日文改走另一條路

- 證據等級：`exact`（兩支逐條讀完；集合與字串常數由原始 bytes 讀出；
  `08D4h` 的旗標極性沿用 spec 698 已定案的結論）
- 作法見 spec 783

## `dos overlay-07:016D3h`（98 條，`retf 8`）— 把 ECL 文字轉成「本文 ＋ 熱鍵表」

⚠ IDA 把兩個參數印成 `arg_2`（`bp+6`）與 `arg_6`（`bp+0Ah`），同一支裡又印成
`[bp+6]`／`[bp+0Ah]`。原始 bytes（`C4 7E 06` 與 `C4 7E 0A`）證明**只有兩個遠指標**，
`retf 8` 也對得上。以下用 `輸出`（`bp+6`）與 `文字`（`bp+0Ah`）稱呼。

```pascal
輸出^ := '';
for i := 1 to 長度(文字^) do begin
    if 文字^[i] in ['0'..'9', 'A'..'Z'] then          { 集合在 CS:16B3h }
        文字^[i] := Chr(Ord(文字^[i]) + 20h);          { ★ 轉成小寫 }
    if 文字^[i] = '~' then begin
        Delete(文字^, i, 1);                           { 0A54h:07D0h }
        文字^[i] := UpCase(文字^[i]);                  { 0A54h:1C62h }
        輸出^ := (輸出^ ＋ Chr(文字^[i])) 上限 28h;    { 074Fh ＋ 634h ＋ 6C1h ＋ 64Eh }
    end;
end;
```

集合 `CS:16B3h` 逐 byte 讀出來與 `overlay-26:000D5h` 的 `CS:00B5h`
**完全相同**：`'0'..'9'` 加 `'A'..'Z'`。

`0A54h:08D4h` 的極性由 spec 698 定案：**`ZF = 1` ＝ 不在集合裡**，
所以 `jz` 跳走的是非英數字，`+20h` 只落在英數字上。

### 這一支做的三件事

1. **一般英數字全部 ＋20h**（`'A'..'Z'` → `'a'..'z'`；`'0'..'9'` → `'P'..'Y'`）。
2. **`'~'` 被刪掉**，它後面那個字元**轉成大寫**留在原地。
3. **被標記的那些字元依序收進 `輸出^`**，上限 40 個。

所以 `'~Yes  ~No'` 進去，出來的是本文 `'Yes  No'`（`Y` 與 `N` 大寫、其餘小寫）
與熱鍵表 `'YN'`。

⚠ **數字被 ＋20h 之後變成 `'P'..'Y'`**，不是「小寫數字」。這一格看得出作者
把集合寫成「英數字」但運算只對字母有意義。remake 若照抄要注意
`'~1'` 這種寫法：`'1'` 會先變成 `'Q'`，再被 `UpCase` 保持 `'Q'`——
**數字熱鍵在這條路上會壞掉**。本規格不宣稱原版有沒有用過數字熱鍵。

### 為什麼大小寫是可行的標記

這個引擎的字型只有 **64 個字模**，取字模時做 `UpCase(c) mod 40h`
（既有結論）——**`'a'` 與 `'A'` 畫出來是同一個字**。
所以大小寫不影響字形，只被拿來當「這一格是熱鍵」的旗標。

`overlay-26:000D5h`（spec 977）掃的正是同一個集合：
在一條 ≤40 字的選項行裡，**大寫英數字的位置就是每一項的起點**，
下一個大寫字前兩格是該項的終點。兩支對得起來：
**16D3h 產生標記，000D5h 讀標記。**

## ⚠ 更正 spec 977 的一段推測

spec 977 當時假設 `000D5h` 的輸入是 spec 975 的熱鍵字串 `DS:11A6h`，
因而寫了「原版字串裡有 `'CPH'` 相鄰、會產生 `迄 < 起` 的空區間」。
**那個假設不成立**：`000D5h` 吃的是**選項行本身**，行內只有熱鍵字母是大寫，
其餘是小寫，天生就隔得開。該段已改寫。

`DS:11A6h` 那條「單一字母被空白隔開」的熱鍵字串是 **PC-98 才有的機制**（見下）。

## ★ 兩平台的熱鍵機制完全不同

| | DOS | PC-98 |
|---|---|---|
| 熱鍵怎麼標 | **選項文字裡把該字母寫成大寫**（`'~'` 在 ECL 原文裡標，`16D3h` 轉換） | **另外一條熱鍵字串**（`DS:11A6h` → `DS:0A335h`，每格一個字元） |
| 項目範圍 | 由選項行掃大寫字母算出（`000D5h`） | 由十格環狀表的 `+4`／`+5` 前後鏈給（spec 972） |
| 空白格 | 沒有這個概念 | 熱鍵字元是空白 ＝ 該格不可選（spec 975） |

原因很直接：**PC-98 的選項文字是日文，沒有可以拿來當標記的大小寫**。
`'   はい                       いいえ    '` 這一行裡一個 Latin 字母都沒有，
DOS 那套機制在上面完全失效，所以 PC-98 另外拉了一條平行的熱鍵字串。

### 中文化的結論

**跟 PC-98 走。** 中文選項行同樣沒有大小寫可用，DOS 那套「大寫標記」
在中文化之後一定失效。要嘛沿用 PC-98 的平行熱鍵字串，要嘛在遊戲外
另外維護一份「項目 → 熱鍵 ＋ 欄位範圍」的表。
**不能只把英文選項行翻成中文而不動熱鍵機制**——翻完之後
`000D5h` 會掃不到任何大寫字母，項數變成 1，整個選單的欄位範圍全錯。

## `pc98 overlay-16:00079h`（93 條，`retf 4`）— 底線換成空白

`retf 4` 只彈掉輸入字串；**`bp+0Ah` 的 `@結果` 留在堆疊上給呼叫端**——
這是 Turbo Pascal「回傳字串的函式」的標準寫法，與 spec 916 的
build-string 同一個慣例。

```pascal
限長(輸入^, s, 0FFh);
結果 := '';
for i := 1 to 長度(s) do
    if s[i] = '_' then 結果 := 結果 ＋ CS:0077h        { 常數，長度 1，內容是半形空白 }
    else                結果 := 結果 ＋ Chr(s[i]);      { 0A65h:075Fh }
限長(結果, 輸出^, 0FFh);
```

`CS:0077h` 逐 byte 讀出來是 **長度 1、內容 `' '`**。所以整支就是
**把 `'_'` 全部換成半形空白**——存檔名之類「檔名不能有空白」的欄位，
顯示時再換回來。

⚠ **迴圈計數器用的是全域 `DS:0A9D9h`，不是區域變數 ⇒ 這一支不可重入。**
`pc98 overlay-29:0045Ah`（spec 760）用的是同一個全域，同樣不可重入——
**這個全域被當成通用的迴圈計數器重複使用**，remake 不能照抄成全域。

### 中文化

`'_' → ' '` 是**逐 byte** 的替換，沒有 DBCS 意識。Shift-JIS 或 Big5 的
**第二個 byte 可能正好是 `5Fh`（`'_'`）**——Big5 的第二 byte 範圍
`40h..7Eh` 與 `A1h..FEh` **確實涵蓋 `5Fh`**，所以中文名字經過這一支會被
從中間切壞。這是 spec 945／948／952／953 那一批 DBCS 呼叫點之外
**又一個必須加 DBCS 判斷的地方**。

## 明確不宣稱

- 沒有宣稱 `dos overlay-07:016D3h` 的呼叫端是誰，也沒有宣稱它的輸出實際上
  是不是拿去餵 `overlay-26:000D5h`（兩支用同一個集合、同一個 40 上限，
  但沒有讀到直接的呼叫鏈）。
- 沒有宣稱大寫字母在畫面上換成什麼顏色（只確定字形相同）。
- 沒有宣稱 `pc98 overlay-16:00079h` 的呼叫端與 `'_'` 出現在哪一種欄位。
