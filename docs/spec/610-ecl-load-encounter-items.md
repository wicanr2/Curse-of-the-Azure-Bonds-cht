## 物品節點的欄位

`0Bh`／`1Ch`／`32h`／`40h` 只用到 `+52h`（next）與 `+56h`（類型）；這一支是
**填寫端**，所以看得到更多：

| 偏移 | 寬度 | 備註 |
|---|---|---|
| `+0` | byte | 一律填 0 |
| `+51h` | byte | |
| `+52h` | far ptr | **next**，新建時填 nil |
| `+56h` | byte | **類型 id** |
| `+57h` | 3 bytes | `Move` 進來 |
| `+5Ah`..`+5Eh` | byte ×5 | 逐個填 |
| `+5Fh` | word | |
| `+61h` | byte | |
| `+62h` | word | |

節點總長 `67h`＝103 bytes（[spec 596](596-ecl-party-item-sweep.md)），
所以 `+63h`..`+66h` 之後還有欄位，`+1h`..`+50h` 這一段這裡也沒碰。

## 顯示符號對應表

```text
case 值 of
    5..7:    符號 := 23h  '#'
    8:       符號 := 22h  '"'
    9:       符號 := 25h  '%'
    0Ah:     符號 := 26h  '&'
    5Bh..5Eh: 符號 := 49h  'I'
    …
```

**這些是 ASCII 可列印字元**，形狀是地圖或清單上的顯示符號。用範圍比較
（`5..7`、`5Bh..5Eh`）而不是逐值列舉。

## 鏈空／非空兩段完全相同

`DS:A026h` 為 nil 與非 nil 各有一段填欄位的程式碼，**內容逐條相同**——編譯器
沒有把它合併。讀的時候容易誤以為是兩種不同的節點。
