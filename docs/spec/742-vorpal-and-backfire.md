# 第七百四十二輪：即死武器，與會反噬施法者的加倍傷害

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：DOS `overlay-12` 的 `299Ch`、`2CD9h`（兩支都沒有位元組缺口）。

## `299Ch`：特定武器直接讓目標進入狀態 8

```text
r := NIL
if <overlay-24 entry#43>(DS:6506h, @r) <> 0
   且 r^[2Eh] = 1Ch                      ← ⚠ 這裡已經解參照了
   且 r <> NIL                            ← ⚠ 檢查在後面
   且 r^[31h] = 87h then
    目標^[195h] := 8                      ← 狀態 8
    目標^[196h] := 0
    目標^[1A4h] := 0                      ← HP 歸零
    <overlay-23 entry#14>(目標)
    <overlay-23 entry#4>(目標, 0Dh)
    if 目標^[196h] = 0 then
        <overlay-32 entry#20>(目標)
```

**`NIL` 檢查排在解參照之後**，順序反了。這是第三處同型（spec 720 龍息、
spec 723 吐酸），成因都一樣：先把指標拿去用，才想起要驗。實務上不會當掉
（讀中斷向量表），但那次比較的輸入是垃圾。

條件是「物品類別 `1Ch` **且** `+31h = 87h`」——**兩個欄位都要對**，
單看類別會誤判。

狀態 `8` 是本專案目前看到的最大狀態值（先前有 0／1／4／5／6）。HP 直接歸零、
`+196h` 清 0，然後才呼叫 `entry#14`／`entry#4`——**不擲任何骰**。

最後那個 `目標^[196h] = 0` 的判斷用的是**剛剛被自己清成 0 的欄位**，除非
`entry#14` 或 `entry#4` 會改它，否則永遠成立。

## `2CD9h`：相鄰時傷害加倍，但打的是自己

```text
if <overlay-24 entry#33>(arg_6, DS:6506h) < 2 then      ← 距離 < 2（spec 720：相鄰）
    舊傷害 := DS:6F94h
    DS:6F94h := DS:6F94h × 2                             ← shl 1，byte
    舊型別 := DS:6F95h
    DS:6F95h := 8
    <overlay-24 entry#20>(DS:6506h, '<名字> gets zapped'（CS:2CCDh）, 0Ah, 1)
    <overlay-23 entry#20>(DS:6506h, DS:6F94h, 0, 0)      ← ⚠ 目標是 DS:6506h
    DS:6F94h := 舊傷害                                    ← 還原
    DS:6F95h := 舊型別
```

`entry#20` 的第一個參數是 `DS:6506h`——**攻擊者自己**。加上訊息 `gets zapped`，
這是近身時的反噬（觸碰型防護法術之類）。

`shl ax, 1` 之後只存回一個 byte：**傷害超過 127 就回捲**。這是繼 spec 705／739
之後第三個 byte 溢位點，但方向不同（那兩個是門檻，這個是傷害本身）。

**兩個全域都有備份與還原**，而 spec 738 的 `27FAh` 設完 `DS:6F95h` 就不還原。
同一個模組裡兩種做法並存，改寫時不能統一。

## 明確不宣稱

- 狀態 `8`、物品類別 `1Ch`、`+31h = 87h`、傷害型別 `8` 各代表什麼。
- `overlay-23 entry#14`、`overlay-32 entry#20` 的行為。
- `2CD9h` 的 `arg_6`／`arg_8` 是誰（傳給 `entry#33` 當距離的另一端）。
