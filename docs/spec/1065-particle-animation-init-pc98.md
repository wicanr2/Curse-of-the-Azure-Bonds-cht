# 1065 — 粒子動畫初始化（PC-98 側）：只有一套顏色，CGA 分支整段不存在

- 證據等級：`exact`（PC-98 側 343 條逐條讀完）
- 作法見 spec 783；DOS 對側見 spec 1064，動畫每一幀見 spec 1025

## `pc98 overlay-18:00026h`（`retf`）

原本待解讀。

## ★★ 與 DOS 的唯一實質差異：沒有 CGA 那一套

```pascal
DS:7BA8h := 0;
FillChar(DS:7BA9h, 0Fh, 1);
for 列 := 1 to 3 do begin                            { ⚠ 沒有 DS:4FE6h 的判斷 }
    if 輸入色[列] > 1 then byte[7BA4h ＋ 列 × 5] := 0Fh;
    byte[7BA5h ＋ 列 × 5] := 0Fh;
    if 輸入色[列] > 1 then byte[7BA6h ＋ 列 × 5] := 輸入色[列] ＋ 8;
    byte[7BA7h ＋ 列 × 5] := 輸入色[列];
    byte[7BA8h ＋ 列 × 5] := 1;
end;
DS:7BA8h := max(DS:7BA8h, Random(14h) ＋ 19h);
```

> ★★ **`7BA4h`..`7BA8h ＋ 列 × 5` 正好是 spec 1025 記的
> PC-98 顏色斜坡表 `DS:7BA3h`（色階 `1`..`5`）。**
> ⇒ spec 1064 在 DOS 側關掉的那個未定項，PC-98 側同樣成立。
>
> ★★★ **PC-98 完全沒有 `DS:4FE6h`（顯示卡種類）的判斷**——
> 走的就是 DOS 的「非 CGA」那一套（`0Fh` → `輸入色 ＋ 8` → `輸入色` → `1`）。
> DOS 382 條 vs PC-98 343 條，**差的 39 條幾乎全是 CGA 分支**。

## 其餘差異全是 RTL 位址

逐條比對（把資料段位址與 RTL 段號正規化之後）只剩 123 行差異，
全部是常式位址的平移：

| DOS | PC-98 | ＝ |
|---|---|---|
| `0A54:1105h` | `0A65:1155h` | `Random`（整數） |
| `0A54:111Bh` | `0A65:116Bh` | 浮點亂數 |
| `0A54:0C5Ah` | `0A65:0CAAh` | 浮點運算（＋`50h`） |
| `0A54:0D7Eh` | `0A65:0DCEh` | 浮點運算（＋`50h`） |
| `0A54:0C72h`／`0C6Eh`／`0D91h` | `0A65:0CC2h`／`0CBEh`／`0DE1h` | 同上（＋`50h`） |

★ **PC-98 的 RTL 浮點常式一律是 DOS 的位址 ＋ `50h`**
——同一份 Turbo Pascal RTL，只是連結位置差 80 bytes。

## 明確不宣稱

- 沒有宣稱那個 6-byte real 常數的數值（同 spec 1064）。
- 沒有宣稱 `DS:7BA9h` 起那 15 bytes 的用途。
- 沒有宣稱 `DS:7BA8h` 一格兩用（顏色格 ＋ 幀數上限）是不是原作疏漏。
