# 1081 — PC-98 戰術地圖彈道動畫：只多了一段入口夾值，其餘與 DOS 逐條相同

- 證據等級：`exact`（DOS 側 586 條已由 spec 1078 逐條讀完；PC-98 側 617 條，
  頭尾逐條讀完 ＋ **助憶碼序列比對**顯示只有一處差異 ＋ 全部運算元逐一核對）
- 作法見 spec 783；DOS 對側見 spec 1078

## `pc98 overlay-24:01CC3h`（`retf 0Ch`）

原本待解讀。範圍 `1CC3h`..`2407h`。

兩支的助憶碼序列比對結果：**586 對 617，相似度 0.9742，只有一個差異塊**
——PC-98 在函式開頭多了 **31 條**（`1CC3h`..`1D28h`），其餘 586 條**一一對應**。

## ★★ 唯一的差異：PC-98 進門就把四個座標夾進地圖範圍

```pascal
if 起點x < 0    then 起點x := 0;
if 起點x > 31h  then 起點x := 31h;      { 49 }
if 終點x < 0    then 終點x := 0;
if 終點x > 31h  then 終點x := 31h;
if 起點y < 0    then 起點y := 0;
if 起點y > 18h  then 起點y := 18h;      { 24 }
if 終點y < 0    then 終點y := 0;
if 終點y > 18h  then 終點y := 18h;
if 延遲 = 0     then 延遲 := 1;          { ★ 最少等一格 }
```

> ★★ **DOS 完全沒有這一段**。
> ⇒ DOS 版把越界座標直接丟進 Bresenham；PC-98 先夾好。
> ★★★ 更關鍵的是最後一行：**PC-98 把「延遲 0」改成 1**，
> 而 spec 1078 記的 DOS 行為是「延遲 ＝ 0 時只畫不落在格心的中間點、
> 終點的精靈不會被擦掉」——**那條路在 PC-98 執行不到**。
> ⇒ 兩平台的快速模式行為不同，remake 要按平台分開。

## 全域與資料表對照

| | DOS（spec 1078） | PC-98 |
|---|---|---|
| 視窗原點記錄 | `DS:6E92h`^（`+2` x、`+3` y） | `DS:9F2Ch`^（同樣 `+2`／`+3`） |
| 方向 → Δx ／ Δy | `DS:2694h` ／ `DS:269Dh` | `DS:489Eh` ／ `DS:48A7h` |
| 目的畫布 | `DS:4FE8h` | **`DS:7F56h`** |
| 精靈來源 | `DS:75E0h` | `DS:0A872h` |
| 擦除來源 | `DS:4FECh` | **`DS:7F5Ah`** |
| 貼圖 ／ 送畫面 ／ 延遲 | `0297:09E4h` ／ `0297:1316h` ／ `09AB:029Eh` | `02A8:077Dh` ／ `02A8:0B7Dh` ／ `08EE:0379h` |
| `Sign` ／ 直線初始 ／ 直線下一步 | `overlay-31 entry#1／#2／#3` | **同樣三個 entry** |
| 可見判定 ／ 捲動 | `overlay-32 entry#11／#13` | **同樣兩個 entry** |
| 邊界 | `12h`（視窗）／`31h`／`18h`（地圖） | **完全相同** |

> ★★★ **`DS:7F56h` 與 `DS:7F5Ah` 就是 spec 1074 在全域初始化裡配置的那兩張圖**：
> `02A8:0180h(0A8h, 2Ah, 1, 0)` ＝ **168 × 42 的戰術地圖畫布**、
> `02A8:0180h(58h, 16h, 1, 0)` ＝ **88 × 22 的背景暫存**。
> ⇒ 兩支獨立對上，這兩塊的用途定案。
