# 第七百一十一輪：把目標筆數永久夾小，與三支 `overlay-23` 的參數個數

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：DOS `overlay-22:4822h`。

## `4822h`

```text
n := ROLLDICE(2, 8)                              ← 2d8
if DS:7434h > n then DS:7434h := n                ← ⚠ 直接改全域筆數

for k := 1 to DS:7434h do
    p := far [7431h + k×4]
    if p = NIL then 跳過
    s := <overlay-23 entry#8>(p, 4, 0)
    r := <sub_E11h>(p, 23h, 52h)
    <overlay-23 entry#21（PUTEFFECT）>(r, 0, 0, 1, s, 'is confused'（CS:4816h）)
```

`DS:7434h` 是目標陣列的筆數（spec 709）。這支**把它改小之後沒有還原**——
和 spec 706 的 `5590h`（改完會還原）正好相反。所以同一段腳本裡接在後面的
opcode 看到的是被夾過的清單。

夾的方式是 `if 筆數 > 2d8 then 筆數 := 2d8`，也就是「最多影響 2d8 個目標」。
陣列本身沒有被重排，超過的那幾格還在原地，只是走不到。

> remake 若把目標清單當成呼叫參數傳遞而不是全域，這個跨 opcode 的副作用會消失。
> 要嘛保留全域語意，要嘛明確記下「這條 opcode 會縮短後續 opcode 看到的目標清單」。

## 參數個數要看被呼叫者的 `retf N`，不要從呼叫端推

本輪原本從呼叫端的推入數量推導參數個數，其中 `entry#21` 推成 7 個、`sub_E11h`
推成 4 個——**兩個都錯**。錯的原因是推導鏈上假設了 `sub_E11h` 的參數個數，
而它實際上是 `retf 2`（1 個 word）。

正確的做法是直接讀被呼叫者結尾的 `retf N`：

| `overlay-23` | `retf` | 參數（word） |
|---|---|---|
| entry#1 | `0Ah` | 5 |
| entry#2 | `0Ch` | 6 |
| entry#3 | `0Ah` | 5 |
| entry#4 | `6` | 3 |
| entry#8 | `8` | 4 |
| entry#9（`ROLLDICE`） | `4` | 2 |
| entry#10（`ROLLDAMAGEDICE`） | `4` | 2 |
| entry#11 | `0Ch` | 6 |
| entry#16 | `6` | 3 |
| entry#20 | `0Ah` | 5 |
| entry#21（`PUTEFFECT`） | **`14h`** | **10** |
| entry#22（`HEALDUDE`） | `8` | 4 |
| entry#24 | `6` | 3 |

`overlay-22:0E11h`（`sub_E11h`）是 `retf 2` ＝ **1 個 word**。

把正確的數字代回去，`4432h` 與 `4822h` 兩個 `entry#21` 呼叫點都得到
`3 ＋ 1 ＋ 4 ＋ 2 = 10`，和 `retf 14h` 吻合。前面那份錯的推導之所以也「自洽」，
是因為兩個呼叫點犯了同一個假設。

> **教訓：呼叫端的推入數量只能用來交叉檢查，不能當成推導的起點。**
> 起點永遠是被呼叫者的 `retf N`——那是編譯器直接寫進去的事實。

## 明確不宣稱

- `entry#8`／`#20`／`#21`／`sub_E11h` 各自做什麼。
- 編號 `23h`、`52h`、`4`、`0` 的意義。
- `2d8` 這個上限與 AD&D 1e **Confusion**「影響 2d8 個生物」一致，訊息也是
  `is confused`（`CS:4816h`），所以法術身分幾乎確定；但本輪沒有從法術表反查
  編號，仍標為推論。
