# 第七百一十一輪：把目標筆數永久夾小，與三支 `overlay-23` 的參數個數

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：DOS `overlay-22:4822h`。

## `4822h`

```text
n := ROLLDICE(2, 8)                              ← 2d8
if DS:7434h > n then DS:7434h := n                ← ⚠ 直接改全域筆數

for k := 1 to DS:7434h do
    p := far [7431h + k×4]
    if p = NIL then 跳過
    s := <overlay-23 entry#8>(p, 4, 0)
    r := <sub_E11h>(p, 23h, 52h)
    <overlay-23 entry#21（PUTEFFECT）>(r, 0, 0, 1, s, 'is affected'（CS:4816h）)
```

`DS:7434h` 是目標陣列的筆數（spec 709）。這支**把它改小之後沒有還原**——
和 spec 706 的 `5590h`（改完會還原）正好相反。所以同一段腳本裡接在後面的
opcode 看到的是被夾過的清單。

夾的方式是 `if 筆數 > 2d8 then 筆數 := 2d8`，也就是「最多影響 2d8 個目標」。
陣列本身沒有被重排，超過的那幾格還在原地，只是走不到。

> remake 若把目標清單當成呼叫參數傳遞而不是全域，這個跨 opcode 的副作用會消失。
> 要嘛保留全域語意，要嘛明確記下「這條 opcode 會縮短後續 opcode 看到的目標清單」。

## 三支 `overlay-23` 的參數個數（由殘留反推）

`overlay-22` 幾個呼叫點的推入數量互相印證，可以把三支的參數個數定下來：

| 被呼叫者 | 參數（word） | 依據 |
|---|---|---|
| `entry#8` | 4 | `45B5h`／`4822h` 正好推 4 個；`3947h` 推 8 個而 `entry#20` 拿到 5 個 |
| `entry#20` | 5 | `56C4h` 推 3 個 ＋ 目標殘留 2 個；`45B5h` 同形 |
| `entry#21`（`PUTEFFECT`） | 7 | `4432h` 與 `4822h` 都是「5 個明推 ＋ 字串鏈留下 2 個」 |

`3947h` 那條特別有說服力：8 個推入減掉 `entry#8` 的 4 個，剩 4 個，再加上
`push ax` 正好是 `entry#20` 的 5 個。**兩個獨立的呼叫點對同一組數字收斂**，
不是單點推測。

`sub_E11h` 在 `4432h` 與 `4822h` 都推 4 個 word 且回傳值在 `AX`，所以它是
`function(far 指標, byte, byte)`。

## 明確不宣稱

- `entry#8`／`#20`／`#21`／`sub_E11h` 各自做什麼。
- 編號 `23h`、`52h`、`4`、`0` 的意義。
- 這支對應哪一個法術（`2d8` 個目標這一點沒有直接對上 AD&D 的標準法術）。
