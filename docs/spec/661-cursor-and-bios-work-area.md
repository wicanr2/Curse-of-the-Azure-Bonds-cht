# 第六百六十一輪：游標位置與 PC-98 BIOS 工作區

狀態：`READY`。日期：2026-08-14
位置：PC-98 `PC98-GAME.EXE` 的 `19A8Bh`、`19A29h`、`19A10h`、`19825h`、`197EFh`。

## `word_280F9h` 是游標位置

`19A8Bh` 從 BIOS 工作區讀回來、`19A29h` 寫過去，兩支對同一組欄位、方向相反：

```text
19A8Bh（讀）:
    low(word_280F9h)  := 0000:071Ch
    high(word_280F9h) := 0000:0710h

19A29h（寫）:
    al := high(word_280F9h)
    ah := 0000:0712h
    if ah >= al then
        0000:0710h := al
        0000:071Ch := low(word_280F9h)
    else                                  ← 超出上限
        0000:0710h := ah
        high(word_280F9h) := ah           ← 夾回來
        low(word_280F9h)  := 0            ← 欄位歸零
        0000:071Ch := 0
```

所以 **`word_280F9h` 的高位元組是列、低位元組是欄**。這與
[spec 659](659-console-raw-mode-and-textrec.md) 的 `192D2h` 用
`high(word_280F9h) × byte_280DAh + low(word_280F9h)` 算位移一致——列 × 每列欄數 ＋
欄。

`0000:0712h` 是列數上限。**超出時不只夾住列，還把欄歸零**——游標會跳到那一列的
最左邊，而不是留在原欄。

### 用到的 BIOS 工作區欄位

| 位址 | 用途（由用法推得） |
|---|---|
| `0000:0710h` | 游標列 |
| `0000:0712h` | 列數上限 |
| `0000:071Bh` | 游標已開啟旗標（見下） |
| `0000:071Ch` | 游標欄 |

## `19A10h`：只開一次

```text
if 0000:071Bh = 0 then
    0000:071Bh := 1
    int 18h (AH = 11h)          ← PC-98 鍵盤／CRT BIOS：游標顯示
```

**先寫旗標再呼叫 BIOS**，而且沒有對應的「關閉」路徑在這支裡。旗標存在 BIOS 工作
區而不是自己的資料段——所以跨程式也看得到。

## `19825h`：把兩個角換算成起點與長寬

```text
dx := dx − cx                  ← 兩個 byte 各自相減（word 減法）
dx := dx + 101h                ← 兩個 byte 各自 +1
dh := dh − al
bx := al
di := al + ch
al := cl
cx := dh
dx := dl
```

`add dx, 101h` 是「兩個 byte 同時加一」的寫法。**但它是 word 加法**——低位元組
若為 `0FFh`，進位會跑進高位元組，多加一列。`sub dx, cx` 同理，低位元組借位會影響
高位元組。

`(cl, ch)` 是左上角、`(dl, dh)` 是右下角，換算成「起點 ＋ 寬高」。

## `197EFh`：與 `197BDh` 幾乎相同

與 [spec 660](660-fourth-sjis-variant.md) 的 `197BDh` 對照，差三處：

| | `197BDh` | `197EFh` |
|---|---|---|
| 座標預處理 | 無 | `dec dh` ＋ `dec ch` |
| 中間呼叫 | `sub_198AE` | `sub_19947` |
| 收尾算式 | `ch := dh − al + 1` | `dh := ch + al − 1` |

範圍檢查（`jl`，有號）與最後的 `sub_19840` 兩支相同。

## 明確不宣稱

- `sub_19947`／`sub_198AE`／`sub_19840` 的行為。
- `int 18h` `AH = 11h` 是開游標還是別的（由 `071Bh` 旗標的名稱推的）。
- `byte_280DAh` 每列欄數的設定來源。
