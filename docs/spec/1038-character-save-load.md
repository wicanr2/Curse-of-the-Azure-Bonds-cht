# 1038 — 角色存讀檔：五個副檔名、三種記錄長度的向下相容、四個指標欄位載入後歸零

- 證據等級：`exact`（DOS 側 1460 條、PC-98 側 1486 條，兩邊各自逐條讀完）
- 作法見 spec 783

## `dos overlay-16:0228Eh` ↔ `pc98 overlay-16:02A6Dh`（`retf 0Ch`）

兩側原本都是待解讀。這是**角色檔的讀取**，也是整份台帳裡最大的一對函式。

## ★★★ 一個角色 ＝ 五個檔

| 副檔名 | 內容 | 一筆的長度 |
|---|---|---|
| `.guy` | 角色本體 | 見下（三種） |
| `.cha` | 角色本體（另一個入口） | 同上 |
| **`.swg`** | **物品鏈** | **`3Fh` ＝ 63 bytes ＝ 物品節點** |
| **`.fx`** | **效果鏈** | **`9` bytes** |
| **`.spc`** | **另一條 9 bytes 的鏈** | **`9` bytes** |

★ 三條鏈的讀法一樣：`GetMem(長度)` → `BlockRead(長度)` → 接上鏈 → 直到讀完，
最後 `FreeMem(長度)` 把多配的那一個還掉。
★★ **`.swg` 的 63 bytes 再次確認 DOS 物品節點大小**（第六次），
**`.fx`／`.spc` 的 9 bytes 是效果節點的長度**——這是新結論。

檔名的組法：主檔名（`DS:5BF0h` 那個字串 ＋ 目錄）＋ 副檔名，
`DS:7584h = 0` 時先把原本的副檔名切掉（`Pos('.')` ＋ `Delete(…, 4)`）再接。

## ★★★ 三種記錄長度 ＝ 三代存檔的向下相容

```pascal
case DS:7584h of
  0: BlockRead(檔, 角色^, 1A6h);                    { 422 —— 現行版本 }
  1: begin p := GetMem(11Dh);  BlockRead(檔, p^, 11Dh);
          …歸零指標…;  <sub_1490>(…);  FreeMem(p, 11Dh) end;   { 285 }
  2: begin p := GetMem(0BCh);  BlockRead(檔, p^, 0BCh);
          …歸零指標…;  …轉換…;  FreeMem(p, 0BCh) end;          { 188 }
end;
```

> ★★★ **`DS:7584h` 是存檔格式代號**：`0` 讀 **422** bytes 直接就位、
> `1` 讀 **285**、`2` 讀 **188**，後兩者先讀進暫存區再轉成現行版面。
> ⇒ 遊戲**帶著兩代舊存檔的轉換路徑**（很可能是《Pool of Radiance》
> 與更早的角色檔）。
>
> ★ `1A6h` ＝ 422 與怪物範本的大小相同，是巧合還是共用版面，本規格不宣稱。

## ★★ 載入後一定要歸零的四個遠指標欄位

三個分支都做同一件事：

```pascal
角色^[0F2h] := NIL;      { word 0F2h ＋ 0F4h }
角色^[14Dh] := NIL;      { 物品鏈頭，word 14Dh ＋ 14Fh }
角色^[189h] := NIL;      { 隊伍 next，word 189h ＋ 18Bh }
角色^[18Dh] := NIL;      { word 18Dh ＋ 18Fh }
```

> ★★ **遠指標不能持久化，所以載入後一律清成 NIL，再由三個鏈檔重建。**
> 這四格正是既有結論裡的三個鏈頭（`+14Dh` 物品、`+189h` 隊伍 next，
> spec 1028／1034）＋ 一個尚未命名的 `+0F2h`。
> ⇒ **remake 的存檔格式必須把這四格排除在序列化之外**，否則會存進無效指標。

## ★★ 兩平台的長度對照

| 內容 | DOS | PC-98 | 差 |
|---|---|---|---|
| 角色記錄（現行） | `1A6h` ＝ **422** | `1A7h` ＝ **423** | **＋1** |
| 角色記錄（舊格式 1） | `11Dh` ＝ **285** | `11Dh` ＝ **285** | **相同** |
| 角色記錄（舊格式 2） | `0BCh` ＝ **188** | `0BCh` ＝ **188** | **相同** |
| 物品節點（`.swg`） | `3Fh` ＝ 63 | `67h` ＝ 103 | ＋`28h` |
| 效果節點（`.fx`／`.spc`） | `9` | `9` | **相同** |

> ★★★ **兩代舊格式的長度兩平台完全相同**——它們是磁碟上的舊版面，
> PC-98 並沒有跟著把它加寬。只有**現行**的角色記錄差 1（既有結論）。
> ★★ **效果節點 9 bytes 兩平台相同**，沒有跟著物品節點加寬。

四個指標欄位在 PC-98 是 `+0F2h`（相同）、`+14Eh`、`+18Ah`、`+18Eh`
——後三個各 ＋1，與 spec 1034 收窄過的邊界一致。

★ PC-98 另外有大寫的 `'.GUY'`／`'.CHA'` 兩個字串（DOS 只有小寫）。

## 磁片提示

| 字串 | 用途 |
|---|---|
| `'Put save disk in '`（17）＋ 磁碟機字母 ＋ `':'` | `arg_0 <> 0` 時 |
| `'Insert disk B in drive '`／`'C'`／`'D'`（各 23） | 表 `DS:25AEh`，筆距 `1Eh`(30)，索引 ＝ `DS:5BEEh`（資料片編號） |
| `'Loading...Please Wait'`（21） | 讀取中 |

★ `DS:5BEEh` 就是 spec 892／1029／1033 的**資料片編號**，這裡拿它挑提示句。
★ 提示句表五筆（索引 1..5）分別對到磁片 B／B／C／C／D。

## 中文化

| DOS | 長度 | 建議 |
|---|---|---|
| `'Put save disk in '` | 17 | 「請放入存檔磁片到 」 |
| `'Insert disk B in drive '` | 23 | 「請放入磁片 B 到磁碟機 」 |
| `'Loading...Please Wait'` | 21 | 「載入中，請稍候」（PC-98 是「読みこみ中です」，見 spec 1029） |
| `'.guy'`／`'.cha'`／`'.swg'`／`'.fx'`／`'.spc'` | 4／4／4／3／4 | ⚠ **副檔名，一律不可翻** |

⚠ 五個副檔名同時是字串常數與檔名組成，與 spec 1029／1033 的
`'PIC'`／`'FINAL'`／`'SPRIT'`／`'CHEAD'` 同一類。

## 明確不宣稱

- 沒有宣稱 `sub_1490`（285 bytes 舊格式的轉換）怎麼把欄位搬過去。
- 沒有宣稱 188 bytes 那一版的轉換細節。
- 沒有宣稱 `+0F2h` 那個遠指標是什麼鏈。
- 沒有宣稱 `.fx` 與 `.spc` 兩條 9 bytes 的鏈差在哪
  （長度相同、讀法相同，掛在角色的不同欄位）。
- 沒有宣稱 `DS:7584h` 由誰設定、怎麼判斷舊存檔的版本。
- 沒有宣稱 `1A6h` ＝ 422 與怪物範本 422 是不是同一個版面。
- 沒有宣稱 `0636:04FFh`／`02E5h`／`0618h`（開檔／關檔／取檔名）的完整介面。
