# 第五百七十五輪：`Random` 本體與 PC-98 VRAM／EMS

狀態：`READY`（限本文件列出的函式）。日期：2026-08-14

## `Random(n)` 的本體

```text
Random(n):
    呼叫 LCG（DOS sub_1B694／PC-98 sub_1B7F4）取得 32-bit 亂數 → dx:ax
    if n = 0 then return 0
    xchg ax, dx ; div n ; xchg ax, dx     ← 取餘數
    return 餘數
```

兩平台逐指令相同（第 570 輪已由位元組比對證明）。因此**原版的隨機值是
「32-bit LCG 結果對 n 取餘數」**，不是常見的「高位乘法」寫法。

至此重現原版隨機序列所需的三塊都已定位：

| 元件 | 位置 |
|---|---|
| 種子 | `dword_20998`（DOS），由 `@Randomize` 以 `INT 21h AH=2Ch` 的系統時間設定 |
| LCG 本體 | DOS `sub_1B694`／PC-98 `sub_1B7F4`（**本輪未讀**） |
| 取值方式 | 對 `n` 取餘數（本輪已讀） |

**LCG 的乘數與加數尚未讀出**，所以還不能宣稱可以重現序列。

## PC-98 圖形 VRAM 與 EMS

- `17239h`：把回傳的 far pointer 設成 **`A800:0000`**——PC-98 的圖形 VRAM
  起始段。
- `1A485h`：以 `INT 21h AX=3567h` 取 `INT 67h` 向量，再把該處理常式起始 8
  bytes 與 `CS:558h` 的簽章比對 ⇒ **EMS 驅動偵測**。
- `overlay-18:1908h`：`si` 從 0 起、每次加 `2B67h` 再 `and 7FFFh`，重複
  `8000h` 次——對 32 KB 平面做**打散順序**的逐格處理（`2B67h` 與 `8000h`
  互質，故會走遍所有位置）。這是常見的「隨機化淡入」效果實作方式。

## 這份規格明確不宣稱

- LCG 的實際係數（`sub_1B694`／`sub_1B7F4` 未讀）。
- `overlay-18:1908h` 每格做什麼（`sub_191E` 未讀）。
