# 1007 — 佈署找空位：11×6 的區塊、由中心左右交替外擴、四組方向表

- 證據等級：`exact`（DOS 側 473 條逐條讀完；PC-98 對側 472 條，
  只差一條 `xor ah, ah`，其餘助憶碼序列完全相同）
- 作法見 spec 783

## `dos overlay-10:01370h` ↔ `pc98 overlay-10:01364h`（`retf 2`，回一個 byte）

兩側原本都是待解讀。整支沒有字串。
它是 spec 之前記過的「依隊形範本把一個戰鬥員放上戰場」（`sub_122Ch`）的**呼叫端**：
一直換候選格，直到放進去或放棄。

```pascal
function 找位置放一個(參數: byte): byte;      { 1 = 放進去了、0 = 放棄 }
```

## ★★ 佈署格是 11 欄 × 6 列 的區塊，一場戰鬥有 4 塊

界內判斷寫死在本支：

```pascal
出界 := ord(not ((0 <= 欄 <= 0Ah) and (0 <= 列 <= 5)));
```

⇒ **11 欄 × 6 列 ＝ 66 格**。

這個 66 與 `sub_122Ch` 的範本索引式對上：
`DS:47F4h ＋ DS:4A12h × 108h ＋ 區塊 × 42h ＋ 列 × 0Bh ＋ 欄`，
其中 `42h ＝ 66 ＝ 11 × 6`、`0Bh ＝ 11`、`108h ＝ 264 ＝ 4 × 66`。

> **一個範本組 ＝ 4 個區塊，每個區塊 11 欄 × 6 列。**
> `DS:4A12h` 選範本組，本支的 `區塊` 變數（0..3）選區塊。

`sub_11FBh`（spec 754 同批）另外判「**兩軸都出界**」——本支用它區分
「只歪出去一軸」（還在同一個區塊的延長線上，繼續繞）與
「整個跑掉了」（換一個方向重來）。

## 狀態機：由中心往左右交替外擴

三個狀態輪流，`排` 與 `距` 兩個計數器控制走法：

```pascal
相位 := byte[2EAh ＋ 方向組 × 4 ＋ 區塊] div 2;      { 0..3 }

case 狀態 of
  1: begin                                          { 開一排 }
       d  := byte[2FAh ＋ (相位 ＋ 2) mod 4];
       基欄 := byte[2FEh ＋ (區塊 > 0)×4 ＋ 相位] ＋ dx[d] × 排;
       基列 := byte[306h ＋ (區塊 > 0)×4 ＋ 相位] ＋ dy[d] × 排;
       欄 := 基欄;  列 := 基列;
       距 := 1;  狀態 := 2;  已走 := 1;
     end;
  2: begin                                          { 往一邊 }
       d := byte[2FAh ＋ (相位 ＋ 1) mod 4];
       欄 := 基欄 ＋ dx[d] × 距;  列 := 基列 ＋ dy[d] × 距;
       狀態 := 3;  inc(已走);
     end;
  3: begin                                          { 往另一邊，然後拉遠 }
       d := byte[2FAh ＋ (相位 ＋ 3) mod 4];
       欄 := 基欄 ＋ dx[d] × 距;  列 := 基列 ＋ dy[d] × 距;
       狀態 := 2;  inc(距);  inc(已走);
     end;
end;
```

`dx`／`dy` 是 spec 999 的九格方向表（DOS `DS:2694h`／`269Dh`）。

★ 狀態 2 與 3 用的是 `(相位＋1)` 與 `(相位＋3)`，兩者在 `DS:2FAh` 上是
**相反方向**，而 `距` 只在狀態 3 之後才加一。所以候選格的順序是

> **基準 → ＋1 → −1 → ＋2 → −2 → ＋3 → −3 …**

一排走完（`已走` 超過上限）就 `inc(排)`，用狀態 1 的算式開下一排，
往 `(相位＋2)` 那個方向平移。

## 四張常數表

| 表 | DOS | PC-98 | 內容 |
|---|---|---|---|
| 方向組 → 三個要試的方向 | `DS:2DAh` | `DS:6CEh` | 16 bytes ＝ 4 組 × 4 |
| 方向組 → 相位（用前先 `div 2`） | `DS:2EAh` | `DS:6DEh` | 16 bytes |
| 相位 → 方向碼 | `DS:2FAh` | `DS:6EEh` | `7, 2, 3, 6` |
| 起始欄 | `DS:2FEh` | `DS:6F2h` | `5, 4, 5, 6` ／ `3, 8, 7, 2` |
| 起始列 | `DS:306h` | `DS:6FAh` | `3, 2, 2, 3` ／ `0, 2, 5, 3` |

★ **起始欄／列的前四筆全在 11×6 的正中央**（(5,3)、(4,2)、(5,2)、(6,3)），
後四筆全在邊上（(3,0)、(8,2)、(7,5)、(2,3)）——
前四筆給 `區塊 = 0`，後四筆給 `區塊 > 0`。

★ **`DS:2DAh` 每組的第 0 筆都是 `8`（＝原地，spec 999）**，而迴圈只跑 1..3，
所以那一格永遠用不到。四組的第 1 筆分別是 `4`（下）、`6`（左）、`0`（上）、`2`（右）
——**四個方向各一組，形狀上是「從哪一邊進場就往反方向擴」**：

| 方向組 | 三個要試的方向（`DS:2DAh` 的 1..3） |
|---|---|
| 0 | 下、左、右 |
| 1 | 左、下、上 |
| 2 | 上、左、右 |
| 3 | 右、上、下 |

## 走不下去的時候換方向

候選格兩軸都出界時，最多換三次方向：

```pascal
while (區塊 < 3) and (狀態 <> 1) do begin
    inc(區塊);
    x := DS:720Fh ＋ byte[4A04h ＋ 組];      { 隊伍位置 ＋ 這一組的偏移 }
    y := DS:7210h ＋ byte[4A06h ＋ 組];
    d := byte[2DAh ＋ byte[4A0Ah ＋ 組] × 4 ＋ 區塊];
    if (DS:4FBAh = 3) or (<sub_378>(x, y, d) <> 1) then begin
        基準欄 := byte[4A04h ＋ 組] ＋ dx[d];
        基準列 := byte[4A06h ＋ 組] ＋ dy[d];
        排 := 0;  狀態 := 1;                 { 從新方向重開 }
    end;
end;
if 狀態 <> 1 then 放棄 := 1;                 { 三個方向都被牆擋住 }
```

★ `sub_378h`（既有台帳：從兩側各查一次牆面）回 1 表示**那個方向有牆**。
⚠ `DS:4FBAh = 3`（畫面模式，spec 892）時**整個牆面檢查被跳過**——
形狀上是「這個模式沒有牆的概念」。

`DS:4A04h`／`4A06h`／`4A08h`／`4A0Ah`（PC-98 `7ABAh`／`7ABCh`／`7ABEh`／`7AC0h`）
在靜態映像裡全是 `0FFh`，**是執行期才填的全域**，不是常數表。
`DS:4A12h`（PC-98 `7AC8h`）是目前這一組的索引。

## 每排的長度上限

```pascal
if 第一輪 and (已走 >= byte[4A08h ＋ 組]) then 換下一排
else if (not 第一輪) and (已走 > 0Bh)     then 換下一排;
```

★ **第一排的長度由執行期全域 `DS:4A08h` 決定，之後固定 11**（`0Bh`，＝區塊寬度）。

## 只在第一組、第一步做一次的額外檢查

```pascal
inc(排);
if (DS:4A12h = 0) and odd(DS:4A0Ah) and (區塊 = 0) and (排 = 1) then begin
    x := DS:720Fh ＋ byte[4A04h];  y := DS:7210h ＋ byte[4A06h];
    擋 := 0;
    for i := 1 to 3 do begin
        d := byte[2DAh ＋ DS:4A0Ah × 4 ＋ i];
        if (DS:4FBAh <> 3) and (<sub_378>(x, y, d) <> 1) then 擋 := 1;
    end;
    if 擋 <> 0 then inc(排);                { ★ 直接跳過一整排 }
end;
狀態 := 1;  第一輪 := 0;
```

`shr al, 1` ＋ `jb` 取的是 `DS:4A0Ah` 的**最低位元**，所以條件是「方向組是奇數」。

## 結尾

```pascal
if not 出界 then
    成功 := <sub_122C>(參數, 欄, 列, 基準欄, 基準列, 區塊);
until (成功 <> 0) or (放棄 <> 0);
結果 := ord(放棄 = 0);
```

⚠ **只有在界內才真的呼叫 `sub_122Ch`**；出界的候選格只是推進狀態機。

## 兩平台差異

只有位址，沒有邏輯差：

| DOS | PC-98 |
|---|---|
| `DS:4A12h` | `DS:7AC8h` |
| `DS:4A04h`／`4A06h`／`4A08h`／`4A0Ah` | `DS:7ABAh`／`7ABCh`／`7ABEh`／`7AC0h` |
| `DS:2DAh`／`2EAh`／`2FAh`／`2FEh`／`306h` | `DS:6CEh`／`6DEh`／`6EEh`／`6F2h`／`6FAh` |
| `DS:2694h`／`269Dh` | `DS:489Eh`／`48A7h` |
| `DS:720Fh`／`7210h`（隊伍欄／列） | `DS:0A2A9h`／`0A2AAh` |
| `DS:4FBAh`（畫面模式） | `DS:7F27h` |

PC-98 少的那一條 `xor ah, ah` 是編譯器的差異，不影響語意。

## 中文化

本支沒有字串。但 **11×6 的佈署區塊**是戰鬥開場的版面常數，
remake 重現隊形時要照這個尺寸，不能改。

## 明確不宣稱

- 沒有宣稱 `DS:4A12h`（範本組）各值代表哪一方。
- 沒有宣稱 `DS:4A04h`／`4A06h`／`4A08h`／`4A0Ah` 由誰在什麼時候填。
- 沒有宣稱 `DS:2FAh` 的 `7, 2, 3, 6`（左上／右／右下／左）為什麼是這四個
  ——它們不是正交的四方向，`(相位＋1)` 與 `(相位＋3)` 才是成對的相反方向。
- 沒有宣稱唯一的參數（`bp+06h`）是什麼，本支只把它原樣轉給 `sub_122Ch`。
- 沒有宣稱 `sub_122Ch` 回 0 的原因（格子已被佔？範本說不能放？）。
