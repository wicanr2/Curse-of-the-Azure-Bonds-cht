# 1091 — PC-98 半形轉全形：整張 ASCII → Shift-JIS 對照表，中文化必須整支換掉

- 證據等級：`exact`（PC-98 resident 側 814 條逐條讀完）
- 作法見 spec 783

## `pc98 PC98-GAME.EXE:145CAh`（`retf 6`）

原本待解讀。整支幾乎沒有呼叫（392 `mov`、128 `xor`、69 `cmp`、53 `jmp`），
就是一張**逐字元的對照表**：把輸入字串裡的半形字元換成 Shift-JIS 全形，
寫進輸出字串。

```pascal
輸入 := arg（上限 0FFh）;
出 := 1;  模式 := 0;
for i := 1 to Length(輸入) do begin
    if <near 14342h>(輸入[i]) then begin        { ★ 這是雙位元組首位元組 }
        輸出[出] := 輸入[i];  inc 出;
        inc i;
        輸出[出] := 輸入[i];  inc 出;           { ⚠ 原樣抄兩個 byte }
    end
    else if 輸入[i] = 08h then 模式 := (模式 xor 3) and 1
    else if 輸入[i] = 0Bh then 模式 := (模式 xor 3) and 2
    else …查表，一律輸出兩個 byte，出 += 2…;
end;
輸出[0] := 出 − 1;                              { 長度 }
arg_輸出 := 輸出（上限 0FFh）;
```

> ★★★ **`near 14342h` 是「這個 byte 是不是雙位元組字元的首位元組」的判定**
> ——命中就把它和下一個 byte **原樣抄過去**，不做任何轉換。
> ⇒ **繁中化的關鍵就在這一支**：Big5 的首位元組範圍（`A1h`..`F9h`）
> 與 Shift-JIS 不同，`near 14342h` 必須改寫，
> 否則中文字會被下面那張表逐 byte 拆掉。

★ **輸出一律是兩個 byte**（`出 += 2`），所以**長度會變成輸入的兩倍**。

## ★★ 兩個模式位元

```pascal
08h → 模式 := (模式 xor 3) and 1;
0Bh → 模式 := (模式 xor 3) and 2;
```

兩個控制碼各自翻轉一個位元（`08h` 管 bit 0、`0Bh` 管 bit 1），
**本身不輸出任何字元**。形狀上是「英數／カタカナ」與另一組的切換。
⚠ 本規格不宣稱模式位元實際改變了哪些字元的對應
（`0Bh` 那一支看到 `82 81` ＝ ａ，形狀上是小寫英文的全形）。

## ★★★ 中文化的三個必改點

1. **`near 14342h` 的首位元組判定**要換成 Big5 的 `A1h`..`F9h`
   （Shift-JIS 是 `81h`..`9Fh` ＋ `E0h`..`FCh`，兩者範圍不同）。
   不改的話，Big5 中文字的兩個 byte 會分別掉進上面那張表，變成兩個亂碼全形字。
2. **半形カタカナ（`A1h`..`DFh`）那一段要整段拿掉**——Big5 的首位元組
   就落在這個範圍，會被誤判成カタカナ。
   ⚠ **這一條與第 1 條是同一個衝突的兩面**，兩邊都要改才會對。
3. **輸出緩衝是 `0FFh`**（`var_203` 起 258 bytes），而輸入也是 `0FFh`
   ——**輸入全是半形時輸出會是兩倍長度**，中文化後若直接沿用會溢位。
   繁中方案建議：**中文字原樣通過（走第 1 條），半形英數維持半形**，
   讓輸出長度不再翻倍。

## 明確不宣稱

- 沒有宣稱 `near 14342h` 的判定範圍（只確定它回真時會原樣抄兩個 byte）。
- 沒有宣稱兩個模式位元改變了哪些字元的對應。
- 沒有宣稱英文字母（`41h`..`5Ah`、`61h`..`7Ah`）的完整對應
  （分散在模式分支裡，本規格只確認 `0Bh` 模式下看得到 `82 81` ＝ ａ）。
- 沒有宣稱 `retf 6` 與兩個遠指標參數（共 8 bytes）的落差是 IDA 的框架基準
  還是呼叫端自己清——與 spec 1078／1079 同一類。
- 沒有宣稱這一支由誰呼叫。
