狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：DOS `overlay-22:6022h`（`retf 0Ah`）。

```text

<[DS:72A0h] 第 0 項>(@DS:7746h, 1, 24h)           ← 選目標

<overlay-24 entry#20>(arg_6, '<名字> gazes...'（CS:600Ch）, 0Ah, 0)
<overlay-24 entry#24>(12h)

```

## 分派表第 0 項是「選目標」

`DS:72A0h` 的第 0 項（spec 721）在 `overlay-22` 有 8 個呼叫點，形狀一致：

```text
push <模式碼> ; push 1 ; push ds ; push 7746h(位址)
call dword ptr ds:72A0h
（然後從 某角色^[18Dh]^[0Ah] 讀出結果）
```

模式碼各不相同：`6022h` 用 `24h`、`5E11h`（spec 720，龍息）用 `41h`。
**結果不是從回傳值拿的，是寫進 `+18Dh^[0Ah]` 這個欄位。**

## 兩支的差別：有沒有先清空

| | `6022h`（本輪） | `5E11h`（spec 720） |
|---|---|---|
| 呼叫前 | `+18Dh^[0Ah] := NIL` | **不清** |
| 呼叫後 | 讀出來，`NIL` 就返回 | 讀出來，先拿去算距離，之後才檢查 `NIL` |

所以 `5E11h` 在「這次沒選到目標」的情況下會**讀到上一次留下的值**，而且會拿它
去做距離判定。`6022h` 沒有這個問題。兩支的其餘結構幾乎一樣，這個差異很容易在
對照時被抹平。

## 石化

`entry#8(p, 1, 0)` 回非 0 就直接返回——**豁免成功完全沒事**，沒有減半也沒有
替代效果。失敗才套 `entry#11(p, 34h, 3Ch, 0FFh, 0)` 並顯示
`is turned to stone`。

訊息用的 `entry#20` 最後一個參數是 `0`（`5E11h` 與 spec 693 那些是 `1`），
所以那個旗標在同一支函式的兩次呼叫裡都是 `0`，和別處不同。

## 明確不宣稱

- `[DS:72A0h]` 第 0 項的內部行為、`24h`／`41h` 這些模式碼的意義。
- `overlay-23 entry#11` 的行為、`34h`／`3Ch`／`0FFh` 的意義。
- `overlay-24 entry#25` 那兩組座標與 `4`／`2Dh` 的用途。
- `entry#20` 最後一個參數 `0` 與 `1` 的差別。
