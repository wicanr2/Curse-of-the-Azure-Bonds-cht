# 990 — 十格選單的選項行組裝器，與那塊記憶體的完整版面

- 證據等級：`exact`（函式逐條讀完；`0A65h:0262h` 由常駐端 11 行全文確認；
  版面由三支函式的索引式互相咬合）
- 作法見 spec 783

## `pc98 overlay-26:008AEh`（126 條，`retf 6`）

`(要不要含前半 arg_0, 輸出字串 arg_2)`。四個字串常數全是空白：
`CS:0898h` ＝ 4 個、`CS:089Dh` ＝ 2 個、`CS:08A0h` ＝ 7 個、
`CS:08A8h` ＝ 1 個、`CS:08AAh` ＝ 3 個。

```pascal
if 含前半 <> 0 then begin i := 1;  輸出^ := '    ' end     { 4 個空白 }
else                begin i := 6;  輸出^ := '  '   end;    { 2 個空白 }

while i <= 0Ah do begin                                     { 無號 }
    if byte[0A338h ＋ 7i] = 0 then
        輸出^ := (輸出^ ＋ '       ') 上限 50h              { 空格 ⇒ 填 7 個空白 }
    else
        輸出^ := (輸出^ ＋ DS:[0A338h ＋ 7i] ＋ ' ') 上限 50h;
    if i = 5 then 輸出^ := (輸出^ ＋ '   ') 上限 50h;       { 兩欄之間再空 3 格 }
    if i = 0Ah then break;
    inc(i);
end;
輸出^ := (輸出^ ＋ '    ') 上限 50h;
```

### 一格 7 欄，兩欄之間 3 欄

| 段 | 欄數 |
|---|---|
| 前導 | 4（含前半）／2（只有後半） |
| 每格 | **7**（6 個字元 ＋ 1 個空白，空格則是 7 個空白） |
| 第 5 與第 6 格之間 | ＋3 |
| 結尾 | 4 |

全十格 ＝ 4 ＋ 5×7 ＋ 3 ＋ 5×7 ＋ 4 ＝ **81**，
被 `限長(…, 50h)` 砍成 **80** ——正好是 PC-98 的一列。
只有後半 ＝ 2 ＋ 5×7 ＋ 4 ＝ **41**。

**每個選項最多 6 個半形字元 ＝ 3 個全形字。** 這是十格選單的硬寬度，
與 spec 972 讀到的「反白一次寫 12 bytes」是不同的兩個數字
（12 是屬性平面的格數，6 是字串本身的長度上限）。

## ★ `0A65h:0262h` 不是字串指派，是 `rep movsb`

常駐端 `PC98-GAME.EXE:1A8B2h` 只有 11 行：

```asm
mov bx, sp
mov dx, ds
lds si, ss:[bx+0Ah]        ; 來源（第一個推的）
les di, ss:[bx+6]          ; 目的
mov cx, ss:[bx+4]          ; 位元組數
cld
rep movsb
mov ds, dx
retf 0Ah
```

**`(來源, 目的, 位元組數)` 的原始位元組複製，沒有重疊處理、沒有長度語意。**
與 Pascal RTL 的 `Move`（`0A65h:1B0Dh`）是兩支不同的東西。
先前把它記成「三段字串指派」是不精確的。

## ★★ 這塊記憶體的版面完全咬合

三支函式的索引式拼起來，`DS:0A334h`..`0A386h` 一格不差：

| 位址 | 內容 | 出處 |
|---|---|---|
| `DS:0A335h`..`0A33Eh` | **熱鍵字元表，10 bytes** | spec 975 的 `0262h(@DS:11A6h, @DS:0A335h, 0Ah)`；spec 972 的略過迴圈讀 `byte[0A334h ＋ 索引]` |
| `DS:0A33Fh`..`0A384h` | **十個選項字串，每個 7 bytes**（長度 byte ＋ 6 字元），第 i 格在 `0A338h ＋ 7i` | 本規格；spec 605 的 `DS:[A339h ＋ i×7]`／`DS:[A338h ＋ i×7]` |
| `DS:0A385h` | 目前格 | spec 972 |
| `DS:0A386h` | 上一格 | spec 972 |

第 10 格佔 `0A37Eh`..`0A384h`，**下一個 byte 正好是 `0A385h`**——
沒有空隙、沒有重疊。

## ★ 第 1 格「碰巧」不可選

spec 975 讀到熱鍵是靠 `0262h` 從 `DS:11A6h` 複製 **10 個 byte** 過來。
`DS:11A6h` 是一個 Pascal 字串，**第一個 byte 是長度**——所以複製過去的是
「長度 byte ＋ 前 9 個字元」，而不是 10 個字元：

| 目的位址 | 來源 | 值 |
|---|---|---|
| `0A335h`（＝ 第 1 格） | `DS:11A6h` 的**長度 byte** | `20h` |
| `0A336h`（第 2 格） | 字元 1 | `' '` |
| … | | |
| `0A33Ah`（第 6 格） | 字元 5 | `'Y'` |
| `0A33Eh`（第 10 格） | 字元 9 | `'N'` |

**那個長度 byte 是 32 ＝ `20h` ＝ 半形空白的字碼**，
所以略過迴圈把第 1 格當成「空白 ⇒ 不可選」——**結果是對的，但理由是巧合**。

⚠ 那個常數字串**只要長度不是 32，第 1 格就會變成可選、而且熱鍵是一個亂碼字元**。
`DS:11A6h` 現在是 32 個字元（`'    Y   N     K   E     CPH E…'`），
**中文化若改動它的長度，會意外打開第 1 格。**
要改熱鍵就必須把長度維持在 32，或者連 `0262h` 的來源位址一起往後挪一格。

這也修正了 spec 975 對「第 i 格對應第 i−1 個字元」的解釋：
真正的原因不是基底差 1，而是**複製時把長度 byte 也算進去了**。
spec 975 的對應表（第 6 格 `'Y'`、第 10 格 `'N'`）**結論正確**。

## 中文化

- **一格 6 個半形字元 ＝ 3 個全形字**。中文選項超過三個字就必須改版面
  （改 `7` 這個間距、或改成兩列）。
- 全十格用滿 80 欄，**沒有多餘空間可以借**。
- 選項字串在 `DS:0A33Fh` 起的資料段裡，執行期由別處填入；
  要換成中文得找到填表的那一支（本規格未讀）。

## 明確不宣稱

- 沒有宣稱 `DS:0A33Fh` 那十筆字串由誰填。
- 沒有宣稱 `arg_0` 的呼叫端語意（只知道 0 時只組後五格）。
- 沒有宣稱本支組出來的字串交給誰顯示。
