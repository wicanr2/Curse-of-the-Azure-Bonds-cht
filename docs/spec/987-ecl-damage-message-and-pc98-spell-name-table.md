# 987 — ECL 傷害訊息（−10 死亡線、捲動暫停）與 PC-98 的法術名稱表

- 證據等級：`exact`（兩支逐條讀完；字串與表格由原始 bytes 讀出）
- 作法見 spec 783

## `dos overlay-07:02252h`（134 條，`retf 6`）— ECL 的「受到傷害」訊息

五個字串全在 overlay 內：`CS:2204h` ＝ `'  '`（兩個空白）、
`CS:2207h` ＝ `' dies. '`、`CS:220Fh` ＝ `' is hit FOR '`、
`CS:221Ch` ＝ `' points of Damage.'`、`CS:222Fh` ＝
`'press <enter>/<return> to continue'`。

```pascal
if 角色^[195h] = 6 then 離開;                         { 已經是 Dead 就不印 }

Str(傷害, 寬度 0, var 數字[3]);
if 角色^[1A4h] ＋ 0Ah < 傷害 then                      { 無號 }
    訊息 := '  ' ＋ 角色^ ＋ ' dies. '
else
    訊息 := '  ' ＋ 角色^ ＋ ' is hit FOR ' ＋ 數字 ＋ ' points of Damage.';

if DS:65A1h > 16h then begin                           { 寫過第 22 列 }
    DS:65A1h := 11h;                                   { 回到第 17 列 }
    先清框 := 1;
    <0542h:0946h>('press <enter>/<return> to continue', 0, 0Fh);
end
else 先清框 := 0;

DS:65A0h := 26h;
<0542h:04A4h>(1, 11h, 26h, 16h, 0Fh, 0, 先清框, 訊息);
<overlay-24 entry#28>(傷害, 角色);                     { spec 698 的扣血與狀態 }
<0542h:0B4Ah>(0Fh, 26h, 1, 11h);
<overlay-24 entry#2>(遠指標(DS:6506h));                { 重畫角色列 }
```

### ★ 「死」的判定就是 AD&D 的 −10 線

`角色^[1A4h] ＋ 0Ah < 傷害` ⟺ `目前HP − 傷害 < −10`。
**傷害會讓 HP 掉到 −10 以下才印 `' dies. '`**，否則印詳細的傷害數字。

⚠ 這只是**訊息**的判定。實際的扣血與狀態轉換由後面的
`overlay-24 entry#28`（spec 698 的 `2421h`）決定，那一支用的是
「溢出 > 9 才設 `+195h := 6`」——**兩處的門檻等價但寫法不同**
（`溢出 > 9` ⟺ `傷害 − HP > 9` ⟺ `HP + 10 < 傷害`，兩邊一致）。

### ★ `' is hit FOR '` 的 `FOR` 是大寫

原版字串就是這樣，不是判讀誤差。中文化沿不沿用不影響行為，但這是原文事實。
`' dies. '` 前後各有一個空白，`'  '` 前綴是兩個空白——**縮排是字串的一部分**。

### ★ `DS:65A0h`／`DS:65A1h` 是訊息框裡的游標

`DS:65A1h` 是**目前輸出列**，超過 `16h`（22）就回到 `11h`（17）並暫停等玩家。
`DS:65A0h` 是欄，寫死 `26h`（38）。

代進 `0542h:04A4h(1, 11h, 26h, 16h, …)` ＝ **欄 1–38 × 列 17–22**
——與 spec 982 從 `overlay-24:017D6h` 算出來的「非戰鬥訊息框」完全相同，
兩個獨立來源互相印證。**可用的高度只有 6 列（17..22）**，寫滿就暫停。

### ⚠ 更正 spec 982 對第七個參數的描述

spec 982 把 `0542h:04A4h` 的第七個參數當成常數 `1`。
本支證明那是**「先清框」旗標**：只有在剛捲回第 17 列時才給 `1`，
一般情況給 `0`（接著往下寫）。spec 982 已補註。

## `pc98 overlay-22:065C9h`（131 條）— 施法訊息，兩種版面

字串：`CS:65AEh` ＝ `'は呪文を唱えた。'`、`CS:65BFh` ＝ `'呪文'`、
`CS:65C4h` ＝ `'は、'`。

```pascal
限長(arg_2^, 本地, 28h);

if DS:7F27h = 5 then begin                              { 戰鬥中 }
    <overlay-24 entry#20>(施法者, 名字 ＋ 'は呪文を唱えた。', 1, 0Ah);
    <019Eh:06B5h>(0, 17h, 27h, 17h);                    { 清第 23 列整列 }
    印字(0, 17h, 0Ah, 0, '呪文' ＋ 法術名);
end
else begin
    <019Eh:06B5h>(1, 12h, 26h, 16h);                    { 清非戰鬥訊息框 }
    <overlay-24 entry#22>(0, 13h, 1, 施法者);           { 印名字於第 19 列 }
    印字(名字長 ＋ 2, 13h, 0Ah, 0, 'は、');
    印字(1, 14h, 0Ah, 0, 法術名 ＋ 本地);               { ★ 這裡才用到 arg_2 }
    <0418h:14AAh>();
    <overlay-24 entry#21>();
end;
```

⚠ **`arg_2` 只在非戰鬥那條路用到。** 函式一開頭無條件把它限長到 40 存進 `本地`，
但戰鬥分支從頭到尾沒有讀它——**戰鬥中呼叫端傳什麼字串都不會顯示**。
兩平台是否都如此，本規格不宣稱（只讀了 PC-98 這一支）。

另外**前綴不同**：戰鬥中是 `'呪文' ＋ 法術名`，非戰鬥是 `法術名 ＋ arg_2`。
`'呪文'` 這個前綴只出現在戰鬥版。

### ★★ `DS:49B3h` ＝ PC-98 的法術名稱表，每筆 61 bytes

`法術名 := DS:[49B3h ＋ 法術編號 × 3Dh]`。`3Dh` ＝ 61 ＝ 長度 byte ＋ 60 個字元。
靜態 bytes 直接讀出前幾筆：

| 編號 | 內容 |
|---|---|
| 0 | （不是字串，長度欄是 `21h` 但內容全是 `00`／`FF`——**索引從 1 開始**） |
| 1 | `ブレス`（Bless） |
| 2 | `カース`（Curse） |
| 3 | `キュア・ライト・ウーンズ`（Cure Light Wounds） |

與 DOS 常駐的法術名稱表 `DS:27BDh`（`docs/audit/resident-data-tables.md`）
的前三筆順序相同——**這就是同一張表的 PC-98 版**。

**中文化最重要的一張表之一**：每筆 60 個字元的空間，
中文全形字算兩個 byte ⇒ 最多 30 個漢字，實務上綽綽有餘。
表在資料段、不在 overlay 裡，可以整批替換。

### `019Eh:06B5h` ↔ `01A0h:04CDh` 是第三對常駐孿生入口

兩處呼叫的形狀完全一致：

| 呼叫 | 矩形 |
|---|---|
| `019Eh:06B5h(0, 17h, 27h, 17h)` | 欄 0–39 × 列 23（整列） |
| `019Eh:06B5h(1, 12h, 26h, 16h)` | 欄 1–38 × 列 18–22（非戰鬥訊息框） |

第二個與 spec 982 的 DOS `01A0h:04CDh(1, y, 26h, 16h)` 是同一塊，
第一個與 spec 693 的 DOS `(0, 18h, 27h, 18h)`「清整列」是同一種用法。
繼 `0542h:0352h` ↔ `0418h:0D17h`（spec 983）、
`0542h:0311h` ↔ `0418h:0139h`（spec 985）之後的第三對。

### 兩種版面的差別

| | 戰鬥中（`DS:7F27h = 5`） | 非戰鬥 |
|---|---|---|
| 施法者訊息 | 走 `entry#20` 的訊息框 | 名字單獨畫在第 19 列 |
| 法術名 | 欄 0、列 23 | 欄 1、列 20 |
| 連接詞 | 無（訊息裡已含 `'は呪文を唱えた。'`） | `'は、'` 接在名字後面 |

**非戰鬥那條路是把句子拆成三段畫在不同位置**（名字／`'は、'`／法術名＋`arg_2`），
中文化要重排語序時**得同時改三處的欄位座標**，不能只換字串。
`'は、'` 的欄位是 `名字長 ＋ 2`——**以 byte 數算**，Big5 名字剛好也成立
（全形字兩個 byte 佔兩欄，見 spec 693 的更正）。

## 明確不宣稱

- 沒有宣稱 `0542h:0946h`（顯示 `'press <enter>…'` 那一支）與
  `0542h:0B4Ah` 的參數意義。
- 沒有宣稱 `DS:49B3h` 那張表共有幾筆。
- 沒有宣稱 `0418h:14AAh` 與 `overlay-24 entry#21`（非戰鬥分支的兩個收尾呼叫）
  做什麼。
- 沒有宣稱 `overlay-24 entry#22` 的四個參數。
