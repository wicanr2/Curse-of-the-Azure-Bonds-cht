# 932 — 常駐的低階文字輸出層，與一支除錯用的效果鏈傾印

- 證據等級：`exact`（逐條讀完；字串取自 `START.EXE.asm` 的資料定義）
- 位置：DOS `START.EXE` 的 `1639Ah`、`16408h`、`16498h`、`16F03h`
- 作法見 spec 783

## `1639Ah`（40 條）：寫一個字元 —— `retf 0Ah`

```pascal
寫字元(字元, 次數, 顏色, 列, 欄);

Regs.AH := 2;   Regs.BH := 0;
Regs.DH := 列;  Regs.DL := 欄;
Intr(10h, Regs);                       { AH=02h 設游標 }

Regs.AH := 9;   Regs.AL := 字元;  Regs.BH := 0;
if byte_211A6 = 0 then
    Regs.BL := byte[256Dh ＋ 顏色]     { ★ 顏色轉換表 }
else
    Regs.BL := 顏色;
Regs.CX := 次數;
Intr(10h, Regs);                       { AH=09h 寫字元與屬性 }
```

`Registers` record 的版面由用法直接讀出：

| 位址 | 欄位 |
|---|---|
| `byte_2118Ah` / `byte_2118Bh` | `AX.lo` / `AX.hi` |
| `byte_2118Ch` / `byte_2118Dh` | `BX.lo` / `BX.hi` |
| `word_2118Eh` | `CX` |
| `byte_21190h` / `byte_21191h` | `DX.lo` / `DX.hi` |

★ **`byte_211A6h` ＝ 0 時顏色要先過 `DS:256Dh` 的轉換表**——
形狀上是單色／CGA 顯示卡的調色盤映射。remake 若要重現原版配色，
這張表是必須的一層。

## `16408h`（44 條）：寫一個字串 —— `retf 0Ah`

```pascal
寫字串(字串, 顏色, 列, 欄);

s := 限長(字串, 0FFh);
for i := 1 to length(s) do begin
    寫字元(s[i], 1, 顏色, 列, 欄);
    inc(欄);
end;
```

**一次一個字元、每次都重設游標並呼叫兩次 `int 10h`**——
所以整行輸出是 `2 × 長度` 次 BIOS 呼叫。這與 spec 930／931 那條
「累積成一段再 `rep movsw`」的 Crt 路徑是**兩套並存的輸出層**，
本支走 BIOS、那一套直接寫顯示記憶體。

## `16498h`（48 條）：底列提示 —— `retf 6`

```pascal
底列提示(字串, 顏色);

s := 限長(字串, 28h);                   { 40 欄 }
<sub_16478h>(28h, 0, 18h, 0);           { 清列 24 的 40 欄 }
寫字串(s, 顏色, 18h, 0);
按鍵 := <sub_16FADh>();                 { ⚠ 回傳值存進區域變數後沒有再用 }
<sub_16478h>(28h, 0, 18h, 0);           { 再清掉 }
```

`18h` ＝ **第 24 列**（0 起算的最後一列，80×25 文字模式）。
字串限長 `28h` ＝ 40，比畫面寬度窄一半——**這一層假設 40 欄**。

⚠ 等到的按鍵被丟棄，所以呼叫端無法知道玩家按了什麼。

## `16F03h`（51 條）：除錯用的效果鏈傾印 —— `retf 4`

```pascal
p := 角色^[0F2h];
while p <> NIL do begin
    Write(Output, 'who: ');
    Write(Output, 角色^);               { ★ 當成 Pascal 字串寫出 }
    Write(Output, '  sp#: ');
    Write(Output, longint(p^[0]));
    WriteLn(Output);
    p := p^[5];
end;
```

字串定義（`START.EXE.asm`）：

```
aWho  db 5,'who: '
aSp   db 7,'  sp#: '
```

三件事同時被確認：

1. **`+0F2h` 是效果鏈，next 在 `+5`**——與 spec 849 的解構子逐格吻合。
2. **效果節點的 `+0` 是法術編號**（原版自己印成 `sp#`），
   spec 849 只寫「效果碼」，這裡拿到原作者的用詞。
3. **角色記錄的 `+0` 起就是名字**（同一個指標直接當 `String` 傳給 `Write`）。

這一支輸出到 `Output`，**不是遊戲畫面**——是開發時留下的除錯程式碼。
沒有任何遊戲流程會呼叫它（本規格沒有查呼叫端）。

## 明確不宣稱

- 沒有宣稱 `DS:256Dh` 那張顏色轉換表的內容與長度。
- 沒有宣稱 `byte_211A6h` 由誰設定（形狀上是「偵測到的顯示卡種類」）。
- 沒有宣稱 `sub_16478h`（清一段）與 `sub_16FADh`（等按鍵）的內部。
- 沒有宣稱 `16F03h` 有沒有呼叫端。
