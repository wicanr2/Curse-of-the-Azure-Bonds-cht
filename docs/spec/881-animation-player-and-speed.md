# 881 — 動畫播放迴圈：遊戲速度值 `DS:4FA9h` 在這裡變成每格的等待時間

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側多一個倍率）
- 作法見 spec 783

## `overlay-18:00B5Fh` ↔ `overlay-18:00A6Fh`（DOS 109 條／PC-98 114 條）

`overlay-18` ＝ ENDSTUFF。`retf 8` ＝ 4 個 word，依推入順序宣告：
`(座標B, 座標A, 序號, 圈數)`。唯一的字串是 `'PIC'`。

```pascal
圈 := 0;
t0 := <far 0542h:0994h>();                        { 現在時間，longint }
FillChar(@動畫, 42h, 0);
暫 := 'PIC';
<far 0179h:0034h>(@動畫, 2, 序號);                { 載入動畫序列 }

<far 0297h:09E4h>(遠指標(DS:4FE8h), 動畫的某一格,
                  0, 0, 座標A − 1, 座標B − 1);
<far 0297h:1316h>();

repeat
    i := 動畫[1];                                 { 目前是第幾格 }
    <far 0179h:0025h>(格[i], 1, 座標A, 座標B);    { 畫出來 }

    t := <far 0542h:0994h>();
    門檻 := 每格延遲[i] * (DS:4FA9h ＋ 3);         { 0A54h:0279h，longint 乘 }

    if t − t0 > 門檻 then begin                    { longint 有號比較 }
        inc(動畫[1]);
        if 動畫[1] > 動畫[0] then begin            { 無號：播完一輪 }
            動畫[1] := 1;  inc(圈);
        end;
        t0 := t;
    end;
until 圈 = 圈數;

<far 0179h:0039h>(@動畫);                          { 釋放 }
```

## 關掉 spec 879 的「速度值怎麼影響遊戲」

`DS:4FA9h` 就是 spec 879 那個 `GameSpeed` 選單調的值（0..9）。
這裡是它的消費端：**每格的等待門檻 ＝ 該格的延遲 × (速度值 ＋ 3)**。

- 速度值 0 → 倍率 3（最快）
- 速度值 9 → 倍率 12（最慢）

879 讀到「`Slower` 走 `inc`、`Faster` 走 `dec`，值越大越慢」——
**這裡是那個推論的直接證據**，不再只是從選單字串反推。

## 動畫描述是 42h ＝ 66 bytes

`動畫[0]` 是總格數、`動畫[1]` 是目前格，之後每格 **8 bytes**
（索引時 `shl di, 3`），含圖指標與該格的延遲。
`(66 − 2) ÷ 8 = 8`，所以**最多 8 格**。

## ⚠ PC-98 多乘一個全域倍率

PC-98 在算門檻時多一步：

```asm
mov ax, ds:0BE2Ah
xor dx, dx
call far ptr 0A65h:027Eh      ; longint 乘法
```

也就是 `門檻 := 每格延遲 × (速度值 ＋ 3) × DS:0BE2Ah`。
DOS 沒有這個倍率。形狀上是**機器速度校正係數**——
PC-98 機種的時鐘頻率差異很大（8 MHz／10 MHz／16 MHz 都有），
需要一個執行期的調整值。**本規格不宣稱那一格由誰設定**。

remake 若要重現原速，DOS 與 PC-98 的節拍公式不同，要各做一套。

  （形狀上依序是 載入動畫／畫一格／釋放）。
- 沒有宣稱 `'PIC'` 怎麼組進檔名（本支只建了字串，沒有看到串接）。
