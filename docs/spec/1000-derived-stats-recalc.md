# 1000 — 角色派生數值重算：裝備槽、負重、命中／傷害加值

- 證據等級：`exact`（DOS 側 391 條逐條讀完；PC-98 對側 390 條相似度 0.988）
- 作法見 spec 783

## `dos overlay-24:00C28h` ↔ `pc98 overlay-24:00E47h`（`retf 4`，參數是角色遠指標）

兩側原本都是待解讀。這一支把物品鏈掃一遍，重算所有派生欄位——
**它是 spec 694／697／974 那三張 AD&D 表與執行期欄位之間的接點**。

### 一、清空並掃物品鏈

```pascal
for i := 0 to 0Ch do 角色^[151h ＋ 4i] := NIL;      { ★ 13 個裝備槽 }
角色^[14Ch] := 0;                                    { 物品數 }
角色^[185h] := 0;
角色^[187h] := 0;                                    { 總重 }
DS:4CB8h    := 0;                                    { 已裝備的重量 }

q := 角色^[14Dh];
while q <> NIL do begin
    inc(角色^[14Ch]);
    w := q^[37h];                                    { 單位重量，word }
    if q^[39h] > 0 then w := w × q^[39h];            { × 數量 }
    角色^[187h] += w;

    if q^[34h] <> 0 then begin                       { 已裝備 }
        DS:4CB8h += w;
        槽 := byte[5CF6h ＋ q^[2Eh] × 10h];
        if (槽 >= 0) and (槽 <= 8) then 角色^[151h ＋ 槽×4] := q
        else if 槽 = 9 then begin                    { ★ 雙持特例 }
            if 角色^[175h] = NIL then 角色^[175h] := q
            else if 角色^[179h] = NIL then 角色^[179h] := q;
        end;
    end;

    if q^[2Eh] = 49h then 角色^[17Dh] := q;          { 類別 73 的專屬槽 }
    if q^[2Eh] = 1Ch then 角色^[181h] := q;          { 類別 28 的專屬槽 }
    角色^[185h] += byte[5CF7h ＋ q^[2Eh] × 10h];

    q := q^[2Ah];
end;
```

★★ **裝備槽是 `+151h` 起的 13 個遠指標**（`+151h`..`+183h`，每個 4 bytes）。
`DS:5CF6h` 那張以物品類別為索引、**每筆 16 bytes** 的表決定槽位；
spec 683 的 `byte[arg_0^[2Eh] × 16 ＋ 5CF6h] <> 2` 用的是同一張表的 `+0`。
**表的 `+1` 是「這件裝備佔幾隻手」**，累加到 `+185h`（spec 1004 由
`overlay-09:01681h` 的反向扣除與 `> 2` 分支證實，上限是兩隻手）。

★ **槽 9 是雙持**：第一件放 `+175h`（＝ `151h ＋ 9×4`），
第二件放 `+179h`（第 10 格）。所以「槽 9」在表上只有一個編號，
實際佔兩個指標格。

### 二、錢也算重量

```pascal
for i := 0 to 6 do 角色^[187h] += word[角色 ＋ 0FBh ＋ 2i];
```

七種貨幣（`+0FBh ＋ j×2`，既有結論）的**數量直接加進總重**——
不是重量、是枚數。AD&D 的硬幣本來就是 10 枚 ＝ 1 磅那一類換算，
本作直接把枚數當重量單位。

### 三、基準值複製到現值

```pascal
for i := 1 to 2 do begin
    角色^[19Dh ＋ i] := 角色^[11Dh ＋ i];
    角色^[19Fh ＋ i] := 角色^[11Fh ＋ i];
    角色^[1A1h ＋ i] := 角色^[121h ＋ i];
end;
角色^[186h] := 0;
角色^[19Ah] := 角色^[124h];
角色^[1A5h] := 角色^[0E4h];      { 移動力基準，spec 683 的 +1A5h }
角色^[199h] := 角色^[73h];
```

**`+11Dh`／`+11Fh`／`+121h` 是基準、`+19Dh`／`+19Fh`／`+1A1h` 是現值**，
每組兩格。spec 1001 把三組定名了：**骰數／面數／傷害加值**，
索引 1 是第一把武器（`+19Eh`／`+1A0h`／`+1A2h`）、索引 2 是第二把
（`+19Fh`／`+1A1h`／`+1A3h`）——與本支槽 9 的兩個指標格（`+175h`／`+179h`）對應。

### ★ 四、力量加值只在「第 0 槽是空的」時候才加

```pascal
var_D[0] := <本模組 117Ah>(角色);                     { 敏捷防禦調整，spec 694 }
if 角色^[151h] = NIL then begin                       { ★ 第 0 個裝備槽 }
    角色^[199h] += <本模組 1345h>(角色);              { 力量命中，spec 697 }
    角色^[1A2h] += <本模組 13FDh>(角色);              { 力量傷害，spec 694 }
end;
```

**`+199h` ＝ 命中能力（畫面上的 THAC0 是 `60 − 它`，見 spec 1001）、
`+1A2h` ＝ 傷害加值**，各自由 `+73h` 與基準值起算。
⚠ 第 0 槽有東西時，力量的命中與傷害調整**完全不加**——
形狀上是「拿著特定裝備就改用裝備的數值」。本規格不宣稱第 0 槽是什麼。

### 五、每件已裝備的物品再過兩支

```pascal
<本模組 0025h>(角色);
q := 角色^[14Dh];
while q <> NIL do begin
    if q^[34h] <> 0 then begin
        <本模組 021Dh>(q, 角色);
        <本模組 02A7h>(@var_7, @var_D, q, 角色);
    end;
    q := q^[2Ah];
end;
```

### ★ 六、5000 的負重減免

```pascal
if var_8 <> 0 then begin
    if 角色^[187h] < 1388h then 角色^[187h] := 0
    else                        角色^[187h] -= 1388h;      { 1388h ＝ 5000 }
    if 角色^[187h] < DS:4CB8h then 角色^[187h] := DS:4CB8h;
end;
```

**條件成立時總重直接減 5000，但不會低於「已裝備物品的重量」。**
5000 這個數字與 spec 974 的負重加值表（最高 15000）同一個量級。

⚠ **這一支走不到這個分支**：`var_8` 在函式開頭設 0 之後沒有任何地方再寫它，
而四個被呼叫的子函式拿到的是角色／物品的遠指標與 `@var_D`
（寫 `[bp−0Dh]`..`[bp−09h]`）、`@var_7`（寫 `[bp−07h]`），都碰不到 `[bp−08h]`。

### ★★ 七、兩個護甲欄位

`var_D` 是 `[bp−0Dh]` 起的**五個位元組**，依位址往上就是
`var_D`／`var_C`／`var_B`／`var_A`／`var_9`。五格由兩個地方填：

| 格 | 誰填 | 內容 |
|---|---|---|
| `[0]` | 本支 | `117Ah(角色)` ＝ **敏捷防禦調整**（spec 694，敏捷高就是正值） |
| `[1]` | `02A7h` | 物品類別表 `+0` ＝ **1** 那一槽：`物品^[32h] ＋ 加值` |
| `[2]` | `02A7h` | 加值 ＝ 0 且 `+0` ≠ 9 的物品，**累加** `物品^[32h]` |
| `[3]` | `02A7h` | 加值 ＝ 0 且 `+0` ＝ 9 的物品，取最大值 |
| `[4]` | `02A7h` | 加值 ≠ 0 的物品取最大值 |

```pascal
if var_7 <> 0 then var_D[3] := 0;                     { 02A7h 設過輸出旗標就清掉 }
<本模組 03C5h>(角色);
if var_D[4] < 角色^[19Ah] then var_D[4] := 角色^[19Ah];   { 夾底到 +124h }
角色^[19Ah] := 0;
for i := 0 to 4 do 角色^[19Ah] += var_D[i];            { 五格全加 }
角色^[19Bh] := var_D[4] ＋ var_D[2] ＋ var_D[3] − 2;   { ★ 少了 [0] 與 [1] }

if ((角色^[10Bh] > 0) or ((角色^[113h] > 0) and <overlay-25 entry#10>(角色)))
   and (角色^[74h] > 0) then
    角色^[0DDh] := 角色^[10Bh] ＋ 角色^[113h] × <overlay-25 entry#10>(角色)
else
    角色^[0DDh] := 1;
```

`+74h` 是種族（spec 998）。`+0DDh` 的預設值是 `1`，
只有在 `+10Bh`／`+113h` 有值時才算出別的——形狀上是**每回合攻擊次數**，
本規格不宣稱。

### ★★ `+19Bh` 就是背後攻擊用的那個 AC

兩式相減得到

> **`+19Bh` ＝ `+19Ah` − 敏捷防禦調整 − 類別 1 那一槽 − 2**

而攻擊結算（`overlay-13:14E8h`，spec 1137）在背後攻擊三道條件成立時改用
`+19Bh`。類別 1 是盾牌那一槽（spec 1120 的自動換裝把 `+0` ＝ 1 當成盾牌統計）。
所以第二個 AC ＝ **不算敏捷、不算盾牌，再 −2**——AD&D 1e 的背後攻擊正是
抵銷這兩項加值並給 ＋2 命中。

儲存值的方向是**越大防禦越好**：畫面顯示的 AC 是 `60 − 儲存值`
（spec 767 讀的是 PC-98 的 `+19Bh`，而 PC-98 在 `+11Ch` 之後整體 ＋1，
對應 DOS 的 `+19Ah`）。減 2 讓儲存值變小，也就是防禦變差。

**拿原作資料量過**：六章 `MON*CHA` 共 81 筆記錄，78 筆的殘差
（`+19Ah − 敏捷防禦調整 − 2 − +19Bh`）是 0，另外三筆是 1、1、2
（DARK ELF LORD 兩筆與 TYRANTHRAXUS）——正好是 ＋1／＋2 盾牌會產生的值。
`+19Bh` 為 0 的一筆也沒有。回歸測試在
`internal/monster/armor_class_facing_test.go`。

## 這一支接起來的既有結論

| 既有規格 | 在這裡的角色 |
|---|---|
| spec 694（敏捷表、傷害表） | `117Ah`／`13FDh` 的呼叫端 |
| spec 697（命中表） | `1345h` 的呼叫端 |
| spec 974（負重表） | 同一組 `+187h` 總重欄位 |
| spec 683（負重決定移動力） | `+1A5h` 在這裡被設成 `+0E4h` |
| spec 832（物品節點 `+2Eh`／`+34h`／`+39h`） | 掃鏈時全部用到 |
| spec 998（`+74h` 種族） | 最後一段的條件 |

## 明確不宣稱

- 沒有宣稱 13 個裝備槽各對應哪個部位（表在 `DS:5CF6h`，內容未讀）。
- 沒有宣稱物品類別 `49h`／`1Ch` 是什麼。
- ~~`+185h`~~ → spec 1004：佔用的手數（上限 2）。~~`+19Ah`／`+19Bh`~~ → 見上：
  兩個護甲欄位，第二個是背後攻擊用的。仍沒有宣稱 `+0DDh`。
- 沒有宣稱 `本模組 0025h`／`021Dh`／`02A7h`／`03C5h` 做什麼
  （`02A7h` 會回填 `var_7` 與 `var_D` 那五格）。
- 沒有宣稱 `var_8` 在別的呼叫路徑上會不會被設成非 0；只宣稱**本支**設不到。
- 沒有宣稱物品類別表 `+0` 的其他值（2、9）各代表哪個部位。
- 沒有宣稱 `overlay-25 entry#10` 回傳什麼。
