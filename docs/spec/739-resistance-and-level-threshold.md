# 第七百三十九輪：減傷、武器判定，與第二個會回捲的門檻

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：DOS `overlay-12` 的 `1374h`、`24B9h`、`2334h`。

## `2334h`：`(11 − 等級) × 5 + arg_0`

```text
lvl    := <overlay-24 entry#36>(DS:6F97h)
門檻   := (0Bh − lvl) × 5 + arg_0            ← 存進一個 byte
if DS:6F93h <> 0 或 (DS:6F95h and 8) <> 0 then
    if ROLLDICE(1, 100) <= 門檻 then <sub_1Bh>(0)
```

等級越高門檻越低，`lvl = 11` 時門檻就是 `arg_0`。

**但門檻只有 8 bit。** `lvl > 11` 時 `(0Bh − lvl) × 5` 是負數，存進 byte 之後
變成很大的值：

| `lvl` | 算式值 | 存成 byte | `1d100 <= 門檻` |
|---|---|---|---|
| 11 | `0 + arg_0` | `arg_0` | 依 `arg_0` |
| 12 | `−5 + arg_0` | `0FBh + arg_0` | **幾乎必定成立** |
| 15 | `−20 + arg_0` | `0ECh + arg_0` | **幾乎必定成立** |

也就是**高等級不但沒有變安全，反而變成一定會觸發**。這是繼 spec 705 `30C0h`
之後第二個同型的問題：**百分比算式的中間值超出 byte 範圍而沒有夾限**。

兩處的成因一樣、方向也一樣（極端值翻轉），所以這應該當成本作的**共通模式**
處理，而不是兩個獨立的 bug。remake 要先決定整體策略：全部照抄回捲，或全部夾成
`0..100`；混著做會產生原作沒有的行為組合。

## `1374h`：每一輪扣 2，扣到地板為止

```text
if (DS:6F95h and 1) <> 0 then                ← 傷害旗標 bit 0
    n := DS:6F98h
    for i := 1 to n do
        DS:6F94h := DS:6F94h − 2
        if DS:6F94h < DS:6F98h then DS:6F94h := DS:6F98h   ← 無號比較
    DS:6F92h := DS:6F92h + 4
    if (DS:6F95h and 8) = 0 then <sub_1Bh>(0)
```

`DS:6F98h` **同時是迴圈次數和傷害下限**。所以「扣 2 × n 次」和「不得低於 n」是
同一個數字控制的，兩者不能拆開改。

夾限用的是**無號**比較（`jnb`）。`DS:6F94h` 減到負數會回捲成大值，那時
`回捲值 >= DS:6F98h` 成立，**夾限不會生效**——迴圈會繼續往下扣。要靠 `n` 夠小
才不會出事。

## `24B9h`：武器決定要不要減半

```text
w := <sub_FAAh>(DS:6506h)                    ← spec 738 的「實際生效的武器」
if w <> NIL then
    t := byte [5CFDh + w^[2Eh] × 16]          ← 物品屬性表格內 +7（基底 5CF6h，spec 700）
    if t = 0 或 (t and 1) <> 0 then
        DS:6F94h := DS:6F94h div 2            ← cwd ＋ idiv 2，往零取整
```

**條件是「`t` 為 0」或「`t` 的 bit 0 為 1」**——兩者都會減半，只有「`t` 非 0 且
bit 0 為 0」才不減。寫成 `(t and 1) <> 0` 單獨判斷會漏掉 `t = 0` 那一半。

除法是有號的 `idiv`，往零取整；`DS:6F94h` 若是奇數會少 0.5 而不是進位。

## 明確不宣稱

- `DS:6F92h`、`DS:6F93h`、`DS:6F98h` 的語意。
- 傷害旗標 `DS:6F95h` 的 bit 0 與 bit 3 各代表什麼。
- `sub_1Bh(0)` 做什麼（`1374h` 與 `2334h` 都在條件成立時呼叫它）。
- 物品表格 `+7` 那個欄位的名稱。
