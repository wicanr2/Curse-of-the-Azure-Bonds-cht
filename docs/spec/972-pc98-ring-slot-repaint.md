# 972 — PC-98 的十格環狀選單：換格時把兩塊 12 bytes 寫回槽緩衝

- 證據等級：`exact`（逐條讀完；環狀表的版面由 `dseg` 靜態 bytes 直接證實）
- 作法見 spec 783

## `pc98 overlay-26:000B4h`（42 條）— 只有 PC-98 有

`retf 2`，而且參數是**父層的 `bp`**——這是 Turbo Pascal 的巢狀程序，
呼叫端一律寫成 `push bp; push cs; call near ptr sub_B4`。
唯一的父層是 `overlay-26:00133h`（581 條），三個呼叫點：`004AFh`、`00755h`、
`0077Bh`。

```pascal
Move(父^[bp − 0A4h], 表[DS:0A386h].緩衝^, 0Ch);   { 上一格 }
Move(父^[bp − 095h], 表[DS:0A385h].緩衝^, 0Ch);   { 目前格 }
DS:0A386h := DS:0A385h;
```

兩次都是 `0A65h:1B0Dh`（Move），`Move(來源, 目的, 數量)` 的順序見 spec 695，
**先推的是來源**——所以資料是**從父層的區域變數寫進槽緩衝**，不是讀出來。

## `DS:15C0h` ＝ 十格環狀表，每格 6 bytes

索引由 `di := 索引 × 6`（`shl 1` ／ `mov si,di` ／ `shl 1` ／ `add di,si`）算出，
`les di,[di+15C0h]` 取的是格內前 4 bytes。父層另外兩處用 `[di+15C4h]` 與
`[di+15C5h]`，把後兩個 byte 也定了下來：

| 格內位移 | 內容 |
|---|---|
| `+0`（4 bytes） | 緩衝遠指標（**靜態全 0，執行期才填**） |
| `+4` | 上一格索引 |
| `+5` | 下一格索引 |

`dseg` 的靜態 bytes（`DS:15C6h` 起，索引 1..10）：

| 索引 | `+4` 上一格 | `+5` 下一格 |
|---|---|---|
| 1 | 10 | 2 |
| 2..9 | i−1 | i＋1 |
| 10 | 9 | 1 |

**首尾相接，是一個 1..10 的雙向環**。索引 0 那 6 bytes（`04 05 02 03 06 07`）
不屬於這張表——實際索引永遠落在 1..10。

`DS:0A385h` ＝ 目前格、`DS:0A386h` ＝ 上一格。spec 825 讀到 PC-98 在戰鬥結束
問話前把**兩格都設成 `0Ah`**（DOS 沒有這兩個 byte），那正是「回到第 10 格、
而且沒有上一格要處理」的重置寫法。第 10 格在 Y/N 選單上就是 `'N'`——
**游標預設停在「いいえ」**（spec 975）。該規格「沒有宣稱那兩個 `0Ah` 是什麼」
可以關掉了。

## 父層怎麼在環上走

`00133h` 的三段呼叫點形狀一致：

```
004A7  DS:0A386h := DS:0A385h        ← 進入時先讓「上一格」＝「目前格」
004AF  sub_B4

0074C  DS:0A385h := 表[DS:0A385h].上一格     { 按鍵 3Ch }
00755  sub_B4

00772  DS:0A385h := 表[DS:0A385h].下一格     { 按鍵 3Dh }
0077B  sub_B4
```

移動之前還有一道略過迴圈：

```
00481  while byte[0A334h + DS:0A385h] = 20h do      { 20h ＝ 半形空白 }
           DS:0A385h := 表[DS:0A385h].上一格;
```

**標籤是空白的格會被跳過**，所以十格裡沒用到的那幾格不會停留游標。

`DS:0A334h` 起的那一段是**選單的熱鍵字串**：呼叫端每次進選單都把一份常數
複製到 `DS:0A335h`、上限 `0Ah` ＝ 10，與這十格一一對應（spec 975 讀
`overlay-17:02B27h` 時補上）。以 Y/N 確認為例，第 6 格是 `'Y'`、第 10 格是 `'N'`，
其餘八格是空白。

## 這一支在做什麼

三個呼叫點都緊接在「目前格換了」之後，而且每次寫的是**兩塊各 12 bytes**：
一塊給剛離開的格、一塊給剛進入的格。第一個呼叫點特意先讓兩個索引相等，
使得「還原上一格」那一次 Move 寫進同一塊緩衝、隨即被第二次 Move 蓋掉——
**進場時只有「套用」沒有「還原」**，這正是初次反白該有的行為。

形狀上就是**選單游標的反白／取消反白**：父層的 `bp−0A4h` 與 `bp−95h`
（相距 `0Fh` ＝ 15 bytes）各存一份 12 bytes 的樣式，槽緩衝指到要塗的位置。
12 這個寬度與 PC-98 文字屬性平面「一格一 byte」相符（見 spec 953），
但**本規格不宣稱那 12 bytes 是屬性還是別的東西**——槽緩衝的配置點沒有讀到。

## 中文化

沒有字串。但 12 這個**固定寬度**要記：如果反白的是文字屬性，中文用全形字時
一列 12 格 ＝ 6 個漢字；選單項的中文長度受這個寬度限制，
與 spec 953「全形字佔兩格」的結論連動。

## 明確不宣稱

- 沒有宣稱槽緩衝指向哪裡（配置點在 `00133h` 之外，未讀）。
- 沒有宣稱那兩塊 12 bytes 的內容。
- 沒有宣稱 `3Ch`／`3Dh` 是哪兩個按鍵（形狀上是上／下或左／右）。
- 沒有宣稱 `overlay-26:00133h` 整支在做什麼（581 條，尚未讀完）。
