# 884 — 轉職資格檢查：三張 AD&D 一版規則表一次到齊

- 證據等級：`exact`（PC-98 側逐條讀完；DOS 側有兩處反組譯錯位，由 PC-98 校正）
- 作法見 spec 783

## `overlay-25:00D2Fh` ↔ `overlay-25:00D17h`（兩平台各 145 條）

`retf 4`。`arg_0` 是**父程序的框架指標**（巢狀程序，用 `ss:[di+6]` 取父的
角色遠指標），`arg_2` 是候選職業碼。回 `al` ＝ 可不可以。

```pascal
角色 := 遠指標(父框架[+6]);
現職 := <本模組 12EEh>(角色);

{ ① 候選不能跟現在同一個 }
ok := (byte[3FF8h ＋ 角色^[74h] * 0Eh ＋ DS:7747h] <> 現職);

{ ② 現職業的需求屬性都要 ≥ 15 }
i := 0;
while i <= 5 do begin                                   { 有號 }
    if byte[4172h ＋ 現職 * 6 ＋ i] >= 9 then           { 無號：這一欄有要求 }
        if 角色^[10h ＋ i*2] <= 0Eh then break;         { 無號：< 15 就不合格 }
    inc(i);
end;
ok := ok and (i > 5);

{ ③ 候選職業的需求屬性都要 ≥ 17 }
i := 0;
while i <= 5 do begin
    if byte[4172h ＋ 候選 * 6 ＋ i] >= 9 then
        if 角色^[10h ＋ i*2] <= 10h then break;         { < 17 就不合格 }
    inc(i);
end;
ok := ok and (i > 5);

{ ④ 角色的陣營要在候選職業的允許清單裡 }
j := 1;
while byte[41D8h ＋ 候選 * 0Ah] >= j do begin           { [0] 是清單長度 }
    if byte[41D8h ＋ 候選 * 0Ah ＋ j] = 角色^[11Bh] then break;
    inc(j);
end;
ok := ok and (j <= 長度);
結果 := ok;
```

## `15` 與 `17` 就是 AD&D 一版的雙職業門檻

`> 0Eh` ＝ **≥ 15**（原職業）、`> 10h` ＝ **≥ 17**（新職業）——
AD&D 一版 dual-class 的規定原文就是這兩個數字。
兩道檢查用同一張需求表、不同門檻，結構上明確是「原職業 / 新職業」兩段。

## `DS:4172h`（PC-98 `DS:7207h`）＝ 職業最低屬性需求，每列 6 bytes

欄位順序與 spec 857 定的屬性版面一致：**力 智 睿 敏 體 魅**。
`0` ＝ 沒有要求（程式用 `>= 9` 當「這一欄有要求」的判準）。
**兩平台逐 byte 相同**：

| 職業碼 | 職業 | 力 | 智 | 睿 | 敏 | 體 | 魅 |
|---|---|---|---|---|---|---|---|
| 0 | Cleric | 6 | 6 | **9** | 0 | 0 | 0 |
| 1 | Druid | 0 | 0 | **12** | 0 | 0 | **15** |
| 2 | Fighter | **9** | 0 | 6 | 6 | 7 | 0 |
| 3 | Paladin | **12** | **9** | **13** | 0 | **9** | **17** |
| 4 | Ranger | **13** | **13** | **14** | 0 | **14** | 0 |
| 5 | Magic-User | 0 | **9** | 6 | 6 | 0 | 0 |
| 6 | Thief | 6 | 6 | 0 | **9** | 0 | 0 |
| 7 | Monk | **15** | 0 | **15** | **15** | **11** | 0 |
| 8 | （多職業第一組） | 9 | 0 | 9 | 0 | 0 | 0 |

**逐格與 AD&D 一版 Players Handbook 的職業需求相符**——
聖騎士的 12/9/13/9/17、遊俠的 13/13/14/14、武僧的 15/15/15/11 都對得上。

## `DS:41D8h`（PC-98 `DS:726Dh`）＝ 職業允許的陣營清單，每列 `0Ah`，`[0]` 是長度

| 職業 | 長度 | 允許的陣營碼 |
|---|---|---|
| Cleric | 9 | 0..8（全部） |
| Druid | 5 | 1, 3, 4, 5, 7 |
| Fighter | 9 | 0..8（全部） |
| **Paladin** | **1** | **0** |
| **Ranger** | **3** | **0, 3, 6** |
| Magic-User | 9 | 0..8（全部） |
| Thief | 7 | 1, 2, 3, 4, 5, 7, 8 |
| Monk | 9 | 0..8（全部） |

### 這張表把陣營編碼定死了

聖騎士只能一種、遊俠只能三種——AD&D 裡分別是
**守序善良**與**全部三種善良**。所以

```
0 = 守序善良   1 = 守序中立   2 = 守序邪惡
3 = 中立善良   4 = 絕對中立   5 = 中立邪惡
6 = 混亂善良   7 = 混亂中立   8 = 混亂邪惡
```

驗證：遊俠的 {0, 3, 6} 正好是三個「善良」；德魯伊的 {1, 3, 4, 5, 7}
正好是五個**名稱裡含「中立」**的陣營（AD&D 原版只准絕對中立，引擎放寬了）；
盜賊排除 {0, 6} 兩個。**三條規則同時成立，編碼不是猜的。**

`角色^[11Bh]` 因此定名為**陣營碼**。

## `DS:3FF8h`（PC-98 `DS:708Dh`）＝ 種族允許的職業組合，每列 `0Eh`，`[0]` 是長度

| 種族碼 | 長度 | 允許的 `+75h` 職業組合碼 |
|---|---|---|
| 1 | 3 | 2, 6, 14 |
| 2 | 7 | 2, 5, 6, 13, 14, 15, 16 |
| 3 | 3 | 2, 6, 14 |
| 4 | **13** | 0, 2, 5, 6, 4, 8, 10, 9, 11, 13, 14, 15, 16 |
| 5 | 3 | 2, 6, 14 |
| 6 | 6 | 0, 2, 6, 8, 12, 14 |
| 7 | 6 | 0, 2, 5, 6, 3, 4 |

**種族 0 那一列不是這張表的內容**（`12 12 64 32 …`），有效範圍是 1..7。

交叉驗證：

- **種族 7 的六個全是單職業**（0 Cleric、2 Fighter、5 Magic-User、6 Thief、
  3 Paladin、4 Ranger），而且是唯一有聖騎士與遊俠的一列——**種族 7 ＝ 人類**。
  人類不能多職業，正是 AD&D 的規則。
- **種族 4 有 13 種、最多**，與 spec 853 讀到的「種族 4 ＝ 半精靈」一致
  （半精靈在 AD&D 的職業選擇最廣）。
- **種族 5 ＝ 半身人**（spec 853）：{Fighter, Thief, 14}，
  而 spec 857 說 `0Ah..0Eh` 是雙職業，所以 14 ＝ 戰士／盜賊。**完全正確。**

種族 1、3、5 三列完全相同，本規格不宣稱它們各是哪一個種族。

## ⚠ DOS 側兩處反組譯錯位

DOS 的 `0E71h` 被解成 `inc byte ptr [bx+si]`、`0E86h` 被解成 `cld`。
PC-98 同位置分別是 `cmp [bp+var_2], 0` 與 `cmp al, [bp+var_4]`。
**又一次由對側平台校正 DOS 的錯位**（同 spec 873）。

## 明確不宣稱

- 沒有宣稱 `本模組 12EEh(角色)` 怎麼算出「現在的職業碼」。
- 沒有宣稱 `DS:7747h` 在呼叫端代表什麼（這裡當種族職業清單的索引，
  spec 862 那裡是 3×3 環走的計數器——**同一格被兩處當不同用途**）。
- 沒有宣稱 `角色^[10h ＋ i*2]` 與 spec 857 的 `+11h` 起那組是什麼關係
  （屬性顯然是每項 2 bytes，本支讀第一個 byte、857 讀第二個）。
- 沒有宣稱 `DS:4172h` 第 9 列（索引 8）屬於哪一種職業組合。
