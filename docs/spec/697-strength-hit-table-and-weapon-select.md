# 第六百九十七輪：力量命中表，與「目前用的是哪件武器」

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：DOS `overlay-24` 的 `1345h`、`30A0h`。

## `1345h`：命中調整，`13FDh` 的雙生子

閘門與索引來源都和傷害調整（spec 694）一樣：`角色^[125h] = 0` 就回 0，
否則 `i := 129Ah(角色)`。

```text
i = 1..3   → −3      i = 4..5   → −2      i = 6..7   → −1
i = 8..16  → 0       i = 17..19 → +1      i = 20..22 → +2
i = 23..25 → +3      i = 26..27 → +4      i = 28..30 → i − 23
```

把索引換算回力量值，與 AD&D 1st edition 的命中調整逐格對照：

| 力量 | 索引 | 本作 | AD&D 1e |
|---|---|---|---|
| 2–3 | 2–3 | −3 | −3 |
| 4–5 | 4–5 | −2 | −2 |
| 6–7 | 6–7 | −1 | −1 |
| 8–16 | 8–16 | 0 | 0 |
| 17 | 17 | +1 | +1 |
| 18 | 18 | +1 | +1 |
| 18/01–50 | 19 | +1 | +1 |
| 18/51–75 | 20 | +2 | +2 |
| 18/76–90 | 21 | +2 | +2 |
| 18/91–99 | 22 | +2 | +2 |
| 18/00 | 23 | +3 | +3 |
| 19 | 24 | +3 | +3 |
| 20 | 25 | +3 | +3 |
| 21 | 26 | +4 | +4 |
| 22 | 27 | +4 | +4 |
| 23 | 28 | +5 | +5 |
| 24 | 29 | +6 | +6 |
| 25 | 30 | +7 | +7 |

**十八格全中**，與傷害表一樣只有力量 1 被併進 2 的格子（1e 給 −5，本作 −3）。

至此 `129Ah` ＋ `13FDh` ＋ `1345h` 三支合起來就是完整的 AD&D 1e 力量表，
可以直接照著實作，不必再查規則書。

`+125h` 這道開關、原版存檔的逐項驗證與 remake 對照都寫在 spec 694。
三張表在共用 engine 的 `combat/ability`。

## `30A0h(結果, 角色)`：決定實際生效的武器

```text
結果^ := NIL
f := 0
p := 角色^[151h]
if p <> NIL then
    f := byte [5D04h + p^[2Eh] shl 4]        ← spec 691 那張 16 bytes 一格的表，格內 +2
    if (f and 10h) <> 0 then 結果^ := p
    if (f and 08h) <> 0 then
        if (f and 01h) <> 0 then 結果^ := 角色^[17Dh]
        if (f and 80h) <> 0 then 結果^ := 角色^[181h]
回傳 (結果^ <> NIL) 或 (f = 0Ah)
retf 8
```

幾個容易讀錯的地方：

- **`f = 0Ah` 是整個 byte 相等**，不是 `(f and 0Ah) = 0Ah`。寫成遮罩比較會把
  `0Bh`、`1Ah` 這些值也算進去。
- 三個 `if` 是**依序覆蓋**而不是互斥分支：`f` 同時有 `10h`、`08h`、`80h` 時，
  最後留下的是 `角色^[181h]`。
- `f` 在 `p = NIL` 時維持 0，所以那條路徑上 `f = 0Ah` 永遠不成立，回傳 0。
- 回傳值是「有沒有找到」，武器本身從 `結果` 這個 var 參數帶出去——和 spec 692
  的 `2396h` 同一個模式。

`+17Dh` 與 `+181h` 是角色紀錄裡的兩個 far 指標，相差 4。

## 明確不宣稱

- `DS:5D04h` 那個 bitfield 各位元的意義（本輪只確定 `01h`／`08h`／`10h`／`80h`
  四個被讀，以及 `0Ah` 這個整值特例）。
- `+17Dh`／`+181h` 各自是什麼槽位。
- `+125h` 是什麼（`1345h` 與 `13FDh` 共用的閘門）。
