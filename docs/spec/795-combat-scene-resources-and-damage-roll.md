# 795 — 戰鬥場景資源名（`DungCom` / `WildCom` / `RandCom`）、傷害擲骰與倍數

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側的運算元差異已逐條列出）
- 作法見 spec 783

## `overlay-10:102Fh`（entry#19，72 條，差異 19 條）— 進戰鬥前的場景載入

```pascal
if word(DS:4F99h^[1CCh]) <> 0 then begin
    暫存 := 'DungCom';   <sub_198A>(1, 0, 19h);
end else begin
    暫存 := 'WildCom';   <sub_198A>(1, 0, 21h);      { PC-98 是 22h }
end;
暫存 := 'RandCom';       <sub_198A>(1, 22h, 6);
GetMem(DS:6E92h, 4E9h);                              { 7 + 1250 }
DS:6E92h^[4] := 0;
DS:6E92h^[5] := 1;
DS:6E92h^[6] := 0;
if word(DS:4F99h^[1CCh]) <> 0 then <sub_08C9>() else <sub_0FC7>();
```

`retf`（無參數）。

### 三個資源名兩平台一字不改

| 名稱 | 長度 | 何時用 |
|---|---|---|
| `DungCom` | 7 | `DS:4F99h^[1CCh]` ≠ 0（地城） |
| `WildCom` | 7 | `DS:4F99h^[1CCh]` ＝ 0（野外） |
| `RandCom` | 7 | 兩種情形都載入 |

**PC-98 版原封不動保留這三個 ASCII 名稱**——它們是資源／檔案識別，不是畫面
文字。中文化**不能動**。這是本專案第一次在 overlay 內嵌字串裡遇到「PC-98 沒有
翻譯」的一組，正好當成「哪些字串該翻、哪些不該翻」的判準：**PC-98 版有沒有
改，就是最直接的證據。**

### 一個平台常數差異

`WildCom` 那一路的第三個參數 DOS 是 `21h`、**PC-98 是 `22h`**（`DungCom` 兩邊
都是 `19h`）。兩平台在這一支不是同一份，這個值必須各自照抄。

### 緩衝區配置與 spec 786 對上

`GetMem(DS:6E92h, 4E9h)` ＝ `7 + 1250`，正是 spec 786 定下的
**50 欄 × 25 列螢幕格緩衝 ＋ 7 bytes 表頭**。表頭的 `+4` / `+5` / `+6` 在這裡被
初始化成 `0` / `1` / `0`（`+2` / `+3` 的戰場原點由別處寫入，spec 750）。

### 字串是 `sub_198A` 的第一個參數

`0A54h:0634h(@區域字串, @字串常數)` 把常數複製到區域字串，**並把目的位址留在
堆疊上**（推導見 spec 803）。它在三個 `push` 之前呼叫，所以那個字串位在堆疊最
深處 ＝ **第一個宣告參數**：`sub_198A(資源名, 1, 0, 19h)`。

## `overlay-13:0192h`（entry#3，74 條，差異 14 條）— 傷害擲骰

`retf 0Ah` ＝ 5 個 word。依宣告順序：`(角色遠指標, 參數4, 參數2, 武器索引)`。

```pascal
傷 := <1461h+1>(角色^[19Dh + i], 角色^[19Fh + i]) + 有號(角色^[1A1h + i]);
DS:6F94h := 傷;
{ 這裡有一段 if 傷 < 0 then 傷 := 0，但編譯成 cmp/jnb，永遠跳過 }
if <本模組 28C3h>(參數2, 參數4, 角色) then begin
    m := 有號(<far 1652h>(角色));
    倍 := ((有號(角色^[117h]) * m + 有號(角色^[10Fh]) − 1) div 4) + 2;   { 有號除法 }
    DS:6F94h := DS:6F94h * 倍;
end;
DS:6F95h := 0;
<1442h+2>(角色, 4);
<1442h+2>(參數2, 參數4, 5);
```

### 每種攻擊有三個並排的 byte 陣列

以 `武器索引` 直接當位移（**不乘 2**）：

| 位移 | 內容 |
|---|---|
| `+19Dh + i` | 擲骰的第一個參數 |
| `+19Fh + i` | 擲骰的第二個參數 |
| `+1A1h + i` | 加值（有號） |

三個陣列相距 2，所以 `i` 的合法範圍是 `0..1`——**每個角色兩組攻擊資料**。

### 倍數式子

`((L2 × m + L1 − 1) div 4) + 2`，其中 `L1` ＝ `+10Fh`、`L2` ＝ `+117h`
（相距 8，就是既有的第一／第二職業區塊）。`m = 0` 時式子化簡成
`((L1 − 1) div 4) + 2`：等級 1–4 ＝ ×2、5–8 ＝ ×3、9–12 ＝ ×4、13+ ＝ ×5。

### 缺陷：負傷害的夾制寫了但編不到

`cmp byte ptr ds:6F94h, 0` ／ `jnb` ——`cmp` 對 0 一定得到 `CF = 0`，所以 `jnb`
**必定跳過**，後面那句 `mov byte ptr ds:6F94h, 0` **永遠執行不到**。

也就是說：**加值 `+1A1h+i` 是負且大於骰出來的點數時，傷害會迴繞成很大的
無號值**，而不是被夾成 0。remake 若要對齊原版行為就得保留這個迴繞；若要修，
必須明確記成刻意的偏離。

## 明確不宣稱

- 沒有宣稱 `DS:4F99h^[1CCh]` 的其他值代表什麼；只確定 0 與非 0 兩條路。
- 沒有宣稱 `sub_198A` 三個參數的意義，也沒有宣稱 `19h` / `21h` / `22h` / `6` 是什麼。
- 沒有宣稱 `1461h+1` 兩個參數哪個是骰數哪個是面數。
- 沒有宣稱 `far 1652h` 回傳的 `m` 是什麼；只確定它參與上面那個式子。
- 沒有宣稱 `DS:6F94h` / `DS:6F95h` 由誰讀。
