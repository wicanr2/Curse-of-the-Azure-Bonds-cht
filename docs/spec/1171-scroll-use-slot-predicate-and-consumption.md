# 1171 — 卷軸的 `USE`：判別看**裝備槽**、名字編號就是剩餘支數

- 證據等級：`exact`（判別、列表、消耗三支逐條讀完；`+30h`／`+35h` 的值由六章
  原版物品資料逐件核對）
- 上游：spec 921（USE 的分派與失敗判定）、spec 1120（類別表 `DS:5CF6h`）、
  spec 1168、spec 1170
- 產物：`internal/game/combat_use_scroll.go`、
  [`docs/audit/combat-item-use.md`](../audit/combat-item-use.md)

## ★★ 「是不是卷軸」判的是類別表的第一格

`overlay-22 entry#6`（`612Eh`，`retf 4`）：

```pascal
function 是卷軸(物品: 遠指標): byte;
begin
    if 物品 = NIL then 結果 := 0
    else begin
        槽 := byte[5CF6h ＋ 物品^[2Eh] × 16];      { 類別表的 +0 ＝ 裝備槽 }
        結果 := (槽 > 0Ah) and (槽 < 0Eh);          { 0Bh..0Dh }
    end;
end;
```

`DS:5CF6h` 就是遊戲 image 的 `ITEMS` 成員（spec 1120），筆距 16，`+0` 是裝備槽。

⚠ **不能用物品類別去判。** 六章的資料裡：

| 物品類別 | 槽 | 名字 | 原作怎麼看它 |
|---|---:|---|---|
| `3Dh` | `0Bh` | `Magic User Scroll` | 卷軸 |
| `3Eh` | `0Ch` | `Clerical Scroll` | 卷軸 |
| **`3Ch`** | **`0Ah`** | **`Scroll`** | **充能物品**（效果 `5Fh`／`60h`）|

所以正確的數字是**卷軸 12 件、充能 18 件**，不是 15／15。

## 三個效果槽就是三支法術

`overlay-22:08A1h` 逐格看 `物品^[3Ch]`／`[3Dh]`／`[3Eh]`（＝ `Affects[0..2]`），
非 0 的就列進選單。選單本體是 `overlay-19:3474h`，一支通用的法術挑選器——
它的標題字串把用途講得很清楚：

| 參數 | 標題 |
|---:|---|
| 0 | `in Memory` |
| 1 | `in Grimoire` |
| **2** | **`on Scroll`** |
| 3 | `on Scrolls` |
| 4 | `to Choose` |
| 5 | `to Memorize` |
| 6 | `to Scribe` |

USE 傳的是 **2**。

## ★★ `+35h` 一個位元組管兩件事

列表之前先過一道：

```pascal
if <找節點>(@有, 10h, 施法者) <> 0 then           { 法術辨識 }
    物品^[35h] := 0
else if (施法者^[109h] > 0) or (施法者^[111h] > 施法者^[0E6h]) then
    if byte[5CF6h ＋ 物品^[2Eh] × 16] = 0Ch then  { 牧師卷軸 }
        物品^[35h] := 0;

if 物品^[35h] <> 0 then 離開;                      { 一支都列不出來 }
```

`+35h` 是**隱藏名稱旗標**（`HiddenNameFlags`）。所以同一個位元組同時決定：

- 看不看得到卷軸上有哪些法術；
- 玩家看到的是 `Magic User Scroll` 還是 `Magic User Scroll With 3 Spells`。

資料佐證：第 2、5 章的卷軸 `+35h = 06`（名字被截短），第 3、4 章的
`+35h = 00`（名字帶 `With 3 Spells`）。**辨識與命名不是兩個欄位，是同一個。**

## ★★ 名字編號就是剩餘支數

`overlay-22 entry#7`（`617Bh`，`retf 0Ah`）：

```pascal
procedure 唸掉一支(效果: byte; 物品, 角色: 遠指標);
begin
    槽 := 0;
    for i := 1 to 3 do
        if (物品^[3Bh + i] and 7Fh) = 效果 then 槽 := i;
    if 槽 = 0 then 離開;

    物品^[3Bh + 槽] := 0;
    dec(物品^[30h]);
    if 物品^[30h] < 0D2h then <丟掉物品>(物品, 角色);
end;
```

`+30h` 是 `NameNumbers[1]`，六章每一張卷軸都是 **`0D4h`**。所以

```
0D4h → 0D3h → 0D2h → 0D1h < 0D2h ⇒ 丟掉
```

**唸完第三支才會消失**，而中間那兩步同時把名字從「三支」變成「兩支」「一支」。
`0D2h` 這個常數不是魔術數字，是 `0D4h − 2`。

## ★★★ 失敗判定就是 AD&D 1e 的卷軸規則

spec 921 已錄的三條路，配上職業槽的偏移（`+109h ＋ c` 是八個職業槽）：

| 條件 | 槽 | 結果 |
|---|---|---|
| `+109h > 0` | 牧師 | 一定成功 |
| `+10Eh > 0` | 法師 | 一定成功 |
| `+10Fh > 9` | **盜賊，10 級以上** | 1d100 ≤ 75 |
| 其餘 | | 一定失敗，只印 `'oops!'` |

1e 的「十級以上盜賊有 75% 機率讀得懂卷軸」就是中間那一條。remake 的
`ClassLevel` 索引（牧師 0、法師 5、盜賊 6）與這三個偏移一一對應。

⚠ 失敗時 `結果^` 保持 0 ⇒ **消耗那一段整個跳過**，卷軸不會被吃掉。

## remake 這一側

- 判別改查類別表（`BaseItemCatalog.IsScroll`），不再用物品類別。
- 唸卷軸與記憶施法**選目標的方式一樣**：game pack 宣告過的 73 支走既有那條，
  沒宣告的才落到 `+6`／`+7`（spec 1170）。
- 結算走同一條 `resolveChargedItem`，等級一樣是 6。
- `U` 使用、`Alt+U` 換物品、`Alt+S` 換要唸的法術。

## 明確不宣稱

- 條件 B 的第二個析取項 `+111h > +0E6h` 沒有讀出來；remake 只實作
  「牧師槽有等級」那一半，多職角色可能比原作嚴格一格。
- 沒有宣稱 `+35h` 被設成非 0 的地方在哪（本支只清不設）。
- 沒有宣稱 `overlay-19:3474h` 的選單互動細節（remake 有自己的 UI）。
- 骰數算出來的法術（火球、閃電、魔法飛彈）走 remake 專屬結算；其餘
  `+0Ah = 0` 而收尾不是標準那兩支的法術唸不出來，會回錯誤且**不消耗卷軸**。
