# 756 — `FillChar 4E2h` 獨立確認戰場格陣，以及一批例程

- 證據等級：`exact`（逐條讀完；顯示位移可疑者回查原始 bytes）

## 戰場格陣 50 × 25 得到第二個獨立證據

`overlay-10:0FC7h`（DOS）／`0FBBh`（PC-98），`retf`，不收參數：

```pascal
FillChar((DS:6E92h + 7)^, 4E2h, 17h);     { 把整張地圖填成 17h }
不用的暫存 := DS:4F99h^[186h];
不用的暫存 := DS:4F99h^[188h];
DS:4A14h := DS:4F99h^[342h];              { PC-98：DS:7ACAh }
本模組 09FEh(); 0B0Ah(); 0E49h();
```

`4E2h` ＝ 1250 ＝ **50 × 25**，起點是地圖緩衝區 ＋ 7。spec 749 是從
`FreeMem` 的 `4E9h`（1257 ＝ 7 ＋ 1250）反推出格陣尺寸與表頭長度；這裡的
`FillChar` 直接把「表頭 7 bytes、格子 1250 bytes」寫在指令裡，**兩條互相獨立的
證據指向同一個結論**。

兩個 local（`+186h` 與 `+188h` 讀出來的值）指派後整支沒再用到。

## `overlay-26:1241h` — 釋放整條鏈，但不清鏈頭

`retf 4`，參數是「指向鏈頭指標的遠指標」：

```pascal
p := 鏈頭^;
while p <> NIL do begin
    tmp := p;  p := p^[2Ah];  FreeMem(tmp, 2Eh);
end;
{ 鏈頭本身沒有被寫回 NIL }
```

節點 `2Eh` ＝ 46 bytes、next 在 `+2Ah`——與既有的「選單節點與物品節點共用前
`2Bh` bytes」一致，這是**選單節點鏈**（物品節點是 `3Fh` ＝ 63 bytes）。

離開時鏈頭仍指著已釋放的第一個節點。呼叫端若沒有自己清掉就是懸空指標。
`overlay-26:0074h`（spec 755）數的是同一種鏈。

## 字串裁切的兩支（DOS `overlay-26`）

兩支都是 `retf 6`：第一個宣告的參數是遠字串指標（`[bp+8]`／`[bp+0Ah]`），第二個
參數（`[bp+6]`）整支沒讀。都先用 `0A54h:064Eh` 把字串複製進 40 字元的本地緩衝
區（長度上限 `28h`）再處理。

`0A10h`：從尾端往回跳過空白，回傳裁掉尾端空白後的長度（下限 1）。
`09C4h`：從頭往後跳過空白，回傳第一個非空白的位置（1 起算）。

兩支合起來就是 trim 的左右兩半。**中文化要注意**：判斷字元用的是 `20h`，全形
空白不會被當成空白。

## `overlay-01:0000h`（兩平台）— 可中斷的計時等待

`retf 2`：

```pascal
06EAh:024Ch();                       { PC-98：07E3h:02C7h }
起點 := 0542h:0994h();               { 回 DX:AX 的 32-bit 計數 }
終點 := 起點 + 參數 * 100;
repeat
    if 09ABh:02FAh() <> 0 then break;    { PC-98：08EEh:03B3h }
until 0542h:0994h() >= 終點;             { 無號 32-bit 比較 }
06EAh:024Ch();
```

`06EAh:024Ch` 在頭尾成對出現。等待長度是**參數 × 100 個計數單位**。

## `overlay-14:0749h`（DOS）／`0714h`（PC-98）— 移除值為 `1Fh` 的那一格

`retf`，不收參數：

```pascal
p := 本模組 06F4h(1Fh);
if p = NIL then f := false
else begin
    i := 找格子(1Fh, p);        { overlay-14:06B1h，見 spec 755 }
    p^[1Eh + i] := 0;
    f := true;
end;
```

與 spec 755 的 84 格陣列是同一個。`1Fh` 是被找、被清掉的那個值。

## `overlay-25:134Ah`（DOS）／`1452h`（PC-98）— 第一個非零的職業欄位

`retf 4`：

```pascal
if p^[74h] <> 7 then f := 0
else begin
    i := 0;
    while (i < 7) and (p^[109h + i] = 0) do inc(i);
    f := p^[109h + i];
end;
```

`+109h` 是第一職業區塊的起點（既有結論）。**七格全為 0 時 `i` 會停在 7，於是
讀到 `p^[110h]`——超出這七格**。`+110h` 屬於第一／第二職業區塊之間，不是這個
迴圈打算讀的東西。remake 要照抄的話，這個越界一格是原版行為的一部分。

spec 754 的 `overlay-25:13BCh` 就是拿這支的結果去和 `p^[0E6h]` 比大小。

## `overlay-19:3656h`（DOS）／`36BDh`（PC-98）— 四個條件的合取

`retf 4`：

```pascal
f := ( (p^[75h] = 3) or ((p^[114h] > 0) and <overlay 呼叫>(p)) )
     and (DS:4FBAh <> 5)
     and (p^[195h] = 0)
     and (p^[191h] > 0);
```

`DS:4FBAh` 就是戰鬥開場（spec 750）結尾設成 5 的那個狀態變數，所以第二個條件
是「不在那個狀態」。`+195h` 是狀態欄位、`+114h` 是第二職業區塊。`+114h` 用有號
比較，`+191h` 用無號。PC-98 對應 `DS:7F27h`、`+196h`、`+192h`。

## `overlay-21` 的三支

`05F9h`（DOS）／`0613h`（PC-98），`retf`：走隊伍鏈，數出 `+0F7h = 0` **或**
`+0F7h = 0B3h` 的成員數（byte）。`+0F7h` 正是本專案記錄過「四個處理常式對它的
存回不對稱」的那個欄位；`0B3h` 是個特別值。

`0F5Bh`（DOS）／`1070h`（PC-98），`retf 8`，兩個遠指標都是輸出參數：

```pascal
a^ := 0;  b^ := 0;
for i := 0 to 6 do
    if 遠指標表[DS:6F70h + i * 4] <> NIL then a^ := 1;
if 遠指標表[DS:6F8Ch] <> NIL then b^ := 1;
```

`DS:6F70h` 起是 **8 個 4-byte 遠指標**（`6F70h`..`6F8Fh`）；前 7 個歸 `a`，第 8 個
（`6F8Ch`）單獨歸 `b`。PC-98 對應 `DS:0A00Ah` 與 `0A026h`，同樣的 8 格。

`0073h`（兩平台），`retf 0Ah`，第三個參數是輸出：

```pascal
function 會超過(p: 遠指標; n: word; var 餘裕: word): boolean;
begin
    上限 := 本模組 001Bh(p);
    if p^[187h] + n > 上限 then begin        { 無號 }
        會超過 := true;  餘裕 := 上限 - p^[187h];
    end else begin
        會超過 := false; 餘裕 := 0;
    end;
end;
```

`本模組 001Bh(p)` 被呼叫兩次，兩次都重算。PC-98 用 `+188h`。

## `overlay-09:1201h`（DOS）／`1223h`（PC-98）— 兩條路的選擇

`retf 4`：先無條件叫一支程序，然後

```pascal
if f1(p) or f2(p) or (p^[18Dh]^[3] = 0)
    then f := h1(p)
    else f := h2(p);
```

`+18Dh` 是戰鬥狀態指標，`^[3]` 是它的第 4 個 byte。PC-98 用 `+18Eh`。

## `overlay-16:351Ch`（DOS）— 載入 `CPIC`

匯出在這支中間漏掉 `21h` 個 bytes，以下由原始 bytes 補回：

```pascal
if DS:4F9Dh^[67Ch] > 7 then exit;       { 無號 }
GetMem(p, 1A6h);                         { 422 bytes }
本模組 3254h(參數, p);
p^[126h] := 參數;
本模組 35A8h(p);
組字串(CS:3517h = 'CPIC' → 本地緩衝);
<overlay-33 entry#5 @01D4h>(參數, p^[143h]);
```

`'CPIC'` 是 4 個字元的資源名。`+67Ch` 那個 `> 7` 的檢查在最前面，超過就整支
不做。

## PC-98 `overlay-22:4416h`

`retf`，不收參數：`本模組 1432h(8, 2, 0, 0, DS:0A031h)` 取得一個 byte `r`，
用 `0A65h:062Fh` 組出字串（來源 `CS:4415h`，**長度 byte 是 0，也就是空字串**），
參數帶 `8` 與 `r + 1`，最後叫本模組 `0F62h`。

## DOS `START.EXE`：CRT 單元的畫面初始化

`19B97h`（近呼叫）：`INT 10h AH=0Fh` 取目前模式，`AX=1130h / BH=0 / DL=0` 取字型
資訊（回傳 `DL` ＝ 列數 − 1）。`DL = 0` 時改用 `18h`（24），且模式 ≤ 3 時另外把
`byte_24E5Dh` 設 1。結果分別存進 `word_24E5Eh`（模式與欄數）、`word_24E68h`
（列數）、`byte_24E5Ch := 1`、`word_24E62h := 0`、`word_24E64h := dx`。
列數超過 `18h` 時 `AH := 1`。

`19B49h`（近呼叫）：先清 BIOS 資料區 `0040h:0087h` 的 bit 0；模式為 7 或小於 4
就保留，否則強制成 3；設模式；接著 `AX=1112h / BL=0`（載入 8×8 字型）、
`AX=1130h` 取列數，**列數為 `2Ah`（42）時**才把 `0040h:0087h` 的 bit 0 設回、
設游標形狀（`AX=0100h / CX=0600h`）、`AH=12h / BL=20h`。

## 明確不宣稱

- 沒有宣稱 `06EAh:024Ch`、`0542h:0994h`、`09ABh:02FAh` 是什麼；只知道
  `0542h:0994h` 回一個會遞增的 32-bit 值、`09ABh:02FAh` 回一個 byte 旗標。
- 沒有宣稱 `'CPIC'` 是檔名還是資源標籤。
- 沒有宣稱 `+0F7h` 的 `0B3h`、`+75h` 的 `3`、`+74h` 的 `7` 各代表什麼。
- `overlay-05:0ED7h` 與其他幾支的匯出位移不可靠（同一種漏 byte），本輪**沒有**
  判讀它們，仍留在待解讀。
