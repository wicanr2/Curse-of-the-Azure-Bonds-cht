# 1132 — 戰鬥地圖要跟著地城座標走，編制帶放在視野中段

- 證據等級：`exact`（戰鬥地圖的生成來源與再生時機由程式路徑逐行確認；
  兩份地圖不一致的實例由 checkpoint 的逐格傾印量到）
- 上游 spec 1130（兩層座標不一致的四個實例）、spec 88（`try_place_combatant`）

## 一、佈陣檢查的地圖，跟畫面上的地圖可以是兩份

戰鬥地圖不是常數，是由**地城座標**生出來的：`GenerateDungeon(格線, x, y)`。
渲染端在隊伍移動時會重生一次（`refreshDungeonPreview`）。

問題在於**生成的時機**：checkpoint 的劇情流程會在開戰之前把隊伍移到別的格，
而那時 `dungeonFloor` 還是啟動時用舊座標生的那一份。於是

- 佈陣的地面檢查（spec 1130 §三）讀**舊**地圖，
- 畫面上的地形讀**新**地圖。

實例：Burial Glen 的紅網戰鬥，開戰時那一列是
`地板 地板 牆 牆 牆 牆 地板`，畫面上那一列卻是
`牆 牆 牆 牆 牆 牆 地板`。這一次結果剛好還合法，但那是運氣——
**這是 spec 1130 那一類「兩層各自算」的第五個來源，只是換成兩份地圖。**

修法是讓三支戰鬥地形投影在查詢前先同步：座標沒變時只做兩次整數比較，
變了才重生。時機因此由「誰記得先呼叫」變成「查詢時保證一致」。

⚠ 重生要**只重生地圖**。`refreshDungeonPreview` 同時會重建牆面貼圖
（要 GPU 內容），不能從逐格的地形查詢裡呼叫。

## 二、編制帶從第 2 列起算

`FormationTile` 的列原本從第 0 列起算，於是兩隊都貼在七列視野的**上緣**：
單人隊伍會被推到右上角，地圖中段的地形全部空著。

改成從第 2 列起算，兩條縱帶落在視野中段；人數多到排不下時往下延伸，
相機自然接手。

⚠ 這仍是 fallback。沒有 `SETUP MONSTER` 的距離與 occupancy 表之前，
縱帶位置、列起點與掃描順序都是本作自訂的，不宣稱與原作逐格相同。

## 順帶：素材缺漏的普查結果是零

同一輪對二十個 checkpoint 做過一次「畫不出來就記一筆」的普查，
記錄點涵蓋戰鬥員圖示、戰鬥地形圖層、牆面 piece set 與版面、共用符號段、
人物舞台與 PIC。**二十個 checkpoint 全部零筆**——第一人稱牆面補上第 0 段
（spec 1131）之後，目前這幾條路上沒有其他解不開的素材參照。

## 明確不宣稱

- 沒有宣稱 `GenerateDungeon` 產生的戰鬥地圖與原作逐格相同；本規格只處理
  「哪一份地圖」的一致性，不處理那份地圖的內容正確性。
- 沒有宣稱第 2 列是原作的編制列起點。
- 「零筆缺漏」只涵蓋那二十個 checkpoint 走到的畫面與那六個記錄點，
  不是全遊戲素材完整性的證明。
