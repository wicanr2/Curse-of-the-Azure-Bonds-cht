# 第六百九十二輪：隊伍統計、鏈結串列搜尋、四段固定參數展開

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：DOS `overlay-24` 的 `25D4h`、`2396h`、`1AAAh`（三支都是 overlay entry）。

## `25D4h`：依 `+197h` 統計人數

```text
DS:6F90h := 0
DS:6F91h := 0
p := DS:650Ah                                  ← 與 spec 689 名單同一條鏈
while p <> NIL do
    if p^[196h] <> 0 then
        byte [6F90h + p^[197h]] += 1           ← p^[197h] 經 cbw，有號
    p := p^[189h]
```

**只清了兩個 byte，卻用 `+197h` 當索引，而且沒有上下界檢查。** `+197h` 只要
不是 0 或 1，就會加到 `6F92h` 之後或 `6F8Fh` 之前——寫進別的全域變數。
先前已知 `+197h` 會被拿來判斷 `= 0`（狀態 5 降為 4 的那條），但它的值域沒有
證據。移植時若照抄成陣列索引，要自己補範圍檢查，否則是一個隨資料而定的越界寫。

`+196h` 就是 `KILLTHEDUDE` 裡「等於 6 整支跳過」的那個欄位，這裡是「等於 0
就不計入」。

## `2396h`：用 key 找節點，結果從 var 參數回傳

```text
arg_0^ := arg_6^[0F2h]                          ← arg_0 是 var 參數（指標的指標）
found := 0
while arg_0^ <> NIL 且 found = 0 do
    if arg_0^^[0] = arg_4 then found := 1
    else arg_0^ := arg_0^^[5]
回傳 found（byte）
retf 0Ah
```

節點版面：`+0` 是比對用的 key（byte），`+5` 是 far 指標指向下一個。
`arg_6^[0F2h]` 是鏈的頭。

**找到的節點是從 `arg_0` 寫回去的**，回傳值只是「有沒有找到」。呼叫端若只看
回傳值會拿不到節點；反過來，找不到時 `arg_0^` 會被留成 `NIL`，不是留成原值。

迴圈每一輪都重新 `les di, [bp+arg_0]` 再解一次，沒有暫存。

## `1AAAh`：四次同樣的呼叫，參數寫死

```text
<1975h>(arg_0, 0, 0, 0)
<1975h>(arg_0, 0, 1, 1)
<1975h>(arg_0, 1, 2, 1)
<1975h>(arg_0, 1, 3, 0)
retf 2
```

第三個參數是 0、1、2、3，其餘兩個沒有規律可推（`0,0,1,1` 與 `0,1,1,0`）。
原始碼應該是四行手寫的呼叫，不是迴圈——所以那兩欄要當**資料**照抄，不要試圖
從第三欄推導。

## 明確不宣稱

- `DS:6F90h`／`6F91h` 這兩個計數給誰用。
- `+197h` 的值域與語意、`+196h` 的語意。
- `arg_6^[0F2h]` 那條鏈裝什麼、`+0` 的 key 是什麼編號。
- `1975h` 做什麼、它四組參數的意義。
