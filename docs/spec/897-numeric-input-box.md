# 897 — 數字輸入框：超過上限就自動夾成上限，並定出兩平台的文字區寬度

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側多一段串接）
- 作法見 spec 783

## `overlay-21:002ADh`（DOS 192 條）↔ `overlay-21:002ABh`（PC-98 203 條）

`retf 8` ＝ 4 個 word：`(上限, 提示字串, 顏色)`。回傳輸入的數字。

```pascal
提示 := 提示字串^;                                  { 上限 28h }
<far 0542h:0311h>(28h, 0, 18h, 0);                  { 清第 18h 列的 28h 欄 }
<far 0542h:0352h>(提示, 0, 顏色, 18h, 0);           { 印提示 }

起欄 := Length(提示);   欄 := 起欄;
Str(上限, 寬度 5, var 上限字);
緩衝 := '';

repeat
    鍵 := ReadKey;                                   { far 06EAh:010Dh }

    if (鍵 >= '0') and (鍵 <= '9') then begin
        緩衝 := (緩衝 ＋ Chr(鍵)) 上限 6;            { 0A54h:074Fh ＝ Chr }
        Val(緩衝, var 錯, var 值);                   { 0A54h:12F6h }
        if 上限 > 值 then
            inc(欄)
        else begin
            緩衝 := 上限字;                          { ★ 夾成上限 }
            欄 := 起欄 ＋ Length(上限字);
        end;
        <far 0542h:0352h>(緩衝, 0, 0Fh, 18h, 起欄);
    end
    else if (鍵 = 8) and (緩衝 <> '') then begin      { Backspace }
        緩衝 := Copy(緩衝, 1, Length(緩衝) − 1);     { 0A54h:0680h }
        <far 0542h:0311h>(1, 0, 18h, 欄);
        dec(欄);
    end;
until (鍵 = 0Dh) or (鍵 = 1Bh);

<far 0542h:0311h>(28h, 0, 18h, 0);
if 鍵 = 1Bh then 結果 := 0                            { Esc ＝ 0 }
else Val(緩衝, var 錯, var 結果);
```

## 超過上限不是拒收，是直接改成上限

打一個會讓數值超過上限的數字時，**整個緩衝被上限的字串取代**，
游標跳到上限字串的尾端。所以玩家連按 `9` 最後會停在上限值，
不會被卡住也不會溢位。

`Esc` 回 0、`Enter` 回輸入值。緩衝上限 6 個字元，
配合 `Str(上限, 寬度 5)`——**最大能表示到 5 位數**。

## ⚠ 兩平台的文字區寬度：DOS 40、PC-98 80

清整列時傳的欄數：

| | 欄數 |
|---|---|
| DOS | `28h` ＝ **40** |
| PC-98 | `50h` ＝ **80** |

PC-98 的文字是 80 個半形位置 ＝ **40 個全形字**，DOS 是 40 個半形字元。
與 spec 867 讀到的「結局動畫版面 3 列 × 40 行」一致。

**中文化跟 PC-98**：一列 40 個中文字。這也解釋了為什麼 PC-98 的
字串上限一路從 `28h`(40) 放寬到 `50h`(80)（spec 859／871／894）。

PC-98 另外在印之前多接一個常數字串（`0A65h:062Fh` 建 ＋ `06BCh` 串接
`loc_2A9`），DOS 直接印緩衝。本規格不宣稱那個常數是什麼。

## 明確不宣稱

- 沒有宣稱 `far 0542h:0311h`／`0352h` 的參數順序細節
  （形狀上是「清一段」與「在某列某欄印字」）。
- 沒有宣稱第 `18h` 列（24）是不是固定的輸入列。
- 沒有宣稱呼叫端拿這個數字做什麼（`overlay-21` 有 spec 863 的分錢與
  spec 875 的幣別解析，形狀上是「輸入金額」）。
