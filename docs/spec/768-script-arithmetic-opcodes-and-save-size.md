# 768 — 腳本 VM 的四則運算碼、存檔大小的計算式

- 證據等級：`exact`（以補洞後的匯出逐條讀完，見 spec 761）

## `overlay-02:019Bh`（DOS）— 腳本 VM 的四則運算

`retf`，不收參數：

```pascal
<呼叫>(3);
A := <取運算元>(1);                       { 存進 var_6 }
B := <取運算元>(2);                       { 存進 var_4 }
目的 := <呼叫>(byte[76C8h], byte[7708h]); { 兩張表的第 3 格 }
case DS:75FFh of
    4: r := A + B;
    5: r := B − A;
    6: begin r := A div B;                                   { 無號 }
             DS:4F9Dh^[67Eh] := A mod B; end;                { 餘數存這裡 }
    7: r := A * B;
end;
<寫回>(r, 目的);
```

`DS:75FFh` 就是 spec 759／766 那個「腳本流的目前 byte」。所以這是**運算碼
4..7 ＝ 加、減、除、乘**。

三件要照抄的細節：

- **減法是 `B − A`，除法是 `A div B`**——兩個運算元的順序不一致。加法與乘法
  可交換所以看不出來，但減與除的順序不同不是筆誤，是程式碼裡就長這樣。
- 除法用 `div` 而不是 `idiv`，**是無號的**；`B = 0` 時沒有任何檢查。
- 除法的**餘數會被存到 `DS:4F9Dh^[67Eh]`**，是這個運算碼的副作用。運算碼 4／5／7
  不會動那個欄位，所以餘數會留著上一次的值。

`DS:76C5h` / `DS:7705h` 那兩張表（spec 766）在這裡以固定索引 3 取用。

## `overlay-16:3D38h`（DOS）— 整隊要多少 bytes

`retf 2`（參數沒被讀）：

```pascal
總量 := 0;
角色 := DS:650Ah;
while 角色 <> NIL do begin
    總量 := 總量 + 1A6h;                        { 每個角色 422 bytes }
    物品 := 角色^[14Dh];
    while 物品 <> NIL do begin
        總量 := 總量 + 3Fh;                     { 每件物品 63 bytes }
        物品 := 物品^[2Ah];
    end;
    節點 := 角色^[0F2h];
    while 節點 <> NIL do begin
        總量 := 總量 + 9;                       { 每個節點 9 bytes }
        節點 := 節點^[5];                        { next 在 +5 }
    end;
    角色 := 角色^[189h];
end;
結果 := 總量;
```

三個常數都對得上既有結論：**422**（`1A6h`）正是 spec 756 的
`overlay-16:351Ch` 為一個角色 `GetMem` 的大小；**63**（`3Fh`）是物品節點的
大小；`+14Dh`／`+2Ah`／`+189h` 也都是既有的鏈結欄位。

新增的是第三條鏈：角色的 `+0F2h` 起、每個節點 **9 bytes、next 在 `+5`**。

`總量` 是 word，**沒有溢位檢查**。以 8 人、每人 16 件物品估算是
`8 × (422 + 16 × 63) = 11440`，還在 word 範圍內；但 `+0F2h` 那條鏈沒有已知上限。

## `overlay-20:0862h`（DOS）— 每 288 次才做一次的整隊回復

`retf 2`：

```pascal
inc(DS:757Ch);
if DS:757Ch < 120h then 離開;                  { 無號，120h = 288 }
有變化 := false;
角色 := DS:650Ah;
while 角色 <> NIL do begin
    if <呼叫>(1, 角色) then 有變化 := true;
    角色 := 角色^[189h];
end;
if 參數 <> 0 then 本模組 05D4h(0);
繪字(1, 13h, 0Ah, 0, 'The Whole Party Is Healed');   { CS:0848h，25 字元 }
if 有變化 then <14Dh:002Ah>(DS:6506h);
<0542h:0B33h>();  <014Dh:0089h>();
DS:757Ch := 0;
```

`DS:757Ch` 是一個純計數器：**每呼叫 288 次才真的動作一次**，動作完歸零。
訊息 `'The Whole Party Is Healed'` 固定畫在 `x = 1`、`y = 13h`（19）、
顏色 `0Ah`。

**中文化要注意**：這句 25 個字元寫死在 `x = 1`，沒有置中計算；換成中文之後
長度變短，右邊會留下前一次畫面的殘留（這一支沒有先清行）。

## PC-98 `overlay-22:45F1h`

`retf`，不收參數：

```pascal
if DS:0A521h^[0E5h] >= 6 then                   { 有號 }
    顯示(角色, CS:45E2h = 'は叩きつけた。')
else begin
    n := <呼叫>(DS:0A031h);
    組字串(CS:45E1h（長度 0，空字串）, 8, 0, 0, n, DS:0A031h);
    本模組 0F62h();
    if <loc_1546+1>(@暫存, 3, 角色) then
        <sub_140Ah>(0, 暫存, …, 角色, 3);
end;
```

`CS:45E1h` 的長度 byte 是 **0**——那是一條刻意的空字串，後續由組字串程序把
名字接上去。緊接著的 `CS:45E2h` 才是 `'は叩きつけた。'`（14 bytes）。
**兩條字串在位元組上是重疊相鄰的**，中文化替換時不能把 `45E1h` 的長度 byte
一起蓋掉。

## 明確不宣稱

- 沒有宣稱運算碼 `0..3` 是什麼；本支只處理 `4..7`，其他值會讓 `r` 保持未指派
  （local 沒有初始化）。
- 沒有宣稱 `DS:4F9Dh^[67Eh]` 除了放餘數之外還有什麼用。
- 沒有宣稱角色 `+0F2h` 那條 9-byte 鏈裝的是什麼。
- 沒有宣稱 `DS:757Ch` 的 288 次對應多少遊戲時間。
- 沒有宣稱 `overlay-22:45F1h` 的 `+0E5h >= 6` 是什麼條件。
