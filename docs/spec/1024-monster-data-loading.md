# 1024 — 怪物資料載入：三個 `.dax` 檔、422 bytes 的範本、9 bytes 的特攻節點

- 證據等級：`exact`（DOS 側 275 條、PC-98 側 324 條，兩邊各自逐條讀完）
- 作法見 spec 783

## `dos overlay-16:03254h` ↔ `pc98 overlay-16:03AA8h`

兩側原本都是待解讀。

## ★★ 一隻怪物要讀三個檔

DOS 把檔名組出來：

```pascal
前綴 := 'MON' ＋ Str(DS:5BEEh) ＋ <'CHA' 或 'SPC' 或 'ITM'>;
副檔 := '.dax';
```

`DS:5BEEh` 是**磁碟／資料片編號**（spec 892 定過預設值 1）。所以三個檔是

```
MON<n>CHA.dax    ← 怪物範本
MON<n>SPC.dax    ← 特殊攻擊
MON<n>ITM.dax    ← 隨身物品
```

⚠ **PC-98 沒有插編號**——它用寫死的 `'MONCHA'`／`'MONSPC'`／`'MONITM'`。
（`'.dax'` 兩平台相同。）

讀不到就顯示 `'Unable to load monster'`（22 字元）並走 `far 06EA:0000h`。

## ★★ 三種紀錄的大小

| 檔 | 一筆多大 | 怎麼配 |
|---|---|---|
| `CHA` | **DOS `1A6h` ＝ 422 bytes**／**PC-98 `1A7h` ＝ 423** | `Move` 進呼叫端給的緩衝 |
| `SPC` | **9 bytes** | `GetMem 9`，串成鏈 |
| `ITM` | **`3Fh` ＝ 63 bytes**（PC-98 103） | `GetMem 3Fh`，串成鏈 |

★★★ **`ITM` 的 63 bytes 是物品節點大小的第四個獨立確認**
（spec 1018 從「留下寶石」的 `GetMem`、spec 1019 從「射出去的箭」的
`GetMem`／`Move`、spec 1011／1013 從欄位與 `next` 位移）。

★ **特殊攻擊節點只有 9 bytes**——比物品節點小得多，
形狀上是「編號 ＋ 幾個參數 ＋ next」。

★ **怪物範本 PC-98 比 DOS 大 1 byte**（`1A7h` vs `1A6h`），
與 spec 1010／1017 量到的**角色記錄 ＋1 位移**一致
（物品節點是 ＋28h，兩種節點的規則不同）。

## 中文化

| 字串 | 長度 | 備註 |
|---|---|---|
| `'MON'`／`'CHA'`／`'SPC'`／`'ITM'`／`'.dax'` | 3／3／3／3／4 | **檔名，不可翻** |
| `'Unable to load monster'` | 22 | PC-98：「モンスターをロードできませんでした」（34 bytes） |

⚠ DOS 的檔名是 `'MON' ＋ 編號 ＋ 'CHA'` 三段拼的，
**中文化若要改資料檔命名，DOS 與 PC-98 要分別處理**
（PC-98 是一整條 `'MONCHA'`）。

## 明確不宣稱

- 沒有宣稱 `far 0636:08DEh`（開檔／找資源）的介面。
- 沒有宣稱 422 bytes 的怪物範本裡有哪些欄位
  （spec 1017 從其中搬出種族、性別、名字與六個屬性）。
- 沒有宣稱 9 bytes 特攻節點的版面。
- 沒有宣稱 `far 06EA:0000h`（載入失敗時走的路）做什麼。
- 沒有宣稱 PC-98 為什麼不在檔名裡放資料片編號。
