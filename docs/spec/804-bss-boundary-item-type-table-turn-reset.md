# 804 — 資料段的 BSS 界線、物品類型表、回合開始的重設

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側的運算元差異已逐條列出；BSS 界線
  由常駐資料段 dump 量出）
- 作法見 spec 783

## 資料段的界線：DOS `DS:47E0h` 之後全是 BSS

量 dump 的結果：

| 平台 | 已初始化資料 | BSS（dump 裡全是 `FFh`） |
|---|---|---|
| DOS | `DS:0000h`..`DS:47DFh` | `DS:47E0h`..`DS:8EFFh`（18,208 bytes） |
| PC-98 | `DS:0000h`..`DS:787Fh` | `DS:7880h`..`DS:0C0CFh`（18,512 bytes） |

這條界線一眼就能分辨「烘進執行檔的表」與「執行時才填的變數」：

| 已初始化（可直接從 dump 讀出內容） | BSS（dump 讀不到，只能靠程式碼推） |
|---|---|
| `DS:00DDh` 疾病碼表（796） | `DS:4F99h` / `DS:4F9Dh` 遠指標（多處） |
| `DS:0F93h` 金錢名稱（773） | `DS:5CF6h` 物品類型表（本支） |
| `DS:2694h` / `DS:269Dh` 方向表（758） | `DS:6506h` / `DS:650Ah` 角色串列（多處） |
| `DS:27BDh` 法術名稱（773） | `DS:66A3h` 戰鬥員記錄（785） |
| `DS:37DAh` 法術屬性（773） | `DS:6E92h` 螢幕格緩衝（786） |
| `DS:3E2Ah` 時鐘進位上限（793） | `DS:7566h` 休息時間（803） |

**先前所有「從 dump 直接讀出內容」的表全部落在界線以下**，這條界線同時是那些
判讀的有效性保證。

## `overlay-24:02A7h`（entry#50，104 條，**差異 2 條**）— 依物品類型累加

兩平台只差物品欄位（`+2Eh` ↔ `+56h`）與表基底。`retf 10h` ＝ 8 個 word，
依宣告順序：`(角色, 物品, 記錄, 輸出)`，四個都是遠指標。

```pascal
v := byte[5CFCh + 物品^[2Eh] * 10h];
if v <= 7Fh then 離開;                                  { 無號：最高位沒設就不處理 }
v := v and 7Fh;
w := byte[5CF6h + 物品^[2Eh] * 10h];
if w = 1 then
    記錄^[1] := 物品^[32h] + v
else if v = 0 then begin
    if w = 9 then begin
        if 有號(物品^[32h]) > 有號(記錄^[3]) then 記錄^[3] := 物品^[32h];
    end else
        記錄^[2] := 記錄^[2] + 物品^[32h];
    角色^[186h] := 角色^[186h] + 物品^[33h];
end
else if 有號(物品^[32h]) + v > 有號(記錄^[4]) then begin
    記錄^[4] := 物品^[32h] + v;
    if (有號(物品^[32h]) > 0) and (w = 2) then 輸出^ := 1;
end;
```

### 物品類型表：`DS:5CF6h`，每筆 16 bytes，用物品的 `+2Eh` 當索引

已知兩欄：

| 位移 | 用途 |
|---|---|
| `+0` | 類別碼（本支用到 `1` / `2` / `9` 三個值） |
| `+6` | 最高位 ＝ 這一筆要不要處理；低 7 位是一個加值 |

這張表落在 BSS 裡，**dump 讀出來全是 `FFh`**——它是**執行時從資料檔載入**的，
不像法術屬性表（`DS:37DAh`）是編譯進去的。要拿到內容必須解資料檔或跑起來抓，
本規格只定出版面。

### 四條互斥的累加路徑

| 條件 | 動作 |
|---|---|
| `+0` ＝ 1 | `記錄^[1] := 物品^[32h] + 加值` |
| 加值 ＝ 0 且 `+0` ＝ 9 | `記錄^[3]` 取 `物品^[32h]` 的**最大值** |
| 加值 ＝ 0 且 `+0` ≠ 9 | `記錄^[2]` **累加** `物品^[32h]`；角色 `+186h` 累加 `物品^[33h]` |
| 加值 ≠ 0 | `記錄^[4]` 取 `物品^[32h] + 加值` 的最大值；再滿足 `物品^[32h] > 0` 且 `+0` ＝ 2 就把輸出 byte 設 1 |

**三種聚合方式並存**（直接寫、取最大、累加），remake 不能統一成一種。
`記錄^[1]` 那條路寫完就離開，其餘三條都不會碰 `記錄^[1]`。

## `overlay-08:026Bh`（entry#4，102 條，差異 26 條）— 回合開始的重設

```pascal
p^[18Dh]^[0Fh] := 0;                      { 動作計數，spec 786 }
p^[18Dh]^[12h] := 0;                      { 累計轉向，spec 786 }

if 有號(p^[18Dh]^[3]) <= 0 then 離開;

    if p^[198h] <> 0 then <far 0813h+2>(p) else <本模組 03D5h>(p);

```

`retf 4` ＝ 一個遠指標。

### 戰鬥狀態 `+3` 就是 spec 791 拿來排優先度的那個 byte

- `<= 0`（**有號**）就整支不做事——與 spec 791「`+18Dh^[3]` ＝ 0 的角色不可能被
  選中」對得起來。
- `= 14h`（20）時被壓成 `13h`（19）。**只壓這一個值**，21 以上不處理。
- 進到後半段之後又檢查一次 `> 0`——中間那一串呼叫可能把它改掉。

⚠ 這個 `+3` 與 spec 800 的「佔幾格」不是同一個欄位：那個在
`DS:66A3h + i * 4` 的 4-byte 並列記錄裡，這個在 `+18Dh` 指到的 22-byte 戰鬥狀態
記錄裡（spec 801）。

### 最後那個巢狀呼叫

`<018Ch:0043h>` 的兩個參數分別是 `<018Ch:006Bh>(p)` 與 `<018Ch:0070h>(p)` 的
回傳值，且 `006Bh` 的結果是**第一個**參數（先推）。

## 明確不宣稱

- 沒有宣稱物品 `+2Eh` / `+32h` / `+33h` 各是什麼。
- 沒有宣稱 `DS:5CF6h` 那張表共有幾筆，也沒有宣稱它從哪個資料檔載入。
- 沒有宣稱 `記錄^` 那四格（`+1`..`+4`）各代表什麼。
- 沒有宣稱角色 `+186h` 是什麼。
- 沒有宣稱 `+18Dh^[3]` 的量綱，也沒有宣稱為什麼 20 要壓成 19。
- 沒有宣稱 `DS:75E5h` / `DS:75E6h` 由誰讀。
