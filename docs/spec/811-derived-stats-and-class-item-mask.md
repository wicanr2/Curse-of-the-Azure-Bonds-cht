# 811 — 升級後重算衍生數值：攻擊表列、職業位元遮罩、卸下不能用的裝備

- 證據等級：`exact`（DOS 側逐條讀完，其中三條由原始位元組手動解碼；PC-98 側的
  運算元差異已逐條列出；兩張表取自常駐資料段 dump，兩平台逐位元組相同）
- 作法見 spec 783

## `overlay-25:03B1h`（entry#3，DOS 249 條／PC-98 247 條，實質差異 16 條）

`retf 4` ＝ 一個角色遠指標。

```pascal
角色^[73h] := 0;
for c := 0 to 7 do begin
    L := 角色^[109h + c];
    v := byte[3E38h + c * 0Dh + L];
    if v > 角色^[73h] then 角色^[73h] := v;            { 無號 }
    if 有號(角色^[0E5h]) < 有號(L) then 角色^[0E5h] := L;
    if      (c = 2) and (L > 6) then 角色^[11Ch] := 3
    else if (c = 4) and (L > 7) then 角色^[11Ch] := 3
    else if (c = 3) and (L > 6) then 角色^[11Ch] := 3;
end;

<本模組 0011h>(角色);                                  { spec 810：重算可記憶法術數 }
<本模組 07E3h>(角色);
if 有號(角色^[10Fh]) > 0 then <本模組 0AD8h>(角色);

角色^[12Bh] := 0;
for c := 0 to 7 do
    if (有號(角色^[109h + c]) > 0)
       or ((有號(角色^[111h + c]) > 0)
           and (有號(角色^[111h + c]) < 有號(角色^[0E5h]))) then
        角色^[12Bh] := 角色^[12Bh] + byte[3EA0h + c];

for k := 0 to 12 do begin                              { 13 個裝備槽 }
    p := 遠指標(角色^[151h + k * 4]);
    if p <> NIL then
        if ((byte[5D03h + p^[2Eh] * 10h] and 角色^[12Bh]) = 0)
           and (p^[36h] = 0) then
            p^[34h] := 0;                              { 強制卸下 }
end;

if not <本模組 13BCh>(角色) then 離開;
for c := 0 to 7 do begin
    L := 角色^[111h + c];
    if      ((c = 2) or (c = 3)) and (L > 6) then 角色^[11Ch] := 3
    else if (c = 4) and (L > 7) then 角色^[11Ch] := 3;
    v := byte[3E38h + c * 0Dh + L];
    if v > 角色^[73h] then 角色^[73h] := v;
end;
if (有號(角色^[113h]) > 6) or (有號(角色^[115h]) > 7)
   or (有號(角色^[114h]) > 6) then 角色^[11Ch] := 3;
if 有號(角色^[117h]) > 0 then <本模組 0AD8h>(角色);
```

## `DS:3E38h`（PC-98 `DS:6ECCh`）：每職業 13 bytes，索引 `c × 13 + 等級`

兩平台逐位元組相同：

| c | 等級 0..12 |
|---|---|
| 0 | `28 28 28 28 2A 2A 2A 2C 2C 2C 2E 2E 2E` |
| 1 | `28 28 28 28 2A 2A 2A 2C 2C 2C 2E 2E 2E` |
| 2 | `27 28 28 2A 2B 2C 2D 2E 2F 30 31 32 33` |
| 3 | `28 28 28 2A 2B 2C 2D 2E 2F 30 31 32 33` |
| 4 | `28 28 28 2A 2B 2C 2D 2E 2F 30 31 32 33` |
| 5 | `27 27 27 27 27 27 29 29 29 29 29 2B 2B` |
| 6 | `28 28 28 28 28 29 29 29 29 2C 2C 2C 2C` |
| 7 | `28 28 28 28 2A 2A 2A 2C 2C 2C 2E 2E 2E` |

**取所有職業中最大的那個值寫進 `角色^[73h]`**。四種進步節奏正好對上 AD&D 的四張
攻擊表：

| 節奏 | 職業槽 | AD&D 對應 |
|---|---|---|
| 每級進步 | 2、3、4 | 戰士系（戰士／聖騎士／遊俠） |
| 每 3 級 | 0、1、7 | 牧師系 |
| 每 4 級（5、9 級跳） | 6 | 盜賊系 |
| 每 5 級（7、12 級跳） | 5 | 法師系 |

配合 spec 810 已定的 c ＝ 0 牧師、3 聖騎士、4 遊俠、5 法師，再加上這裡的
「c ＝ 2 與 3 同在 7 級升攻擊次數、c ＝ 4 在 8 級」，**c ＝ 2 是戰士、c ＝ 6 是
盜賊**（AD&D 戰士／聖騎士 7 級、遊俠 8 級升到 3/2 次攻擊）。

## `DS:3EA0h`（PC-98 `DS:6F34h`）：每職業一個位元

| c | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| 位元 | `02` | `10` | `08` | `40` | `40` | `01` | `04` | `20` |

累加進 `角色^[12Bh]` 得到**這個角色的職業遮罩**。

⚠ **c ＝ 3 與 c ＝ 4 共用 `40h`，而累加用的是 `+`（不是 `or`）**。兩個職業槽同時
成立時會進位成 `80h`，遮罩就壞了。`80h` 是這張表唯一沒用到的位元，所以壞掉的
遮罩不會意外對上任何物品。

物品那一側是 `DS:5D03h` ＝ 物品類型表（`DS:5CF6h`，spec 804）的 **`+0Dh`**，
同樣是職業位元遮罩。`and` 出來是 0 就代表**這個職業不能用這件裝備**。

## 卸下裝備的條件

```
不能用（遮罩不合） 且 未被詛咒（+36h ＝ 0） → +34h := 0
```

`+36h` 是 spec 794 定的詛咒旗標、`+34h` 是 spec 807 定的裝備中旗標。
**被詛咒的裝備卸不下來**，即使職業不能用——這正是詛咒的定義。

裝備槽是 `角色^[151h]` 起的 **13 個 4-byte 遠指標**（`k = 0..12`）。spec 808 用到
的 `角色^[151h]` 就是第 0 槽。

## 攻擊次數基底 `+11Ch`

三處把它設成 `3`：戰士（c ＝ 2）或聖騎士（c ＝ 3）超過 6 級、遊俠（c ＝ 4）超過
7 級。spec 808 已知 `+11Ch` 是 `+19Ch`（本回合攻擊次數）的基礎值。

⚠ **只設不清**：這一支從來不把 `+11Ch` 設回原值，所以它靠別處初始化。

## 一條方法論：指令數只差一兩條時先懷疑反組譯錯位

DOS 側匯出在 `0597h` 少了一個位元組的對齊，於是 `0598h`..`059Eh` 被解成
`add bp, cx` / `iret` / `add dh, al` / `inc si` / `inc word ptr [bx+si]` 這種
不可能出現在 Pascal 程式碼裡的東西，`pair_dump.py` 因此判定兩平台「不同形」而把
這一組排除掉。

原始位元組兩平台完全相同（`08 C0 75 03 E9 CF 00 C6 46 FF 00 EB 03`），而
**PC-98 側的 IDA 解對了**：

```
0595  08 C0        or   al, al
0597  75 03        jnz  short 059C
0599  E9 CF 00     jmp  066B          { 直接返回 }
059C  C6 46 FF 00  mov  [bp+var_1], 0
05A0  EB 03        jmp  short 05A5
```

兩平台的助憶碼序列扣掉這一段之後**完全相同**，所以它們是同一支函式。

**規則：兩平台指令數只差一兩條時，先去對原始位元組，不要直接當成「兩邊實作不
同」。** 另一個平台的正確解碼就是修正答案。
