# 1036 — 隨機物品產生器：名稱三段、重量表、價值公式、卷軸法術，以及特殊物品範本表

- 證據等級：`exact`（DOS 側 788 條、PC-98 側 778 條，兩邊各自逐條讀完）
- 作法見 spec 783

## `dos overlay-21:00FEDh` ↔ `pc98 overlay-21:010FCh`（`retf 6`）

兩側原本都是待解讀。

> ⚠ **PC-98 那 133 bytes「空洞」不是空洞**：函式在 `1945h` 的 `retf 6` 就結束了，
> `19CAh` 之後 IDA 多圈進來的是資料。真正的函式體 `10FCh`..`1945h`
> **已完整反組譯**，778 條全部讀完。台帳先前把它算成「有大空洞」是誤判。

```pascal
procedure 造物品(節點: 遠指標;   { bp+08h }
                 類別: byte);    { bp+06h }
```

## 骨架

```pascal
FillChar(節點^, 3Fh, 0);          { ★ 63 bytes ＝ DOS 物品節點 }
FillChar(節點^[3Ch], 3, 0);       { special(1..3) }
節點^[2Ah] := NIL;                { next }
節點^[34h] := 0;                  { ready }
節點^[35h] := 6;                  { ★ identified ＝ 6，不是 0/1 }
節點^[36h] := 0;                  { cursed }
節點^[2Eh] := 類別;               { itemptr }
FillChar(節點^[2Fh], 3, 0);       { namenum(1..3) }

if (類別 in [1..3Bh]) or (類別 in [49h, 4Dh, 5Dh]) then …一般物品…
else if 類別 in [3Dh, 3Eh]        then …卷軸…
else if 類別 in [3Fh, 43h, 4Eh, 4Fh, 54h, 5Ch, 47h] then …特殊範本…;
```

欄位名全部來自 spec 1011 的除錯畫面。PC-98 全部 `+28h`
（`+52h`／`+56h`／`+57h`..`+59h`／`+5Ah`／`+5Dh`／`+5Fh`／`+61h`／`+62h`），
**第五次確認 DOS 63 bytes／PC-98 103 bytes**。

## ★★ 名稱是三段索引，`+0A1h` 起是「＋N」後綴

`sub_FAF()`（`overlay-21:0FAFh`）先擲出 `plus`（`+32h`）：
**擲 1d20，1..14 給 ＋1、15..20 給 ＋2**，沒有 ＋0 也沒有 ＋3。
⇒ 隨機戰利品的加值分布是 70% ／ 30%。
接著依類別把三個 `namenum` 排出來：

| 類別 | namenum(3)`+31h` | namenum(2)`+30h` | namenum(1)`+2Fh` | 備註 |
|---|---|---|---|---|
| 一般（預設） | ＝類別 | `plus ＋ 0A1h` | 0 | |
| `15h` | `15h` | `plus ＋ 0A1h` | 0 | 另擲 1d5，＝5 時改走特殊範本 49 |
| `1Ch` | `1Ch` | `plus ＋ 0A1h` | 0 | |
| `32h`／`33h` | ＝類別 | `'1'`(31h) | `plus ＋ 0A1h` | `identified := 4` |
| `34h` | ＝類別 | `'2'`(32h) | `plus ＋ 0A1h` | `identified := 4` |
| `35h`..`3Ah` | ＝類別 | `'0'`(30h) | `plus ＋ 0A1h` | `identified := 4` |
| `49h` | `3Dh` | `plus ＋ 0A1h` | 0 | |
| `4Dh` | `4Fh` | `0A7h` | `0DDh`／`0DEh` | ★ `plus := plus × 2 ＋ 2`，再依 4／6 分 |
| `5Dh` | `42h` | `0E0h` | `plus ＋ 0A1h` | |

> ★★ **`plus ＋ 0A1h` ⇒ 名稱表第 `0A1h`(161) 筆起是「＋0／＋1／＋2…」那組後綴**。
> 中文化時這一段是**組字**，不能整句翻。

## ★★★ 卷軸（類別 `3Dh`／`3Eh`）

```pascal
法術數 := ROLLDICE(1, 3);                       { 1..3 }
節點^[31h] := (類別 = 3Dh) ? 0D1h : 0D0h;
節點^[30h] := 法術數 ＋ 0D1h;                    { 「N 個法術」那組名稱 }
節點^[2Fh] := 0;  plus := 1;  重量 := 25;  價值 := 0;
for k := 1 to 法術數 do begin
    環 := ROLLDICE(1, 5);
    法術 := ROLLDICE(1, n環) ＋ 基底環;
    節點^[3Bh ＋ k] := 法術;                     { ★ special(1..3) }
    價值 := 價值 ＋ 環 × 300;
end;
```

| 環 | 類別 `3Dh` | 類別 `3Eh` |
|---|---|---|
| 1 | `1d13 ＋ 8` | `1d8 ＋ 0` |
| 2 | `1d7 ＋ 28` | `1d7 ＋ 21` |
| 3 | `1d11 ＋ 44` | `1d8 ＋ 36` |
| 4 | `1d9 ＋ 80` | `1d5 ＋ 65` |
| 5 | `1d4 ＋ 90` | `1d6 ＋ 70` |

> ★★★ **卷軸上的法術直接存在 `special(1..3)`（`+3Ch`..`+3Eh`）**
> ——spec 1011 只給了欄位名，這裡給出它們在卷軸上的語意。
> ★ 兩個類別的法術編號區間互不重疊，形狀上是**兩種施法職業的卷軸**
> （對照 spec 1016 的法術屬性表 `DS:37DAh` 可以逐一查職業與環數）。

## ★★★ 特殊物品範本表 `DS:82Ch`（PC-98 `DS:1372h`）

```pascal
節點^[2Fh ＋ k] := lo(表[索引 ＋ k]);      { k ＝ 0..2，namenum(1..3) }
plus := 1;  plussave := 1;
節點^[37h] := 表[索引 ＋ 3];               { 重量 }
節點^[39h] := 0;
節點^[3Ah] := 表[索引 ＋ 4];               { 價值 }
```

## 中文化

本支沒有字串，但**它決定了物品名稱怎麼被組出來**：

- 名稱 ＝ `namenum(1)` ＋ `namenum(2)` ＋ `namenum(3)` 三段索引，
  **不是一句完整的字串**。中文化必須把名稱表拆成同樣三段，
  且 `0A1h` 起的「＋N」後綴要能接在中文名稱後面。
- ⚠ **英文的「A of B」語序**（`namenum(2) = 167` 那組）在中文要倒過來，
  三段的組法本身可能要改，不能只換詞。
- 卷軸的 `0D0h`／`0D1h` 與「N 個法術」`0D1h ＋ N` 同樣是組字。

## 明確不宣稱

- 沒有宣稱 `+35h`（`identified`）被寫成 `6`／`4` 各代表什麼
  ——spec 1011 給的名字在這裡看起來不是布林。
- 沒有宣稱 `+39h`（寫 0／5／`0Ah`）是什麼。
- 沒有宣稱 `+37h` 那張重量表裡非護甲部分逐一對應哪件武器。
- 沒有宣稱名稱表第 157／167／173／185／187／206／226／239／64／69／100／21 筆是什麼詞。
- 沒有宣稱範本索引 25 那一筆是誰用的（本支沒有出現）。
- 沒有宣稱兩種卷軸各自對應哪個施法職業（要另外查 `DS:37DAh` 才能定）。
