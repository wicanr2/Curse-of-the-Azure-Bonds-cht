# 783 — 兩平台同形配對（第一批三組）

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側的運算元差異已逐條列出）
- 工具：`scripts/pair_dump.py`

## 作法

`pair_dump.py` 找「兩平台同一個 entry、助憶碼序列相同（只比到最後一條 `ret`）、
而且**兩邊都還沒判讀**」的配對——全庫還有 **103 組、涵蓋 206 支**。

讀 DOS 側一支，再把 PC-98 側的運算元差異逐條列出來；**差異若全部落在 DS 位址、
overlay-local 位址與同模組的近呼叫目標，兩支就是同一份程式碼的兩個版本**。
只要出現常數或指令運算元的實質差別，就必須各自判讀（spec 760 的
`overlay-13:040B8h` 就是這種例外：DOS 是常數 `1Eh`、PC-98 是算出來的）。

下面三組的差異都只有位址。

## `overlay-32:0011h`（entry#2，41 條，差異 2 條）

```pascal
結果 := false;
if 第二索引 = 0 then 離開;
i := 第二索引 * 8 + 第一索引 * 2;
輸出A^ := byte[27A2h + i];        { PC-98：49ACh }
輸出B^ := byte[27A3h + i];        { PC-98：49ADh }
if 輸出A^ >= 0 then 結果 := true;  { 有號 }
```

`DS:27A2h` 是**每列 8 bytes、每格 2 bytes 的二維表**（所以一列四格），
兩個索引各自乘 8 與 2。取出來的是一對 byte，第一個為負代表「這一格無效」。

## `overlay-32:1355h`（entry#22，41 條，差異 10 條）

```pascal
地圖^[4] := 參數0;
i := 本模組 0CAEh(x, y);                    { spec 757 的索引查詢 }
地圖^[5] := byte[66A6h + i * 4];
if DS:75E6h <> 0 then
    本模組 09DFh(8, 參數2,
                 本模組 0C5Eh(x, y),         { spec 759：戰鬥員 y }
                 本模組 0C36h(x, y));        { spec 759：戰鬥員 x }
地圖^[4] := 0;
地圖^[5] := 1;
```

- 地圖緩衝區的表頭又多知道兩個 byte：**`+4` 與 `+5`**。它們被設成
  `(參數0, byte[66A6h + i*4])`，畫完馬上還原成 `(0, 1)`——所以那是**繪圖期間
  的暫時狀態**，不是持久欄位。表頭的 `+2` / `+3` 是戰場原點（spec 750）。
- `DS:66A6h + i*4` 與 spec 772 的 `overlay-13:48DCh` 寫的是同一個陣列。
- `DS:75E6h`（PC-98 `DS:0A878h`）是「要不要畫」的旗標。

## `overlay-14:0288h`（entry#6，43 條，差異 3 條）

```pascal
有 := false;
角色 := DS:650Ah;                            { PC-98：DS:9598h }
while (角色 <> NIL) and not 有 do begin
    if (角色^[109h + 索引] > 0)
       or ((角色^[111h + 索引] > 0) and <呼叫>(角色)) then 有 := true;
    角色 := 角色^[189h];                     { PC-98：+18Ah }
end;
結果 := 有;
```

「第一職業區塊 `+109h` 或第二職業區塊 `+111h`」這個組合與 spec 756 的
`overlay-19:3656h`、spec 757 的 `overlay-09:024Dh` 是同一個判準。兩個區塊相差
`8`，與既有結論一致。

**找到就停**——所以它只回答「隊上有沒有人」，不數人數。

## 明確不宣稱

- 沒有宣稱 `DS:27A2h` 那張二維表裝的是什麼，也沒有宣稱「第一個 byte 為負」
  之外的值域。
- 沒有宣稱地圖表頭 `+4` / `+5` 在繪圖期間代表什麼。
- 沒有宣稱 `overlay-14:0288h` 的索引參數選的是哪一種職業。
