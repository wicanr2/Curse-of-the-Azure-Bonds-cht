# 792 — 記憶法術的計時整條閉合（`'has memorized'`）

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側的運算元差異已逐條列出）
- 作法見 spec 783

## `overlay-20:091Dh`（entry#13，68 條，差異 7 條）— 記完一個，回報下一個的等級

| | DOS | PC-98 |
|---|---|---|
| 訊息 | `'has memorized'`（13，前後都沒有空白） | `'を覚えた'`（8 bytes） |

`retf 8` ＝ 兩個遠指標：`arg_4` 是角色、`arg_0` 指向一個 byte 旗標
（呼叫端給初值，本支會改寫）。

```pascal
結果 := 0;  i := 0;
while (i <= 53h) and (結果 = 0) do begin
    if 角色^[1Eh + i] > 7Fh then begin              { 最高位為 1：還在記 }
        if 旗標^ <> 0 then
            結果 := byte[37DBh + (角色^[1Eh+i] and 7Fh) * 10h]   { 法術等級 }
        else begin
            角色^[1Eh + i] := 角色^[1Eh + i] − 80h;              { 記好了 }
            <本模組 05D4h>(0);
            顯示(角色名 ＋ 'has memorized' ＋ 法術名);            { 0A54h:0634h }
            <011Ah:0048h>(角色^[1Eh + i]);
            旗標^ := 1;
        end;
    end;
    inc(i);
end;
```

## 這一支把三件事同時定下來

### 一、`+1Eh` 那 84 格的最高位是「**還在記憶中**」

清掉最高位的那一刻印出 `'has memorized'`。所以：

- **最高位 ＝ 1**：這個法術**還沒記完**，佔著格子但不能施放。
- **最高位 ＝ 0**：記好了，可以施放。

### 二、記一個法術要花「等級 × 3」拍

`旗標^ = 1` 那條路回傳的是**下一個還在記的法術的等級**，而 spec 789／791 的兩支
呼叫端拿到回傳值之後一律寫成 `byte[7573h + i] := 回傳值 × 3`。所以：

**`DS:7573h + i` 是「這個角色記完下一個法術還要幾拍」，值 ＝ 法術等級 × 3。**
等級越高記越久。

### 三、兩個呼叫端的旗標初值差別，意義出來了

| 呼叫端 | 節奏 | 旗標初值 | 效果 |
|---|---|---|---|
| `overlay-20:0B05h`（spec 791） | 每拍 | **0** | 讓一個法術**記完**（印訊息），再抓下一個的等級去重填倒數 |
| `overlay-20:0BB6h`（spec 789） | 每 12 拍 | **1** | **只查**下一個的等級去重填倒數，不讓任何法術記完 |

`0B05h` 還要求角色的 `+72h` 同時為 0 才動手——`+72h` 是那個十二拍才減一次的
長週期計數（spec 789）。

## 撤回：spec 788 的最高位語意

spec 788 原本寫「最高位是**已施放／待施放**的旗標」。那是從
`overlay-15:0188h`（清掉 `> 7Fh` 的格子）的形狀猜的，沒有證據。
`'has memorized'` 這條訊息推翻它：最高位是**還在記憶中**。

連帶更正：`overlay-15:0188h` 清的是「**還沒記完**的格子」（例如休息被打斷），
不是「已施放的格子」。spec 788 正文已改寫。

## `overlay-15:2309h`（entry#24，68 條，差異 19 條）

`retf 4` ＝ 一個遠指標輸出 byte。整支由巢狀程序組成（每個呼叫都多推一個 `bp`
當靜態鏈）：

```pascal
輸出^ := 0;
if <2069h>() = 0 then 離開;
<1EFDh>();
if <2069h>() = 0 then begin
    <14F8h+2>(DS:6506h);  <15ADh+1>();
end else begin
    Move(DS:7566h, 暫存, 0Eh);                { 存下 14 bytes }
    <20C5h>();
    輸出^ := <10AEh+1>(0);
    if 輸出^ = 0 then begin
        <1FB9h>();  <2255h>();
        <14F8h+2>(DS:6506h);  <15ADh+1>();
        Move(暫存, DS:7566h, 0Eh);            { 失敗才還原 }
    end;
end;
```

`Move` 的參數順序由推入順序判定（先推的是第一個宣告參數）：第一次是
`Move(DS:7566h → 暫存)`，第二次反過來。

**只有在 `10AEh+1` 回 0（＝ 輸出 0）時才還原**；回非 0 就把改過的 14 bytes 留著。

`DS:7566h` 這 14 bytes 的結尾正好接上 spec 791 的倒數陣列基底
（`7566h + 0Dh = 7573h`）；兩者相鄰，但**本支沒有證據說它們是同一張表**。

## 明確不宣稱

- 沒有宣稱 `011Ah:0048h` 做什麼（收到剛記好的那個 byte）。
- 沒有宣稱 `overlay-20:05D4h` 的參數 `0` 是什麼。
- 沒有宣稱 `+72h` 那個長週期計數代表的遊戲內時間。
- 沒有宣稱 `overlay-15:2309h` 是哪一個畫面；只確定它會存／還原 `DS:7566h`
  起的 14 bytes。
- 沒有宣稱 `DS:7566h` 那 14 bytes 與 `DS:7573h` 的倒數陣列有關。
