# 1116 — AI 的決策層接進 remake：門檻掃描、士氣編碼，與一個不該照抄的 off-by-one

- 證據等級：`exact`（規則來自 spec 835／836／758／802，逐條對照）
- 對應工作項：`RE-07` → `ENG-08` 的決策那一格

## 接了什麼

在這一輪之前，怪物**只要身上有魔法飛彈就一定放**。原作不是這樣：AI 每回合先擲
1d7 決定「肯將就到什麼程度」，門檻從 7 往下降，候選要靠法術屬性表 `+0Dh` 的分數
過門檻才會被選中。

| 規則 | 出處 | 實作 |
|---|---|---|
| 門檻 7 起、每輪降 1、掃 1d7 輪 | 835／836 | `combat.AIThresholdScan` |
| 施法每輪隨機抽 3 個候選 | 836 | `Battle.AIChooseSpell` |
| 用道具每輪全掃物品鏈 | 835 | `Battle.AIChooseItemEffect` |
| 效果碼 `> 38h` 減 `17h` | 835 | `AIRemapItemEffect` |
| `+0F7h` 士氣編碼 | 758 | `MoraleValue` |
| 分數來自屬性表 `+0Dh` | 802／1111 | 遊戲層用 `gamepack.SpellByID(...).AIPriority` 供給 |

分數的來源正是 `ENG-09` 那一輪匯出的法術主表——資料先建好，決策層才接得上。

## 骨架的兩個細節

**1d7 一定要擲，即使沒有候選。** 原作在檢查清單之前就擲了（835 與 836 都是），
省掉它會讓後續的亂數序列整條偏掉。`TestThresholdScanAlwaysRollsTheRoundCount`
數擲骰次數把它釘住。

**查不到分數的候選一律略過，不能當成分數 0。** 門檻會降到 0，屆時「分數 0」
會突然變成合法選擇——沒有資料的法術就這樣被放出來了。

## 士氣：`+0F7h` 不是士氣值本身

bit 7 是「這個值有效」的旗標，低 7 位存的是**原值的一半**，讀出來要乘 2；
超過 `66h`（102）一律當 0。所以資料裡最常見的 `0B3h` 不是 179，
是「旗標已設、原值 102」。

士氣崩了（旗標有效但值為 0）就不施法——這是 spec 836 的第一道前置閘門。

## ⚠ 一個**不該**照抄的 off-by-one

spec 836 讀到 AI 收集法術清單時是 `for k := 1 to 53h`，從 `+1Fh` 開始，
所以角色記錄 `+1Eh` 那一格對 AI 是隱形的（而玩家記的第一個法術正好落在那裡）。

**這個 quirk 在 remake 這一層重現不了。** `Fighter.MonsterSpellIDs` 是**壓縮過**
的清單：`internal/monster` 從 `+33h..+6Ah` 讀進來時就把 0 濾掉了，索引 0 不等於
`+1Eh`。在壓縮清單上「跳過第一個」等於隨機丟掉一支真的法術——那是照抄表面、
丟掉語意。

> 這一輪先寫成跳過第一格，測試也綠——**綠的是錯的東西**。
> 要真的重現它，得先保留帶洞的原始槽位陣列，那是另一輪的事。
> `TestSpellCandidatesDoNotSkipTheCompactedFirstEntry` 釘住「不跳過」，
> 免得日後有人照著 spec 836 的字面再補上去。

## 決策選到 remake 還沒實作的法術時

`monsterWantsToCast` 回 false，回合退回物理攻擊——**不是把回合丟掉**。
缺的是那支法術的效果（`ENG-09`），不是決策。

## 還沒接的部分

- **恐慌逃走的訊息**（830：`+14h ≠ 0` 且 `+10h = 0` 時印 `flees in panic`）：
  兩個都是戰鬥狀態記錄的欄位，remake 沒有建那份 22 bytes 的記錄。
- **自動換裝**（1004）：需要戰鬥中重算裝備槽，remake 的裝備投影是進場時算一次。
- **目標挑法**：仍用既有的 `selectEnemyPhysicalTarget`，不是 spec 838 §五的
  「射程內候選清單 ＋ 隨機挑一個」。
- **移動的兩種障礙豁免效果**（837 的效果碼 `1Eh`／`20h`／`3Fh`／`6Fh`／`7Dh`／
  `81h`／`85h`）：目前只看地形與佔位。
