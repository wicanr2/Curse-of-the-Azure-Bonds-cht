# 1101 — 建角的 HP：八個職業槽各擲一次 HD，加體質後除以職業數

- 狀態：`READY`
- 證據等級：`exact`（DOS `overlay-17:00782h` 的 `21C1h`..`2290h` 逐條讀完）
- 這一段是 spec 1093 建角流程的收尾，spec 1093 §六 沒有涵蓋
- 用到的兩支已有各自的規格：
  [`850`](850-hit-dice-and-effective-level.md)（`sub_4A12` 擲 HD）、
  [`869`](869-constitution-bonus-per-class-slot.md)（`sub_45E9` 體質加值）

## 一、程式碼

```pascal
{ 前面的迴圈掃 c := 0..7，只有 角色^[109h + c] > 0 的槽才 inc 職業數 }

角色^[103h] := 12Ch;                              { 300，見 §四 }

角色^[12Ch] := <sub_4A12>(角色, 遮罩 := 0FFh);    { 擲 HD，八個職業槽全算 }
角色^[78h]  := 角色^[12Ch];

調整 := 有號(<sub_45E9>(角色));                    { 體質加值，可正可負 }
if 調整 < 0 then begin
    if 角色^[78h] <= 職業數 ＋ abs(調整) then
        角色^[78h] := 1                           { ★ 下限是 1 }
    else
        角色^[78h] := (角色^[78h] ＋ 調整) div 職業數;
end else
    角色^[78h] := (角色^[78h] ＋ 調整) div 職業數;

角色^[1A4h] := 角色^[78h];                        { 目前 HP ＝ 最大 HP }
角色^[12Ch] := 角色^[12Ch] div 職業數;            { ★ 基礎最大 HP 也要除 }
```

`+78h` ＝ 最大 HP、`+12Ch` ＝ 基礎最大 HP、`+1A4h` ＝ 目前 HP（spec 1079）。

## ★★★ 二、多職業就是「全部擲完再平均」

`sub_4A12` 的職業遮罩傳 `0FFh` ⇒ **八個職業槽全部納入**，
所以它回傳的是「這個角色所有職業第一級的 HD 總和」。
體質加值 `sub_45E9` 同樣是**逐職業槽各給一份**（spec 869），
所以雙職角色會拿到兩份體質加值——最後一起除以職業數，等於各拿一份。

> ★★★ 這與 AD&D 一版的多職業規則一致：多職角色的 HP 是各職業 HP 的平均。
> ★★ 同樣的「加調整再除以職業數」形狀也出現在 `sub_46EC`（有效等級，spec 850）
> 與 `sub_47C6`（HP 上限，spec 1055）。**三支各自有一份內嵌的實作**，
> 不是共用副程式。

### 建角時 `sub_4A12` 實際會走的路

建角後每個職業槽的等級都是 1，所以 spec 850 裡「過了 HD 上限改給固定值」
那條路走不到，一律走擲骰路：

| 槽 | 職業 | 擲法（`DS:0818h` × `DS:0820h`） | 備註 |
|---|---|---|---|
| 0 | 牧師 | 1d8 | |
| 1 | 德魯伊 | 1d8 | |
| 2 | 戰士 | 1d10 | |
| 3 | 聖騎士 | 1d10 | |
| 4 | 遊俠 | **2d8** | 一級兩顆骰 |
| 5 | 法師 | 1d4 | |
| 6 | 盜賊 | 1d6 | |
| 7 | 武僧 | **2d4** | 一級兩顆骰 |

⚠ **每個槽都擲兩次取大**（spec 850）——不是 AD&D 規則，是引擎自己加的。
照抄的話期望值會比桌上規則高一截。

⚠ 遊俠槽等級為 1 時，`sub_45E9` 會把**累積到當下的整個體質加值總和乘 2**
（spec 869），不只是遊俠那一份。多職角色若遊俠槽之前已經累加過別的職業，
那些也會一起被乘 2。

## 三、`+109h + i` 的語意早有定案：是職業槽等級

同一組欄位在 spec 1034、850、869、857、1055 各被獨立確認過一次，
建角這一支的 `mov byte ptr es:[di+109h], 1` 是**產生端**：
選完職業組合後，屬於該組合的每個槽都寫 1。

⇒ `sub_46EC`（`(等級總和 ＋ 調整) div 職業數`）算的是**有效等級**，不是 HP；
HP 走的是本規格與 `sub_47C6` 兩條路。**兩者形狀相同但輸入不同**，不可混用。

## 四、順帶：AD&D 的起始金錢被擲出來又丟掉

同一個 `c := 0..7` 的迴圈裡，每個有等級的槽都會擲一次
`ROLLDICE(byte[DS:45B1h ＋ c × 2], byte[DS:45B2h ＋ c × 2])`
並累加到一個區域變數——**那個變數整支函式再也沒有被讀過**。

| 槽 | 職業 | 擲法 | ＝ AD&D 1e 起始金錢 |
|---|---|---|---|
| 0 | 牧師 | 3d6 | 3d6 × 10 gp ✓ |
| 1 | 德魯伊 | 3d6 | ✓ |
| 2 | 戰士 | 5d4 | 5d4 × 10 gp ✓ |
| 3 | 聖騎士 | 5d4 | ✓ |
| 4 | 遊俠 | 5d4 | ✓ |
| 5 | 法師 | 2d4 | 2d4 × 10 gp ✓ |
| 6 | 盜賊 | 2d6 | 2d6 × 10 gp ✓ |
| 7 | 武僧 | 5d4 | ✓ |

> ★★★ **八格全部命中 AD&D 一版的起始金錢表**，所以 `DS:45B1h`／`45B2h`
> 的身分沒有疑問。但結果被丟棄，改成寫死的 `角色^[103h] := 12Ch`。
> ⚠ 擲骰本身有副作用（消耗亂數序列），remake 若要逐位元重現亂數流就不能省。
> ⚠ `+103h` 是 spec 622 的五個硬幣欄位之一（該規格推 `+101h` gp、`+103h` pp）。
> 300 這個值偏大，本規格**不宣稱** `12Ch` 的幣別與單位。

## 對 remake 的意義

- 建角完成時要補上 HP：逐槽擲 HD（兩次取大）＋ 逐槽體質加值，再除以職業數。
- `目前 HP` 直接等於最大 HP，`基礎最大 HP` 是**未加體質的總和除以職業數**
  ——與最大 HP 不同，兩格要分開存。
- 起始金錢那一擲可以略過（結果沒人用），但亂數序列會因此偏移。

## 明確不宣稱

- 沒有宣稱 `12Ch` 寫進 `+103h` 的幣別與用意。
- 沒有宣稱被丟棄的起始金錢是刻意還是 Pool of Radiance 留下的殘碼。
- 沒有宣稱 PC-98 對側（`pc98 overlay-17:00AFBh`，spec 1094）這一段是否逐條相同。
