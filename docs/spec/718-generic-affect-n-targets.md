## 兩個容易在改寫時被「修掉」的地方

**預算先扣、再檢查有沒有重複。** 一個已經帶著該效果的目標會**吃掉一格預算**
然後被清掉。所以「這個法術最多影響 N 個」在實際上是「最多**嘗試** N 個」。
改寫成「檢查通過才扣」會讓法術變強。

這和 spec 715 的 Sleep 正好相反：Sleep 對已經睡著的目標**不扣**預算。
兩支的處理不一致，所以不能拿其中一支的行為去補另一支。

**第二個迴圈用的還是原來的筆數。** 上面把不合格的格子寫成 `NIL`，但
`DS:7434h` 沒有變，所以 `entry#4` 會被餵到 `NIL`。`entry#4` 收 3 個 word
（`retf 6`），第一個就是那個 far 指標。

## 這是共用的實作

三個參數（訊息、類別 `arg_4`、效果編號 `arg_6`）都由呼叫端給，函式本身不含任何
法術專屬的常數。所以好幾條法術 opcode 應該都是「填三個參數呼叫這一支」——
`overlay-22` 裡 `retf 8` 且第一個參數是字串的呼叫端值得一併整理。
