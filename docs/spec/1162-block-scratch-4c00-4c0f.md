# 1162 — `4C00h`..`4C0Fh` 是每一段自己的暫存

- 證據等級：`exact`（守衛條件、寫入端與分派表逐位元組讀出）＋ `measured`（整條主線實跑）
- 查詢工具：`cmd/ecl-cell-refs`（走 `ecl.TraceGraph`）、`cmd/ecl-window -at`
- 取代 spec 1142 對 `4C00` 區的懸而未決結論

## 結論

ECL 位址 `4C00h`..`4C0Fh` 這 16 格是**每一段 ECL block 自己的暫存**：換段時
收起目前這一段的值、換上目標那一段的值，沒跑過的段從 0 開始。`4C10h` 以上與
`4B00h`..`4BFFh` 維持整個 session 共用。

實作在 `internal/ecl/session.go` 的 `swapBlockScratch`，由 `Switch` 觸發。

## 為什麼是這 16 格

`cmd/ecl-cell-refs -range 4C00-4C0F` 把每一格的存取端逐條列出來，結果整齊得
不像巧合：**這 16 格沒有任何唯讀的消費者**——會讀某一格的 block，一定自己也
寫那一格。

`4C10h` 以上正好相反，跨段交接俯拾即是：

| 格子 | 寫 | 只讀 | 語意 |
|---|---|---|---|
| `4CE3` | `ECL4/0x20` | `ECL4/0x21`、`ECL4/0x22` | 「你是怎麼進贊提爾堡神殿的」，`ECL4/0x21:003Fh` 的 `ON GOTO` 索引 |
| `4C59` | `ECL5/0x33` | `ECL1/0x50`、`ECL1/0x51` | 巫師塔的崔坎卓斯已死 |
| `4C5A` | `ECL4/0x22` | `ECL1/0x50`、`ECL1/0x51`、`ECL3/0x10` | 眼魔洞穴的 Dexam 已死 |
| `4C5B` | `ECL3/0x11`、`ECL3/0x12` | `ECL1/0x50`、`ECL1/0x51` | 猶拉什那位已死 |
| `4C2A` | `ECL2/0x04` | `ECL2/0x03` | 提爾弗頓下水道進度 |
| `4CE4` | `ECL4/0x20` | `ECL4/0x23` | 同上一類 |

立石群的灰袍男子就是靠這三格數人頭：`ECL1/0x50:0232h` 起把 `4C59`、`4C5B`、
`4C5A` 各算一分，湊滿三分（`028Bh IF =`）才揭露烈焰之主並指向密斯卓諾。
把 `4C10h` 以上也換成 per-block，這段劇情立刻壞掉。

`4B00h`..`4BFFh` 同樣不能換：`4BE6h` 是重畫髒旗標、`4BF0h`／`4BF1h` 是移動前的
座標快照、`4BF2h` 是「上一段 ECL 的編號」——由**離開的那一段自己寫**
（`ECL1/0x50:008Eh SAVE 50 4BF2`）給**下一段**讀（`ECL6/0x40:0059h`）。

## 判定證據：眼魔洞穴的死精靈

共用一份 `4C06` 時，主線走到眼魔洞穴會出現這條鏈：

```
ECL1/0x51:0B4Fh  GETTABLE 9C96 4C9D 4C06     { 旅行表查出這一段路的耗時 }
ECL1/0x51:0C2Fh  MULTIPLY 4C06 02 4C06       { 依旅行方式加權，離開時 4C06 = 4 }
ECL4/0x22:0651h  COMPARE  4C06 01
ECL4/0x22:065Ch  IF <     → 066Bh            { 第一次：SAVE 01 4C06 後開選單 }
ECL4/0x22:0661h  SAVE     00 4C06            { 4C06 > 1 這條：歸零，不開選單 }
```

`4C06 = 4` 走的是最後那條，死精靈的遺骸只唸敘述、不給
`EXAMINE REMAINS`／`LEAVE` 選單，於是袋子、毒氣陷阱與**冒險手札第 59 條的地圖**
整串拿不到。手札 59 是主線內容，眼魔洞穴又是必經之地——原作不可能讓這三格共用
同一個字。

同一個字在三個地方各有各的用途，彼此都排斥：

| 使用者 | 用途 |
|---|---|
| `ECL1/0x50`／`0x51` | 旅行耗時暫存（每一段路重算） |
| `ECL4/0x21` | 神殿某間房的一次性獎勵標記（`0D78h` 守衛／`0F20h` 設定） |
| `ECL4/0x22` | 死精靈選單的一次性標記（0 未看、1 看過、3 拿走袋子） |

## spec 1142 那五間房

密斯卓諾內城與散提爾堡城區那幾格「走到了卻沒有反應」的房間，全部是同一個
成因，換成 per-block 之後逐一復原：

| 房間 | 守衛 | 換成 per-block 之後 |
|---|---|---|
| 內城廚房 `(13,14)` | `COMPARE AND 4C06,0 4C07,0` | 唸得出來（走正門進來時 `4C07 = 0`）|
| 內城辦公室 `(11,12)` | `4C05` 一次性 | 唸得出來 |
| 食品儲藏室 `(14,4)` | `COMPARE 4C0B,1 → EXIT` | 唸得出來 |
| 冥想中的祭司 `(14,11)` | `COMPARE AND 4C08,0 4C00,0` | 仍安靜，但理由換成 `4C00`（儀式那場打完警報已起）|
| 禮拜中的祭司 `(14,8)` | `COMPARE AND 4C09,0 4C00,0` | 同上 |

⚠ 兩件事順手校正：

- **「下水道塌了」`(15,15)`**：`ECL6/0x43:0E47h COMPARE 4C07 0 → IF = → EXIT`。
  這句只有**從下水道進來**（前導 `00EEh SAVE 1 4C07`）才唸得到。走正門的路線
  看不到它是對的，不是被壓掉。
- **停屍架與棺木 `(10,1)`**：地形 `0x93`，`ON GOTO (C04F & 0x7F)` 的第 19 支是
  一句 `EXIT`（`10EAh`）。有內容的是地形 `0x94`（`10EBh`，要 `4C0E == 1`）與
  `0x95`（`10FBh`，要 `4C0F == 0 且 4C0E == 0`）那兩格。這一格本來就不唸。

## 讀「別段那一份」

隊伍換段之後 `MemoryValue` 只看得到眼前這一段的暫存。要驗「某一段留下什麼」
用 `BlockSession.BlockMemoryValue(blockID, address)`。

## 存檔

remake 自己的存檔（`SessionSnapshot.BlockScratch`）把停在旁邊那幾段的暫存也
帶著，讀檔之後走回去，演過的房間不會再演一次。

原版版面（SAVGAM）的 `Area1` 就是區 0（spec 1163），裡面 `4C00h`..`4C0Fh` 只有
一份 ⇒ **原作只保證「目前這一段」的一次性旗標跨存檔存活**。remake 這一側比原版
多留一點狀態，不會少。

## 還沒解決的

**換段的引擎側機制沒定位。** 這裡是從 ECL 側的存取模式反推的：per-block 是唯一
同時容得下「三處各用各的 `4C06`」與「`4CE3` 跨段交接」的切法。DOS 側真正在哪裡
搬這 16 格還沒找到。
