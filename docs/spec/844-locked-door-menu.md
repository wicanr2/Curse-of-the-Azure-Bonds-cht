# 844 — 上鎖的門：Bash／Pick／Knock 三選項與 PC-98 的固定槽選單

- 證據等級：DOS 側 `exact`（逐條讀完）；PC-98 側**只列差異，本體尚未讀完**
- 作法見 spec 783

## `overlay-14:00BAFh`（DOS，334 條）

`retf`（無參數）。PC-98 的同 entry 是 `overlay-14:00BCCh`，只有 190 條，
助憶碼相似度 **0.615**——**兩平台真的不同**，PC-98 要另外讀。

| | DOS | PC-98 |
|---|---|---|
| 提示 | `'Locked. '` | `'鍵がかかっている'` |
| 撞門 | `'Bash'` | `'蹴破る'` |
| 開鎖 | `' Pick'` | `'鍵開け'` |
| 敲門 | `' Knock'` | `'ノック'` |
| 離開 | `' Exit'` | `'やめる'` |

```pascal
結果 := 0;
if DS:4FBAh <> 4 then goto 收尾;
if word(遠指標(DS:4F9Dh)^[592h]) >= 0FFh then begin        { 無號 }
    遠指標(DS:4F9Dh)^[592h] := 0;  goto 收尾;
end;
DS:7580h := 1;

r := <far 17Fh:39h>(DS:720Fh, DS:7210h, DS:7211h);

if r = 1 then 結果 := 1
else if (r = 2) or (r = 3) then begin
    選單 := '';
    if DS:7588h <> 0 then                              選單 := 'Bash';
    if (DS:7589h <> 0) and <本模組 0288h>(6) then       選單 := 選單 ＋ ' Pick';
    if (DS:758Ah <> 0) and (<本模組 06F4h>(1Fh) <> 0) then 選單 := 選單 ＋ ' Knock';
    選單 := 選單 ＋ ' Exit';

    if 選單 = ' Exit' then                             { 一個選項都沒有 }
        <本模組 003Eh>(DS:720Fh, DS:7210h, DS:7211h)

        if      鍵 = 42h then 結果 := <本模組 0302h>()        { 'B' }
        else if 鍵 = 50h then
            if r = 2 then 結果 := <本模組 05E8h>()            { 'P' }
            else          DS:7589h := 0                       { ⚠ r = 3 時只是關掉選項 }
        else if 鍵 = 4Bh then 結果 := <本模組 0749h>();       { 'K' }
```

## 三個開關決定選單長什麼樣

| 全域（DOS） | PC-98 | 控制 |
|---|---|---|
| `DS:7588h` | `DS:0A81Ah` | 有沒有 `Bash` |
| `DS:7589h` | `DS:0A81Bh` | 有沒有 `Pick`（還要 `0288h(6)` 成立） |
| `DS:758Ah` | `DS:0A81Ch` | 有沒有 `Knock`（還要 `06F4h(1Fh)` 回非 0） |

`0288h(6)` 形狀上是「隊上有沒有能開鎖的職業」（`6` 是職業碼位置），
`06F4h(1Fh)` 回傳 32 bit，形狀上是「有沒有人記了第 `1Fh` 號法術」——
`1Fh` ＝ 31，查 `DS:27BDh` 的法術名稱表可對，本規格不代查。

**沒有任何可用手段時整個選單只剩 `' Exit'`**，程式用字串比對
（`0A54h:724h` 比 `選單` 與 `' Exit'`）判斷這件事，直接走 `003Eh` 而不開選單。

## ⚠ 模式 3 選 Pick 不會開鎖，只會把選項關掉

`r = 2` 與 `r = 3` 兩條路的選單組法完全相同，差別只在 `'P'`：

- `r = 2`：`結果 := <本模組 05E8h>()`——真的去開鎖。
- `r = 3`：`DS:7589h := 0`——**只是把 Pick 從選單上拿掉，什麼也沒做**。

PC-98 那一側雖然整段結構重寫過，**同一個寫法還在**（`mov byte ptr ds:0A81Bh, 0`），
所以這不是反組譯錯位，是兩平台一致的行為。remake 要照抄的話，這一格得標成
「已知怪行為」。

## PC-98 的選單改成固定槽 ＋ 獨立熱鍵

DOS 是「把 `'Bash'`／`' Pick'`／`' Knock'`／`' Exit'` 串起來成一個字串，再讓選單程式
從字串裡找大寫字母當熱鍵」。PC-98 改成：

```
mov di, 0A362h ; …Move(6 bytes) ; mov byte ptr ds:0A33Ah, 42h   { 'B' }
mov di, 0A369h ; …Move(6 bytes) ; mov byte ptr ds:0A33Bh, 50h   { 'P' }
mov di, 0A370h ; …Move(6 bytes) ; mov byte ptr ds:0A33Ch, 4Bh   { 'K' }
mov di, 0A37Eh ; …Move(6 bytes)
```

**四個標籤各是固定 6 bytes（＝ 3 個全形字），寫進資料段的固定槽；熱鍵是另外三個
ASCII byte。**這與 spec 817 在別的選單看到的手法完全一樣：
**PC-98 把「熱鍵藏在標籤裡」拆成「標籤」與「熱鍵」兩份資料**。

那四個槽（`DS:0A362h`／`0A369h`／`0A370h`／`0A37Eh`）與三個熱鍵格
（`DS:0A33Ah`..`0A33Ch`）在 dump 裡全是 `FFh`——它們落在 PC-98 資料段的
BSS 區（`DS:7880h` 之後，spec 804），確認是執行期緩衝而非烘進去的表。

**中文化直接沿用 PC-98 的形狀最省事**：標籤 3 個全形字、熱鍵維持英數。
DOS 那種「從英文標籤裡挑大寫字母」的作法在中文下不可行。

DOS 的判斷式 `選單 = ' Exit'` 在 PC-98 換成一個布林區域變數（`var_3`），
不再做字串比對——中文化若沿用 DOS 版，這個字串比對要一起改。
