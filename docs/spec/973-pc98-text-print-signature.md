# 973 — 定案 PC-98 的印字入口 `0418h:0D17h`，並讀三支呼叫端

- 證據等級：`exact`（被呼叫端與三個呼叫端都逐條讀完，簽章由被呼叫端自己的
  堆疊框推出，不是從呼叫端猜的）
- 作法見 spec 783

## `0418h:0D17h` ＝ `PC98-GAME.EXE:14E97h`（82 行）

`0418h` 是**相對段**：IDA 的載入基底是 `1000h`，所以 `0418h:0D17h` 的線性位址是
`(1000h ＋ 0418h) × 10h ＋ 0D17h` ＝ `14E97h`。
⚠ IDA 在 overlay 那邊把這個呼叫印成 `call far ptr loc_4E95+2`——那是
**overlay 自己段內偏移撞號**造成的假標籤，與 spec 928 的 entry stub 撞號同一類。
追資深呼叫目標時要先把基底加回去。

### 簽章（`retf 0Ch`，五個參數）

被呼叫端的堆疊框把順序定死了。Turbo Pascal **由左至右推疊**，所以
**位址最高的 `[bp+10h]` 是第一個宣告的參數**：

| 位置 | IDA 名 | 型別 | 意義 |
|---|---|---|---|
| `[bp+10h]` | `arg_A` | byte | **欄**（全形單位，`≤ 27h`；callee 內部 `× 2` 才是文字格） |
| `[bp+0Eh]` | `arg_8` | byte | **列**（`≤ 27h`） |
| `[bp+0Ch]` | `arg_6` | byte | **顏色**（經 `DS:1928h` 那張表轉換） |
| `[bp+0Ah]` | `arg_4` | byte | 未辨識，三個呼叫端全部給 `0` |
| `[bp+6]` | `arg_0` | far ptr | **字串** |

```pascal
StoreString(字串^, 本地, 0FFh);                    { 1AC99h }
if (欄 <= 27h) and (列 <= 27h) then begin
    <本模組 145CAh>(@暫存 203h, @本地, 0);         { 814 條，尚未讀 }
    本地 := 限長(本地, 0FFh);
    顏色 := byte[1928h + 顏色];
    <1692Dh>(欄 × 2, 列, 顏色, arg_4, 長度(本地), @本地[1]);
end;
```

### 為什麼欄是 `arg_A`

三件事互相印證：

1. **只有 `arg_A` 被乘 2**。PC-98 一個全形字佔兩個文字格（spec 953），
   所以會被加倍的那一個是水平座標。
2. **`overlay-16:03FB7h` 的版面**（見下）用 `arg_A ∈ {0, 14h}`、
   `arg_8 ∈ {5,7,9,11,13}`。當成「欄 0 與欄 20（＝文字格 0 與 40）、
   列 5..13 每隔一列」就是標準的**兩欄十列清單**；反過來當成「列 0 與列 20、
   欄 5..13」則五個 40 字長的字串會互相蓋掉，不可能成立。
3. 上界 `27h` ＝ 39 ⇒ 欄 0..39 全形 ＝ 文字格 0..78，正好是 PC-98 的 80 欄。

### ⚠ 既有規格的參數順序

`spec 757`（`(該指標, 0, [+20h], [+1Ch] + …, [+1Eh])`）與
`spec 767`（`(@s, 0, 0Ah, x, y)`）、`spec 970`（`(0, 顏色, arg_2, arg_4, 名字)`）
列的都是**推疊的相反順序（pop 順序）**。欄位對應本身：

- spec 757 與 spec 970 **正確**（757 的 `[+1Eh]` 是欄、`[+1Ch]+…` 是列；
  970 的 `arg_4` 是欄、`arg_2` 是列）。
- **spec 767 的 `x`／`y` 標反了**：`overlay-24:0B41h` 推的是
  `arg_2`（欄）→ `arg_0`（列）→ `0Ah` → `0` → `@s`。已就地更正。

## `pc98 overlay-16:03FB7h`（53 條，`retf 0`）— 兩欄十列的清單

```pascal
for i := 0 to 4 do begin
    印字(0,   5 + i×2, 0Ah, 0, @DS:[0A648h + (i + 1) × 29h]);
    印字(14h, 5 + i×2, 0Ah, 0, @DS:[0A648h + (i + 6) × 29h]);
end;
```

`DS:0A648h` 起是 **10 筆各 41 bytes（`29h`）的字串**（索引 1..10，索引 0 那筆
不畫）。41 ＝ 長度 byte ＋ 40 個字元，正好是一欄 40 個文字格 ＝ 20 個全形字。
靜態內容全是 `FFh`，**執行期才填**。

顏色固定 `0Ah`，兩欄都一樣——這一支是**整張清單的重畫**，沒有反白邏輯。

## `pc98 overlay-26:00BFEh`（48 條，`retf 4`）— 重畫清單裡的一項

`(視窗記錄的 SS 偏移 arg_0, 項次 arg_2)`。

```pascal
p := <本模組 0011h>(項次, 視窗^[16h], 視窗^[14h]);      { 回遠指標 }
色 := 視窗^[24h];
if p^[51h] = 0 then 色 := 視窗^[22h];
印字(視窗^[1Eh], 視窗^[1Ch] + (項次 − DS:0A32Ch), 色, 0, p);
```

- **`arg_0` 是 SS 偏移不是遠指標**（`mov di,[bp+arg_0]` 後一律用 `ss:` 前綴），
  所以視窗記錄放在呼叫端的堆疊框上。
- **`列 := 視窗^[1Ch] ＋ (項次 − DS:0A32Ch)`**：`DS:0A32Ch` 是捲動起點，
  第一個可見項就畫在 `+1Ch` 那一列。
- **`+22h` 與 `+24h` 是同一項的兩種顏色**，由項目物件自己的 `+51h` 決定用哪一個。

視窗記錄的欄位到此累積成：

| 位移 | 內容 | 出處 |
|---|---|---|
| `+14h`、`+16h` | 傳給 `0011h` 的兩個 word | 本支 |
| `+1Ch` | 起始列 | 本支、spec 757 |
| `+1Eh` | 欄 | 本支、spec 757 |
| `+20h` | 一種顏色 | spec 757 |
| `+22h`／`+24h` | 另兩種顏色 | 本支 |

## `pc98 overlay-28:00016h`（52 條，`retf 0`）— 只有 PC-98 有

DOS 側沒有對應函式（單邊）。

```pascal
if DS:0A325h = 50h then DS:0A66Ch := 0;
if DS:7F34h <> 0 then 離開;                        { 連結尾都跳過 }

if word(遠指標(DS:7F05h)^[1CCh]) <> 0 then begin    { 在迷宮裡 }
    DS:0A2ADh := <overlay-30 entry#6>(DS:0A2A9h, DS:0A2AAh);   { 讀地圖第二平面 }
    if DS:0A2ADh > 7Fh then                                     { 無號 }
        DS:0A2A4h := byte[164Ch + word(遠指標(DS:7F05h)^[1FCh])]
    else
        DS:0A2A4h := byte[164Ch + word(遠指標(DS:7F05h)^[1FAh])];
    DS:0A2A7h := 8;
    if word(遠指標(DS:7F05h)^[1F6h]) <> 0 then DS:0A2A8h := 0;
    <overlay-30 entry#7>(DS:0A2A9h, DS:0A2AAh, DS:0A2ABh);
end
else if DS:0A66Ch <> 0 then begin
    <overlay-29 entry#9>(79h);                     { 載入 bigpic 編號 121 }
    <overlay-29 entry#10>();                       { 顯示後釋放 }
end;
DS:0A66Ch := 0;
```

★ **`79h` ＝ 121 就是世界地圖**。spec 343 從資料側認出 `BIGPIC1.DAX` 的
block `0x79` 是 304×120 的月海／谷地世界地圖，spec 305／320 也記過「BIGPIC 121」。
本支是**程式側第一次直接證實**：不在迷宮裡（`+1CCh` ＝ 0）而且 `DS:0A66Ch`
有設，就把 121 號大圖叫出來。

`overlay-30 entry#6` 是 spec 763 的「讀迷宮地圖第二平面」，`entry#7` 是相鄰的
第 7 號向量。地圖那一格的值 `> 7Fh`（最高位有設）與否，決定 `DS:0A2A4h`
從兩個不同的欄位去查 `DS:164Ch` 那張表——**最高位是「特殊格」旗標**，
與 spec 763 讀到的兩平面首尾相接一致。

### 順帶定案兩個跨平台對應

`overlay-29` 的整批釋放（DOS `055Bh` ／ PC-98 `0045Ah`，見 spec 971／760）
在同一個位置各寫兩個全域，加上本支與 spec 876 都用 `= 50h` 分支：

| DOS | PC-98 | 釋放後寫入 |
|---|---|---|
| `DS:7278h` | `DS:0A313h` | `0` |
| `DS:728Ah` | `DS:0A325h` | `0FFh` |

`50h` ＝ 80 這個門檻在 DOS（spec 876）與 PC-98（本支）都出現，
**兩平台是同一個判斷**。本規格不宣稱 80 代表哪一張圖。

## 中文化

`0418h:0D17h` 是 PC-98 的**主要文字輸出口**，中文化必經之路。三個硬限制：

1. **欄的單位是全形字**，callee 自己乘 2；改版面時算的是全形格數，不是文字格。
2. **欄與列都必須 `≤ 27h`（39）**，超出**整支靜默不畫**——沒有錯誤訊息。
   把中文字串排到第 40 欄以後會什麼都不出現。
3. **一列最多 40 個文字格 ＝ 20 個全形字**（`overlay-16:03FB7h` 的 41-byte 記錄
   就是照這個長度配的）。

`0418h:0D17h` 內部先過 `145CAh`（814 條，本輪未讀）才送去畫，中文化前
要把那一支讀完——它是字串進 VRAM 之前唯一的加工點。

- 沒有宣稱 `DS:1928h` 那張顏色轉換表的內容。
- 沒有宣稱 `145CAh`／`1692Dh`／`1AC99h` 各做什麼。
- 沒有宣稱 `DS:0A648h` 那十筆字串裝什麼（靜態全 `FFh`）。
- 沒有宣稱 `overlay-26:00011h` 回傳的物件是什麼（只知道 `+51h` 是選色旗標）。
- 沒有宣稱 `DS:0A66Ch`／`DS:7F34h`／`DS:0A2A4h`／`0A2A7h`／`0A2A8h`／`0A2ADh`
  各代表什麼，也沒有宣稱 `DS:164Ch` 那張表的內容。
