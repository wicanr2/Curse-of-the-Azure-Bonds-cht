# 995 — 四種存檔副檔名的掃描，與 PC-98 的改名流程

- 證據等級：`exact`（兩支逐條讀完；字串與三張表由原始 bytes 讀出）
- 作法見 spec 783

## `dos overlay-16:00453h`（193 條，`retf 8`）— 依模式掃描四種檔案

四個字串常數都在 overlay 內，各 5 個字元：

| 位址 | 內容 |
|---|---|
| `CS:043Bh` | `'*.guy'` |
| `CS:0441h` | `'*.cha'` |
| `CS:0447h` | `'*.sav'` |
| `CS:044Dh` | `'*.hil'` |

```pascal
arg_4^ := NIL;  arg_0^ := NIL;
if not <本模組 0643h>() then 離開;

case DS:7584h of                                        { 模式 }
  0: 掃(DS:5BF0h ＋ '*.guy', 0);
  1: begin 掃(DS:5BF0h ＋ '*.cha', 1);  掃(DS:5BF0h ＋ '*.sav', 1) end;
  2: 掃(DS:5BF0h ＋ '*.hil', 2);
end;

{ 掃(路徑, i) 展開成 }
<本模組 008Dh>(byte[506h ＋ i], word[509h ＋ 2i], word[50Fh ＋ 2i],
              arg_4, arg_0, 父bp);
```

`DS:5BF0h` 是路徑前綴（spec 868 已記；spec 975 的 PC-98 對應是 `DS:8BF6h`）。

### ★ 三張以模式為索引的表

（`mov al,[di+506h]` 用的是 **DS**，不是 CS。位址在常駐資料段。）

| 模式 | `DS:506h`（byte） | `DS:509h`（word） | `DS:50Fh`（word） | 副檔名 |
|---|---|---|---|---|
| 0 | `0` | `247` | **`1A6h` ＝ 422** | `*.guy` |
| 1 | `0` | `132` | `11Dh` ＝ 285 | `*.cha` ＋ `*.sav` |
| 2 | `4` | `19` | `0BCh` ＝ 188 | `*.hil` |

★ **模式 0 的 `1A6h` 正是 DOS 的角色記錄大小**（spec 849）——
所以 `DS:50Fh` 那一欄是**每筆記錄的位元組數**，
而 **`.guy` 就是角色檔**（一個角色一筆 422 bytes）。

`.cha` 與 `.sav` **共用 285 bytes 的記錄**，`.hil` 是 188 bytes。

⚠ 模式 1 **掃兩次**（先 `.cha` 再 `.sav`），兩次都用同一組表值，
結果累積到同兩個輸出指標上——**`.cha` 與 `.sav` 對這個掃描器是同一種東西**。

⚠ 這關掉 spec 975 的一個未宣稱項：`*.hil` 不是孤立的，
它是四種存檔類副檔名之一（模式 2）。**本規格仍不宣稱 `.hil`／`.cha` 各裝什麼。**

## `pc98 overlay-17:02C1Ch`（184 條，`retf 4`）— 改名

五個字串：

| 位址 | 長度 | 內容 |
|---|---|---|
| `CS:2BAAh` | 20 | `'名前を変更しますか？'` |
| `CS:2BBFh` | 15 | 15 個半形空白（用來清空輸入緩衝） |
| `CS:2BCFh` | 14 | `'新しい名前は？'` |
| `CS:2BDEh` | 38 | `'このキャラクタ名は受け付けられません。'` |
| `CS:2C05h` | 22 | `'これでよろしいですか？'` |

```pascal
repeat
    if <本模組 2B27h>('名前を変更しますか？', 0Fh, 0Ah, 0Dh) <> 'Y' then break;

    repeat                                                { 輸入迴圈 }
        緩衝 := 限長('               ', 0Fh);              { 清成 15 個空白 }
        <0418h:1150h>(1, 0Fh, 0, 0Dh, '新しい名前は？', @緩衝);
        緩衝 := 限長(緩衝, 0Fh);
        合法 := (<0723h:05BDh>(@暫存, @緩衝)^[0] <> 0);
        if not 合法 then
            <overlay-24 entry#19>('このキャラクタ名は受け付けられません。');
    until (長度(緩衝) <> 0) and 合法;

    <0418h:0139h>(0Fh, 0, 1, 1);                          { 清底色 }
    印字(1, 1, 0Dh, 0, 緩衝);                              { 顯示新名字 }

    ans := <overlay-26 entry#8>('これでよろしいですか？', 0Fh, 0Ah, 0Dh);
    if ans = 'Y' then begin
        限長(緩衝, 遠指標(DS:9594h)^, 0Fh);                { ★ 寫回角色記錄 +0 }
        ans := 'N';
    end;
until ans <> 'Y';
結果 := arg_0^;
```

`本模組 2B27h` 就是 spec 975 讀的「はい／いいえ」確認選單。

### ★ 名字上限是 15 個半形字元

`0Fh` 這個上限在四個地方一致：清空用的空白字串長度、輸入呼叫的參數、
兩次 `限長`、以及寫回角色記錄的 `限長`。
角色記錄 `+0` 是 Pascal 字串（既有結論），所以**名字欄就是 15 bytes ＋ 長度 byte**。

**中文化：15 個半形格 ＝ 7 個全形字**（第 15 格放不下第 8 個字的後半）。
中文名字要限制在 **7 個字**，而且輸入端（`0418h:1150h`）與檢查端
（`0723h:05BDh`）都得改成以字元為單位——否則第 8 個字會被 `限長` 從中間切斷，
留下半個 Big5 位元組。

### 兩層確認、兩層重試

- **外層**：改完一個名字之後回到「名前を変更しますか？」再問一次，
  答 `'Y'` 就再改一個。答 `'N'` 才離開。
- **內層**：名字空白或不合法就重新輸入，**不會退回外層**。
- 確認「これでよろしいですか？」答 `'N'` 時**不回到輸入迴圈**，
  而是把 `ans` 留著往外層判斷——⚠ 所以**答「不」等於放棄這次改名**，
  不是重新輸入。這一點與玩家直覺相反，remake 要照原樣重現。

## 明確不宣稱

- 沒有宣稱 `.cha`／`.sav`／`.hil` 各裝什麼內容（只知道記錄大小）。
- 沒有宣稱 `DS:506h`／`DS:509h` 兩欄的意義。
- 沒有宣稱 `本模組 0643h`（前置檢查）與 `本模組 008Dh`（實際掃描）做什麼。
- 沒有宣稱 `0723h:05BDh` 用什麼規則判斷名字合不合法。
- 沒有宣稱 `0418h:1150h` 的輸入行為（可用鍵、編輯功能）。
