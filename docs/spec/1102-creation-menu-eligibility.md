# 1102 — 建角三張清單的可選項：種族選單跳過半獸人，陣營選單依職業組合過濾

- 狀態：`READY`
- 證據等級：`exact`（DOS `overlay-17:00782h` 的選單迴圈逐條讀完；
  `DS:41D8h` 的內容取自 `workplace/re-sweep/dos/dseg/dos-dseg-dseg.bin`）
- 選項**文字**見 spec 1100，本規格只講**哪幾項會出現**
- `DS:41D8h` 這張表本身已由 spec 884（雙職轉職資格）解出，本規格是它的第二個使用端

## ★★★ 一、種族選單只有六項——半獸人不可選

顯示迴圈（`86Fh`..`91Bh`）跑 `i := 1..7`，但分成兩段：

```pascal
for i := 1 to 7 do
    if (i >= 1) and (i <= 5) then 加入第 i 項           { 矮人..半身人 }
    else if i = 7 then          加入第 i 項            { 人類 }
    { i = 6 兩個條件都不成立 ⇒ 整項被跳過 }
```

兩段都用 `DS:0E9Ch ＋ i × 0Ah` 取名稱，所以顯示的字是對的；
差別只在 **`i = 6`（`Half-Orc`）沒有任何分支收它**。

選完之後還要補一手（`9B1h`）：

```pascal
if 選單索引 = 6 then inc(選單索引);      { ★ 6 → 7 }
角色^[74h] := 選單索引;
```

> ★★★ **選單只有六列，但索引仍以 1..7 編號**：使用者選到第 6 列時，
> 選單本身回報的索引是 6（因為第 6 列實際上是人類），程式再把它 `inc` 成 7。
> ⇒ **半獸人在建角階段完全取不到**，`+74h` 永遠不會是 6。
> ★ 這與 spec 1099 的另一個現象一致：種族可選職業表 `DS:3FF8h` 的第 6 列
> 對建角沒有作用。
> ⚠ 半獸人的名稱、屬性上下限、可選職業、起始年齡在資料段裡都齊全——
> 不可選是**選單的事**，不是資料缺漏。本規格不宣稱它是否在別處（NPC、
> 讀舊存檔）被用到。

## ★★★ 二、陣營選單依職業組合過濾

選完職業之後才顯示陣營選單，清單長度與內容都查 `DS:41D8h`：

```pascal
筆數 := byte[DS:41D8h ＋ 角色^[75h] × 0Ah];              { [0] 是長度 }
for k := 1 to 筆數 do
    加入( 字串[DS:0EECh ＋ byte[DS:41D8h ＋ 角色^[75h] × 0Ah ＋ k] × 11h] );
…
角色^[11Bh] := byte[DS:41D8h ＋ 角色^[75h] × 0Ah ＋ 選單索引];
```

★ 選單索引不是陣營編號——要再過一次表才變成 `+11Bh`。

### `DS:41D8h` 的內容（17 列 × `0Ah`，陣營編號用 spec 1100 的九宮格）

| `+75h` | 職業組合 | 可選陣營 |
|---|---|---|
| 0 | 牧師 | 全部九項 |
| 1 | 德魯伊 | 守序中立、中立善、**絕對中立**、中立惡、混亂中立 |
| 2 | 戰士 | 全部九項 |
| 3 | **聖騎士** | **守序善（只有一項）** |
| 4 | **遊俠** | **守序善、中立善、混亂善** |
| 5 | 法師 | 全部九項 |
| 6 | **盜賊** | 全部**除了**守序善與混亂善 |
| 7 | 武僧 | 全部九項 |
| 8 | 牧師／戰士 | 全部九項 |
| 9 | 牧師／戰士／法師 | 全部九項 |
| `0Ah` | 牧師／遊俠 | 守序善、中立善、混亂善 |
| `0Bh` | 牧師／法師 | 全部九項 |
| `0Ch` | 牧師／盜賊 | 全部九項 ⚠ |
| `0Dh` | 戰士／法師 | 全部九項 |
| `0Eh` | 戰士／盜賊 | 同盜賊（七項） |
| `0Fh` | 戰士／法師／盜賊 | 同盜賊（七項） |
| `10h` | 法師／盜賊 | 同盜賊（七項） |

> ★★★ **聖騎士只能守序善、遊俠只能善、德魯伊是中立十字**——
> 三個 AD&D 一版最有辨識度的陣營限制一格不差。
> 多職組合取的是各單職的交集：牧師／遊俠 ＝ 遊俠的三項、
> 戰士／盜賊與法師／盜賊 ＝ 盜賊的七項。
> ⚠ **`0Ch`（牧師／盜賊）是唯一的例外**：盜賊只有七項，交集應該是七項，
> 這一列卻是九項。這是**表本身寫成這樣**，不是計算結果——
> 表是手寫死的，沒有任何程式碼在算交集。本規格不宣稱這是刻意還是漏改。
> ⚠ 武僧（`7`）給了全部九項，與 AD&D 一版「武僧必須守序」不符；
> 但武僧不在任何種族的可選職業清單裡（spec 1100 §三），建角選不到。

## 三、職業選單依種族過濾（已在 spec 1093）

`DS:3FF8h ＋ 種族 × 0Eh`：`[0]` 是筆數，`[1..n]` 是職業組合編號。
內容見 spec 1099 §五。形狀與陣營表完全一樣（長度前綴 ＋ 編號清單）。

## 四、性別選單沒有過濾

兩項固定顯示。性別只影響力量上限（spec 1099 §一 的男／女兩欄）。

## 對 remake 的意義

- **種族清單要拿掉半獸人**，但編號仍是 1,2,3,4,5,7（不可重新連號，
  `+74h` 要與原版存檔相容）。
- **陣營清單要依職業組合過濾**，不能固定顯示九宮格；
  聖騎士只有一項時原版仍然顯示選單（不是自動帶入）。
- 三張過濾表（種族→職業、職業→陣營）都應該進 game pack JSON，
  不要寫死在 Go 裡。

## 明確不宣稱

- 沒有宣稱半獸人在建角以外的地方是否可用。
- 沒有宣稱 `0Ch`（牧師／盜賊）九項是刻意還是漏改。
- 沒有宣稱 `DS:41D8h` 第 17 列之後的位元組屬於哪張表
  （spec 1099 §五 已標記過那個邊界）。
- 沒有宣稱 PC-98 對側（spec 1094）的選單迴圈是否逐條相同——
  spec 1094 記錄的六個差異塊裡有「三個選單實作」，需要另外核對。
