# 781 — `Put8x8Symbol` 的分段查表，以及牆面位元的設定端

- 證據等級：`exact`（以補洞後的匯出逐條讀完，見 spec 761）

## `overlay-35:0173h`（DOS）— `Put8x8Symbol`

函式名稱由它自己的錯誤訊息定住：`CS:0150h` ＝
`'Bad symbol number in Put8x8Symbol.'`（34 字元）。`retf 0Ah`（5 個 word）。

```pascal
編號 := 參數;                             { word，有號比較 }
if      1    <= 編號 <= 2Dh   then 組 := 0
else if 2Eh  <= 編號 <= 73h   then 組 := 1
else if 74h  <= 編號 <= 0B9h  then 組 := 2
else if 0BAh <= 編號 <= 0FFh  then 組 := 3
else if 100h <= 編號 <= 127h  then 組 := 4
else if (編號 = 0) or (128h <= 編號 <= 7FFFh) then begin
    顯示('Bad symbol number in Put8x8Symbol.');  等一個鍵;
end;
{ 編號為負數時：不報錯，而且「組」沒有被指派 }

p := 遠指標[65B6h + 組 * 4];
if p = NIL then 離開;
編號 := 編號 − word[2680h + 組 * 2];       { 減掉該組的起始編號 }
if 第二個參數 <> 0 then
    <0297h:08F8h>(遠指標@DS:4FE8h, p, 參數0, 低位(編號), 參數6, 參數8)
else begin
    Move(p^[17h + 編號 * p^[11h]], DS:65CAh^[17h], p^[11h]);
    <0297h:1110h>(遠指標@DS:65CAh, 參數6, 參數8);
end;
```

三組可以直接用的事實：

- **符號編號分五段**，各對應 `DS:65B6h` 起的一個遠指標（每組 4 bytes），
  段起始值在 `DS:2680h`（每組 2 bytes）。五段的界線是
  `1..45`、`46..115`、`116..185`、`186..255`、`256..295`。
- **符號資源的版面**：表頭至少 `17h`（23）bytes，`+11h` 是**每個符號的位元組
  數**，符號資料從 `+17h` 起連續排列。第 n 個符號在 `+17h + n × [+11h]`。
  （`+11h` 這個欄位在 spec 766 的繪圖前置裡也出現過。）
- 第二個參數決定走「直接畫」還是「先搬進 `DS:65CAh` 這個暫存資源再畫」。

⚠ **編號為負數時 `組` 這個 local 沒有被指派**——四段區間判斷都用 `jl` 往下
串，負數一路落到最後的錯誤判斷，而該判斷只擋 `0` 與 `128h..7FFFh`。之後
`遠指標[65B6h + 組 * 4]` 會用堆疊殘值當索引。呼叫端目前是否可能傳負數，本輪
沒有追。

## `overlay-14:0153h`（DOS）— 牆面位元的設定端

`retf 6`，宣告順序 `(x, y, 方向)`，與 spec 761 的 `overlay-14:003Eh` 成對：

```pascal
if not ((0 <= x <= 0Fh) and (0 <= y <= 0Fh)) then 離開;   { 有號 }
格 := DS:7206h^[300h + (y shl 4) + x];
case 方向 of
    6: 格 := (格 and 3Fh)  or 40h;    { bits 6-7 := 01 }
    4: 格 := (格 and 0CFh) or 10h;    { bits 4-5 := 01 }
    2: 格 := (格 and 0F3h) or 04h;    { bits 2-3 := 01 }
    0: 格 := (格 and 0FCh) or 01h;    { bits 0-1 := 01 }
end;
```

`003Eh` 把 2-bit 欄位清成 `00`，這一支把它設成 `01`。**兩支合起來只用到 2 位元
中的兩個值**，`10` 與 `11` 由別處寫入（或根本沒用到）。

兩支的差別還有一個：**這一支有範圍檢查**（`0..0Fh`，有號，超出就整支不做），
`003Eh` 沒有。同一組操作的兩半防護不對稱。

## 明確不宣稱

- 沒有宣稱 `0297h:08F8h` 與 `0297h:1110h` 的差別（前者在 spec 759 的
  `overlay-33:00F9h` 也出現過）。
- 沒有宣稱 `+300h` 那個 2-bit 欄位的四個值各代表什麼；目前只見到 `00` 與 `01`
  被寫入。
