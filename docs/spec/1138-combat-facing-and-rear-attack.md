# 1138 — 戰鬥面向與背後攻擊：字面移植，語意留白

- 證據等級：`exact`（`overlay-13:29A2h` 的八扇形分類、`sub_194A` 的轉向記帳、
  `overlay-13:19D8h` 的轉向段、`overlay-13:14E8h` 的三段 AC 都逐條讀完；
  面向的六個寫入者全掃）／**未定**（`+09h` 的幾何意義、`+19Bh` 的算法）
- 上游 spec 1137（四道閘的位置）、spec 805（開場面向）、spec 808（轉向函式）、
  spec 1019（攻擊時的轉向）、spec 786（轉向記帳）、spec 817（機會攻擊的呼叫點）

## 一、方向分類：`overlay-13:29A2h`

`retf 8` ＝ 兩個角色遠指標。回傳**從第二個看向第一個**的八方向碼。

判準是兩個定點正切門檻，`dx`／`dy` 是兩點座標差的絕對值：

| 常數 | 值 | 角度 |
|---|---|---|
| `0x26A / 0x100` | 2.4140625 | tan 67.5° |
| `0x006A / 0x100` | 0.4140625 | tan 22.5° |

⚠ 乘除是 **16-bit 整數且先乘後除**：`dx * 618 / 256` 與 `dx * (618/256)` 是兩個
不同的函式，順序不能換。

⚠ 八個扇形是**依序**試的（0,1,2,…,7），先中先贏。所以邊界不是對稱的：
`dx = 4` 時 `dy = 9` 仍判成「右下」，要 `dy = 10` 才輪得到「正下」。
照角度直覺寫會在邊界上錯一格。

## 二、★ `+09h` 的幾何意義還沒有結論

兩個寫入端給出**相反**的形狀：

- **攻擊動作**（spec 1019）：`攻擊者^[09h] := (29A2h(攻擊者, 目標) + 4) mod 8`
  ——加 4 是取反方向，而且 PC-98 把這一段整個拿掉。
- **轉向記帳**（`sub_194A`）：`差 := 最短轉法(29A2h(角色, 對象), 角色^[09h])`
  ——**沒有**那個 `+ 4`。

把兩者同時當成「`+09h` ＝ 我正在看的方向」會得到矛盾：前者讓角色面向目標，
後者算出來的「要轉幾格」在**已經面向目標時是 4、背對時是 0**。

**所以本輪不解釋這個欄位，只做字面移植**：算式原樣搬過來，remake 算出來的數字
就與原作相同，不論那個數字最後怎麼解釋。

⚠ 界線在「誰在用它」：**把它餵給原作自己的消費端**（`sub_194A` 的轉向記帳、
`14E8h` 的三段 AC、spec 1010 的扇形檢查）仍然是字面移植，數字一樣就對了；
**自己新寫**一段「角色朝這邊所以畫這張圖／所以看得到那個人」才是要等語意定案的。

## 三、三個欄位與它們的生命週期

| 欄位 | 原作 | 誰寫 |
|---|---|---|
| `CombatFacing` | `+09h` | 開場（spec 805）、攻擊動作（spec 1019）、`overlay-32 entry#14`（spec 808）|
| `CombatActionCount` | `+0Fh` | `sub_194A` 加一；回合開始清 0 |
| `CombatTurnTotal` | `+12h` | `sub_194A` 累加最短轉法後 **mod 8**；回合開始清 0 |

- **開場面向**：`表{7,2,3,6}[隊伍朝向 div 2]`，敵方再轉 180 度。
  ⚠ 索引是**除以 2**，八個朝向只對到四筆——朝向 0 與 1 得到同一個面向。
- **`+12h` 是 0..7 的環狀量，不是單調成本**：累加四次「轉 2 格」之後回到 0。
- 回合開始只清 `+0Fh` 與 `+12h`，**面向跨回合保留**。

## 四、攻擊結算的三段 AC

`overlay-13:14E8h` 在三道條件全成立時改用防禦者的第二個 AC 欄位：

1. 防禦者的 `+0Fh` > 1；
2. `29A2h(攻擊者, 防禦者)` ＝ 防禦者的 `+09h`；
3. 防禦者的 `+12h` > 4。

remake 的 `RearAttackApplies` 是這三道的字面移植。

### ★ 第二個 AC 的值

`+19Bh ＝ +19Ah − 敏捷防禦調整 − 盾牌那一槽 − 2`（算式與資料驗證在
spec 1000 §七）。儲存值**越大越難打**，所以減掉那三項就是「背後比較好打」。

`Fighter` 多的是**兩個**欄位：`ArmorClassFacing` 與 `ArmorClassFacingKnown`。
沒有標成已知時，攻擊結算**不會**改用它——隊員那一側目前還沒有第二個 AC。
⚠ 零值不能當「沒有」：0 是合法的 AC，所以要一個獨立的 known 旗標。

★ **投影搬的是差值，不是絕對值**。`monster.CombatArmorClass` 會把儲存值
反轉成顯示值（`60 − 儲存值`），而 `ResolveAttack` 的判定是
`attackTotal >= AC`（數字小才好打）。直接搬 `+19Bh` 的絕對值會讓背後攻擊
變成**更難**打，而且兩種寫法在「有沒有換到第二個 AC」上看起來一樣。
`TestRearAttackIsEasierThanFacingTheAttacker` 就是擋這個符號。

## 明確不宣稱

- 沒有宣稱 `+09h` 指的是「角色看向哪裡」還是別的東西（§二）。
- 隊員那一側沒有第二個 AC：`internal/party` 的 `Fighter()` 不算 `+19Bh`，
  所以只有從 `MON*CHA` 匯入的戰鬥員會走到背後那一格。
- 沒有宣稱 `sub_194A` 的**全部**呼叫點都接上了；本輪接的是 spec 817 那一處，
  移動指令那一側還沒對回原作。
- 沒有宣稱 `overlay-32 entry#14`（一般轉向）在 remake 有對應的呼叫點。
- spec 1010 那支機會攻擊只接了**面向這一道閘**；它前面還有四道
  （`entry#6`、`sub_1144`、效果碼 `4Ah`／`4Bh`）都還沒解讀，remake 沒有對應物。
- 沒有宣稱 DOS 的 `(d + 4)` 與 PC-98 的「沒有 +4」哪一邊是對的；本作以 DOS 為準。
