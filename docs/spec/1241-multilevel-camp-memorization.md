# 1241 — CAMP 多環法術記憶與準備時間

狀態：`READY`（一至五環容量、候選、逐環上限、REST 寫回與整小時準備時間；
不替使用者決定快捷法師的固定法術書）

## 證據

- spec 923（`exact`）：原版 `BuildSpellList` 以法術表的「施法職業、環級」索引
  角色記錄的 `3×5` 容量；牧師使用完整職業法術表，法師／德魯伊受 known-spell
  旗標限制，並依環級插入標題。
- spec 809／810／1016（`exact`）：五級牧師基礎容量 `3/3/1`，五級法師
  `4/2/1`；牧師另套智慧額外法術門檻。
- RuleBook 與 spec 133：每支法術每環 15 分鐘；一／二環至少 4 小時，三／四環
  至少 6 小時，五環至少 8 小時。多名角色平行準備，取最慢角色所需時間。
- `gamepack/rules/spell-table.json` 是原版 100 筆全域法術表；ID、職業與環級已有
  committed regression，不由 UI 重新手打對照。

## 修正

舊 CAMP adapter 把所有施法者縮成「一環候選＋一環總容量」。五級角色雖已持久
保存完整 `SpellCastCount[3][5]`，玩家仍只能把一環格填滿，二／三環永遠不可用。

現在：

- 候選直接掃原版法術表；有容量的牧師法術全部列出，法師／德魯伊只列已知法術。
- 每次選取依該法術的職業與環級計數，只能消耗相同 `3×5` 儲存格的容量；多職
  角色不能拿牧師二環格準備法師二環法術。
- 角色列顯示所有可用環級的容量總和；舊存檔沒有容量表時，仍保留既有的一環
  fallback 與已記憶清單，不因升級 adapter 而縮掉資料。
- REST 以最高環級決定 4／6／8 小時最低值，再加每支法術「環級 × 15 分鐘」，
  向上取整至現有整小時 UI；不足時 pending 選擇維持不變。
- 補上五級牧師清單新暴露的 `Find Traps`（偵測陷阱）與 `Cure Disease`
  （治療疾病）中英文名稱，玩家路徑不再顯示 `0x16`／`0x27`。

## 驗證

- 五級牧師可各自填滿一／二／三環 `3/3/1`，第四個一環選取被逐環上限拒絕。
- 五級法師只在 known-spell 中看見已知的一／二／三環法術。
- 一支一環法術需要 5 小時；一、二、三環各一支需要 8 小時。
- `go test ./internal/game` 全套通過。
- 一般強度 3000 幀重放顯示牧師 `0/11`、法師 `0/7`，證實完整容量已到正式
  CAMP UI；既有 route 仍只選前五／四個一環法術，於 2255 幀死亡，不能把這次
  介面完成冒稱為一般強度通關。

## 保留的產品決策

spec 1217 已記錄：快捷建角的五級法師要採固定 loadout，或讓 guided 建角逐級
選擇，會改變玩家體驗。此規格只把所有合法選項與容量接到正常 UI，不代替使用者
決定快捷模板應自動學哪幾支法術。
