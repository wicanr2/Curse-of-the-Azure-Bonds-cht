# 第七百零二輪：`overlay-22` 的另外四支法術 opcode

狀態：`READY`。等級：`exact`。日期：2026-08-14

## `578Bh`：與 `407Ah` 逐指令相同的第二份

`578Bh` 和 spec 701 的 `407Ah` 走完全一樣的流程：`ROLLDICE(2,4)+2` →
`HEALDUDE(目標, 量, 0)` → 成功則 `<overlay-24 entry#26>(目標, 1, 訊息)`。

差別只有訊息字串的**位址**：`407Ah` 用 `CS:4070h`、`578Bh` 用 `CS:5781h`，
而兩者的內容都是 `is Healed`。

> 同一句話在同一個 overlay 裡存了兩份。中文化時**必須兩份都改**，只改一份會
> 出現「有時中文有時英文」而且很難重現。這種重複要用位址掃描找，不能靠字串
> 去重後的清單。

## `23F2h`：`is held`

```text
v := DS:7434h
if v = 1 then
    if DS:6F97h = 17h then r := −2 else r := −3
elif v = 2 then r := −1
elif v = 3 或 v = 4 then r := 0
（v 為其他值時 r 不被寫入 ── 回傳堆疊殘值）
<sub_1ABFh>(r, 'is held'（CS:23EAh）)
```

`DS:7434h` 在 spec 700 的治療系裡是「有沒有目標」的旗標（只判非 0），這裡卻被
當成 1..4 的**列舉**用。同一個全域在不同 opcode 有不同的解讀寬度。

又是一支**有未初始化路徑**的函式（`v` 不在 1..4 時），和 spec 694 的 `129Ah`
同一類。

## `262Fh`：先發訊息再套效果

```text
<sub_F06h>(DS:6F97h, 0, 1, 0, 0, 空字串（CS:262Eh）)
<overlay-23 entry#2>(17h, DS:7435h 的目標, 0（dword）, 0)
```

`sub_F06h` 的第四個參數（在 spec 701 的致傷三支裡是傷害量）這裡是 `0`，
第三個從 `0` 變成 `1`——所以那兩個欄位不是固定的，`sub_F06h` 有模式之分。

`17h` 這個常數在 `23F2h` 裡也出現（拿去和 `DS:6F97h` 比），兩處是同一個編號域。

## `3C98h`：`N d6`，`N` 由另一支算出來

```text
n := <overlay-24 entry#36>(DS:6F97h)
r := ROLLDICE(n, 6)
<sub_3947h>(DS:7559h, DS:755Ah, r, 4, 0, @區域)
<sub_3A03h>(7, r, 4, 1)
```

骰子的**顆數是算出來的、面數寫死 6**。`overlay-24 entry#36` 讀 `DS:6506h` 指到
的紀錄裡四個欄位（`+109h`、`+10Eh`、`+10Ch`、`+10Dh`）先做一輪判斷，不滿足就
回 6，否則再查 `[37DAh + arg×16]` 那張 16 bytes 一格的表——本輪沒有把它讀完，
所以 `n` 的語意不宣稱。

同一個 `r` 被兩支下游各用一次，參數位置不同（`sub_3947h` 的第三個、
`sub_3A03h` 的第二個）。

## 明確不宣稱

- `sub_1ABFh`、`sub_F06h`、`sub_3947h`、`sub_3A03h`、`overlay-23 entry#2`、
  `overlay-24 entry#36` 各自的行為。
- `DS:6F97h`、`DS:7559h`、`DS:755Ah` 是什麼。
- `17h` 這個編號代表什麼。
- 這四支各自對應哪一個法術。
