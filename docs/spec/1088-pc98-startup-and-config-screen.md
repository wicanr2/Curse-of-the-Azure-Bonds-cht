# 1088 — PC-98 開機流程：overlay 緩衝、兩片軟碟的路徑推導、`curse.cfg` 與初期設定畫面

- 證據等級：`exact`（PC-98 resident 側 502 條逐條讀完；指令種類只有
  `push`／`mov`／`call`／`xor`／`cmp`／`jmp`／`pop`／`sub`）
- 作法見 spec 783

## `pc98 PC98-GAME.EXE:1259Fh`（`retf`）

原本待解讀。這是**程式最外層的開機序列**，也是 PC-98 專屬的
**初期設定畫面**。

★ resident 也能用 `scripts/annotated_dump.py`（模組名寫 `PC98-GAME.EXE`／`START.EXE`），
不必走 objdump；字串則要用 spec 1046 的位移公式
`file ＝ ea − 10000h ＋ 2464` 從 EXE 影像取。

## 一、overlay 初始化與記憶體檢查

```pascal
OvrInit('GAME.OVR');                            { 19EB:0014 }
<19EB:0560>();                                  { OvrInitEMS 之類 }
if OvrResult < 0FFFCh then 緩衝 := 8000h（32 KB）else 緩衝 := 4000h（16 KB）;
if MemAvail − 緩衝 夠 then OvrSetBuf(緩衝)      { 19EB:019B }
else 印('メモリが足りません。あと' ＋ 差額 ＋ 'バイトが必要です。');
if (OvrResult <> 0FFFBh) and (OvrResult <> 0) then
    印('オーバーレイ・エラーです。プログラムを中止します。');
```

★ **overlay 緩衝依 EMS 可用與否選 32 KB 或 16 KB**。
★ 三個訊息都用 `1A65:178Bh`（Write）輸出到 `unk_2820Eh` 那個 Text 變數。

## ★★★ 二、兩片軟碟的資料路徑推導

```pascal
路徑 := FExpand('*.exe');                       { 18BD:01A0 }
FSplit(路徑, 目錄, 名稱);                        { 18BD:0289 }
if 路徑[1] >= 'C' then  工作路徑 := 路徑         { 硬碟：用執行檔所在目錄 }
else if 路徑[1] = 'A' then 工作路徑 := 'B:\'     { ★ 從 A: 開機 → 資料在 B: }
else                       工作路徑 := 'A:\';    { ★ 從 B: 開機 → 資料在 A: }
存檔路徑 := 路徑;
```

> ★★★ **兩片軟碟互為對方的資料碟**：從 A: 執行就去 B: 找資料，反之亦然；
> 磁碟機字母 ≥ `'C'`（硬碟）時直接用執行檔所在目錄。
> ⇒ remake 若要相容原版目錄結構，這條規則要照抄。
> ★ 兩個路徑字串上限都是 `43h` ＝ 67 bytes（`0649h` 的第三個參數）。

## ★★ 三、`curse.cfg`

```pascal
Assign(檔案, 'curse.cfg');  Reset(檔案);
Read(檔案, 兩個字元);
ReadLn(檔案, 一個字串);                          { 上限 0FFh，存進 unk_24E86h }
Close(檔案);
```

接著用讀到的字母做一次硬體檢查：

```pascal
b := byte[Ptr(0060h, 6Ch ＋ (資料碟字母 − 'A'))];
if not (b in [90h..94h]) then <17E3:0077h>();    { 不合格就處理掉 }
```

★ 段 `0060h` 是 **PC-98 的 BIOS 資料區**；形狀上是**檢查資料碟的磁碟機種類**。
⚠ 本規格不宣稱 `90h`..`94h` 各代表哪一種磁碟機，也不宣稱 `17E3:0077h` 做什麼。

## ★★★ 四、初期設定畫面

畫面用 `Assign(檔案, '')` ＋ `Rewrite`（Turbo Pascal 的**空檔名 ＝ 主控台**）輸出，
內容是 PC-98 的 ANSI 控制碼加全形文字：

| 位址 | bytes | 內容 |
|---|---|---|
| `CS:123E1h` | 17 | `ESC[>5h ESC[>1h ESC* ESC[37m`（關游標、清畫面、白字） |
| `CS:123F3h` | 4 | `ESC=$)` ＝ 游標移到第 4 列第 9 欄 |
| `CS:123F8h` | 8 | **「初期設定」** |
| `CS:12401h` | 42 | `ESC=)!` ＋「ＣＴＲＬ＋Ｏ　－　ＢＧＭのＯＮ／ＯＦＦ」 |
| `CS:1242Ch` | 42 | `ESC=+!` ＋「ＣＴＲＬ＋Ｓ　－　効果音のＯＮ／ＯＦＦ」 |
| `CS:12457h` | 62 | `ESC=-!` ＋「ＣＴＲＬ＋Ｂ　－　戦闘時、魔法の効果範囲表示のＯＮ／ＯＦＦ」 |
| `CS:12496h` | 38 | `ESC=/!` ＋「ＣＴＲＬ＋Ｖ　－　液晶デイスプレイ」 |
| `CS:124BDh` | 52 | `ESC=2#` ＋「ＢＧＭ＝ＯＦＦ、効果音＝ＯＦＦ、範囲表示＝ＯＦＦ」 |
| `CS:124F2h` | 28 | `ESC=3#` ＋「のとき最高速になります。」 |
| `CS:1250Fh` | 48 | `ESC=5#` ＋「ゲーム中およびこの画面で切り替えができます。」 |
| `CS:12540h` | 38 | `ESC=6#` ＋「設定後、リターンを押してください。」 |
| `CS:12567h`／`1257Ah`／`1257Fh`／`12584h` | 各 4 | `ESC=)b`／`ESC=+b`／`ESC=-b`／`ESC=/b` ＝ 四個開關的欄位（第 66 欄） |
| `CS:1256Ch` | 6 | 「ＯＮ　」 |
| `CS:12573h` | 6 | 「ＯＦＦ」 |
| `CS:12589h` | 10 | 「使用しない」 |
| `CS:12594h` | 10 | 「使用する　」 |

★ `ESC=` 後面兩個 byte 是 **(列 ＋ 20h, 欄 ＋ 20h)** ⇒
四行選項在第 9／11／13／15 列，狀態顯示在第 66 欄；
說明文在第 18／19／21／22 列第 3 欄。

四個開關對應的全域：

| 選項 | 全域 | 判定 |
|---|---|---|
| BGM | `unk_24E73h` | `= 0` → 「ＯＮ」 |
| 効果音 | `unk_24DE8h` | `= 2` → 「ＯＦＦ」 |
| 範囲表示 | `unk_24E7Eh` | `= 0` → 「ＯＮ」 |
| 液晶ディスプレイ | `unk_24E82h` | `= 0` → 「使用する　」，否則「使用しない」 |

進門的預設值：`unk_24E73h := 0`（BGM ＝ ＯＮ）、`unk_24DE8h := 0`（効果音 ＝ ＯＮ）、
`unk_24E7Eh := 1`、`unk_24E7Fh := 1`、`unk_24E71h := 0FFh`、
`unk_24E82h := 1`（液晶 ＝ 使用しない）、`unk_280C0h := 0`。

```pascal
repeat
    重畫四個狀態欄;
    鍵 := <17E3:0206h>();                        { 取鍵，spec 1077 的同一支 }
until 鍵 = 0Dh;                                  { Enter }
Close(主控台檔案);
```

> ★★★ **`Ctrl+O`／`Ctrl+S`／`Ctrl+B`／`Ctrl+V` 這四個切換鍵，本支完全沒有處理**
> ——它只是重畫狀態。畫面上那句「ゲーム中およびこの画面で切り替えができます。」
> 已經說明了原因：**四個開關是全域熱鍵，由 resident 的取鍵常式
> （`17E3:0206h`，遊戲中同一支）直接改全域**。
> ⇒ remake 要把這四個切換做成**輸入層的全域攔截**，不是設定畫面的區域邏輯。

## 明確不宣稱

- 沒有宣稱 `19EB:0560h`（`OvrInit` 之後那一支）是什麼。
- 沒有宣稱 `17E3:0077h`（磁碟機種類不合格時呼叫）做什麼。
- 沒有宣稱 `0060h:006Ch ＋ 磁碟編號` 那個 byte 的 `90h`..`94h` 各代表什麼。
- 沒有宣稱 `curse.cfg` 前兩個字元與那一行字串的格式。
- 沒有宣稱 `unk_24E7Fh`／`unk_24E71h`／`unk_280C0h`／`unk_241E4h`／`unk_24194h`
  五個進門就設好的全域是什麼。

- 沒有宣稱 DOS 側有沒有對應的設定畫面（`START.EXE` 那兩支尚未讀）。
