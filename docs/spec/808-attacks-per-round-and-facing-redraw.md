# 808 — 本回合攻擊次數（遠程受彈藥數限制）、轉向時才重畫

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側的運算元差異已逐條列出）
- 作法見 spec 783

## `overlay-13:0DD9h`（entry#8，105 條，差異 13 條）— 算出 `+19Ch`

這就是 spec 806 的回合初始化第一個呼叫的那一支。`retf 4` ＝ 一個角色遠指標。

```pascal
遠程 := 0;
舊 := 角色^[19Ch];
角色^[19Ch] := 角色^[11Ch];                        { 先放基礎值 }
if <far 15BCh+1>(角色) and <far 15C6h+1>(角色, @彈藥) then begin
    遠程 := 1;
    v := byte[5CFBh + 角色^[151h]^[2Eh] * 10h];    { 物品類型表 +5 }
    if v < 2 then v := 2;                          { 無號 }
    DS:6F96h := v;
end else
    DS:6F96h := 角色^[19Ch];
DS:6F9Ah := 0;
<far 1442h+2>(角色, 12h);
n := <本模組 0F12h>(DS:6F96h);
if (遠程 <> 0) and (彈藥 <> NIL) then begin
    m := 1;
    if 彈藥^[39h] > m then m := 彈藥^[39h];         { 無號 }
    if (m < n) and (彈藥^[39h] > 0) then n := m;
end;
if (角色^[18Dh]^[8] = 0)
   or (n < 舊)                                     { 無號 }
   or ((有號(n) < 有號(舊) * 2) and (遠程 = 0)) then
    角色^[19Ch] := n;
```

### `+11Ch` / `+11Dh` 是基礎值，`+19Ch` / `+19Dh` 是本回合的值

與 spec 806 完全對稱：

| | 基礎 | 本回合 | 換算 |
|---|---|---|---|
| spec 806（`overlay-13:0000h`） | `+11Dh` | `+19Dh` | `DS:6F96h` → `0F12h` |
| 本支 | `+11Ch` | `+19Ch` | 同一條路 |

兩支都走 `DS:6F96h := 來源`、`DS:6F9Ah := 0`、`<1442h+2>(角色, 12h)`、
`0F12h(DS:6F96h)` 這條固定的換算鏈。所以 **`DS:6F96h` 是換算的輸入暫存**。

### 遠程攻擊會被彈藥數量卡住

`15C6h+1` 除了回傳「有沒有遠程武器」，還從第二個參數帶回一個**物品節點**。
接著取它的 `+39h`——就是 spec 789「對半分」定出來的**數量**欄位——當成上限：

```
m := max(1, 彈藥^[39h]);
if (m < n) and (彈藥^[39h] > 0) then n := m;
```

`彈藥^[39h] = 0` 時 `m` 是 1，但第二個條件把它擋掉，所以**數量為 0 不會把次數壓成
1**，而是維持算出來的 `n`。這個組合看起來不像刻意設計，remake 要照抄就得保留。

### 物品類型表補上一欄

`5CFBh` ＝ `DS:5CF6h` 的 **`+5`**（spec 804 已定 `+0` 類別碼、`+6` 旗標＋加值）。
索引一樣是裝備的 `+2Eh`。取出來的值**下限夾成 2**。

裝備從 `角色^[151h]` 取（另一個物品遠指標，與 spec 794 的物品鏈頭 `+14Dh` 相距 4）。

### 最後那個寫回條件

`+18Dh^[8]`（戰鬥狀態，spec 806 開場設 0）決定要不要保護原值：

- `+8` ＝ 0：**一律寫回**。
- `+8` ≠ 0：只有 `n < 舊`，或「`n < 舊 × 2` 且不是遠程」時才寫回。

中間那句 `cmp c^[8], 0 / jz` 在 `+8` ≠ 0 的路徑上**永遠不成立**（前面已經判過），
是編譯出來的死碼。

## `overlay-32:0B3Fh`（entry#14，101 條，差異 12 條）— 轉向

`retf 0Ah` ＝ 5 個 word。依宣告順序：`(角色, 新面向, 參數2, 參數0)`。

```pascal
i := <本模組 0CAEh>(角色);                          { 戰鬥員索引 }
if (not <本模組 0763h>(1, 角色)) and (DS:75E6h <> 0) then
    <本模組 09DFh>(8, 3, <0C5Eh>(角色), <0C36h>(角色));

if not ((有號(新面向) div 4 = 有號(角色^[18Dh]^[9]) div 4)
        and (參數2 = 0) and (參數0 = 0))
   and (DS:75E6h <> 0) then
    <本模組 0578h>(i, 0, 0);

角色^[18Dh]^[9] := 新面向;

if (參數0 = 0) and <本模組 0763h>(0, 角色) and (DS:75E6h <> 0) then begin
    <0196h:003Eh>(byte[67C6h + i], byte[680Eh + i], 新面向, 參數2, 角色^[143h]);
    <0297h:1316h>();
end;
```

### 面向只分兩半

判斷用的是 `面向 div 4`：**0..3 算一組、4..7 算另一組**。同一組之內轉向（例如
0 → 2）**不會觸發 `0578h`**——形狀上就是「精靈只有左右兩個朝向，同一側轉向不用
換圖」。

`0578h` 只在「換邊」或兩個參數任一不為 0 時才呼叫，而且**一定要 `DS:75E6h` ≠ 0**。

### `DS:75E6h` 是「這個角色要不要畫」

三個地方都拿它當閘門。spec 804 讀到它在回合開始時被設成 0 或 1
（`陣營 ＝ 0` 或 `<018Ch:005Ch>` 成立才是 1）。

### 面向一定會被寫入

三段判斷都在 `角色^[18Dh]^[9] := 新面向` 之前或之後，**沒有任何一條路會跳過這個
賦值**——畫不畫是一回事，狀態一定更新。
