# 1018 — 寶石與珠寶的鑑價：兩張 AD&D 1e 表，以及 63 bytes 的物品節點

- 證據等級：`exact`（DOS 側 823 條逐條讀完）
- ⚠ **PC-98 對側只讀了字串與前 150 條**——該函式的匯出從 `1BBAh` 到 `2305h`
  有一個 1867 bytes 的洞沒有反組譯，本規格**不宣稱** PC-98 那一段的內容，
  台帳也維持待解讀
- 作法見 spec 783

## `dos overlay-21:0198Ch`（`retf 4`）

原本待解讀。這是**「你身上的寶石與珠寶」畫面**：計數、鑑價、賣掉或留著。

## ★★ 兩個計數欄位

```pascal
寶石數 := word(角色^[105h]);      { DS:6506h 指的那個人 }
珠寶數 := word(角色^[107h]);
if (寶石數 = 0) and (珠寶數 = 0) then begin
    顯示 'No Gems or Jewelry';  結果 := 0;  exit
end;
```

## ★★★ 寶石價值：AD&D 1e 的 1d100 表

```pascal
dec(角色^[105h]);
r := <overlay-23 entry#9>(1, 100);          { 1d100 }
```

| 1d100 | 價值（gp） |
|---|---|
| 1–25 | 10 |
| 26–50 | 50 |
| 51–70 | 100 |
| 71–90 | 500 |
| 91–99 | 1000 |
| 100 | 5000 |

> ★★★ **這就是 AD&D 1e《DMG》的寶石基礎價值表，六段一格不差。**

## ★★★ 珠寶價值：`Random(n) ＋ 基底`

```pascal
dec(角色^[107h]);
r := <overlay-23 entry#9>(1, 100);
```

| 1d100 | 算式（`@Random$q4Word`） | 實際範圍 |
|---|---|---|
| 1–10 | `Random(900) ＋ 100` | 100–999 |
| 11–20 | `Random(1000) ＋ 200` | 200–1199 |
| 21–40 | `Random(1500) ＋ 300` | 300–1799 |
| 41–50 | `Random(2500) ＋ 500` | 500–2999 |
| 51–70 | `Random(5000) ＋ 1000` | 1000–5999 |
| 71–90 | `Random(6000) ＋ 2000` | 2000–7999 |
| 91–100 | `Random(10000) ＋ 2000` | 2000–11999 |

> ★★★ **與 1e《DMG》的珠寶價值表七段對得上**
> （100–1000、200–1200、300–1800、500–3000、1000–6000、2000–8000、2000–12000）。
> **上界都差 1，因為 Turbo Pascal 的 `Random(n)` 回 `0..n−1`。**

## ★★ 留下來的話會生一個 63 bytes 的物品節點

選單問 `'You can : '`，選項 `'Sell'`／`'Sell Keep'`；按 `K` 走這一段：

```pascal
GetMem(節點, 3Fh);                      { ★ 63 bytes }
FillChar(節點^, 3Fh, 0);
節點^.next(+2Ah)      := NIL;
節點^.ready(+34h)     := 0;
節點^.namenum(3)(+31h) := 65h;          { 101 }
節點^.namenum(2)(+30h) := 0;
節點^.namenum(1)(+2Fh) := 0;
節點^.itemptr(+2Eh)   := 46h;           { 70 }
節點^.value(+3Ah)     := 剛剛擲出來的價值;
```

★★ **物品節點在 DOS 是 63 bytes**，而欄位名全部來自 spec 1011 的除錯畫面
（`itemptr`／`namenum`／`ready`／`value`）——**四份規格在這裡對上**。

★ 只用 `namenum(3)`（＝ 101），前兩段留 0 ⇒
顯示名就是名稱表第 101 筆那一個詞（spec 1014 的組裝規則）。

## 中文化：又一組英文單複數

| DOS | PC-98 |
|---|---|
| `'No Gems or Jewelry'`（18） | 「宝石も宝石飾りも持っていませんよ」（32 bytes） |
| **`' Gem'`（4）／`' Gems'`（5）** | 「宝石」（4 bytes）——**只有一個** |
| **`' piece of Jewelry'`（17）／`' pieces of Jewelry'`（18）** | 「宝石飾り」（8 bytes）——**只有一個** |
| `'You have a fine collection of:'`（30） | 「あなたのお持ちになっているのは」（30 bytes） |
| `'  Gems'`／`'  Jewelry'`／`' Exit'` | 「 宝石 」／「宝石飾」／「抜ける」（各 6 bytes ＝ 3 全形字） |
| `'Appraise : '`／`'You can : '` | 「見積る：」／「どうしますか？」 |
| `'The Gem is Valued at '`／`' gp.'` | 「宝石の値段は」／「ｇｐです。」 |
| `'Sell'`／`'Sell Keep'` | 「  売る…」／「      (   売る　…」（各補到 32 bytes） |

> ★★★ **PC-98 把英文的單／複數兩個字串合併成一個**——日文沒有複數形。
> 中文同理，**跟 PC-98 這一版**：`' Gem'`／`' Gems'` 只留一個「顆寶石」，
> `' piece of Jewelry'`／`' pieces of Jewelry'` 只留一個「件珠寶」。

⚠ 三個選單選項在 PC-98 都是 **6 bytes ＝ 3 個全形字**，中文只有 3 個字的空間。
⚠ `'The Gem is Valued at '` 後面接數字再接 `' gp.'`，中文語序相同，可以直接換。

## 明確不宣稱

- ~~沒有宣稱 PC-98 對側 `1BBAh`..`2305h` 那 1867 bytes 的內容~~ ——
  **已於 spec 1035 用 `objdump` 補讀完畢**，兩張價值表逐格相同。
- 沒有宣稱名稱表第 101 筆是什麼詞、物品類別 70 是什麼。
- 沒有宣稱 `+105h`／`+107h` 這兩個計數是隊伍共用還是個人的。
- 沒有宣稱賣掉那一支怎麼把錢加進去（`overlay-24 entry#22`／`entry#7` 的呼叫）。

> ★★★ **spec 1035 補上的兩件事**：①「賣」實際入帳的是 **估價 ÷ 5**（整數除法），
> 畫面顯示的價錢是估價不是拿到的錢；②**角色身上一件物品都沒有時，
> 選「留下」產生的節點沒有接回物品鏈頭**（DOS `01E60h`／`021BCh`、
> PC-98 `01F19h`／`0228Ah` 四個分支都一樣），東西與記憶體一起消失。
> 另外「留下」還有 16 件的上限（`角色^[14Ch]`／PC-98 `+14Dh`）。
