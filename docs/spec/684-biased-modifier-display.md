# 第六百八十四輪：偏移 60 的修正值顯示，與 HP 顏色的兩平台差異

狀態：`READY`。日期：2026-08-14
位置：DOS `overlay-24` 的 `0939h`、`09C1h`。

## `0939h`：儲存值 60 代表 0，而且方向相反

```text
v := arg_4^[19Ah] − 3Ch                       ← 3Ch ＝ 60
if v < 0 then v := −v                          ← 取絕對值
把 v 轉成字串
if arg_4^[19Ah] > 3Ch then
    在前面接 '-' 再接上數字                     ← 只有這時才加負號
顯示
```

| 儲存值 | 顯示 |
|---|---|
| 55 | `5` |
| 60 | `0` |
| 65 | `-5` |
| 0 | `60` |
| 120 | `-60` |

**顯示值 ＝ `60 − 儲存值`**。負號的條件是「儲存值**大於** 60」——與絕對值那段的
方向相反，所以儲存得越大、顯示越負。

這是「數字越小越好」的欄位（AD&D 的 AC、THAC0 都是這一類）用偏移量存起來的做法：
存 60 當基準，實際顯示時反過來。

**判讀時最容易錯的地方**：`sub ax, 3Ch` 之後那個 `neg` 只是取絕對值供轉字串用，
真正決定正負的是後面**獨立的一次比較**。只看前半段會得到相反的結論。

## `09C1h`：與 PC-98 同邏輯、不同顏色

```text
if arg_6^[1A4h] < arg_6^[78h] then v := 0Eh    ← 受傷
else                                v := 0Ah    ← 滿
if arg_0 <> 0 then                  v := 0Dh    ← 覆蓋
把 arg_6^[1A4h] 連同 v 交給顯示 routine
```

與 PC-98 的 `0BD5h`（[spec 643](643-hp-fields-and-slot-array.md)）**結構完全相同**，
連 `arg_0` 覆蓋的那一段都一樣。差別只有一個常數：

| 狀態 | PC-98 | DOS |
|---|---|---|
| 受傷 | `6` | **`0Eh`** |
| 滿 | `0Ah` | `0Ah` |
| `arg_0` 非 0 | `0Dh` | `0Dh` |

三個裡有兩個相同、一個不同。DOS 是 EGA 16 色、PC-98 是文字 VRAM 屬性
（[spec 673](673-ega-graphics-controller-reset.md) 與
[spec 658](658-color-bit-swap-and-attribute-codec.md)），兩者的顏色編號本來就不是
同一套——**相同的兩個是巧合，不是共用**。

欄位偏移也照對照表：DOS `+1A4h` ＝ PC-98 `+1A5h`（目前 HP），`+78h` 兩平台相同
（上限）。

## 明確不宣稱

- `+19Ah` 是哪一項（AC、THAC0 還是別的修正值）。
- `arg_0` 非 0 代表什麼狀態。
- `542h:352h`／`sub_10CB` 的行為。
