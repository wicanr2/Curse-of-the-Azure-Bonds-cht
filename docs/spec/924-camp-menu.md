# 924 — 紮營選單：六個熱鍵，而 PC-98 拿掉了「離開到 DOS」

- 證據等級：`exact`（兩平台都逐條讀完；相似度 0.896，五個差異區塊）
- 作法見 spec 783

## `overlay-15:023FCh`（DOS 206 條）↔ `overlay-15:02457h`（PC-98 197 條）

`retf 4` ＝ `@結果`（一個 byte 的 var 參數）。

| | DOS | PC-98 |
|---|---|---|
| 宣告 | `'The party makes camp...'` | `'パーティーはキャンプを張った。'` |
| 選單標題 | `'Camp:'` | **空字串**（見下） |
| 離開確認 | `'Quit TO DOS '` | **沒有這個字串** |
| 檔名前綴 | `'PIC'` | `'PIC'` |

```pascal
舊模式 := DS:4FBAh;   DS:4FBAh := 2;
DS:757Ch := 0;
FillChar(DS:7566h, 0Eh, 0);
限長(DS:7278h → DS:7281h, 8);
DS:728Bh := DS:728Ah;
<sub_15A9h>();
<loc_1EC9h+4>(16h, 26h, 11h, 1);              { ★ 開視窗；PC-98 沒有這一步 }
印字(0, 0Ah, 12h, 1, 'The party makes camp...');
<sub_23Eh>();

    鍵 := 選單(@已選, 1, 1, 0Fh, 0Ah, 0Dh, @DS:0428h, 'Camp:');   { loc_169Dh+2 }

    <loc_17C3h+1>(@DS:7281h, 0, DS:728Bh, DS:722Ch);
```

## 離開條件是一個 32 bytes 的 Pascal 集合

`unk_23C5`（PC-98 `2433h`）不是字串，是 **256 位元的集合常數**，
由 `0A54h:08D4h`（PC-98 `0A65h:08E4h`）測試成員資格、用 ZF 回報。
兩平台逐 byte 相同：

```
01 00 00 00 00 00 00 00 20 00 00 … 00      （32 bytes）
```

byte 0 的 bit 0 → 元素 **0**；byte 8 的 bit 5 → 元素 **8×8＋5 ＝ 69 ＝ `'E'`**。
所以集合是 **`[0, 'E']`**——按 **E**（Exit）或拿到 0 就離開紮營。

迴圈變數初值是 `20h`（空白），不在集合裡，所以至少會進去一次。

## 六個熱鍵

| 鍵 | 碼 | 動作 | 設 `DS:7294h` |
|---|---|---|---|
| **S**ave | `53h` | `<loc_EA5h+2>()` 之後問 `'Quit TO DOS '`，答 `'Y'` 就 `<06EAh:0000h>` | 否 |
| **V**iew | `56h` | `<unk_1009h>(@x)` | 是 |
| **M**agic | `4Dh` | `<sub_14D2h>(@結果)` | 是 |
| **R**est | `52h` | `<sub_7B2h>(@結果)` | 是 |
| **F**ix | `46h` | `<sub_2309h>(@結果)` | **否** |
| **A**lter | `41h` | `<sub_1D0Ah>()` | 是 |
| **E**xit | `45h` | 在集合裡，直接跳出迴圈 | — |

這正是 Gold Box 的紮營選單。⚠ **Fix 是唯一不設 `DS:7294h` 的分支**，
Save 也不設；其餘四個都設。

`已選 <> 0` 那條路是「選單自己處理掉了」（`<sub_1022h>` ＋ `<loc_14F8h+2>`），
與六個熱鍵互斥。

## ⚠ PC-98 的兩處刪減

1. **不開視窗**：DOS 在印宣告之前呼叫 `<loc_1EC9h+4>(16h, 26h, 11h, 1)`，
   PC-98 整段拿掉（差異區塊 1，共 9 條指令）。
2. **沒有「離開到 DOS」**：DOS 的 `'Quit TO DOS '` Y/N 確認與 `<06EAh:0000h>`
   共 16 條指令，PC-98 換成單一呼叫 `<loc_1C47h+1>()`。
   **`'Quit TO DOS '` 這個字串在 PC-98 的常數區裡不存在。**

繁中版若照 DOS 走，`'Quit TO DOS '` 得自己譯（PC-98 沒有可以參考的譯法）。

## PC-98 的選單標題是空字串

DOS 把 `'Camp:'` 建進暫存字串再傳給選單。PC-98 傳的來源位址是 `2434h`，
那個 byte 是 `00`——**長度 0 的字串**（該位址落在集合常數內部，
編譯器把空字串疊在集合的零位元組上）。

取而代之的是差異區塊 2：把 `DS:0A14h` 的 10 bytes 指派到 **`DS:0A335h`**，
也就是 spec 894／899／900 那個「固定寬度標籤陣列 ＋ 熱鍵陣列」機制。
**PC-98 把選單標題搬進共用的熱鍵字串緩衝，不再由本支自己帶。**

## 收尾：檔名開頭是 `'PIC'` 才做那一步

`Copy(DS:7281h, 1, 3) = 'PIC'` 用 `0A54h:0724h`（PC-98 `0A65h:0734h`）比字串。
`DS:7281h` 是函式一開始從 `DS:7278h` 限長 8 抄過來的，
所以是**一個 8 字元的檔名**。

## 明確不宣稱

- 沒有宣稱 `DS:7294h` 由誰讀（形狀上是「紮營期間有沒有動到隊伍」）。
- 沒有宣稱 `DS:7566h`（14 bytes）、`DS:757Ch`、`DS:7555h`／`DS:7557h`、
  `DS:722Ch`、`DS:728Ah`／`DS:728Bh` 的用途。
- 沒有宣稱六個熱鍵各自呼叫的函式做什麼。
- 沒有宣稱 PC-98 用 `<loc_1C47h+1>()` 取代離開流程之後，玩家還能不能離開遊戲。
