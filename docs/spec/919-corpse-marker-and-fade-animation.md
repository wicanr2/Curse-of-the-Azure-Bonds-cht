## `DS:6E52h` 屍體登記簿：本支是寫入端

spec 908 從**還原端**讀出版面，本支是**寫入端**，兩邊逐格對上：

| 位移 | 內容 | 本支寫的值 |
|---|---|---|
| `+0`（dword） | 角色遠指標 | 倒下的角色 |
| `+4` | 欄 | `<sub_C36h>(角色)` |
| `+5` | 列 | `<sub_C5Eh>(角色)` |
| `+6` | 原本的地形碼 | 該格 `+7` 的舊值 |

寫入順序是：先抄走舊地形，再把地圖那一格改成 `1Fh`。
所以 **`1Fh` 是「有屍體」的地形碼**（spec 748 也在有生物站著的格子畫 `1Fh`）。

這同時解釋 spec 908 的 `if byte[6E58h ＋ i*7] <> 1Fh` ——
備份欄位存到 `1Fh` 代表**那一格本來就已經是屍體格**，還原它沒有意義，
所以還原端把 `1Fh` 當成「不用還原」。本支的 `if 原地形 <> 1Eh` 是另一道保護：
`1Eh` 那種地形連蓋都不蓋。

## 地圖記錄的 row stride 再確認

`地圖^[7 ＋ 列 × 32h ＋ 欄]`——**`32h` ＝ 50**，與既有規格一致；
地形資料從 `+7` 開始，`+2`／`+3` 是視窗原點（結尾那個
`<sub_9DFh>(8, 3, 地圖^[3] ＋ 3, 地圖^[2] ＋ 3)` 又用了一次）。

## ⚠ 查表迴圈用錯索引變數

```
mov [bp+var_2], 1        ← 計數器
loc:
cmp [bp+var_2], 9
jnb  結束
mov al, [bp+var_3]       ← ★ 讀的是 var_3，不是 var_2
mov dx, 7 ; mul dx
les ax, [di+6E52h]
…比較…
inc [bp+var_2]           ← 只有計數器前進
jmp loc
```

`var_3` 在這個迴圈之前**沒有被寫過**（`sub sp, 0Ah` 之後直接用），
而且要到迴圈後面的 `mov [bp+var_3], 0` 才第一次被賦值。
所以這個「這個角色是不是已經登記過」的檢查：

- 每一圈比對的是**同一筆**（索引不變），
- 而那一筆的位置由**堆疊殘值**決定。

**兩平台完全相同**，不是反組譯錯位。這與 spec 862（`overlay-22:0317Eh`
第一個迴圈的索引變數從未使用）是同一類缺陷，本專案第二例。

實務後果：重複登記不會被擋下，`DS:6E91h` 可能被同一個角色推進兩次。

## ⚠ PC-98 的動畫延遲又改用遊戲速度

| | 每幀延遲 |
|---|---|
| DOS | 常數 `0Ah` |
| PC-98 | **`DS:7F16h`（＝ `DS:4FA9h` 遊戲速度）× 3** |

整份差異區塊只有這三條指令（`xor ah,ah` ／ `mov cx,3` ／ `imul cx`）。

**這是 `DS:4FA9h` 的第六個消費端**，也是「DOS 用常數、PC-98 才看速度」的第四例
（spec 895、914、918、本支）。到這裡形態已經穩定：**DOS 版的動畫節奏基本上
不受設定影響，PC-98 版才真的把「遊戲速度」接到動畫上**。
