# 第七百二十七輪：力量增強——`(值, 百分位)` 兩段式的對照表

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：DOS `overlay-22:1FA0h`。

## 對照表

```text
[4CB5h] := 12h                                  ← 預設「18」
[4CB6h] := 0                                    ← 預設「無百分位」
v := <overlay-24 entry#36>(DS:6F97h)
```

| `v` | 改哪一個 | 結果 |
|---|---|---|
| 1 | `[4CB6h] := 0` | 18 |
| 2 | `[4CB6h] := 1` | 18/01 |
| 3 | `[4CB6h] := 33h`（51） | 18/51 |
| 4 | `[4CB6h] := 4Ch`（76） | 18/76 |
| 5 | `[4CB6h] := 5Bh`（91） | 18/91 |
| 6 | `[4CB6h] := 64h`（100） | 18/00 |
| 7 | `[4CB5h] := 13h` | 19 |
| 8 | `[4CB5h] := 14h` | 20 |
| 9 | `[4CB5h] := 15h` | 21 |
| 10 或 11 | `[4CB5h] := 16h` | 22 |
| 其他 | （都不改） | 18 |

`1`..`6` 只動百分位、`7`..`11` 只動整數值，而另一個維持預設——所以
**兩段是分開設定的，不是同一個 `case` 的兩欄**。改寫時若寫成
「每個 `v` 都給一組 `(值, 百分位)`」，`v = 7..11` 會多帶一個 `0` 百分位，
剛好也對；但 `v` 落在範圍外時原碼給的是 `(18, 0)`，不是「不做事」。

`1`／`51`／`76`／`91`／`100` 正是 spec 694 `129Ah` 那五段百分位區間的**下界**
（`1..50`、`51..75`、`76..90`、`91..99`、`100`）。兩支從不同方向確認了同一組
AD&D 例外力量分級。

## 流程

```text
if <overlay-23 entry#19>(目標, [4CB5h], [4CB6h], @舊值) then
    <overlay-24 entry#20>(目標, '<名字> is stronger'（CS:1F86h）, 0Ah, 1)
    d := <sub_E11h>(DS:6F97h)                    ← 持續時間（spec 712）
    <overlay-23 entry#11>(目標, 0Ch, d, 舊值, 1)
    <overlay-23 entry#24>(目標, 0)
else
    <overlay-24 entry#20>(目標, '<名字> is unaffected'（CS:1F92h）, 0Ah, 1)
```

`entry#19` 用 `var` 參數帶回**舊值**，接著把舊值一起交給 `entry#11`——所以效果
結束時要還原成什麼，是在套用的當下記下來的，不是事後推算的。

`entry#19` 回傳 0 表示沒生效（目標本來就更強？）——這時完全不套效果，
也不消耗持續時間。

## `4CB5h`／`4CB6h` 的第三種用途

spec 715 已記過這兩個位址在 `30C0h` 是擲骰門檻、在 `22B4h` 是 Sleep 的 HD 預算。
本輪是第三種：力量值與百分位。**同一組暫存被三支函式當成完全不同的東西**，
再次確認它們不是具名狀態。

## 明確不宣稱

- `overlay-23 entry#19`／`entry#11`／`entry#24` 的內部行為。
- 效果編號 `0Ch` 在這裡的意義（spec 716 的 `20E1h` 也用 `0Ch`，訊息是
  `has been reduced`——同一個編號兩種方向，值得再查）。
- `entry#36` 回傳 `1..11` 的來源。
