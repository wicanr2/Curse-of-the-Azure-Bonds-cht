# 777 — 把物品接進背包、範圍法術的豁免掃描

- 證據等級：`exact`（以補洞後的匯出逐條讀完，見 spec 761）

## `overlay-06:0355h`（DOS）— 把一件物品複製進背包尾端

`retf 8`：

```pascal
if <00FDh:004Dh>(物品, DS:6506h) then begin
    顯示('OverLoaded');                     { CS:034Ah，10 字元 }
    輸出^ := 1;
end else begin
    輸出^ := 0;
    p := DS:6506h^[14Dh];
    if p = NIL then begin
        GetMem(p, 3Fh);
        <搬>(物品, p, 3Fh);
        p^[2Ah] := NIL;
        DS:6506h^[14Dh] := p;
    end else begin
        while p^[2Ah] <> NIL do p := p^[2Ah];    { 走到鏈尾 }
        GetMem(q, 3Fh);
        <搬>(物品, q, 3Fh);
        q^[2Ah] := NIL;
        p^[2Ah] := q;
    end;
    <014Dh:0043h>(DS:6506h);
end;
```

- 物品節點 `3Fh`（63）bytes、next 在 `+2Ah`——與既有結論一致，而且這裡是
  **配置端**的證據。
- **新物品接在鏈尾**，不是鏈頭，所以背包順序等於取得順序。
- 兩條分支（空鏈／非空鏈）各自寫了一份 `GetMem` ＋ 搬 ＋ 清 next 的程式碼。

⚠ **`'OverLoaded'` 與 spec 767 記錄的 `overlay-19:2131h` `'Overloaded'` 大小寫
不同**（`L` 一個大寫一個小寫），兩處是各自獨立的字串常數。中文化時兩條都要
改，而且不能只靠搜尋其中一種寫法。這與 `docs/audit/duplicate-strings.md` 裡
`goes berserk` / `goes berzerk` 是同一類問題。

## `overlay-09:02B1h`（DOS）— 範圍法術的豁免掃描

`retf 8`：

```pascal
結果 := false;
if DS:6506h^[197h] = 0 then 修正 := 0FEh   { −2 }
                       else 修正 := 8;
<呼叫>(地圖(DS:6E92h), 1, 0FFh, byte[37E9h + 法術 * 10h], y, x);
n := DS:6E96h;                              { 掃出來的目標數 }
for i := 1 to n do begin
    對面 := <overlay-24 entry#30>(DS:6506h);   { 施法者的「對面那一隊」隊號 }
    idx := byte[6E94h + i * 3];
    目標 := 遠指標[6D35h + idx * 4];
    if 目標^[197h] <> 對面 then                { ⇒ 目標和施法者同一隊 }
        if byte[37E2h + 法術 * 10h] <> 1 then
            if not <豁免>(修正, byte[37E3h + 法術 * 10h], 目標) then
                結果 := true;
end;
```

把幾條既有的線接起來：

- `DS:37DAh` 是法術屬性表（16 bytes 一筆）。這裡用到三個欄位：
  `+8`（`37E2h`，既有結論是**豁免旗標**——值為 1 就整個跳過）、
  `+9`（`37E3h`，**豁免類別**，傳給豁免程序）、
  `+0Fh`（`37E9h`，傳給範圍掃描程序）。
- `DS:6E92h` 是戰場地圖遠指標、`DS:6E96h` 是掃出來的目標數、
  `DS:6E97h` 起是**每筆 3 bytes** 的結果陣列（基底寫成 `6E94h`、1 起算）。
  這三者在記憶體上首尾相接。
- `DS:6D35h` 是戰鬥員遠指標表（spec 757 的 `overlay-32:0CAEh` 用同一張）。
- **豁免修正取決於施法者的陣營**：陣營 0 是 `−2`、其他是 `+8`。同一個法術對
  兩邊的難度不同，這是原版行為，不是對稱的。
- **只有和施法者同一隊的目標會被算進去**，敵方的直接跳過。判斷用的
  `overlay-24 entry#30` 回的是「**對面**那一隊的隊號」（`+197h = 0` 回 1、
  否則回 0，spec 1112），所以 `目標^[197h] <> 對面` 就是「目標是自己人」。

> **這一支是範圍法術的友軍誤傷檢查。** 呼叫端（spec 802／835）在 AI 施放前叫它，
> **任何一個目標回真就不放**——「有隊友會中招就別放」。remake 的怪物 AI 要照這個
> 方向實作，方向反了會得到一支專打自己人的 AI。

`結果` 的意義是「至少有一個**自己人**的豁免程序回 0」。

## 明確不宣稱

- 沒有宣稱豁免程序回 0 代表「豁免失敗」還是「豁免成功」——本輪沒有讀
  `sub_1458h`。
- 沒有宣稱 `+0Fh`（`37E9h`）傳給範圍掃描程序之後怎麼用（它是掃描半徑，
  spec 1111；掃描程序內部沒讀）。
- 沒有宣稱 `00FDh:004Dh` 判的是重量還是件數（`overlay-19:3258h`，spec 762，
  兩者都判）。
- 沒有宣稱 3-byte 一筆的結果陣列另外兩個 byte 裝什麼。
