# 1085 — PC-98 隊伍主選單：十二個項目是 `DS:0DC2h` 起的 83 bytes 一筆的靜態表

- 證據等級：`exact`（PC-98 側 707 條逐條讀完，`filled` 匯出無破洞）
- 作法見 spec 783；DOS 對側是 `dos overlay-17:001DDh`（`'Choose a function '`）

## `pc98 overlay-17:002CBh`（`retf`，無參數）

原本待解讀。範圍 `2CBh`..`9F4h`。這是**角色管理／出發前的主選單**，
也是 `overlay-17` 其他幾支大函式的共同入口。

## ★★★ 一、選項表：`DS:0DC2h ＋ i × 53h`，共 12 筆

| 位移 | 內容 |
|---|---|
| `+0`..`+50h` | **選項文字**（`string[80]`，複製時上限 `50h`） |
| `+51h` | **啟用旗標**（0 ＝ 這次不顯示） |
| `+52h` | **熱鍵字元** |

一筆 `53h` ＝ **83 bytes**，`i` ＝ 0..11。

⚠ 這張表在**資料段**（`push ds` ＋ `add di, 0DC2h`），**不在 overlay 的 `.bin` 裡**
——想看內容要從 resident 的資料段影像取，本規格不宣稱那 12 個字串。
IDA 把每一筆的旗標標成程式標籤（`loc_E12+1`、`loc_E65+1`、`loc_F0C`…），
**那些都是 `DS:` 位址**，不是程式碼。

★ 對照 spec 1073：**執行期的選單節點是 `56h` ＝ 86 bytes**
（`string[80]` ＋ 填補 ＋ 4 bytes next 在 `+52h`），
而這張**靜態表是 83 bytes**（`+51h` 旗標 ＋ `+52h` 熱鍵）。
兩者前 81 bytes 的版面相同，後面三格用途不同——**別把兩者混為一談**。

## 二、每次進選單先決定哪些項目要亮

```pascal
if 目前角色 <> NIL then begin
    <overlay-24 entry#2>(目前角色);
    啟用[1] := 1;  啟用[2] := 1;                    { D、M }
    啟用[3] := ord(bank1^[550h] > 0);               { T ——這鎮有沒有訓練所 }
    啟用[4] := ord(bank1^[550h] > 0);               { H }
    啟用[5] := 1;  啟用[7] := 1;  啟用[9] := 1;      { V、R、S }
    啟用[8] := 0;  啟用[10] := 0;                    { L、B 先關掉 }
    { 走一次隊伍鏈：只要有一個「可行動」的角色，B 就打開 }
    節點 := 隊伍頭 DS:9598h;
    while (節點 <> NIL) and (啟用[10] = 0) do begin
        if ((節點^[196h] = 0) or (節點^[196h] = 4)) and (節點^[0F7h] = 0) then
            啟用[10] := ord(bank0^[3FAh] = 0);
        節點 := 節點^[18Ah];
    end;
end else begin                                      { 隊伍是空的 }
    啟用[1] := 0;  啟用[2] := 0;  啟用[3] := 0;
    啟用[4] := 0;  啟用[5] := 0;  啟用[7] := 0;
    啟用[8] := ord(bank0^[1E4h] = 0);                { ★ 只有空隊伍才給 L }
    啟用[9] := 0;  啟用[10] := 0;
end;
```

★ `bank1^[550h]` 就是 spec 1084 的**「這一間訓練所收哪些職業」**遮罩
——非 0 才會出現 `T`（訓練）與 `H`（轉職）兩個項目。
★ `節點^[196h]` 是 spec 1061 的**倒下狀態**（`0` ＝ 正常、`4` ＝ 另一種可行動狀態）。

## 三、把亮著的項目串成選單鏈

```pascal
for i := 0Bh downto 0 do
    if 啟用[i] <> 0 then begin
        GetMem(節點, 56h);                          { ★ spec 1073 的選單節點 }
        節點^[52h] := 前一個節點;                    { 串鏈 }
        節點^ := 文字[i];                            { 上限 50h }
        節點^[51h] := 0;
        熱鍵暫存[n] := 熱鍵[i];  dec n;
    end;
項目數 := 0Ah − n;
把熱鍵暫存反轉成正序;
DS:0A816h := 0;                                     { 檔案類別 ＝ '*.guy'，spec 1043 }
FillChar(DS:0A335h, 0Ah, 'S');
鍵 := <overlay-26 entry#7>(…, 15h, 26h, 0Bh, 3, 0Fh, 0Ah, 0Dh);
if 鍵 = 'S' then begin                              { ★ 捲動 }
    <overlay-26 entry#6>();  <overlay-26 entry#10>(鏈);   { 收掉重來 }
    …回到建鏈…
end;
鍵 := 熱鍵[選到的索引];
```

★ **表是由後往前掃（`0Bh downto 0`），節點也是往前串**，所以顯示順序是
`i = 0` 在最前面。
★ 回傳 `'S'` 是「翻頁」，不是選項——會把整條鏈釋放掉重建。

## ★★★ 四、十二個項目各自做什麼

| `i` | 熱鍵 | 提示句 | 動作 |
|---|---|---|---|
| 0 | `C` | — | `overlay-17:0AFBh`（**建立角色**） |
| 1 | `D` | 「誰を消去しますか？」（18） | 選角色 → `near 28E1h` |
| 2 | `M` | 「誰を調整しますか？」（18） | 選角色 → `overlay-17:2E9Bh`（**數值調整**） |
| 3 | `T` | 「誰を訓練しますか？」（18） | 選角色 → `overlay-17:5420h`（**訓練所**，spec 1084 的對側） |
| 4 | `H` | 「誰を変更しますか？」（18） | 選角色 → `overlay-25 entry#6／#7／#5`；<br>不能轉職就印「このキャラクターはクラス変更できません。」（40） |
| 5 | `V` | 「誰の詳細を見ますか？」（20） | 選角色 → `overlay-19 entry#5`（**檢視角色**） |
| 6 | `A` | — | `overlay-17:3BBDh`（**加入角色**） |
| 7 | `R` | 「誰を離脱させますか？」（20） | 選角色 → 先存檔（`overlay-16 entry#2／#6`）再 `near 28E1h` 移除 |
| 8 | `L` | — | `overlay-16 entry#10`（**載入存檔**） |
| 9 | `S` | — | `overlay-16 entry#11`（**存檔**） |
| 10 | `B` | — | `near 0115h`（**出發**） |
| 11 | `E` | 「きみたちは勝利した。」（20）等 | **結束遊戲**，見下 |

★ 選角色一律走 `overlay-24 entry#40`（把提示句與五個參數丟進去），
回傳新的「目前角色」寫回 `DS:9594h`。

## 五、結束遊戲的三段確認

```pascal
if bank0^[3FAh] = 0FFh then 印('きみたちは勝利した。');        { 已通關 }
if 問('ゲームを終わる前にセーブしておきますか？') = 'Y' then     { 40 bytes }
    <overlay-16 entry#11>();                                    { 存檔 }
if 問('ゲームを終わりますか？') = 'Y' then begin                { 22 bytes }
    if (隊伍非空) and (DS:8CF7h <> 0) then begin
        印('データがセーブされていません。');                    { 30 bytes }
        if 問('それでも終わりますか？') <> 'N' then 離開;        { 22 bytes }
    end else 離開;
end;
```

★ `DS:8CF7h` 是**「有未存檔的變更」旗標**——選單迴圈裡每按一個
落在集合 `CS:181h` 裡的鍵就會把它清 0。

——中文化可以完全不含英文字母，但**熱鍵 byte 要保持原值**，
否則 `'S'`（翻頁）與 `'E'`（結束）的分派會錯。

## 明確不宣稱

- 沒有宣稱 `DS:0DC2h` 那 12 個選項文字的內容（在資料段，本次沒有取出）。
- 沒有宣稱 `overlay-26 entry#7` 的完整參數表（IDA 判不出參數個數）。
- 沒有宣稱 `near 0115h`（出發）、`near 28E1h`（移除角色）、
  `near 4122h`、`near 3BBDh`（加入角色）各自的內容。
- 沒有宣稱 `overlay-24 entry#2`／`entry#40`、`overlay-25 entry#5／#6／#7`、
  `overlay-19 entry#5` 的介面。
- 沒有宣稱 `bank0^[3FAh]`（`0FFh` ＝ 已通關）的完整語意。
★ `bank0^[1E4h]` ＝ **上一個 block／scene 編號**（spec 1097 §一）⇒ 本規格的
`啟用[8] := ord(bank0^[1E4h] = 0)` 是「**還沒進過任何 block（新遊戲）才給載入**」。
- 沒有宣稱 `DS:0A819h`、`DS:8CF7h` 由誰設定成非 0。
- 沒有宣稱 `CS:180h`／`CS:181h` 兩個空字串／集合常數的內容。
