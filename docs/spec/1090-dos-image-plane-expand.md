# 1090 — DOS 圖片展開：每 4 bytes 拆成 8 個 4-bit 像素，依顯示卡走兩套完全不同的碼

- 證據等級：`exact`（DOS resident 側 617 條逐條讀完）
- 作法見 spec 783

## `dos START.EXE:12C1Dh`（`retf 0Eh`）

原本待解讀。resident 段位址是 `1297:02ADh`（＝ overlay 視角的 `0297:02ADh`，
與 spec 1078 的貼圖 `0297:09E4h` 同一個單元）。

這是**把載入的圖片資料展開成顯示卡格式**——包含色彩平面與遮罩平面。

參數（`retf 0Eh` ＝ 14 bytes，由高到低 ＝ 由先到後宣告）：

| 位移 | 用途 |
|---|---|
| `bp+10h` | **來源緩衝**（遠指標） |
| `bp+0Eh` | 來源起始位移 |
| `bp+0Ch` | 本支未讀取 |
| `bp+0Ah` | 一個 byte，轉交給 `near 12970h` |
| `bp+6` | **圖片結構**（遠指標） |

## ★★★ 一、三層迴圈：張 × 寬 × 高

```pascal
if 圖 = NIL then exit;
if unk_211A6h = 0 then …第一套… else …第二套…;

for 張 := 1 to 圖^[8] do
  for x := 0 to 圖^[0] − 1 do
    for y := 0 to 圖^[2] − 1 do begin
        Move(來源^[來源位移], 暫存 4 bytes, 4);        { ★ 一次 4 bytes }
        …展開…
    end;
```

★ **`圖^[0]` ＝ 寬、`圖^[2]` ＝ 高、`圖^[8]` ＝ 張數**——與 spec 1074 從
`E000h` 那張圖推出的欄位定義一致（第二次獨立確認）。
★ **一次搬 4 bytes ＝ 8 個像素**（每像素 4 bit）。

## ★★★ 二、遮罩平面與色彩平面

```pascal
if (圖^[13h] <> NIL) then begin                     { ★ 有遮罩平面才做 }
    位元 := <near 12970h>(暫存[0], 暫存[2], arg_4);
    遮罩位元 := 80h;
    for i := 1 to 2 do
      for j := 4 to 7 do begin
          if (遮罩位元 and 位元) <> 0 then
              圖^[13h]^[偏移] := 圖^[13h]^[偏移] or word[DS:257Dh ＋ j × 2];
          遮罩位元 := 遮罩位元 shr 1;
      end;
end;

for j := 0 to 7 do begin                            { 八個像素 }
    if j 是奇數 then 色 := 暫存[j div 2] and 0Fh
    else            色 := (暫存[j div 2] and 0F0h) shr 4;
    槽 := <near 129EBh>(@圖^[9], 色);                { 查調色 }
    圖^[17h]^[偏移] := 圖^[17h]^[偏移] or byte[DS:2592h ＋ 槽 × 4 ＋ j];
end;
```

> ★★★ **`圖^[13h]` 是遮罩平面、`圖^[17h]` 是色彩平面**
> ——spec 1074／880 從 PC-98 側推出的同一組欄位，這裡在 DOS 的**產生端**確認。
> ★★ 兩張常數表：**`DS:257Dh`（word，遮罩用）與 `DS:2592h`（byte，
> 一個顏色四格，色彩平面用）**。
> ★ `圖^[9]` 起是**這張圖自己的調色資料**，由 `near 129EBh` 查出平面槽號。
> ⚠ 兩張表的內容與 `near 129EBh` 的算式，本規格不宣稱。

## ★★★ 三、`unk_211A6h` 把整支切成兩套

`12C4Bh` 起與 `12F78h` 起是**兩段各自完整的展開碼**，由 `unk_211A6h` 二選一，
差別不只是參數：

| | 第一套（`unk_211A6h = 0`） | 第二套（≠ 0） |
|---|---|---|
| 遮罩 | 逐位元 `or` 進 `圖^[13h]` | 先 `<near 12970h>` 算出長度再 **`FillChar`** 整段清 |
| 像素展開 | 直接 `or` 進 `圖^[17h]` | 先把色存進暫存 `var_24` 再處理 |
| 迴圈邊界 | `x`／`y` 各到 `−1` | 同形但位移算式不同 |

> ★★ 對照 spec 1037：DOS 的顯示卡型別放在 `DS:4FE6h`
> （`0` ＝ CGA、`1` ＝ EGA／VGA、`2` ＝ Tandy），而 spec 1089 讓玩家在
> `curse.cfg` 選 CGA／EGA／Tandy。
> **形狀上 `unk_211A6h` 就是這個型別的 resident 副本**，
> 兩套展開碼對應兩種畫面記憶體佈局。
> ⚠ 本規格**不宣稱** `unk_211A6h` 與 `DS:4FE6h` 是同一格，
> 也不宣稱哪一套對應哪一種顯示卡——要定案得追 `unk_211A6h` 的寫入端。

## 中文化

本支沒有字串。⚠ 但它決定了**所有圖片的展開格式**——中文字型若要走圖片路徑
（而不是文字 VRAM），就得產生符合這裡兩套佈局的資料。

## 明確不宣稱

- 沒有宣稱 `unk_211A6h` 是什麼、由誰寫入。
- 沒有宣稱 `DS:257Dh`（word 表）與 `DS:2592h`（byte 表）的內容。
- 沒有宣稱 `near 12970h`（算遮罩位元／長度）與 `near 129EBh`（查調色）的算式。
- 沒有宣稱 `bp+0Ah` 那個 byte 參數是什麼。
- 沒有宣稱兩套展開碼各自對應哪一種顯示卡。
- 沒有宣稱 PC-98 側有沒有對應函式（PC-98 的圖片是三平面 ＋ 一遮罩，
  見 spec 1074／overlay-35 的註記）。
