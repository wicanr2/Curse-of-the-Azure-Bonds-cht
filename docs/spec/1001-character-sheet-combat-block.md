# 1001 — 角色資料畫面的戰鬥數值區：THAC0、傷害的 `XdY+Z`、兩把武器

- 證據等級：`exact`（DOS 側 332 條逐條讀完；PC-98 對側 335 條相似度 0.987）
- 作法見 spec 783

## `dos overlay-19:00698h` ↔ `pc98 overlay-19:0069Eh`

兩側原本都是待解讀。六個標籤字串**都帶尾隨空白**：

| 位址 | 長度 | 內容 |
|---|---|---|
| `CS:064Eh` | 6 | `'AC    '`（`AC` ＋ 4 空白） |
| `CS:0655h` | 6 | `'HP    '` |
| `CS:065Ch` | 8 | `'THAC0   '` |
| `CS:0665h` | 1 | `'d'` |
| `CS:066Bh` | 14 | `'Damage        '` |
| `CS:067Ah` | 17 | `'Encumbrance      '` |
| `CS:068Ch` | 11 | `'Movement   '` |

⚠ **尾隨空白是字串常數的一部分**，用途與 spec 767 的 AC 欄位相同：
**蓋掉上一次畫的較長內容**。中文化不能把它們刪掉。

## ★★ THAC0 ＝ `60 − 角色^[199h]`

```pascal
<印字>(…, Str(3Ch − 角色^[199h]));
```

`3Ch` ＝ 60。spec 767 讀到 AC 的顯示是 `60 − 角色^[19Bh]`（含負值處理），
**這裡的 THAC0 用同一個基準**——

> **`60` 是這個引擎的共同基準**：AC 與 THAC0 兩個「越低越好」的數值
> 都以 `60 − 內部值` 顯示，內部存的是「越高越好」的版本。

所以 spec 1000 把 `+199h` 記成「命中加值」要收窄：
**`+199h` 是命中能力的內部值，畫面上的 THAC0 是 `60 − 它`**。
力量的命中調整加上去會讓 `+199h` 變大 ⇒ THAC0 變小 ⇒ 更容易命中 ✓ 方向正確。

⚠ THAC0 這一欄**沒有負值處理**（AC 那一欄有，見 spec 767）。
`+199h > 60` 時會印出 `Str` 對負數的結果，本規格不宣稱那會長什麼樣。

## ★★ 傷害顯示是 `XdY+Z`

```pascal
s := Str(角色^[19Eh]) ＋ 'd' ＋ Str(角色^[1A0h]);
if 角色^[1A2h] <> 0 then s := s ＋ '+' ＋ Str(角色^[1A2h]);
```

| 欄位 | 內容 |
|---|---|
| `+19Eh` | 骰數（`X`） |
| `+1A0h` | 面數（`Y`） |
| `+1A2h` | 加值（`Z`，**為 0 時整段不印**） |

★ 這與 spec 1000 的三對基準／現值欄位咬合：那一支的迴圈是
`for i := 1 to 2`，把 `+11Dh ＋ i` → `+19Dh ＋ i`、`+11Fh ＋ i` → `+19Fh ＋ i`、
`+121h ＋ i` → `+1A1h ＋ i`。代進去：

| 索引 | 骰數 | 面數 | 加值 |
|---|---|---|---|
| **1** | `+19Eh` | `+1A0h` | `+1A2h` |
| **2** | `+19Fh` | `+1A1h` | `+1A3h` |

★★ **所以每個角色有兩組「骰數／面數／加值」**，
而 spec 1000 的裝備槽 9 也正好是**兩個指標格**（`+175h` 與 `+179h`）。
**兩組傷害對應兩把武器**——本畫面只顯示第 1 組。

（本規格不宣稱第 2 組在哪裡顯示或使用。）

## ★ 進來第一件事是重算

```pascal
<overlay-24 entry#7>(角色);          { ＝ 0C28h，spec 1000 的派生數值重算 }
```

**畫面每次重畫都會先把派生數值算一遍**，所以 spec 1000 那一支是這一頁的
資料來源。AC 與 HP 兩欄的數值不是本支自己印的，而是交給
`overlay-24 entry#4`（`@0939h`，收 4 個 word）——本支只負責標籤。
（AC 的「60 − 值」與負號處理在 spec 767 的 `overlay-24:0B41h`。）

## 其他兩欄

- **Encumbrance** ＝ `角色^[187h]`（總重，spec 1000／974）
  ——用 `overlay-24 entry#9` 轉字串（word 版）。
- **Movement** ＝ 一個區域變數，用 `overlay-24 entry#10` 轉字串（byte 版）。
  spec 683 的 `+1A5h` 是移動力欄位，spec 1000 把它設成 `+0E4h`。

`overlay-24 entry#9` 收 1 個 word、`entry#10` 收 1 個 byte，
兩支都是「數值轉字串」，差別在寬度。

## 中文化

六個標籤在 overlay 內、要逐一改，而且**寬度是機制的一部分**：

| 標籤 | 原寬 | 中譯 | 建議 |
|---|---|---|---|
| `'AC    '` | 6 | 防禦 | 4 格 ＋ 2 空白 ＝ 6 |
| `'HP    '` | 6 | 生命 | 同上 |
| `'THAC0   '` | 8 | 命中 | 4 格 ＋ 4 空白 ＝ 8 |
| `'Damage        '` | 14 | 傷害 | 4 格 ＋ 10 空白 ＝ 14 |
| `'Encumbrance      '` | 17 | 負重 | 4 格 ＋ 13 空白 ＝ 17 |
| `'Movement   '` | 11 | 移動 | 4 格 ＋ 7 空白 ＝ 11 |

**總長度維持不變是最安全的做法**——尾隨空白負責蓋掉舊值，
縮短標籤本體、把差額補成空白即可。

`'d'` 與 `'+'` 是**骰子表示法的一部分**，不要翻。

## 明確不宣稱

- 沒有宣稱六個欄位各畫在哪一欄（列號由呼叫端的 `var_5` 決定，
  本支只確定每個標籤與其數值同列、數值接在標籤後面）。
- 沒有宣稱 `+199h` 的基準 `+73h` 是怎麼算出來的。
- 沒有宣稱第 2 組骰數／面數／加值在哪裡使用。
- 沒有宣稱 `overlay-24 entry#4`（負責畫 AC 與 HP 數值的那一支）怎麼取值。
