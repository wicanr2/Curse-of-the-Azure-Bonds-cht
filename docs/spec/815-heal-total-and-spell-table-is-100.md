# 815 — 法術表其實有 100 筆、全隊治療總量、挑 `+0E9h` 最小的目標

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側的差異已逐條列出；表的長度由常駐
  資料段 dump 量出）
- 作法見 spec 783；錯位的判定方式見 spec 811

## 更正：法術表是 **100 筆**，不是 56 筆

spec 773 把 `DS:27BDh`（名稱，每筆 `29h` bytes）與 `DS:37DAh`（屬性，每筆 16
bytes）記成 56 筆。實際量到的是 **1..100**，索引 101 起才是別的資料。

發現的路徑是 `overlay-15:1EFDh` 拿 `3Ah`（58）與 `47h`（71）當法術編號比對——
兩個都超過 56。回頭查表：

| 編號 | 名稱 |
|---|---|
| 3 | `Cure Light Wounds` |
| 3Ah（58） | `Cure Serious Wounds` |
| 47h（71） | `Cure Critical Wounds` |

100 筆裡有 **13 筆名字是空的**（索引 57、59..65、95..99），屬性全是
`+0 = 03` / `+1 = 06`，是佔位。

`+0`（職業類別）四個值的分佈：`00` 36 支（牧師系）、`01` 4 支（**德魯伊**，
索引 77..80）、`02` 45 支（法師系）、`03` 15 支（13 支佔位 ＋ 兩支
`Animate Dead`）。

### 連帶更正

- **spec 810**：原本寫「`+0` 從來不是 1，所以遊俠那段旗標迴圈一支都設不到」與
  「`s = 57..100` 讀的是表外資料」，兩條都不成立——`+0 = 01` 有四支德魯伊法術，
  而 `s = 1..100` 正好是完整的表。正文已改寫，只剩「`s <> 24h` 是多餘的」這一條
  落差。
- **spec 803**：角色的每法術旗標陣列是 `+79h`..`+0DCh`（**100 格**），不是 56 格。
  下一個有用途的欄位 `+0DDh`（spec 806）正好接在後面，版面因此連得起來。
- **spec 773 / `docs/audit/resident-data-tables.md`**：兩張表都已重排成 100 列。

⚠ 教訓：**先前那份 56 筆的表是「掃到哪裡算哪裡」得來的，沒有量過邊界**。
本輪是靠程式碼裡出現的索引值反過來戳破它。凡是「表有幾筆」這種數字，都要有
量測依據，不能沿用前一次的印象。

## `overlay-15:1EFDh`（entry#24，74 條，實質差異 5 條）— 全隊能治多少

`retf 2` ＝ 一個 word（呼叫端框架裡的記錄位址）。

```pascal
總 := 0;
p := DS:650Ah;
while p <> NIL do begin
    if <本模組 1EDAh>(rec, p) then
        for i := 0 to 53h do
            case 角色^[1Eh + i] of                    { 整個 byte，不遮最高位 }
            03h:  總 := 總 + <far 145Bh+2>(1, 8);         { 1d8 }
            3Ah:  總 := 總 + <far 145Bh+2>(2, 8) + 1;     { 2d8+1 }
            47h:  總 := 總 + <far 145Bh+2>(3, 8) + 3;     { 3d8+3 }
            end;
    p := p^[189h];
end;
ss:[rec − 2] := ss:[rec − 2] + 總;
```

### 三個治療法術的骰數與 AD&D 相同

| 法術 | 編號 | 骰 |
|---|---|---|
| `Cure Light Wounds` | 3 | 1d8 |
| `Cure Serious Wounds` | 3Ah | 2d8 ＋ 1 |
| `Cure Critical Wounds` | 47h | 3d8 ＋ 3 |

**比較的是整個 byte**，所以最高位為 1（還在記憶中，spec 792）的格子不算——
只有已經記好的才計入。

`145Bh+2(骰數, 面數)`：先推的是骰數。

結果**累加**進呼叫端記錄的 `rec − 2`（不是覆寫）。與 spec 789 的
`overlay-15:2255h` 是同一個位置——那一支把 `rec − 2` 當「剩餘可治療量」往下扣，
本支則是把它加起來。**兩支合起來就是「先算全隊能治多少、再分配下去」。**

## `overlay-13:1433h`（entry#14，62 條，實質差異 6 條）— 挑 `+0E9h` 最小的

`retf 8` ＝ 4 個 word。依宣告順序：`(角色, 輸出遠指標)`。

```pascal
最小 := 0Dh;
輸出^ := NIL;
n := <far 1590h>(角色, 0FFh);
有 := 0;
for k := 1 to n do begin                              { 無號 }
    i := byte[758Eh + k];                             { 目標索引清單，spec 802 }
    q := 遠指標(DS:6D35h + i * 4);                    { 戰鬥員遠指標表，spec 785 }
    if (q^[18Dh]^[10h] = 0)
       and (有號(q^[0E9h]) > 0) and (有號(q^[0E9h]) < 最小) then begin
        最小 := q^[0E9h];
        輸出^ := q;
        有 := 1;
    end;
end;
結果 := 有;
```

- 門檻的初值是 **`0Dh`（13）**，所以 `+0E9h` ≥ 13 的戰鬥員永遠選不上。
- 戰鬥狀態記錄的 **`+10h`** 在這裡第一次有用途：**必須為 0** 才是候選。
  spec 806 的版面表把它列在「還沒看到用途」那一格，現在可以刪掉。
- `n = 0` 時整個迴圈不跑，輸出留 NIL、回傳 0。

### PC-98 側這次是**它**錯位

DOS 62 條、PC-98 63 條，多出來的是 PC-98 的 `14F3h std`。原始位元組兩平台同形：

```
DOS  1470: FE 46 FD 8A 46 FD 30 E4 8B F8 8A 85 8E 75 30 E4
PC-98 14F1: FE 46 FD 8A 46 FD 30 E4 8B F8 8A 85 20 A8 30 E4
```

`FE 46 FD` ＝ `inc byte ptr [bp−3]`（3 bytes）；PC-98 側的 IDA 在前面斷錯，把
`FD` 單獨解成 `std`。

**spec 811 是 DOS 錯、這裡是 PC-98 錯——兩邊都會發生，不能預設哪一邊比較可信。**
