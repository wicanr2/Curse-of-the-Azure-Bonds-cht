# 1035 — 鑑價畫面補讀完（PC-98 側）：賣價只有五分之一，以及「空物品鏈接不上」的原作瑕疵

- 證據等級：`exact`（PC-98 側 843 條全部讀完 ——
  IDA 匯出在 `1BBAh`..`2305h` 有 **1867 bytes 空洞**，本次以
  `objdump -D -b binary -m i8086` 逐指令補讀，補出的序列與 DOS 對側逐條對得上）
- 作法見 spec 783；DOS 對側見 spec 1018

## `pc98 overlay-21:01A3Eh`（`retf 4`）

spec 1018 當時把這一列**誠實留在「待解讀」**，理由記在台帳上：
只匯出 843 條裡的 150 條，中間 1867 bytes 沒有反組譯。
本次補齊，該列改為已解讀。

> ★ **方法**：`objdump` 的起點要對齊指令邊界。從匯出的最後一條
> （`1BBAh  call far ptr …`，5 bytes）算出 `1BBFh` 才是下一條的起點；
> 直接從空洞的標示位址（`1BBAh` 之後的任意位置）開始會整段錯位。
> 對齊之後每一條都能與 DOS 側對上，這是補讀正確與否的驗收條件。

## 與 DOS 對照：數值完全一致

spec 1018 記的兩張表在 PC-98 側逐格相同：

- **寶石**：1d100 → `1-25→10`、`26-50→50`、`51-70→100`、`71-90→500`、
  `91-99→1000`、`100→5000`
- **珠寶**：1d100 → `1-10→Random(900)+100`、`11-20→Random(1000)+200`、
  `21-40→Random(1500)+300`、`41-50→Random(2500)+500`、
  `51-70→Random(5000)+1000`、`71-90→Random(6000)+2000`、
  `91-100→Random(10000)+2000`

物品節點欄位（PC-98，全部 ＝ DOS ＋ `28h`，spec 1011 的欄位名）：

| PC-98 | DOS | 內容 |
|---|---|---|
| `+52h`／`+54h` | `+2Ah` | next ＝ NIL |
| `+56h` | `+2Eh` | itemptr ＝ `46h`（70），寶石與珠寶**相同** |
| `+57h`／`+58h` | `+2Fh`／`+30h` | namenum(1)／(2) ＝ 0 |

| `+5Fh`（word） | `+37h` | ＝ 1 |

★ `GetMem(67h)` ＝ **103 bytes** ⇒ PC-98 物品節點 103 bytes，
DOS `GetMem(3Fh)` ＝ 63 —— 第四次確認。

## ★★★ 兩個新結論（spec 1018 沒記到）

### 1. 賣掉只拿到估價的五分之一

```asm
22D2  mov  ax, [價值]
22D8  mov  cx, 5
22DB  div  cx                    ; ★ 除以 5
22DD  mov  [價值], ax
22E1  push [價值]
22E6  call 0218h                 ; 本模組的入帳程序
```

> ★★★ **選「賣」時入帳的是「估價 ÷ 5」，不是估價本身**（整數除法，餘數丟掉）。
> 兩平台、寶石與珠寶四個分支都一樣。
> ⇒ 玩家看到的 `'宝石の値段は … ｇｐです。'` 是**估價**，不是實際拿到的錢。

### 2. 「留下」有兩道門檻，其中一道是 16 件

```pascal
能不能拿 := <本模組 0073h>(目前角色, 1, @價值);   { 形狀上是負重檢查 }
if (能不能拿 <> 0) or (角色^[14Dh] >= 10h) then
    只給「賣」                                     { 熱鍵塊 DS:13E4h }
else
    給「賣」與「不賣」                             { 熱鍵塊 DS:13EEh }
```

★ **`角色^[14Dh]`（PC-98）＝ 物品件數，上限 `10h` ＝ 16 件**
——注意它**不是**物品鏈頭（鏈頭在 `+14Eh`，spec 1034）。
DOS 對應是 `+14Ch`／`+14Dh`。

★ 兩塊 10 bytes 的熱鍵常數（機制見 spec 1030）：

| 位址 | 內容 | 讀作 |
|---|---|---|
| `DS:13E4h` | `20×5 53 20×4` | 槽 6 ＝ `S`（只能賣） |
| `DS:13EEh` | `20×5 53 20×3 4B` | 槽 6 ＝ `S`、槽 10 ＝ `K` |

## ★★★ 原作瑕疵：物品鏈是空的時候，留下來的東西會消失

```pascal
p := 角色^[14Eh];                     { DOS：+14Dh }
if p = NIL then
    p := 新節點                        { ⚠ 只寫進區域變數，沒有寫回 角色^[14Eh] }
else begin
    while p^[52h] <> NIL do p := p^[52h];
    p^[52h] := 新節點;                 { 這一路是對的 }
end;
```

> ★★★ **角色身上原本一件物品都沒有時，`GetMem` 出來的寶石／珠寶節點
> 只被寫進區域變數，從來沒有接回角色的物品鏈頭。**
> 玩家選了「留下」，錢沒拿到、東西也沒有——而且那 63／103 bytes 記憶體漏掉。
>
> ⚠ **兩平台、寶石與珠寶四個分支，全部一樣**：
> DOS `overlay-21:01E60h`／`021BCh` 的 `jnz`，
> PC-98 `01F19h`／`0228Ah` 的 `jne`，之後那一段都沒有回寫。
> ⚠ 沒有實機驗證（要先讓一個角色身上完全沒有物品再去鑑價）。

★ 選項行**兩個變體都是 40 bytes**（不是 spec 1030／1031 的 80）。
★ 熱鍵 `G`（`0A33Ah`）／`J`（`0A33Bh`）／`E`（`0A33Eh`），
以及賣／不賣的 `S`／`K` ——**全部沿用 DOS 的英文大寫字母**。
⚠ 「売ﾗﾅｲ」配 `K`（Keep）、「売る」配 `S`（Sell）：**文字與熱鍵字母對不上**，
這是 PC-98 一貫的作法（換文字不換鍵），中文化照做即可。
