# 1031 — 商店版營地選單：同一支版面換一個字，以及 Yes／No 熱鍵在兩處不一致

- 證據等級：`exact`（DOS 側 270 條、PC-98 側 307 條，兩邊各自逐條讀完）
- 作法見 spec 783

## `dos overlay-06:006F6h` ↔ `pc98 overlay-06:00778h`

兩側原本都是待解讀。這是 spec 1030（`overlay-04` 營地選單）的**商店版**：
逐條比對後，兩支的指令序列只差開頭一段與字串，其餘完全對應
（DOS 251 條 vs 270 條，差的 19 條全在下面兩節）。

| | 營地（spec 1030） | 商店（本支） |
|---|---|---|
| 第一個選項 | `Heal`／「治療」 | **`Buy`／「買う」** |
| 熱鍵 | `H` | **`B`** |
| 離開 | `Exit`／「やめる」 | `Exit`／**「抜ける」** |
| 說話的人 | `a priest`／「僧侶」 | `the Shopkeeper`／「店主」 |

其餘七個選項、分支去向（`V`／`T`／`P`／`S`／`A`／`E`／`G`／`O`）、
離開流程、`overlay-24 entry#37` 重繪條件都與 spec 1030 相同。

## ★ 多出來的前置：走公用池第 8 格的物品鏈

商店版在進迴圈前多一段：

```pascal
p := 遠指標(DS:6F8Ch);                 { 公用池第 8 格，spec 773 }
while p <> NIL do begin
    <overlay-24 entry#1>(0, 0, 0, 0, p, 0);
    p := p^[2Ah];                      { ★ 物品節點的 next }
end;
```

★ **`+2Ah`（DOS）／`+52h`（PC-98）＝ 物品節點的 next**，差正好 `28h`
——與「DOS 物品節點 63 bytes／PC-98 103 bytes、名稱欄加寬 40」那條既有結論
（spec 1011／1018）一致，這是第三個獨立確認。

★ 所以 `DS:6F70h` 那八格裡，**前七格是七種貨幣的 longint，第八格是物品鏈頭**
（spec 773 記過「第 8 格另外判斷」，這裡看到它被當指標走）。

## ★★ 獨立確認 spec 1030 的「暫存字串參數」產碼慣例

spec 1030 是從堆疊算術回推出「`0A54:0634h` 把目的指標留在堆疊當第一個參數」。
商店版換了一種寫法，直接證實同一件事：

```asm
0709  mov  byte ptr [bp+var_2B], 0     ; ★ 迴圈外把長度 byte 設 0 ＝ 空字串
…
07E7  lea  di, [bp+var_2B] ; push ss ; push di   ; 第一個參數
07EC  lea  di, [bp+var_29] ; push ss ; push di   ; 第二個參數（選項行）
      …五個 byte…
07FA  call far ptr 167h:2Fh                       ; retf 16h ＝ 22 bytes ✓
```

> ★★ 這裡沒有 `0A54:0634h`，長度 byte 在迴圈外設一次就好，
> **推入次數與 `retf 16h` 直接對得上**——
> 確認選單的參數表是「兩行選項字串 ＋ 5 個 byte ＋ 1 個輸出旗標」。

## ★★★ 同一個 Yes／No 提示，兩處的熱鍵不一樣

PC-98 兩支都是整塊 `Move` 進熱鍵表（機制見 spec 1030），但內容不同：

| 提示 | 熱鍵塊 | 內容 | 是／否 |
|---|---|---|---|
| 營地（spec 1030） | `DS:0570h` | `59 20×8 42` | **`Y`／`B`** |
| 商店（本支） | `DS:0656h` | `41 20×8 42` | **`A`／`B`** |

> ★★★ **同一句「要不要回去拿錢」，PC-98 在營地綁 `Y`，在商店綁 `A`。**
> 兩邊的「否」都是 `B`。⚠ 這是原作的不一致，不是判讀誤差——
> 兩塊常數在資料段裡相隔 `0F6h`，內容逐 byte 不同。
> 中文化沿用時要照抄各自的塊，不能統一成一組。

空槽的填法也不一致：

| | 空槽 6 bytes |
|---|---|
| 營地 `DS:057Ah` | 半形空白 `20` × 6 |
| 商店 `DS:0660h` | **全形空白 `81 40` × 3** |

★ 但**兩邊的欄位寬度都是 7 bytes（1 個長度 byte ＋ 6 bytes 容量）** ——
spec 1030 那條「一格 ＝ 容量固定 6 bytes 的短字串」在這裡第二次成立。
⚠ 長度 byte 是實際長度、不是固定 `06`：spec 1032 的那一塊空槽直接填 `00`。

## 兩個選項列（PC-98，各 80 bytes ＝ 80 欄）

```
有寶物  '     買う  ｷｬﾗｸﾀｰ 金戻す 金集ﾒﾙ 金分ｹﾙ    見積る                      抜ける    '
沒寶物  '     買う  ｷｬﾗｸﾀｰ        金集ﾒﾙ           見積る                      抜ける    '
```

★ 各選項的起始位移在兩個變體裡**固定不變**（5／11／18／25／32／42／70），
用不到的就整格留白——與 spec 1030 的營地兩個變體是同一組位置。
熱鍵塊 `DS:0642h` ＝ `B V T P S A _ _ _ E`、`DS:064Ch` ＝ `B V _ P _ A _ _ _ E`。

## 中文化

| 功能 | DOS | PC-98 | 熱鍵 | 建議中文 |
|---|---|---|---|---|
| 買 | `Buy` | 「買う」 | `B` | 購買 |
| 看角色 | `View` | 「ｷｬﾗｸﾀｰ」 | `V` | 人物 |
| 取回 | `Take` | 「金戻す」 | `T` | 取錢 |
| 集中 | `Pool` | 「金集ﾒﾙ」 | `P` | 集資 |
| 分配 | `Share` | 「金分ｹﾙ」 | `S` | 分錢 |
| 鑑價 | `Appraise` | 「見積る」 | `A` | 估價 |
| 離開 | `Exit` | 「抜ける」 | `E` | 離開 |

離開訊息：

| | DOS | PC-98 |
|---|---|---|
| 前句 | `'As you Leave the Shopkeeper says, "Excuse me but you have Left Some Money here."  '`（82） | 「きみたちが行こうとすると、店主が呼び止めた。「お金をお忘れですよ」」（66） |
| 後句 | `'Do you want to go back and get your Money?'`（42） | 「引き返してお金を取りますか？」（28） |
| 是／否 | `'~Yes ~No'`（8，波浪號標記） | `' はい　いいえ'` ＋ 熱鍵 `A`／`B` |

⚠ DOS 這兩句的大小寫本身就亂（`Leave`／`Left`／`Some Money`／`Money?`），
而且前句結尾有**兩個空白**——照抄長度即可，不必模仿大小寫。
⚠ 對照營地版：`retrieve your money?` ↔ `get your Money?`，
**英文兩句不同、日文兩句完全相同**。中文可以統一成一句（跟 PC-98）。

## 明確不宣稱

- 沒有宣稱 `overlay-24 entry#1(0, 0, 0, 0, 物品, 0)` 對每個物品做什麼。
- 沒有宣稱 `sub_474`（DOS）／`sub_4BE`（PC-98）＝ `Buy` 分支做什麼。
- 沒有宣稱選項在 80 欄那一列裡的欄位起點是怎麼算出來的（只知道位置固定）。
- 沒有宣稱為什麼營地用 `Y`、商店用 `A`。
- 沒有宣稱印字參數 `0Ah`／`1`（營地）與 `0Fh`／`0`（商店）的差別代表什麼。
