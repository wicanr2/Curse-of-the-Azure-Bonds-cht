# 第六百二十五輪：ECL 位址分類器 —— bank 常數是刻意讓區間起點落在 offset 0

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：PC-98 `overlay-07:1148h`（`STORESTRING`，540 bytes）。

本輪要處理的是一個先前留著的缺口：分類器（`0801h`，[spec 563](563-ecl-memory-model-and-operand-resolution.md)）
與 `FINDGUY`（`085Ch`，[spec 615](615-ecl2-findguy-maxrange.md)）都已判讀，但
**類別怎麼變成實際位址**一直沒有解釋——`6A00h` 這些常數只能當魔術數字抄。

## 位址分類器回顧（`0801h`，spec 563）

輸入一個 ECL 位址，回傳一個 byte 類別：

| 類別 | 位址區間 |
|---|---|
| `0` | `4B00h`..`4EFFh` |
| `1` | `7C00h`..`7FFFh` |
| `2` | `7A00h`..`7BFFh` |
| `3` | `8000h`..`9E40h` |
| `4` | 以上皆非（預設值） |

四段互不重疊，所以鏈上的先後順序不影響結果。

類別 3 的上界 `9E40h` 與同 spec 從 `New` 參數量到的 bank 3 大小
（`1E41h` = `8000h..9E40h`）**完全吻合**——那邊是配置大小，這邊是位址判斷，兩條
互相獨立。

類別 1 就是 [spec 624](624-ecl-special-address-space.md) 的特殊位址空間。

## bank 常數的來歷

`STORESTRING` 依類別把字元存進對應 bank：

| 類別 | 定址式 | 每字元 |
|---|---|---|
| `0` | `DS:7F05h` ＋ `(addr + i) × 2` ＋ `6A00h` | **word** |
| `1` | `DS:7F09h` ＋ `(addr + i) × 2` ＋ `800h` | **word** |
| `2` | `DS:7F0Dh` ＋ `(addr + i) × 2` ＋ `0C00h` | **word** |
| `3` | `DS:7F12h` ＋ `(addr + i)` − `8000h` | **byte** |

**位址沒有先減去區間起點**，直接乘 2 加常數。之所以還能對，是因為 16-bit
偏移量會回捲，而常數正好補到剛好一圈：

| bank | 起點 × 每字元寬度 | `10000h` 減該值 | 程式碼常數 |
|---|---|---|---|
| 0 | `4B00h` × 2 = `9600h` | `6A00h` | `6A00h` |
| 1 | `7C00h` × 2 = `F800h` | `0800h` | `0800h` |
| 2 | `7A00h` × 2 = `F400h` | `0C00h` | `0C00h` |
| 3 | `8000h` × 1 = `8000h` | `8000h` | `8000h`（寫成 `−8000h`）|

四個全對。**這四個常數不是任意挑的**——它們是「讓區間起點對到 bank 的 offset 0」
的唯一解。少掉這層，`6A00h` 之類的數字只能當魔術數字抄，也沒辦法判斷位址算錯時
會落到哪裡。

回捲是**刻意的**，不是溢位 bug：`(4B00h × 2 + 6A00h) mod 10000h = 0`。

### bank 3 的寬度不一樣

bank 0／1／2 一個字元佔一個 **word**，bank 3 佔一個 **byte**。所以同樣長度的
字串在 bank 3 只用一半空間，而 bank 3 也是四個裡唯一大小被量到的
（`1E41h` bytes）。

### 類別 4 靜默不做事

分類結果是 `4`（不在任何區間）時，`STORESTRING` 沒有對應分支——**什麼都不寫也不
報錯**。

## `STORESTRING` 的字串終止與角色名字

每個 class 的迴圈寫完 `n` 個字元後，會**再寫一個 0** 當終止符（bank 3 寫 byte，
其餘寫 word）。長度為 0 的字串就只寫那個 0。

一個特例：`addr = 7C00h`（bank 1 的第一個位址）**不進迴圈**，而是直接把字串
複製進 `DS:9594h` 指的角色紀錄開頭，**上限 `0Fh`（15）**：

```asm
cmp  [bp+arg_4], 7C00h
jnz  short 一般路徑
lea  di, [bp+var_100]        ; 來源字串
push ss / push di
les  di, ds:9594h            ; 目的：角色紀錄 offset 0
push es / push di
mov  ax, 0Fh                 ; 上限 15
```

角色名字在紀錄 offset 0（[spec 623](623-killthedude-damage-message.md) 從讀取側
看到同一個位置）。**寫入上限是 15，讀取上限是 30**——兩邊不一樣，中文化取較嚴的
15 bytes 為準。

## 順帶補上的一筆：角色鏈的 next 指標

`FINDGUY`（[spec 615](615-ecl2-findguy-maxrange.md)）走的那條鏈，next 指標在角色
紀錄的 **`+18Ah`**，串列頭在 `DS:9598h`。

[spec 624](624-ecl-special-address-space.md) 的 `7EB1h`／`7EB4h` 兩個特殊位址就是
拿 `DS:9594h`（目前角色）去查 `FINDGUY`——也就是**目前角色在隊伍中的位置**。

## 明確不宣稱

- `DS:9598h` 串列裝的是隊伍還是別的集合（只知道 `DS:9594h` 是其中一員）。
- 類別 `4` 的位址由誰處理、或根本不處理。
- 為什麼 bank 3 用 byte 而其他用 word。
