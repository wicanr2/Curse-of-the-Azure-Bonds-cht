## `overlay-09:00DB1h`（entry#6，兩平台各 371 條）

`retf 4` ＝ 一個角色遠指標。回傳 `al`（1 ＝ 這回合結束）。

## 武器射程 ＝ 物品類型表的 `+0Ch` 減 1

`DS:5D02h` ＝ `5CF6h + 0Ch`，也就是 spec 804 那張**物品類型表**（16 bytes 一筆）
的第 `0Ch` 欄。**這一欄是武器射程**：

```pascal
射程 := byte[5CF6h + 類型 * 10h + 0Ch] − 1;
if (射程 = 0) or (射程 = 0FFh) then 射程 := 1;
```

沒裝備武器（`+151h` 為 NIL）時射程也是 1。`0FFh` 是「減 1 減到溢位」的情形，
也就是表裡填 0 的類型——一律當 1 處理。

物品類型表已知欄位累積：`+0` 類別碼、`+5`、`+6` 旗標＋加值、**`+0Ch` 射程**、
`+0Dh` 職業遮罩。

## 距離單位是半格

`far 18A9h` 把距離回填進 `距離`，判定寫成 `(距離 div 2) ≤ 射程`。
spec 837 讀到移動花費是 `地形成本 × 2`（正向）／`× 3`（斜向），
兩處對得起來：**引擎內部的距離與移動力都以半格為單位**，射程則是整格。

## 20 次上限是硬性的

`次數` 每繞一圈加 1，超過 `14h`（20）就強制 `停 := 1`。這是防呆——AI 每回合最多
繞 20 圈，之後由 `1201h` 決定 `續`。remake 照抄這個上限即可，不必自己設計。

## `+18Dh^[03h]` 在這裡有兩個哨兵值

主迴圈進出都在看 `+03h`（先攻值，spec 806）：

- `= 0` → 續 := 0（回合結束）
- `= 14h`（20）→ 同樣 續 := 0
- 移動階段只在 `0 < +03h < 14h` 時跑

所以 **`14h` 是先攻值的哨兵值**，不是一般的先攻順位。

## 開場清三個全域

`DS:47F0h := 8`、`DS:47F1h := 0`、`DS:47F2h := 0`。三格都落在 DOS 資料段的
**BSS 起點 `47E0h` 之後**（spec 804），是執行期變數，dump 裡讀不到初值。

spec 839 把前兩格定名了：**`DS:47F0h` ＝ 上一步走的方向**（`8` 是「還沒走過」的哨兵值，
落在 0..7 之外）、**`DS:47F1h` ＝ 連續折返次數**。`DS:47F2h` 仍未定名。

## PC-98：全部是位址差

`+18Dh`↔`+18Eh`、`+151h`↔`+152h`、`+196h/197h`↔`+197h/198h`、
`DS:47F0h`↔`DS:78A6h`、`DS:75E4h`↔`DS:0A876h`、`DS:6E92h`↔`DS:9F2Ch`、
`DS:5D02h`↔`DS:8D90h`、物品 `+2Eh`↔`+56h`，其餘是呼叫目標。**沒有邏輯差異。**

## 順帶更正 spec 830

spec 830 把 `0CB7h` 的呼叫記成 `(0, 1, 0FFh, 角色)`，那是**推入順序的反向**。
兩個呼叫點（`overlay-09:01F7h` 與本支 `100Bh`）都先推角色遠指標再推三個 byte，
依 spec 783 的規矩，宣告順序是 `(角色, 0FFh, 旗標, 0)`。830 已改。
