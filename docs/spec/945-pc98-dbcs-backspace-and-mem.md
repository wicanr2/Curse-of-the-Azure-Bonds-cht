# 945 — PC-98 常駐四支：雙位元組退格、記憶體池、按鍵分派

- 證據等級：`exact`（四支逐條讀完，來源是 `PC98-GAME.EXE.asm`）
- 位置：`PC98-GAME.EXE` 的 `19C91h`、`18571h`、`18612h`、`16E70h`
- 作法見 spec 783

## ★ `19C91h`（70 行）：會處理全形字的退格

```pascal
byte_280E3h := 0;
{ ── 從頭掃到倒數第二個位元組，判斷最後一個是不是全形字的後半 ── }
ah := 0;                                   { 前導位元組旗標 }
for i := 0 to 長度 − 2 do begin
    al := 緩衝[i];
    if ah <> 0 then ah := 0                { 上一個是前導 → 這個是後續 }
    else if byte_280D0h <> 0 then
        if <sub_1977Eh>(al) 進位 then ah := al;   { 這個是前導 }
end;

if ah = 0 then begin                       { 單位元組：退一格 }
    送(8);  送(' ');  送(8);
    dec(長度);
end else begin                             { ★ 全形：退兩格 }
    cs:byte_19D01h := 1;                   { ⚠ self-modifying 旗標 }
    送(8);
    cs:byte_19D01h := 0;
    送(' ');  送(' ');
    送(8);   送(8);
    dec(長度);  dec(長度);
end;
```

**這是整份 PC-98 常駐裡最直接對中文化有用的一支。**
它的作法是：**每次退格都從頭重掃一遍緩衝**，用 `<sub_1977Eh>` 逐位元組
判斷前導／後續，據此決定退一格還是兩格。

- `byte_280D0h` ＝ 0 時完全不做雙位元組判定，等於停用全形支援。
- 全形分支多寫一次 `' '`（共兩格空白）與多一次 `BS`，並把長度減 2。
- ⚠ `mov cs:byte_19D01h, 1` 是**寫進程式碼段的旗標**（self-modifying），
  只在第一個 `BS` 期間立著——形狀上是讓底層送字元的常式知道
  「這一次不要做全形拆分」。

**Big5 與 Shift-JIS 同樣是雙位元組**，所以繁中版可以照抄這個結構，
只要換掉 `<sub_1977Eh>` 的前導位元組判定範圍。
DOS 版的輸入欄（spec 941）**沒有這一層**——它一個位元組退一格。

## `18571h`（58 行）：抓走最大的一塊 DOS 記憶體

```pascal
word_24186h := 0;  word_24188h := 0;  word_2418Ch := 0;  word_24190h := 0;

int 21h AH=48h, BX=0FFFFh;                 { 故意失敗，BX 帶回最大可用段數 }
word_24184h := BX;
int 21h AH=48h;                            { 用那個大小真的配置 }
if 進位 or (AX <= 2) then 結果 := 0
else begin
    word_24182h := AX;                     { 池的起始段 }
    word_24186h := AX ＋ 2;
    word_24188h := word_24184h − 2;        { 可用段數 }
    word_2418Ah := AX;                     { 池 A 的表頭段 }
    word_2418Eh := AX ＋ 1;                { 池 B 的表頭段 }
    { 兩個表頭各把 +0..+6 四個 word 清 0 }
end;
```

**一次把幾乎全部剩餘記憶體要走**，前兩段留給兩個池的表頭
（每個表頭 8 bytes，四個 word 都是 0 ＝ 空鏈）。

## `18612h`（66 行）：在兩個池之間搬區塊

用 `<sub_18767h>` 找一塊、`<sub_187AAh>` 另尋、
`<sub_1883Eh>` 掛到 `word_2418Eh` 那個池、`<sub_18810h>` 掛到 `word_2418Ah`；
每次都從區塊前一段（MCB）的 `+0` 讀出大小去加減
`word_2418Ch`／`word_24190h` 兩個計數。搬進池 B 時在 MCB 的 `+8`
寫下標記 **`818Eh`**。

所以那兩個池是 **「使用中」與「可回收」** 的雙鏈，`+8` 的魔數用來認自己的區塊。

## `16E70h`（65 行）：按鍵分派迴圈

```pascal
<sub_1705Ah>();
byte_16A23h := <sub_16ECEh>();
repeat
    <sub_16F81h>();
    鍵 := int 21h AH=7;                     { 直接讀鍵盤、不回顯 }
    if <sub_1711Fh>(鍵, 遠指標(dword_16A19h)) then
        <sub_16F2Bh>()                       { 命中第一張表 → 處理後繼續 }
    else if <sub_1711Fh>(鍵, ds:2AA6h) then begin
        n := 結果 − 1;
        r := call word ptr [2D1Eh ＋ n × 2]; { ★ 跳表 }
        if r <> 0 then begin
            <sub_170C5h>(r ＋ 1);
            離開;
        end;
    end;
until false;
```

兩張按鍵表：第一張在 `遠指標(dword_16A19h)`（可換），
第二張固定在 `ds:2AA6h`，命中之後用 `ds:2D1Eh` 的**近指標跳表**分派。
處理常式回 0 就繼續等下一個鍵，非 0 就結束並把值 ＋1 交給 `<sub_170C5h>`。

## 明確不宣稱

- 沒有宣稱 `<sub_1977Eh>` 判定前導位元組的實際範圍。
- 沒有宣稱 `byte_280D0h`／`cs:byte_19D01h` 由誰設定與讀取。
- 沒有宣稱 `<sub_18767h>`／`<sub_187AAh>`／`<sub_18810h>`／`<sub_1883Eh>`
  的內部，也沒有宣稱兩個池哪一個是「使用中」。
- 沒有宣稱 `ds:2AA6h` 那張按鍵表與 `ds:2D1Eh` 跳表有幾筆。
