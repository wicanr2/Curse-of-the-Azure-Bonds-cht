# 836 — AI 選法術：同一套門檻掃描，但每輪只隨機抽 3 個候選

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側**助憶碼完全相同**，8 條差異全是位址）
- 作法見 spec 783

## `overlay-09:00605h`（entry#5，兩平台各 111 條）

## 與 spec 835 是同一套骨架

`overlay-09:004AAh`（用道具）與本支（施法）共用一模一樣的門檻機制：

| | 用道具（835） | 施法（本支） |
|---|---|---|
| 起始門檻 | 7 | 7 |
| 輪數 | 1d7 | 1d7 |
| 每輪降 | 1 | 1 |
| 每輪看幾個候選 | **物品鏈全掃** | **隨機抽 3 個** |
| 閘門欄位 | `+18Dh^[02h]` | `+18Dh^[01h]` |
| 判定 | `本模組 03B1h`（spec 802） | 同 |

## `+18Dh^[01h]` ＝ 能施法、`+18Dh^[02h]` ＝ 能用道具

spec 806 讀到回合初始化把這兩格都固定寫 1，當時只記成「常數」。兩支 AI 決策各卡
其中一格，語意就出來了：**這兩格是「這回合還能不能施法／用道具」的開關**，
回合開始時打開，被別處的處置關掉。

## 隨機抽 3 個 ≠ 全掃

施法這一支**不會把記憶中的法術逐一評估**。每輪只擲 3 次 `1d n`，重複抽到同一格
也算一次。所以

- 記了很多法術的高階施法者，**單一法術被看到的機率反而變低**（每輪 3/n）。
- 最多評估 `1d7 × 3` ＝ 3..21 次，`n` 大於 21 時**一定有法術從頭到尾沒被考慮**。

這是刻意的行為（省 CPU ＋ 讓 AI 不完美），還是取巧，本規格不判斷；但 remake 若照
原樣重現，**這個隨機性必須保留**，否則怪物的施法選擇會明顯變強。

## ⚠ 收集清單時漏掉第一格

spec 788 的掃描是 `for i := 0 to 53h`，動到 `+1Eh`..`+71h` 共 **84 格**。
本支是 `for k := 1 to 53h`，動到 **`+1Fh`..`+71h`，只有 83 格**——
**`+1Eh` 那一格從來不會被 AI 看見**。

兩邊的上界都是 `53h`，只有下界差 1，形狀上是一處 off-by-one。**兩個平台都一樣**，
所以不是反組譯錯位。remake 要照原樣重現的話，第一格記憶欄對 AI 是隱形的。

**這一點後來被證實不是誤讀**：`overlay-15:00942h`（記憶法術選單）找空格時寫的是
`i := 0; while 角色^[1Eh + i] <> 0 do inc(i)`——**從 `+1Eh` 這一格開始找**，
所以玩家記的第一個法術確實會落在 AI 看不到的那一格。

## 兩道前置閘門

- **士氣**：`+0F7h ≤ 7Fh`（最高位被清掉 ＝ 士氣已崩，見 spec 831 把它重設成 `0B3h`
  的那一段）時**不施法**，除非 `DS:75DAh` ≠ 0 蓋過去。
- `byte[6F90h + <far 1586h>(角色)] ≤ 0` 就不施法——**與 spec 835 用道具那一支是同一道
  閘門**（那邊寫成 `ja` 繼續，這邊寫成 `jbe` 離開，同一個判斷）。

## PC-98：全部是位址差

8 條差異：`+18Dh`↔`+18Eh`、`DS:75DAh`↔`DS:0A86Ch`、`DS:6F90h`↔`DS:0A02Ah`，
其餘是呼叫目標。**沒有邏輯差異。**

## 明確不宣稱

- 沒有宣稱 `far 0C8Eh+1(選中, 1, @暫存)` 做什麼（形狀上是「把這個法術排進施放流程」）。
- 沒有宣稱 `DS:75DAh` 與 `DS:6F90h`／`far 1586h` 的意義（與 spec 835 同一批未知）。
- 沒有宣稱漏掉 `+1Eh` 是 bug 還是那一格另有用途。
