# 803 — `DS:7566h` 是休息時間、抄寫法術、`0A54h:0634h` 的呼叫慣例

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側的運算元差異已逐條列出）。
  `0A54h:0634h` 的參數清除方式標 `inferred`，理由與反例見下。
- 作法見 spec 783

## `overlay-20:05D4h`（entry#10，110 條，差異 6 條）— 「Rest Time:」的畫面

| | DOS | PC-98 |
|---|---|---|
| 標題 | `'Rest Time:'`（10） | `'休息時間'`（8 bytes） |
| 分隔 | `':'`（1） | `':'`（1，**半形，未改**） |

```pascal
for i := 0 to 6 do 顏色[i] := 0Ah;
顏色[選中] := 0Fh;
畫字串(0, 0Ah, 11h, 1, 'Rest Time:');
列 := 0Bh;
for i := 4 downto 3 do begin
    畫數字(列 + 1, 11h, 顏色[i], 0, @暫存, word[7566h + i * 2]);
    畫字串(0, 0Ah, 11h, 列 + 3, ':');
    列 := 列 + 3;
end;
畫數字(列 + 1, 11h, 顏色[2], 0, @暫存, DS:756Ah * 0Ah + DS:7568h);
```

`retf 2` ＝ 一個 word（**要高亮哪一格**，值寫進 `顏色[選中] := 0Fh`）。

### 這一支給 `DS:7566h` 那組倒數取了名字

畫面標題就是 `'Rest Time:'`。所以 spec 802 讀到的「第二組七個 word 的倒數時鐘」
是**休息時間**。

### 顯示的是「日 : 時 : 分」

- 迴圈只跑 `i = 4` 與 `i = 3` 兩次（`4` 開始、`dec`、`cmp var_1, 3` 相等就停）。
- 最後一格畫的是 `DS:756Ah * 10 + DS:7568h` ＝ **索引 2 × 10 ＋ 索引 1**。

照 spec 793 的單位表（`[1]` ＝ 分、`[2]` ＝ 十分鐘、`[3]` ＝ 時、`[4]` ＝ 日），
這三格正好是 **日、時、分**——而且分鐘是把「十分鐘」與「分」合成一個 0..59 的
數字再顯示。**這是對 spec 793 單位判定的獨立交叉驗證**（那邊靠 `24 / 30 / 12`
的上限，這邊靠畫面版面）。

索引 0（六秒）、5（月）、6（年）**不顯示**——與 spec 802「借位只到索引 4」對得起來。

### 中文化

`':'` 是半形，PC-98 沒改。標題 PC-98 用「休息時間」（不是「休憩」），四個字
剛好可以直接沿用到中文版。**版面是靠 `列 := 0Bh` 起、每格 ＋3 算出來的**，
標題長度改變不會動到數字的位置。

## `overlay-20:09DFh`（entry#14，105 條，差異 13 條）— 抄寫法術

| | DOS | PC-98 |
|---|---|---|
| 訊息 | `'has scribed'`（11） | `'を書き写した'`（12 bytes） |

`retf 8` ＝ 兩個遠指標：`arg_4` 是角色、`arg_0` 指向一個 byte 旗標。

```pascal
結果 := 0;
p := 角色^[14Dh];                                   { 物品鏈 }
while (p <> NIL) and (結果 = 0) do begin
    if <011Ah:003Eh>(p) then begin
        i := 1;
        while (i <= 3) and (結果 = 0) do begin
            if p^[3Bh + i] > 80h then begin          { 無號，嚴格大於 }
                if 旗標^ <> 0 then
                    結果 := byte[37DBh + (p^[3Bh+i] and 7Fh) * 10h]   { 法術等級 }
                else begin
                    s := p^[3Bh + i] and 7Fh;
                    角色^[78h + s] := 1;
                    <011Ah:0043h>(s, p, 角色);
                    <本模組 05D4h>(0);
                    顯示(角色名 ＋ 'has scribed');
                    <011Ah:0048h>(s);
                    旗標^ := 1;
                end;
            end;
            inc(i);
        end;
    end;
    p := p^[2Ah];
end;
```

### 與 spec 792 是同一個模子

`overlay-20:091Dh`（記憶法術）與這一支（抄寫法術）**結構完全平行**：

| | `091Dh`（spec 792） | `09DFh`（本支） |
|---|---|---|
| 來源 | 角色 `+1Eh` 起 84 格 | 物品鏈上每件物品的 `+3Ch`／`+3Dh`／`+3Eh` |
| 觸發條件 | 值 `> 7Fh` | 值 `> 80h` |
| 旗標 ≠ 0 | 回傳該法術的等級 | 同左 |
| 旗標 ＝ 0 | 清掉最高位、印 `'has memorized'` | 印 `'has scribed'`、設 `旗標^ := 1` |
| 呼叫 | `05D4h(0)` ＋ `011Ah:0048h` | 同左 |

**物品的三個效果槽用的是同一套編碼**（最高位 ＝ 還沒處理完、低 7 位 ＝ 法術編號）。
兩支的門檻差一個值：記憶是 `> 7Fh`（含 `80h`），抄寫是 `> 80h`（**不含 `80h`**）。

⚠ 抄寫這一支**不清掉物品上的最高位**——它改設 `角色^[78h + s] := 1`，
物品那一格原封不動。

### 角色 `+79h`..`+0B0h` 是每個法術一個 byte

`角色^[78h + s]` 的 `s` 來自 `and 7Fh`，而觸發條件 `> 80h` 保證原值至少是 `81h`，
所以 **`s` 一定 ≥ 1**。法術編號本來就是 1 起算（spec 773 的 56 筆表），因此這個
陣列實際占用 `+79h`..`+0B0h`（56 格）。

`+78h` 本身是**最大 HP**（spec 789 的治療分配用它與 `+1A4h` 相減），**永遠不會被
這個陣列寫到**——又一次「1 起算的陣列把第 0 格讓給別的東西」（spec 785 已數到
第三次，這是第四次）。

## `0A54h:0634h` 的呼叫慣例（`inferred`）

本支出現了一個先前解不開的形狀：

```
push 1 ; push 11h ; push 0Ah ; push 0        ← 四個參數
push ss ; push di                            ← @區域字串
push cs ; push di                            ← @字串常數
call far ptr 0A54h:0634h
call far ptr 0542h:0352h                     ← 中間沒有任何 push
```

兩個 `call` 之間**沒有任何 push**，`0542h:0352h` 卻拿得到五個參數。唯一自洽的
解釋是：**`0A54h:0634h` 把常數複製進區域字串後，只清掉「來源」那 4 bytes，
把「目的位址」留在堆疊上當下一個呼叫的參數**。

這回頭解掉 spec 795 的一個開放項：那裡 `sub_198A` 的字串是**第一個**參數
（字串呼叫在三個 `push` 之前），本規格已把 795 的「明確不宣稱」對應條目改寫。

⚠ 標 `inferred`：本規格**沒有讀 `0A54h:0634h` 的本體**（它在常駐區段，不在
overlay dump 裡）。要升級成 `exact` 必須讀到它的 `retf` 值。

## 明確不宣稱

- 沒有宣稱 `011Ah:003Eh` 判物品的什麼（形狀上是「這件東西可不可以抄」）。
- 沒有宣稱 `011Ah:0043h` / `011Ah:0048h` 做什麼。
- 沒有宣稱 `+79h` 那 56 格旗標由誰讀（本支只寫 1）。
- 沒有宣稱抄寫為什麼不清掉物品上的最高位。
- 沒有宣稱 `0542h:0352h` 六個參數各自的意義；只確定最後一個是字串、
  前面四個是 `(0, 0Ah, 11h, 列)` 這種形狀。
