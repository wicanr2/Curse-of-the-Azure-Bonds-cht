# 1002 — 「目標在不在朝向的 90° 扇形內」

- 證據等級：`exact`（DOS 側 411 條逐條讀完；PC-98 對側 410 條相似度 0.999）
- 作法見 spec 783

## `dos overlay-31:0054Ah` ↔ `pc98 overlay-31:0054Ah`（同位址）

兩側原本都是待解讀。整支**沒有任何呼叫**，純幾何判斷，`retf 0Ah`（5 個 word）。

```pascal
function 在扇形內(起點x arg_8, 起點y arg_6, 目標x arg_4, 目標y arg_2,
                  方向 arg_0): byte;

if (起點x < 0) or (起點x > 31h) or (起點y < 0) or (起點y > 18h)
   or (目標x < 0) or (目標x > 31h) or (目標y < 0) or (目標y > 18h) then
    結果 := 0                                        { ★ 出界一律否 }
else begin
    if 方向 = 0FFh then 方向 := 8;                   { ★ 0FFh 當成「原地」 }
    px := 起點x ＋ 有號(byte[2694h ＋ 方向]);         { 九格位移表，spec 999 }
    py := 起點y ＋ 有號(byte[269Dh ＋ 方向]);

    if ((起點x = 目標x) and (起點y = 目標y))
       or ((px = 目標x) and (py = 目標y)) then
        結果 := 1                                     { 起點本身、或正前方那一格 }
    else case 方向 of
        0..7: 結果 := <該方向的兩道半平面判斷>;
        8   : 結果 := 1;                              { 原地永遠成立 }
    end;
end;
```

## ★ 座標上下界就是 50×25 的戰場

`31h` ＝ 49、`18h` ＝ 24 ⇒ **x ∈ 0..49、y ∈ 0..24**，
與 spec 994 的地形鋪設（`地圖^[7 ＋ 列×50 ＋ 欄]`）、
spec 999 的雲、`overlay-32` 的兩平面讀取**同一個戰場尺寸**。

四個座標**任一個出界就直接回 0**，不是夾到邊界。

## ★★ 方向 0（上）的判斷展開後就是一個 90° 錐

程式分成兩支，各自帶一個 `目標x` 與 `px` 的大小比較：

| 分支 | 條件 |
|---|---|
| `目標x >= px` | `目標y <= py ＋ px − 目標x` |
| `目標x <= px` | `目標y <= py ＋ 目標x − px` |

兩式合起來就是

> **`目標y <= py − |目標x − px|`**

——頂點在 `(px, py)`、往 **y 遞減的方向**張開、半角 45° 的錐形。
y 在螢幕上往下遞增，所以「y 遞減」＝ **上**，
與 spec 991（浮點八方向）與 spec 999（九格位移表）的
「方向 0 ＝ 上」完全一致。

八個方向各有一段結構相同的程式（每段約 45 條），
只是把 `x`／`y` 與加減號依方向對調。**斜向的四段多一道條件**
（除了錐形本身，還要落在對角線的正確一側）。

## ★ `0FFh` 是「原地」的別名

進來時 `方向 = 0FFh` 會被改成 `8`，而索引 8 在九格位移表上是 `(0, 0)`
（spec 999）。方向 8 的分支**無條件回 1**——
所以 **`0FFh` 與 `8` 都代表「不看方向，全部都算在內」**。

呼叫端用 `0FFh` 當「不限方向」的哨兵，比傳 `8` 直覺，兩者等價。

## 這一支是什麼

沒有呼叫、沒有副作用、只回 0／1，而且吃的是「起點 ＋ 朝向 ＋ 目標」——
**形狀上是「這個目標在不在我面前」的判定**，
用於前方攻擊、扇形法術、或視野。本規格不宣稱呼叫端是誰。

⚠ 錐的頂點**不是起點本身，而是起點往朝向前進一格的位置**（`px, py`）。
起點自己另外由第一道判斷放行。所以「正前方一格」與「起點」都算在內，
但**起點的正後方一格不算**。

## 明確不宣稱

- 沒有宣稱斜向四段多出來的那道條件的幾何意義。
- 沒有宣稱本支的呼叫端與用途。
- 沒有宣稱回傳 `1` 代表「看得到」還是「打得到」。
