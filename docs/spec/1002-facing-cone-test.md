# 1002 — 「目標在不在朝向的 90° 扇形內」

- 證據等級：`exact`（DOS 側 411 條逐條讀完；PC-98 對側 410 條同樣逐條讀完，
  差的一條是方向分派用 byte 比較而非先 `xor ah, ah` 再 word 比較）
- 作法見 spec 783

## `dos overlay-31:0054Ah` ↔ `pc98 overlay-31:0054Ah`（同位址）

兩側原本都是待解讀。整支**沒有任何呼叫**，純幾何判斷，`retf 0Ah`（5 個 word）。

★ PC-98 的 Borland 除錯符號把這支叫 **`INARC`**——「在弧內」是原作者自己的命名，
不是我們從形狀推的。

```pascal
function 在扇形內(起點x arg_8, 起點y arg_6, 目標x arg_4, 目標y arg_2,
                  方向 arg_0): byte;

if (起點x < 0) or (起點x > 31h) or (起點y < 0) or (起點y > 18h)
   or (目標x < 0) or (目標x > 31h) or (目標y < 0) or (目標y > 18h) then
    結果 := 0                                        { ★ 出界一律否 }
else begin
    if 方向 = 0FFh then 方向 := 8;                   { ★ 0FFh 當成「原地」 }
    px := 起點x ＋ 有號(byte[2694h ＋ 方向]);         { 九格位移表，spec 999 }
    py := 起點y ＋ 有號(byte[269Dh ＋ 方向]);

    if ((起點x = 目標x) and (起點y = 目標y))
       or ((px = 目標x) and (py = 目標y)) then
        結果 := 1                                     { 起點本身、或正前方那一格 }
    else case 方向 of
        0..7: 結果 := <下表那兩支半平面判斷>;
        8   : 結果 := 1;                              { 原地永遠成立 }
    end;
end;
```

## ★ 座標上下界就是 50×25 的戰場

`31h` ＝ 49、`18h` ＝ 24 ⇒ **x ∈ 0..49、y ∈ 0..24**，
與 spec 994 的地形鋪設（`地圖^[7 ＋ 列×50 ＋ 欄]`）、
spec 999 的雲、`overlay-32` 的兩平面讀取**同一個戰場尺寸**。

四個座標**任一個出界就直接回 0**，不是夾到邊界。
方向為 0..8 與 0FFh 以外的值時，`case` 一支都不成立，回的是**沒被寫過的區域變數**。

## ★★ 八個方向的完整判斷式

每個方向都是**兩支半平面判斷取聯集**，程式碼長度一模一樣（各 0x55 bytes）。
下表以頂點 `(px, py)` 為原點寫；`目標x`／`目標y` 簡寫成 `tx`／`ty`。

| 方向 | 第一支 | 第二支 | 合起來 |
|---|---|---|---|
| 0 上 | `tx >= px` 且 `ty <= py ＋ px − tx` | `tx <= px` 且 `ty <= py ＋ tx − px` | `ty <= py − ǀtx − pxǀ` |
| 2 右 | `tx >= px ＋ py − ty` 且 `ty <= py` | `tx >= px ＋ ty − py` 且 `ty >= py` | `tx >= px ＋ ǀty − pyǀ` |
| 4 下 | `tx >= px` 且 `ty >= py ＋ tx − px` | `tx <= px` 且 `ty >= py ＋ px − tx` | `ty >= py ＋ ǀtx − pxǀ` |
| 6 左 | `tx <= px ＋ py − ty` 且 `ty >= py` | `tx <= px ＋ ty − py` 且 `ty <= py` | `tx <= px − ǀty − pyǀ` |
| 1 右上 | `tx >= px` 且 `ty <= py ＋ px − tx`（上～右上） | `tx >= px ＋ py − ty` 且 `ty <= py`（右上～右） | 上到右的 90° |
| 3 右下 | `tx >= px ＋ ty − py` 且 `ty >= py`（右～右下） | `tx >= px` 且 `ty >= py ＋ tx − px`（右下～下） | 右到下的 90° |
| 5 左下 | `tx <= px` 且 `ty >= py ＋ px − tx`（左下～下） | `tx <= px ＋ py − ty` 且 `ty >= py`（左～左下） | 下到左的 90° |
| 7 左上 | `tx <= px ＋ ty − py` 且 `ty <= py`（左～左上） | `tx <= px` 且 `ty <= py ＋ tx − px`（左上～上） | 左到上的 90° |

**正交四向**的兩支互為鏡像，合起來就是「沿軸的投影 ≥ 垂直方向的絕對值」；
**斜向四向**的兩支則是被對角線切開的兩個 45° 楔形，合起來同樣是 90°。
兩者在程式上是同一個形狀，斜向並沒有多一道額外條件。

y 在螢幕上往下遞增，所以方向 0 的「y 遞減」＝ **上**，
與 spec 991（浮點八方向）與 spec 999（九格位移表）一致。

## ★ `0FFh` 是「原地」的別名

進來時 `方向 = 0FFh` 會被改成 `8`，而索引 8 在九格位移表上是 `(0, 0)`
（spec 999）。方向 8 的分支**無條件回 1**——
所以 **`0FFh` 與 `8` 都代表「不看方向，全部都算在內」**。

呼叫端用 `0FFh` 當「不限方向」的哨兵，比傳 `8` 直覺，兩者等價。

## ★★ 頂點是往前一格，不是起點

錐的頂點是 `(px, py) = 起點 ＋ 位移[方向]`。起點自己另外由第一道判斷放行，
所以「正前方一格」與「起點」都算在內，但**起點的正後方一格不算**。

這個位移會改變邊界的直覺。以起點 `(3,2)`、目標 `(1,2)`（正西）為例：
只有方向 6 的扇形收得到它。方向 5（左下）的頂點在 `(2,3)`，目標落在頂點的
**左上**；方向 7（左上）的頂點在 `(2,1)`，目標落在頂點的**左下**——
兩個都在 90° 之外。拿起點當頂點推會得到「三個方向都收得到」的錯答案。

## 呼叫端

`overlay-13:095Ah`（spec 1010，離開接觸就被打）在動手之前跑
**朝向 −2 .. ＋2 五個方向**各問一次，任一成立就打得到——正面加左右各 90°，
合起來 180°。⚠ 打手的先攻 `+3 > 0` 或這一輪動作計數 `+0Fh = 0` 時，
整段面向檢查被跳過，無條件打。
