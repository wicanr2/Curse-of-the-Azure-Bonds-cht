## 戰鬥狀態 `+15h` ＝ AI 行為模式（1..6）

這是 22 bytes 記錄裡最後幾個未知欄位之一（spec 806 的版面表）。

**每回合的重骰規則**：

```
模式 ∈ 1..4 且 1d4 ≠ 1  →  保持原模式
其餘（模式 ＝ 0、模式 ≥ 5、或 1d4 ＝ 1）  →  重骰
```

也就是**模式 1..4 有 3/4 機率延續、1/4 機率重骰；模式 5 與 6 每回合必重骰**。

**重骰的分佈**：先擲 1d8，擲到 8（1/8）就再擲 1d2 ＋ 4 得到 5 或 6；否則擲 1d4 得到
1..4。所以

| 模式 | 機率 |
|---|---|
| 1..4 | 各 7/8 × 1/4 ＝ **7/32** |
| 5、6 | 各 1/8 × 1/2 ＝ **1/16** |

⚠ 第一次的 1d8 只用來決定「要不要走 5/6 那條路」，**擲出來的點數本身被丟掉**——
remake 若要對齊亂數序列，這一次空擲不能省。

## 恐慌逃走的條件

`+14h` ≠ 0（本回合已撤退，spec 782）且 `+10h` ＝ 0（spec 815 的候選條件）。
**只印訊息，不改狀態**——真正的處置在別處。

## 詠唱中的法術：DOS 不清、PC-98 會清

`+18Dh^[00h]` ＞ 0 表示上一回合開始詠唱（spec 827 寫進去的）。這一支把它交給
`11D7h+2` 結算。

**PC-98 在結算之後多做一件事**：

```
mov [bp+var_3], al
les di, [bp+arg_0]
les di, es:[di+18Eh]
mov byte ptr es:[di], 0        { 把詠唱中的法術編號清成 0 }
mov al, [bp+var_3]
```

DOS **沒有這一段**。照 DOS 的寫法，`+00h` 會一直留著上一次的法術編號，要靠別處
清；PC-98 則在這裡就地清掉。**兩邊行為不同**，remake 必須挑一邊。

## 主迴圈的兩條路

`0CB7h(0, 1, 0FFh, 角色)` 成立、先攻值 ＞ 0、且 `+196h` ≠ 0 → 走 `0DB1h`；
否則走 `1201h`。兩者都回傳「這回合完了沒」，迴圈跑到非 0 為止。

**先攻值（`+3`）在迴圈裡被讀但不在這裡減**——扣減發生在別處（spec 827 的詠唱延遲
是其中一處）。
