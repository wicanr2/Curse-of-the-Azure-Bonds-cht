# 1058 — 圖示換色：把角色的兩個 4-bit 顏色接進 16 格對照表，再重畫兩個槽

- 證據等級：`exact`（PC-98 側 210 條逐條讀完）
- 作法見 spec 783

## `pc98 overlay-17:04320h`（`retf 8`）

原本待解讀。

> ⚠ **台帳記的「160 bytes 匯出空洞」是誤判**：函式在 `452Ah` 的 `retf 8`
> 就結束了，`45CAh` 之後是 spec 1037 的字串資料
> （`0C 8C C3 82 A2 83 41 83 43 83 52 83 93` ＝ 「古いアイコン」）。
> **210 條就是完整的函式體**，與 spec 1036 是同一類誤判。

## ★★ 先把來源槽整組複製到目的槽

```pascal
{ 槽表 ＝ DS:0966Ch（spec 1033），一槽兩個遠指標 }
Move(槽[來源].a^[17h], 槽[目的].a^[17h], 槽[來源].a^[0] × …);
Move(槽[來源].b^[17h], 槽[目的].b^[17h], …);
Move(槽[來源].a^[13h]^, 槽[目的].a^[13h]^, …);      { 遮罩平面 }
Move(槽[來源].b^[13h]^, 槽[目的].b^[13h]^, …);
```

> ★★★ **這一段同時用到三份既有結論**：
> 槽表 `DS:0966Ch`（spec 1033）、圖片資料從 `+17h` 起（spec 1049）、
> 遮罩平面掛在 `+13h`（spec 1050）。三者在同一支函式裡對上。

## ★★★ 換色表：16 格恆等，再把角色的顏色插進去

```pascal
for i := 0 to 0Fh do begin 表A[i] := i;  表B[i] := i end;    { 先恆等 }
for i := 1 to 7 do begin
    表B[byte[6F54h ＋ i]]      := 角色[i]^[144h] and 0Fh;      { 第一色 }
    表B[byte[6F54h ＋ i] ＋ 8] := (角色[i]^[144h] and 0F0h) shr 4;  { 第二色 }
end;
<far 02A8:0C32h>(表A, 表B, …, 槽[來源].a);
<far 02A8:0C32h>(表A, 表B, …, 槽[來源].b);
```

★ `角色^[144h] ＋ 部位` 就是 spec 1037 的**六個部位、每格兩個 4-bit 顏色**
（低 nibble 第一色、高 nibble 第二色）。
★ `DS:6F54h ＋ i`（i ＝ 1..7）是一張**部位 → 調色盤格位**的小表；
第二色固定放在 **該格位 ＋ 8**。

> ★★★ **一個角色的外觀 ＝ 把 `+145h`..`+14Ah` 六個 byte 的十二個 4-bit 顏色
> 插進一張 16 格的恆等對照表，再整張套到圖示上。**
> ⇒ 這解釋了 spec 1037 的圖示編輯畫面改的到底是什麼：
> **改的是這張表的輸入，不是圖本身。**
> ⇒ remake 只要保留「圖 ＋ 16 格對照表」這個結構，就能重現全部配色。

## 中文化

本支沒有字串。★ 但它確認了**圖示與顏色是分離的**：
中文化換掉美術時只要維持平面版面，配色會自動跟著角色資料走。

## 明確不宣稱

- 沒有宣稱 `DS:6F54h` 那張小表的實際內容對應哪個部位
  （只確定索引 1..7、輸出是調色盤格位）。
- 沒有宣稱 `far 02A8:0C32h`（套表換色）的完整介面。
- 沒有宣稱 `arg_2`（為 0 時整段換色都跳過）是什麼。
- 沒有宣稱兩個槽（`.a`／`.b`）的分工（spec 1033 也沒有宣稱）。
