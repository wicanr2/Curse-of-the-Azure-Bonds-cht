# 1177 — 「站上去沒反應」自動分得出來：守衛的 `COMPARE` 拆出前置狀態

- 證據等級：`measured`（`cmd/cell-sweep` 全遊戲逐格實測）
- 上游：spec 1142（`4C00` 區同一格在不同段是不同的東西）、spec 1162（切法）
- 產物：[`docs/audit/cell-sweep.md`](../audit/cell-sweep.md)

## 先前「沒演出來」是一個混在一起的桶子

逐格實測站上每一個地形分派索引，記玩家真的看到什麼字。演不出來的原因至少四種，
而工具只分得出前兩種（地圖上沒有那個地形碼、要搜尋才演），剩下的一律落進
「沒演出來」，報表只能印出處理常式開頭那幾條指令，**要人去讀**。

問題在於那個桶子裡混著兩種完全不同的東西：

- **remake 沒接**：處理常式接不上、文字沒進 game pack ⇒ 要修。
- **缺前置劇情**：處理常式好好的，只是這一格要先發生別的事 ⇒ 盤點的限制。

兩者的處置相反，而分辨的成本是一格一格反組譯。

## 做法：把守衛的 `COMPARE` 拆出來，設好再站一次

守衛已經抓得到了（`internal/eclcells` 的 `Guards`），只是存成字串。改成也存
結構（`GuardCells`），對每個「沒演出來」的格子做第二次：

```
COMPARE <格子> <值> / IF <op> / EXIT
        ↓
把 <格子> 設成一個**避開 EXIT** 的值，再站上去一次
```

演得出來 ⇒ 這一格**有接、只是缺前置**，報表把擺了什麼寫在「前置」欄。
還是演不出來 ⇒ 才是真的要查。

## ★★ 不是「設成比對的值」就好

第一版就是這樣寫的，只多救回三格。原因是運算子被忽略了：

```
COMPARE 4C01 01 / IF >= / EXIT      { 4C01 >= 1 就離開 }
```

把 `4C01` 設成 `1` **反而保證離開**。要避開得往另一邊走：

| `IF` | 何時離開 | 要設成 |
|---|---|---|
| `<>` | 不等於 | 比對值 |
| `=` | 等於 | 比對值 ＋1 |
| `>=` | 大於等於 | 比對值 −1（比對值是 0 就避不開）|
| `<=` | 小於等於 | 比對值 ＋1 |
| `<`／`>` | 小於／大於 | 比對值 |

補上運算子之後從 3 格變成 **5 格**。

⚠ 只避「條件成立就 `EXIT`」那幾條——別的 `COMPARE` 動了只會擾亂分派。

## 剩下那 10 格的四種形狀

逐格看過，**都是盤點的限制不是 remake 的缺口**：

1. **守衛比的是移動前快照**（`4BF0`／`4BF1`）——這支是把隊伍**放**上去不是
   **走**過去，快照對不上。
2. **擺好的旗標被該段自己的前導覆蓋**（`4C01` 這一類）：前置狀態在進段時擺，
   而該段的前導在跑生命週期之前又寫了一次。
3. **擷取到的守衛跨過了真正的處理常式**：開頭就有 `EXIT` 的那幾格，抓到的是
   位址上相鄰、執行上無關的下一支。
4. **處理常式本來就不講話**：`PICTURE FF` 只是把圖關掉。

四種都寫進報表的抬頭，下一個人不必重推。

## 明確不宣稱

- 沒有宣稱「擺好守衛就演得出來」等於「正常玩下來會演」——那是**滿足守衛**
  不是重現劇情，報表照實寫出擺了什麼。
- 沒有宣稱那 10 格在原版演不演得出來；本篇只宣稱它們演不出來的成因在盤點側。
- 沒有處理 `COMPARE AND` 兩組條件之間的關係（兩組都會被擺，但沒有驗證
  「同時成立」是不是原作要的）。
