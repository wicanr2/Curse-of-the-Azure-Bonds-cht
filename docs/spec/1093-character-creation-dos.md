# 1093 — DOS 建角流程：種族屬性上下限表一列 16 bytes，起始年齡與 18/xx 都在這裡決定

- 證據等級：`exact`（DOS 側 2,883 條；四個「Pick」選單與六個屬性的夾值區塊
  是同一形狀重複，已各取四份逐條核對，其餘逐條讀完）
- 作法見 spec 783

## `dos overlay-17:00782h`（`retf`）

原本待解讀。範圍 `782h`..`2514h`——**全台帳最大的函式**。這是建立新角色的完整流程。

## 一、骨架

```pascal
GetMem(角色, 1A6h);  FillChar(角色^, 1A6h, 0);
角色^[124h] := 32h;   角色^[73h] := 28h;   角色^[195h] := 0;   角色^[196h] := 1;
角色^[0DEh] := 1;     角色^[126h] := Random(…);   角色^[143h] := 0Ah;

選單('Pick Race')      → 角色^[74h]  := 種族;
選單('Pick Gender')    → 角色^[119h] := 性別;
選單('Pick Class')     → 角色^[75h]  := byte[DS:3FF8h ＋ 種族 × 0Eh ＋ 選單索引];
選單('Pick Alignment') → 角色^[11Bh] := 陣營;
角色^[76h] := 起始年齡;                          { ★ 迴圈外，只算一次 }

repeat                                            { ★ 15CAh：重擲迴圈的頂點 }
    for c := 0 to 7 do if 角色^[109h + c] > 0 then 角色^[109h + c] := 1;
    角色^[1Ch] := 0;  for i := 0 to 5 do 角色^[11h + i × 2] := 0;
    …擲屬性、套種族調整、夾值…
    …決定 HP（spec 1101）…                        { ★ 也在迴圈裡 }
until 問('Reroll stats? ') = 'N';

repeat 問('Character name: ') until 名字 <> '';   { ★ 空名字直接重問 }
for i := 0 to 5 do 角色^[10h ＋ i × 2] := 角色^[11h ＋ i × 2];   { ★ 名字之後才抄 }
角色^[1Dh] := 角色^[1Ch];
if 問('Save ' ＋ 名字 ＋ '? ') <> 'N' then <overlay-16 entry#6>(…);   { spec 1075 的存檔 }
FreeMem(角色, 1A6h);  DS:6506h := 原本的目前角色;
```

> ★★ **兩個順序容易擺錯**：**HP 在重擲迴圈裡面**（`21C1h`，屬性重擲一次就
> 重算一次，因為體質變了）；**基準值複製在名字輸入之後**（`244Bh`），
> 不是擲完屬性就抄。
> ★★ `Save <名字>? ` 只比對 **`'N'`**（`24BBh`）：答 `N` 就 `FreeMem` 離開、
> 角色不留，**其餘任何鍵都存檔**。兩條路都直接結束函式，不會回到前面。
> ★ 名字欄位在角色紀錄的位移 0，複製長度是 **`0Fh` ＝ 15 字元**（`2435h`）。

★ 每個選單都是「`overlay-26 entry#1` 逐項加進鏈 → `entry#5` 顯示 → `entry#8` 釋放」，
選項文字後面接 `'  '`（`CS:706h`）與 `'Select'`（`CS:70Ah`）。
★ 四個選單都可以按 `'S'` 翻頁（`var_16 = 53h`）。

> ★★★ **職業選單的索引要再過一張表**：`DS:3FF8h ＋ 種族 × 0Eh`
> ——**一個種族一列 14 bytes**，把「這個種族的第 n 個可選職業」翻成
> 真正的職業組合編號。⇒ 各種族的可選職業清單就是這張表。

## ★★★ 二、十七種職業組合（`角色^[75h]`）

`+109h ＋ j` 是八個職業槽的等級（spec 1055／1084：牧師／德魯伊／戰士／聖騎士／
遊俠／法師／盜賊／武僧）。

| `+75h` | 設定的職業槽 | 起始經驗值 | 附帶 |
|---|---|---|---|
| `0`..`2` | `+109h ＋ 值`（牧師／德魯伊／戰士） | 25,000 | |
| `3` | `+10Ch`（聖騎士） | 25,000 | `+191h := 1`、加效果 `08h` |
| `4` | `+10Dh`（遊俠） | 25,000 | 加效果 `86h` |
| `5`..`7` | `+109h ＋ 值`（法師／盜賊／武僧） | 25,000 | |
| `8` | 牧師 ＋ 戰士 | **12,500** | |
| `9` | 牧師 ＋ 戰士 ＋ 法師 | **8,333** | |
| `0Ah` | 牧師 ＋ 遊俠 | 12,500 | 加效果 `86h` |
| `0Bh` | 牧師 ＋ 法師 | 12,500 | |
| `0Ch` | 牧師 ＋ 盜賊 | 12,500 | |
| `0Dh` | 戰士 ＋ 法師 | 12,500 | |
| `0Eh` | 戰士 ＋ 盜賊 | 12,500 | |
| `0Fh` | 戰士 ＋ 法師 ＋ 盜賊 | 8,333 | |
| `10h` | **法師 ＋ 盜賊** | **8,333** | ⚠ 見下 |

> ★★★ **起始經驗值就是 25,000 平分**：單職 25,000、雙職 12,500、三職 8,333
> ——這正是 spec 1086／1092 那三個「數值可調整」門檻的來源。
> ⚠ **例外：`10h`（法師／盜賊）只有兩職卻拿到 8,333**。
> 形狀上不是刻意的（其他雙職都是 12,500），比較像原作的漏改。
> 本規格只記錄事實，不宣稱它是不是 bug。
>
> ★ 職業槽有等級之後，若有盜賊（`+10Fh > 0`）會多叫一次 `overlay-25 entry#4`
> （形狀上是分配盜賊技能）。

## ★★★ 三、種族屬性表：一列 16 bytes（`DS:3F86h ＋ 種族 × 10h`）

| 列內位移 | 內容 | 索引 |
|---|---|---|
| `+0`、`+1` | **力量下限** | **再 ＋ 性別** |
| `+2`、`+3` | **力量上限** | 再 ＋ 性別 |
| `+4`、`+5` | **力量百分比（`+1Ch`）上限** | 再 ＋ 性別 |
| `+6`／`+7` | 智力 下限／上限 | |
| `+8`／`+9` | 睿智 下限／上限 | |
| `+0Ah`／`+0Bh` | 敏捷 下限／上限 | |
| `+0Ch`／`+0Dh` | 體質 下限／上限 | |
| `+0Eh`／`+0Fh` | 魅力 下限／上限 | |

> ★★★ **只有力量的三格再依性別分**（`角色^[119h]`），其餘五個屬性只看種族
> ——這正是 AD&D 1e「女性角色力量上限較低」的實作。
> ⇒ **spec 1086／1092 那兩張表的完整版面就是這一張**：
> 它們只用到「下限」那幾格（`3F86h`、`3F8Ch` …），上限在 `＋1`／`＋2`。

另外一張 **`DS:4172h ＋ 職業組合 × 6 ＋ 屬性`**（一個組合 6 bytes）
是**每個職業組合對六個屬性的最低要求**，在種族夾值之後再夾一次。

## ★★★ 四、擲屬性與 18/xx

```pascal
for i := 0 to 5 do begin
    …擲點…
    if 屬性[i] < 種族下限 then 屬性[i] := 種族下限;
    if 屬性[i] > 種族上限 then 屬性[i] := 種族上限;
    if 屬性[i] < 職業最低 then 屬性[i] := 職業最低;
end;

if (力量 = 12h) and ((戰士 > 0) or (遊俠 > 0) or (聖騎士 > 0)) then
    角色^[1Ch] := Random(64h) ＋ 1;                 { ★ 18/01..18/00 }
if 角色^[1Ch] > 力量百分比上限 then 角色^[1Ch] := 力量百分比上限;

if (職業組合 in 集合 CS:737h) and (某屬性 < 0Dh) then 某屬性 := 0Dh;
```

> ★★★ **力量剛好 18 且有戰士系職業，才會擲 `Random(100) ＋ 1` 的百分比**
> ——與 spec 1079 的「只有戰士／聖騎士／遊俠能有 18/xx」互相印證，
> 這裡是**產生端**。
> ★ `CS:737h` 是 32 bytes 的**職業集合常數**，命中的組合有一個屬性的下限被拉到 **13**。

## ★★★ 五、起始年齡與年齡調整

```pascal
if 職業組合 <= 7 then
    角色^[76h] := word[DS:404Ch ＋ 種族 × 1Ch ＋ 職業 × 4]
                ＋ ROLLDICE(byte[…＋3], byte[…＋2])
else
    角色^[76h] := word[DS:404Ch ＋ 種族 × 1Ch]
                ＋ byte[DS:404Eh ＋ 種族 × 1Ch] × byte[DS:404Fh ＋ 種族 × 1Ch];

if word[DS:4124h ＋ 種族 × 0Ah] <= 角色^[76h] then inc 某屬性;
if word[DS:4126h ＋ 種族 × 0Ah] <= 角色^[76h] then dec 某屬性 by 2;
if word[DS:4128h ＋ 種族 × 0Ah] <= 角色^[76h] then inc 某屬性;
```

> ★★★ **`角色^[76h]` 是年齡**，`DS:404Ch` 是 **AD&D 1e 的起始年齡表**
> （一個種族一列 `1Ch` ＝ 28 bytes ＝ 7 個職業 × 4 bytes：
> 基礎年齡 word ＋ 兩個骰子參數）。
> **多職角色不擲骰**，直接用職業 0 那一格的基礎值加上兩個骰子參數的乘積。
> ★★★ `DS:4124h`／`4126h`／`4128h`（一個種族一列 `0Ah` ＝ 10 bytes）是
> **三個年齡分期門檻**，過了就套 AD&D 的年齡屬性增減。
> ⚠ 本規格不宣稱三個門檻各自對應哪一期，也不宣稱調整的是哪幾個屬性。

## ★★ 七、種族天賦效果

選完種族後依 `角色^[74h]` 掛上永久效果（`overlay-23 entry#11(0, 0FFh, 0, 效果碼, 角色)`）：

| `+74h` | 種族 | `+144h` | 效果碼 |
|---|---|---|---|
| 1 | 矮人 | 1 | `61h`、`1Ah`、`2Fh` |
| 2 | 精靈 | 2 | `6Bh` |
| 3 | 地精 | 1 | `61h`、`12h`、`2Fh`、`30h` |
| 4 | 半精靈 | 2 | `7Ch` |
| 5 | 半身人 | 1 | `61h` |
| 6／7 | 半獸人／人類 | 2 | **無** |

★ 種族編號是 **1..7**（spec 1100 的字串表，索引 0 是 `Monster`），
與 spec 1084 的亞人等級上限表一致。
★★ `+144h` 只有 1 與 2 兩個值，落點正好是 AD&D 的**小體型**
（矮人／地精／半身人）與**中體型**（精靈／半精靈／半獸人／人類）。
最後那格是 `case` 的 `else`，人類與半獸人共用，兩者都不掛效果。
⚠ 效果碼 `61h`／`1Ah`／`12h`／`2Fh`／`30h`／`6Bh`／`7Ch`／`08h`／`86h`
各代表什麼，本規格不宣稱。

## ★★★ 六之二、收尾：把「目前值」抄成「基準值」

```pascal
for i := 0 to 5 do 角色^[10h ＋ i × 2] := 角色^[11h ＋ i × 2];
角色^[1Dh] := 角色^[1Ch];
```

> ★★★ **這是 spec 1086 那組「偶數位移 ＝ 基準值、奇數位移 ＝ 目前值」的產生端**
> ——建角結束時把六個屬性與力量百分比的目前值原封不動抄成基準值。
> 兩平台一字不差（spec 1094）。
> ★★ 位置是 `244Bh`，**在名字輸入之後**、`Save <名字>? ` 之前。
> 重擲迴圈每一輪都會把目前值清成 0 再重擲（`15FBh`），基準值那一組
> 全程不動，直到這裡才被寫入一次。

## 明確不宣稱

★ **`DS:3F86h`／`DS:4172h`／`DS:3FF8h`／`DS:404Ch` 四張表的內容已由 spec 1099 取出**
（種族屬性上下限、13 個職業組合的六屬性最低要求、種族可選職業、AD&D 1e 起始年齡）。
⚠ 三張表的**索引 0 都不是該表的資料**，人類必須當特例處理。
- 沒有宣稱 `DS:4124h`／`CS:737h` 兩表的**內容**（在資料段，本次沒有取出）。
  `DS:3E38h` 的內容見 spec 811。
★ 本支尾端還有一段 **HP 決定**（`21C1h`..`2290h`），本規格沒有涵蓋，見 spec 1101。
- 沒有宣稱效果碼 `61h`／`1Ah`／`2Fh`／`08h`／`86h` 是什麼。
- 沒有宣稱年齡三個門檻各自對應哪一期、調整哪幾個屬性。
- 沒有宣稱 `角色^[124h]`／`[73h]`／`[0DEh]`／`[29h]`／`[12Bh]`／`[0E5h]`／
  `[144h]`／`[11Bh]` 的語意。
- 沒有宣稱職業組合 `10h`（法師／盜賊）拿到 8,333 是刻意還是漏改。
★ PC-98 對側是 `pc98 overlay-17:00AFBh`（spec 1094）：助憶碼相似度 0.7554，
  六個差異塊分別是三個選單實作、多職年齡表、名字驗證與節點大小。
- 沒有宣稱屬性是用哪一種擲法。擲點在 `1625h`：`<far 145Bh+2>(3, 6)` 之後接
  `inc ax`，外面還包一層 `[bp-14h]` 的迴圈，而 `ROLLDICE` 本身的回傳基準
  （和是 `n..n×s` 還是 `0..n×(s−1)`）本規格沒有確認 ⇒ **公式不宣稱**。
★ 同一段裡的種族屬性調整已可讀出（`1636h` 起的 `case 種族 of`）：
  矮人體質 ＋1／魅力 −1、精靈敏捷 ＋1／體質 −1，形狀是 AD&D 一版的種族調整。
  ⚠ 完整的七個種族本規格沒有逐條讀完，不列表。
- 沒有宣稱 `sub_3EE3`（名字輸入後才呼叫）做什麼。
