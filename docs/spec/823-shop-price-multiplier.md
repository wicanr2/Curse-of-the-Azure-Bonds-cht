# 823 — 商店買東西：七段價格倍率（中間那一段沒有寫，價格是未初始化的區域變數）

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側**助憶碼完全相同**，實質差異 1 條）
- 作法見 spec 783

## `overlay-06:0474h`（entry#4，兩平台各 166 條）

`retf`（無參數）。

```pascal
repeat
    選中 := NIL;  清單 := DS:6F8Ch;  旗標 := 0;
    <far 01A0h:0000h>();
    DS:47EEh := 1;
    <本模組 0050h>(@鍵, @選中, @清單, @旗標);        { 'Buy' 清單 }
    if (鍵 <> 42h) and (鍵 <> 0Dh) then begin        { 'B' 或 Enter }
        結束 := 1;
    end else begin
        結束 := 0;
        case word(DS:4F9Dh^[6DAh]) of
            1:    價 := 選中^[3Ah] div 10h;
            2:    價 := 選中^[3Ah] div 8;
            4:    價 := 選中^[3Ah] div 4;
            8:    價 := 選中^[3Ah] div 2;
            20h:  價 := 選中^[3Ah] shl 1;
            40h:  價 := 選中^[3Ah] shl 2;
            80h:  價 := 選中^[3Ah] shl 3;
        end;                                          { ← 沒有 else }
        有 := <00FDh:0057h>(DS:6506h);
        if 價 <= 有 then begin
            <本模組 0355h>(@失敗, 選中);
            if 失敗 = 0 then <0110h:006Bh>(有 − 價);
        end else begin
            池 := <0110h:0075h>(@DS:6F70h);           { longint }
            if 價 <= 池 then begin                    { 32 位元有號比較 }
                <本模組 0355h>(@失敗, 選中);
                if 失敗 = 0 then <0110h:0070h>(低字(池 − 價));
            end else begin
                顯示('Not enough Money.');
                <014Dh:007Fh>();
            end;
        end;
    end;
until 結束 <> 0;
```

### 價格倍率是七段的位元旗標

`DS:4F9Dh^[6DAh]`（word，PC-98 `DS:7F09h^[62h]` 的同一塊）用**單一位元**表示商店
的態度：

| 值 | 位元 | 價格 |
|---|---|---|
| `01h` | 0 | 定價 ÷ 16 |
| `02h` | 1 | ÷ 8 |
| `04h` | 2 | ÷ 4 |
| `08h` | 3 | ÷ 2 |
| **`10h`** | **4** | **沒有寫**（見下） |
| `20h` | 5 | × 2 |
| `40h` | 6 | × 4 |
| `80h` | 7 | × 8 |

八個位元剛好排成「÷16 ÷8 ÷4 ÷2 ×1 ×2 ×4 ×8」的等比階梯，**中間那一段（`10h`，
原價）應該是 ×1**。

### 缺陷：`10h` 那一段整段沒有程式碼

`case` 沒有 `else`，`10h` 也沒有自己的分支——比較完七個值就直接跳到用 `價` 的
地方，而 `價` 是一個**從頭到尾沒有被賦值過的區域變數**（`bp − 8`）。

也就是說：**商店態度落在中間那一格時，價格是堆疊上的殘值**。任何不在那七個值裡
的內容也一樣。

remake 若要對齊原版，這裡只能明確記成「原版未定義」，不可能逐位元組重現。
合理的作法是補上 `×1` 並在文件裡註明這是刻意的偏離。

### 付款流程與神殿共用同一個模型

先扣角色（`00FDh:0057h` → `0110h:006Bh`），不夠才整筆改扣 Pool
（`0110h:0075h` → `0110h:0070h`），與 spec 822 的神殿收費一模一樣，包括
**Pool 的減法是 32 位元但只把低 16 位傳回去**這個限制。

差別是商店多一步：扣款前先呼叫 `本模組 0355h(@失敗, 選中)`，**失敗就不扣錢**
（東西沒拿到）。神殿那一支沒有這個回滾點。

| | DOS | PC-98 |
|---|---|---|
| 錢不夠 | `'Not enough Money.'`（17，**大寫 M**） | `'お金が足りません'` |

⚠ 這一句與 spec 822 神殿的 `'Not enough money.'`（**小寫 m**）**是兩個不同的字串
常數**，只差一個字母的大小寫。翻譯時要逐處替換。

## 明確不宣稱

- 沒有宣稱 `DS:4F9Dh^[6DAh]` 由誰設定，也沒有宣稱七段各對應什麼態度。
- 沒有宣稱 `物品^[3Ah]` 那個 word 是定價還是別的量。
- 沒有宣稱 `本模組 0355h` 做什麼（形狀上是「把東西交給玩家」，回一個失敗旗標）。
- 沒有宣稱 `DS:47EEh` 由誰讀。
