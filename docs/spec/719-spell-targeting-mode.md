# 第七百一十九輪：法術的選目標模式

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：DOS `overlay-22:10D2h`（`retf 8`）。

## 流程

```text
if DS:7555h = NIL then DS:7555h := DS:6506h          ← 記住上次選過的目標
DS:7435h := DS:6506h                                  ← 預設目標＝施法者自己
DS:7434h := 1
arg_0^ := 1                                           ← 預設「成功」

模式 := byte [37E1h + arg_6 × 16]                     ← DS:37DAh 表格內 +7

模式 = 1：什麼都不做（沿用上面的預設）

模式 = 2：<overlay-24 entry#37>()
          <overlay-24 entry#40>(@DS:7555h, 1, 'Cast Spell on whom'（CS:10BFh，長度 18））
          if DS:7555h = NIL then
              DS:7435h := NIL；DS:7434h := 0；arg_0^ := 0     ← 取消
          else
              DS:7435h := DS:7555h

模式 = 4：p := DS:650Ah
          [7431h + DS:7434h × 4] := p
          while 該格^[189h] <> NIL do
              [7431h + (DS:7434h + 1) × 4] := 該格^[189h]
              DS:7434h := DS:7434h + 1

其他：arg_0^ := 0                                      ← 直接失敗
```

## 三種模式

| 值 | 行為 |
|---|---|
| `1` | 目標就是施法者自己（`DS:6506h`），筆數 1 |
| `2` | 叫玩家選一個；取消（選出 `NIL`）就把 `arg_0^` 設成 0 |
| `4` | 從 `DS:650Ah` 起沿 `+189h` 走整條鏈，全部塞進目標陣列 |
| 其他 | `arg_0^ := 0`，什麼都不設 |

`+189h` 就是 spec 689 隊伍名單走訪用的那個鏈結欄位，所以模式 4 是「全隊」。

`arg_0` 是一個 `var` 參數，帶回「這次選目標成不成立」。**預設是 1**，只有模式 2
被取消或模式值不認得時才變 0。

## 兩個沒有邊界檢查的地方

**模式 4 的迴圈沒有上限。** 每多一個節點就寫進 `[7431h + (n+1) × 4]` 並把
`DS:7434h` 加 1，鏈有多長就寫多長。目標陣列的容量在本輪範圍內沒有出現任何檢查。

**`DS:7555h` 是跨呼叫保留的。** 進來時若不是 `NIL` 就不覆寫，所以模式 2 的
「上次選的目標」會被記住並當成 `entry#40` 的初值。模式 1 與 4 不會更新它——
也就是模式 2 讀到的可能是很久以前留下的值。

## 表格欄位

`DS:37DAh` 這張 16 bytes 一格的表（spec 705／712）目前已知的欄位：

| 格內位移 | 用途 | 出處 |
|---|---|---|
| `+0` | — | `overlay-24:28B3h` |
| `+2`、`+3` | 持續時間係數（第一組） | spec 705 |
| `+4`、`+5` | 持續時間係數（第二組） | spec 712 |
| `+6` | 「至少撐 1」的旗標 | spec 705 |
| `+7` | **選目標模式** | 本輪 |

## 明確不宣稱

- `overlay-24` entry#37／#40 的行為。
- `DS:650Ah`、`DS:6506h`、`DS:7555h` 各指向什麼結構。
- 模式值 `3`、`5`…是否存在（本輪只看到 `1`／`2`／`4` 被處理，其餘一律失敗）。
