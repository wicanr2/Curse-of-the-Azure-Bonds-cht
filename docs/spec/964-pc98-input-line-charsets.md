# 964 — PC-98 的底列輸入欄：三種可選的允許字元集

- 證據等級：`exact`（逐條讀完，來源是 `PC98-GAME.EXE.asm`）
- 位置：`PC98-GAME.EXE` 的 `152D0h`
- 作法見 spec 783

## `152D0h`（152 行，far，`retf 0Ch`）

`(字元集 arg_0, 最大長度 arg_2, 提示前景 arg_4, 提示背景 arg_6,
提示 arg_8, @結果 arg_C)`。

DOS 的對應是 spec 941 的 `15B42h`。

```pascal
提示 := 限長(arg_8, 50h);

{ ── 清第 24 列 ── }
<sub_1C180h>(0A000h:0F00h, 0A0h, 0);              { 字碼平面填 0 }
<sub_1C180h>(0A200h:0F00h, 0A0h, 1);              { ★ 屬性平面填 1 }

<sub_14E97h>(提示, arg_4, arg_6, 18h, 0);         { 印在第 24 列 }
游標 := (length(提示) ＋ 2) × 2 ＋ 0F00h;
上限 := 0E1h;
緩衝 := '';

case 字元集 of
  0: 取消 := <sub_171DFh>(byte_1DBD8h, 上限, 最大長度, @緩衝, 游標);
  1: 取消 := <sub_171DFh>(byte_1DC76h, 上限, 最大長度, @緩衝, 游標);
  2: 取消 := <sub_171DFh>(a0123456789, 上限, 最大長度, @緩衝, 游標);
end;

if 取消 = 0 then 結果^ := 限長(緩衝, 28h)
else            結果^ := '';                       { 空字串 }
```

## ★ 三種允許字元集

| `arg_0` | 表 | 內容 |
|---|---|---|
| 0 | `byte_1DBD8h` | 長度 `9Dh` ＝ **157 個**，從 `20h` 起連續（空白以上幾乎全收） |
| 1 | `byte_1DC76h` | 長度 `8Bh` ＝ **139 個**，從 `23h` 起且**跳掉 `27h`／`2Ah`／`2Bh`／`2Ch`／`2Eh`／`2Fh`** |
| 2 | `a0123456789` | **`"0123456789"`——只能輸入數字** |

**DOS 版（spec 941）把範圍寫死成 `20h`..`7Ah`，只有一種。**
PC-98 版改成**查表**，而且提供了「檔名可用字元」（字元集 1 跳掉的
正是 DOS 檔名不合法的那些符號）與「純數字」兩種受限模式。

★ 這對繁中化有直接影響：**允許字元是資料驅動的**，
表裡的 157／139 個項目可以直接擴充或替換，不必改程式碼。

## 幾個座標常數

- `0F00h` ＝ 3840 ＝ **24 × 80 × 2**，正好是第 24 列的起點。
- `0A0h` ＝ 160 ＝ 80 格 × 2 bytes，清整列。
- `0A200h` 是屬性平面（spec 950／946）。
- 游標位移 `(提示長度 ＋ 2) × 2` ——**提示與輸入之間空兩格**。
- 結果限長 `28h` ＝ 40，與 DOS 版相同。

⚠ **屬性平面被填成 `1` 而不是 `0`**，所以清完的那一列不是「全黑」，
而是帶著屬性 1。DOS 版的對應（spec 941 的 `<sub_15731h>`）填什麼未讀。

## 取消時回空字串

`<sub_171DFh>` 回非 0 表示取消，此時 `結果^[0] := 0`（空 Pascal 字串）。
**DOS 版沒有這個回報**——spec 941 的 Esc 與 Enter 都回傳緩衝內容，
呼叫端分不出來。**PC-98 版修掉了這個問題。**

## 明確不宣稱

- 沒有宣稱 `<sub_171DFh>`（實際的輸入迴圈）的內部，
  也沒有宣稱它會不會像 spec 941 那樣把結果轉大寫。
- 沒有宣稱 `上限 := 0E1h`（225）與 `最大長度 arg_2` 的關係。
- 沒有宣稱兩張字元表為什麼是 157 與 139 個。
