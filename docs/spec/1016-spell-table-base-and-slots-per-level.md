# 1016 — 法術屬性表的真正基底、AD&D 每環法術數進度表，以及「效果來自物品」旗標

- 證據等級：`exact`（DOS 側 352 條逐條讀完；PC-98 對側 370 條）
- 作法見 spec 783

## `dos overlay-19:01B00h` ↔ `pc98 overlay-19:01A8Fh`（`retf 6`）

兩側原本都是待解讀。

```pascal
procedure 物品效果(物品: 遠指標;   { bp+08h..0Bh }
                   加倍: byte);    { bp+06h }
模式 := 物品^.special(3) and 7Fh;   { +3Eh，spec 1011 的欄位名 }
```

## ★★★ 一、`DS:7582h` 就是「這次效果來自物品」

模式 0 的整段是：

```pascal
DS:7582h := 1;
<CALLEFFECT>(物品^.special(3), 遠指標(DS:6506h), 物品, ord(加倍 = 0));
```

`CALLEFFECT`（`overlay-23:00C9h`）的簽章
`(效果碼, 角色, 節點, 旗標)` 與 spec 1005 讀出來的**一格不差**。

★★ spec 1005 記過「`DS:7582h` 非零時整張分派表被跳過，一律走效果碼 147」。
現在知道**設這個旗標的就是物品觸發的路徑**——全 DOS 只有兩處寫 `1`、兩處寫 `0`。

> **`DS:7582h` ＝「這次的效果是物品發動的」。**
> 效果碼 147 那一支（spec 743：用物品節點第二個效果槽 `+3Dh` 的套用／解除）
> 因此是**所有物品效果的共同入口**。

## ★★★ 二、法術屬性表的基底是 `DS:37DAh`，不是 `37DBh`

本支同時讀 `byte[法術 × 16 ＋ 37DAh]`（比對 2）與 `byte[法術 × 16 ＋ 37DBh]`。
兩者相差 1 ⇒ **記錄的基底只可能是 `37DAh`**，筆距 16。

把三個已知欄位對回法術名稱表（`DS:27BDh`，筆距 41）：

| 法術 | 名稱 | `+0` | `+1` | AD&D 1e |
|---|---|---|---|---|
| 1 | Bless | 0 | 1 | 牧師 1 環 ✓ |
| 3 | Cure Light Wounds | 0 | 1 | 牧師 1 環 ✓ |
| 5 | Detect Magic | 0 | 1 | 牧師 1 環 ✓ |
| 11 | Detect Magic | 2 | 1 | 法師 1 環 ✓ |
| 21 | Sleep | 2 | 1 | 法師 1 環 ✓ |
| 23 | Hold Person | 0 | 2 | **牧師 2 環** ✓ |
| 25 | Silence, 15' Radius | 0 | 2 | 牧師 2 環 ✓ |
| 47 | Fireball | 2 | 3 | 法師 3 環 ✓ |
| 49 | Hold Person | 2 | 3 | **法師 3 環** ✓ |
| 51 | Lightning Bolt | 2 | 3 | 法師 3 環 ✓ |
| 79 | Faerie Fire | **1** | 1 | **德魯伊 1 環** ✓ |

> ★★★ **`+0` ＝ 施法職業（0 牧師、1 德魯伊、2 法師）、`+1` ＝ 法術環數。**
> 兩個 Hold Person 分別是牧師 2 環與法師 3 環——**AD&D 1e 一格不差**。

分佈：`+0 = 0` 有 37 支、`= 2` 有 45 支、`= 3` 有 15 支、`= 1` 有 4 支。

### 兩份既有規格因此要改基底

| 既有寫法 | 正確寫法 |
|---|---|
| spec 1005 效果碼 63：`byte[法術×16 ＋ 37DBh] < 4` | 讀的是 **`+1` ＝ 法術環數**，條件是「**環數 < 4**」 |
| spec 1009 目標模式：`byte[37DBh ＋ 法術×16 ＋ 5]` | 位址不變（`37E0h`），但那是記錄的 **`+6`** 不是 `+5` |

兩份都已一併更正。

## ★★★ 三、每環可記憶法術數：AD&D 1e 的進度表

模式 1（`加倍 = 0` 時）重算施法能力：

```pascal
等級 := 角色^[10Eh] ＋ 角色^[116h] × <overlay-25 entry#10>(角色);

for i := 1 to 5 do 角色^[136h ＋ i] := 0;
角色^[137h] := 1;                                   { 1 環先給 1 個 }
for L := 2 to 等級 do
    for i := 1 to 5 do
        角色^[136h ＋ i] += byte[44A9h ＋ L × 5 ＋ i];
```

`DS:44A9h` **不是絕對值表，是「每升一級的增量」表**。累加出來是：

| 等級 | 1 環 | 2 環 | 3 環 | 4 環 | 5 環 |
|---|---|---|---|---|---|
| 1 | 1 | | | | |
| 2 | 2 | | | | |
| 3 | 2 | 1 | | | |
| 4 | 3 | 2 | | | |
| 5 | 4 | 2 | 1 | | |
| 6 | 4 | 2 | 2 | | |
| 7 | 4 | 3 | 2 | 1 | |
| 8 | 4 | 3 | 3 | 2 | |
| 9 | 4 | 3 | 3 | 2 | 1 |
| 10 | 4 | 4 | 3 | 2 | 2 |
| 11 | 4 | 4 | 4 | 3 | 3 |
| 12 | 4 | 4 | 4 | 4 | 4 |

> ★★★ **這就是 AD&D 1e 法師的每日法術數表，1 到 12 級一格不差。**
> 角色的 `+137h`..`+13Bh` 是「目前每環可記憶幾個」。

### ★ `加倍 <> 0` 時把前三環的名額變兩倍

```pascal
for i := 1 to 3 do 角色^[136h ＋ i] += 角色^[136h ＋ i];
```

——形狀上是一件**把 1～3 環法術位加倍**的魔法物品。

### 重算完之後砍掉超額的已記憶法術

```pascal
FillChar(計數, 5, 0);
for i := 0 to 53h do begin                          { 記憶法術清單 +1Eh.. }
    法術 := 角色^[1Eh ＋ i];
    if (法術 <> 0) and (byte[37DAh ＋ 法術 × 16] = 2) then begin   { 只看法師的 }
        環 := byte[37DBh ＋ 法術 × 16];
        inc(計數[環]);
        if 計數[環] > 角色^[136h ＋ 環] then 角色^[1Eh ＋ i] := 0;  { 超額就丟掉 }
    end;
end;
```

★ **記憶法術清單是 `+1Eh` 起的 84 格**（迴圈跑到 `53h`）。

## 其他模式

`模式` ＝ `special(3) and 7Fh`：

| 模式 | 做什麼 |
|---|---|
| 0 | `DS:7582h := 1` ＋ `CALLEFFECT`（上面第一節） |
| 1 | 重算施法能力（上面第三節） |
| 2 | `<overlay-23 entry#24>(3, 角色)`；`<overlay-25 entry#4>(角色)` |
| 4 | `special(2) and 0Fh` ≠ 角色 `+11Bh`（陣營）時：卸下（`ready := 0`）、`DS:6F95h := 8`、`<overlay-23 entry#20>(0, 0, special(2) div 16, 角色)`、`DS:6F9Eh := 1` |
| 5 | `entry#24(0, 角色)` |
| 6 | `entry#24(4, 角色)` ＋ `entry#24(5, 角色)` |
| 8 | 再依 `special(2)`（`+3Dh`）0..5 分派成 `entry#24(0..5, 角色)` |
| 9 | `<overlay-23 entry#3>(…)`（5 word） |
| `0Ah` | `entry#24(…)` |
| `0Bh` | `<overlay-25 entry#4>(角色)` |
| `0Ch`／`0Dh`／其他 | `entry#24(…)`，最後一支還多叫一次 `entry#24(1, 角色)` |

★ **模式 4 是「陣營不合就用不了」**：`special(2)` 的低 4 位元與角色的
`+11Bh`（陣營，既有結論）比對，不同才會觸發——形狀上是
「善良角色拿了邪惡武器會被反噬」那一類。

## 中文化

本支沒有字串。但**法術屬性表 `DS:37DAh`（`+0` 職業、`+1` 環數）
與名稱表 `DS:27BDh`（筆距 41）是法術系統的兩張主表**，
中文化的法術名與「幾環」顯示都靠它們。
