# 1201 — 按鍵重放：「卡住換下一項」要環繞，夾在最後一項會被兩個選單互踢鎖死

- 狀態：`READY`（已實作；量測見下表）
- 證據等級：實測（同一份路線 `route-clean-709`、同樣 12,000 幀，改動前後各一次；
  無路線的預設路徑另量一次）
- 上游：spec 1191（路線重放）、1197（查表式路線）、1198（走位放手條件）

## 症狀

帶路線的按鍵重放 12,000 幀停在 137 格／5 段（`0x01..0x04 0x50`），最後一次有
新東西在第 1,437 幀——之後 **11,000 幀全部耗在世界地圖的紮營選單**裡。

trace 指出精確的死環：

```
「順序｜移除｜速度｜小人｜圖片｜離開｜改名」 → 卡住換下一項 → 第 6 項「改名」
「第1位：戰士｜返回修改選單」               → 卡住換下一項 → 最後一項「返回」
→ 回到修改選單 → …（每兩幀一圈，永遠出不去）
```

## 成因

「同一個選單看第 N 次就往下換一項」的 escalate 把目標項**夾在最後一項**：

```go
want := (menuSeen - 1) / patience
if want >= count { want = count - 1 }   // ← 夾住
```

兩個選單互相把對方叫出來時，各自的計數各自漲、各自夾在自己的最後一項——
「修改」的最後一項是「改名」、「改名」的最後一項是「返回修改選單」，
兩個出口（「離開」在第 5 項）**永遠不再被輪到**。

## 修法與量測

夾住改成環繞：`want := ((menuSeen-1)/patience) % count`。每一項（含出口）都
週期性被試到，死環自解。

| 12,000 幀 | 改動前 | 改動後 |
|---|---|---|
| 帶路線 | 137 格／164 句／5 段 | **314 格／253 句／8 段**（重返巫師塔 `0x31..0x33`）|
| 無路線（套件預設）| 94 格／92 句 | **309 格／171 句**／4 段 |
| 最後一次進展 | 第 1,437 幀 | 第 9,984 幀 |
| 落回原文 | 0 | 0 |

⚠ spec 1197 曾實測「輪流選會自己切斷路線」而選擇預設第一項——那個結論仍然
成立：環繞**不是**輪流選，預設仍是第一項，只有同一個選單反覆出現才逐項換，
換完一圈回到第一項。

## 下一個瓶頸（換位置了）

第 9,984 幀之後的迴圈在 `ECL2/0x03`（下水道）：「牆面太滑…還有人要試嗎？」
的爬牆事件——六個預設戰士**沒有盜賊**，爬牆永遠失敗，「是｜否」與選人選單
交替。這不是選單策略問題：原作這一面牆本來就是盜賊技能的閘，而重放的隊伍
組成是六個戰士。要嘛讓重放的預設隊伍帶一名盜賊，要嘛把「同一格的同一個事件
連續 N 次沒有進展」列為放手條件。

## 明確不宣稱

- 沒有宣稱 314 格是新的上限——每次改走法都要重量（`keyDrivenDefaultFrames`
  上面那張表）。
- 沒有宣稱環繞在所有選單上都優於夾住；量的是這兩條路徑的段序列與格數。
