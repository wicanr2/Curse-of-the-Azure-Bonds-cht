# 1124 — 傷害／治療類法術的骰子：分派表 → handler → 兩支擲骰入口

- 證據等級：`exact`（法術分派表由 `overlay-22` 的初始化函式逐條讀出；
  骰子由 `scripts/spell_damage_table.py` 從各 handler 本體機械抽出）
- 對應工作項：`ENG-09` 的「`+0Ah = 0` 的傷害類」
- 上游 spec 1071（分派表的 PC-98 對側）、spec 731（施法收尾）、spec 1111（屬性表）

## 骰子為什麼不在屬性表裡

屬性表（spec 1111）每支法術 16 bytes，裡面有持續時間係數、豁免類別、目標形狀，
但**沒有傷害**。`+0Ah`（效果碼）為 0 的那 31 支就是靠 handler 自己算的那一批。

handler 的位址在**法術分派表**：`DS:72A0h` 起 101 筆遠指標，由 `overlay-22` 的
一支初始化函式一條一條填進去（PC-98 對側是 `DS:0A38Ch`，spec 1071）。

```
段固定 011Ah  →  ＋7Bh 段落 ＝ overlay-22 的控制記錄
位移           →  (位移 − 20h) ÷ 5 ＝ entry 編號
```

101 筆指到 **81 個相異 handler**——20 筆是共用的（解除魔法的牧師版與法師版指到
同一支，移除詛咒也是）。

## 兩支擲骰入口，各兩個參數

```pascal
<overlay-23 entry#9> (骰數, 面數)   { 擲 骰數 次 1..面數 並加總；骰數 ≤ 0 回 0 }
<overlay-23 entry#10>(骰數, 面數)   { 把骰數記進 DS:6F98h，再轉呼 entry#9 }
```

兩支都 `retf 4`。**用途不是「治療 vs 傷害」**：`entry#9` 既被治療輕傷用，也被
解除魔法拿去擲 `1d100`。所以表裡的形狀欄位照 entry 編號記，用途要看該支法術自己。

收尾也是兩支：

```pascal
sub_F06(法術編號, 等級覆寫, ?, 傷害, 傷害屬性旗標, 訊息)   { 傷害 }
<overlay-23 entry#22>(…, 治療量, 0)                        { 治療 }
```

`sub_F06` 的框架自己證實了這個順序：`[bp+0Ah]` 是屬性旗標（`mov ds:6F95h, al`）、
`[bp+0Ch]` 是傷害（**為 0 就把旗標一起歸零**）、`[bp+10h]` 是等級覆寫（為 0 時
改呼 `<overlay-24 entry#44>(法術編號)` 自己算）、`[bp+12h]` 是法術編號。

## ★ 數字要從收尾的呼叫點取，不是從擲骰取

只看擲骰會在三個地方出錯：

| 法術 | 只看擲骰會得到 | 實際 |
|---|---|---|
| 燃燒之手 | 整支漏掉（沒擲骰）| 傷害 ＝ 施法者等級 |
| 治療中傷／重傷 | `2d8`／`3d8` | `2d8 ＋ 1`／`3d8 ＋ 3` |
| 電擊之握 | `1d8` | `1d8 ＋ 施法者等級` |

偏低的那幾支特別危險：`2d8` 是個看起來合理的數字，錯了也不會有人覺得奇怪。

## ★ 骰數不一定是立即數

`entry#9` 對骰數 0 的處理是**直接回 0**（`cmp [bp+8],0 / jbe 出口`），所以
「骰數 0 ＝ 用施法者等級」這個讀法在任何真的傳 0 的地方都是錯的。真相是那幾支
的骰數是**算出來的**：

| 法術 | handler | 算式 |
|---|---|---|
| 魔法飛彈 | `ov22@21C7h` | `n := (等級＋1) div 2`；`n d4 ＋ n` |
| 火球 | `ov22@370Eh` | `等級 d6`（旗標 `09h`）|
| 閃電 | `ov22@3C98h` | `等級 d6` |
| 寒冰錐 | `ov22@54EBh` | `等級 d4 ＋ 等級`（旗標 `0Ah`）|
| 電擊之握 | `ov22@2260h` | `1d8 ＋ 等級`（旗標 `0Ch`）|
| 燃燒之手 | `ov22@1E7Ch` | `等級`（不擲骰，旗標 `09h`）|

抽取端因此把骰數與加值分成「立即數」與「算出來的」兩類，後者一律標 `computed`
**不給數字**；算式由人讀完寫在 `internal/combat/spell_formula.go`，每一支附位址。

## ★ 不能只取第一次擲骰

火球的 handler 裡擲了兩次（`1d3` 與 `等級d6`），第一次是另一支法術共用這個
handler 時的分支（`cmp ds:6F97h, 40h`）。只取第一次會產生「看起來有答案但是錯的」
那一列——那比空白更糟。

## 量到的

| 類別 | 支數 |
|---|---:|
| `+0Ah = 0` 且不是占位 | 31 |
| 三個數字都是立即數（直接可用）| 8 |
| 有一段是算出來的（`computed`）| 5 |
| 不擲骰的固定值（`flat`）| 3 |
| 收尾不是那兩支（`other_finish`）| 15 |

同族法術的差別確實只有骰數與加值：治療輕／中／重傷 ＝ `1d8`／`2d8 ＋ 1`／
`3d8 ＋ 3`，致傷那三支一樣。火焰打擊 `6d8`、冰風暴 `3d10`——都與 AD&D 的數字
對得上，加值那兩個也是。

`other_finish` 那 15 支不是抽不出來，是**收尾另有出路**：屠殺活物走豁免即死、
火焰護盾是被打才反擊、解除魔法是 `1d100` 對抗。它們的骰子欄位照樣記著，
但**不可以**當成傷害套上去。

完整逐支見 [`spell-damage-table.md`](../audit/spell-damage-table.md)。

## remake 這一側

- `gamepack/rules/spell-damage.json`（由腳本產生）＋ `gamepack.SpellDamage()`。
- `internal/combat/spell_formula.go`：骰數含施法者等級的那幾支，逐支讀完的算式。
  `combat.SpellDamageRoll(法術編號, 等級)` 先查算式、再退回機械表，兩邊都沒有就
  回 false——**不從殘值湊數字**。
- `combat.CastHealingDice`／`CastDamageDice`／`CastAreaDamageDice` 都吃
  `SpellDamageFormula`（骰數、面數、加值），所以加值漏不掉。
- game pack 的 behavior `heal_dice`／`damage_dice`／`damage_dice_area` 走同一條路。

## 逐支讀完的那幾支

有共通形狀的都走資料驅動；剩下這幾支形狀各自不同，handler 逐條讀完之後
單獨接（`internal/combat/spell_special.go`）。

- **屠殺活物**（`entry#89`）：豁免類別 4 沒過就**直接死**，過了改吃 `2d8 ＋ 1`
  並把傷害屬性旗標改成 `8`。★ 表裡抽到的那個 `2d8` 是**豁免成功**那一支——
  接成「單純 2d8 傷害」會少掉主要效果。
- **治療失明**（`entry#54`）：查目標身上有沒有效果 `21h`，有就移除。
- **混亂術**（效果碼 `23h`）：處理常式就是士氣崩潰的四段表（spec 831），
  所以它不需要新規則，見 `Battle.CastAreaMoraleBreak`。
