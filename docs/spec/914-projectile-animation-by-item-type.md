# 914 — 依物品類別選飛行動畫與音效

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側差異逐條列出）
- 作法見 spec 783

## `overlay-13:02BFBh`（DOS 216 條）↔ `overlay-13:02A72h`（PC-98 223 條）

`retf 0Ch` ＝ 6 個 word：`(物品, 起點座標, 迄點座標)` 兩組。

```pascal
<far 0713h:0020h>(word[25C3h＋1]);                    { 音效 }
r := <本模組 29A2h>(起y, 起x, 迄y, 迄x);
步 := 1;   延遲 := 0Ah;   基 := 0Dh;

類 := 物品^[2Eh];

if 類 in [09h, 15h, 64h, 1Ch, 1Fh, 49h] then begin     { ① 有方向的飛行物 }
    if odd(r) then begin
        if r in [3, 5] then <far 1562h+1>((r = 5) ? 1 : 0, 0, 1, 基 ＋ 1)
        else                <far 1562h+1>((r = 7) ? 1 : 0, 0, 0, 基 ＋ 1);
    end else
        <far 1562h+1>(0, 0, r div 4, 基 ＋ (r mod 4));
    <far 0713h:0020h>(word[25C3h＋1]);
end
else if 類 in [02h, 07h, 14h] then begin               { ② }
    <far 1567h+1>(基 ＋ 3);   步 := 4;   延遲 := 32h;
    <far 0713h:0020h>(word[25BDh＋1]);
end
else if 類 in [55h, 56h] then begin                    { ③ }
    <far 1567h+1>(基 ＋ 4);   步 := 4;   延遲 := 32h;
    <far 0713h:0020h>(word[25B7h＋1]);
end
else if 類 in [65h, 2Fh, 62h] then begin               { ④ }
    inc(基);
    <far 1562h+1>(0, 0, 0, 基 ＋ 7);
    <far 1562h+1>(0, 1, 1, 基 ＋ 7);
    步 := 2;   延遲 := 0Ah;
    <far 0713h:0020h>(word[25B7h＋1]);
end
else begin                                             { ⑤ 其餘 }
    <far 1562h+1>(0, 0, 0, 基 ＋ 7);
    <far 1562h+1>(0, 1, 1, 基 ＋ 7);
    步 := 2;   延遲 := 14h;
    <far 0713h:0020h>(word[25BDh＋1]);
end;

<far 156Dh>(延遲, 步, <192Dh+3>(起), <192Ah+1>(起),
            <192Dh+3>(迄), <192Ah+1>(迄));
```

## 五組類別碼

| 組 | 類別碼 | 動畫 |
|---|---|---|
| ① | `09h` `15h` `64h` `1Ch` `1Fh` `49h` | 依 `r`（方向）選八種圖磚之一 |
| ② | `02h` `07h` `14h` | 單一圖磚 `基 ＋ 3`，步 4、延遲 `32h` |
| ③ | `55h` `56h` | 單一圖磚 `基 ＋ 4`，步 4、延遲 `32h` |
| ④ | `65h` `2Fh` `62h` | 兩格輪播，步 2、延遲 `0Ah` |
| ⑤ | 其餘 | 兩格輪播，步 2、延遲 `14h` |

`1Ch` 與 `49h` 又出現在①（spec 901 的死碼分支、spec 907 的專屬裝備欄
都是這一對），但這裡它們與另外四個碼同一組。

`far 156Dh` 就是 spec 886 用來「把游標從舊格移到新格」的同一支——
**這裡拿來畫飛行物從起點到迄點的軌跡**，`步` 與 `延遲` 控制節奏。

## ⚠ PC-98 用遊戲速度取代常數延遲

| | 延遲 |
|---|---|
| DOS | 常數 `0Ah` / `32h` / `14h` |
| PC-98 | **`DS:7F16h`（＝ `DS:4FA9h` 遊戲速度）× 5** 或 **× 2** |

這是 `DS:4FA9h` 的**第四個消費端**，而且與 spec 895 一樣是
**DOS 用常數、PC-98 才看速度值**的形態：

| 出處 | 用法 | DOS 看不看速度 |
|---|---|---|
| spec 881 | 每格延遲 × (速度 ＋ 3) | 看 |
| spec 890 | 動畫重播 速度 ＋ 1 次 | 看 |
| spec 895 | 延遲值本身 | **不看**（固定 `0Fh`） |
| **本支** | 延遲值本身（× 5 或 × 2） | **不看**（常數） |

所以 DOS 版的飛行動畫速度是固定的，PC-98 版會跟著設定變。

## ⚠ DOS 有一個死變數

DOS 在開頭做 `var_6 := 遠指標(DS:75E0h)^[11h]`，之後**整支都沒有再讀**。
PC-98 直接把這一步拿掉，改成從參數取類別碼。
**兩平台一致地不使用那個值**，所以是 DOS 留下來的殘骸。

## 明確不宣稱

- 沒有宣稱五組類別碼各是哪些物品。
- 沒有宣稱 `本模組 29A2h` 回的 `r` 是不是方向（形狀上是，`div 4`／`mod 4`
  與 `odd` 的用法像是把八方向拆成兩軸）。
- 沒有宣稱 `far 1562h+1`／`1567h+1` 的四個參數。
- 沒有宣稱三個音效編號 `25B7h`／`25BDh`／`25C3h` 各是什麼聲音。
