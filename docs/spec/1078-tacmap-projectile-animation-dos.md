# 1078 — DOS 戰術地圖彈道動畫：沿 Bresenham 逐格畫，飛出視窗就自動捲動再重跑

- 證據等級：`exact`（DOS 側 586 條逐條讀完，無匯出破洞）
- 作法見 spec 783

## `dos overlay-24:01AF7h`（`retf 0Ch`）

原本待解讀。範圍 `1AF7h`..`21DAh`。這是**投射物／法術彈道在戰術地圖上飛過去**
的動畫。

六個 word 運算元（IDA 標成 `arg_2`..`arg_C`，由高到低 ＝ 由先到後宣告）：

| IDA 標籤 | 用途 |
|---|---|
| `arg_C` | **起點 x**（地圖格） |
| `arg_A` | **起點 y** |
| `arg_8` | **終點 x** |
| `arg_6` | **終點 y** |
| `arg_4` | 動畫**幀數**（幀號到這個值就繞回 0） |
| `arg_2` | 每格**延遲**（0 ＝ 不畫也不等） |

⚠ IDA 的 `arg_N` 基準與 `retf 0Ch` 差 2 bytes（`arg_C` 落在 `bp+12h`，
而 `retf 0Ch` 只收到 `bp+11h`）。本規格**只用六個運算元的相對順序**，
不宣稱它們的絕對堆疊位移，也不宣稱那 2 bytes 的差是 IDA 的框架基準
還是呼叫端多推一個 word。

## 一、先把整條路徑算出來

```pascal
FillChar(方向緩衝, 94h, 8);          { 148 格，預設方向碼 8 }
FillChar(座標組,   18h, 0);
座標組 := (起點x × 3, 起點y × 3, 終點x × 3, 終點y × 3);

<overlay-31 entry#2>(座標組);                    { 直線初始 }
repeat
    完成 := <overlay-31 entry#3>(座標組);        { 取下一步 }
    方向緩衝[n] := 座標組 的第 2 個 byte;        { ★ 方向碼 }
    inc n;
until 完成;
步數 := n − 2;
if (步數 < 2) and (n < 2) then exit;
```

★ 座標一律**乘 3** ⇒ 一格 ＝ 3 個像素單位，整條線用 spec 918 那套
`overlay-31` 的直線走訪算出**逐步的方向碼**存進 148 bytes 的緩衝。
★ 緩衝預填 `8`，所以沒走到的格子是方向 8。

## 二、決定要不要跟著捲動視窗

```pascal
Δx := 終點x − 起點x;   Δy := 終點y − 起點y;
起點可見 := <overlay-32 entry#11>(起點x − 視窗x, 起點y − 視窗y);
終點可見 := <overlay-32 entry#11>(終點x − 視窗x, 終點y − 視窗y);

if 起點可見 and 終點可見 then begin
    同框 := 1;
    中心 := (終點x, 終點y);                       { 走到終點就結束 }
end else if |Δx| ≤ 6 and |Δy| ≤ 6 then begin
    同框 := 1;
    中心 := (起點 ＋ Δ div 2);                    { ★ 取中點 }
end else begin
    同框 := 0;
    中心 := (視窗x ＋ 3, 視窗y ＋ 3);              { 視窗正中央 }
end;
<overlay-32 entry#13>(中心x, 中心y, 0FFh, 8);      { 捲動／置中 }
```

★ `DS:6E92h`^ 的 `+2`／`+3` 是**目前視窗左上角的地圖座標**。
★ **`6` 是視窗的格數上限**：底下的邊界檢查用 `0`..`12h`（＝ 18 ＝ 6 × 3）
⇒ **戰術地圖視窗是 7 × 7 格**。

## ★★★ 三、主迴圈：逐格畫、逐格擦

```pascal
repeat                                            { ← 21C8h 會跳回這裡 }
    畫面 := ((起點x − 視窗x) × 3 ＋ 誤差x, (起點y − 視窗y) × 3 ＋ 誤差y);
    i := 0;  越界 := false;
    repeat
        dx := DS:2694h[方向緩衝[i]];              { ★ 方向 → Δx }
        dy := DS:269Dh[方向緩衝[i]];              { ★ 方向 → Δy }
        畫面x := 畫面x ＋ dx;   畫面y := 畫面y ＋ dy;

        if (延遲 > 0) or ((畫面x mod 3 <> 0) and (畫面y mod 3 <> 0)) then begin
            <0297:09E4h>(目的 DS:4FE8h, 圖 DS:75E0h, 5, 幀, 畫面x, 畫面y);
            <0297:1316h>();                       { 送上畫面 }
            <09AB:029Eh>(延遲);                   { 等 }
            <0297:09E4h>(目的 DS:4FE8h, 底圖 DS:4FECh, 0, 0, 畫面x, 畫面y);  { 擦掉 }
            inc 幀;  if 幀 >= 幀數 then 幀 := 0;
        end;
        inc i;
        if (畫面x < 0) or (畫面x > 12h) or (畫面y < 0) or (畫面y > 12h) then
            越界 := true;

        if not 越界 and (i < 步數) then begin
            誤差x := 誤差x ＋ dx;  誤差y := 誤差y ＋ dy;
            if |誤差x| = 3 then begin 起點x := 起點x ＋ Sign(誤差x); … 誤差x := 0 end;
            if |誤差y| = 3 then begin 起點y := 起點y ＋ Sign(誤差y); … 誤差y := 0 end;
        end;
    until 越界 or (i >= 步數);
    …
until 同框 <> 0;
```

★ `DS:2694h` 與 `DS:269Dh` 是**方向碼 → Δx／Δy** 的兩張 9 筆表（`cbw`，有號）。
★ `overlay-31 entry#1` 是 `Sign`（把誤差的正負轉成 ±1），累到 ±3 就進位成一整格。
★ 畫／擦是同一支 `0297:09E4h`，差別在圖來源（`DS:75E0h` 的精靈 vs `DS:4FECh` 的底圖）
與參數 `5`／`0`。
★ **`延遲 = 0` 時只畫「不落在格心」的中間點**（`mod 3 <> 0`）
——形狀上是快速模式只畫格與格之間的過場。

## ★★★ 四、飛出視窗就捲動再重跑

越界時走 `1ECAh` 那一整段：**從剛才停下的地方倒著走回去**
（`dec i`、`dx`／`dy` 取 `neg`），一路把畫面座標推回視窗內，
同時把新的視窗左上角夾在地圖範圍內：

```pascal
if x ＋ 3 > 31h then 位移x := x − 31h                 { 地圖右界 49 }
else if x < 3   then 位移x := 3 − x;
if y ＋ 3 > 18h then 位移y := y − 18h                 { 地圖下界 24 }
else if y < 3   then 位移y := 3 − y;
<overlay-32 entry#13>(x ＋ 位移x, y ＋ 位移y, 0FFh, 8);   { 捲動 }
```

然後回到 `21C8h`：**`同框 = 0` 就整條路徑重畫一次**（`jmp 1CEAh`）。

> ★★★ **彈道飛出可視範圍時，原作會把戰術地圖視窗捲過去、再從頭把整條線
> 重畫一遍**——不是接著畫下去。
> ⇒ 玩家看到的是「畫面一跳，箭再飛一次」。remake 要照抄這個行為，
> 否則長距離射擊的節奏會不一樣。
> ★ 地圖邊界是 **x ≤ `31h` ＝ 49、y ≤ `18h` ＝ 24**，視窗中心固定留 3 格邊。

## 五、終點

```pascal
同框 := 1;
if not <overlay-32 entry#11>(終點x − 視窗x, 終點y − 視窗y) then
    <overlay-32 entry#13>(終點x, 終點y, 3, 8);       { ★ 第 3 個參數 3，不是 0FFh }
畫面 := ((終點x − 視窗x) × 3, (終點y − 視窗y) × 3);
<0297:09E4h>(… 精靈 …, 5, 幀, 畫面x, 畫面y);
if 延遲 > 0 then begin
    <0297:1316h>();  <09AB:029Eh>(延遲);
    <0297:09E4h>(… 底圖 …, 0, 0, 畫面x, 畫面y);      { 擦掉 }
end;
<0297:1316h>();                                      { 收尾再送一次畫面 }
```

★ **延遲為 0 時終點的精靈不會被擦掉**——留在畫面上。

## 明確不宣稱

- 沒有宣稱 `DS:2694h`／`DS:269Dh` 兩張表的實際內容（只知道是方向 → Δx／Δy）。
- 沒有宣稱 `overlay-32 entry#11`（可見／可通行判定）與
  `entry#13`（捲動／置中）的完整介面，也沒有宣稱 `entry#13` 的第 3 個參數
  `0FFh` 與 `3` 差在哪。
- 沒有宣稱 `0297:09E4h` 八個參數各自的角色（只從兩次呼叫的差異推出
  「圖來源 ＋ 兩個模式參數 ＋ 座標」）。
- 沒有宣稱 `DS:75E0h`／`DS:4FE8h`／`DS:4FECh` 三個緩衝各是什麼。
- 沒有宣稱方向緩衝預填 `8` 代表哪個方向。
- 沒有宣稱「起點與終點都可見」那條路為什麼把中心設成終點
  （其餘兩條路設成中點或視窗中央）。
- 沒有宣稱 PC-98 的對應函式是哪一支。
