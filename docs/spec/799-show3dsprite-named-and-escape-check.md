# 799 — 從錯誤訊息拿回真名 `Show3DSprite`、逃跑判定

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側的運算元差異已逐條列出）
- 作法見 spec 783

## `overlay-29:0754h`（entry#8，74 條，差異 21 條）— `Show3DSprite`

| | DOS | PC-98 |
|---|---|---|
| 錯誤訊息 | `'Illegal range in Show3DSprite.'`（30） | **一字未改**（30） |

`retf 6`。依宣告順序：`Show3DSprite(索引: byte; 表: 遠指標)`。

```pascal
Move(表^, 暫存, 42h);                          { 66 bytes 整份抄進區域 }
if (索引 < 1) or (索引 > 3) then begin         { 無號 }
    <0297h:0107h>();
    <0A54h:173Bh>(0, @'Illegal range in Show3DSprite.', @DS:8DB2h);
    <0A54h:1673h>();
    <far 06EAh:0000h>();                       { 不返回 }
end;
p := 暫存[索引];                               { 每筆 8 bytes，取其中的遠指標 }
if p <> NIL then begin
    <0297h:09E4h>(遠指標@DS:4FE8h, p, 1, 0, p^[6] + 2, p^[4] + 2);
    <0297h:1316h>();
end;
```

### 這是本專案第一個從錯誤訊息拿回來的函式名

`'Illegal range in Show3DSprite.'` 是原始碼寫死的除錯字串，**PC-98 版一字未改**。
兩件事同時成立：

- 這一支的真名是 **`Show3DSprite`**，索引的合法範圍是 **1..3**。
- **內部錯誤訊息不翻譯**。配合 spec 795 的資源名（`DungCom` / `WildCom` /
  `RandCom` 也原封不動），中文化的取捨判準再多一條：**PC-98 版沒改的字串就別碰**。

### 越界不是回傳錯誤，是中止

`0A54h:173Bh` ＋ `0A54h:1673h` ＋ `far 06EAh:0000h` 是 Turbo Pascal 的
runtime error ＋ halt 路徑，**不會回到呼叫端**。所以 remake 若把索引範圍放寬，
行為會與原版分岔。

### 座標各加 2

`es:[di+4] + 3 − 1` 與 `es:[di+6] + 3 − 1` ——編譯器把 `+3` 和 `−1` 分開發，
實際是 **`+2`**。`0297h:09E4h` 就是 spec 785 的 `overlay-29:000Ch` 用的同一支
繪圖程序，那裡傳的是 `參數 − 1`；本支傳的是 `精靈^[6] + 2` 與 `精靈^[4] + 2`。

`0297h:09E4h` 的前兩個參數固定是「目的 ＝ `DS:4FE8h` 的遠指標」與「來源 ＝ 精靈
遠指標」。

## `overlay-13:0D1Ch`（entry#7，74 條，差異 12 條）— 逃跑成不成功

| | DOS | PC-98 |
|---|---|---|
| 成功 | `'Got Away'`（8，無句點） | `'は逃げきった。'`（14 bytes，有句點） |
| 失敗 | `'Escape is blocked'`（17，無句點） | `'逃げられなかった'`（16 bytes） |

```pascal
逃掉 := 0;
if <overlay-24 entry#32>(0FFh, 角色) = 0 then      { 沒有任何戰鬥員貼著 }
    逃掉 := 1
else begin
    半 := 有號(<本模組 0124h>(角色)) div 2;         { 我的移動率，格 }
    v  := <本模組 2EACh>(角色);                     { 對面隊伍中最快的移動率 }
    if v < 半 then 逃掉 := 1                       { 無號比較；敵人全都比我慢 }
    else if v = 半 then
        if <overlay-23 entry#9>(2, 1) = 1 then 逃掉 := 1;   { 1d2 }
end;
if 逃掉 <> 0 then
    <overlay-23 entry#12>(角色, 3, 名字 ＋ 'Got Away')
else
    <overlay-24 entry#19>('Escape is blocked');
結果 := <overlay-24 entry#34>(角色);
```

外呼的名字由 `cmd/far-call-map` 解出（spec 1112）。原本寫成 `<far 1590h>`
那一類的標籤是 IDA 把 overlay 從位址 0 載入之後的誤解，不是位址。

`retf 4` ＝ **一個角色遠指標**，回傳 `al`（**注意回傳的不是「逃沒逃掉」，而是
最後那個 `159Ah` 的結果**）。

- `0124h` / `2EACh` 是既有的移動率換算對（前者把速率乘 2 成半格單位、後者除回
  去）。這裡取 `0124h` 結果的一半當門檻，拿 `2EACh` 的結果去比。
  `2EACh` 走戰鬥員鏈時的條件是「隊號 ＝ `overlay-24 entry#30`(角色)」，
  而那一支回的是**對面**那一隊（spec 1112）⇒ **比的是我的速度對敵方最快的速度**。
- **剛好相等時再擲一次** `145Ah+3(2, 1)`，回 1 才算逃掉——所以平手偏向失敗。
- **只有成功那一句前面接名字**（`146Bh+1` 多收一個角色遠指標與 `3`）；失敗那句
  由 `154Ch+3` 單獨顯示。PC-98 兩句都照這個結構翻，成功句以 `は` 開頭。

### 中文化：兩句的標點不一致

DOS 兩句都**沒有**句點；PC-98 成功句補了 `。`、失敗句沒有。這已是本專案第三次
看到 PC-98 自行調整標點（spec 794 的 `'Attack Ally: '`、spec 797 的
`'has no spells memorized'`）——**標點不是原文的一部分，中文版依語感決定即可。**

## 明確不宣稱

- 沒有宣稱那 66 bytes 的表裡每筆 8 bytes 的其他欄位是什麼；本支只取其中的遠指標。
- 沒有宣稱精靈記錄 `+4` / `+6` 是寬高。
- 沒有宣稱 `overlay-24 entry#34`（回傳值的來源）算什麼。
- 沒有宣稱 `overlay-24 entry#32` 的第一個參數 `0FFh` 與 `1`（spec 817／833 用的值）
  差在哪——只確定它把符合條件的戰鬥員編號填進 `DS:758Eh` 並回筆數。
