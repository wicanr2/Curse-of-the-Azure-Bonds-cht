# 1131 — 第一人稱牆面的第 0 段符號與洋紅透明鍵

- 證據等級：`exact`（`Put8x8Symbol` 的五段分界由 spec 781 逐條讀出；
  `sub_448` 的「非零就畫」由 spec 780 讀出；45 項的資源與洋紅的用法由
  `cmd/symbol-export` 從遊戲映像直接匯出比對）
- 上游 spec 781（`Put8x8Symbol`）、spec 780（`sub_448`）、spec 1006（十個牆位）、
  spec 161（WALLDEF 的全域位移）
- 起點：spec 1130 收尾時留下的「牆磚選圖還沒比」

## 症狀

第一人稱走廊看起來像**幾根分離的柱子**，牆面之間有大片黑色，牆角沒有收邊，
天空與牆的交界是鋸齒。量下去，每個牆位實際畫出來的磚遠少於它的格數：

| 牆位 | 格數 | 實際畫出 |
|---|---:|---:|
| 深度 0 正面（7×8）| 56 | 7 或 10 |
| 深度 0 左（2×11）| 22 | 5 |
| 深度 0 右（2×11）| 22 | 2 或 16 |
| 深度 1 正面（3×4）| 12 | 2 或 3 |

## 一、符號編號分五段，先前只載了中間三段

`Put8x8Symbol`（spec 781）把符號編號切成五段，各有自己的資源指標：

| 段 | 編號 | 來源 |
|---:|---|---|
| 0 | `1..45` | **全遊戲共用一份**（先前完全沒載）|
| 1 | `46..115` | `LOAD PIECES` 選到的第一個 8X8D 區塊 |
| 2 | `116..185` | 第二個 |
| 3 | `186..255` | 第三個 |
| 4 | `256..295` | 本輪沒用到 |

`WALLDEF` 的一筆 156 bytes 裡，低編號密集出現在**每個牆位的第一列與斜邊**。
以提爾佛頓的第二組為例（`WALLDEF2` 的一筆，各牆位攤開）：

```
牆位6 深度0正面 7欄×8列        牆位7 深度0左 2欄×11列
  1   1   1   1   1   1   1      18   1
123 117 119 117 119 117 122     118  18
123 118 117 118 117 118 122     116 118
…（其餘六列都是 116..123）      …
                                118  19
                                 19   3
```

`1` 鋪滿每個牆位的第一列，`3`／`17`／`18`／`19`／`20` 沿著側牆的斜邊排列
——**那就是天空格與透視收邊**。它們全都落在第 0 段，先前的 `item = 編號 −
該段基準` 會算出負數而整格被丟掉，於是牆頂沒有天空、牆角沒有斜邊。

★ `sub_448`（spec 780）寫得很清楚：`if v > 0 then 畫(…)`——**非零就畫**，
沒有「低於某個值就跳過」這回事。低編號不是結構碼，是另一段的符號編號。

## 二、第 0 段就是 `8X8D1.DAX` 的 `0CBh`

`cmd/symbol-export` 把六個 `8X8D*.DAX` 的每個區塊逐項匯出：

| 檔案 | 區塊 | 項數 |
|---|---|---:|
| `8X8D1.DAX` | `0CAh` | 40（AREA 地圖符號，game pack 早已宣告）|
| `8X8D1.DAX` | **`0CBh`** | **45** |
| `8X8D2..6.DAX` | 各 4..5 個區塊 | 全部 70 |

**全部六個檔案裡只有一個 45 項的區塊**，而第 0 段的編號範圍正好是 45 個。
它的內容也對得上：整片都是三角形收邊磚與牆面碎片，第 0 項是一整格空白
——那是 `1` 這個「天空格」。

⚠ `8X8D1.DAX` 不是「第一區的檔案」：它只有 `0CAh`／`0CBh` 兩個可解析區塊，
兩個都是**全遊戲共用**的符號資源（一個給 AREA 地圖，一個給第一人稱）。
拿「檔名數字＝章節」去推它屬於哪一區會推錯。

## 三、洋紅是透明鍵，不是顏色

不遮罩地匯出 `0CBh` 之後一眼就看得出來：**第 0 項是一整格洋紅**（EGA index 13），
其餘洋紅在斜角磚裡切出乾淨的三角形。

- 一整格洋紅的「天空格」如果是顏色，牆頂上方會是一片桃紅色。
- 斜角磚的洋紅半邊如果是顏色，牆角會出現桃紅三角形——先前畫面上那幾塊
  桃紅三角就是這麼來的。

所以牆面符號要以 **index 13 為透明鍵**解碼。⚠ 遮罩要在**索引**上做而不是比對
RGB：同一個 EGA 顏色在別處是合法顏色，只有這批素材的 13 號索引是鍵。

## remake 這一側

- 第 0 段的檔案與區塊宣告在 `gamepack/rules/wall-symbols.json`（遊戲這一側，
  不進共用 engine 的 pack schema——`kind` 是列舉，塞不進去，而這也不是
  引擎機制，是這一款的資料位置）。
- `maskWallSymbols` 在 `LOAD PIECES` 之後把三個區塊的 index 13 換成透明索引。
- `sharedWallGroupStamps` 用一份**影子 `PieceSet`**（符號集基準改 0、假 Picture
  的項目數放到 255）再跑一次引擎的版面展開，取回每一格的**原始編號**，
  只挑編號小於 `46` 的補畫。★ 這樣十個牆位的欄／列／位移表**只有引擎那一份**，
  遊戲這一側不必再抄一份。

修好之後四個朝向都是完整的走廊：木板牆、石牆、逐格收斂的側牆、鋪滿的地板，
西向還看得到拱門。README 的第一人稱截圖因此改回**正常流程的朝向**，不再需要
`-dungeon-facing` 覆寫。
