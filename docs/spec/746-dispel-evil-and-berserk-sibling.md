# 第七百四十六輪：Dispel Evil，與另一支會還原陣營的狂暴

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：DOS `overlay-12` 的 `2D7Dh`、`2B3Eh`（兩支都沒有位元組缺口）。

## `2D7Dh`：Dispel Evil

```text
p := 角色^[18Dh]^[0Ah]
DS:6FA3h := p

if (p^[14Bh] and 1) <> 0 且 <overlay-23 entry#8>(p, 4, 0) = 0 then
    <overlay-23 entry#1>(p, 8, '<名字> is dispelled'（CS:2D5Ch）)
    <overlay-23 entry#3>(DS:6506h, 4, 0)              ← ⚠ 解除的是**施法者**身上的
    <overlay-23 entry#3>(DS:6506h, 91h, 0)
else
    <overlay-24 entry#20>(p, '<名字> resists dispel evil'（CS:2D69h）, 0Ah, 1)
```

`+14Bh` 的 bit 0 是目標的「邪惡」旗標——spec 738 的 `2AD6h` 用的是同一個欄位的
**bit 3**（傷害加成）。同一個 byte 至少兩個位元各有用途。

**成功時解除的兩個效果掛在施法者身上，不是目標身上。** `entry#3` 的第一個參數是
`DS:6506h`。這是「用完就失效」的自我解除，很容易在改寫時誤寫成對目標操作。

兩條失敗路徑（目標不邪惡、或豁免成功）**共用同一句訊息** `resists dispel evil`。
所以玩家看到這句話時，分不出是「對方不是邪惡的」還是「擋下來了」。

## `2B3Eh`：狂暴，但這一支會還原陣營

流程和 spec 743 的 `1809h` 幾乎一樣：立 `+198h`、依三態設 `+0F7h`、清掉鎖定目標、
用 `overlay-31 entry#6` 重新選一個、然後

```text
角色^[197h] := 新目標^[197h] xor 1
```

差別在**解除路徑**：

```text
1809h（spec 743）：角色^[197h] := 0                  ← 寫死
2B3Eh（本輪）：    角色^[197h] := 節點^[3]           ← 從節點取回
```

`2B3Eh` 把原陣營整個 byte 存在 `節點^[3]`，解除時原樣寫回。**姊妹支做對了，
`1809h` 沒有。** 這讓 spec 743 標記的「解除後陣營一律歸 0」從「可能是設計」
變成「很可能是 `1809h` 的缺陷」——不過 `1809h` 的套用路徑裡我沒有看到它把原陣營
存進任何地方，所以它**根本沒有可以還原的來源**，兩件事是一起漏掉的。

`2B3Eh` 的套用路徑同樣沒有看到寫 `節點^[3]` 的動作——那應該是由呼叫端
（`PUTEFFECT` 的某個參數）填的，和 spec 744 的機制一致。

## `節點^[3]` 的第三種用法

| 效果 | 存法 | 取法 |
|---|---|---|
| 操縱屍體（spec 744） | `(陣營 shl 4) + 等級` | `div 16` |
| 魅惑（spec 745） | bit 5 旗標 ＋ bit 6 陣營 | `and 40h` 再 `div 40h` |
| 狂暴（本輪 `2B3Eh`） | **整個 byte ＝ 陣營** | 直接讀 |

三種效果、三種版面。再次確認 `節點^[3]` 不能有統一的結構定義。

## 明確不宣稱

- `+14Bh` 各位元的名稱。
- 效果編號 `4`／`8`／`91h` 代表什麼。
- `2B3Eh` 與 `1809h` 為何要有兩支幾乎相同的狂暴處理程序。
