# 986 — DOS 側的 ECL 讀取路徑（關掉 spec 565 的未宣稱項），與 PC-98 的圖格填入

- 證據等級：`exact`（兩支逐條讀完）
- 作法見 spec 783

## `dos overlay-07:00F3Ah`（128 條，`retf 2`）— ECL 的記憶體讀取

spec 565 讀完 PC-98 的讀取路徑（`overlay-07:0FFCh`）後，
「明確不宣稱」最後一條寫的是

> **DOS 側的讀取路徑**。本輪只讀 PC-98；……讀取端尚未逐條核對。

本支就是那一支。**逐條核對的結果：兩平台完全對稱**，該項可以關閉。

```pascal
bank := <本模組 0735h>(位址);
結果 := 0;
case bank of
 0: 結果 := word[遠指標(DS:4F99h) ＋ 6A00h ＋ 2×位址];
 1: begin
        結果 := <本模組 07F1h>(@算得出來, 位址);
        if 算得出來 = 0 then
            結果 := word[遠指標(DS:4F9Dh) ＋ 800h ＋ 2×位址];
    end;
 2: 結果 := word[遠指標(DS:4FA1h) ＋ 0C00h ＋ 2×位址];
 3: 結果 := byte[遠指標(DS:4FA5h) ＋ 位址 − 8000h];
 4: …（見下）
end;
```

### bank 0–3：位移、寬度、指標三項全對稱

| bank | DOS | PC-98（spec 565） |
|---|---|---|
| 0 | `DS:4F99h`，`+6A00h + 2×addr`，word | `DS:7F05h`，同式 |
| 1 | 先叫 `本模組 07F1h` 算；旗標 0 才讀 `DS:4F9Dh` `+800h + 2×addr` | 先叫 `08BDh`；`DS:7F09h` |
| 2 | `DS:4FA1h`，`+0C00h + 2×addr`，word | `DS:7F0Dh`，同式 |
| 3 | `DS:4FA5h`，`+addr − 8000h`，**byte** | `DS:7F12h`，同式 |

**bank 1「先算、算不出來才讀陣列」的兩段式在 DOS 也一樣**，
計算 routine 是 `dos overlay-07:07F1h`（PC-98 是 `08BDh`）。
spec 565「哪些位址走計算路徑」仍然不宣稱。

### bank 4 的具名特例：DOS 位址對照

```pascal
if 位址 < 0C04Bh then                        { 無號 }
    case 位址 of
      0B1h: 結果 := word[DS:75EEh];
      0FBh: 結果 := word[DS:75EAh];
      0FCh: 結果 := word[DS:75ECh];
      33Dh: 結果 := byte[DS:7211h];           { 零延伸，★ 沒有除以 2 }
      35Fh: { no-op }
    end
else begin
    位址 -= 0C04Bh;
    case 位址 of
      0  : 結果 := 有號(byte[DS:720Fh]);      { cbw }
      1  : 結果 := 有號(byte[DS:7210h]);      { cbw }
      2  : 結果 := byte[DS:7211h] div 2;      { 零延伸後除 2 }
      3  : 結果 := byte[DS:7212h];            { 零延伸 }
      4  : 結果 := byte[DS:7213h];            { 零延伸 }
      0Eh: { no-op }
    end;
end;
```

| ECL 位址 | DOS | PC-98（spec 565） |
|---|---|---|
| `00B1h` | `DS:75EEh` | `DS:0A880h` |
| `00FBh` | `DS:75EAh` | `DS:0A87Ch` |
| `00FCh` | `DS:75ECh` | `DS:0A87Eh` |
| `033Dh` | `DS:7211h` | `DS:0A2ABh` |
| `035Fh` | no-op | no-op |
| `C04Bh` | `DS:720Fh`，符號延伸 | `DS:0A2A9h`，符號延伸 |
| `C04Ch` | `DS:7210h`，符號延伸 | `DS:0A2AAh`，符號延伸 |
| `C04Dh` | `DS:7211h` ÷ 2 | `DS:0A2ABh` ÷ 2 |
| `C04Eh` | `DS:7212h`，零延伸 | `DS:0A2ACh`，零延伸 |
| `C04Fh` | `DS:7213h`，零延伸 | `DS:0A2ADh`，零延伸 |
| `C059h` | no-op | no-op |

**延伸方式（`cbw` vs `xor ah,ah`）、`÷2`、no-op 全部一致。**

### ★ 這獨立驗證了 spec 976 的跨平台對應表

spec 976 從 `overlay-28` 的視野更新推出 `DS:720Fh..7213h` ↔ `DS:0A2A9h..0A2ADh`。
本支從**完全不同的路徑**（ECL 讀取的具名特例）得到同一組對應——
兩個獨立來源互相印證。

### ★ `033Dh` 與 `C04Dh` 是同一個 byte 的兩個 ECL 位址

兩者都讀 `DS:7211h`，但 `033Dh` **不除以 2**、`C04Dh` **除以 2**。
配上 spec 565 的寫入端（寫 `C04Dh` 會存 ×2），可以確定：

- `DS:7211h`（PC-98 `DS:0A2ABh`）**內部存的是方向值的兩倍**。
- ECL 透過 `C04Dh` 看到的是原值，透過 `033Dh` 看到的是兩倍值。

**同一個變數在 ECL 裡有兩種刻度**。remake 若把方向統一存成原值，
`033Dh` 這條路必須自己乘 2，否則所有用 `033Dh` 的腳本都會錯一半。
spec 565「`×2` 只有繪圖端看得到」這句要補上：**`033Dh` 這個 ECL 位址也看得到**。

## `pc98 overlay-24:01B2Fh`（128 條，`retf 0Ah`）＝ DOS `01975h`（spec 983）

把圖庫的一張圖填進動畫 surface 的第 N 格，`(組 arg_8, 編號 arg_6, 格號 arg_4,
要不要轉換 arg_2, 旗標 arg_0)`。

```pascal
每張   := DS:0A872h^[11h];
每平面 := DS:0A872h^[0] × DS:0A872h^[2];        { 高 × 寬 }

if 要不要轉換 <> 0 then begin
    <02A8h:0F5Dh>(18h, 6, 1, 1, @暫存);
    <02A8h:0836h>(暫存, 遠指標[0966Ch ＋ 組×8 ＋ 編號×4]);
    Move(暫存 ＋ 17h,     DS:0A872h ＋ 格號×每張 ＋ 17h, 每張);
    Move(暫存^[13h],       DS:0A872h^[13h] ＋ 格號×每平面, 每平面);
    <02A8h:10D5h>(@暫存);
end
else begin
    Move(原圖 ＋ 17h,     DS:0A872h ＋ 格號×每張 ＋ 17h, 每張);
    Move(原圖^[13h],       DS:0A872h^[13h] ＋ 格號×每平面, 每平面);
end;
```

### ★ `+11h` 與「高 × 寬」的關係定案

DOS（spec 983）**兩次 `Move` 都用 `+11h`**；PC-98 **像素用 `+11h`、遮罩用
`高 × 寬`**。加上 spec 985 讀到 PC-98 的像素是**三個平面連續排列**，
關係就閉合了：

| | 像素資料 | 遮罩 |
|---|---|---|
| PC-98 | `+11h` ＝ **3 × 高 × 寬**（三平面） | `高 × 寬`（單平面） |
| DOS | `+11h` | `+11h`（與像素同大小） |

spec 977 當初只能說「兩台機器圖形平面配置不同，第二塊大小關係不一樣」，
現在可以寫成具體的等式。

### 跨平台位址與差異

| | DOS `01975h` | PC-98 `01B2Fh` |
|---|---|---|
| 動畫 surface | `DS:75E0h` | `DS:0A872h` |
| 圖庫表 | `DS:65D6h` | `DS:0966Ch` |
| 建暫存圖 | `0297h:1C59h(18h, **3**, 1, 1, @暫存)` | `02A8h:0F5Dh(18h, **6**, 1, 1, @暫存)` |
| 轉換複製 | `0297h:0BB5h` | `02A8h:0836h` |
| 釋放 | `0297h:1D19h` | `02A8h:10D5h` |

⚠ 建暫存圖的第二個參數 DOS 是 `3`、PC-98 是 `6`（第一個都是 `18h` ＝ 24）。
**本規格不宣稱那兩個常數是什麼**，但差一倍這件事與「PC-98 三平面、DOS 打包」
的整體差異方向一致。

## 明確不宣稱

- 沒有宣稱 bank 1 的計算 routine（DOS `07F1h`／PC-98 `08BDh`）算什麼
  （同 spec 565）。
- 沒有宣稱 `DS:75EEh`／`75EAh`／`75ECh` 三個唯讀計算值的語意。
- 沒有宣稱 `0297h:1C59h`／`02A8h:0F5Dh` 四個常數的意義。
