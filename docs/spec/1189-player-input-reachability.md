# 1189 — 戰役測試走的每一步，玩家按得出來嗎

- 證據等級：`derived`（`go/ast` 靜態可達性；方向不對稱，見下）
- 上游：spec 1188（把戰役檢查點交給真的前端畫一張）
- 產物：`cmd/player-path-audit`、`docs/audit/player-path.md`
- 狀態：`READY`

## 問題

spec 1188 讓真的前端把戰役的 23 個檢查點各畫了一張，補掉了「畫面那一層沒被跑到」。
剩下的是**輸入那一層**：戰役直接呼叫 `state.X()`，玩家按的是鍵盤。
**前端的 `Update()` 到不了的方法，就沒有任何按鍵組合到得了**——那一段劇情
在測試裡走得通，在遊戲裡走不到。

## 方向不對稱

這是靜態可達性，能證明的只有一個方向：

| 結論 | 這份能不能給 |
|---|---|
| 前端**沒有**那條路 ⇒ 玩家按不出來 | ✅ 硬缺口 |
| 前端**有**那條路 ⇒ 玩家玩得到 | ❌ 那一行可能藏在永遠不成立的條件底下 |

**不要反著讀。**

## 四個分類，全部自動判

| 分類 | 判法 |
|---|---|
| ✅ 按得出來 | 在 `(*app).Update` 的可達閉包裡 |
| — 觀測點 | 未匯出（前端在別的套件叫不到），或只出現在 `Draw()` |
| — 啟動接線 | 只出現在 `main()`（載資料、接目錄、跳段落） |
| — 讀取器差異 | 不改狀態 ⇒ 前端用別的方式讀同一件事 |
| **硬缺口** | 會改狀態，而且哪一條路都到不了 |

三個地方**故意不用手打的表**（這個 session 已經被手打表漏格咬過三次）：

- **別名**自動解：`func (s *State) A() { return s.B() }` 這種單行轉呼叫。
- **會不會改狀態**自動判：body 裡有沒有寫 `s.X = …`，再對 `State` 內部呼叫做不動點。
- **可達集合**沿 `State` 內部呼叫展開。

### 兩次「掃描面比實際窄 ⇒ 假缺口」

做這一支的時候自己踩了兩次，都是同一種錯：

1. 只收 `CallExpr` 的 Fun，漏掉**把方法當成值傳出去**的寫法
   （`a.combatAction(a.state.CombatAct)`）⇒ `CombatAct` 被報成「玩家按不出來」。
2. 可達閉包只走前端的方法圖，**停在第一個 `state.X`**⇒ 玩家紮營走
   `Select()` → `selectCamp()` → `AdvanceGameTimeHours()`，三步之外的被報成到不了。

修完之後硬缺口從 **29 → 28 → 7 → 2 → 1**。⚠ 那些中間數字**每一個看起來都像
真的結論**，而且都附得出理由。**假缺口比假零更難察覺，因為它會給你一份待辦清單。**

## 結果

戰役用到 57 個 `State` 進入點，硬缺口 **1** 個：`NextJournalPage`。

## 找到的缺陷：按 `I` 永遠跳出第一則的圖

`NextJournalPage` 不是漏接，是**前端刻意自己管翻頁**：它用
`a.journalDisplayPage` 走 `journalDisplayPages(...)` 切出來的顯示頁，
從來不推進 `State.JournalPage`。

問題在於**圖的查法沒有跟著改**：

```
翻頁   a.journalDisplayPage          ← 顯示頁
看圖   state.JournalMessageID()      ← 讀 State.JournalPage，永遠是 0
```

⇒ 玩家翻到第 5 則按 `I`，跳出來的是**第 1 則的圖**。而且 `I` 鍵本身的
「有沒有圖」判斷也是拿第 1 則算的，所以連鍵能不能按都是錯的。

★ 兩個頁碼還**不是同一個粒度**：一則手札可能被切成好幾個顯示頁，
所以不能把兩個計數器直接同步。

修法：`journalDisplayPagesWithSources` 在分頁時一併回傳**每個顯示頁來自第幾則**，
前端用它換算，再用新的 `State.JournalMessageIDAt(index)` 查。
`journalDisplayPages` 保留成薄包裝，既有測試不動。

## 這一份不宣稱什麼

- **沒有**宣稱玩得完。可達性不管條件、不管順序、也不管畫面上有沒有提示那個鍵。
  它排除的是「有一段劇情根本沒有按鍵到得了」這一種硬缺口。
- 「會不會改狀態」是**靜態近似**：透過介面或閉包改狀態的看不出來，會被低估成
  讀取器。方向是**寧可少報缺口**，所以這一欄不能拿來宣稱「沒有缺口」。
- **沒有**驗按鍵配置本身（哪個鍵對應哪個動作）、也沒有驗連續操作的流程。
