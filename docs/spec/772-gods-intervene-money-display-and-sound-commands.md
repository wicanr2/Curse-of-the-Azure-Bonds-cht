# 772 — 「The Gods intervene!」、七欄的金錢顯示、音效命令分派

- 證據等級：`exact`（以補洞後的匯出逐條讀完，見 spec 761）

## `overlay-13:48DCh`（DOS）— 全隊倒下時的神明介入

`retf`，不收參數：

```pascal
結果 := 0;
FillChar(本地緩衝, 2, …);
if not <0A54h:0724h>(@DS:8C80h) then 離開;      { 以 ZF 回報 }
結果 := 1;
顯示('The Gods intervene!');                    { CS:48C8h，19 字元 }
角色 := DS:650Ah;
while 角色 <> NIL do begin
    if 角色^[197h] = 1 then begin                { 陣營 1 }
        角色^[196h] := 0;
        角色^[195h] := 6;                        { 狀態 := 6 }
        byte[66A6h + 4 * <索引>(角色)] := 0;
    end;
    <呼叫>(角色);
    角色 := 角色^[189h];
end;
<呼叫>(地圖^[2] + 3, 地圖^[3] + 3, 0FFh, 8);
```

三個可以直接用的結論：

- **狀態欄位（DOS `+195h`）的值 `6`** 是神明介入之後被設定的狀態。與 spec 763
  的 `7 ＝ 石化` 是同一個欄位的另一個值。
- 最後那個呼叫的前兩個參數是 `地圖^[2] + 3` 與 `地圖^[3] + 3`。spec 750 記錄
  戰鬥開場時寫的是 `隊伍位置 − 3`，**這裡加回來就是隊伍原本的座標**——兩邊互相
  印證了那個 `−3` 是「往回退三格當戰場左上角」。
- `DS:66A6h` 在 spec 757 是「指標表 `DS:6D35h` 的項數」，這裡卻以
  `66A6h + 4 × 索引` 當陣列基底寫入。索引從 1 起算，所以實際寫的位置在
  `66AAh` 之後，不會蓋到那個計數 byte——**同一個位址既是計數又是 1-based 陣列的
  第 0 格**，remake 不能把兩者分開擺。

## `overlay-19:0597h`（DOS）— 七欄的金錢顯示

`retf`，不收參數：

```pascal
<開窗>(0Eh, 1Ah, 7, 0Ch);
列 := 7;
for i := 6 downto 0 do
    if DS:6506h^[0FBh + i * 2] > 0 then begin        { 無號 }
        名稱 := 字串[DS:0F93h + i * 0Bh];
        繪字(14h − 名稱長度, 列, 0Ah, 0, 名稱);       { 右對齊到第 20 欄 }
        繪字(15h, 列, 0Ah, 0, 數值轉字串(DS:6506h^[0FBh + i * 2]));
        inc(列);
    end;
```

- `+0FBh` 是**七個 word** 的陣列（`i = 0..6`）。spec 764 的
  `overlay-21:0A03h` 就是從這個陣列扣數量的那一支。
- 名稱表在 **`DS:0F93h`，每筆 `0Bh`（11）bytes**（Pascal 短字串，內容最長 10
  個字元），七筆共 77 bytes。
- **只有數量大於 0 的欄位才會佔一列**，所以列數是浮動的，從第 7 列往下排。
- 名稱**右對齊到第 20 欄**（`14h − 長度`），數值固定從第 21 欄開始。

**中文化的直接影響**：右對齊是用 `14h − 長度` 算的，長度是 byte 數。全形中文
的 byte 數是顯示寬度的兩倍，直接換字會讓名稱往左跑一倍的距離、甚至算出負值。
這個表在**常駐資料段**（`DS:0F93h`），不在任何 overlay 的 `.bin` 裡，所以
`scripts/scan_pascal_strings.py` 掃不到它——與 spell 名稱表（`DS:27BDh`）同一種
情況。

## `START.EXE:17150h`（DOS）— 音效命令分派

`retf 2`：

```pascal
if 命令 not in <CS:17130h 的集合> then 離開;
case 命令 of
    00h:      if 裝置 <> 2 then begin <關 A>(0); <關 B>(0); end;
    01h:      if 裝置 <> 2 then <呼叫 197B4h>(1);
    0FFh:     if 裝置 <> 2 then begin <關 A>(0); <關 B>(0);
                                     19355h();          { spec 755 的卸載 }
                                     unk_21DACh := 0; end;
    02h..0Eh: if 裝置 <> 2 then
                  case 裝置 of
                      0: <播 B>(命令 − 1);
                      1: <播 A>(命令 − 1);
                  end;
    0Fh:      dword[unk_21154h]^ := 1388h;               { 5000 }
end;
```

`unk_21DAAh` 就是 spec 755 記錄的音效裝置代碼（值 `2` 會跳過 PIT ＋ Tandy 的
安裝），這裡同樣是「等於 2 就什麼都不做」。裝置 `0` 與 `1` 各走一組不同的播放
程序，**命令值會先減 1** 才傳下去。

命令 `0Fh` 直接寫 `1388h`（5000）到 `unk_21154h` 指向的 word——`unk_21154h`
在 spec 755 的 `17206h` 被設成 `seg045:0124h`。

進入處的集合判定用 Borland 還原出的 `Set::MemberOf`，集合常數在 `CS:17130h`。
**不在集合裡的命令會被安靜丟掉**。

## 明確不宣稱

- 沒有宣稱狀態值 `6` 的名稱（只知道是神明介入後設定的）。
- 沒有宣稱 `0A54h:0724h` 是什麼；只知道它收一個遠指標、以 ZF 回報。
- 沒有宣稱 `DS:0F93h` 那七個名稱的內容——常駐資料段本輪沒有 dump。
- 沒有宣稱 `+0FBh` 那七個 word 各自是什麼。
- 沒有宣稱音效命令 `01h` 與 `0Fh` 的語意。
