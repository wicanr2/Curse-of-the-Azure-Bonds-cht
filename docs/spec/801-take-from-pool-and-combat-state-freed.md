# 801 — 從 Pool 拿錢、戰鬥狀態記錄是 22 bytes（由 `FreeMem` 定出來）

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側的運算元差異已逐條列出）
- 作法見 spec 783

## `overlay-21:0A8Ah`（entry#21，87 條，差異 7 條）— 從 Pool 拿錢給角色

| | DOS | PC-98 |
|---|---|---|
| 訊息 | `'Overloaded'`（10） | `'持ちすぎです'`（12 bytes） |

`retf 8` ＝ 4 個 word。依宣告順序：`(角色, 數量, 幣別)`。

```pascal
if <本模組 0073h>(@餘裕, 數量, 角色) then begin
    顯示(名字 ＋ 'Overloaded');
    <far 154Fh>();
end else begin
    if longint(DS:6F70h + 幣別 * 4) < 數量 then          { 有號 32 位元比較 }
        數量 := word(DS:6F70h + 幣別 * 4);               { 只取低 16 位 }
    longint(DS:6F70h + 幣別 * 4) := longint(...) − 零延伸(數量);
    角色^[0FBh + 幣別 * 2] := 角色^[0FBh + 幣別 * 2] + 數量;
    <本模組 0057h>(數量, 角色);
end;
```

與 spec 793 的「角色之間給錢」、spec 798 的「全隊併進 Pool」湊成一組完整的金錢
流動：

| 方向 | spec | 負重呼叫 |
|---|---|---|
| 角色 → 角色 | 793 | 給方 `003Bh`、收方 `0057h` |
| 角色 → Pool | 798 | `003Bh` |
| Pool → 角色 | 本支 | `0057h` |

- **超重時什麼都不做**（只印訊息），不像 spec 786 的撿錢會把拿不動的部分退回
  Pool。
- **要多少給多少，但不超過 Pool 現有的量**：`數量` 會被夾到 Pool 的餘額。
  夾制時只取 longint 的**低 16 位**——Pool 若真的超過 65535，夾出來的值會失真。
  遊戲內累積到那個量並非不可能，這一點 remake 要照抄還是修正必須明講。
- 減法是 32 位元、加法是 16 位元；角色端沒有上限檢查（上限由 `0073h` 事先擋）。

## `overlay-05:1370h`（entry#11，80 條，差異 30 條）— 戰鬥結束的收尾

```pascal
word(DS:4F9Dh^[590h]) := 0;
p := DS:650Ah;
while p <> NIL do begin
    if (p^[18Dh]^[13h] = 1) or (p^[197h] = 1) then begin
        DS:47ECh := 1;
        if p^[196h] <> 1 then inc(word(DS:4F9Dh^[590h]));
        後 := p^[189h];
        DS:6506h := p;
        <far 0F0Dh+2>(1, ord(p^[18Dh]^[13h] = 1));
        p := 後;
    end else begin
        if p^[18Dh] <> NIL then begin
            FreeMem(p^[18Dh], 16h);                { 22 bytes }
            p^[18Dh] := NIL;
        end;
        p := p^[189h];
    end;
end;
DS:6506h := DS:650Ah;
```

`retf`（無參數）。

### 戰鬥狀態記錄的大小定下來了：`16h` ＝ 22 bytes

`FreeMem(p^[18Dh], 16h)` 直接給出配置大小。既有的欄位全部落在範圍內：

| 位移 | 內容 | 出處 |
|---|---|---|
| `+09h` | 目前面向 | spec 782 |
| `+0Ah` / `+0Ch` | 目前目標的遠指標 | spec 782／790 |
| `+0Fh` | 動作計數 | spec 786 |
| `+12h` | 累計轉向量（mod 8） | spec 786 |
| `+13h` | 本支判斷的旗標 | 本支 |
| `+14h` | 本回合已撤退 | spec 782 |

`+15h` 之後就出界了，所以 **`+14h` 是最後一個 byte 欄位**。

### 兩條路的差別

- **留下的成員**（`+18Dh^[13h]` ＝ 1 或陣營 `+197h` ＝ 1）：設 `DS:47ECh` ＝ 1、
  把自己設成目前角色、呼叫 `0F0Dh+2(1, 旗標)`；**戰鬥狀態記錄不釋放**。
- **其餘成員**：釋放 `+18Dh` 並清成 NIL。

`DS:4F9Dh^[590h]` 數的是「留下且 `+196h` ≠ 1」的成員數。走訪前先把它清零。

⚠ **留下的那條路先把 `後` 抓起來再呼叫 `0F0Dh+2`**——因為那支可能把 `p` 從串列
裡拿掉。另一條路沒有這個保護（它不呼叫任何可能改串列的東西）。

收尾時 `DS:6506h` 被重設成隊首。

## 明確不宣稱

- 沒有宣稱 `+18Dh^[13h]` 代表什麼。
- 沒有宣稱 `+196h` ＝ 1 是哪一種狀態（spec 784 也只知道它為 0 時目前 HP 不計）。
- 沒有宣稱 `DS:47ECh` 與 `DS:4F9Dh^[590h]` 由誰讀。
- 沒有宣稱 `far 0F0Dh+2` 做什麼。
