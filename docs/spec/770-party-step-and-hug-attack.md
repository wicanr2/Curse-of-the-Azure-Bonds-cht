# 770 — 迷宮裡走一步（含環繞）、`hugs` 攻擊訊息

- 證據等級：`exact`（以補洞後的匯出逐條讀完，見 spec 761）

## `overlay-14:083Ch`（DOS）— 隊伍在迷宮裡前進一格

`retf`，不收參數：

```pascal
<0713h:0020h>(DS:25C0h);
<09ABh:029Eh>(32h);                          { 50 }
DS:720Fh := DS:720Fh + byte[2694h + DS:7211h];   { x ＋ dx }
DS:7210h := DS:7210h + byte[269Dh + DS:7211h];   { y ＋ dy }
if DS:720Fh < 0    then DS:720Fh := 0Fh;     { 有號比較，往左出界 → 繞到右邊 }
if DS:720Fh > 0Fh  then DS:720Fh := 0;
if DS:7210h < 0    then DS:7210h := 0Fh;
if DS:7210h > 0Fh  then DS:7210h := 0;
DS:7212h := <017Fh:0034h>(DS:720Fh, DS:7210h, DS:7211h);
FillChar(@DS:7588h, 3, 1);
DS:7213h := <017Fh:003Eh>(DS:7210h, DS:720Fh);
if (DS:4F9Dh^[594h] and 1) <> 0
    then <0108h:002Ah>(2, 1)
    else <0108h:002Ah>(1, 1);
```

三個相鄰的 byte 定住了隊伍在迷宮裡的位置：

| 位址 | 意義 |
|---|---|
| `DS:720Fh` | x |
| `DS:7210h` | y |
| `DS:7211h` | 面向（索引 `DS:2694h` / `DS:269Dh` 這對 dx／dy 表） |
| `DS:7212h` | 走完之後由 `017Fh:0034h(x, y, 面向)` 算出的值 |
| `DS:7213h` | 由 `017Fh:003Eh(y, x)` 算出的值 |

**環繞是無條件的**：出界不是被擋下來，而是繞到對邊。這與 spec 763 的
`overlay-30:07C6h`（讀地圖時同樣先環繞）一致，也與 spec 761 的 16 × 16 地圖
對得上。要注意 `overlay-30:07C6h` 的環繞還多一道 `DS:8B5Eh` 的判斷，這一支
**沒有**——移動一律環繞。

`FillChar(@DS:7588h, 3, 1)` 把三個相鄰的 byte 全設成 1，位置在
`DS:7588h`..`758Ah`。

最後那個二選一只看 `DS:4F9Dh^[594h]` 的 bit 0。

## `overlay-13:4811h`（DOS）— `hugs` 攻擊

`retf 0Ah`：

```pascal
if DS:6F9Fh < 12h then 離開;                  { 有號 }
DS:6FA3h := 攻擊者^[18Dh]^[0Ah];              { 把目標抄到全域 }
顯示(攻擊者 ＋ CS:480Bh ＋ 目標名);           { 'hugs ' — 5 字元，含尾隨空白 }
<呼叫>(1, 0Ch);
<呼叫>(0, <算值>(目標, 0, 3Ah), 目標);
<呼叫>(0, 0, 0, 目標, 3Ah);
<呼叫>(1, <算值>(攻擊者, 0, 90h), 攻擊者);
```

`'hugs '` 的**尾隨空白是字串常數的一部分**（長度 byte 是 5），因為後面要直接
接上目標的名字。中文化時這一格空白要換成適當的接續方式，不能只翻五個字元。

`3Ah`（58）與 `90h`（144）是兩個效果／傷害碼，分別作用在目標與攻擊者身上——
**這個攻擊對攻擊者自己也有一次作用**。

`DS:6FA3h` 是把目標暫存到全域，與 spec 766 記錄的「借用 `+18Dh^[0Ah]` 當參數
通道」是不同的作法：這裡是複製到另一個全域，原欄位不動。

## `overlay-15:1FB9h`（DOS）— 三級治療量累加

70 條指令的助憶碼與 PC-98 `overlay-15:2020h`（spec 763）**完全相同**：
`ss:[p−4]` 次 `1d8`、`ss:[p−6]` 次 `2d8+1`、`ss:[p−8]` 次 `3d8+3`，累加到
`ss:[p−2]`。

## 明確不宣稱

- 沒有宣稱 `017Fh:0034h` / `017Fh:003Eh` 算出來的是什麼（`DS:7212h` /
  `DS:7213h` 的意義未定）。
- 沒有宣稱 `DS:7588h` 那三個 byte 是什麼。
- 沒有宣稱 `DS:6F9Fh >= 12h` 這個門檻的意義。
- 沒有宣稱 `3Ah` / `90h` 對應哪兩個效果。
- 沒有宣稱 `0713h:0020h`、`09ABh:029Eh`、`0108h:002Ah` 是什麼。
