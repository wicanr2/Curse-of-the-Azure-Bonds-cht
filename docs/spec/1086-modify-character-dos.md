# 1086 — DOS 角色數值調整：經驗值必須「恰好」是四個起始值之一，屬性上下限查兩張表

- 證據等級：`exact`（DOS 側 1,291 條逐條讀完，`filled` 匯出無破洞）
- 作法見 spec 783

## `dos overlay-17:02868h`（`retf`）

原本待解讀。範圍 `2868h`..`3560h`。這是隊伍選單 `M`（Modify）的內容：
**直接編輯角色的六個屬性、最大 HP 與名字**。

## ★★★ 一、經驗值必須「恰好」是四個值之一

```pascal
可改 := (經驗值 = 0)
     or (經驗值 = 208Dh)          { 8,333 }
     or (經驗值 = 30D4h)          { 12,500 }
     or (經驗值 = 61A8h);         { 25,000 }
if 可改 and (角色^[0E6h] = 0) then …進入編輯…
else begin 印(角色名 ＋ " can't be modified.");  exit end;
```

> ★★★ **是「等於」不是「大於」**——三次比較全部用 `jz`，
> 最後一次 `jnz` 直接跳到拒絕路徑。
> ⇒ 條件是「**經驗值還停在建角時發下來的那個值**」（0／8,333／12,500／25,000，
> 形狀上對應職業數），**而且 `角色^[0E6h] = 0`**；
> 只要打過一場、拿到任何額外經驗，數值就鎖死。
> ★★★ **四個值就是建角時發下來的起始經驗值**（`dos overlay-17:00782h`）：
> **單職 25,000、雙職 12,500（＝ 25,000 ÷ 2）、三職 8,333（＝ 25,000 ÷ 3）**
> ——25,000 平分給各職業。
> ★ PC-98 對側（spec 1092）逐條相同，另外多一道 `bank0^[1E4h] <= 1` 的整段略過。

## 二、八個可編輯欄位

`var_37` 是目前選到的欄位（`0`..`7`），`'O'` 往下一個、`'G'` 往上一個，兩端環繞。

| `var_37` | 欄位 | 位址 |
|---|---|---|
| 0..5 | **六個屬性**（力／智／睿／敏／體／魅） | `角色^[11h ＋ i × 2]`（spec 1079 的**目前值**） |
| 6 | **最大 HP** | `角色^[78h]`，同步寫 `角色^[1A4h]`（目前 HP） |
| 7 | **名字** | `角色^[0]` 是長度、`角色^[1]` 起是字元 |

★ **角色記錄的第 0 個 byte 就是名字字串的長度**——與 spec 1043 表 A
（`.guy` 的名字位移 ＝ 0）互相印證。

## ★★★ 三、屬性加減：兩張表各自夾一次下限／上限

按 `4Bh`（←）減、`4Dh`（→）加。以「減」為例：

```pascal
dec 角色^[11h ＋ i × 2];

if i = 0 then begin                      { 力量 }
    if 角色^[1Ch] > 0 then begin         { ★ 先扣百分比 }
        dec 角色^[1Ch];  inc 角色^[11h]; { 把剛才那一點加回去 }
    end else begin
        下限 := byte[DS:3F86h ＋ 角色^[74h] × 10h ＋ 角色^[119h]];
        if 角色^[11h] < 下限 then 角色^[11h] := 下限;
    end;
    下限2 := byte[DS:4172h ＋ 角色^[75h] × 6];
    if 角色^[11h] < 下限2 then 角色^[11h] := 下限2;
end
else if i = 1 then begin                 { 智力 }
    下限 := byte[DS:3F8Ch ＋ 角色^[74h] × 10h];
    if 角色^[13h] < 下限 then 角色^[13h] := 下限;
    下限2 := byte[DS:4172h ＋ 角色^[75h] × 6 ＋ …];
    …
end
…其餘四個屬性同一形狀…
```

> ★★★ **兩張表、兩次夾值**：
> - 第一張 `DS:3F86h`，索引 **`角色^[74h]`（種族，spec 1084）× `10h`**
>   ——**一個種族一列 16 bytes**。
>   力量那一格再加上 **`角色^[119h]` ＝ 性別**，其餘五個屬性各佔一格
>   （智力在 `＋6`）⇒ **種族的屬性下限，而力量那一格再依性別分**
>   （AD&D 1e 的女性角色力量上限較低）。
> - 第二張 `DS:4172h`，索引 **`角色^[75h]`（＝ 職業組合編號，0..`0Ch`）× 6**
>   ——**一個職業組合一筆 6 bytes** ⇒ **每個職業對六個屬性的最低要求**。
>
> ★ 兩個欄位的身分由 `dos overlay-17:00782h` 的建角流程直接看到：
> `Pick Gender` 之後寫 `+119h`、`Pick Class` 之後寫 `+75h`。
> ⚠ 兩張表的**內容**仍未宣稱——它們在**資料段**，不在 overlay 的 `.bin` 裡。
>
> ★★ **力量的百分比（`+1Ch`，spec 1079 的 18/xx）是獨立的一階**：
> 從 18/xx 往下調時**先把百分比一點一點扣掉**，扣到 0 才動整數部分。
> 加的方向是鏡像的同一套。

## 四、HP 欄位

```pascal
值 := <near 46ECh>(角色);
if 值 <= 角色^[78h] then 角色^[78h] := <near 46ECh>(角色);
角色^[1A4h] := 角色^[78h];               { ★ 目前 HP 直接等於最大 HP }
```

⚠ **`near 46ECh` 是「有效等級」不是「HP 上限」**（spec 850 逐條讀完：
各職業槽等級總和加調整後除以職業數）。本規格先前把它標成 HP 上限，是錯的。
真正算 HP 上限的是 `near 47C6h`（spec 1055）。
⇒ 這一段拿有效等級去夾最大 HP，形狀上很怪；**本規格不宣稱它的用意**，
只記錄實際呼叫的是哪一支。

★ 與 spec 1084 的訓練所不同：**這裡是「調數值」，目前 HP 直接補滿**，
不像升級時要保留受傷差額。

## 五、名字欄位

`var_3F` 是名字裡的游標位置（1 起算）。

- `'S'`：刪掉游標處的字元——**把後面的字元整段往前搬再把長度減 1**；
  游標在最後一格時只減長度。長度 ≤ 1 時不動。
- `4Bh`／`4Dh`：游標左右移，**兩端環繞**（移到 1 再往左會跳到最後一格）。

## 中文化

| DOS | 位址 | 長度 | 建議 |
|---|---|---|---|
| `" can't be modified."` | `CS:2841h` | 19 | 「 無法調整。」（接在角色名後） |
| `'Modify: '` | `CS:2855h` | 8 | 「調整：」 |
| `'Keep Exit'` | `CS:285Eh` | 9 | ⚠ **熱鍵 `K`／`E` 必須留在文字裡**（spec 1060） |

⚠ 名字編輯是**逐個 byte 搬移**（`角色^[i] := 角色^[i＋1]`），
**對 Big5 雙位元組完全沒有保護**——按一次 `S` 會切掉半個中文字。
⇒ **remake 的中文名字編輯必須改成以字元為單位**，不能照抄這一段。
⚠ 游標左右移也是逐 byte，同一個問題。

## 明確不宣稱

- 沒有宣稱經驗值 `0` 這一格對應哪一種角色（其餘三個已由建角流程對上職業數）。
- 沒有宣稱 `角色^[0E6h]` 是什麼（spec 1084 的訓練所也用同一格）。
★★★ **`角色^[119h]` ＝ 性別、`角色^[75h]` ＝ 職業組合編號**（`dos overlay-17:00782h`
  的建角流程直接看到：`Pick Gender` 之後寫 `+119h`、`Pick Class` 之後寫 `+75h`）。
  ⇒ 第一張表是**種族的屬性下限，其中力量那一格再依性別分**（AD&D 1e 的女性力量上限）；
  第二張表是**每個職業組合的六個屬性最低要求**（13 個組合 × 6 個屬性）。
★ **兩張表的內容已由 spec 1099 取出**：`DS:3F86h` 是種族的屬性上下限
（每列 `10h` bytes，力量三組各分男女），`DS:4172h` 是 13 個職業組合的
六屬性最低要求（索引 3 ＝ 聖騎士 `12 9 13 0 9 17`）。
⚠ `3F86h` 的**索引 0 那列不是屬性限制**，人類要當特例處理。
- 沒有宣稱 `near 46ECh`（有效等級，spec 850）在本流程的用意；
  `near 47C6h`（HP 上限，spec 1055）／`near 2515h`／
  `near 2724h`（重畫）各自的內容。
- 沒有宣稱 `角色^[12Dh]`（本支會把它設成 1）代表什麼。
- 沒有宣稱 `overlay-19 entry#1／#2`、`overlay-24 entry#7`、
  `overlay-25 entry#2` 的介面。
★ PC-98 對側是 `pc98 overlay-17:02E9Bh`（spec 1092）：機制逐項相同，
兩張表的基底是 `DS:701Bh` 與 `DS:7207h`。
