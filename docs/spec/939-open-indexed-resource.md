# 939 — 開啟索引式資源檔：同一個檔開兩次，索引與資料各一個位置

- 證據等級：`exact`（逐條讀完）
- 位置：DOS `START.EXE` 的 `16B24h`
- 作法見 spec 783

## `16B24h`（109 條）—— `retf 14h`

```pascal
開資源(資料檔 arg_0, 索引檔 arg_4, @位移 arg_8, 副檔名 arg_C, 主檔名 arg_10);

主 := 限長(arg_10, 14h);              { 20 }
副 := 限長(arg_C,  14h);
名 := 主 ＋ 副;

路徑 := DS:25AEh ＋ byte_21DAEh × 1Eh;          { 路徑表，每筆 1Eh ＝ 30 bytes }
if not <sub_16645h>(名, 路徑, byte_21EB0h, arg_4) then begin
    結果 := 0;  離開;
end;

名 := 主 ＋ 副;                        { ★ 一模一樣地再組一次 }
if not <sub_16645h>(名, 路徑, byte_21EB0h, arg_0) then begin
    結果 := 0;  離開;
end;

BlockRead(arg_0, arg_8^, 2, 讀到幾個);  { 從索引檔讀一個 word 到呼叫端的位移變數 }
arg_8^ := arg_8^ ＋ 2;
Seek(arg_4, arg_8^);                    { 把資料檔定位到那裡 }
結果 := 1;
```

## 同一個檔開兩次

`arg_0` 與 `arg_4` 是**兩個不同的 `File` 變數，開的是同一個檔名**
（字串在兩次呼叫之間被原封不動重組一次）。
這樣兩邊各有獨立的讀取位置——**一個當索引游標、一個當資料游標**，
不必來回 `Seek`。

流程是：從 `arg_0`（索引側）讀一個 word 當作「資料起點」，
`＋2` 跳過那個 word 本身，再把 `arg_4`（資料側）`Seek` 過去。
讀到的位移**同時寫回呼叫端的 `arg_8^`**，所以呼叫端拿得到目前位置。

## 路徑表：`DS:25AEh`，每筆 `1Eh`

`byte_21DAEh` 是索引。`1Eh` ＝ 30 ＝ `string[29]`——
一個 DOS 路徑（`A:\CURSE\` 之類）綽綽有餘。
`byte_21EB0h` 是另一個參數（形狀上是磁碟或重試次數），與路徑一起傳給
`<sub_16645h>`。

**兩個全域一起決定檔案從哪裡開**——這解釋了 spec 926 那個
`WALLDEF<磁碟>.dax` 為什麼只帶磁碟編號在檔名裡：**目錄由這張表提供**。

## 失敗就是回 0

兩次開檔任一失敗就回 0，**沒有訊息、沒有重試**。
與 spec 926 的「載不到就結束程式」是不同層級的處理——
本支把失敗交回呼叫端。

## 明確不宣稱

- 沒有宣稱 `<sub_16645h>` 的內部（形狀上是「在指定路徑上開檔，失敗回 false」）。
- 沒有宣稱 `byte_21DAEh`／`byte_21EB0h` 由誰設定。
- 沒有宣稱路徑表有幾筆。
- 沒有宣稱為什麼要把檔名重組一次而不是留著用。
