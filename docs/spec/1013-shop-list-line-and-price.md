# 1013 — 商店清單：價格靠右對齊、就地覆寫名稱，以及 `+28h` 位移的由來

- 證據等級：`exact`（DOS 側 323 條逐條讀完；PC-98 對側 364 條，
  多出來的 41 條是熱鍵表填寫與加寬的欄位，已逐條讀完）
- 作法見 spec 783

## `dos overlay-06:00050h` ↔ `pc98 overlay-06:00037h`（`retf 10h`）

兩側原本都是待解讀。這是**商店「買」清單**的畫面：把每一件商品排成
「名稱靠左、價格靠右」的一行，開選單讓玩家挑，挑完再把名稱還原。

四個參數都是遠指標（`bp+06h`／`0Ah`／`0Eh`／`12h`），
`bp+12h` 收選單回傳的鍵、`bp+0Eh` 收選到的那件商品。

## ★★ 價格：`value` 乘除一個由旗標決定的倍率

```pascal
物品 := 遠指標(DS:6F8Ch);                       { 商店存貨鏈的頭 }
while 物品 <> NIL do begin
    緩衝 := 30 個空白;                          { CS:0025h，長度 1Eh }
    if 物品^.value = 0 then 物品^.value := 1;   { ★ 免費品強制變 1 }

    case 遠指標(DS:4F9Dh)^[6DAh] of
       1  : 價 := 物品^.value div 16;
       2  : 價 := 物品^.value div 8;
       4  : 價 := 物品^.value div 4;
       8  : 價 := 物品^.value div 2;
      20h : 價 := 物品^.value × 2;
      40h : 價 := 物品^.value × 4;
      80h : 價 := 物品^.value × 8;
      else  價 := 物品^.value;
    end;
    …
```

★ `物品^.value` 就是 `+3Ah` 那個 word——**開發者自己的欄位名**，見 spec 1011。

★★ **倍率旗標 `遠指標(DS:4F9Dh)^[6DAh]` 是單一位元**
（`1, 2, 4, 8, 20h, 40h, 80h`，`10h` 沒有用到）。
從 `÷16` 到 `×8` 一共七檔，**每一檔差一倍**——
形狀上是「這家店的買價倍率」。本規格不宣稱那七檔各對應哪種店。

⚠ `value = 0` 會被**就地改成 1**，商品節點被寫壞（下次再進店就不是 0 了）。

## ★★ 一行怎麼排：價格靠右、名稱靠左

```pascal
    Str(價, 16, 數字);                          { resident 0A54:12ABh，LongInt }
    for i := 1 to Length(數字) do               { ★ 右對齊 }
        緩衝[30 − Length(數字) + i] := 數字[i];
    for i := 1 to Length(物品^) do              { ★ 名稱靠左，直接覆蓋 }
        緩衝[i] := 物品^[i];

    複製(緩衝 → 物品^, 40);                     { resident 0A54:064Eh }
    物品^[0] := 1Eh;                            { ★ 長度固定 30 }
    物品 := 物品^[2Ah];                         { 下一件 }
end;
```

> ⚠⚠ **這一支直接把排好的行寫回物品節點的名稱欄位，原名就沒了。**
> 選單關掉之後，最後一段再走一次鏈，對每一件叫
> `<overlay-24 entry#1>(0, 0, 0, 0, 物品, 0)` 把名稱重建回來。
> 形狀上 `entry#1` 就是「依 `namenum(1..3)` 組回顯示名」（spec 1011），
> 但那一支還沒讀，本規格不宣稱。

★★ **物品節點的 `+0` 是一個 Pascal 短字串**（`0A54:064Eh` 的複製長度 40）。
`+2Ah` 是鏈的 next（spec 1000 同一格）。

## ★★★ `+28h` 位移的由來：PC-98 把名稱欄位加大 40 bytes

同一段程式在 PC-98 的三個常數全部變大：

| | DOS | PC-98 |
|---|---|---|
| 行寬（右對齊基準） | `1Eh` ＝ 30 | `23h` ＝ 35 |
| 複製長度 | `28h` ＝ 40 | `50h` ＝ 80 |
| 寫回的長度 | `1Eh` ＝ 30 | `46h` ＝ 70 |
| **鏈的 next** | **`+2Ah`** | **`+52h`** |

`52h − 2Ah = 28h`。

> ★★★ **spec 1011 量到「物品節點的 13 個欄位在 PC-98 整體 ＋28h」，
> 原因就在這裡——名稱欄位從 41 bytes 加大到 81 bytes，
> 後面所有欄位跟著往後推 40 bytes。**

Shift-JIS 一個字兩個 byte，所以日文版必須加寬。
**Big5 完全一樣**——中文化要跟 PC-98 的版面，不能沿用 DOS 的 41 bytes。

## ★★★ 熱鍵：又一次同樣的分工

| | DOS | PC-98 |
|---|---|---|
| 標題 | `'Items: '`（`CS:0044h`） | 「アイテム：」（`CS:002Ch`） |
| 選項 | `'Buy'`（`CS:004Ch`） | 「 買う 」（`CS:0025h`，**6 bytes ＝ 3 全形字**） |
| 熱鍵怎麼標 | **`'Buy'` 的大寫 `B`** | 文字寫進 `DS:0A362h`，**熱鍵 `42h`（`'B'`）另外寫進 `DS:0A33Ah`** |

`0A362h ＝ 0A338h ＋ 6 × 7`、`0A33Ah ＝ 0A334h ＋ 6` ⇒ **兩邊的索引都是 6**，
與 spec 755 的兩張平行陣列、spec 1012 的三個選項完全同構。

PC-98 也先叫一次 `overlay-26 entry#3 @0858h`（十筆欄位初始化，spec 755），
和 spec 1008 的移動選單一樣。

⚠ 「買う」的複製長度寫死 **6 bytes ＝ 3 個全形字**，中文同樣只有 3 個字。

## 中文化

**清單行的版面是硬約束**：PC-98 的一行是 70 bytes，名稱靠左、價格靠右。
中文一個字兩 bytes，所以名稱 ＋ 價格加起來**最多 35 個全形位**。

⚠ 右對齊是用 `緩衝[行寬 − 長度 ＋ i]` 逐 byte 搬的，**沒有 DBCS 概念**。
只要價格字串的長度讓起點落在漢字的中間，那個漢字就會被劈開。
價格是純數字（ASCII），所以只要**名稱的 byte 長度是偶數**就安全——
中文名全用全形字時自然成立，但**混進半形數字或 `+1` 這類後綴就要湊偶數**。

## 明確不宣稱

- 沒有宣稱 `遠指標(DS:4F9Dh)^[6DAh]` 的七個位元各代表哪一種店。
- 沒有宣稱 `overlay-24 entry#1`（重建名稱）怎麼組，那一支還在待解讀。
- 沒有宣稱 `DS:7294h`／`DS:47EEh` 的用途。
- 沒有宣稱四個參數裡 `bp+06h`／`bp+0Ah` 各是什麼（都原樣轉給選單）。
