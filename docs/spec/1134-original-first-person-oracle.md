# 1134 — 原版第一人稱 oracle：互動式驅動、存檔版面、天花板顏色

- 證據等級：`exact`（原版 DOS 版在 Docker/DOSBox 裡實跑；存檔位元組由原版自己
  寫出；每一格畫面與 remake 逐格比對，比的是 EGA 量化後的 16 色索引）
- 上游 spec 1131（第 0 段符號）、spec 1130（幾何與框）、spec 346（`Draw3dWorldBackground`）、
  spec 181／1072（存檔前綴）、spec 1133（第一份角色樣本）

## 結論

提爾佛頓（`GEO2` 區塊 `01h`）**五格 × 四個朝向、共二十張**畫面與原版逐格比對：
十九張完全相同，一張差**一格**。第一人稱的牆磚選圖、透視收斂、地板與外框
在這二十張裡沒有其他差異。

修好的是**天花板**：先前整片是黑的。

| 項目 | 先前 | 現在 |
|---|---|---|
| `tilverton.first-person` 的 `outdoor_sky_color` | 3 | 11 |
| `tilverton.first-person` 的 `indoor_sky_color` | 0 | 9 |

`BuildBackground` 用 `skyPalette[selection % 8]` 取色，`skyPalette[1] = 0Fh`＝白。
室內走廊的 `MapWallRoof` 是 `80h`（≥ `80h` 為室內），所以取的是
`indoor_sky_color = 9`，`9 % 8 = 1` → 白色天花板。先前宣告的 0 取到 `skyPalette[0] = 0`，
於是天花板與底色一樣黑，看起來像「沒有天空層」。

★ 這兩個數字是**原版自己寫出來的**：在遊戲裡站上那張地圖之後 `ENCAMP → SAVE`，
存檔的 `Area1` `1FAh`／`1FCh` 就是 11 與 9。從**選單**存的那一份兩個都是 0——
那時 ECL 還沒把 runtime 值填進去。**同一支存檔常式，存的時機不同，欄位意義不同。**

## 一、`CURSE.CFG` 是四行純文字

19 bytes，`\r\n` 分行：

```
E          顯示介面卡：C＝CGA、E＝EGA、T＝Tandy
S          音效：P＝PC 喇叭、T＝Tandy、S＝靜音
C:\SAVE\   存檔路徑（結尾要有反斜線）
F          第四行
```

留著它，開機三道提示整個跳過，直接以 EGA 進標題畫面。**取 oracle 一律留著**：
少三個按鍵就少三個錯位的機會。第四行 `F` 的意義還沒查。

## 二、互動式驅動取代定時按鍵序列

原本的取樣方式是「猜一整串鍵、等一輪、看結果」。一輪兩分半，而任何一步的
載入時間漂移都會讓後面每一個鍵錯位——錯位的鍵可能剛好按到 `EXIT TO DOS`。

現在容器常駐，主機端逐步送鍵並讀回畫面：

| 工具 | 做什麼 |
|---|---|
| `tools/dos-oracle-session.sh` | `start`／`key`／`type`／`shot`／`text`／`stop`；容器名固定 `coab-dos-oracle` |
| `tools/dos_screen.py` | 把 320×200 的 8×8 文字格解成字串；字型表 `tools/dos_screen_font.json` |
| `tools/dos_screen_pos.py` | 從畫面讀「x y 朝向」 |
| `tools/dos-oracle-capture-cell.sh` | 目前這一格拍四個朝向，順手消掉 `PRESS <ENTER>` 提示 |
| `tools/fp-oracle-compare.py` | 原版擷取與 remake 同格畫面逐格比對 |

每一步約一秒。**判別狀態靠讀畫面文字，不靠等待時間。**

⚠ 每一格的背景色取「格內最常出現的顏色」，其餘像素當前景——反白（選取中的
項目）因此自動正規化成與正常顯示相同的位元圖。`LOAD WHICH GAME: A` 的那個
反白 `A` 就是這樣讀出來的。

⚠ 比對一律在 **EGA 量化之後**做。DOSBox 與 remake 對同一個 EGA 顏色算出的 RGB
差幾個階（`168,168,168` vs `173,173,173`），直接比 RGB 會有九成的格子「不同」，
把真正的差異埋掉。

## 三、原版存檔：DOS 是 13,149 bytes

原版自己寫出來的 `savgam?.dat` 是 **13,149 bytes**，與 spec 181 的
`1E00h` ECL 區塊相符。spec 1072 的 `1E41h`／13,214 是 **PC-98 的版面**，
兩者是平台差異，不是其中一份記錯。DOS 側 overlay-16 `sub_3748` 的
`39BC b8001e mov ax, 1E00h` 也是同一個數字。

合成的存檔與原版存檔逐區塊比對，只有兩處不同：

| 區塊 | 差異 |
|---|---|
| `Area2 + 67Ch` | 原版是 1，合成是 0；**載入端在讀完之後立刻把它清成 0**（`3AE8`），不影響 |
| 角色檔名那八筆 | 見下 |

## 四、★ 存檔裡的角色檔是 `.SAV` ＋ `.FX`，而且原版會改名

存檔時原版把隊伍成員的 `<名字>.GUY`／`<名字>.FX` **改名**成
`CHRDAT<槽><序>.SAV`／`CHRDAT<槽><序>.FX`（實測：存檔後 `BOB.GUY` 消失，
出現 `CHRDATA1.SAV`）。載入端組出來的路徑是 `<存檔路徑><檔名欄>.sav`。

⚠ **檔名欄指到不存在的檔案時，原版不會報錯**：`3B84` 直接跳過那名角色。
八筆全跳過的結果是隊伍為空，而空隊伍會退回「沒有隊伍」的主選單——
畫面上看起來就是「按了槽的字母之後回主選單」，與「拒絕讀檔」一模一樣。
**沒有錯誤訊息的失敗，症狀會長得像另一個問題**——這一個看起來像「檔案格式不對」，
於是會把人推去查前綴長度、角色記錄版面、檔名欄的長度位元組，而那些都不是成因。
判準是**先確認失敗發生在哪一步**（這裡是「載入成功但隊伍為空」），不是先猜輸入哪裡錯。

## 五、開場那一格是密室

載入之後隊伍站在 `(7,13)`，而那一格只有**一個**可走方向（劇情要求先找出口）。
在那裡按方向鍵前進不會動——這不是按鍵沒送進去。`cmd/geo-probe` 會把一張
`GEO` 地圖的可走方向數印成 16×16 的圖，取 oracle 之前先看它挑格子。

要站到任意格子，用 `cmd/dos-save-export -base <原版存檔>`：以原版自己寫出來的
檔案為底，只覆寫 `Area1` 的 `LastX`／`LastY` 與地圖那五格的 `x`／`y`／朝向。
朝向沿用遊戲的 0..7（0＝北、2＝東、4＝南、6＝西），與 remake 的
`-dungeon-facing` 相同——由 `(7,13)` 四個朝向的畫面逐格對上確認。

## 六、`-dungeon-x`／`-dungeon-y` 改成 checkpoint 之後才套

先前這兩個旗標在故事流程**之前**設定，而流程會自己決定站在哪，於是
`-tilverton-dungeon` 不論給哪一格都只畫流程的起點。現在與 `-dungeon-facing`
一起在流程之後再套一次。

## 七、剩下那一格

`(1,7)` 面西，原生座標 `(88,70)`：原版是 EGA 8（深灰），remake 是 0（黑）。
其餘 19 張、以及這一張的其他 7,743 格全部相同。已經縮到這裡：

- **不是 `SKY` 地面 overlay 解錯**。那一格落在 `SKY.DAX` 區塊 `0FCh`
  （88×48，畫在 native `(24,64)`）的第 `(64,6)` 像素，
  `cmd/picture-probe -member SKY.DAX -block 252 -x 64 -y 6` 讀出來是 **8**
  ——與原版畫面上的顏色相同。背景那一層是對的。
- ⇒ 蓋掉它的是**牆面 stamp 那一層**。`wallStampNativePosition(列,欄) =
  ((欄+3)×8, (列+3)×8)`，native `(88,70)` 對應牆格 **(列 5, 欄 8)** 的
  局部像素 `(0,6)`；remake 在那裡畫了一個不透明的 0，原版沒有。
- 還沒查：那一格的符號編號是什麼、它是走一般三段還是第 0 段
  （spec 1131 的 `sharedWallGroupStamps` 補畫）。

## 明確不宣稱

- 沒有宣稱 `outdoor_sky_color = 11`／`indoor_sky_color = 9` 適用於其他地圖。
  這兩個值量自 `GEO2` 區塊 `01h` 的一份原版存檔，本輪只改這一張地圖的宣告。
- 沒有宣稱其他 `GEO` 地圖的牆磚選圖也逐格相符；驗過的是提爾佛頓的五格。
- 沒有宣稱 `CURSE.CFG` 第四行 `F` 的意義。
- 沒有宣稱那一格差異的成因。
- 沒有宣稱 `-base` 覆寫之後的 `MapWallType`／`MapWallRoof` 一定與原版走到該格時
  算出來的相同；本輪沿用底檔的值，畫面比對沒有因此出現差異，但沒有逐格驗過。
