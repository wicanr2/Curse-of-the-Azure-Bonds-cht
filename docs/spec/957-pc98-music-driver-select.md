# 957 — PC-98 的 Ctrl-O：依機種／音源碼切換一個編號

- 證據等級：`exact`（逐條讀完，來源是 `PC98-GAME.EXE.asm`）
- 位置：`PC98-GAME.EXE` 的 `18AA7h`
- 作法見 spec 783

## `18AA7h`（158 行，far）

spec 951 的等按鍵按下 **`0Fh`（Ctrl-O）** 時，先把 `byte_24E73h` 反轉，
再呼叫本支。

```pascal
if byte_24E73h = 1 then begin                     { 剛被切成 1 }
    byte_24E71h := 0FFh;
    <sub_18A8Eh>();
    離開;
end;

if byte_241B7h in [1, 5, 7] then 離開;            { 這三種狀態不處理 }

al := byte_28080h;                                { ★ 機種／音源識別碼 }
case al of
  01h, 31h                          : byte_24E83h := 3;
  11h, 12h, 21h, 22h, 23h, 15h,
  43h, 45h                          : byte_24E83h := 4;
  50h, 51h                          : if byte_241A1h <> 0 then byte_24E83h := 6
                                      else                     byte_24E83h := 5;
  20h, 23h, 40h, 42h                : byte_24E83h := 8;
  02h, 10h, 05h, 35h                : byte_24E83h := 9;
  03h, 04h, 25h, 32h, 33h           : byte_24E83h := 0Ch;
  30h                               : { 不改，直接往下 }
else
  離開;                                            { 不呼叫下面那一支 }
end;

<sub_18A44h>(byte_24E83h);
```

## `byte_28080h` 是一張識別碼表

出現的值：`01h 02h 03h 04h 05h 10h 11h 12h 15h 20h 21h 22h 23h 25h
30h 31h 32h 33h 35h 40h 42h 43h 45h 50h 51h`——**高位元組像是「大類」、
低位元組像是「型號」**（`0x`、`1x`、`2x`、`3x`、`4x`、`5x` 六大類）。

映出來的 `byte_24E83h` 只有 **3、4、5、6、8、9、0Ch** 七個值，
之後交給 `<sub_18A44h>`。

⚠ **`23h` 同時出現在「值 4」與「值 8」兩組**：
程式碼由上往下比，`23h` 在第二組（`byte_24E83h := 4`）就會命中，
**第四組裡的 `23h` 永遠到不了**。兩個列表都逐條讀過，這是原版的重複。

## 這一支做什麼，本規格不宣稱

從形狀上看，`byte_28080h` 是**開機時偵測到的機種或音源板識別碼**，
`byte_24E83h` 是選出來的**驅動程式編號**，`<sub_18A44h>` 是套用它。
PC-98 的音源有 PC-9801-26K／86／SoundBlaster16 等多種，
分成六大類再細分型號的形狀與之相符。

**但本規格沒有讀 `<sub_18A44h>` 與 `<sub_18A8Eh>`，也沒有找到
`byte_28080h` 的寫入端**，所以不宣稱它就是音源選擇。
`0Fh` 這個鍵在遊戲裡對玩家的意義同樣未定。

## 明確不宣稱

- 沒有宣稱 `byte_28080h` 是什麼識別碼、由誰設定。
- 沒有宣稱 `byte_24E83h` 的七個值各代表什麼。
- 沒有宣稱 `byte_241B7h`（三個值直接跳過）與 `byte_241A1h`（`50h`／`51h` 的細分）。
- 沒有宣稱 `<sub_18A44h>`／`<sub_18A8Eh>` 的內部。
