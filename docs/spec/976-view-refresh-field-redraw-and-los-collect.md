# 976 — DOS 的完整視野更新（PC-98 砍了一半）、角色欄位重畫、視線佔用者收集

- 證據等級：`exact`（三支逐條讀完）
- 作法見 spec 783

## `dos overlay-28:000CCh`（82 條，`retf 0`）↔ `pc98 overlay-28:00016h`（52 條）

PC-98 那一支已在 spec 973 讀完。DOS 版是**完整版**：

```pascal
if DS:728Ah = 50h then DS:7580h := 0;
if DS:4FC7h <> 0 then 離開;

if word(遠指標(DS:4F99h)^[1CCh]) <> 0 then begin           { 在迷宮裡 }
    DS:7213h := <overlay-30 entry#6>(DS:720Fh, DS:7210h);
    if DS:7213h > 7Fh then                                  { 無號 }
        DS:720Ah := byte[0A88h + word(遠指標(DS:4F99h)^[1FCh])]
    else
        DS:720Ah := byte[0A88h + word(遠指標(DS:4F99h)^[1FAh])];

    if DS:4FE6h <> 0 then DS:720Dh := 8
    else if DS:8B67h <> 0 then begin                        { ★ PC-98 沒有這一段 }
        DS:720Bh := <巢狀 0016h>(DS:75E9h, bp);
        DS:720Ch := <巢狀 004Fh>(DS:75E9h, bp);
        DS:720Dh := <巢狀 0088h>(DS:75E8h, bp);
        <overlay-30 entry#2>(DS:720Ah, DS:720Bh, DS:720Ch, DS:720Dh);
    end;

    if word(遠指標(DS:4F99h)^[1F6h]) <> 0 then DS:720Eh := 0;
    <overlay-30 entry#7>(DS:720Fh, DS:7210h, DS:7211h);
end
else if DS:7580h <> 0 then
    <overlay-29 entry#10>();                                { 只顯示，不載入 }

DS:7580h := 0;
```

### 一次補齊九組跨平台全域對應

兩支的骨架逐句對得上，位址全部不同：

| DOS | PC-98 |
|---|---|
| `DS:728Ah` | `DS:0A325h` |
| `DS:7580h` | `DS:0A66Ch` |
| `DS:4FC7h` | `DS:7F34h` |
| `DS:4F99h` | `DS:7F05h` |
| `DS:720Ah`..`720Eh` | `DS:0A2A4h`..`0A2A8h` |
| `DS:720Fh`／`7210h`／`7211h` | `DS:0A2A9h`／`0A2AAh`／`0A2ABh` |
| `DS:7213h` | `DS:0A2ADh` |
| 表 `DS:0A88h` | 表 `DS:164Ch` |

`DS:720Ah`..`720Dh` 這四格由 `overlay-30 entry#2` 一次寫入
（spec 已記的「四個 byte 的 setter」），本支是它的呼叫端。

### ⚠ 兩處真實的平台差異

1. **PC-98 砍掉 `DS:8B67h` 那條分支。** DOS 在 `DS:4FE6h = 0` 且 `DS:8B67h <> 0`
   時會用三個巢狀程序（`0016h`／`004Fh`／`0088h`）算出 `720Bh`／`720Ch`／`720Dh`
   再一次寫入；PC-98 只留 `DS:0A2A7h := 8`（＝ DOS 的 `DS:720Dh := 8`），
   **另外兩格與那三支計算完全不存在**。
2. **平原分支 PC-98 多一次載入。** DOS 只叫 `overlay-29 entry#10`（顯示），
   PC-98 先叫 `entry#9(79h)` 載入 bigpic 121 再顯示。
   DOS 假設圖已經在記憶體裡，PC-98 每次自己載。

`DS:4FE6h` 與 `DS:8B67h` 的意義本規格不宣稱。

## `pc98 overlay-17:02DB7h`（76 條，`retf 4`）— 角色畫面的單一欄位重畫

`arg_0` 是**父層的 `bp`**（巢狀程序），`arg_2` 是反白旗標。
欄位編號取自 `ss:[父bp − 38h]`：

| 編號 | 動作 |
|---|---|
| 0..5 | `<overlay-19 entry#3>(arg_2, 編號)` ＝ 六個屬性的顯示（spec 已記） |
| 6 | `<overlay-24 entry#3>(arg_2, 12h, 4, DS:9594h)` ＝ HP 顯示（spec 643） |
| 7 | 名字：`arg_2 <> 0` 先叫 `0418h:0139h(名字長 ＋ 1, 1, 0, 1)`，再用顏色 `0Dh` 印；否則直接用顏色 `0Ah` 印 |

名字那一路直接把 `DS:9594h` 指到的**角色記錄本身**當字串傳給 `0418h:0D17h`——
角色記錄的 `+0` 就是 Pascal 字串形式的名字（既有結論），所以不需要另外取。
印在**欄 1、列 1**（`0418h:0D17h` 的簽章見 spec 973）。

編號 0..5 對應 spec 857 定案的六個屬性欄（`+11h` 力量、`+13h` 智力、`+15h` 睿智、
`+17h` 敏捷、`+19h` 體質、`+1Bh` 魅力）。**這一支是「反白／取消反白某一列」的
重畫器**：同一個欄位用兩種顏色各畫一次。

⚠ **顏色是硬編碼的 `0Dh`／`0Ah`**，不是查表。中文化不必動，但 remake 若要改
配色，這一支與 spec 970（名字依陣營選 `0Ch`／`0Eh`／`0Bh`）是**兩套獨立的
顏色來源**，不能只改一處。

### 中文化

名字那一路先用 `名字長 ＋ 1` 去叫 `0418h:0139h` 清出底色。
**那是半形格數**，中文名字用全形時每個字佔兩格（spec 953），
底色寬度會只有需要的一半——反白會蓋不滿。這一格是中文化必改的點。

## `pc98 overlay-22:018E4h`（74 條，`retf 2`）— 沿視線收集不重複的佔用者

`arg_0` 同樣是父層的 `bp`。

```pascal
repeat
    走完 := (<overlay-31 entry#3>(@父^[bp − 1Ch]) = 0);     { LOS Bresenham 推進 }
    父^[bp − 1Dh] := ord(走完);
    if not 走完 then begin
        <overlay-32 entry#9>(父^[bp − 0Eh], 父^[bp − 0Ch],
                             @父^[bp − 72h], @父^[bp − 73h]);   { 讀戰場兩平面 }
        i := 1;  已處理 := false;
        if 父^[bp − 72h] > 0 then                               { 無號 }
            repeat
                if      父^[bp − 72h + i] = 父^[bp − 72h] then 已處理 := true
                else if 父^[bp − 72h + i] = 0 then begin
                    父^[bp − 72h + i] := 父^[bp − 72h];
                    已處理 := true;
                end
                else inc(i);
            until 已處理;
    end;
until 走完;
```

`overlay-31 entry#3` 是 spec 已記的**視線 Bresenham 逐格推進**（狀態記錄在
`父bp − 1Ch`），`overlay-32 entry#9` 是**讀戰場兩個平面**。

外層一直推進到視線走完；每走一格就把該格的佔用者編號
（`父^[bp − 72h]`，來自地圖平面）**線性掃描地加進 `−71h` 起的清單**：
已經在清單裡就跳過，遇到第一個 `0` 就填進去。

**清單沒有上限檢查。** 迴圈只有「找到相同值」與「找到 0」兩個出口；
如果清單填滿而且沒有重複值，`i` 會一路加下去，**掃出清單範圍**。
以戰場最長對角線的格數推算通常不會發生，但 remake 要補界限——
這與 spec 741 記的那一類「沒有預設值」屬同一種原版寫法。

⚠ 空格（佔用者 ＝ 0）**整段跳過**，所以清單裡不會有 0，
「遇到 0 就填」這個哨兵才成立。
