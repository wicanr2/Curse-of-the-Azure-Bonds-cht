# 880 — 複製一張圖再貼上：二維圖庫表 `DS:65D6h`

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側只差一處長度算法）
- 作法見 spec 783

## `overlay-33:00508h` ↔ `overlay-33:007A9h`（DOS 111 條／PC-98 114 條）

`retf 0Ah` ＝ 5 個 byte。依推入順序宣告：
`(組, 編號, 模式, 座標A, 座標B)`。

```pascal
p := 遠指標(DS:65D6h ＋ 組 * 8 ＋ 編號 * 4);
if p = NIL then 離開;

<far 0297h:1C59h>(p^[0], p^[2], 1, 1, var 新);      { 依原圖尺寸建一張新的 }

if 模式 > 3 then                                     { 無號 }
    <far 0297h:0BB5h>(新, p)                         { 走轉換複製 }
else begin
    Move(p^[17h],            新^[17h],            p^[11h]);
    Move(遠指標(p^[13h])^,   遠指標(新^[13h])^,   p^[11h]);
end;

<far 0297h:09E4h>(遠指標(DS:4FE8h), 新, 1, 0, 座標A * 3, 座標B * 3);
<far 0297h:1D19h>(@新);                              { 釋放 }
```

## 圖庫表 `DS:65D6h`（PC-98 `DS:0A2A0h − 4`）

索引算式 `組 × 8 ＋ 編號 × 4` ＝ **每組 2 個遠指標**（`8 ÷ 4`）。
所以那是一張 `[組][0..1]` 的遠指標表。

## 圖的表頭

| 位移 | 內容 |
|---|---|
| `+0`（word） | 尺寸 A（傳給建圖常式的第一個參數） |
| `+2`（word） | 尺寸 B |
| `+11h`（word） | 第一平面的位元組數 |
| `+13h`（far） | 第二平面的位址 |
| `+17h` 起 | 第一平面的資料 |

`overlay-33:0002Eh` 用的是同一組欄位（`+11h`、`+17h`）。

**兩個平面**：一張圖由「`+17h` 起的內嵌資料」與「`+13h` 指出去的另一塊」組成
——形狀上是圖形平面與遮罩，本規格不定名。

## ⚠ 第二平面的長度兩平台不同

| | 第一次 `Move` 的長度 | 第二次 `Move` 的長度 |
|---|---|---|
| DOS | `p^[11h]` | `p^[11h]` |
| PC-98 | `p^[11h]` | **`p^[0] × p^[2]`（兩個尺寸相乘）** |

PC-98 的第二平面用寬高相乘算長度，DOS 兩次都用同一個 `+11h`。
這是真的邏輯差異（spec 783 第 d 類）。**spec 882 給出原因**：
PC-98 的 `+11h` ＝ 寬 × 高 × **3**（三個色彩平面），而 `+13h` 指出去的
遮罩只有寬 × 高 **一倍**。所以第二次 `Move` 必須用寬高相乘，不能用 `+11h`。
DOS 兩塊同大小，才能兩次都用 `+11h`。remake 要照原資料的平台各算各的。

## 座標乘 3

`far 0297h:09E4h` 的最後兩個參數是 `座標A × 3`、`座標B × 3`。
**呼叫端給的是格子座標，貼圖前換算成像素（一格 ＝ 3）**。
`遠指標(DS:4FE8h)` 是貼上去的目標畫面。

## 明確不宣稱

  （形狀上依序是 建圖／轉換複製／貼上／釋放）。
- 沒有宣稱 `模式 > 3` 走的那條轉換路徑做什麼轉換。
- 沒有宣稱 `+0`／`+2` 哪個是寬哪個是高。
- 沒有宣稱「一格 ＝ 3」的 3 是像素還是別的單位。
