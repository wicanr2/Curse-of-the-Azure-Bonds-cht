# 757 — VROOMM stub 重建、PC-98 圖檔載入，與職業欄位的三支查詢

- 證據等級：`exact`（逐條讀完）

## `START.EXE:1A4E3h` — 直接寫出 VROOMM stub

```asm
mov cx, es:0Ch          ; 項數
mov di, 20h             ; 從 +20h 開始
cld
loop:
    mov dx, es:[di+1]   ; 先讀走原本的 2-byte 描述子
    mov ax, 3FCDh
    stosw               ; CD 3F  = INT 3Fh
    mov ax, dx
    stosw               ; 2 bytes 描述子
    xor al, al
    stosb               ; 1 byte 補 0
loop
```

每項寫 **5 bytes**，從控制區塊的 **`+20h`** 開始，內容是 `INT 3Fh` ＋ 3 bytes。
這與既有的 stub 版面（`+20h` 起、5 bytes 一格、`CD 3F` ＋ 3-byte 描述子）完全
相符——而且這次是**產生端**的證據，不是由 stub 內容反推。項數取自控制區塊的
`+0Ch`。

前半段（`es:10h` / `es:12h` 那條鏈的搬移）是同一個管理結構的清理，本輪只讀懂
指令，沒有推論鏈上每個節點的意義。

## PC-98 `overlay-18:17F3h` — 載入 3 平面圖檔並置中貼上

```
out 0A6h, 1                          { 關中斷 }
開檔(檔名由 BX:CX 指定, AH=3Dh)
讀 4 bytes 檔頭 → 0C29h:7BCCh
寬位元組 := (檔頭[0] + 7) div 8       → DS:7BCAh
起點 := (80 - 寬位元組) div 2
起點 := 起點 + ((400 - 檔頭[2]) div 2) * 80     → DS:7BD0h
for 列 := 1 to 檔頭[2] do begin
    貼一列(A800h);  貼一列(0B000h);  貼一列(0B800h);
    起點 := 起點 + 80;
end
關檔；out 0A6h, 0
成功回 0，失敗回 0FFFFh
```

檔頭是兩個 word：**寬（像素）**與**高（列）**。畫面規格從程式碼直接讀出來：
每列 **80 bytes**、共 **400 列**，三個平面基底 `A800h` / `0B000h` / `0B800h`。
圖檔因此是三平面 8 色，**不含第四平面 `E000h`**。

搭配 spec 754 的 `overlay-18:1951h`（把 Pascal 字串就地改成 NUL 結尾後呼叫這
一支），整條路徑是「Pascal 字串檔名 → 開檔 → 置中貼圖」。

`0C29h` 是寫死的段值，這段程式不能重定位。

## PC-98 `overlay-18:17AAh` — 讀一個像素

`retn 4`，參數是 `(x, y)`：

```
位移 := y * 80 + x div 8
遮罩 := 80h shr (x and 7)
結果 := 0
for 平面 in (A800h, B000h, B800h) do        { bh 每次 +8 }
    if VRAM[平面:位移] and 遮罩 <> 0 then 結果 := 結果 or 位元;
    位元 := 位元 shl 1
```

同樣**只讀三個平面**，回傳 0..7。PC-98 的 16 色模式有四個平面，這支拿不到第四
個——與上面的圖檔格式一致，兩者都是 8 色。

## 職業欄位的三支查詢（`overlay-25`）

三支形狀相同，差別在「掃哪個區塊」與「回值還是回索引」：

| 函式 | 掃描範圍 | 回傳 | 找不到 |
|---|---|---|---|
| `134Ah`（spec 756） | `+109h`..`+10Fh` | 該格的**值** | 直接讀 `+110h`（越界一格） |
| `12EEh` | `+109h`..`+10Fh` | 該格的**索引** | `11h` |
| `1292h` | `+111h`..`+117h` | 該格的**索引** | `11h` |

PC-98 對應 `13F6h`（`+109h`）與 `139Ah`（`+111h`）。三支都先檢查
`p^[74h] = 7`，不成立就直接回失敗值。

`12EEh` / `1292h` 的迴圈同樣會在七格全零時把索引推到 7、再讀一次 `+110h` /
`+118h`，但**它們有檢查讀回來的值**（`> 0` 才採用），所以越界的那一格不會變成
結果。`134Ah` 沒有這層檢查。

## `overlay-32:0CAEh`（DOS）／`1363h`（PC-98）— 在指標表裡找索引

`retf 4`：從索引 1 開始，逐格比對 `DS:6D35h + i*4` 這個遠指標是否等於參數，
相等就回傳索引，走到 `DS:66A6h`（項數）還沒找到就回 0。PC-98 對應
`DS:9DCFh` 與 `DS:9740h`。

## `overlay-14:06F4h`（DOS）／`06C0h`（PC-98）— 找持有某值的隊員

`retf 2`，回傳遠指標：走隊伍鏈，對每個成員叫 `找格子(v, 成員)`（spec 755 的
`06B1h`），回傳值不是 `0FFh` 就停下並回傳該成員；整條走完沒找到就回 NIL。
spec 756 的 `0749h` 正是它的呼叫端。

## `overlay-15:206Bh`（DOS）／`20D2h`（PC-98）— 全隊受傷總量

`retf 2`（參數沒被讀）：走隊伍鏈，累加 `p^[78h] - p^[1A4h]`（最大 HP 減目前
HP），回傳 word。兩個欄位都是 byte 零延伸後相減，**目前 HP 大於最大 HP 時會
變成很大的正數**（沒有下限保護）。PC-98 用 `+1A5h`。

## `overlay-09:024Dh`（DOS）／`026Fh`（PC-98）

`retf 4`：

```pascal
if p^[18Dh]^[11h] <> 0 then f := false
else if (p^[109h] <= 0) and (p^[111h] <= p^[0E6h]) then f := false
else if not <overlay 呼叫>(p, @本地) then f := false
else begin <另一支>(p); f := true end;
```

`+109h` 用有號比較、`+111h` 與 `+0E6h` 也是有號。PC-98 戰鬥狀態在 `+18Eh`。

## `overlay-21:019Eh`（DOS）／`019Dh`（PC-98）— 金幣換白金幣

`retf 2`：

```pascal
for i := 0 to 4 do 四位元組表[DS:6F70h + i * 4] := 0;   { 5 格 }
DS:6F80h := 參數 div 5;   DS:6F82h := 0;                { 第 4 格 }
DS:6F7Ch := 參數 mod 5;   DS:6F7Eh := 0;                { 第 3 格 }
```

除法是**無號**的。`DS:6F70h` 起是 8 格 4-byte 的量，索引與金錢欄位名稱表
（`DS:0F93h`，見 spec 773）同一套：0 = Copper、1 = Silver、2 = Electrum、
3 = Gold、4 = Platinum、5 = Gems、6 = Jewelry。所以這一支寫的是
**`參數 div 5` → Platinum、`參數 mod 5` → Gold**——正是 5 金幣換 1 白金幣。
PC-98 對應 `DS:0A00Ah` 起。

## PC-98 `overlay-26` 的兩支

`13C7h`（`retf 4`）：釋放整條鏈，next 在 `+52h`、每節點 `56h`（86）bytes，
**離開前有把鏈頭寫回 NIL**。DOS 的對應功能是 `overlay-26:1241h`（spec 756），
節點 `2Eh`（46）bytes、next 在 `+2Ah`，而且**沒有清鏈頭**。兩平台在節點大小與
收尾行為上都不同。

`0BA9h`（`retf 4`）：參數是一個 SS 相對的記錄指標。先用 `+14h` 起的遠指標與第
二個參數叫本模組 `0011h` 取得一個遠指標，再呼叫
`0418h:0D17h(該指標, 0, [+20h], [+1Ch] + (參數 − DS:0A32Ch), [+1Eh])`。
`[+1Ch]` 的加減表示第二個參數是一個以 `DS:0A32Ch` 為基準的相對量。

## DOS `START.EXE` 的四支

`16566h`：反覆檢查 `'game.ovr'` 是否存在，不在就印
`'Please insert overlay disk.'` ＋換行、等一個按鍵，然後再試一次。**沒有離開
的出口**，找不到片就一直卡在這裡。

`1685Fh`：把參數字串複製進 `50h` bytes 的緩衝區，`FindFirst(路徑, 0, 記錄)`，
回傳 `(word_24E58 = 0) and (長度 <> 0)`。`word_24E58` 是 `DosError`。

`1B5F6h`：6-byte real 的 Horner 多項式求值。入口 `AX:BX:DX` 是 `x`、`CS:DI`
指向係數表、`CX` 是項數；迴圈用 `__RealAdd` / `__RealMul`，最後再加上
`CX=81h, SI=0, DI=0`——Turbo Pascal real 格式裡的 **1.0**。屬 RTL 的數學核心。

`1BF52h`：先檢查檔案記錄的 `+02h` 是否等於 `0D7B3h`（Turbo Pascal 的
`fmInOut`），不是就把 `word_20996`（`IOResult`）設成 `67h`（103，檔案未開啟）
並回 CF。通過的話用 `INT 21h AH=42h` 做三次 LSEEK：`AL=01h` 取目前位置、
`AL=02h` 取檔尾、`AL=00h` 移回原位置，把檔案大小放進 `BX:CX` 回傳。
