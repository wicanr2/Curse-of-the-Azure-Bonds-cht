# 第六百七十五輪：兩種像素深度的水平鏡射，與 blit 參數計算

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：DOS `START.EXE` 的 `13467h`、`14B53h`。

## `13467h`：16-bit 裡 8 組兩位元的順序反轉

八段 `and` ＋ 移位，遮罩取自 `DS:1E73Dh` 起的八個 word。實際讀出來：

| 位址 | 值 | 位元 |
|---|---|---|
| `1E73Dh` | `C000h` | `11000000 00000000` |
| `1E73Fh` | `3000h` | `00110000 00000000` |
| `1E741h` | `0C00h` | … |
| `1E743h` | `0300h` | |
| `1E745h` | `00C0h` | |
| `1E747h` | `0030h` | |
| `1E749h` | `000Ch` | |
| `1E74Bh` | `0003h` | `00000000 00000011` |

**八組互不重疊的兩位元**。移位量是 `+14`／`+10`／`+6`／`+2`／`−2`／`−6`／`−10`／
`−14`——每組移到對稱的位置。

**逐值驗算**：對 `0..65535` 全部比對「把 8 個 2-bit 群組順序顛倒」，
**不一致 0 筆**。

### 與 `133E2h` 成一套

| 函式 | 單位 | 一個 word／byte 裝幾個 |
|---|---|---|
| `133E2h`（[spec 674](674-ega-pixel-mask-and-bit-reverse.md)） | **1 bit** | 8 個 |
| `13467h`（本輪） | **2 bit** | 8 個 |

兩支都是「把 8 個單位的順序顛倒」，差別只在每個單位幾個 bit——也就是**同一個動作
（水平鏡射）在兩種像素深度下的兩個版本**。

遮罩放在資料段而不是寫死在指令裡，所以 `13467h` 的行為可以由資料改變；`133E2h`
的則是寫死的立即值。

## `14B53h`：blit 前的參數計算

```text
src := arg_0^ ; dst := arg_4^
var_8  := arg_A shl 3                       ← ×8
var_C  := var_8 × src^[2]
var_14 := arg_C
var_12 := src^[2] − dst^[2] − arg_C
var_6  := var_14 × 2
var_10 := dst^[2] × 2
var_A  := dst^[0]
var_14 := var_14 × 2
var_12 := var_12 × 2
var_E  := dst^[11h] × byte(arg_8)
var_C  := var_C × 2
bx := var_8 ; cx := var_A
var_1A := var_18 := var_16 := 0
<sub_15329>()
```

`arg_A shl 3` ＝ ×8——**一個 byte 裝 8 個像素**（1-bit 深度），與 `133E2h` 的單位
一致。

`src^[2]` 與 `dst^[2]` 是兩張圖各自的**每列位元組數**（stride）：`var_12` 算的是
「來源 stride 減目的 stride 再減 `arg_C`」，也就是**每畫完一列要跳過多少**。

`var_10`／`var_14`／`var_12`／`var_C` 最後都乘 2——所以 `sub_15329` 那邊是以
**word** 為單位前進。

`dst^[11h]` 與 [spec 673](673-ega-graphics-controller-reset.md) 的 `14689h` 用的是
同一個欄位（那裡拿它算釋放大小），所以兩支操作的是同一種圖形記錄。

`sub_15329` 是 `retn`（近呼叫）而這支是 `retn 0Eh`，參數靠暫存器 `bx`／`cx` 與
一整片區域變數傳遞——**不是堆疊參數**。

## 明確不宣稱

- `sub_15329` 實際怎麼畫。
- 圖形記錄 `+0`／`+2`／`+11h` 以外的欄位。
- `arg_8`／`arg_C` 的語意。
