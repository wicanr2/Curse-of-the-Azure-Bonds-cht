# 第一千二百五十二輪：建角框畫面的文字安全區

狀態：`READY`

## 適用範圍

`gfx.ExtendedCharacterCreationFrame()` 這個框由兩類畫面共用：

- 建角與外層隊伍組裝（`drawCreation`，spec 1246 外層流程）
- 正常 `CAMP → VIEW → 角色` 的角色資料頁（`drawCharacterView`，spec 1246 VIEW）

它和冒險框（`ExtendedAdventureFrame`）**不是同一個版面**，兩者的可寫字區間不同。

## 框的幾何

框本身是 320×240 素材，繪製時 `GeoM.Scale(2, 2)` 放大到 640×480。在 640×480
座標下，框有兩條橫向不透明帶：

| 帶 | y 範圍（640×480） | 作用 |
|---|---|---|
| 中間分隔帶 | 352..361（含 366..367 的裝飾） | 分開上面板與下面板 |
| 底部框帶 | 448..457（含 462..463 的裝飾） | 版面下緣 |

因此文字只有兩個落點：**上面板** `..351`、**下面板** `368..447`。

## 契約

1. 下面板的提示文字一律用 `creationFrameHelpBaseline = 438`。它讓 16×15 的 CJK
   字連同下伸部完整落在 `368..447` 之內。
2. 上面板右欄的隊伍人數用 `creationFramePartyCountY = 340`，位在隊伍成員清單
   （最低 `y = 140 + 5*30 = 290`）之下、中間分隔帶之上。
3. **`adventureCommandBaseline`（478）不得用於這個框的任何畫面。** 那個值屬於
   冒險框的延伸指令列內部（`y = 464..479`），畫在建角框上會整行沒入底部框帶：
   字仍然畫得出來，但被框的像素蓋住，畫面上只剩上半截。
4. `safeBottomBaseline` 擋不住這一類：它只在 `modern-a6` theme 生效，而且是為
   冒險框的下緣（`y = 454`）算的，不是這個框。

## 為什麼要機械檢查

這條規則的失效方式是「文字有畫出來、只是被蓋住」，而不是缺字或崩版。逐張人工
檢視會漏——**spec 1246 兩份的驗證段都寫過「文字留在框內」，而底部提示當時就是
被蓋住的**。所以基線改由測試對著框本身驗：

`cmd/azure-bonds-game/creation_frame_baseline_test.go` 掃 `ExtendedCharacterCreationFrame()`
自己的不透明橫帶，算出空白區間，再斷言上列每個基線連同下伸部都落在空白裡。
框帶座標不寫死在測試裡，框改了測試跟著改。

同檔案帶一則正對照：`adventureCommandBaseline` 必須被判為不安全。它若通過，
代表安全區的量測失效，主測試也就測不到東西。

## 驗證

- `go test ./cmd/azure-bonds-game` 通過，含上述兩則。
- Docker／Xvfb 實拍：角色 VIEW 底部提示（`選擇 <名字> 要整備或卸下的物品`）
  與外層選單的 `隊伍人數：0／6` 都完整可讀。
- 回歸對照：`-guided-creation`、`-inn`、`-camp-row camp` 三張截圖與修正前
  **逐位元組相同**，確認改動沒有波及其他版面。

證據等級：框的橫帶位置為 `exact`（量自素材本身）；基線值為
`layout-reconstructed`，理由是 CJK 字距與原版 DOS 的英文行距本來就不同。
