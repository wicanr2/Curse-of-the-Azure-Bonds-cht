# 1051 — 開檔的兩個搜尋路徑：開不到就把兩條路徑對調再試

- 證據等級：`exact`（PC-98 常駐段 231 條逐條讀完，`objdump` 路線見 spec 1046／1048）
- 作法見 spec 783

## `pc98 PC98-GAME.EXE:1741Dh`（`retf 0Eh`，569 bytes）

原本待解讀。唯一呼叫端 `17960h`。五個參數（`4 ＋ 4 ＋ 2 ＋ 2 ＋ 2 ＝ 14`）：

| `bp` | 內容 |
|---|---|
| `+10h` | 檔名（字串，上限 80） |
| `+0Ch` | 第二個字串（上限 80） |
| `+0Ah` | 一個 byte 旗標（非 0 時不重試） |
| `+08h`／`+06h` | 兩個 word |

## ★★ 兩條搜尋路徑

| 位址 | 角色 |
|---|---|
| `DS:8CFCh` | **目前的搜尋路徑**（上限 `43h` ＝ 67） |
| `DS:7EACh` | **備援路徑**（上限相同） |

★ 兩者在靜態映像裡都是 `0FFh`，**執行期才填**。

## 流程

```pascal
A := Copy(檔名, 1, 50h);  B := Copy(第二個字串, 1, 50h);
<far 08BD:0289h>(A, @目錄, @主檔名, @副檔名);        { FSplit }
if 目錄 = '' then 目錄 := DS:8CFCh;                  { 補上預設路徑 }
repeat
    完整 := 目錄 ＋ 主檔名 ＋ 副檔名;
    成功 := <sub_7FF6h>(完整, …);
    if 成功 then break;
    if 目錄 <> DS:8CFCh then break;
    { ★★★ 兩條路徑對調 }
    暫存    := DS:8CFCh;
    DS:8CFCh := DS:7EACh;
    DS:7EACh := 暫存;
    目錄    := DS:8CFCh;
until 旗標 <> 0;
```

> ★★★ **開不到就把 `DS:8CFCh` 與 `DS:7EACh` 對調再試一次**，
> 而且**對調是持久的**——下一次開檔會先試剛才成功的那一條。
> ⇒ 這是多磁片遊戲的「記住玩家把片子放在哪個磁碟機」機制，
> 與 spec 1038 的 `'Insert disk B/C/D in drive '` 是同一組問題的兩半。

## ★ 失敗之後看磁碟機字母

```pascal
if (not 成功) and (旗標 = 0) then begin
    if 目錄[1] = 'B'(42h) then <sub_7C75h>(B, …, 0Eh)
    else if 目錄[1] > 'B'  then
        <sub_7C75h>(主檔名 ＋ 副檔名 ＋ CS:01BCh, …, 0Eh);
    { 之後再回到迴圈頭重試 }
end;
```

★ **`'B'` 與「大於 `'B'`」分成兩條路**——形狀上是
「B 槽（第二台軟碟）」與「C 槽以上（硬碟／第三台）」給的提示不同。
★ 兩條都把樣式參數 `0Eh` 傳給同一支 `sub_7C75h`（形狀上是提示視窗）。

⚠ `CS:01BCh` 那個接在檔名後面的字串沒有讀到
——常駐段是多程式碼段，`push ds` 這裡指的是資料段，
但 `01BCh` 在資料段是別的東西；本規格**不宣稱**它的內容（同 spec 1047 的邊界）。

## 中文化

★ 兩個提示都走 `sub_7C75h`，訊息本身在別處組。
⚠ **路徑字串上限是 `43h` ＝ 67 bytes**，中文化不影響（路徑是 ASCII）。

## 明確不宣稱

- 沒有宣稱 `sub_7FF6h`（實際開檔）與 `sub_7C75h`（提示）的介面。
- 沒有宣稱 `far 08BD:0289h` 是不是 Turbo Pascal 的 `FSplit`
  （形狀相符：一個輸入、三個輸出）。
- 沒有宣稱 `bp+08h`／`bp+06h` 兩個 word 參數是什麼。
- 沒有宣稱 `CS:01BCh` 的內容（理由見上）。
- 沒有宣稱 `DS:8CFCh`／`DS:7EACh` 的初值由誰設定。
