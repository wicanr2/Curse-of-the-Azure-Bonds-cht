# 1143 — 世界地圖的路段編號 `4C9D`

- 證據等級：`exact`（`ECL1/0x50` 與 `0x51` 的指令逐條讀出）
- 作法見 spec 783
- 查詢工具：`cmd/ecl-cell-refs -cell 4C9D`、`cmd/ecl-window -gettable`

## 結論

**`4C9D` ＝ 出發地 × 4 ＋ 選的第幾個方向**，也就是世界地圖上一條**有向邊**的編號。
四張表都用它當索引，一段旅途的所有性質都是查表查出來的。

## 抵達一個地點時：算出基底、載入四個鄰居

`ECL1/0x50` 位移 `0x0FBE` 起：

```
MULTIPLY 4C9C, 4      → 7F79      { 4C9C ＝ 現在在哪個地點 }
SAVE     7F79         → 4C9D      { 基底 ＝ 地點 × 4 }
GETTABLE 0x9C02, 7F79 → 4C02      { 四個鄰居載進 4C02..4C05 }
ADD      1, 7F79      → 7F79
GETTABLE 0x9C02, 7F79 → 4C03
```

`4C02..4C05` 就是 remake 的 `syncWorldDestinationSelectors` 在填的那四格。

## 選好目的地之後：基底加上選的方向

位移 `0x0E32`／`0x0E47` 的 `VERTICAL MENU` 把玩家選的索引放進 `7F79`，接著：

```
GETTABLE 4C02, 7F79   → 4C9C      { 選中的鄰居成為新的「現在在哪」}
ADD      7F79, 4C9D   → 4C9D      { 基底（出發地 × 4）＋ 選的第幾個 }
GETTABLE 0x9C3A, 4C9D → 4C06      { 這一段要走幾天 }
GETTABLE 0x9C72, 4C9D → 4C08      { 這一段有幾種走法 }
```

⚠ `4C9C` 在 `ADD` 之前就被改成目的地了，而 `4C9D` 的基底是**抵達出發地時**算的
——所以 `4C9D` 記的是「從哪裡往哪個方向」，不是「現在在哪裡」。

## 四張表

| 表 | 存進 | 用途 |
|---|---|---|
| `0x9C3A`（`0x51` 是 `0x9C96`）| `4C06` | 旅行天數，餵給 `ECL CLOCK 4C06, 4` |
| `0x9C72`（`0x51` 是 `0x9CCE`）| `4C08` | 這一段有幾種走法（`HOW WILL YOU GET TO …?` 的選項數）|
| `0x9D13`（`0x51` 是 `0x9D6C`）| `4CA1` | 到達的地點編號；`0xFF` ＝ 那個方向沒有路 |
| `0x9CAA`（`0x51` 是 `0x9D06`）| `7F7A` | **旅途場景**，接 `ON GOTO`（14 個）|

⚠ `4CA1` 是引擎側也讀的共用格子（`overlay-10:0FC7`，見 `docs/audit/ecl-shared-cells.md`）。

## 旅途場景

`0x9CAA` 那張表把每一條有向邊對到 14 支處理常式其中一支：暗影隘口的新客棧、
無法翻越的山壁、天空的黑影、溫拉爾的敗兵、匕首谷的田野、河岸的蜥蜴人、
紫色腰帶的女騎士、火刀的伏擊（四個變體）、半人馬的款待。

表的開頭：`0→0`、`1→1`、`2→0`、`3→13`、`4→0`、`5→6`、`6→4`、`7→2`、`8→1`、
`9→6`、`10→11`、`11→13`、`12→4`、`13→5`…（完整內容由 `cmd/ecl-cell-events`
產生在 `docs/audit/ecl-cell-events.md`）。

⚠ 表**沒有宣告長度**。工具探測前 48 個索引；索引上界應該是「地點數 × 4」，
但地點數本身還沒從原作讀出來，所以不宣稱表到哪裡結束。

## 明確不宣稱

- 沒有宣稱地點編號 `4C9C` 的完整清單與名字對應——game pack 的世界地圖宣告是
  另一份來源，兩者還沒逐格對過。
- 沒有宣稱 `4C08`（走法數）的三種走法各是什麼。
- 沒有宣稱旅途場景會不會受旅行天數或隨機影響——只確認索引是 `4C9D`。
