# 1119 — 戰術地圖的兩種障礙格：`1Eh` 擲豁免、`1Ch` 看等級

- 證據等級：`exact`（`overlay-32 entry#19`、`overlay-24 entry#27`、
  `overlay-23 entry#8` 三支 DOS 側逐條讀完；呼叫端 `overlay-09 sub_735`
  的十個效果碼逐一取自 `mov al, xx` 立即數）
- 對應工作項：`RE-07` → `ENG-08` 的「移動的障礙豁免效果」
- far call 的解析方式見 spec 1112

## `far 193Eh+1` 是什麼

spec 837 把它記成「沒有宣稱回填的四個值分別是什麼」。用 spec 1112 的對照表解出來
是 **`overlay-32 entry#19`**（DOS 側 `sub_D06`，147 條，`retf 16h` ＝ 11 個 word，
與呼叫端的 `(角色, d, @a, @地形, @b, @c)` 對得上）。

它做的事是**把腳印的四個格子各查一次**：

```pascal
a := 0;  地形 := 17h;  b := 0;  c := 0;  最貴 := 1;
形狀 := <overlay-32 sub_CAE>(角色);
基準X := byte[66A3h + 形狀 * 4];
基準Y := byte[66A4h + 形狀 * 4];

for 序號 := 0 to 3 do begin
    if not <sub_11>(byte[66A6h + 形狀 * 4], 序號, @dx, @dy) then 繼續;

    X := byte[2694h + d] + dx + 基準X;      { 2694h／269Dh ＝ 八方向的 dx／dy }
    Y := byte[269Dh + d] + dy + 基準Y;
    <sub_509>(X, Y, @佔位者, @地形碼);

    if 佔位者 = 形狀 then 佔位者 := 0;      { 查到自己不算 }
    if 佔位者 > 0 then a := 佔位者;

    if (地形碼 = 0) or (地形 = 0) then begin 地形 := 0; 繼續 end;   { 出界，黏住 }
    if 地形碼 = 1Eh then begin b := 1; 繼續 end;
    if 地形碼 = 1Ch then begin c := 1; 繼續 end;

    if byte[26A2h + 地形碼 * 4] >= 最貴 then begin
        最貴 := byte[26A2h + 地形碼 * 4];
        地形 := 地形碼;                      { 四格取最貴的那一格 }
    end;
end;
```

所以 spec 837 那四個回填值分別是：

| 值 | 是什麼 |
|---|---|
| `a` | 擋路的**人**（腳印四格裡任一格有別的戰鬥員） |
| `地形` | 四格裡**最貴**的那一格的地形碼；任一格出界就變 0 並黏住 |
| `b` | 四格裡出現過地形碼 **`1Eh`** |
| `c` | 四格裡出現過地形碼 **`1Ch`** |

`b`／`c` 不是抽象旗標，是**兩個特定的地形碼**。它們不進成本表 `26A2h`，
走的是呼叫端另一條路。

## 兩種障礙的通行條件

呼叫端 `overlay-09 sub_735` 的十次 `<overlay-24 entry#27>(角色, 碼, @游標)`
立即數逐一讀出來：

| | 觸發 | 照走的條件（任一成立） |
|---|---|---|
| `1Eh` | `b ≠ 0` | 效果 `20h`／`1Eh`／`6Fh`／`7Dh`／`81h`／`3Fh` 之一；或 `+18Dh^[10h] ≠ 0`；或**豁免過關** |
| `1Ch` | `c ≠ 0` | `有號(+0E5h) ≥ 7`；或效果 `81h`／`6Fh`／`85h`／`7Dh` 之一；或 `+18Dh^[10h] ≠ 0` |

兩張效果清單**只有部分重疊**：`20h`／`3Fh`／`1Eh` 只在 `1Eh` 那一張，
`85h` 只在 `1Ch` 那一張，`6Fh`／`7Dh`／`81h` 兩張都有。照抄成同一張清單會讓
兩種障礙變成同一種。

條件都不成立時原作把花費設成 `剩餘移動力 + 1`——不是 return。兩個障礙區塊依序
執行，後面那個會覆蓋前面算出來的花費（spec 837 §「兩種障礙」）。

## `有效果` 是走效果串列比第一個位元組

`overlay-24 entry#27`（`sub_2396`）：

```pascal
游標^ := 角色^[0F2h];                    { 效果串列頭，far pointer }
while (游標^ <> nil) and not 命中 do
    if byte[游標^^ + 0] = 碼 then 命中 := true
    else 游標^ := 游標^^[5];             { +5 ＝ 下一節 }
```

節點的 `+0` 就是 spec 731 的 `PUTEFFECT` 寫進去的 `表[法術編號].+0Ah`——
**兩邊同一個命名空間**。

⚠ 拿法術主表（spec 1111）的 `+0Ah` 反查這幾個碼會得到「臭雲術」（`1Eh`）、
「死者復生」（`20h`）、「次級無敵球」（`3Fh`），名字和「可以穿過障礙」對不上。
那不是對照表壞了，是**效果碼命名的是效果不是法術**：一個碼可以被好幾支法術套上，
而碼本身的語意仍未解讀。`6Fh`／`7Dh`／`81h`／`85h` 在法術表裡完全沒有出現，
所以那幾個只能來自道具或怪物本身的能力。

## `far 1458h` 是豁免擲骰

`overlay-23 entry#8`（`sub_12EB`）：

```pascal
點數 := 1d20;
if 點數 = 1  then 過 := false                  { 天然 1 一定失敗 }
else if 點數 = 20 then 過 := true              { 天然 20 一定成功 }
else begin
    總和 := 點數 + 角色^[186h] + 修正;
    <sub_3FE>(角色, 0Ch);                      { 重算某組衍生值 }
    過 := byte[角色^[0DFh + 類別]] <= 總和;
end;
```

`0DFh` 起是五張豁免門檻表，`類別` 是索引。障礙 `1Eh` 呼叫的是
`far 1458h(角色, 0, 0)` ＝ **類別 0、修正 0**。

天然 1／天然 20 這兩條之前不在 remake 的豁免路徑裡；本輪連同效果類法術的豁免
一起改走同一支。

## remake 這一側

`internal/combat/ai_obstacle.go`：

- `ObstacleTerrainSaveable`／`ObstacleTerrainVeteran` ＝ `1Eh`／`1Ch`
- `ObstacleTerrainBlocks(角色, 碼, 豁免旗標, save)` ＝ 上表兩列；
  `save` **只有在前面每一條都不成立時才會被呼叫**（原作是短路求值，
  多擲一次骰亂數序列就分家了）
- `Battle.SetCombatTerrainCodes` 掛地形碼查詢；沒掛就沒有障礙格，
  與加這一層之前的行為相同
- `Battle.RollSavingThrow` ＝ `overlay-23 entry#8`
- `Fighter.RawCombatState10` ＝ `+18Dh^[10h]`，語意未解讀但照原樣留著

`Fighter.HitDice` 本來就是 `+0E5h` 那一個位元組，等級判斷直接 `int8(...)` ＝ 有號。
`80h` 是 −128 不是 128——`TestVeteranObstacleReadsTheLevelByteAsSigned` 釘住這一點。

## 明確不宣稱

- 沒有宣稱地形碼 `1Eh`／`1Ch` 在畫面上長什麼樣、對應原作手冊的哪個名詞。
- 沒有宣稱效果碼 `1Eh`／`20h`／`3Fh`／`6Fh`／`7Dh`／`81h`／`85h` 各是什麼效果。
  remake 照碼比對，不替它們取名字。
- 沒有宣稱 `+18Dh^[10h]` 是什麼；只知道它不為 0 時兩種障礙都放行。
- 沒有宣稱 `overlay-32 sub_CAE`（回傳「形狀」）與 `sub_11`（依形狀展開四個腳印
  偏移）的完整對照，只知道它們是腳印那一層。
- 沒有宣稱 `sub_3FE(角色, 0Ch)` 在豁免中重算了什麼。
