# 766 — 借用目標欄位的慣用法、84 格排序、`'%'` 這個腳本記號

- 證據等級：`exact`（以補洞後的匯出逐條讀完，見 spec 761）

## `overlay-13:1144h`（DOS）— 暫時借用「目前目標」欄位

`retf 8`，兩個遠指標：

```pascal
function 可以嗎(甲, 乙: 遠指標): boolean;
var 原本 : 遠指標;
begin
    可以嗎 := false;
    if 甲 = NIL then 離開;
    if 乙 = 甲 then begin 可以嗎 := true; 離開 end;
    DS:6F9Bh := 0;                       { 中止旗標 }
    <呼叫>(1, 甲);
    if DS:6F9Bh = 0 then begin
        原本 := 乙^[18Dh]^[0Ah];         { 目前目標 }
        乙^[18Dh]^[0Ah] := 甲;           { 借用 }
        <呼叫>(0, 乙);
        乙^[18Dh]^[0Ah] := 原本;         { 還回去 }
    end;
    可以嗎 := (DS:6F9Bh = 0);
end;
```

`+18Dh^[0Ah]` 就是既有的「目前鎖定的目標」（spec 719 寫入、spec 755 的
`overlay-08:1314h` 清除）。這裡的用法是**把它當成傳參數的通道**：呼叫的那支
程序只認得「乙的目標」，所以要問「乙對甲做得到嗎」就得先把甲塞進去、問完再
還原。

`DS:6F9Bh` 是被呼叫端設的中止旗標；本支負責清零、事後檢查。與 spec 758 的
`DS:6F9Ah`（`overlay-13:0124h` 用的那個）是相鄰但不同的旗標。

**這個慣用法對 remake 的意義**：不能把「目前目標」當成純狀態，它同時是參數
傳遞的暫存位置。中途離開（例外、提早 return）會留下錯誤的目標。

## `overlay-15:085Ch`（DOS）— 把 84 格排序

`retf`，不收參數，對象是 `DS:6506h`（目前角色）的 84 格陣列（spec 755）：

```pascal
for i := 0 to 52h do
    for j := i to 53h do
        if (角色^[1Eh + i] and 7Fh) > (角色^[1Eh + j] and 7Fh) then begin
            暫 := 角色^[1Eh + i];
            角色^[1Eh + i] := 角色^[1Eh + j];
            角色^[1Eh + j] := 暫;
        end;
```

典型的選擇排序，**比較時遮掉最高位、交換時整個 byte 一起搬**——所以最高位的
旗標跟著值走。遞增排序。

外圈到 `52h`、內圈到 `53h`，兩層都是無號比較，沒有提早結束的條件：
**固定跑 `84 × 85 / 2` 次比較**，與資料是否已排序無關。

## `overlay-02:1A9Bh`（DOS）— `'%'` 在腳本流裡是跳躍記號

`retf`，不收參數：

```pascal
完成 := false;
<呼叫>(2);
選擇 := <呼叫>(1);
筆數  := <呼叫>(2);
dec(DS:4FB4h);
<呼叫>(筆數);
i := 0;
while (i < 筆數) and not 完成 do
    if 選擇 = i then begin
        if DS:75FFh = '%' then
            DS:4FB4h := <呼叫>(byte[76C5h + i + 1], byte[7705h + i + 1])
        else
            <呼叫>(i + 1);
        完成 := true;
    end else inc(i);
```

`DS:75FFh` 是 spec 759 的 `overlay-02:3621h` 每輪從 `DS:4FA5h` 讀進來的那個
byte，`DS:4FB4h` 是它的位置。所以這一整組是**腳本／文字流的直譯器**，而
`'%'`（`25h`）是流裡的一個記號：碰到它就不走一般分支，改用兩張平行的 byte 表
`DS:76C5h` 與 `DS:7705h`（相距 `40h` ＝ 64）算出新的位置，等於**跳躍**。

兩張表都以 `i + 1` 索引（1 起算），所以第 0 格沒有用到。

## `START.EXE:1507Ah` 與 `1510Fh` — 兩支成對的繪圖前置

兩支都是 `retn 0Eh`（7 個 word），把兩個點陣圖表頭的欄位算成 13 個 local 之後
分別跳進 `sub_15329h` 與 `sub_15388h`。相同的部分：

```
var_8  := 參數A shl 3                       { ×8 }
var_C  := var_8 * 來源^[2]
var_14 := 參數B
var_12 := 來源^[2] − 目的^[2] − 參數B
var_6  := 參數B shl 2
var_10 := 目的^[2] shl 2
var_A  := 目的^[0]
var_14 := var_14 shl 2
var_12 := var_12 shl 2
var_E  := 目的^[11h] * 參數C
var_C  := var_C shl 2
BX := var_8;  CX := var_A
var_1A := 0;  var_18 := 0;  var_16 := 0
```

`1510Fh` 比 `1507Ah` **多讀兩個欄位**：`var_4 := 目的^[13h]`、
`var_2 := 目的^[15h]`。

由此可以讀出點陣圖表頭的一部分：`+00h` 與 `+02h` 是兩個 word（`+02h` 參與寬度
運算），`+11h` 是另一個 word（乘上第三個參數），`+13h`／`+15h` 只有第二支用到。
兩支都 `sub sp, 1Ch` **兩次**（配置 `38h` bytes），這是編譯器把兩層 local 分開
配置的結果，不是重複的指令。
