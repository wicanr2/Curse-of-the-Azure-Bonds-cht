# 788 — 角色 `+1Eh` 起那 84 格就是「記憶中的法術」

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側的運算元差異已逐條列出）
- 作法見 spec 783

## `overlay-15:0282h`（entry#8，63 條，差異 6 條）

```pascal
已記 := 0;
for i := 0 to 53h do begin
    v := 角色^[1Eh + i];
    if v > 0 then begin                            { 無號 }
        s := v and 7Fh;                            { 低 7 位 = 法術編號 }
        if (byte[37DBh + s * 10h] = 等級)          { 法術屬性表 +1 }
           and (byte[37DAh + s * 10h] = 職業) then { 法術屬性表 +0 }
            inc(已記);
    end;
end;
結果 := 角色^[12Ch + 職業 * 5 + 等級] − 已記;
```

這一支把三件先前分開的事一次接起來：

### 一、`+1Eh` 起那 84 格是**記憶中的法術**

格子裡的值直接當**法術編號**去查 `DS:37DAh` 的法術屬性表（16 bytes 一筆，
spec 773 已把 56 筆全部排出來），比對 `+0`（職業類別）與 `+1`（等級）。

這解釋了先前四支只知道形狀的函式：

| 函式 | 先前的描述 | 現在的意義 |
|---|---|---|
| `overlay-15:0188h`（spec 755） | 清掉 `> 7Fh` 的格子 | 把**還沒記完**（最高位為 1）的格子清掉 |
| `overlay-14:06B1h`（spec 755） | 找值等於 `v` 的索引 | 找某個法術記在第幾格 |
| `overlay-15:085Ch`（spec 766） | 依低 7 位遞增排序 | 把記憶的法術按編號排好 |
| `overlay-14:0749h`（spec 756） | 移除值為 `1Fh` 的格子 | 移除編號 `1Fh`（31 ＝ `Knock`）的那一格 |

**最高位是「還在記憶中」的旗標，低 7 位是法術編號**（由 spec 792 的
`'has memorized'` 訊息定出來）——這也解釋了為什麼排序時遮掉最高位比較、卻整個
byte 一起搬。本支計數時**不分最高位**，所以記到一半的法術照樣佔格子。

### 二、`+12Ch` 是每職業每等級的可記憶數

索引式是 `+12Ch + 職業 * 5 + 等級`，所以**每個職業佔 5 個 byte**。回傳的是
「還能再記幾個」（可記憶數 − 已記數），可能為負（byte 相減，會迴繞）。

### 三、法術屬性表的前兩欄坐實

`+0` ＝ 職業類別、`+1` ＝ 等級——與 spec 773 排出來的表相符（`+0` 只出現
`00`／`02`／`03`，`+1` 是 `1`..`7`）。

PC-98 的法術屬性表在 `DS:61B4h`。

## `overlay-13:41CCh`（entry#44，63 條，差異 10 條）

```pascal
ss:[rec − 5] := 1;
if not 本模組 3E56h(參數2, 0, 0FFh, ss:[rec + 0Ch]) then 離開;
x1 := <取 x>(某人^[18Dh]^[0Ah]);        { 「目標的目標」的座標 }
y1 := <取 y>(某人^[18Dh]^[0Ah]);
if <呼叫>(<取 x>(ss:[rec + 0Ch]), <取 y>(ss:[rec + 0Ch]),
          @x1, @y1, @ss:[rec − 3], 遠指標@DS:6E92h) <> 0 then
    ss:[rec − 5] := 0;
```

`<取 x>` / `<取 y>` 是 spec 759 認過的 `overlay-32 entry#15 / #16`。輸出旗標
`ss:[rec − 5]` **預設為 1**，只有兩個條件都通過才改成 0——所以「1」是預設的
拒絕值。
