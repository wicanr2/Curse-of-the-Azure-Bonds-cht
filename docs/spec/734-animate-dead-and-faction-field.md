## `+197h` 是陣營

`p^[197h] := DS:6506h^[197h]`——把目標的這個欄位**直接改成施法者的值**，而效果
的名稱是 `is animated`。一個「被操縱的屍體變成我方」的動作只會改陣營。

原值沒有丟掉：`v := (原 +197h shl 4) + 等級` 被打包成一個 byte 交給
`PUTEFFECT`，所以**效果結束時可以還原陣營**。`shl 4` 表示陣營值只用低 4 位，
等級也只有 4 位。

這回頭解釋了另外兩支：spec 692 `25D4h` 用 `+197h` 當統計陣列的索引（只清了
兩個 byte ＝ 兩個陣營），spec 709 `1C39h` 用它篩選目標（同陣營／不同陣營）。
三處一致。

## 效果 `20h` ＝ animated，而且是永久的

`PUTEFFECT` 的第三個參數（持續時間，spec 724）在這裡是**常數 0**，不是
`sub_E11h` 算出來的值。所以這個效果不會自己過期。

spec 707 的復活（`44D3h`）會 `<entry#3>(p, 20h, 0)` 解除 `20h`——**把被操縱的
屍體正式復活時要先解掉 animated**。兩處對得上。

## 額度的計算方式

`額度 := entry#36(法術編號)` 只算一次，之後每成功操縱一具就減 1。但迴圈裡又
呼叫了 `entry#36` **第二次**去算 `v` 裡的等級部分——同一個參數、同一個結果，
沒有共用。

`額度 > 0` 是**迴圈條件**，所以額度用完就整個停下來，不像 spec 715 的 Sleep
會繼續掃完並清掉剩下的。

## 一個沒有邊界的清除

`for i := 0 to 53h do p^[1Eh + i] := 0` 清掉 `+1Eh`..`+71h` 共 84 bytes。
迴圈上界是寫死的 `53h`，沒有任何檢查。
