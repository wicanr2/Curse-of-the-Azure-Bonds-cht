# 1235 決定性 CAST 重放與塔頂法術恢復

狀態：`READY`（2026-08-27）

## 開場戰停格的實際成因

一般強度鍵盤測試先前同一命令有時到 `0x33`、有時在 `0x01` 皇家衛兵戰按數千次
仍不動。停格快照證明 active fighter 是活著的手動牧師、沒有視覺事件、CAST
快捷 gate 與選單都有祝福；不是 engine 隨機失去 turn。

根因有兩層：

1. 前端戰鬥動畫用真實 `time.Since`，鍵盤測試的模擬幀是緊密迴圈。測試現在由
   `app.combatNow` 注入決定性 renderer clock；正式 app 未注入時仍使用 `time.Now`。
2. MEMORIZE 重放用 Go `map` 迭代法術，slot 順序每次不同；CAST 重放卻固定按第 0
   項。當第 0 項不是祝福，就會關掉選單後再次按 C。整備改用有序 slice，戰鬥選單
   也依穩定 `SpellID` 移動游標，不再依索引猜法術。

修正後同一正常強度命令連跑 20 次，20 次完全相同：第 1,967 幀停止、259 格、
8 個 ECL block、196 句中文、58 次快速戰鬥、原文 fallback 0；全部通過
`0x01 → 0x02 → 0x03 → 0x04 → 0x50 → 0x31 → 0x32 → 0x33`。報表另加硬閘門：
一般強度跑滿幀數仍只到 `0x01` 會直接失敗，不再把停格印成 PASS。

## 安全休息要同時補法術

城市與塔頂的 REST 先前只看「是否至少還有一格法術」，會把殘缺 loadout 當完成；
塔頂因此顯示恢復 197 HP、完成 0 名角色記憶。現在以完整 loadout 判斷：牧師須各有
祝福、詛咒、治療輕傷、造成輕傷、防護邪惡一格，法師須有四格燃燒之手。安全休息
會重新走正式 MAGIC → MEMORIZE → REST，只補選單星號顯示不足的槽。

實跑結果：城市休息恢復 162 HP 並完成 2 名角色記憶；塔頂恢復 197 HP 並完成 2 名
角色記憶。沒有直接寫 HP、SpellSlots 或遊戲時鐘。

## 新的正常強度瓶頸

`ECL5/0x33` `(3,1)` 的樓梯後是強制黑暗精靈領主戰：領主 108 HP、AC 0、攻擊加值
10、每回合兩擊。補滿法術後 QUICK 會使用詛咒、造成輕傷、治療及阿卡巴的臭雲，
但延遲法術落地前隊伍仍敗戰；ECL 允許敗戰後移動，下一座樓梯才把全員 0 HP 投影
成正式全滅。

控制實驗：在 `(3,1)` 選「否」後 5,000 幀反覆回到同一樓梯，無法步行到其他房間；
已撤回該選項實驗。因此下一步不是繞路，而是閉合這場戰鬥所需的正常玩家戰術或
尚未接入的五級角色法術能力，再用同一按鍵路線驗證。
