# 912 — 八格防禦數值：盾只保護前兩格

- 證據等級：`exact`（PC-98 側逐條讀完；**DOS 側有兩段反組譯錯位**，由 PC-98 校正）
- 作法見 spec 783

## `overlay-25:00AD8h`（DOS 225 條）↔ `overlay-25:00AC4h`（PC-98 224 條）

`retf 4` ＝ 一個角色遠指標。

```pascal
盾 := 0;   特殊 := 0;
物品 := 角色^[14Dh];
while (物品 <> NIL) and (盾 = 0) and (特殊 = 0) do begin
    if (物品^[3Eh] > 80h) and (物品^[34h] <> 0) then begin   { 已裝備 }
        部位 := 物品^[3Eh] and 7Fh;
        盾   := (部位 = 0Bh);
        特殊 := (部位 = 02h);
    end;
    物品 := 物品^[2Ah];
end;

基 := <本模組 13BCh>(角色) * 角色^[117h] ＋ 角色^[10Fh];
if (基 < 4) and 特殊 then begin 基 := 4;  特殊 := 0 end;
存 := 基;

for i := 1 to 8 do begin
    調 := 0;
    if 盾 then begin
        if i = 1 then
            if 基 < 5 then 基 := 5 else 調 := 5;
        if i = 2 then
            if 基 < 7 then 基 := 7 else 調 := 5;
    end;

    v := 有號(byte[3F1Eh ＋ 角色^[74h] * 8 ＋ i]);     { 種族表 }
    if v < 0 then begin
        if 有號(byte[3EBEh ＋ 基 * 8 ＋ i]) < (−v ＋ 調) then
            角色^[0E9h ＋ i] := 0
        else
            角色^[0E9h ＋ i] := byte[3EBEh ＋ 基 * 8 ＋ i] ＋ v ＋ 調;
    end else
        角色^[0E9h ＋ i] := byte[3EBEh ＋ 基 * 8 ＋ i] ＋ v ＋ 調;

    if i < 6 then
        角色^[0E9h ＋ i] := 角色^[0E9h ＋ i]
                          ＋ byte[3F31h ＋ 角色^[17h] * 5 ＋ i];   { 敏捷 }

    if 特殊 then 角色^[0E9h ＋ i] := 角色^[0E9h ＋ i] ＋ 0Ah;

    基 := 存;                                          { 每圈還原 }
end;
```

## 八格對上八個方向

`i` 跑 1..8，結果寫進 `角色^[0E9h ＋ i]`，而**盾牌只影響 `i = 1` 與 `i = 2`**、
敏捷修正只影響 `i = 1..5`。spec 854 定案的方向編碼正好是 0..7 八個方向
（0 ＝ 上，順時針）。

形狀上這是**依方向分開的防禦數值**：正面兩格有盾、側面還有敏捷修正、
背後三格什麼都沒有。本規格**不宣稱它就是 AC**，但「盾只擋前面」
是 Gold Box 戰鬥的已知行為。

⚠ `角色^[0E9h]` 本身（`i = 0`）不在這一支的範圍內——
spec 834 讀到怪物的 `+0E9h` 是不死生物種類。**兩者不衝突**：
這裡寫的是 `+0EAh`..`+0F1h`，而 `+0F2h` 是效果鏈（spec 849）。

## 三張表

| 位址 | 索引 | 每列 |
|---|---|---|
| `DS:3EBEh`（PC-98 `DS:6F53h`） | `基` | 8 |
| `DS:3F1Eh`（PC-98 `DS:6FB3h`） | `角色^[74h]` 種族碼 | 8 |
| `DS:3F31h` | `角色^[17h]` 敏捷 | 5 |

種族表的值**是有號的**（`< 0` 走另一條），而且有下限保護：
扣完會變負的就直接寫 0。敏捷那張只有 5 欄，所以只套在前五個方向。

`角色^[17h]` 是敏捷（spec 857 的屬性版面）、`角色^[74h]` 是種族碼（spec 853／884）。

## `物品^[3Eh]` ＝ 旗標 ＋ 裝備部位

spec 907 讀到 `+3Eh > 7Fh` 控制要不要更新畫面；本支再取 `and 7Fh` 當**部位碼**：
`0Bh` ＝ 盾、`02h` ＝ 另一種會讓全部 ＋`0Ah` 的裝備。
所以那一個 byte 是 **bit 7 旗標 ＋ 低 7 bits 部位碼**。

## ⚠ DOS 側兩段反組譯錯位

DOS 從 `0C2Dh` 與 `0C99h` 起被解成 `add dh, bh` / `fadd dword ptr [bp+di]` /
`retn` / `test [bp+303Eh], di` / `in al, 3` 之類。PC-98 同兩段是正常的
`jns` / `neg ax` / `add ax, bx` / `cmp ax, bx` 比較與加總。

**這是第五支由 PC-98 校正 DOS 錯位的函式**。單看 DOS 會以為函式中間有
`retn` 與浮點指令——Turbo Pascal 的 `retf` 函式不會這樣。

## 明確不宣稱

- 沒有宣稱這八個值是不是 AC。
- 沒有宣稱 `本模組 13BCh(角色)` 與 `角色^[117h]`／`角色^[10Fh]` 的意義
  （`+10Fh` 落在 spec 850 的職業等級陣列 `+109h ＋ c` 的 `c = 6`）。
- 沒有宣稱部位碼 `0Bh`／`02h` 之外還有哪些。
- 沒有宣稱三張表的內容（靜態 dump 未取）。
