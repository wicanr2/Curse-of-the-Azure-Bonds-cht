# 1140 — 命中能力表（`DS:3E38h`）與建角的兩個預設值

- 證據等級：`exact`（`overlay-17:0782h` 的算式與 `overlay-16:228Eh` 的預設值逐條讀完；
  表的內容直接讀資料段，落在 BSS 界線 `47E0h` 之前）
- 上游 spec 1000（`+73h`／`+124h` 怎麼被用）、spec 1139（刻度）、spec 1101（職業槽）

## `+73h` ＝ 八個職業槽查表取最大

TRAINING（`overlay-17:0782h`）重算派生數值時：

```pascal
角色^[73h] := 0;
for j := 0 to 7 do begin
    等級 := 角色^[109h ＋ j];                    { 該槽的等級 }
    if 等級 > 0 then begin
        v := byte[3E38h ＋ j × 0Dh ＋ 等級];      { ★ 每槽 13 bytes }
        if v > 角色^[73h] then 角色^[73h] := v;   { 無號比較，取最大 }
        角色^[12Bh] += byte[3EA0h ＋ j];          { 職業可用性遮罩 }
    end;
end;
```

⚠ 等級為 0 的槽那條 `jle` 跳到的是迴圈**尾巴**（`cmp var_19, 7`）而不是出口，
所以空槽是**跳過**不是提早結束。聖騎士只有槽 3 有等級，讀成 break 會在槽 0
就結束、算不出任何值。

## ★ 表的內容

`DS:3E38h` 起，八個職業槽各 13 bytes，索引就是等級（0..12）。
值是**儲存刻度**，畫面上的 THAC0 是 `60 − 它`（spec 1139）。

| 槽 | 職業 | 等級 1..12 的 THAC0 |
|---:|---|---|
| 0 | 牧師 | 20 20 20 18 18 18 16 16 16 14 14 14 |
| 1 | 德魯伊 | 同上 |
| 2 | 戰士 | 20 20 18 17 16 15 14 13 12 11 10 9 |
| 3 | 聖騎士 | 同上 |
| 4 | 遊俠 | 同上 |
| 5 | 法師 | 21 21 21 21 21 19 19 19 19 19 17 17 |
| 6 | 盜賊 | 20 20 20 20 19 19 19 19 16 16 16 16 |
| 7 | 武僧 | 同牧師 |

槽的名稱來自 game pack 的 `class_slots`（spec 1101），不是從進程反推的——
三組共用同一條進程（牧師／德魯伊／武僧、戰士／聖騎士／遊俠）正好與
AD&D 1e 的攻擊矩陣一致，這是**獨立的交叉驗證**，不是命名的依據。

⚠ 索引 0 是等級 0 那一格，內容與等級 1 不一定相同（槽 2 是 `27h`、槽 3／4 是
`28h`）。原作只在等級 > 0 時查表，所以那一格走不到。

## 建角寫的兩個預設值

`overlay-16:228Eh` 與 `overlay-17:0782h` 都有同一組：

```pascal
角色^[124h] := 32h;      { ＝ 50 ⇒ AC 10 }
角色^[73h]  := 28h;      { ＝ 40 ⇒ THAC0 20 }
```

⚠ 一級法師的表值是 `27h`（THAC0 21），與這個預設值差 1——
**建角先寫預設、訓練場再依表重算**，兩條路本來就不一定相同。

沒有值才退回本作自己的近似式。DOS 存檔匯入與建角兩條路都會填。

## 明確不宣稱

- 沒有宣稱等級超過 12 時原作怎麼處理：表只有 13 筆，原作沒有夾，
  remake 選擇夾到最後一筆而不是讀過表尾。
- 沒有宣稱 `DS:3EA0h` 那八個位元組（`02 10 08 40 40 01 04 20`）的位元語意，
  只宣稱它們累加進 `+12Bh`。
- 沒有宣稱力量的命中／傷害調整表（spec 694／697）已經接上——
  `Fighter()` 那一段仍是本作的近似式。
