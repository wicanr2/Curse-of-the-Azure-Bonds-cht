# 第七百四十四輪：效果節點的 `+3` 存什麼，與 AC 的兩個欄位

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：DOS `overlay-12` 的 `08CDh`、`0818h`（兩支都沒有位元組缺口）。

## `08CDh`：操縱屍體的解除程序

```text
節點^[4] := 0
if DS:6F9Ch = 0 then                                  ← 不在「批次解除」期間才發訊息
    <overlay-23 entry#1>(角色, 6, '<名字> collapses'（CS:08C3h）)

角色^[197h] := 節點^[3] div 16                        ← ⚠ 還原陣營
角色^[198h] := 1
角色^[0E9h] := 0
角色^[0DDh] := 角色^[10Bh] + 角色^[113h] × <overlay-25 entry#10>(角色)
角色^[0E4h] := 0Ch
if 角色^[0F7h] = 0B3h then 角色^[0F7h] := 0
角色^[11Ah] := 0
```

### 效果節點的 `+3` 就是 `PUTEFFECT` 的第四個參數

spec 734 的 `2DB6h` 把 `(原 +197h shl 4) + 等級` 打包成一個 byte，當成
`PUTEFFECT` 的**第四個參數**傳進去。這裡用 `節點^[3] div 16` 取出高 4 位——
正好是原陣營。

所以 spec 724 留下的「`PUTEFFECT` 中間四個參數的意義」解掉一格：
**第四個參數會被存進效果節點的 `+3`**，解除程序從那裡讀回來。

`div 16` 是**有號** `idiv`；打包時的值是 `(0..1) shl 4 + 等級`，等級佔低 4 位，
所以等級超過 15 會污染陣營位。`2DB6h` 那邊的等級來自 `entry#36`，沒有夾限。

### 和 `2DB6h` 不是完全對稱

| 欄位 | 套用（`2DB6h`） | 解除（本輪） |
|---|---|---|
| `+197h` | 設成施法者的 | **還原**（從節點 `+3`） |
| `+198h` | `1` | `1`（一樣） |
| `+0E9h` | `2` | `0` |
| `+0E4h` | `6` | `0Ch` |
| `+11Ah` | `4` | `0` |
| `+0DDh` | `0` | **重新算**（見下） |
| `+0F7h` | `0B2h` 或 `0B3h` | 只有 `0B3h` 會被清 |

`+0E9h` 與 `+0E4h` 的解除值（`0`／`0Ch`）**不等於**套用前的值——套用時是寫死的
`2`／`6`，解除時也是寫死的 `0`／`0Ch`。兩邊都不看原值，所以**一個活人被操縱再
解除之後，這兩個欄位會停在解除值上**，不會回到他原本的樣子。

### 第四組平行職業欄位

`角色^[0DDh] := 角色^[10Bh] + 角色^[113h] × entry#10(角色)`

`+10Bh` 與 `+113h` 相差 8，又是 spec 728 那組模板。目前累積四對：

| 第一職業 | 第二職業 | 出處 |
|---|---|---|
| `+109h` | `+111h` | spec 728 |
| `+10Bh` | `+113h` | 本輪 |
| `+10Ch` | `+114h` | spec 728、spec 737 |
| `+10Dh` | `+115h` | spec 728、spec 738 |
| `+10Eh` | `+116h` | spec 728、spec 705 |

所以 `+109h..+110h` 與 `+111h..+118h` 是兩個 8 bytes 的平行區塊，這一點已由五對
欄位獨立驗證。

## `0818h`：AC 每次變差 2，直到 AC 10

```text
if 角色^[18Dh]^[2] <> 0 then
    <overlay-24 entry#20>(角色, '<名字> is coughing'（CS:080Ch）, 0Ah, 1)
角色^[18Dh]^[2] := 0
角色^[18Dh]^[1] := 0
<overlay-24 entry#7>(角色)

if 角色^[19Bh] > 34h then 角色^[19Bh] := 角色^[19Bh] − 2
else                      角色^[19Bh] := 32h
角色^[19Ah] := 角色^[19Bh]

if 角色 = DS:6506h then <overlay-24 entry#5>(角色)
```

`+19Ah` 是 AC（spec 684／689：**顯示值 ＝ 60 − 儲存值**）。這裡先改 `+19Bh`
再整個複製到 `+19Ah`，所以

> **`+19Bh` 是 AC 的基準值，`+19Ah` 是目前值。**

代進顯示公式：儲存值每次減 2 ＝ **顯示的 AC 每次加 2（變差）**，
下限 `32h` ＝ 50 ＝ 顯示 AC 10。從 AC 0（儲存 60）開始會經過 2／4／6／8 停在 10。

`34h` ＝ 52 ＝ 顯示 AC 8，也就是「還剩 8 以上就再減 2，否則直接歸位到 10」。

最後那個 `if 角色 = DS:6506h` 比的是兩個 word 都相等，只有目標正好是目前這個
角色時才呼叫 `entry#5`（多半是重畫）。

## 明確不宣稱

- `+18Dh^[1]`／`^[2]`／`^[4]`、`+0DDh`、`+0E4h`、`+0E9h`、`+11Ah` 的語意。
- `overlay-24` entry#5／#7、`overlay-23 entry#1` 的行為。
- `DS:6F9Ch = 0` 那個閘門（spec 704／707／714 都看過它在解除效果期間被設成 1）。
