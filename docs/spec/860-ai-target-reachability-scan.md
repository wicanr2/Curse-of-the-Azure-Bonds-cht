# 860 — 戰鬥 AI 的目標可及性掃描：4 格 × 4 格配對，取最小路徑成本

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側助憶碼完全相同，15 條差異全是位址）
- 作法見 spec 783

## `overlay-31:008E3h` ↔ `overlay-31:008D8h`（兩平台各 294 條）

`retf 0Eh` ＝ 7 個 word。依 Turbo Pascal 的推入順序（先推的先宣告），
參數是 `(基準A, 基準B, 成本上限, 攻擊方式, 我方體型, 遠指標)`——
`arg_C`／`arg_A` 是一組座標、`arg_8` 是成本上限、`arg_6` 是攻擊方式、
`arg_4` 是體型，最後一個是遠指標（`arg_0` 位移、`arg_2` 節段）。

```pascal
{ 一、我方佔的 4 格 }
for i := 0 to 3 do
    if <far 18Ch:002Ah>(我方體型, i, var 偏A, var 偏B) then begin
        我格A[i] := 偏A ＋ 基準A;
        我格B[i] := 偏B ＋ 基準B;
    end else
        我格A[i] := 0FFh;                      { −1 ＝ 這一格不存在 }

DS:6E96h := 0;                                  { 結果表清空 }
筆數 := DS:66A6h;
for t := 1 to 筆數 do begin
    if 目標[t].體型 = 0 then continue;          { 無號 }
    有解 := 0;  最佳 := 0FFh;

    { 二、目標佔的 4 格 }
    for j := 0 to 3 do
        if <far 18Ch:002Ah>(目標[t].體型, j, var 偏A, var 偏B) then begin
            敵格A[j] := 偏A ＋ 目標[t].A;
            敵格B[j] := 偏B ＋ 目標[t].B;
        end else
            敵格A[j] := 0FFh;

    { 三、4 × 4 配對 }
    for j := 0 to 3 do begin

                                     敵格A[最佳敵格], 敵格B[最佳敵格], 方式) do
```

## 兩張表

| 位址 | PC-98 | 內容 |
|---|---|---|
| `DS:66A3h` | `DS:9740h − 3` | **目標表**，每筆 4 bytes：`+0` 座標A、`+1` 座標B、`+2` 未用到、`+3` 體型 |
| `DS:66A6h` | `DS:9740h` | 目標表第 0 筆的 `+3`，**被拿來當筆數**（1 起算） |
| `DS:6E94h` | `DS:9F30h − 2` | **結果表**，每筆 3 bytes：`+0` 目標序號、`+1` 最小成本、`+2` 攻擊方式 |
| `DS:6E96h` | `DS:9F30h` | 結果表第 0 筆的 `+2`，**被拿來當筆數** |

⚠ 兩張表用**同一個手法**：第 0 筆的最後一格拿來存筆數，正式資料從第 1 筆開始。
`DS:27BDh` 法術名稱表把第 0 筆的 41 bytes 拿去塞小表也是同一種節省法
（`resident-data-tables.md`）——**這個引擎習慣把「第 0 筆」當成 header 用**。
remake 若把這些改成正常的 `count + array`，要記得原始碼裡索引全是 1 起算。

## 一個單位最多佔 4 格

`far 18Ch:002Ah(體型, 格序 0..3, var 偏A, var 偏B)` 回傳布林：
真代表這個體型有第 `格序` 格、並回填相對偏移；假代表沒有。
所以**體型最多 2×2**，與 Gold Box 大型怪物佔四格的表現一致。
不存在的格子在陣列裡寫 `0FFh`，後面用**有號**比較 `< 0` 濾掉——
座標本身是無號的 0..N，所以 `0FFh` 當哨兵不會跟合法座標撞。

## `攻擊方式 ≥ 8` ＝ 「自己找最省的那一種」

`本模組 054Ah(我A, 我B, 敵A, 敵B, 方式)` 是「這一對格子在這個方式下打不打得到」。
呼叫端傳 `< 8` 就照傳入的方式記錄；傳 `≥ 8` 就從 0 往上試到第一個成立的。
**這個 while 沒有上界**——`054Ah` 對所有方式都回假時會一直加下去。
掃描階段已經確認至少有一個方式成立（`有解` 是靠 `054Ah` 才會被設 1），
所以正常路徑走不到，但 remake 要補防護。

## `本模組 03EAh` ＝ 路徑成本查詢

`(起A, 起B, var 迄A, var 迄B, var 成本, 遠指標)`：`成本` 進去時是上限
（`arg_8`），回來是實際值；`迄A`／`迄B` 也是 var，代表**它可以改寫終點**
（形狀上是「走到相鄰可攻擊的位置就停」）。回假代表走不到。

## PC-98：15 條差異全是位址

`18Ch`↔`189h`（常式所在節段）、`66A3h`↔`9740h−3`、`6E94h`↔`9F30h−2`。
**沒有一處是邏輯差異**，兩平台共用同一份判讀。

## 明確不宣稱

- 沒有宣稱 `arg_C`／`arg_A` 哪個是 x 哪個是 y（本支只做加法，沒有方向語意）。
- 沒有宣稱「攻擊方式」的編號各代表什麼，也沒有宣稱 8 這個門檻的由來。
- 沒有宣稱目標表 `+2` 那一格是什麼（本支沒讀）。
- 沒有宣稱最後那個遠指標參數是什麼（原樣轉給 `03EAh`）。
- 沒有宣稱 `本模組 0035h` 收尾做什麼。
- 沒有宣稱結果表由誰消費。
