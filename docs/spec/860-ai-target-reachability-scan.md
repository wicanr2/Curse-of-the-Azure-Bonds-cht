# 860 — 目標掃描：半徑內所有有視線的目標，記錄「索引／距離／方向」

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側助憶碼完全相同，15 條差異全是位址）
- 作法見 spec 783

## `overlay-31:008E3h` ↔ `overlay-31:008D8h`（兩平台各 294 條）

`overlay-31` ＝ LOS 模組（spec 787／854）。這一支是它的對外入口
**`far 18ADh+1`**——spec 852 的 `overlay-24:02628h` 就是拿它來填目標清單的。

`retf 0Eh` ＝ 7 個 word。參數由 spec 852 的呼叫點直接定案：

| 位置 | spec 852 傳入 | 意義 |
|---|---|---|
| `arg_C` | `<far 192Bh>(角色)` | **起點 y** |
| `arg_A` | `<far 192Eh+2>(角色)` | **起點 x** |
| `arg_8` | 半徑 | **距離上限**（整格；`03EAh` 進去後 ×2＋1 換成半格） |
| `arg_6` | `0FFh` | **方向碼**，`≥ 8` ＝ 不限方向 |
| `arg_4` | `<far 1933h+2>(角色)` | **體型** |
| `arg_0`／`arg_2` | `遠指標(DS:6E92h)` | **地圖**（原樣轉給 `03EAh`） |

```pascal

for i := 0 to 3 do

        我y[i] := dy ＋ 起點y;   我x[i] := dx ＋ 起點x;

        我y[i] := 0FFh;                          { −1 ＝ 這個體型沒有第 i 格 }
```

## 關掉 spec 852 的「另外兩個 byte 裝什麼」

spec 852 讀到 `DS:758Eh` 只留每筆的第一個 byte，並明記「另外兩個 byte 裝什麼，
兩支都沒有讀到」。本支就是填那三個 byte 的地方：

| 位移 | 內容 | 來源 |
|---|---|---|
| `+0` | 戰鬥員索引 | 迴圈變數 `t` |
| `+1` | **最短距離**（半格單位） | `03EAh` 回填的距離取最小 |
| `+2` | **方向碼 0..7** | `054Ah` 由 0 往上找到的第一個成立值 |

spec 852 的 `overlay-31:0035h` 排序「依 `+1` 遞增、`+1` 相同時依 `+2` 遞增」
因此讀作**先近後遠，同距離時依方向碼順時針**——不是任意的次序鍵。

## `054Ah` ＝ 方向篩選，`8` 是「不限」的哨兵

`054Ah(起y, 起x, 迄y, 迄x, 方向)` 回布林。`< 8` 就照傳入的方向篩，
`≥ 8`（spec 852 傳 `0FFh`）就改成**從 0 往上試、回填實際方向**。
`8` 這個門檻與 spec 854 的方向編碼一致：**0 ＝ 上、順時針到 7 ＝ 左上、8 ＝ 原地**，
所以 `≥ 8` 正好是「不是任何一個實際方向」。

`054Ah` 落在 `03EAh` 與 `008E3h` 之間，**函式索引沒有單獨列出它**
（併進 `03EAh` 的範圍），呼叫點是 `push cs` ＋ near call。

⚠ `≥ 8` 那個 while **沒有上界**。走到它之前 `054Ah` 已經對某個方向回真過
（`有解` 就是這樣被設 1 的），所以正常路徑不會失控，但 remake 要補防護。

## 一個單位最多佔 4 格

`far 18Ch:002Ah(體型, 格序 0..3, var dy, var dx)` 回布林：
真代表這個體型有第 `格序` 格並回填相對偏移，假代表沒有。
**體型最多 2×2**，與 Gold Box 大型怪物佔四格的表現一致。
不存在的格子填 `0FFh`，後面用**有號** `< 0` 濾掉——座標本身無號，不會撞。

大型怪物因此是**任一格有視線就算看得到**，而距離取四格配對裡的最小值。

## `DS:66A3h`（PC-98 `DS:9740h − 3`）＝ 戰鬥員座標快取

每筆 4 bytes：`+0` y、`+1` x、`+2` 未用到、`+3` 體型。索引與 spec 852 的
`遠指標(DS:6D35h ＋ 索引 × 4)` 是同一組——那邊拿索引去取戰鬥員記錄，
這邊拿同一個索引取座標與體型。

⚠ 筆數存在 `DS:66A6h`，也就是**第 0 筆的 `+3`**；結果表的筆數存在 `DS:6E96h`，
也就是第 0 筆的 `+2`。兩張表都是「第 0 筆當 header、資料從第 1 筆開始」，
與 `DS:27BDh` 法術名稱表拿第 0 筆塞小表是同一個習慣
（`resident-data-tables.md`）。remake 改成正常的 `count + array` 時，
要記得原始碼的索引全是 1 起算。

## PC-98：15 條差異全是位址

`18Ch`↔`189h`、`66A3h`↔`9740h − 3`、`6E94h`↔`9F30h − 2`。
**沒有一處是邏輯差異**，兩平台共用同一份判讀。
