# 1142 — `4C00` 區的旗標跨地圖互相污染

- 證據等級：`exact`（守衛條件與寫入端逐位元組讀出）＋ `measured`（實機值量到）
- 作法見 spec 783
- 查詢工具：`cmd/ecl-cell-refs`（走 `ecl.TraceGraph`）

## 症狀：走到了卻沒有反應的五間房

密斯卓諾內城逐間走過之後，**九間出得來、五間安靜**：

| 房間 | 格子 | 地形 | 守衛 | 走到時的值 |
|---|---|---|---|---|
| 廚房 | `(13,14)` | `0x8C` | `COMPARE AND 4C06,0 4C07,0` | `4C06=0x0A`／`4C07=0x80` |
| 冥想中的祭司 | `(14,11)` | `0x8E` | 同上 | 同上 |
| 禮拜中的祭司 | `(14,8)` | `0x8F` | 同上 | 同上 |
| 停屍架與棺木 | `(10,1)` | `0x93` | `COMPARE AND 4C0F,0 4C0E,0` | `4C0F=0x07`／`4C0E=0x6A` |
| 食品儲藏室 | `(14,4)` | `0x91` | `COMPARE 4C0B,1 → EXIT` | `4C0B=1` |

不是走錯格：位置與地形碼都對（地形碼就是 `ON GOTO (C04F & 0x7F)` 的索引）。
**這條 session 根本沒進過那五間房**，旗標卻已經是「進過」的值。

同一個成因也壓住散提爾堡城區的四格（`ECL4/0x20` 索引 7 客棧、14 法官辦公室、
19／20 闖進民宅，守衛都是 `COMPARE 4C01,1 → IF >= → EXIT`），量測見
`docs/audit/cell-sweep.md`。

## ★ 同一格在不同地圖是不同的東西

`4C06` 是最乾淨的例子（`cmd/ecl-cell-refs -cell 4C06`，**75 處存取**）：

| 地圖 | 用途 | 證據 |
|---|---|---|
| 世界地圖 `ECL1/0x50`／`0x51` | **旅行時鐘**：`ECL CLOCK 4C06 04`、`MULTIPLY 4C06 04 4C06` | 位移 `0x0EA7`／`0x0F08` |
| 猶拉什 `ECL3/0x10` | 進段先歸零（`SAVE 00 4C06`），之後當旗標 | 位移 `0x001A` |
| 希爾斯法／古洞窟／外城 | 計數器，數到 8（`ADD 01 4C06 4C06`／`COMPARE 4C06 08`）| `ECL3/0x15`、`ECL5/0x35`、`ECL6/0x45` |
| 密斯卓諾內城 `ECL6/0x43` | 三間房共用的 once-only 標記（`SAVE 01 4C06`）| 位移 `0x0DEA` |

旅行時鐘走到 `0x0A` 之後進內城，三間房的守衛就永遠不成立。

## `4C07` 從第四章之後再也回不到 0

`cmd/ecl-cell-refs -cell 4C07` 的寫入端逐條看：

| 值 | 寫入處 |
|---|---|
| `0` | `ECL2/0x01`（兩處）、`ECL4/0x21`（兩處）|
| `1` | `ECL2/0x01`、`ECL3/0x11`、`ECL3/0x12`、`ECL4/0x21`（兩處）、`ECL4/0x22`、`ECL6/0x43` |
| `0xFF`／`0x80`／`0x03` | `ECL4/0x22`（眼魔洞穴）|

**最後一次寫 0 是第四章的 `ECL4/0x21`**，而同一章的 `ECL4/0x22` 之後寫下 `0x80`
（位移 `0x09AC`，正是實機量到的值）。第五、第六章沒有任何一處把它寫回 0。

## `ECL6/0x43` 自己的前導：`4C07`／`4C0E` 是抵達標記

內城前導依 `C04B`（**隊伍的 X 座標**，不是抵達來源）分支：

```
0x0083  COMPARE C04B, 0 → IF = → EXIT          { X=0 直接結束 }
0x008B  COMPARE C04B, 6 → IF = → GOTO 0x052F
0x0096  COMPARE C04B, 8 → IF = → GOTO 0x00F9   { 0x00F9: SAVE 1 → 4C0E }
0x00A1  PRINTCLEAR "THE SEWER ENDS IN A DARKENED KITCHEN. ..."
0x00EE  SAVE 1 → 4C07
```

所以 `4C07` 與 `4C0E` 是「**你抵達時已經看過這間房了**」的標記：從下水道進來會
先讀到廚房的敘述，廚房那一格就不再重複。⚠ 這兩格與 `4C06`／`4C0F` 的角色不同
——後兩者是房間自己的 once-only 標記，要求進段時是 0。

## 換 bank 的時機：兩個候選都有反例

| 候選時機 | 反例 |
|---|---|
| `NEWECL`／進 block 時整批清掉 | `ECL4/0x20` 前導 `COMPARE 4C01, 1`（位移 `0x0058`）讀的是**第二章**寫的值；清掉就永遠讀到 0 |
| `LOAD FILES` 時整批換掉 | `ECL3/0x10` 在 `LOAD FILES`（`0x005E`）**之前**寫 `4C05 := 0x80`、`4C0C := 3`，之後整段都在加減那個值（17 處）；換掉就立刻失效 |

⇒ 兩個都不是。剩下的可能只有兩種，而**靜態讀碼分不出來**：

1. `4C00` 區真的是 map-local，換的時機還沒找到（不在 `NEWECL`，不在 `LOAD FILES`）；
2. 這一區就是一整片全域旗標，那五間房在**原作也演不出來**——`4C07` 從第四章起
   就不是 0，而眼魔洞穴是主線必經。

分辨這兩者要拿原作當 oracle：把原版跑到密斯卓諾內城，讀那幾格的值。

## 目前的處置

`TestRealNewGameRunsToTheEnding` 把內城一樓九間、二樓五間逐間走過，壓不住的五間
標成 `suppressed`：**現在出不來是預期的，哪天出得來測試會紅**，提醒把清單更新。
`cmd/cell-sweep` 對散提爾堡那四格印出守衛，成因消失時同樣會被看見。

## ⚠ 事件目錄查不到全部的存取

`docs/audit/ecl-event-catalog.json` 的指令表有可達性缺口：查 `4C06` 只列 **18 處**，
`ecl.TraceGraph` 走得到 **75 處**，廚房那支 `SAVE 01 4C06`（`ECL6/0x43` 位移
`0x0DEA`）就不在目錄裡。**拿目錄下「沒有人寫這個旗標」的結論會反過來。**
查存取一律用 `cmd/ecl-cell-refs`。
