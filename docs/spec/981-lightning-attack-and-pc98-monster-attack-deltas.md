# 981 — 電光攻擊（兩平台都沒讀過），與 PC-98 三支怪物特攻的差異

- 證據等級：`exact`（四支逐條讀完）
- 作法見 spec 783

## `dos overlay-22:05F2Fh` ↔ `pc98 overlay-22:062D7h` — 丟電光

兩平台**都還沒判讀過**（DOS 側原本標成邊界碎片）。
字串：DOS `CS:5F1Eh` ＝ `'throws lightning'`，PC-98 `CS:62C2h` ＝
`'は電光を投げつけた。'`。

```pascal
if DS:758Dh >= 4 then 離開;                        { ★ 回合數閘門，見下 }

a := <overlay-32 entry#15>(角色);                  { 座標 }
b := <overlay-32 entry#16>(角色);
<overlay-24 entry#20>(角色, 名字 ＋ 'throws lightning', 1, 0Ah);
<DS:72A0h 第 0 項>(@DS:7746h, 1, 33h);             { 選目標，模式碼 33h }
<overlay-23 entry#13>(角色);
<overlay-24 entry#24>(13h);
<overlay-24 entry#25>(a, b, DS:755Ah, DS:7559h, 4, 32h);
<本模組 3947h>(DS:7559h, DS:755Ah, <overlay-23 entry#10>(10h, 6), 4, 0, @暫存);
<本模組 3A03h>(0Ah, <overlay-23 entry#10>(10h, 6), 4, 0);
暫存 := <overlay-24 entry#34>(角色);
```

### ★ `DS:758Dh >= 4` ＝ 第四回合起就不再丟電光

`DS:758Dh` 是**回合計數**（spec 825：每回合 ＋1）。所以這一招
**只在戰鬥的前四個回合能發動**，之後整支直接返回、連訊息都不印。

這是本專案第一次看到「怪物特殊攻擊被回合數限制」的寫法——
spec 720／722／723 的龍息、凝視、吐酸都沒有這道閘門，
它們各自用的是距離或擲骰。

### 選目標的模式碼再添一個

spec 721／722 記過 `DS:72A0h` 第 0 項是「選目標」，模式碼寫進
`+18Dh^[0Ah]`：龍息與吐酸 `41h`、凝視 `24h`。**電光是 `33h`**。

⚠ 本支**呼叫選目標之後完全沒有讀 `+18Dh^[0Ah]`**，也沒有檢查 NIL；
後面直接用 `DS:7559h`／`DS:755Ah` 兩個全域座標。所以這一招的落點來源
與其他三支不同——本規格不宣稱那兩個全域是誰寫的。

### 兩平台差異只有兩處

| | DOS `05F2Fh` | PC-98 `062D7h` |
|---|---|---|
| 回合閘門 | `DS:758Dh` | `DS:0A81Fh` |
| 座標全域 | `DS:7559h`／`755Ah` | `DS:0A645h`／`0A646h` |
| `entry#25` 最後一個參數 | 常數 `32h`（50） | `DS:7F16h × 0Ch` |

第三項是 PC-98 的通例（見下）。

## PC-98 的三個常數換算

PC-98 把 DOS 的動畫常數統一換成 `DS:7F16h × n`：

| 招式 | DOS 常數 | PC-98 |
|---|---|---|
| 龍息／吐酸（spec 720／723） | `1Eh`（30） | `DS:7F16h × 7` |
| 凝視（spec 722） | `2Dh`（45） | `DS:7F16h × 0Ch` |
| 電光（本規格） | `32h`（50） | `DS:7F16h × 0Ch` |

spec 760 當初在 `pc98 overlay-13:040B8h` 看到 `1Eh → DS:7F16h × 7` 時，
只能說「這是兩平台真實的行為差異」。現在四支特攻都是同一個換法，
可以確定**那是 PC-98 版全域的動畫速度參數，不是個別函式的特例**。

三組比值（30/7 ≈ 4.3、45/12 ≈ 3.8、50/12 ≈ 4.2）**不是同一個數**，
所以 PC-98 不是單純把常數除以固定倍率——每一招都重新調過。
本規格不宣稱 `DS:7F16h` 的執行期值。

## `pc98 overlay-22:05D17h` ＝ DOS `05974h`（吐酸，spec 723）

骨架逐句相同：模式碼 `41h`、距離 `>= 7` 放棄、`1d100` 判定、
傷害參數用**攻擊者的 HP 上限 `+78h`**、豁免類別 `3`。

### ⚠ PC-98 刪掉了「沒打中」的訊息

| | DOS | PC-98 |
|---|---|---|
| 擲骰在訊息之前還是之後 | 先擲，`> 30` 印 `'... Spits Acid and Misses'` | **先印 `'は酸を吹いた。'`，再判 `> 1Eh` 就直接返回** |
| 未命中時玩家看到什麼 | 專屬的 miss 訊息 | **只看到「吐酸了」，然後什麼都沒發生** |

spec 723 當時指出「龍息靜默、吐酸會告訴玩家」是兩支的差異；
現在要再加一層：**那個差異只存在於 DOS**，PC-98 把吐酸也改成了靜默。
`pc98 overlay-22` 的字串清單裡這一支**只有一個字串**，可以佐證。

中文化若以 PC-98 為底，會少掉一句原版 DOS 有的回饋。
建議照 DOS 補回來——玩家看不出「吐了酸卻沒事」和「程式沒反應」的差別。

## `pc98 overlay-22:063D4h` ＝ DOS `06022h`（凝視，spec 722）

兩個字串：`CS:63BCh` ＝ `'は睨んだ。'`（凝視）、`CS:63C7h` ＝ `'は麻痺した。'`
（DOS 是 `'gazes...'` 與 `'is paralyzed'`）。

流程逐句相同：先把 `+18Eh^[0Ah]` 清成 NIL、模式碼 `24h` 選目標、
NIL 就返回、印凝視訊息、動畫 `12h`、
`entry#8(目標, 1, 0)` 豁免成功就結束、失敗才
`entry#11(目標, 34h, 3Ch, 0FFh, 0)` 掛效果並印麻痺訊息。

**唯一的差異是動畫常數**（`2Dh` → `DS:7F16h × 0Ch`）。

### 豁免類別碼再補一格

| 類別碼 | 用在哪 | 出處 |
|---|---|---|
| `0` | 死亡光線 | spec 842 |
| `1` | 石化光線、**麻痺凝視** | spec 842、本規格 |
| `3` | 分解光線、**龍息**、**吐酸** | spec 842、spec 720／723、本規格 |

`3` 同時用在三種吐息／噴射，`1` 同時用在石化與麻痺凝視——
**與 AD&D 的五欄豁免表（麻痺/毒/死亡、石化/變形、法杖、吐息、法術）
對得上前兩欄的話，`3` 就是吐息那一欄**。
⚠ 但麻痺在 AD&D 屬於第一欄（和死亡同欄），本作卻和石化同用 `1`；
分解在 AD&D 屬法術欄，本作卻和吐息同用 `3`。
**所以本作的分類不是 AD&D 原表**，spec 842「沒有宣稱類別碼對應 AD&D 哪一欄」
維持不宣稱，但可以確定**這是引擎自己的四／五分類**。

## ⚠ 更正 spec 980 的一句

spec 980 寫「DOS 側的噴火訊息不在 `dos overlay-22` 裡」——**那是錯的**。
DOS 的龍息在 `overlay-22:05E11h`（spec 720），吐酸在 `05974h`（spec 723），
字串就在同一個模組。當時是拿 `scripts/function_strings.py` 的輸出下的結論，
而**那支工具對這個模組有漏**：它只列出 4 支帶字串的函式，
`05E11h` 與 `05974h` 都沒被列到。

**教訓寫成規則**：`function_strings.py` 的輸出**只能證明「有」，不能證明「沒有」**。
要下「某個字串不存在」的結論，得回到 overlay 的原始 bytes 或既有規格去確認。
（同 `~/diagnosis-notes/docs/02-query-returned-empty` 的「查詢回空」那一類。）

## 明確不宣稱

- 沒有宣稱 `overlay-23 entry#10(10h, 6)` 算的是什麼（兩個呼叫點參數相同）。
- 沒有宣稱 `本模組 3947h`／`3A03h`（DOS）與 `3BF5h`／`3CB1h`（PC-98）做什麼。
- 沒有宣稱電光為什麼只在前四回合能用。
- 沒有宣稱 `DS:7F16h` 的執行期值。
