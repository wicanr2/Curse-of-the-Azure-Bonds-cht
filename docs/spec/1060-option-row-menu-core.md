# 1060 — 選項列選單本體：大寫字母熱鍵是「掃字串比對」，游標鍵是 `,` 與 `.`

- 證據等級：`exact`（DOS 側 365 條逐條讀完）
- 作法見 spec 783

## `dos overlay-26:003D4h`（`retf 16h`）

原本待解讀。這是 spec 1030／1031／1032／1039／1059 一路呼叫的那一支。
參數表（宣告序 ＝ 由高位移到低）與 spec 1030 從堆疊回推的完全一致：

| `bp` | 內容 |
|---|---|
| `+18h` | 選項行 1（複製成上限 40） |
| `+14h` | 選項行 2（複製成上限 40） |
| `+12h` | 顏色（`arg_C`） |
| `+10h`／`+0Eh` | 兩個 byte（任一非 0 ⇒ 允許 Enter 選取） |
| `+0Ch`／`+0Ah` | 兩個 byte |
| `+06h` | **輸出旗標**（遠指標） |

## ★★★ 大寫字母熱鍵的實作：掃選項行比對

```pascal
鍵 := UpCase(讀鍵());
if 鍵 in ['0'..'9', 'A'..'Z', ' '] then begin        { 集合常數 CS:0394h }
    if 鍵 = ' ' then 結束 := 1
    else for i := 1 to 選項行長度 do
        if 選項行[i] = 鍵 then begin                  { ★ 逐字元比對 }
            結束 := 1;
            …由 i 反查是第幾個選項，寫進 DS:7294h…
        end;
end;
```

> ★★★ **這就是 spec 1030／1039「大寫字母熱鍵」的實作端**：
> 沒有熱鍵表，程式**把使用者按的鍵大寫化之後，逐字元掃整條選項行**，
> 撞到相同字元就選那一項。
> ⇒ 這解釋了為什麼 DOS 版的熱鍵**必須是選項文字裡真的出現的大寫字母**，
> 也解釋了 spec 1039 的波浪號只是**給玩家看的標記**——
> 程式不看 `~`，只看後面那個大寫字母。
>
> ⚠ **中文化的致命點**：Big5 的**低位元組**落在 `41h`..`5Ah` 時
> （`'A'`..`'Z'`）會被這一段當成熱鍵撞到。**DOS 版沒有安全的中文熱鍵**，
> 只能跟 PC-98 的獨立熱鍵表。
> ★ 集合裡還有 `'0'`..`'9'` 與空白——**數字也可以當熱鍵**，空白直接結束。

## ★★ 游標鍵是 `,` 與 `.`

```pascal
if 鍵 = ',' then  { 上一個，到頭就環繞到最後 }
else if 鍵 = '.' then  { 下一個，到尾就環繞回 1 }
else if 鍵 = 0Dh then  { Enter：選 DS:7294h 指的那一項 }
else if 鍵 = 1Bh then  { ESC：結束，回傳 0 }
```

★ **目前的游標位置存在 `DS:7294h`**（spec 1013 記過的同一格），進門時夾在 `1..選項數`。
★ Enter 只有在 `bp+10h` 或 `bp+0Eh` 非 0 時才有作用；
選到的字元若是 `0` 就改回傳 `0Dh`。

## ★ 另一組鍵（`bp+0Ch` 非 0 時）

集合常數 `CS:03B4h` ＝ `['1'..'9', '\']`：

```pascal
if 鍵 = '\' then 鍵 := '7'
else 鍵 := byte[27CEh ＋ (鍵 − '1')];
輸出旗標^ := 1;
```

`DS:27CEh` 起是 `4F 50 51 4B 20 4D 47 48 49`
⇒ **`'1'`..`'9'` 被翻成 `4Fh 50h 51h 4Bh 20h 4Dh 47h 48h 49h`**
——正是數字鍵盤的**方向掃描碼**（End／Down／PgDn／Left／空白／Right／Home／Up／PgUp）。

> ★★★ **DOS 版用數字鍵 `1`..`9` 模擬數字鍵盤的方向**，
> 對照 spec 1023／1027 記的「PC-98 把掃描碼換成 `'2'`／`'3'`／`'8'`／`'9'`」
> ——**兩個平台從相反方向解同一個問題**。

## ★★ 閒置時的動畫與逾時

```pascal
基準 := 計時器();                                  { far 0542:0994h }
動畫下次 := 基準 ＋ 1Eh;   下下次 := 動畫下次 ＋ 32h;
…
if (DS:4FBAh = 3) and (DS:7290h = 'y') and (DS:728Ah <> 50h) then begin
    <overlay-27 entry#3／#4／#5>();                { 開場動畫 }
    每隔 1Eh 個 tick 再叫一次 entry#4;
end;
if (bank0^[3FEh] <> 0) or (arg_4 <> 0) then
    每隔 0Ah 個 tick 把 DS:722Dh ＋1（到 DS:722Ch 就繞回 1）並叫 <overlay-29 entry#1>;
if (DS:7296h／7298h 這個 32-bit 逾時 > 0) and 已經超時 then begin
    鍵 := DS:729Ah;  結束 := 1;                    { ★ 自動送出一個鍵 }
end;
```

★ `DS:728Ah`（圖片子索引，spec 1029）與 `DS:4FBAh`（畫面模式）都被拿來當動畫條件。
★ **`DS:7296h`／`7298h` 是 32-bit 的逾時值、`DS:729Ah` 是逾時後自動送出的鍵**
——這是 demo／attract mode 的機制。

## 中文化

⚠ 兩個選項行的上限都是 **`28h` ＝ 40 bytes**。
⚠⚠ 熱鍵靠掃字串比對 ⇒ **DOS 版中文化必須改用 PC-98 的獨立熱鍵表**，
否則 Big5 低位元組會誤觸。

## 明確不宣稱

- 沒有宣稱 `sub_D5h`（數選項數）與 `sub_1E5h`（重畫游標）的細節。
- 沒有宣稱 `DS:722Ch`／`722Dh`（那個會循環的計數）是什麼動畫。
- 沒有宣稱 `bank0^[3FEh]` 與 `arg_4` 的語意。
- 沒有宣稱 `DS:7290h ＝ 'y'` 這個條件由誰設定。
- 沒有宣稱 `far 09AB:02FAh`（有沒有按鍵）與 `far 06EA:010Dh`（讀鍵）的細節。
