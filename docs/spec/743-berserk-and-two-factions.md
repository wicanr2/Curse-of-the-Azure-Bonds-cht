# 第七百四十三輪：狂暴，以及陣營只有兩個值

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：DOS `overlay-12` 的 `1809h`、`2A2Ch`（兩支都沒有位元組缺口）。

## `1809h`：套用與解除共用一支

```text
if arg_2 <> 0 then                                   ← 解除
    if 角色^[0F7h] = 0B3h then 角色^[0F7h] := 0
    角色^[197h] := 0                                  ← ⚠ 無條件設成 0
    返回

（以下是套用）
角色^[198h] := 1
if 角色^[0F7h] <= 7Fh 或 角色^[0F7h] = 0B3h then 角色^[0F7h] := 0B3h
else                                                  角色^[0F7h] := 0B2h

if DS:4FBAh <> 5 then 返回                            ← 非戰鬥就到此為止

角色^[18Dh]^[0Ah] := NIL                              ← 先清掉原本鎖定的目標
<overlay-31 entry#6>(x, y, 0FFh, 0FFh, z, DS:6E92h)   ← 重新選一個
角色^[18Dh]^[0Ah] := far [6D35h + DS:6E9Ah × 4]
角色^[18Dh]^[1] := 0
角色^[197h] := 新目標^[197h] xor 1                    ← ⚠ 設成目標陣營的**相反**
<overlay-24 entry#20>(角色, '<名字> goes berzerk'（CS:17FCh）, 0Ah, 1)
```

## `xor 1` 定死了陣營只有兩個值

`角色^[197h] := 新目標^[197h] xor 1` 只有在 `+197h ∈ {0, 1}` 時才講得通——
`xor 1` 是在兩個值之間翻轉。所以

> **`+197h`（陣營，spec 734）只有 0 與 1 兩個值。**

這回頭解釋了 spec 692 的 `25D4h`：它只清 `DS:6F90h` 與 `DS:6F91h` **兩個 byte**
就拿 `+197h` 當索引累加。當時記為「沒有上下界檢查、值不是 0 或 1 就會寫進別的
全域」——現在知道那個假設在原作裡成立，統計陣列剛好兩格就是因為只有兩個陣營。
**風險仍在**（`2DB6h` 之類的地方若寫進別的值就會越界），但不是原作的日常路徑。

狂暴的機制也因此清楚：**先重新選一個目標，再把自己的陣營設成那個目標的相反**——
所以狂暴者一定會攻擊剛選中的對象，不論對方原本是敵是友。

## 解除時陣營一律歸 0

解除路徑寫的是 `角色^[197h] := 0`，**沒有還原原本的陣營**。
對照 spec 734 的操縱屍體：那支特地把原陣營打包成 `(原 +197h shl 4) + 等級` 交給
`PUTEFFECT` 保存。同樣是會改陣營的效果，一個保存一個不保存。

如果 `0` 就是玩家隊伍那一側，那麼**敵方單位狂暴結束後會變成我方**。這一條需要
實機驗證再決定 remake 怎麼寫——照抄可能重現一個原作的 bug，改掉則會偏離原作。

## `+0F7h` 的三態處理

這支比 spec 724 的恐懼完整：

| | `<= 7Fh` | `= 0B3h` | 其他（含 `0B2h`） |
|---|---|---|---|
| `4A8Fh`（恐懼，spec 724） | → `0B3h` | 不動 | 不動 |
| `1809h`（本輪，套用） | → `0B3h` | → `0B3h` | → `0B2h` |
| `2C94h`（解除恐懼，spec 738） | 不動 | → `0` | 不動 |
| `1809h`（本輪，解除） | 不動 | → `0` | 不動 |

**四支對同一個 byte 的處理各不相同**，而且兩支解除程序都只認 `0B3h`——
被設成 `0B2h` 的角色，任何一種解除都不會還原它。

## `2A2Ch`：用物品節點的第二個效果槽

```text
DS:7582h := 0
id := 物品節點^[3Dh]                                  ← spec 703 的第二個效果槽
if arg_0 <> 0 then
    <overlay-23 entry#3>(目標, id, 0)                  ← 解除
else
    <overlay-23 entry#11>(目標, id, 0, 0FFh, 1)        ← 套用
    if DS:4FBAh <> 5 then
        <overlay-23 entry#2>(id, 目標, 0, 0)
```

和 `1809h` 一樣是「同一支處理套用與解除」，由第一個參數切換。
套用時**戰鬥中與非戰鬥中做的事不同**（非戰鬥才多呼叫 `entry#2`）。

## 明確不宣稱

- `+198h`、`+0F7h`、`DS:7582h`、`DS:6E9Ah` 的語意。
- 陣營 `0` 與 `1` 分別是哪一側。
- `overlay-31 entry#6` 選目標的規則。
