# 1052 — 分塊讀取（PC-98 側）：目錄表一次讀進 VRAM，解出來的塊也放 VRAM

- 證據等級：`exact`（PC-98 常駐段 227 條逐條讀完，`objdump` 路線見 spec 1046／1048）
- 作法見 spec 783；DOS 對側見 spec 1047

## `pc98 PC98-GAME.EXE:17A54h`（`retf 12h`，609 bytes）

原本待解讀。呼叫端 `12AEDh`、`12D1Ch`。參數與 DOS 對側同形：

```pascal
function 讀一塊(檔名A: 字串;      { bp+14h，上限 80 }
                檔名B: 字串;      { bp+10h，上限 80 }
                要的id: byte;     { bp+0Eh }
                長度出: 遠指標;   { bp+0Ah }
                指標出: 遠指標)   { bp+06h }
```

## ★★★ 塊目錄項是 9 bytes——兩平台相同，所以那是**檔案格式**

```pascal
項數 := (檔案長度 − 2) div 9;
```

| 項內位移 | 內容 |
|---|---|
| `+0`（byte） | **id** |
| `+1`（4 bytes） | **位移** |
| `+5`（word） | 寫進 `長度出^` |
| `+7`（word） | 大小 |

> ★★★ **與 spec 1047 在 DOS 側逐塊讀出來的表頭欄位順序、寬度完全一致。**
> DOS 是「一塊一塊 seek＋read 掃過去」，PC-98 是
> 「**把整張目錄表一次讀進來再線性掃**」——
> **實作不同、格式相同** ⇒ 那 9 bytes 是 `.dax` 這一族檔案的格式，
> remake 兩邊都得照著做。
>
> ★ `− 2` ⇒ 檔案開頭有 **2 bytes** 不屬於目錄項（形狀上是項數或版本）。

## ★★★ 用 VRAM 當載入期的暫存

```asm
8494  mov  WORD PTR [bp-0x2be], 0xa800     ; 目錄表讀到 A800h:0000h
…
8584  mov  WORD PTR es:[di+0x2], 0xb000    ; 指標出^ := B000h:0000h
```

> ★★★ **PC-98 把兩個圖形平面直接拿來當載入期的暫存區**：
> `A800h`（藍平面）放目錄表、`B000h`（紅平面）放解出來的塊。
> ⇒ 這兩塊 VRAM 在載入期間的內容是垃圾，**載入完一定要重畫**
> ——與 spec 1048「清矩形只清三個平面」是同一個世界的設計。
> ⚠ remake 若把 VRAM 當成唯一畫面來源，會看到載入時的雜訊。

★ 進出各叫一次 `far 0893:0000h`，並在開頭 `out 0A6h, 1`
——`0A6h` 是既有結論裡的**繪圖頁選擇器**（spec 1029 記過 IDA 標成 8259A 是錯的）。

## 找不到的路

```pascal
if 項.id <> 要的id then begin
    長度出^ := 0;  指標出^ := NIL;
    <sub_83D7h>(…);  <far 0893:0000h>();  exit(false)
end;
```

★ 與 DOS 對側同一個形狀（兩個輸出清零、關檔、回 false）。
