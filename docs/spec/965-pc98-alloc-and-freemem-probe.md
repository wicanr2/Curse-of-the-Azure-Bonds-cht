`(要求大小 arg_0, 檔案 arg_2)`。由 `sub_139DDh` 呼叫兩次（尚未讀）。

if (要求大小 mod 40h) <> 0 then 要求大小 := 要求大小 ＋ 40h;
要求大小 := (要求大小 div 40h) shl 2;             { ★ 換算成段數 }

{ ── ④ 量剩餘記憶體 ── }

## ★ ④ 是「還剩多少堆積」的量測

`word_23AECh`／`word_23AEEh` 是**目前配置指標**、
`word_23AE8h`／`word_23AEAh` 是**下界**（spec 952／954 已定名）。
本支把兩者各自用 `<sub_1A8CEh>`（`× 10h` 的長整數乘法）換算成**線性位址**，
相減得到 `dword_24E75h` ＝ **剩餘可用的位元組數**。

⚠ 兩次換算都寫成「先取段、`× 10h`、再加偏移」，
而 `les di, [bp+var_10C]` 那一段其實只是把一個近位址包成遠指標再讀回來
——**是編譯器對 `LongInt(Seg(p)) * 16 + Ofs(p)` 這種寫法的直譯，不是特殊技巧**。

## ③ 的版本比對有一個不對稱

```
if (主 = 讀到的主) and (次 < 讀到的次) then 更新次;
if (主 < 讀到的主) then begin 更新主;  更新次 end;
```

**主版本相同時只在讀到的次版本較大時更新；主版本較大時無條件更新兩者。**
但**沒有「主版本較小就忽略」的分支**——那條路自然落空，行為正確。
兩個判斷是分開的 `if`（不是 `else if`），所以主版本較新時
第一個 `if` 的條件不成立、第二個成立，只會更新一次。

## ① 的對齊換算

```
向上對齊到 40h 的倍數 → div 40h → shl 2
```

`40h` ＝ 64 bytes。`div 40h` 之後 `shl 2` 等於 `div 10h`，
也就是**換算成段（paragraph）數**。所以「先對齊到 64 bytes」
是為了讓段數是 4 的倍數——**配置粒度是 64 bytes**。
