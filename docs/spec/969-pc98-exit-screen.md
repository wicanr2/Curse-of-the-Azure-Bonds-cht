# 969 — PC-98 的結束畫面：清全螢幕、道別、等 Enter 回 DOS

- 證據等級：`exact`（逐條讀完，訊息由 `PC98-GAME.EXE.asm` 的位元組解碼）
- 位置：`PC98-GAME.EXE` 的 `17EA7h`
- 作法見 spec 783

## `17EA7h`（175 行）

由 `sub_1259Fh:loc_12808h` 呼叫（主流程，尚未讀）。

```pascal
<sub_18A8Eh>();

{ ── ① 清文字畫面：25 列 × 兩平面 ── }
for 列 := 0 to 18h do begin
    <sub_1C180h>(0A000h : 列 × 0A0h, 0A0h, 0);      { 字碼 }
    <sub_1C180h>(0A200h : 列 × 0A0h, 0A0h, 0);      { 屬性 }
end;

{ ── ② 清圖形畫面：200 列 × 三平面 ── }
for 列 := 1 to 0C8h do begin
    <sub_1C180h>(0A800h : 位移, 50h, 0);            { ★ B 平面 }
    <sub_1C180h>(0B000h : 位移, 50h, 0);            { ★ R 平面 }
    <sub_1C180h>(0B800h : 位移, 50h, 0);            { ★ G 平面 }
end;

{ ── ③ 道別 ── }
Assign(f, …);  Rewrite(f);
Write(f, ESC ＋ '[37m' ＋ ESC ＋ '=' ＋ … ＋ 'お疲れさまでした。');
WriteLn(f);  Close(f);
<sub_18229h>();

{ ── ④ 等 BIOS 旗標，然後等 Enter ── }
repeat
    if byte(0060h:006Ch) > 0 then begin
        印('リターンキーを押すとＤＯＳに戻ります。');
        repeat 鍵 := <sub_192A0h>() until 鍵 = 0Dh;
        <sub_1A726h>(0);                            { 正常結束，不返回 }
    end;
until false;                                        { ⚠ 見下 }
```

## ★ 兩段訊息

| 常數 | 內容 |
|---|---|
| `byte_17E30h`（27 bytes） | `ESC [37m` ＋ `ESC =` ＋ 定位 ＋ **`お疲れさまでした。`** |
| `byte_17E7Ah`（44 bytes） | `ESC =` ＋ 定位 ＋ **`リターンキーを押すとＤＯＳに戻ります。`** |

兩段都帶 **ANSI／PC-98 的 escape 序列**（`ESC [37m` 設白色、`ESC =` ＋ 兩個
byte 定位游標），走的是主控台而不是遊戲的文字層——
與 spec 966 的堆積錯誤訊息同一條路。

**DOS 版沒有這個結束畫面**：spec 924 的紮營選單問完
`'Quit TO DOS '` 就直接 `06EAh:0000h` 離開。
PC-98 版多了一個道別畫面，還要玩家再按一次 Enter。

## PC-98 圖形 VRAM 的三個平面基底

`0A800h`（B）／`0B000h`（R）／`0B800h`（G），每列 `50h` ＝ 80 bytes、
共 `0C8h` ＝ 200 列。**與 spec 954 的「每列 80 bytes、640 像素、
每平面 1 bit」完全一致**，並補上三個平面的實際段位址。

⚠ **只清三個平面**——PC-98 的 16 色還有第四個 I 平面（`0E000h`）沒被清。
這與 spec 949／956／967 一路都只動三個平面一致：
**這個遊戲只用 8 色**（三個平面 ＝ 2³）。

## ⚠ 那個 `repeat until false` 可能不會結束

迴圈條件只有一個：`byte(0060h:006Ch) > 0`。
不成立時 `jmp loc_17FB4` 回到迴圈開頭，**沒有其他離開路徑**。
所以那個 BIOS 資料區的旗標若一直是 0，**程式會停在這裡**
（畫面已清、道別已印，但按鍵不會被處理）。

本規格不宣稱 `0060h:006Ch` 是什麼，也不宣稱這在實機上會不會發生。

## 明確不宣稱

- 沒有宣稱 `0060h:006Ch` 這個 PC-98 BIOS 資料區的位元組是什麼。
- 沒有宣稱 `<sub_18A8Eh>`／`<sub_18229h>` 的內部。
- 沒有宣稱第四個圖形平面（`0E000h`）由誰清或是否需要清。
