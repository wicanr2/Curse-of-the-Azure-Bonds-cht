# 759 — 戰鬥員座標的取法、`bit 7` 當資源分頁，以及文字檔截斷

- 證據等級：`exact`（逐條讀完）

## 戰鬥員的 x／y 怎麼查出來

`overlay-13:4162h`（DOS，`retf 4`）把整條鏈串起來了：

```pascal
<overlay-24 entry#24 @1AAAh>(參數 + 0Dh);
x1 := <overlay-32 entry#15 @0C36h>(記錄^[+0Ch]);   { 遠指標 }
y1 := <overlay-32 entry#16 @0C5Eh>(記錄^[+0Ch]);
x2 := <overlay-32 entry#15>(記錄^[-0Ah]);
y2 := <overlay-32 entry#16>(記錄^[-0Ah]);
<overlay-24 entry#25 @1AF7h>(x1, y1, x2, y2, 1, 1Eh);
```

entry#15／#16 各自先用 `overlay-32:0CAEh`（spec 757）把遠指標換成索引，再從
每筆 4 bytes 的記錄陣列取 `+0` 與 `+1`——也就是**戰鬥員的 x 與 y**。

這回頭補上了 spec 750 的一個缺口：戰鬥開場寫的
`地圖^[2] := entry#15(隊伍鏈頭) − 3`、`地圖^[3] := entry#16(隊伍鏈頭) − 3`
確實是「隊伍位置往回退 3 格」，形狀相符的推測現在有了機制上的依據。

第一個參數是 SS 相對的記錄指標，兩個戰鬥員遠指標分別在 `+0Ch` 與 `−0Ah`
（**負位移**，所以那個記錄的基準點不在起頭）。

## `overlay-33:00F9h`（DOS）／`0267h`（PC-98）— 用 bit 7 選資源

`retf 8`：

```pascal
if 代碼 > 7Fh then
    0297h:08F8h(遠指標@DS:4FE8h, 遠指標@DS:65D2h, a, 代碼 and 7Fh, b, c)
else
    0297h:08F8h(遠指標@DS:4FE8h, 遠指標@DS:65CEh, a, 代碼, b, c);
```

同一支繪製程序，**只差第二個遠指標**：`DS:65D2h` 或 `DS:65CEh`。代碼的
bit 7 就是分頁選擇，低 7 位是頁內索引。比較是無號的。PC-98 對應
`DS:9668h` / `DS:9664h`、`02A8h:0712h`。

這是本專案第二個「bit 7 當旗標、低 7 位當值」的欄位（另一個是 spec 758 的
`+0F7h`），但兩者的低位語意不同：`+0F7h` 的低 7 位要乘 2，這裡是直接當索引。

## `overlay-02:3621h` — 逐格前進的迴圈

`retf 2`：

```pascal
DS:4FB4h := 參數;
DS:47E0h := 0;
while (DS:47E0h = 0) and (DS:4FC7h = 0) do begin
    DS:75FEh := DS:75FFh;                              { 上一個值往後推 }
    DS:75FFh := DS:4FA5h^[DS:4FB4h − 8000h];
    if DS:4FC1h <> 0 then begin
        本模組 19EFh(DS:75FFh, @本地緩衝, @DS:8B76h);
        0A54h:173Bh(0);  0A54h:1673h();
    end;
    本模組 3377h();
end;
DS:47E0h := 0;
```

`DS:75FEh` / `DS:75FFh` 是「前一個／目前」的一對值。索引用的負位移
（`−8000h`）表示 `DS:4FA5h` 這個遠指標指向的位置在陣列中段。`DS:4FC1h` 是個
只在為真時才做那三個呼叫的旗標——形狀像是除錯／追蹤開關，但沒有證據，不宣稱。

**離開條件只看 `DS:47E0h` 與 `DS:4FC7h` 兩個全域**，迴圈本身不會自己結束。

## `START.EXE:1B9FEh` — 依 `^Z` 截斷文字檔

近呼叫、無 prologue，`DI` 指向檔案記錄：

```
seek 到檔尾                              { INT 21h AX=4202h }
位置 := 檔案大小 − 80h;  若為負數則 0
seek 到該位置                            { AX=4200h }
讀 80h bytes 進 [di+80h]                 { AH=3Fh；失敗則讀到 0 bytes }
在讀進來的內容裡找第一個 1Ah
    找不到（掃到讀取長度）就直接返回
找到的話：
    seek 相對檔尾 −(讀取長度 − 位置)      { AX=4202h，CX:DX 為負 }
    寫入 0 bytes                          { AH=40h，CX=0 → 截斷 }
```

`AH=40h` 配 `CX=0` 是 DOS 的截斷慣用法。`1Ah` 是文字檔的 EOF 字元，所以這支的
作用是**把檔案切到第一個 `^Z` 為止**，且只在最後 128 bytes 內找。
