# 第六百三十四輪：`Str` 三個寬度版本，以及 `overlay-24` 小函式

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：PC-98 `overlay-24` 的 `12E5h`、`1321h`、`135Bh`、`27E3h`、`2AAEh`、`30E7h`。

## `Str` 的三個寬度版本

`0A65h:12FBh` 是 Turbo Pascal 的 `Str`（也出現在
[spec 623](623-killthedude-damage-message.md) 的 `KILLTHEDUDE`）。三支包裝只差
**怎麼把輸入湊成 32-bit**：

| 函式 | 取值方式 | 輸入寬度 | `retf` |
|---|---|---|---|
| `12E5h` | `mov al, [bp+arg_0]` ＋ `xor ah, ah` ＋ `xor dx, dx` | **byte**（無號） | `2` |
| `1321h` | `mov ax, [bp+arg_0]` ＋ `xor dx, dx` | **word**（無號） | `2` |
| `135Bh` | `push [bp+arg_2]` ＋ `push [bp+arg_0]` | **longint**（整個 dword） | `4` |

三支的後半完全相同：`Str(值, 0, 暫存, 0FFh)` 之後，把暫存字串指派給呼叫端傳進來
的字串變數（`0A65h:649h`，上限 `0FFh`）。

`xor dx, dx` 表示前兩支都當**無號**看待——byte 版不會把 `0FFh` 印成 `-1`。

## 其餘三支

```text
27E3h:  回傳 (arg_0^[198h] = 0)          ← 是則 1，否則 0

2AAEh:  r := <sub_2A5B>(arg_0)
        arg_0^[18Eh]^[7] := 1             ← 先呼叫再設旗標
        備妥 '防御している'，<sub_194C>()
        回傳 r

30E7h:  <far 018Ch:0301h>()
        <sub_1F6E>()
        <sub_18F1>(DS:9F2Ch^[2] + 3, DS:9F2Ch^[3] + 3, 0FFh, 8)
```

`2AAEh` 的回傳值是**進來時就算好的** `sub_2A5B` 結果，設旗標與顯示訊息都在那之後
——所以回傳值不受旗標影響。

`30E7h` 把 `DS:9F2Ch^[2]` 與 `^[3]` 各加 3 後傳出去，兩者都用 `cbw`（**有號**）。
這對值看起來是一組座標，加 3 是固定偏移。

## 明確不宣稱

- `+198h`、`+18Eh` 指向的結構、`+7` 旗標的意義。
- `DS:9F2Ch^[2]`／`^[3]` 是不是座標（只確定是兩個相鄰的有號 byte，各加固定的 3）。
- `sub_2A5B`／`sub_194C`／`018Ch:0301h`／`sub_1F6E`／`sub_18F1` 的內部行為。
