  由 `cmd/geo-probe` 的連通性算出）＋ 一次**已還原**的整輪實作實驗
- 前置：[spec 1160](1160-declared-spawn-is-a-fallback-and-the-guild-transform.md)（那六件事）

## 這一輪做到哪裡

spec 1160 那六件事全部實作、九處原作行為的斷言全部改完之後，
`internal/game` 從四條測試紅收斂到**只剩主線通關測試的眼魔洞穴那一段**。

## ★★★ 擋住最後一段的是一個結構問題，不是路線

原作的 `2E10h` 重畫會**自己去地圖讀**目前這一格的牆面與地形，寫進
`C04E`／`C04F`；每格事件的分派器 (`AND C04F, <遮罩>` ＋ `ON GOTO`) 就靠 `C04F`。

remake 的 `State` **手上沒有 GEO 目錄**——`grid` 一律由呼叫端傳進
`MoveDungeon`／`TurnDungeonWithGrid`。所以腳本傳送（只寫 `C04B`／`C04C`）之後
`C04F` 還停在**被搬走前那一格**的地形，接下來的每格事件就分派到錯的一支，
或什麼都不演。

⇒ 實驗裡每一處腳本傳送都要在測試裡手動補
`DungeonWallType`／`DungeonWallRoof` ＋ `syncDungeonECLRegisters()`
才走得下去（巫師塔塔頂、熔岩池、眼魔洞穴各一次）。**那不是路線問題，
是引擎少了一塊。**

## remake（已完成）

- `State` 收下一份 `geo.Catalog`（`SetGeoCatalog`），`currentDungeonGrid` 依
  `GeoMapSet`／`GeoMapBlock` 取圖。
- `projectFreshDungeonCoordinatesBeforeCall` 投影完座標就呼叫
  `refreshDungeonTerrainFromMap`，照原作重畫的做法把牆面／地形讀回
  `C04E`／`C04F`。
- `cmd/azure-bonds-game` 在載完 GEO 目錄之後交給 `State`，遊戲本體與測試走
  同一條路徑。
- 兩面測試 `TestRedrawRefreshesTerrainOnlyWhenTheScriptMovedTheParty`：
  腳本有寫座標的重畫要換地形碼，沒寫座標的不能動它——只釘一邊的話
  「每次重畫都重讀」與「永遠不重讀」各會過一邊。

★ 效果已量到：把 spec 1160 那六件事套上去之後，眼魔洞穴到站時的
`C04E`／`C04F` **不再需要測試手動補**，直接就是 `8`／`0C0h`。

## ⚠ 剩下的是內容順序，不是引擎

六件事全部套上、九處斷言全部改完之後，`internal/game` 只剩主線通關測試的
眼魔洞穴那一段。卡住的點已經定位到 `ECL4/0x22:0651h`：

```text
0631h  PRINTCLEAR "YOU SEE THE REMAINS OF AN ELF FIGHTER."
0651h  COMPARE 4C06 01
0657h  IF =   → GOTO 0E41h     { 已經看過就跳過選單 }
065Ch  IF <   → GOTO 066Bh     { 第一次：SAVE 01 4C06 之後才開選單 }
```

⇒ 死精靈那個選單是**一次性**的（`4C06`）。投影生效之後主線會在更早的地方
先走到那一格，選單就在那時被消費掉，等到這一段的斷言時只剩敘述。
**這不是引擎問題，是那一段測試的內容順序要跟著重排。**

## ★★ 巫師塔怎麼走（`ECL5/0x33`）

`GEO5/0x33` 上是**五個互不相連的房間**，層與層之間只靠樓梯事件接：

| 房間（格數）| 樓梯格 → 要站的朝向 |
|---|---|
| 15 | `(3,1)` → 北 |
| 19 | `(8,0)` → 南（往上）、`(5,4)` → 西（往下）|
| 34 | `(9,5)` → 東、`(14,1)` → 北 |
| 47 | `(14,6)` → 南、`(9,12)` → 西 |
| 87（地面層）| `(0,12)` → 東（往上）|

朝向表在 `1C81h`，由 `ECL5/0x33:090Ch` 用地形碼查；**朝向不對就直接 `EXIT`**，
畫面上什麼都不會發生。⚠ 表對索引 1 給的是 `5`，不是合法朝向——那一格
（`(7,15)`）不是樓梯，它走 `07D7h` 那條分支，`07E2h` 要求 `C04D == 1`（朝東），
對了才演「地道還是荒野」的出口選單（`0811h`）。

★ 劇情把隊伍搬進塔頂 `(3,1)` 之後，走法是：`(3,1)` 往北下樓 → `(5,4)` 往西
下樓 → `(14,1)` 往北 → `(9,12)` 往西 → 地面層 → 走到 `(7,15)` 朝東 → 出口選單。
⚠ 每一層的另一道樓梯是**回頭路**，要記下用過哪些，否則會在上下之間來回。

## ★★ 眼魔洞穴的傳送器（`ECL4/0x22`）

走到 `(5,9)` 會演：

```text
05C1h  PRINTCLEAR "YOU SEE THE WALLS AROUND BLUR TO A GRAY SMEAR."
05EBh  PRINTCLEAR "YOU ARE SUDDENLY SLAMMED AGAINST A WALL."
060Ch  DAMAGE     C0 02 0A 00 04
061Bh  SAVE 0D C04B; SAVE 01 C04C; SAVE 03 C04D
062Dh  CALL 2E10
0631h  PRINTCLEAR "YOU SEE THE REMAINS OF AN ELF FIGHTER."
```

⇒ 傳送到 `(13,1)` 朝西，而且**死精靈那一段就在同一次執行裡印出來**。
game pack 的 `zhentil-keep.beholder-cave.same-block-launch` 那條
`set_map_position` 是投影被壓掉時的替身，位置那一半已經不需要了；
但它同時帶的 `wall_type`／`wall_roof`／`4C03 := 0` 還有人用——那正是上面
那個結構問題的症狀。

## ★★ 測試走訪器的兩條規則（實驗裡加的，下一輪照用）

- **落點不是規劃的那一格就把控制權交回呼叫端。** 劇情隨時會搬隊伍；照舊計畫
  繼續走，目標很可能在新位置那一區根本走不到，最後會以「目標走不到」收場
  ——**症狀出現在終點，原因在中間某一步**。
- **開鎖門那條子路徑也要記「被拒的邊」**（第 629 輪只加在主迴圈）。
- 寫死的隨機格排除清單（`(10,2)`／`(8,11)`／`(8,15)`／`(12,10)`）是**逐圖**的，
  巫師塔那張圖要放行：`(8,15)` 與 `(12,10)` 落在它的走廊上，排除掉會把第 15 列
  切斷，看起來就像「塔頂下不來」。
