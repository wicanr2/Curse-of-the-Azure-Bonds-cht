# 813 — 休息時間怎麼算出來的：等級總和 × 15 分 ＋ 4 或 6 小時

- 證據等級：`exact`（**PC-98 側**逐條讀完；DOS 側的匯出有三處反組譯錯位，已用
  原始位元組確認兩平台完全相同）
- 作法見 spec 783；錯位的判定方式見 spec 811

## `overlay-15:0034h`（entry#2，121 條，實質差異 7 條）

`retf 4` ＝ 一個角色遠指標，回傳 `ax`。

```pascal
最高A := 0;  最高B := 0;  總A := 0;  總B := 0;

for i := 0 to 53h do                                   { 角色的 84 格 }
    if 角色^[1Eh + i] > 7Fh then begin                 { 還在記憶中 }
        lv := byte[37DBh + (角色^[1Eh+i] and 7Fh) * 10h];
        if lv > 最高A then 最高A := lv;                { 無號 }
        總A := 總A + lv;                               { byte 加法 }
    end;

p := 角色^[14Dh];
while p <> NIL do begin
    if <far 11DEh>(p) then
        for i := 1 to 3 do
            if p^[3Bh + i] > 7Fh then begin            { 抄寫中的槽 }
                lv := byte[37DBh + (p^[3Bh+i] and 7Fh) * 10h];
                if lv > 最高B then 最高B := lv;
                總B := 總B + lv;
            end;
    p := p^[2Ah];
end;

d := 0;
if (總A > 0) or (總B > 0) then d := 4;
if (最高A > 2) or (最高B > 2) then d := 6;
角色^[72h] := d;

結果 := 總A * 0Fh + d * 3Ch + 總B * 0Fh;
```

## 休息／記憶這條線到此完全閉合

| 量 | 存在哪 | 怎麼來的 | 出處 |
|---|---|---|---|
| 需要休息幾小時 | 角色 `+72h` | 本支：`0` / `4` / `6` | 本支 |
| 總共要花多少分鐘 | 回傳值 | `(總A + 總B) × 15 + 小時 × 60` | 本支 |
| 剩餘休息時間（日:時:分） | `DS:7566h` 七個 word | 倒數，spec 802／803 | 802／803 |
| `+72h` 每 12 拍減 1 | — | `overlay-20:0BB6h` | 789 |
| 每個法術還要幾拍 | `DS:7573h + i` | 法術等級 × 3 | 791／792 |
| 記完一個 | — | `overlay-20:091Dh`，印 `'has memorized'` | 792 |
| 抄完一個 | — | `overlay-20:09DFh`，印 `'has scribed'` | 803 |

**每個法術等級 15 分鐘**，另外要先睡 **4 小時**（最高只到 2 級）或 **6 小時**
（有 3 級以上）。與 AD&D 的記憶規則一致。

`+72h` 因此是**休息小時數的倒數**——spec 789 只知道它「每 12 拍減 1」，現在知道
它一開始就是 4 或 6，所以**12 拍 ＝ 一小時**。

### 兩種來源分開統計、合併計時

角色自己的 84 格（要記憶的法術）與物品鏈上每件東西的三個效果槽（要抄寫的法術）
**各自算最高等級與總和**，但最後併成同一個時間。`d` 取兩邊的較嚴格者。

### 缺陷：總和是 byte，會迴繞

`總A` / `總B` 都是 byte，用 `add` 累加**沒有進位**。84 格全部記著 4 級以上的
法術時 `總A` 會超過 255 而迴繞，休息時間變成一個很小的數。remake 要照抄還是
修正必須明講。

同理 `最高A` / `最高B` 的比較是**無號**的，但法術等級只有 1..7，不會出問題。

## DOS 側的匯出有三處錯位

| 位置 | DOS 匯出 | PC-98 匯出（正確） |
|---|---|---|
| `0068h` | `in al, 0C4h` ／ `jle short loc_72` | `xor ah, ah` ／ `les di, [bp+arg_0]` |
| `0082h` | `hlt` | `mov [bp+var_C], al` |
| `00FCh` | `hlt` | `mov [bp+var_C], al` |

原始位元組兩平台**完全相同**：

```
0064: 8A 46 F5 30 E4 C4 7E 06 03 F8 26 8A 45 1E
007C: 8A 85 DB 37 88 46 F4          （PC-98 只差 DB 37 → B5 61）
```

`8A 85 DB 37` ＝ `mov al, [di+37DBh]`、`88 46 F4` ＝ `mov [bp+var_C], al`；
DOS 側的 IDA 把 `88 46` 吃掉之後把 `F4` 單獨解成 `hlt`。

這是本專案先前**刻意不標「已解讀」**的其中一支（匯出讀不通就不猜）。現在由
PC-98 側的正確解碼補上，兩邊的判讀一致。

## 明確不宣稱

- 沒有宣稱 `far 11DEh` 判物品的什麼（形狀上是「這件東西上有沒有可抄的法術」）。
- 沒有宣稱回傳的分鐘數由誰換算進 `DS:7566h` 那七個 word。
- 沒有宣稱 `d` ＝ 0（沒有任何要記的法術）時呼叫端會不會直接跳過休息。
