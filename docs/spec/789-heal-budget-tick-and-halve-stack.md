# 789 — 定額治療的分配、每 12 拍的倒數、物品堆「對半分」

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側的運算元差異已逐條列出）
- 作法見 spec 783

## `overlay-15:2255h`（entry#30，63 條，差異 5 條）— 把一筆治療量分給全隊

```pascal
p := DS:650Ah;                                  { 角色鏈結串列 }
while p <> NIL do begin
    if p^[78h] > p^[1A4h] then begin            { 最大 HP > 目前 HP，無號比較 }
        缺 := p^[78h] − p^[1A4h];
        if 缺 > ss:[rec − 2] then 缺 := ss:[rec − 2];   { 不能超過剩餘額度 }
        if 缺 < 1 then 缺 := 0;
        if 缺 > 0 then
            if <148Ah:149Eh>(p, byte(缺), 0) then
                if 缺 <= ss:[rec − 2] then
                    ss:[rec − 2] := ss:[rec − 2] − 缺;
    end;
    p := p^[189h];
end;
```

`retf 2` ＝ 一個 word：呼叫端框架裡的記錄位址，**剩餘可治療量放在 `rec − 2`**。

- **順序決定誰拿得到**：沿著 `DS:650Ah` 的鏈結由前往後補，前面的成員補滿之後
  才輪到後面，額度用完的成員一格都拿不到。這是 remake 要照抄的行為。
- 額度扣除**只在治療呼叫回傳成功時發生**；回傳失敗時額度不動，但迴圈照樣往下走。
- `缺 < 1 then 缺 := 0` 這一段在無號比較下是死碼（`缺 = 0` 時本來就跳過），
  但它證明比較是無號的——所以 `p^[78h] > p^[1A4h]` 那個前置判斷是必要的：
  少了它，減法會迴繞成很大的值。

欄位與 spec 784 一致：`+78h` 最大 HP、`+1A4h` 目前 HP、`+189h` next（PC-98 各 ＋1）。

## `overlay-20:0BB6h`（entry#16，65 條，差異 5 條）— 每 12 拍跑一次的倒數

```pascal
inc(計數^);                                     { arg_0 是遠指標 }
if 計數^ < 0Ch then 離開;                       { 無號比較 }
計數^ := 0;
i := 1;
p := DS:650Ah;
while p <> NIL do begin
    if p^[72h] > 0 then begin                   { 有號比較 }
        dec(p^[72h]);
        if p^[72h] = 0 then begin
            旗標 := 1;
            r := <本模組 09DFh>(p, @旗標);
            if r = 0 then r := <本模組 091Dh>(p, @旗標);
            byte[7573h + i] := r * 3;
        end;
    end;
    p := p^[189h];
    inc(i);
end;
```

`retf 4` ＝ 一個遠指標。

**`+72h` 就是 `+1Eh` 那 84 格記憶法術陣列的下一個 byte**（`1Eh + 54h = 72h`，
spec 788），是一個**每 12 拍減 1 的倒數**；歸零時重算某個狀態並把
`結果 × 3` 寫進 `DS:7573h + i`（i 由 1 起算，跟著鏈結順序走）。

`× 3` 這個倍數與 spec 772 的七欄金錢顯示無關；它是寫進一個 byte 陣列的值，
remake 不能自行改成 1 倍。

PC-98 的陣列在 `DS:0A65Fh`（`di − 59A1h`）。

## `overlay-19:21F3h`（entry#20，66 條，差異 19 條）— 物品堆對半分

| | DOS | PC-98 |
|---|---|---|
| 節點大小 | `3Fh`（63） | `67h`（103） |
| 數量欄 | `+39h` | `+61h` |
| next | `+2Ah` | `+52h` |
| 清掉的欄 | `+34h` | `+5Ch` |
| 訊息 | `'Can't halve that'`（16） | `'それは分けることはできません'`（28 bytes） |

```pascal
半 := 有號(節點^[39h]) div 2;
if 半 > 0 then begin                            { 無號比較 }
    餘 := 節點^[39h] − 半;
    GetMem(新, 3Fh);
    Move(節點^, 新^, 3Fh);                      { 整個節點複製一份 }
    新^[39h] := 半;
    新^[34h] := 0;
    新^[2Ah] := 節點^[2Ah];                     { 插在原節點後面 }
    節點^[39h] := 餘;
    節點^[2Ah] := 新;
end else
    顯示('Can't halve that');
```

三件要照抄的事：

- **新節點拿的是 `div 2`（少的那半），原節點留下餘數**。奇數量分下去，原節點
  多一個。
- **新節點的 `+34h` 被清成 0**——複製出來的那半**不繼承**這個欄位。原節點的
  `+34h` 不動。
- `retf 4` ＝ 一個遠指標；分裂後**回傳值沒有**，呼叫端只能靠鏈結自己找新節點。

數量欄是 byte 且 `div 2` 走**有號**除法：值 ≥ `80h` 時會得到負的一半，接著
`半 > 0` 用**無號**比較——負值當成大的無號數而通過。`餘 := 數量 − 半` 於是
變成加法。**這一路沒有任何防護**，remake 若允許數量超過 127 必須自行處理。

`GetMem` / `Move` 是 `0A54h:0329h` / `0A54h:1ABDh`（PC-98 `081Fh:0043h` /
`0A65h:1B0Dh`）；參數順序由推入順序判定（先推的是第一個宣告參數）。

## 明確不宣稱

- 沒有宣稱 `DS:7573h` 那個 byte 陣列顯示在哪裡。
- 沒有宣稱 `overlay-20` 的 `09DFh` / `091Dh` 各算什麼；只確定前者回 0 時才問後者。
- 沒有宣稱 `+72h` 的 12 拍是遊戲內多久。
- 沒有宣稱物品節點 `+34h` 裝什麼；只確定複製時要清掉。
- 沒有宣稱 `148Ah:149Eh` 是「加 HP」；只確定它收 (角色, 量, 0) 且回傳成功與否。
