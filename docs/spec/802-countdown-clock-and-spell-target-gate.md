# 802 — 休息時間的倒數（與遊戲時鐘共用進位表）、施法目標的閘門

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側的運算元差異已逐條列出）
- 作法見 spec 783

## `overlay-20:045Eh`（entry#8，92 條，差異 12 條）— 倒數扣時間

```pascal
if (DS:7568h = 0) and (DS:756Ah = 0) and (DS:756Ch = 0) and (DS:756Eh = 0) then 離開;
repeat
    if 數量 > word[7566h + 索引 * 2] then begin          { 無號 }
        j := 索引 + 1;
        while (word[7566h + j * 2] = 0) and (j < 5) do inc(j);
        if j = 5 then begin
            FillChar(DS:7566h, 0Eh, 0);                  { 整組清零 }
            數量 := 0;
        end else
            for k := j downto 索引 + 1 do begin
                dec(word[7566h + k * 2]);
                word[7566h + (k − 1) * 2] :=
                    word[7566h + (k − 1) * 2] + word[3E2Ah + (k − 1) * 2];
            end;
    end else begin
        word[7566h + 索引 * 2] := word[7566h + 索引 * 2] − 數量;
        <本模組 0385h>();
        離開;
    end;
until false;
```

`retf 4` ＝ 2 個 word：`(索引, 數量)`。

### `DS:7566h` 是休息時間的七個 word

`DS:7566h` 起那七個 word 是**休息時間**（畫面標題 `'Rest Time:'`，spec 803）。
它與 spec 793 的遊戲時鐘（`DS:4F99h^[18Ch]`）**共用同一張進位上限表
`DS:3E2Ah`**（`10, 10, 6, 24, 30, 12, 256`），單位完全相同，但方向相反：
那一組往上加、這一組**往下扣**，不夠就從高位借。

這正好解釋 spec 792 裡 `overlay-15:2309h` 為什麼要存下／還原 `DS:7566h` 起的
**14 bytes** ——那就是這七個 word。

### 借位只到索引 4（日）

- 進場的守衛只檢查索引 **1..4**（`7568h` / `756Ah` / `756Ch` / `756Eh`）；
  四個都是 0 就直接返回，**連索引 0 都不扣**。
- 借位迴圈的上界是 `j < 5`，`j` 走到 5 就判定借不到，**整組清成 0**。
  所以索引 5（月）與 6（年）的值在這一支裡永遠不會被借走。

### 借位是一次搬一階

`for k := j downto 索引+1`：每一階把高位減 1、低位加上**那一階的上限**
（`3E2Ah + (k−1)*2`），一路傳到 `索引 + 1`。傳完之後回到最外層重試，這次
`索引` 那一格才夠減。

## `overlay-09:03B1h`（entry#11，97 條，差異 11 條）— 施法前的目標閘門

```pascal
可 := 0;
if byte[37E7h + 法術 * 10h] < 門檻 then 結束;              { 無號，屬性 +0Dh }
if 法術 = 3 then begin
    if <far 0C84h+1>(@暫存, 參數4, 參數6) then begin 可 := 1; 結束 end
end
else if byte[37E8h + 法術 * 10h] = 0 then begin 可 := 1; 結束 end;   { 屬性 +0Eh }

n := <far 158Eh+2>(<本模組 11CFh>(法術), 參數4, 參數6);
if n <= 0 then 結束;                                       { 無號 }
if byte[37E9h + 法術 * 10h] = 0 then begin 可 := 1; 結束 end;        { 屬性 +0Fh }
for k := 1 to n do begin
    i := byte[758Eh + k];

end;

```

`retf 8` ＝ 4 個 word，回傳 `al`。

### 法術屬性表又多三欄有了用途

`37E7h` / `37E8h` / `37E9h` ＝ `DS:37DAh` 的 `+0Dh` / `+0Eh` / `+0Fh`
（spec 773 的 56 列表已經把這三欄的值全部排出來）：

| 欄 | 這一支怎麼用 |
|---|---|
| `+0Dh` | 小於傳進來的門檻就整支失敗 |
| `+0Eh` | ＝ 0 就直接通過，不再檢查目標 |
| `+0Fh` | ＝ 0 就直接通過，不逐一檢查每個目標 |

對照 spec 773 的表：`+0Eh` 在 `Bless`／`Cure Light Wounds`／`Detect Magic` 是
`00`，在 `Curse`／`Cause Light Wounds` 是 `01`。形狀上「`+0Eh` ≠ 0 才需要檢查
目標」。

### 法術編號 3（`Cure Light Wounds`）有硬寫死的特例

`cmp [bp+arg_2], 3` ——編號 3 **不走 `+0Eh` 那條判斷**，改問
`<far 0C84h+1>(@暫存, 參數4, 參數6)`；回真才直接通過，回假就掉進「要逐一檢查
目標」的那條路。

remake 不能把它併進資料驅動的規則：**這是程式碼裡對單一法術編號的例外**。

### 目標清單在 `DS:758Eh`

`158Eh+2` 回傳筆數 `n`，清單放在 `DS:758Eh + k`（k 由 1 起算），每格是一個
**戰鬥員索引**；再用 `DS:66A3h + i * 4` 的 `+0` / `+1` 取世界座標（spec 785）
餵給 `02B1h`。**任何一個目標讓 `02B1h` 回真，整支就失敗。**

`02B1h` 是巢狀程序（呼叫時多推一個 `bp` 當靜態鏈），參數依宣告順序是
`(x, y, 法術)`。
