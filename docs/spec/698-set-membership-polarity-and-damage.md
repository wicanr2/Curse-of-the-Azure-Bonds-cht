# 第六百九十八輪：`0A54:08D4h` 的旗標極性，與傷害後的狀態判定

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：DOS `overlay-24:2421h`；極性由 `overlay-26:06B5h` 判定。

## `0A54:08D4h(值, @集合)` 是 Pascal 的 `in`

DOS 側有 **53 個呼叫點**（跨 17 個 overlay），形狀一律是

```text
push 值
mov di, offset 集合常數 ; push cs ; push di
call far 0A54h:08D4h
jz／jnz ...
```

`call` 之後**直接**接條件跳躍，中間沒有 `or al, al`——所以旗標是這支自己設的，
不能當成「回傳布林值再自行測試」。

集合常數是 Turbo Pascal 的 32 bytes 位元集合（0..255，低位元在前）。

### 極性

`overlay-26:06B5h` 把它定死了。那裡先用 `0A54:1C62h` 把字元轉大寫，再測
`CS:0394h` 的集合——解出來是 **`{空白, '0'..'9', 'A'..'Z'}`**：

```text
call far 0A54h:08D4h
jz   短跳到本輪結束        ← 跳走的是「不能用的字元」
cmp  ch, ' '               ← 沒跳走的才繼續處理
```

輸入處理只會處理合法字元，而集合裝的正是合法字元。所以

> **`ZF = 1` 代表「不在集合裡」，`ZF = 0` 代表「在集合裡」。**

反過來讀會讓所有 `jz`／`jnz` 的分支對調——而兩邊通常都跑得起來，不會當掉。

## `2421h(傷害, 角色)`：扣血並決定狀態

```text
if 角色^[1A4h] >= 傷害 then 剩餘 := 角色^[1A4h] − 傷害；溢出 := 0
else                        溢出 := 傷害 − 角色^[1A4h]；剩餘 := 0

if 溢出 > 9                              then 角色^[195h] := 6
elif 剩餘 = 0 且 角色^[195h] = 1          then 角色^[195h] := 6
elif 溢出 > 0 then
    角色^[195h] := 5
    if DS:4FBAh = 5 then 角色^[18Dh]^[0Eh] := 溢出
elif 剩餘 = 0                             then 角色^[195h] := 4
（其餘情況狀態不變）

if 角色^[195h] in {0, 1} then
    角色^[1A4h] := 剩餘
else
    角色^[196h] := 0
    角色^[1A4h] := 0
    if DS:4FBAh = 5 then
        byte [6F90h + 角色^[197h]] −= 1        ← spec 692 的統計陣列
        角色^[18Dh]^[3] := 0
retf 6
```

`溢出 > 9` 就是 **HP 到達 −10 判定死亡**：`溢出` 是「低於 0 多少」，超過 9
表示 HP ≤ −10。這與既有台帳裡 AD&D 的死亡門檻是同一條規則的另一個出處。

`溢出` 在 1..9 之間是狀態 5，並且**只在 `DS:4FBAh = 5` 時**把負值記進
`角色^[18Dh]^[0Eh]`——所以「還欠多少血」這個數字不是每個畫面都會維護。
spec 696 的包紮把 `[0Eh]` 清成 0、狀態 5 降為 4，兩邊對得上。

`剩餘 = 0 且 原狀態 = 1` 直接跳到狀態 6（不是 4），是唯一一條「原狀態影響
結果」的路徑。

最後的集合測試用的是**更新後**的狀態：留在 `{0, 1}` 才正常寫回剩餘 HP，
否則 HP 歸零並從隊伍統計裡扣掉一個。

## 明確不宣稱

- 狀態值 0／1／4／5／6 各自的名稱。
- `角色^[196h]`、`角色^[18Dh]^[3]`、`+18Dh^[0Eh]` 的語意。
- `DS:4FBAh = 5` 是哪個畫面。
- `0A54:1C62h`（轉大寫）的完整行為。
