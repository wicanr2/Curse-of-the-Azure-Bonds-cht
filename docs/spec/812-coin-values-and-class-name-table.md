# 812 — 幣值換算表、職業名稱表（19 筆，含一句彩蛋）、取鏈上第 N 個節點

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側的差異已逐條列出；兩張表取自常駐
  資料段 dump）
- 作法見 spec 783；近似同形配對的判讀方式見 spec 811

## `overlay-19:33ABh`（entry#22，44 條，實質差異 7 條）— 身上的錢值多少金幣

`retf 4` ＝ 一個角色遠指標，回傳 `dx:ax`（longint）。

```pascal
總 := 0;
for j := 0 to 4 do
    總 := 總 + <0A54h:0279h>(longint(角色^[0FBh + j * 2]),
                             longint@(0CA2h + j * 4));
結果 := <0A54h:0294h>(總 + 64h, longint@0CAEh);
```

### 幣值表 `DS:0CA2h`（PC-98 `DS:1C46h`），5 個 longint，兩平台相同

| j | 幣別（spec 773 的名稱表） | 值 |
|---|---|---|
| 0 | Copper | 1 |
| 1 | Silver | 10 |
| 2 | Electrum | 100 |
| 3 | **Gold** | **200** |
| 4 | Platinum | 1000 |

單位是**銅幣**。AD&D 一版的換算（1 gp ＝ 20 sp ＝ 200 cp、1 ep ＝ ½ gp、
1 pp ＝ 5 gp）逐格相符。

除數 `0CAEh` 就是 `0CA2h + 3 × 4` ——**索引 3（金幣）自己那一格**。加上的
`64h`（100）正好是除數的一半，所以整條式子是

```
金幣數 = round( Σ 錢[j] × 值[j] / 200 )
```

**只算前 5 種幣別**；`+0FBh` 那 7 個 word 的後兩格（Gems / Jewelry）不計入。

`0A54h:0279h` / `0A54h:0294h` 是 32 位元的乘與除（收兩個 longint、回一個 longint）。

## 職業名稱表 `DS:0CB6h`（PC-98 `DS:1C5Ah`）

固定長度的 Pascal 字串陣列：**DOS 每筆 27 bytes、PC-98 每筆 35 bytes**，
共 **19 筆**。

| # | DOS | PC-98 |

| 18 | `Monster` | `モンスター` |

### 前 8 筆就是職業槽 0..7

spec 810 與 811 從進階表與攻擊表的形狀推出「c ＝ 0 牧師、2 戰士、3 聖騎士、
4 遊俠、5 法師、6 盜賊」；這張表**逐格印證**，並補上 **c ＝ 1 是德魯伊、
c ＝ 7 是武僧**。spec 810 說「列 1 是遊俠寫進去的那一列」，現在可以合理對應到
德魯伊系——但本規格仍不宣稱，因為沒有直接證據把「列 1」與「職業槽 1」連起來。

### 索引 17 是開發者留下的彩蛋

`'OK buddy, who are you?'`（22）——職業組合對不上任何一筆時的預設值。
PC-98 照樣翻成日文，所以**中文版也該翻**（這是玩家看得到的字串，不是內部訊息；
與 spec 799 的 `Show3DSprite` 錯誤訊息剛好相反）。

### 中文化的三個注意點

- **固定長度陣列**：DOS 27、PC-98 35。中文版的 stride 要按最長那筆重新算，
  不能沿用。最長的是索引 9（DOS 25 字元／PC-98 20 bytes）。
- **分隔符號**：DOS 用半形 `/`，PC-98 換成全形 `／`。
- ⚠ **PC-98 自己有個錯字**：索引 4 的 `レンジャ－` 用的是 `81 5C`（`―` 橫線），
  索引 10 的 `レンジャー` 用的才是 `81 5B`（`ー` 長音符）。**同一個詞在同一張表裡
  兩種寫法**，中文版不要跟著抄。

## `overlay-26:0011h`（entry#2，38 條，實質差異 6 條）— 取鏈上第 N 個節點

`retf 6` ＝ 3 個 word。依宣告順序：`(索引, 串列頭)`，回傳 `dx:ax`。

```pascal
n := 0;  p := 串列頭;
while (p <> NIL) and (n <> 索引) do begin
    p := p^[2Ah];
    inc(n);
end;
if n = 索引 then 結果 := p else 結果 := NIL;
```

`+2Ah` 是物品節點的 next（spec 789／794）。串列比索引短時 `p` 會先變成 NIL，
迴圈跟著結束，`n < 索引` 於是回 NIL——**兩種「找不到」都回 NIL，呼叫端分不出來
是走完了還是剛好停在 NIL**。

## 兩支的平台差異都是編譯器碼型，不是行為差異

兩支的助憶碼序列各有**一個位置**不同，形狀完全一樣：

```
DOS   mov ax, [bp+var]      /  mov dx, [bp+var+2]
PC-98 les ax, [bp+var]      /  mov dx, es
```

兩種寫法都把同一個 4-byte 值載進 `dx:ax`（PC-98 那版順便改了 `ES`，而後面沒有
用到 `ES`）。**這是編譯器版本的差異，不是兩平台實作不同**——與 spec 811 的
反組譯錯位是不同的成因，但結論一樣：可以共用一份判讀。
