# 793 — 遊戲時鐘的七個單位、角色之間給錢

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側的運算元差異已逐條列出；進位上限
  取自常駐資料段 dump）
- 作法見 spec 783

## `overlay-20:02D8h`（entry#6，69 條，差異 4 條）— 時鐘進位

```pascal
for i := 0 to 6 do
    if 時鐘[i] >= word[3E2Ah + i * 2] then begin       { 無號比較 }
        if i <> 6 then begin
            inc(時鐘[i + 1]);
            時鐘[i] := 時鐘[i] − word[3E2Ah + i * 2];
        end else begin
            p := DS:650Ah;
            while p <> NIL do begin
                inc(word(p^[76h]));
                p := p^[189h];
            end;
        end;
    end;
```

`retf 4` ＝ 一個遠指標（指向 7 個 word 的時鐘陣列）。

### 進位上限表在 `DS:3E2Ah`（PC-98 `DS:6804h`），兩平台一模一樣

| 索引 | 上限 | 單位 |
|---|---|---|
| 0 | 10 | 進位到 1 分的十分之一 |
| 1 | 10 | 分 |
| 2 | 6 | 十分鐘 |
| 3 | 24 | 時 |
| 4 | 30 | 日 |
| 5 | 12 | 月 |
| 6 | 256 | 年 |

`24 / 30 / 12` 三個值把單位釘死：`[3]` 是**時**、`[4]` 是**日**、`[5]` 是**月**、
`[6]` 是**年**。往下推 `[2]` 是十分鐘、`[1]` 是分、`[0]` 是分的十分之一（6 秒）。

配合 spec 790：時鐘本體存在 `DS:4F99h^[18Ch]` 起的 7 個 word
（PC-98 `DS:7F05h^[18Ch]`）。

### 兩個要照抄的行為

- **每呼叫一次，每個單位最多只進一位**（`if` 不是 `while`）。所以推進時間要
  一次加一、每次都呼叫，不能先加 N 再進位一次——spec 790 的 `03B9h` 正是這樣做的。
- 迴圈由低到高單向跑一遍，所以**一次呼叫可以連鎖進位**（分滿了進十分鐘、
  十分鐘滿了進時……一路到年）。

### 索引 6 溢位時不歸零（缺陷）

年滿 256 時，全體角色的 `+76h`（word）＋1，但**時鐘[6] 沒有減掉 256**。下一次
呼叫條件仍然成立，於是每呼叫一次就再加一次。實際遊戲跑不到 256 年，這條路
到不了，但 remake 若要沿用這張表必須自己補上歸零。

## `overlay-21:046Bh`（entry#12，71 條，差異 6 條）— 把錢從一個角色給另一個

| | DOS | PC-98 |
|---|---|---|
| 訊息 | `'Overloaded'`（10） | `'持ちすぎです'`（12 bytes） |

`retf 0Ch` ＝ 6 個 word。依宣告順序（先推的是第一個參數）：
`(給方, 收方, 數量, 幣別)`，其中給方／收方各是一個**指向遠指標的遠指標**。

```pascal
上限 := <本模組 001Bh>(收方^);
if 收方^^[187h] + 數量 > 上限 then                    { 無號比較 }
    顯示(名字 ＋ 'Overloaded')
else begin
    給方^^[0FBh + 幣別 * 2] := 給方^^[0FBh + 幣別 * 2] − 數量;
    <本模組 003Bh>(數量, 給方^);
    收方^^[0FBh + 幣別 * 2] := 收方^^[0FBh + 幣別 * 2] + 數量;
    <本模組 0057h>(數量, 收方^);
end;
```

- `+0FBh` 起那 7 個 word 的金錢陣列（spec 772／786）第一次看到**任意幣別**的
  索引用法：`幣別` 是參數，直接乘 2 當位移。
- `+187h` 是收方目前的負重，`001Bh` 算上限——**只檢查收方，不檢查給方**。
- **沒有餘額檢查**：給方那一格直接減，不夠就迴繞成很大的值。呼叫端必須先擋。
- `003Bh` / `0057h` 成對出現（減完呼叫前者、加完呼叫後者），`0057h` 就是
  spec 786 撿錢時用的同一支。

### 又一個重複字串陷阱

`'Overloaded'`（10）在本模組；`overlay-19` 有 `'Overloaded'`、`overlay-06` 有
`'OverLoaded'`（大小寫不同）、spec 786 的 `overlay-21:021Ch` 則是
`'Overloaded.  Money will be put in Pool.'`。**四處各自獨立，翻譯時要逐處替換**，
不能用單一字串取代。

## 明確不宣稱

- 沒有宣稱時鐘的絕對起點。
- 沒有宣稱角色 `+76h`（word）是什麼；只確定年溢位時它會 ＋1。
- 沒有宣稱 `overlay-21:001Bh` 算的上限是重量還是件數。
- 沒有宣稱 `003Bh` / `0057h` 做什麼（各收到數量與一個角色遠指標）。
