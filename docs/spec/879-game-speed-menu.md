# 879 — 遊戲速度選單：DOS 動態串接選項，PC-98 固定欄位 ＋ 熱鍵寫進固定位置

- 證據等級：`exact`（兩平台各自逐條讀完）
- 作法見 spec 783

## `overlay-08:011DFh`（DOS 133 條）↔ `overlay-08:0124Dh`（PC-98 123 條）

`retf` ＝ 無參數。

| | DOS | PC-98 |
|---|---|---|
| 標題 | `'GameSpeed ('` ＋ 數字 ＋ `') :'` | `'速さ（'` ＋ 數字 ＋ `'）'` |
| 變慢 | `'Slower '` | `' 遅く '` |
| 變快 | `'Faster '` | `' 速く '` |
| 離開 | `'Exit'` | `'抜ける'` |

```pascal
鍵 := 20h;
while <0A54h:08D4h>(離開鍵表, 鍵) do begin
    標題 := 'GameSpeed (' ＋ <far 014Dh:0052h>(DS:4FA9h) ＋ ') :';
    選項 := '';
    if DS:4FA9h < 9 then 選項 := 選項 ＋ 'Slower ';     { 無號 }
    if DS:4FA9h > 0 then 選項 := 選項 ＋ 'Faster ';     { 無號 }
    選項 := 選項 ＋ 'Exit';
    鍵 := <far 0167h:002Fh>(@DS:75DBh, 0, 0, 0Fh, 0Ah, 0Dh, 選項, 標題);
    if      鍵 = 'S' then inc(DS:4FA9h)
    else if 鍵 = 'F' then dec(DS:4FA9h);
end;
```

`DS:4FA9h` 是速度值，範圍由兩道邊界夾出來：**0..9**。
`'Slower'` 走 `inc`、`'Faster'` 走 `dec`——**值越大越慢**。
到 9 就不再顯示 `Slower`、到 0 就不再顯示 `Faster`，
所以邊界是靠「選項消失」而不是靠按鍵無效來擋。

每個字串指派的上限都是 `28h`（40），與 spec 859 的 `string[40]` 一致。

## PC-98 把選項改成固定欄位，熱鍵寫進固定位置

這一支是那個模式**最直接的證據**。PC-98 不做字串串接，而是：

```asm
指派(DS:0A37Eh, 6)            ; 固定寬度的欄位
mov byte ptr ds:0A33Eh, 45h   ; 'E'  ← Exit 的熱鍵
mov byte ptr ds:0A33Bh, 53h   ; 'S'  ← 遅く 的熱鍵
mov byte ptr ds:0A33Ah, 46h   ; 'F'  ← 速く 的熱鍵
```

**熱鍵緩衝是一個字元陣列，每個選項的熱鍵寫在自己的固定 offset**
（`0A33Ah`／`0A33Bh`／`0A33Eh`），而不是從標籤裡取首字母。
spec 865／871／877 看到的「把 10 bytes 指派到 `DS:0A335h`」是同一塊緩衝
（`0A335h` ＋ 5／6／9），這裡是逐格寫入的版本。

**字母熱鍵 `S`／`F`／`E` 兩平台完全相同**——日文標籤 `' 遅く '`／`' 速く '`／
`'抜ける'` 完全不含這些字母，所以熱鍵只能另外指定。
