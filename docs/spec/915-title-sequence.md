# 915 — 片頭四張圖：DOS 漏釋放第一張，PC-98 補上

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側逐條讀完）
- 作法見 spec 783

## `overlay-01:00634h`（DOS 142 條）↔ `overlay-01:00936h`（PC-98 162 條）

`retf` ＝ 無參數。整支只有一個字串常數：**`'title'`**（資源檔名）。

```pascal
{ PC-98 多一行：DS:8BF3h := 1 }
圖 := NIL;

檔名 := 'title';   載入(檔名, 1, 0, 0, @圖);
                   { PC-98 多一個 byte 參數，並在此 額外(DS:8BF3h) }
顯示(0, 0, 圖);
延遲(5);

if DS:4F98h = 0 then 離開;                { PC-98：DS:7F04h }

{ ★ PC-98 在這裡 釋放(@圖)；DOS 沒有 }

檔名 := 'title';   載入(檔名, 2, 0, 0, @圖);
顯示(0, 0, 圖);
{ PC-98 多 延遲(5) }
釋放(@圖);

檔名 := 'title';   載入(檔名, 3, 0, 0, @圖);
顯示(6, 0Bh, 圖);                          { PC-98：顯示(5, 0Bh, 圖) }
釋放(@圖);
延遲(0Ah);

檔名 := 'title';   載入(檔名, 4, 0, 0, @圖);
音效(word[25C6h]);                         { PC-98：音效(word[4854h]) }
顯示(0, 0Bh, 圖);
釋放(@圖);
延遲(0Ah);

清畫面();                                  { DOS 0542h:0A0Eh／PC-98 0418h:13B6h }
<本模組 01DFh>();                          { 製作群名單 }
延遲(0Ah);
清畫面();
```

## ⚠ DOS 漏掉第一張圖的釋放

DOS 在旗標檢查通過之後**直接載入第 2 張蓋掉 `圖`**，第 1 張的記憶體沒有還。
PC-98 在同一位置（`099Fh`）補了一次釋放。

**這是 PC-98 修掉 DOS 缺陷的第三個案例**（前兩個：spec 883 的越界寫入、
spec 884 的反組譯錯位不算——那是判讀問題）。片頭只跑一次，所以 DOS 的洩漏
在實際遊玩中不會累積，影響僅限於一張圖的常駐。

## 四張圖的版面

| 圖號 | 位置（列, 欄） | 之後 |
|---|---|---|
| 1 | (0, 0) | 延遲 5；接著判旗標 |
| 2 | (0, 0) | DOS 無延遲；PC-98 延遲 5 |
| 3 | DOS (6, 0Bh)／PC-98 (5, 0Bh) | 延遲 `0Ah` |
| 4 | (0, 0Bh) ＋ 音效 | 延遲 `0Ah` |

圖 2 是整面底圖，圖 3、圖 4 疊在欄 11 上——**DOS 圖 2 之後沒有延遲是合理的**，
因為圖 3 馬上疊上去；PC-98 加了 5 個單位的停頓，是刻意的節奏差異。

圖 3 的列在 PC-98 上移一列（6 → 5）。

## `DS:4F98h`（PC-98 `DS:7F04h`）＝ 播不播完整片頭

為 0 就只留第 1 張圖然後結束，連清畫面都不做。所以那張圖會留在畫面上給
下一段用。

## 呼叫製作群名單

`push cs; call near ptr sub_1DF` ＝ 呼叫本模組的 `001DFh`（DOS 553 條／
PC-98 `00321h` 777 條）。那一支帶著
`'based on the tsr novel "azure bonds"'`／`'by:'`／`'kate novak'`／`'and'`／
`'jeff grubb'`／`'scenario created by:'`——**PC-98 把這幾句改成全大寫**
（`'BASED ON THE TSR NOVEL "AZURE BONDS"'`、`'Kate Novak'`、`'Jeff Grubb'`），
人名維持原大小寫。那一支尚未逐條讀。

## PC-98 多的兩段

- 進入時 `DS:8BF3h := 1`，第一張圖載入後 `<893h:0114h>(DS:8BF3h)`。
  模組 `893h` 同時提供音效（`893h:0`），所以形狀上是**片頭音樂的開關**。
- 載入呼叫多一個 byte 參數（DOS `retf 0Ah` → PC-98 `retf 0Ch`），常數 0。

## 中文化

`'title'` 是資源檔名，**不可翻譯**。四張圖是點陣美術，
中文化要改的是圖本身（見製作群名單那一支的字串）。
