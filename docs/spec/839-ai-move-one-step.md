## `DS:47F0h` ＝ 上一步的方向、`DS:47F1h` ＝ 連續折返次數

spec 838 在進主迴圈前把 `DS:47F0h := 8`、`DS:47F1h := 0`——當時只記成
「開場清三個全域」。本支給了它們語意：

```pascal
if (序號 = 6) or (DS:47F0h = (方向 + 4) mod 8) then …折返處置…
if 序號 < 6 then DS:47F0h := 方向;
```

`(方向 + 4) mod 8` 就是**正反方向**。所以判斷式的意思是「這一步要往回走」。
初值 `8` 落在 0..7 之外，第一步永遠不算折返——**這是刻意選的哨兵值**。

折返的處置是三級的：

| `DS:47F1h` | 處置 |
|---|---|
| 1 | 只換 AI 模式（`+15h := (+15h mod 6) + 1`，spec 830／837 的 1..6 循環） |
| 2 | 再清掉目前目標 `+18Dh^[0Ah]`，並問一次 `0CB7h` |
| ≥ 3 | 移動力歸零、直接停 |

**這是原版的「AI 卡住了」脫困機制**：先換走法、再換目標、最後放棄這回合。
remake 照抄即可，不需要另外設計 pathfinding 的逾時。

## 兩種基準方向

- **沒撤退**（`+14h` ＝ 0）：`0CA2h+1(角色, 目前目標)` ＝ **朝目標的方向**。
- **撤退中**（`+14h` ≠ 0）：AI 模式重骰成 1 或 2（spec 837 的「直衝，先偏左／先偏右」），
  基準方向改由全域 `DS:7211h` 算，而且**陣營 `+197h` ＝ 0 的一方要再加 4**（轉 180°）。
  形狀上是「往地圖的出口方向逃」，兩邊陣營逃往相反側。

`基準 := DS:7211h − (((DS:7211h + 2) mod 4) div 2)` 這個式子把 `DS:7211h`
往下修到最近的偶數方向（餘數 0..3 除 2 得 0 或 1）。

## ⚠ 士氣閘門裡有一段到不了的碼

```
cmp [+0F7h], 80h ; jb  → 略過整段
cmp [+0F7h], 7Fh ; jbe → 跳到陣營檢查
```

第二個比較在 `+0F7h ≥ 80h` 已成立之後才執行，**`≤ 7Fh` 永遠不可能成立**。
編譯器照著原始碼裡兩段獨立的條件展開，結果第二條是死碼。實際行為只剩：

- 士氣最高位**沒設**（已崩，見 spec 831）→ 完全不檢查，照走。
- 士氣正常 → 擲 1d100，`DS:75D9h > DS:6FA2h + 1d100` 時**只有陣營 1 能動**。

## 狀態列印的是「格數」不是「半格」

`角色^[18Dh]^[06h] div 2` 才送去顯示——與 spec 838 的射程判定 `距離 div 2` 一致。
**玩家看到的移動力是內部值的一半。** PC-98 把整句翻成
`'移動／攻撃，残り移動力＝'`，尾綴的兩個半形空白兩邊都保留（用來蓋掉上一次的數字）。

## 回傳值不可靠

`停` 是區域變數，收尾只有 `mov sp, bp / pop bp / retf 4`，**沒有統一把它搬進 `al`**。
好幾條路徑離開時 `al` 是上一次呼叫留下的值。spec 838 的兩個呼叫點都把它**當程序用**
（不看回傳值），所以不影響行為——但 remake 不要試圖沿用這個「回傳值」。

## PC-98：全部是位址與字串差

`+18Dh`↔`+18Eh`、`+159h`↔`+15Ah`、`+197h`↔`+198h`、`DS:2B6h`↔`DS:06AAh`、
`DS:6FA2h`↔`DS:0A03Ch`、`DS:75D9h`↔`DS:0A86Bh`、`DS:7211h`↔`DS:0A2ABh`，
其餘是呼叫目標與那兩個字串。**沒有邏輯差異。**
