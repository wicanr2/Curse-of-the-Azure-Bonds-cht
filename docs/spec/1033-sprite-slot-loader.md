# 1033 — 圖組槽載入：`CHEAD`／`CBODY`／`COMSPR`／`ICON` 四條路，以及 PC-98 的預置指標表

- 證據等級：`exact`（DOS 側 353 條、PC-98 側 451 條，兩邊各自逐條讀完）
- 作法見 spec 783

## `dos overlay-33:001D4h` ↔ `pc98 overlay-33:0038Fh`（`retf 8`）

兩側原本都是待解讀。

```pascal
procedure 載入圖組(名稱: 字串;   { bp+0Ah，第一個宣告 ⇒ 最高位移 }
                   編號: byte;   { bp+08h }
                   槽:   byte);  { bp+06h }
```

`retf 8` ＝ 4（遠指標）＋ 2 ＋ 2，與三個參數對得上。

## ★★ 目的地：一張「一槽兩個遠指標」的表

兩次寫入的位址是 `槽 × 8 ＋ 基底` 與 `槽 × 8 ＋ 基底 ＋ 4`：

| | 基底 |
|---|---|
| DOS | `DS:65D6h`（`+4` ＝ `65DAh`） |
| PC-98 | `DS:0966Ch`（`+4` ＝ `09670h`）—— 組語寫成 `[di−6994h]` |

★ **一筆 8 bytes ＝ 兩個遠指標**。第二個遠指標一律用「編號 ＋ `80h`」載入
——同一個槽的兩份資料，第二份的編號高位元被設起來。

⚠ DOS 的 `DS:65D6h` 在靜態映像裡整片是 `0FFh`，**執行期才填**。

## 四條路

```pascal
名稱 := 參數;                                     { 上限 255 }
if Copy(名稱, 1, 5) in ['CHEAD', 'CBODY'] then begin
    尾 := UpCase(名稱[Length(名稱)]);
    if 尾 = 'T' then 編號 := 編號 ＋ 40h;         { ★ 尾字 T 讓編號 +40h }
    名稱 := Copy(名稱, 1, Length(名稱) − 1);      { 去掉最後一個字元 }
    載(名稱, 編號,        @表[槽].a);
    載(名稱, 編號 ＋ 80h, @表[槽].b);
end
else if 名稱 in ['COMSPR', 'ICON'] then begin
    載(名稱, 編號,        @表[槽].a);
    載(名稱, 編號 ＋ 80h, @表[槽].b);
    if 名稱 = 'ICON' then begin                   { ★ 只有 ICON 多這一步 }
        換色(DS:0B1Eh, DS:0B3Eh, 0, 0, 表[槽].a);
        換色(DS:0B1Eh, DS:0B3Eh, 0, 0, 表[槽].b);
    end;
end
else begin                                        { 其他名稱 }
    Str(byte(DS:5BEEh), 尾);                      { ★ 資料片編號 }
    載(名稱 ＋ 尾, 編號,        @表[槽].a);
    換色(DS:0B1Eh, DS:0B2Eh, 0, 0, 表[槽].a);
    載(名稱 ＋ 尾, 編號 ＋ 80h, @表[槽].b);
    換色(DS:0B1Eh, DS:0B2Eh, 0, 0, 表[槽].b);
end;
<far 06EA:024Ch>();
```

`載` ＝ `far 0297:011Bh`（DOS），`換色` ＝ `far 0297:1626h`。

★ **只有「其他名稱」那條路會把資料片編號接到名字後面**
——與 spec 892／1029 的檔名組法（`名字 ＋ 資料片編號 ＋ '.dax'`）是同一套，
也就是說 `CHEAD`／`CBODY`／`COMSPR`／`ICON` 這四個是**不分資料片的共用資源**。

⚠ `CHEAD`／`CBODY` 是**前五個字元**比對（後面還接東西），
`COMSPR`／`ICON` 是**整個字串**比對。

## ★★ 三張 16 色對照表

`0297:1626h` 的前兩個參數是兩張 16-byte 的表：

| 位址 | 靜態內容 |
|---|---|
| `DS:0B1Eh` | `00 01 02 … 0F`（恆等） |
| `DS:0B2Eh` | `00 01 02 … 0F`（恆等） |
| `DS:0B3Eh` | `00 01 … 0B` **`00`** `0E 0F` —— **顏色 `0Ch` 映成 `0`** |

> ★★ **`ICON` 走的是 `0B3Eh`，把顏色 12 換成 0；其他名稱走 `0B2Eh`（恆等，等於不換）。**
> ⚠ 這是靜態映像的內容；沒有驗證執行期會不會被改寫。

## ★★★ PC-98 多一段：21 個槽的指標直接從靜態表抄

PC-98 在四條路之前多一整段（DOS 完全沒有）：

```pascal
暫存 := NIL;
if 槽 <= 7 then begin
    表[槽].a := 指標表[槽].a;   表[槽].b := 指標表[槽].b;   { DS:1722h ＋ 槽×8 }
    要配置 := 0;
end
else if 槽 in [0Dh..19h] then begin
    表[槽].a := 指標表[槽].a;   表[槽].b := 指標表[槽].b;   { DS:16FAh ＋ 槽×8 }
    要配置 := 0;
end
else begin
    表[槽].a := NIL;  表[槽].b := NIL;
    <02A8:0F5Dh>(@表[槽].a, 1, 1, 6, 18h);
    <02A8:0F5Dh>(@表[槽].b, 1, 1, 6, 18h);
    要配置 := 1;
end;
```

★ `1722h − 16FAh = 28h = 5 × 8` ⇒ **兩段用的是同一張表**：
槽 0..7 取第 0..7 筆、槽 `0Dh`..`19h` 取第 8..20 筆，**共 21 筆**。
★ 範圍判斷 `cmp al, 0 / jb` 對 byte 永遠不成立，是**廢碼**；實際只判 `槽 <= 7`。
★ `0Dh..19h` 那一段之後由 `@Set@MemberOf`（`0A65:08E4h`，集合常數 `CS:036Fh`
＝ `{13..25}`）再判一次，兩處範圍一致。

`DS:1722h` 的 21 筆靜態內容（每筆兩組 4 bytes，**前 2 bytes 進高 word、後 2 bytes 進低 word**
——與一般 Intel 遠指標的擺法相反）：

```
#0  f0 ab 00 00  15 ac 07 00
#1  3a ac 0e 00  60 ac 05 00
…
#20 72 b7 08 00  97 b7 0f 00
```

★ 把兩個 word 合成 `高×16 ＋ 低`，**42 個值以固定 `0257h`（599）等差遞增**，
起點 `0ABF00h`。⚠ 沒有宣稱這些值指向什麼，也沒有宣稱執行期會不會被覆寫。

★ PC-98 的載入路徑也整個換掉：改用 `02A8:025Bh` → `02A8:0601h` → `02A8:10D5h`
三步搭一個暫存緩衝（`var_106`），而且把 `要配置` 旗標傳給 `02A8:0601h`
——**已經從靜態表拿到指標的槽，走的是不一樣的載入分支**。

## 中文化

四個名稱 `'CHEAD'`(5)／`'CBODY'`(5)／`'COMSPR'`(6)／`'ICON'`(4) 在兩平台**逐 byte 相同**，
⚠ 它們同時是**資源檔名前綴**與**程式裡的比較字串**，翻了會同時弄壞載入與分支判斷
——與 spec 1029 的 `'PIC'`／`'FINAL'`／`'SPRIT'` 同一類。**一律不可翻。**

本支沒有給玩家看的字串。

## 明確不宣稱

- 沒有宣稱 `0297:011Bh`（載入）與 `0297:1626h`（換色）的完整介面，
  只知道參數個數與各自的實參。
- 沒有宣稱「編號」與「編號 ＋ `80h`」兩份資料的差別是什麼
  （形狀上是同一個槽的兩份）。
- 沒有宣稱 `CHEAD`／`CBODY` 名稱尾字為 `'T'` 時 `+40h` 代表什麼。
- 沒有宣稱 `far 06EA:024Ch`（收尾）做什麼。
- 沒有宣稱 `DS:1722h` 那 42 個值指向哪裡、或執行期是否被覆寫。
- 沒有宣稱 `02A8:0F5Dh(…, 1, 1, 6, 18h)` 配置的是多大、什麼形狀的緩衝。
