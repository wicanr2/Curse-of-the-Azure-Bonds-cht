# 第六百九十三輪：`0542:0352h` 的參數順序，與拼接出來的英文文法

狀態：`READY`。等級：`exact`（參數順序為 `strong inference`，見下）。
日期：2026-08-14
位置：DOS `overlay-24` 的 `177Ah`、`18F3h`、`2543h`。

## `0542:0352h(x, y, colour, mode, str)`

五個呼叫點的參數對照：

| 位置 | 參數 | 佐證 |
|---|---|---|
| `0795h` | `(x, y, 0Fh, 0, 名字)` | `x` ∈ {1, 11h}，`y` 每列遞增 |
| `09C1h` | `(arg_4, arg_2, c, 0, Str(HP))` | HP 欄 |
| `177Ah` | `(0, 18h, 0Ah, 0, 訊息)` | 同一支函式前後用 `01A0:04CDh(0, 18h, 27h, 18h)` 清同一列 |
| `18F3h` | `(arg_4, arg_2, c, 0, 名字)` | 由 `0795h` 傳入 `x`、`y` |
| `2BAAh` | `(11h, 0Fh, 0Ah, 0, 狀態列)` | — |

`177Ah` 那組最有決定性：清除矩形是 `(0, 18h, 27h, 18h)`，也就是
`(x1=0, y1=24, x2=39, y2=24)` 清整列第 24 列；緊接著的繪製用 `(0, 18h, ...)`。
**清的座標與畫的座標是同一組前兩個參數**，所以順序是先 `x` 後 `y`。

第三個參數在 `18F3h`／`09C1h` 都是依狀態選出來的顏色。第四個一律是 0，用途不明。

## `18F3h`：名字的顏色，以及 `'s`

```text
if 角色^[196h] = 0      then c := 0Ch
elif 角色^[197h] = 1     then c := 0Eh
else                          c := 0Bh
<0542:0352h>(arg_4, arg_2, c, 0, 角色^)          ← 名字就在紀錄的 +0
if arg_0 <> 0 then
    <0542:0352h>(arg_4 + 角色^[0], arg_2, c, 0, CS:18F0h)
```

名字是紀錄 `+0` 起的 Pascal 字串，`角色^[0]` 是它的長度位元組——所以第二次繪製
的欄位是**名字結尾的下一格**。`CS:18F0h` 的內容是 `'s`。

> 中文化：這是把英文所有格用「畫在名字後面」的方式硬接上去。中文沒有對應的
> 後綴，`arg_0 <> 0` 這條路徑要整段改掉，不是換字串就好。
>
> ★ **`x + 長度位元組` 這個加法對 Big5 是成立的**（spec 726）：全形字元佔 2 個
> 位元組**也**佔 2 個顯示欄，兩者相等。這裡唯一的中文化問題是 `'s` 後綴，
> 不是欄寬。

`0795h` 對選中的角色不走這支，直接用顏色 `0Fh` 畫。所以名字有四種顏色：
`0Fh`（選中）、`0Ch`（`+196h = 0`）、`0Eh`（`+197h = 1`）、`0Bh`（其他）。

## `2543h`：`is fully healed` / `is partially healed`

```text
if 角色^[1A4h] = 角色^[78h] then s := CS:251Fh   ← 'is fully healed'
else                             s := CS:252Fh   ← 'is partially healed'
<17D6h>(角色, s, 0Ah, 1)
if DS:4FBAh <> 5 then <0795h>(DS:6506h)          ← 重畫名單
retf 4
```

判斷是「目前 HP **等於**上限」而不是「大於等於」，用 `jnz`。

> 中文化：訊息是「主詞由呼叫端補、述部是常數字串」的組合。中文語序相同
> （`<名字> 已完全治癒`），但兩個字串都以空白起頭的英文慣例要改成不加空白，
> 而且 `is partially healed` 的長度 19 已接近 `28h` ＝ 40 的緩衝上限，中文若用
> 全形會佔更多位元組。

## `177Ah`：在第 24 列顯示一行訊息然後清掉

```text
複製 arg_0 → 區域緩衝（上限 28h）
<01A0:04CDh>(0, 18h, 27h, 18h)                   ← 清第 24 列，欄 0..39
<0542:0352h>(0, 18h, 0Ah, 0, 緩衝)
<0542:0B33h>()                                    ← 中間阻塞，推測是等按鍵
<01A0:04CDh>(0, 18h, 27h, 18h)                   ← 再清一次
retf 4
```

訊息列寬度上限 **40 字元**，位置固定在第 24 列。

## 明確不宣稱

- `0542:0352h` 第四個參數（一律 0）的用途，以及 `0542:0B33h` 到底在等什麼。
- `17D6h` 如何把角色名字與述部字串接起來。
- `DS:4FBAh = 5` 為何不重畫名單。
- 四種名字顏色各對應什麼狀態。
