# 1094 — PC-98 建角流程：多一道名字驗證，年齡表只留一條算式

- 證據等級：`exact`（PC-98 側 2,788 條；與 DOS 側（spec 1093）做**助憶碼序列比對**，
  相似度 0.7554、只有六個 ≥ 12 條的差異塊，六塊全部逐條讀完，
  其餘 2,000 餘條與 DOS 一一對應）
- 作法見 spec 783；DOS 對側見 spec 1093

## `pc98 overlay-17:00AFBh`（`retf`）

原本待解讀。這是 spec 1093 的 PC-98 對側，**台帳最後一支待解讀的函式**。

## 六個差異塊

| # | DOS（spec 1093） | PC-98 | 差在哪 |
|---|---|---|---|
| 1 | `0936h`..`0C2Eh`（328） | `0CC3h`..`0FE6h`（344） | **選單實作換掉**：DOS 用 `overlay-26 entry#1／#5／#8`，PC-98 用 `entry#3／#7／#10`（spec 1085 的同一組捲動清單） |
| 2 | `0D21h`..`0D9Ah`（58） | `10DAh`..`1168h`（66） | 同上，第二個選單 |
| 3 | `11B5h`..`122Eh`（58） | `1584h`..`1612h`（66） | 同上，第四個選單 |
| 4 | `13BCh`..`15D5h`（**207**） | `17B8h`..`17E1h`（**14**） | ★★★ **年齡表的多職分支** |
| 5 | `242Bh`..`2438h`（6） | `2636h`..`267Dh`（33） | ★★★ **名字驗證** |
| 6 | `2447h`..`250Dh`（79） | `2690h`..`2783h`（100） | 收尾（節點大小 `1A7h` vs `1A6h`） |

## ★★★ 一、DOS 的多職年齡表在 PC-98 不見了

DOS 側 `13BCh`..`15D5h` 是一長串 `cmp al, 0Ch／0Dh／0Eh…`，
**每一種多職組合各有一個年齡表基底**（`DS:404Ch`、`DS:4060h`、`DS:4054h`…），
各自 `基礎 word ＋ 兩個骰子參數相乘`。

PC-98 對應的位置只有 **14 條**——沒有這一串。

> ★★★ **DOS 為每一種多職組合準備了獨立的起始年齡表，PC-98 沒有。**
> ⚠ 本規格不宣稱 PC-98 是改用單一算式、還是那些組合在 PC-98 根本選不到
> （職業清單由 `DS:3FF8h` 那張「種族 → 可選職業」的表決定，兩平台的表內容未取出）。
> ⇒ remake 若要兩平台一致，這一段要以 DOS 為準。

## ★★★ 二、PC-98 多一道名字驗證

```pascal
名字 := 輸入（上限 0Fh ＝ 15）;
合法 := <far 0723:05BDh>(名字) <> 0;
if not 合法 then 印('このキャラクタ名は受け付けられません。');   { 38 bytes }
if (名字 <> '') and 合法 then …繼續存檔…
else 回到「請輸入名字」;
```

> ★★★ **DOS 完全沒有這一段**（差異塊 5 在 DOS 只有 6 條）。
> PC-98 會把輸入的名字丟給 `0723:05BDh` 驗一次，不合法就重問。
> ⚠ 本規格不宣稱 `0723:05BDh` 的判定規則
> （它也出現在 spec 1072 的角色檔名處理裡）。
> ⇒ **中文化要特別留意**：這道驗證很可能會擋掉 Big5 名字。

★ **名字上限是 `0Fh` ＝ 15 bytes**（全形 7 個字）。

## ★★★ 三、兩平台共同的收尾：把「目前值」抄成「基準值」

```pascal
for i := 0 to 5 do 角色^[10h ＋ i × 2] := 角色^[11h ＋ i × 2];
角色^[1Dh] := 角色^[1Ch];
```

> ★★★ **這是 spec 1086 那組「偶數位移 ＝ 基準值、奇數位移 ＝ 目前值」的產生端**
> ——建角結束時，六個屬性與力量百分比的**目前值原封不動抄成基準值**。
> ⇒ 之後裝備／法術只改奇數格，脫下來就能回到偶數格。**兩平台一字不差。**

## 四、其餘與 DOS 相同

種族／性別／職業／陣營四個選單的欄位（`+74h`／`+119h`／`+75h`／`+11Bh`）、
十七種職業組合與起始經驗值、種族屬性上下限表的索引算式、
`力量 = 18` 才擲 `Random(100) ＋ 1` 的百分比、種族天賦效果、
`+109h ＋ j` 的職業等級——**全部與 spec 1093 一一對應**，不重複描述。

★ 配置／釋放的大小是 **`1A7h` ＝ 423**（DOS 是 `1A6h` ＝ 422，spec 1038）。
★ 存檔改叫 PC-98 自己的那一支（DOS 是 `overlay-16 entry#6`）。

| PC-98 | 位址 | bytes | 建議 |
|---|---|---|---|
| 「種族を選んでください」 | `CS:9F5h` | 20 | 「請選擇種族」 |
| 「性別を選んでください」 | `CS:A19h` | 20 | 「請選擇性別」 |
| 「クラスを選んでください」 | `CS:A2Eh` | 22 | 「請選擇職業」 |
| 「アラインメントを選んでください」 | `CS:A4Ch` | 30 | 「請選擇陣營」 |
| 「能力値を決めなおしますか？」 | `CS:A8Dh` | 26 | 「要重新決定能力值嗎？」 |
| 「キャラクターの名前は？」 | `CS:AA8h` | 22 | 「角色名稱是？」 |
| 「このキャラクタ名は受け付けられません。」 | `CS:ABFh` | 38 | 「這個角色名稱不被接受。」 |
| 「をセーブしますか？」 | `CS:AE6h` | 18 | 「 要儲存嗎？」（接在名字後） |
| 「 決定 」／「決定」 | `CS:A0Dh`／`A14h` | 6／4 | ⚠ **兩個長度不同的版本並存**，各自有使用處 |
| `'  '` | `CS:A0Ah` | 2 | ⚠ 選項分隔 |
| **`'Select'`** | `CS:A45h` | 6 | ⚠⚠ **英文殘留**——PC-98 版沒有翻掉這一個 |

> ⚠⚠ **`'Select'` 是 PC-98 版沒有日文化的殘留**，而它旁邊的「決定」有兩個版本
> （6 bytes 與 4 bytes）。中文化時三者要一起處理，並確認各自的使用點。
> ⚠ 名字上限 15 bytes，中文全形**最多 7 個字**，而且要先確認
> `0723:05BDh` 的驗證會不會擋掉中文。

## 明確不宣稱

- 沒有宣稱 `0723:05BDh`（名字驗證）的判定規則。
- 沒有宣稱 PC-98 少掉的多職年齡表是改用單一算式還是那些組合選不到。
- 沒有宣稱 `'Select'`／「 決定 」／「決定」三者各自用在哪個選單。
- 其餘未宣稱項與 spec 1093 相同（各張資料段表格的內容、效果碼、
  年齡分期門檻的語意、擲屬性的骰法）。
