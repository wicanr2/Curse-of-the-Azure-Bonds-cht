# 1004 — AI 自動換裝：評分挑最佳、詛咒物品換不掉、`+185h` 是佔手數

- 證據等級：`exact`（DOS 側 451 條逐條讀完；PC-98 對側 451 條**助憶碼序列
  完全相同**，相似度 1.000）
- 作法見 spec 783

## `dos overlay-09:01681h` ↔ `pc98 overlay-09:0169Eh`（`retf 4`，參數是角色遠指標）

兩側原本都是待解讀。整支沒有任何字串。

### 一、先把已裝備物品的「佔手數」扣回來

```pascal
for 每個裝備槽 s（+151h、+155h、… 共 13 格）do
    if 角色^[s] <> NIL then
        角色^[185h] -= byte[5CF7h ＋ 角色^[s]^[2Eh] × 10h];
```

★★ **這證實 `+185h` 是「目前佔用的手數」**：spec 1000 的重算是把每件已裝備
物品的 `[5CF7h ＋ 類別×10h]` **加**進 `+185h`，本支開頭把同一批值**減**回去。
後面又用 `角色^[185h] > 2` 與 `< 2` 當分支條件——**上限就是兩隻手**。

所以物品類別表 `DS:5CF6h`（每筆 16 bytes）的欄位再補一格：

| 表內位移 | 內容 | 出處 |
|---|---|---|
| `+0` | 裝備槽編號（`9` ＝ 雙持特例） | spec 1000／683 |
| `+1` | **佔幾隻手** | **本規格** |
| `+2`／`+3` | 對大型目標的骰數／面數 | spec 1011 |
| `+0Dh` | **可用性遮罩**（與角色 `+12Bh` 做 `and`） | **本規格** |
| `+0Eh` | **旗標位元**（本支用到 bit 3 與 bit 4） | **本規格** |

（`5D03h − 5CF6h = 0Dh`、`5D04h − 5CF6h = 0Eh`。）

### 二、掃物品鏈，評分挑出兩件候選

```pascal
for 每件物品 q（走 +14Dh 的鏈）do begin
    if byte[5D03h ＋ q^[2Eh]×10h] and 角色^[12Bh] = 0 then continue;   { 用不了 }
    分 := <本模組 1542h>(q, 角色);
    f := byte[5D04h ＋ q^[2Eh]×10h];

    if ((f and 08h <> 0) or (f and 10h <> 0)) and (分 > 分A) then
        begin 最佳A := q;  分A := 分 end;

    if (f and 08h = 0) and (分 > 分B) then
        begin 最佳B := q;  分B := 分 end;

    if byte[5CF6h ＋ q^[2Eh]×10h] = 1 then …（另一組統計）…;
end;
```

★ **`角色^[12Bh]` 是「這個角色能用哪些類別」的位元遮罩**——
與類別表 `+0Dh` 做 `and`，為 0 就整件跳過。
AD&D 的「法師不能用劍」這類限制就在這一格。

`本模組 1542h(物品, 角色)` 回傳一個 byte 的**評分**，本規格不宣稱它怎麼算。

### 三、兩件候選二選一

```pascal
if (分A > 分B) and (var_1F <> 0)
   and ((var_1E <> 0) or (<overlay-24 entry#32>(1, 角色) = 0)) then
    選 := 最佳A
else
    選 := 最佳B;
```

`overlay-24 entry#32` 收三個 word、回一個 byte，本規格不宣稱它判斷什麼。

### ★ 四、詛咒的裝備換不掉

```pascal
可換 := 1;
if 角色^[151h] <> NIL then
    if (角色^[151h] = 選) or (角色^[151h]^[36h] <> 0) then 可換 := 0;
```

`+36h` 是物品節點的**詛咒旗標**——開發者自己的欄位名就叫 `cursed`（spec 1011）。
**已經裝著詛咒物品的槽位，AI 不會去動它**——
這是 AD&D「cursed item 脫不下來」的實作。同一個檢查在第二槽（`+155h`）
也出現一次。

### 五、換裝與重算

換下用 `overlay-19 entry#7`（收一個遠指標，**裝備／卸下的切換**），
每次動完就叫 `overlay-24 entry#7`（＝ spec 1000 的派生數值重算）。

手數的兩道分支：

| 條件 | 動作 |
|---|---|
| `角色^[185h] > 2` | 把第二槽或新選的那件卸掉（詛咒的除外），標記「有換過」 |
| `角色^[185h] < 2` | 若第二槽有東西就卸掉，重算，再處理另一件 |

最後若「有換過」，叫 `overlay-24 entry#5`（收角色遠指標）收尾。

## 這一支在整條鏈上的位置

| 相關規格 | 關係 |
|---|---|
| spec 1000（派生數值重算） | 本支每動一次裝備就叫它一次 |
| spec 835／836（AI 用道具／施法） | 同一個 `overlay-09` 模組的 AI 決策家族 |
| spec 832（物品節點 `+2Eh` 類別、`+34h` 已裝備、`+36h` 詛咒） | 三個欄位都用到 |
| spec 683（`DS:5CF6h` 類別表） | 同一張表，本支補了三個欄位 |

## 中文化

本支沒有字串。但**類別表 `DS:5CF6h` 的 `+0Dh` 可用性遮罩與角色 `+12Bh`**
決定了「這個職業能不能裝這件」——
中文化若要改物品分類或新增裝備，這兩格是必須同步的地方。

## 明確不宣稱

- 沒有宣稱 `本模組 1542h` 的評分公式。
- 沒有宣稱 `DS:5D04h` 那個旗標位元組的 bit 3／bit 4 各代表什麼
  （形狀上是「主手可用」與「副手可用」）。
- 沒有宣稱 `overlay-24 entry#32`／`entry#5` 與 `overlay-19 entry#7` 的內部行為。
- 沒有宣稱 `var_1E`／`var_1F` 兩個旗標由哪一段設定。
- 沒有宣稱角色 `+12Bh` 的位元配置。
