# 927 — 八方向判定：22.5° 與 67.5° 的正切值寫成 8.8 定點數

- 證據等級：`exact`（兩平台都逐條讀完；相似度 0.255，因為 PC-98 把判定抽了出去）
- 作法見 spec 783

## `overlay-13:029A2h`（DOS 215 條）↔ `overlay-13:029F4h`（PC-98 42 條）

`retf 8` ＝ 兩組座標（`(arg_0, arg_2)` 與 `(arg_4, arg_6)`），回傳 `al` ＝ **方向 0..7**。

```pascal
迄x := <loc_192Ah+1>(arg_4, arg_6);   迄y := <loc_192Dh+3>(arg_4, arg_6);
起x := <loc_192Ah+1>(arg_0, arg_2);   起y := <loc_192Dh+3>(arg_0, arg_2);
dx := abs(起x − 迄x);
dy := abs(起y − 迄y);

方向 := 0;   命中 := 0;
while 命中 = 0 do begin
    case 方向 of
      0: 命中 := (起y <= 迄y) and (dx × 26Ah div 100h <= dy);
      2: 命中 := (起x >= 迄x) and (dx ×  6Ah div 100h >= dy);
      4: 命中 := (起y >= 迄y) and (dx × 26Ah div 100h <= dy);
      6: 命中 := (起x <= 迄x) and (dx ×  6Ah div 100h >= dy);
      1: 命中 := (起y <= 迄y) and (起x >= 迄x)
                 and (dx × 26Ah div 100h >= dy) and (dx × 6Ah div 100h <= dy);
      3: 命中 := (起y >= 迄y) and (起x >= 迄x) and 同上兩式;
      5: 命中 := (起y >= 迄y) and (起x <= 迄x) and 同上兩式;
      7: 命中 := (起y <= 迄y) and (起x <= 迄x) and 同上兩式;
    end;
    if 命中 = 0 then inc(方向);
end;
結果 := 方向;
```

## 兩個常數就是 22.5° 與 67.5° 的正切值

| 常數 | ÷ `100h` | 對應角度 |
|---|---|---|
| `26Ah` ＝ 618 | **2.4141** | `tan 67.5°` ＝ 2.4142 |
| `6Ah` ＝ 106 | **0.4141** | `tan 22.5°` ＝ 0.4142 |

也就是把 `100h` 當成 1.0 的 **8.8 定點數**。八個方向各佔 45°，
邊界正好落在 22.5° 與 67.5°：

| 方向 | 條件（斜率） | 扇區 |
|---|---|---|
| 0 / 4 | `dy` 佔優（斜率 > tan 67.5°） | 正上／正下 |
| 2 / 6 | `dx` 佔優（斜率 < tan 22.5°） | 正右／正左 |
| 1 / 3 / 5 / 7 | 介於兩者之間 | 四個斜角 |

比較全用**有號 `imul`／`idiv`**，所以 `dx` 很大時乘 618 會溢位到負值——
`dx` 超過 `7FFFh div 26Ah` ＝ 53 就會翻號。地圖尺寸遠小於 53，實務上碰不到。

## 這關掉了 spec 914 的待答項

spec 914 的「沒有宣稱 `本模組 29A2h` 回的 `r` 是不是方向」可以關閉：
**`r` 就是 0..7 的八方向編號**。
spec 914 用 `odd(r)`、`r div 4`、`r mod 4` 拆圖磚，正是把八方向拆成
「正向四個」與「斜角四個」兩組。

## `loc_192Ah+1` ＝ 取欄、`loc_192Dh+3` ＝ 取列

方向 0（正上）要求 `dy` 佔優、而且 `起y <= 迄y`——
所以 `loc_192Dh+3` 那一軸是**列（y）**，另一軸是**欄（x）**。
spec 914／918 用到同一對取值函式。

## 迴圈一定會停

八個扇區覆蓋整個平面，所以最遲在 `方向 = 7` 命中。
起訖同點時 `dx = dy = 0`，方向 0 的兩個條件都成立 → 回 0。
（沒有上界檢查，`方向` 是 byte，理論上會繞回 0 重來；實際到不了。）

## ⚠ PC-98 把判定抽出去，而且 fallback 是死碼

PC-98 版只有 42 條：取完四個座標之後呼叫 `<0117h:005Ch>(起y, 起x, 迄y, 迄x)`（見下），
然後

```
mov al, [bp+var_2]
xor ah, ah              ← 零延伸，ax 一定落在 0..0FFh
cmp ax, 0FFFFh          ← 永遠不相等
jnz short loc_2A63      ← 一定跳走
    方向 := 角色^[18Eh]^[9]      ← ★ 到不了
loc_2A63:
```

原始碼寫的顯然是 `if 方向 = −1 then 方向 := 角色^[18Eh]^[9]`，
但 `方向` 宣告成 byte，零延伸之後**永遠不會等於 −1**。
**這條 fallback 從來不會執行**；那一支真的回 `0FFh` 時，
PC-98 會把 `0FFh` 原封不動傳回給呼叫端，而 DOS 版根本不可能回出範圍值。

## ⚠ PC-98 的委派目標是跨模組呼叫，IDA 的符號名是撞號

`029F4h` 那一條 IDA 顯示成 `call sub_11CC`，實際位元組是

```
9A 5C 00 17 01   →   call far ptr 0117h:005Ch
```

**是 far call，不是 near call。** `0117h` 在本 overlay 的 far call 目標段裡出現
8 次，與 `014Ah`（114 次）、`0189h`（93 次）、`0A65h`（RTL，84 次）並列，
所以它是一個**正常的外部模組**。

IDA 把它命名成 `sub_11CC` 是因為 `0117h × 16 ＋ 5Ch ＝ 11CCh`，
剛好撞上本 overlay 自己的偏移 `11CCh`——而 `011CCh` 是
`CHECKTARGET`（`011AFh`，63 條，spec 766）body 裡的一條 `jnz short loc_11D9`。
函式索引裡那筆「`sub_11CC`，140 bytes，邊界碎片」是同一個撞號造出來的幻影。

> **這正是 `~/.claude/knowledge-base/retro/borland-tpov-overlay-re.md` 記的坑：
> 「stub offset 撞號要比 segment」。** 引用 overlay 內的近位址前，
> 先確認那條指令是 `E8`（near）還是 `9A`（far）。

## PC-98 沒有這兩個正切常數

| 位元組樣式 | DOS | PC-98 |
|---|---|---|
| `B9 6A 02`（`mov cx, 26Ah`） | overlay-13 **6 處** | **0 處** |
| `B9 6A 00`（`mov cx, 6Ah`） | overlay-13 **6 處** | **0 處** |

掃過兩平台的**全部 36 個 overlay 與兩支常駐執行檔**，
`26Ah`／`6Ah` 只出現在 DOS 的 `overlay-13`。

所以 PC-98 不是把同一段搬到別處，**是換了一套算法**
（在 `0117h` 那個模組裡）。本規格不宣稱它的內容。

## 明確不宣稱

- 沒有宣稱 PC-98 `0117h:005Ch` 那一支的算法（只確認它不是本 overlay 的 `11CCh`，
  而且沒有用 `26Ah`／`6Ah` 這兩個常數）。
- 沒有宣稱 `角色^[18Eh]^[9]`（DOS 的 `+18Dh^[9]`）是什麼
  ——那條路徑到不了，所以也沒有行為可以觀察。
- 沒有宣稱兩組座標參數的實際型別（DOS 推兩個 word，PC-98 推一個遠指標，
  byte 數相同）。
