# 907 — 裝備物品的四道檢查，並補齊 `DS:5CF6h` 物品類別表

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側差異逐條列出）
- 作法見 spec 783

## `overlay-19:01EE9h`（DOS 203 條）↔ `overlay-19:01EAEh`（PC-98 205 條）

`retf 4` ＝ 一個物品遠指標。對象角色是 `遠指標(DS:6506h)`。

```pascal
可顯示 := (物品^[3Eh] > 7Fh);                      { 無號 }
角色   := 遠指標(DS:6506h);

if 物品^[34h] <> 0 then begin                      { 已經裝備著 }
    if 物品^[36h] <> 0 then
        訊息(卸不下來)                              { ★ 詛咒 }
    else begin
        物品^[34h] := 0;                           { 卸下 }
        if 可顯示 then <本模組 1B00h>(物品, 0);
    end;
    離開;
end;

錯 := 0;
類 := 物品^[2Eh];

{ ① 手不夠 }
if 有號(byte[5CF7h ＋ 類 * 10h] ＋ 角色^[185h]) > 2 then 錯 := 3;

{ ② 同一個部位已經有東西 }
槽 := byte[5CF6h ＋ 類 * 10h];
if (槽 >= 0) and (槽 <= 8) then begin
    if 遠指標(角色^[151h ＋ 槽 * 4]) <> NIL then 錯 := 2;
end else if 槽 = 9 then
    if 遠指標(角色^[179h]) <> NIL then 錯 := 2;

if (類 = 49h) and (遠指標(角色^[17Dh]) <> NIL) then begin 錯 := 2;  槽 := 0Bh end;
if (類 = 1Ch) and (遠指標(角色^[181h]) <> NIL) then begin 錯 := 2;  槽 := 0Ch end;

{ ③ 職業不能用 }
if (byte[5D03h ＋ 類 * 10h] and 角色^[12Bh]) = 0 then 錯 := 1;

case 錯 of
  0: begin
        物品^[34h] := 1;
        if 可顯示 then <本模組 1B00h>(物品, 1);
     end;
  1: 訊息(職業不能用);
  2: 訊息(已經裝了 ＋ 遠指標(角色^[151h ＋ 槽 * 4])^);
  3: if not ((DS:4FBAh = 5) and (角色^[198h] <> 0)) then 訊息(手不夠);
end;
```

## `DS:5CF6h` 物品類別表補三欄

spec 691／700 已經定出**表的基底是 `DS:5CF6h`、每筆 16 bytes、索引是
物品的 `+2Eh` 類別碼**，並讀了 `+0Ch`（`5D02h`）與 `+0Eh`（`5D04h`）。
本支再補三欄：

| 格內位移 | 位址寫法 | 內容 | 出處 |
|---|---|---|---|
| **`+0`** | `5CF6h` | **裝備槽編號**（0..8 走 `+151h` 陣列、9 走 `+179h`） | 本支 |
| **`+1`** | `5CF7h` | **佔用的手數** | 本支 |
| `+0Ch` | `5D02h` | `> 1` 才算近戰武器；spec 838 的**武器長度 ＝ `+0Ch` − 1** | spec 691／838 |
| **`+0Dh`** | `5D03h` | **職業允許遮罩**（與角色 `+12Bh` 相 `and`） | 本支 |
| `+0Eh` | `5D04h` | bit 2 ＋ bit 4 要同時成立 | spec 691 |

⚠ 靜態 dump 裡整張表都是 `0FFh`，**是執行期才載入的**（spec 683 也讀過同一張表）。

## 角色的裝備欄

| 位址 | 內容 |
|---|---|
| `+151h ＋ 槽 × 4` | 槽 0..8 的遠指標陣列（9 格，`+151h`..`+173h`） |
| `+179h` | 槽 9 |
| `+17Dh` | 類別 `49h` 專用 |
| `+181h` | 類別 `1Ch` 專用 |
| `+185h` | **目前佔用的手數** |
| `+12Bh` | **職業遮罩**（與表的 `+0Dh` 相 `and`） |

`佔用手數 ＋ 已用手數 > 2` 才算錯——**雙手上限就是 2**。

`49h` 與 `1Ch` 是**唯二被寫死在程式裡的類別碼**，各有自己的裝備欄
（`+17Dh`／`+181h`）。spec 901 那個死碼分支也是拿這兩個碼比對——
**兩支獨立出現同一對常數**，所以 901 那裡本來想判的多半就是這兩類。

## `物品^[36h]` ＝ 卸不下來（詛咒）

已裝備的物品要卸下時，`+36h` ≠ 0 就印一句話擋掉。
PC-98 是 `+5Eh`（spec 832 的 `+28h` 位移）。這是 AD&D 詛咒物品的行為。

`物品^[34h]`（PC-98 `+5Ch`）是**已裝備旗標**，`+3Eh > 7Fh`（PC-98 `+66h`）
控制要不要叫 `本模組 1B00h` 更新畫面。

## `錯 = 3` 有一個例外

手不夠時，若**正在戰鬥（`DS:4FBAh = 5`）且角色 `+198h` ≠ 0**，
就**不印訊息**（spec 906 讀到 `+198h` ≠ 0 是「不能自主選擇」的狀態）。
其餘情形都會印。

## PC-98：只差有號／無號碼型與一次串接

槽的範圍檢查 DOS 用 `jl`／`jg`（有號）、PC-98 用 `jb`／`ja`（無號），
值域 0..255 結果相同。另外多一次字串串接。

## 明確不宣稱

- 沒有宣稱四句訊息的內容（見台帳）。
- 沒有宣稱 `本模組 1B00h(物品, 0/1)` 做什麼。
- 沒有宣稱類別碼 `49h`／`1Ch` 是哪兩類物品。
- 沒有宣稱槽 `0Bh`／`0Ch` 那兩個值寫回 `槽` 之後給誰用
  （`錯 = 2` 的訊息只讀 `+151h ＋ 槽 × 4`，**`0Bh`／`0Ch` 會超出那 9 格**）。
