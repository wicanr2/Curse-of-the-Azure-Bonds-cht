# 923 — 法術清單建構器：七種模式，外加依等級插標題

- 證據等級：`exact`（兩平台都逐條讀完；相似度 0.995）
- 作法見 spec 783

## `overlay-22:009FCh`（DOS 326 條）↔ `overlay-22:00A69h`（PC-98 326 條）

`retf 2` ＝ 一個 byte（模式）。回傳 `al`（清單是不是非空）。整支無字串常數。

```pascal
要分組 := 1;   結果 := 0;
清單 := NIL;                                   { DS:4B44h（DOS）／DS:7C22h（PC-98） }
for i := 0 to 53h do byte[4B9Ch ＋ i] := 0;    { 候選編號陣列清空，84 格 }

case 模式 of
  0: for i := 0 to 53h do                                  { 還沒用掉的記憶法術 }
       if 角色^[1Eh ＋ i] > 0 then
         if <sub_20h>(角色^[1Eh ＋ i] and 7Fh, 角色) then
           if 角色^[1Eh ＋ i] < 80h then <sub_5B4h>(角色^[1Eh ＋ i]);

  5: for i := 0 to 53h do                                  { 已經用掉的 }
       if 角色^[1Eh ＋ i] > 7Fh then
         if <sub_20h>(角色^[1Eh ＋ i] and 7Fh, 角色) then
           <sub_5B4h>(角色^[1Eh ＋ i]);

  1: for i := 1 to 64h do                                  { 已學會的 }
       if 角色^[78h ＋ i] <> 0 then
         if <sub_20h>(i, 角色) then <sub_5B4h>(i);

  4: for i := 1 to 64h do begin                            { 還能學的 }
       職 := byte[37DAh ＋ i × 10h];   等 := byte[37DBh ＋ i × 10h];
       if 角色^[12Ch ＋ 職 × 5 ＋ 等] > 0 then
         if <sub_20h>(i, 角色) then
           if 角色^[78h ＋ i] = 0 then <sub_5B4h>(i);       { 已學過的排除 }
     end;

  2: <sub_8A1h>(0);   要分組 := 0;
  3: <sub_981h>(0);   要分組 := 0;
  6: <sub_981h>(1);   要分組 := 0;
end;

if 清單 = NIL then begin 結果 := 0;  離開 end;
if 要分組 = 0 then begin 結果 := 1;  離開 end;

{ 依法術等級插標題節點 }
i := 0;
等 := byte[37DBh ＋ byte[4B9Ch ＋ 0] × 10h];
GetMem(頭, 2Eh);   頭^[2Ah] := 清單;   清單 := 頭;
頭^[0] := 限長(字串[875h ＋ 等 × 29h], 28h);
頭^[29h] := 1;                                 { ★ 1 ＝ 這是標題不是選項 }
p := 頭;
repeat
    前等 := 等;
    if byte[4B9Ch ＋ i] <> 0 then
        等 := byte[37DBh ＋ byte[4B9Ch ＋ i] × 10h];
    if 前等 < 等 then begin                    { ★ DOS 有號 `jge`；PC-98 是 `jz` }
        GetMem(新, 2Eh);
        新^[2Ah] := p^[2Ah];   p^[2Ah] := 新;   p := 新;
        p^[0] := 限長(字串[875h ＋ 等 × 29h], 28h);
        p^[29h] := 1;
    end;
    inc(i);
    p := p^[2Ah];
until p = NIL;
結果 := 1;
```

## 七種模式

| 模式 | 來源 | 條件 |
|---|---|---|
| 0 | `+1Eh ＋ i`（84 格記憶欄） | `> 0` 且 **`< 80h`**（最高位沒立） |
| 5 | 同上 | **`> 7Fh`**（最高位立起來） |
| 1 | `+78h ＋ i`（100 格） | `<> 0` |
| 4 | 全部 100 個編號 | `+12Ch ＋ 職 × 5 ＋ 等 > 0` 且 **`+78h ＋ i = 0`** |
| 2 / 3 / 6 | `<sub_8A1h>(0)` ／ `<sub_981h>(0)` ／ `<sub_981h>(1)` | 不分組 |

**`+1Eh` 那 84 格的最高位就是「這個法術這回合用掉了沒」**——
模式 0 列還能用的、模式 5 列用掉的。這與 spec 788／836 的
「`+1Eh`..`+71h` 記憶欄」對上，並補足最高位的語意。

**`+78h ＋ i`（i ＝ 1..100）是「已經學會的法術」**：模式 1 列已學的，
模式 4 明確把 `+78h ＋ i <> 0` 的排除掉。

## `+12Ch ＋ 職 × 5 ＋ 等` 對上 `+12Dh..+13Bh`

`職 := byte[37DAh ＋ i × 10h]`、`等 := byte[37DBh ＋ i × 10h]`，
索引式是 `+12Ch ＋ 職 × 5 ＋ 等`。既有規格記的是
**`+12Dh..+13Bh` ＝ 可記憶法術數量 3×5**——
職 ＝ 0、等 ＝ 1 時剛好落在 `+12Dh`，3 × 5 ＝ 15 格到 `+13Bh` ✓。

所以法術屬性表（stride `10h`）的前兩格是：

| 位址 | 內容 |
|---|---|
| `37DAh ＋ n×10h` | **施法職業別**（0..2） |
| `37DBh ＋ n×10h` | **法術等級**（1..5） |

兩個索引式差 1 byte，所以**職業與等級是相鄰的兩欄**，每一筆的欄位至少從
`37DAh` 起算。`resident-data-tables.md` 原本只記了等級那一欄（基底寫 `DS:37DBh`），
已補上職業欄；`碼 shl 4 + 37E5h` 那一欄見 spec 921。

## `DS:0875h`：等級標題字串表，stride `29h`

`限長(字串[875h ＋ 等 × 29h], 28h)`——`29h` ＝ 41 ＝ `string[40]`，
與選單節點的文字欄位同寬。**索引就是法術等級**。

## ⚠ 兩平台的插入條件不同

| | 插新標題的條件 |
|---|---|
| DOS | `前等 < 等`（有號 `jge` 跳過） |
| PC-98 | **`前等 <> 等`**（`jz` 跳過） |

差別在**等級變小的時候**：DOS 不插標題，PC-98 會插。
只要清單是遞增排好的，兩者結果相同；**清單若不是遞增的，兩平台會長得不一樣**。

這是整支唯一的邏輯差異（另一個差異區塊是 `cmp ax, 0` ↔ `cmp al, 0`
帶來的一條 `xor ah, ah`，屬 spec 783 的編譯器碼型差異）。

## 節點與 spec 920／922 同型

`GetMem(…, 2Eh)`、`+0` 文字（限長 `28h`）、`+29h` 旗標、`+2Ah` next——
與丟棄／交易錢幣的選單節點是同一種。**`+29h` 在這裡定名：1 ＝ 標題列**
（錢幣選單全部寫 0，因為那裡每一列都可選）。

## 明確不宣稱

- 沒有宣稱 `<sub_20h>(編號, 角色)` 判什麼（形狀上是「這個角色能不能用這個法術」）。
- 沒有宣稱 `<sub_5B4h>(編號)` 怎麼接鏈、接在頭還是尾——
  **因此也沒有宣稱 `4B9Ch` 陣列的索引與走訪順序是否對齊**。
  分組那一段用 `i` 同時當陣列索引與節點計數，若 `sub_5B4h` 是往前接
  （與本支的標題插入一樣），兩者的順序會相反。
- 沒有宣稱 `<sub_8A1h>`／`<sub_981h>` 各建什麼清單。
- 沒有宣稱模式 2／3／6 對應哪三種畫面。
