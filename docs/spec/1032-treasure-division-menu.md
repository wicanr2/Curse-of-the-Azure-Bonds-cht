# 1032 — 戰利品分配畫面：Detect Magic 的三個一環版本，以及 PC-98 的 `T` 熱鍵漏關

- 證據等級：`exact`（DOS 側 310 條、PC-98 側 356 條，兩邊各自逐條讀完）
- 作法見 spec 783

## `dos overlay-05:0106Ch` ↔ `pc98 overlay-05:01072h`

兩側原本都是待解讀。這是**戰利品（寶物）分配畫面**，
和 spec 1030／1031 是同一族的選單，但選項是**組出來的**而不是二選一。

## ★★★ Detect 選項的條件：身上記著三個一環偵測法術的任一個

```pascal
偵測 := false;
for i := 0 to 53h do begin                        { 84 格記憶法術清單 }
    法術 := 目前角色^[1Eh ＋ i];
    if (法術 in [5, 0Bh, 4Dh]) and (目前角色^[196h] <> 0) then begin
        偵測 := true;  偵測法術 := 法術;
    end;
end;
```

查法術屬性表 `DS:37DAh`（spec 1016，筆距 16、`+0` 職業、`+1` 環數）：

| 編號 | `+0` 職業 | `+1` 環數 | ＝ |
|---|---|---|---|
| 5 | 0 ＝ 牧師 | 1 | **Detect Magic（Cleric 1）** |
| 11 | 2 ＝ 法師 | 1 | **Detect Magic（Magic-User 1）** |
| 77 | 1 ＝ 德魯伊 | 1 | **Detect Magic（Druid 1）** |

> ★★★ **AD&D 1e 的 Detect Magic 正好是牧師 1 環、德魯伊 1 環、法師 1 環三個版本，
> 一個不多一個不少。** 這同時獨立確認了 spec 1016 的兩件事：
> 法術屬性表基底是 `DS:37DAh`（不是 `37DBh`）、`+0` 的職業編碼是
> **0 牧師／1 德魯伊／2 法師**。
>
> ★ 掃的是 `+1Eh` 起的 84 格記憶法術清單——與 spec 1016／1021／1028 第四次對上。
> ★ 還要求 `+196h <> 0`（可行動）——與 spec 1008／1010 的門檻同一格。
> ⚠ 只掃**目前選中的角色**（`DS:6506h`），不是掃全隊。

## DOS：選項字串是接出來的

```pascal
選項行 := 'View Pool Exit';                       { 預設 }
尾巴   := ' Exit';
…上面那段偵測…
if 偵測 then 尾巴 := ' Detect Exit';
if 公用池有錢 then      選項行 := 'View Take Pool Share' ＋ 尾巴
else if 公用池有物品 then 選項行 := 'View Take Pool'      ＋ 尾巴;
鍵 := <overlay-26:003D4h>('', 選項行, 0Dh, 0Ah, 0Fh, 1, 1, @旗標);
```

★★ 這裡把 spec 1030／1031 的 RTL 慣例**完整攤開**——三個字串常式串成一條，
每一支都把「目的指標」留在堆疊上給下一支用：

| 常式 | 參數（推入順序） | 行為 |
|---|---|---|
| `0A54:0634h` | 目的、來源 | 指派；**只彈掉來源** |
| `0A54:06C1h` | （堆疊上的目的）、來源 | **串接**；只彈掉來源 |
| `0A54:064Eh` | 來源、目的、上限 | 指派含上限；全部彈掉 |

`偵測 → 尾巴 → 選項行` 那一串正好是 `0634h → 06C1h → 064Eh`，
最後 `064Eh` 只推了「目的 ＋ 上限」，來源就是前面留下來的指標。
★ 第一個參數（空字串）在這支是 `mov [bp+var_108], 0` 直接把長度 byte 設 0
——與 spec 1031 同一種寫法。

分支：`V` 角色檢視（spec 1028）、`T` 本模組 `sub_ED7`、`P` 併入公用池（spec 798）、
`S` 分錢（spec 858）、**`D` 施法主流程 `overlay-22 entry#5(偵測法術, 0, 0, @旗標)`**（spec 705）、
`E`／`#0` 離開、`G`／`O` 換角色（spec 794）。

## ★★★ PC-98 改成「一格一格填兩張表」，而且 `T` 的熱鍵漏關

PC-98 不傳選項字串，改成先 `overlay-26 entry#3`（十格初始化：文字清空、熱鍵設空白），
再逐格寫文字與熱鍵，最後叫一支只收 3 個 word 的選單：

| 槽 i | 文字位址 `DS:0A338h ＋ i × 7` | 熱鍵位址 `DS:0A334h ＋ i` | 內容 |
|---|---|---|---|
| 1 | `0A33Fh` | `0A335h` | 「 取る 」／`T` |
| 2 | `0A346h` | `0A336h` | 「ｷｬﾗｸﾀｰ」／`V` |
| 4 | `0A354h` | `0A338h` | 「金集ﾒﾙ」／`P` |
| 5 | `0A35Bh` | `0A339h` | 「金分ｹﾙ」／`S` |
| 6 | `0A362h` | `0A33Ah` | 「ﾃﾞｨﾃｸﾄ」／`D` |
| 10 | `0A37Eh` | `0A33Eh` | 「抜ける」／`E` |

> ★★★ **六格的文字位址與熱鍵位址逐一對上 `0A338h ＋ i × 7` 與 `0A334h ＋ i`**
> ——spec 755／1012／1013／1022／1023／1028／1030 的版面，這是第一次**同一支函式裡
> 六組索引全部同時成立**。
> ★ 每次複製的上限參數都是 **`6`** ⇒ 一格的內容容量就是 6 bytes ＝ 3 個全形字。

⚠ **原作瑕疵（PC-98 才有）**：

```asm
11A3  cmp  byte ptr [bp-1], 0    ; 公用池有錢？
11A7  jz   loc_11DB
          文字[1] := ' 取る ' ; 熱鍵[1] := 'T'
          文字[5] := '金分ｹﾙ' ; 熱鍵[5] := 'S'
11D9  jmp  loc_11F9
11DB  cmp  byte ptr [bp-2], 0    ; 公用池有物品？
11DF  jz   loc_11F4              ; ★ 跳到「設熱鍵」而不是跳過它
11E1      文字[1] := ' 取る '
11F4  mov  byte ptr ds:0A335h, 54h   ; 'T' —— 兩條路都會執行
```

> ⚠ **兩者皆無時，槽 1 的文字是空的（初始化清過），熱鍵卻仍然被設成 `T`。**
> `jz` 的落點少跳了一條。DOS 側對應的字串是 `'View Pool Exit'`，**沒有 Take**。
> ⚠ 我沒有實機驗證按下 `T` 會發生什麼；已知的只有 spec 990 的
> 「熱鍵為空白 ＝ 不可選」，而這裡熱鍵不是空白。

## ★ 第三種 Yes／No 常數塊：空槽用空字串

離開時同樣整塊 `Move`（機制見 spec 1030）：
`Move(DS:05E8h, DS:0A33Fh, 46h)` ＋ `Move(DS:062Eh, DS:0A335h, 0Ah)`。

| 出處 | 熱鍵 | 空槽 7 bytes 的填法 |
|---|---|---|
| 營地 `DS:057Ah`／`0570h`（spec 1030） | `Y`／`B` | `06` ＋ 半形空白 × 6 |
| 商店 `DS:0660h`／`0656h`（spec 1031） | `A`／`B` | `06` ＋ 全形空白 × 3 |
| 本支 `DS:05E8h`／`062Eh` | `A`／`B` | **`00`（空字串）** |

> ★ **三塊常數三種寫法**，但欄位寬度都是 7 bytes。
> ⚠ 因此那個 7 bytes 的欄位要讀成 **「1 個長度 byte ＋ 6 bytes 容量」**，
> 長度 byte 是**實際長度**（可以是 0），不是固定 `06`。

## 中文化

| 功能 | DOS | PC-98 | 熱鍵 | 建議中文 |
|---|---|---|---|---|
| 取走 | `Take` | 「 取る 」 | `T` | 取走 |
| 看角色 | `View` | 「ｷｬﾗｸﾀｰ」 | `V` | 人物 |
| 集中 | `Pool` | 「金集ﾒﾙ」 | `P` | 集資 |
| 分配 | `Share` | 「金分ｹﾙ」 | `S` | 分錢 |
| 偵測 | `Detect` | 「ﾃﾞｨﾃｸﾄ」 | `D` | 偵測 |
| 離開 | `Exit` | 「抜ける」 | `E` | 離開 |

⚠ DOS 側是**五個完整字串接出來的**（`'View Pool Exit'`(14)、`' Exit'`(5)、
`' Detect Exit'`(12)、`'View Take Pool Share'`(20)、`'View Take Pool'`(14)），
中文化要跟 PC-98 的逐格寫法，不要去接字串。

離開訊息：

| | DOS | PC-98 |
|---|---|---|
| 前句 | `'There is still treasure left.  '`（31，結尾兩個空白） | 「まだ宝物が残っている。」（22） |
| 後句 | `'Do you want to go back and claim your treasure?'`（47） | 「戻って宝物を取りますか？」（24） |
| 是／否 | `'~Yes ~No'`（8） | `' はい　いいえ'` ＋ 熱鍵 `A`／`B` |

⚠ 這是第三組「要不要回去拿」的訊息，和 spec 1030（錢）／1031（錢）措辭都不同
（這裡是 treasure）。**三組都要各自翻**。
