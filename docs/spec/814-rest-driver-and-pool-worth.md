# 814 — 休息的主流程（把分鐘拆成 時／十分／分）、Pool 值多少金幣

- 證據等級：`exact`（DOS 側逐條讀完，尾端兩條由原始位元組手動解碼；PC-98 側的
  差異已逐條列出）
- 作法見 spec 783；錯位的判定方式見 spec 811

## `overlay-15:07B2h`（entry#10，66 條，實質差異 7 條）— 休息的主流程

`retf 4` ＝ 一個遠指標（輸出一個 byte）。

```pascal
最大 := 0;
p := DS:650Ah;
while p <> NIL do begin
    t := <本模組 0034h>(p);            { spec 813：這個角色要休息幾分鐘 }
    if t > 最大 then 最大 := t;        { 無號 }
    p := p^[189h];
end;

DS:756Ch := 最大 div 3Ch;                                  { 索引 3 ＝ 時 }
DS:756Ah := (最大 − DS:756Ch * 3Ch) div 0Ah;               { 索引 2 ＝ 十分鐘 }
DS:7568h := 最大 mod 0Ah;                                  { 索引 1 ＝ 分 }

輸出^ := <far 10AEh+1>(1);                                 { 休息迴圈本體 }

FillChar(DS:7566h, 0Eh, 0);                                { 收尾清掉整組 }
<far 014Dh:00DEh>();
```

### 全隊取最大

**休息時間是全隊裡最久的那一個**（`overlay-15:0034h` 逐人算，取 max），不是總和。

### 分鐘怎麼拆進那七個 word

`DS:7566h` 的單位在 spec 793／802／803 已定（`[1]` 分、`[2]` 十分鐘、`[3]` 時、
`[4]` 日）。這裡只寫索引 1、2、3：

```
時       := 分鐘 div 60
十分鐘   := (分鐘 − 時 × 60) div 10
分       := 分鐘 mod 10
```

- **索引 0（六秒）與索引 4（日）都不寫**——所以休息永遠不會跨「日」那一格，
  超過 24 小時只會讓「時」那一格變成大於 23 的數。spec 803 的畫面照樣把它印出來。
- 三個除法都是**無號**的。

### 收尾把整組清成 0

`FillChar` 在 `10AEh+1` **回來之後**才執行——休息迴圈跑完（或被中斷）就把剩餘
時間整組歸零。所以 `DS:7566h` 只在休息進行中有意義。

### DOS 側匯出的尾端錯位

DOS 匯出把 `0850h` 起解成 `or bl, [bp+si+arg_D8]` ／ `dec bp`。原始位元組是

```
DOS  : 9A E0 1A 54 0A   9A DE 00 4D 01
PC-98: 9A 30 1B 65 0A   9A DE 00 4A 01
```

＝ `call far 0A54h:1AE0h`（FillChar）與 `call far 014Dh:00DEh`，兩平台只差節區。

## `overlay-21:00C7h`（entry#6，51 條，實質差異 2 條）— Pool 值多少金幣

`retf 4` ＝ 一個遠指標，回傳 `dx:ax`（longint）。

```pascal
Move(來源^, 暫存, 1Ch);                      { 28 bytes ＝ 7 個 longint }
總 := 0;
for j := 0 to 4 do
    總 := 總 + <0A54h:0279h>(暫存[j], longint@(0CA2h + j * 4));
結果 := <0A54h:0294h>(總 + 64h, longint@0CAEh);
```

與 spec 812 的 `overlay-19:33ABh`（角色身上的錢）是同一條式子，差別只在來源：

| | 來源 | 每格 |
|---|---|---|
| `overlay-19:33ABh` | 角色 `+0FBh` | **word** |
| 本支 | 傳進來的 28 bytes | **longint** |

**先整份抄進區域再算**，所以不會動到原始的 Pool。抄 `1Ch` ＝ 7 個 longint，與
spec 798「Pool 只動前 7 個 longint」對得起來（`DS:6F70h` 的第 8 個不在內）。

同樣**只算前 5 種幣別**，Gems / Jewelry 不計入總價。

## 明確不宣稱

- 沒有宣稱 `far 10AEh+1` 的參數 `1` 是什麼，也沒有宣稱它回傳的 byte 代表什麼。
- 沒有宣稱 `far 014Dh:00DEh` 做什麼。
- 沒有宣稱呼叫端傳進 `overlay-21:00C7h` 的那 28 bytes 一定是隊伍 Pool。
