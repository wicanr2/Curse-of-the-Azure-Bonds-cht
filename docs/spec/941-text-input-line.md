# 941 — 底列文字輸入欄：只收 `20h`..`7Ah`，收完一律轉大寫

- 證據等級：`exact`（逐條讀完）
- 位置：DOS `START.EXE` 的 `15B42h`
- 作法見 spec 783

## `15B42h`（171 條）—— `retf 0Ah`

```pascal
輸入(最大長度 arg_0, 前景 arg_2, 背景 arg_4, 提示 arg_6, @結果 arg_A);

提示 := 限長(arg_6, 28h);
<sub_15731h>(28h, 0, 18h, 0);                     { 清第 24 列的 40 欄 }
<sub_15772h>(提示, 前景, 背景, 18h, 0);           { spec 934 的格線字串輸出 }
欄 := length(提示);
緩衝 := '';

repeat
    鍵 := <sub_16FADh>();                         { spec 936 的等按鍵 }

    if (鍵 >= 20h) and (鍵 <= 7Ah) then begin
        if length(緩衝) < 最大長度 then begin     { 無號 }
            緩衝 := 緩衝 ＋ 鍵;
            inc(欄);
            <sub_15772h>(鍵, 0, 0Fh, 18h, 欄);    { 回顯，固定用 0／0Fh }
        end;
    end
    else if 鍵 = 8 then begin                     { Backspace }
        if length(緩衝) > 0 then begin
            緩衝 := Copy(緩衝, 1, length(緩衝) − 1);
            <sub_15731h>(1, 0, 18h, 欄);          { 清掉那一格 }
            dec(欄);
        end;
    end;
until (鍵 = 0Dh) or (鍵 = 1Bh) or (byte_2117Ch <> 0);

<sub_15731h>(28h, 0, 18h, 0);                     { 清掉整列 }
for i := 1 to length(緩衝) do 緩衝[i] := UpCase(緩衝[i]);
結果^ := 限長(緩衝, 28h);
```

## ★ 收完一律轉大寫

離開迴圈之後**逐字元 `UpCase`**，才寫回呼叫端。
這與 spec 937 的字型只有 **64 個大寫字模**是同一件事的兩面：
**原版根本無法顯示小寫**，所以輸入也不保留小寫。

角色名字、存檔名等玩家輸入全部經過這一層——
**remake 若允許小寫，就與原版的資料相容性脫鉤**。

## 接受範圍是 `20h`..`7Ah`

空白（`20h`）到小寫 `z`（`7Ah`）。`7Bh`..`7Fh`（`{ | } ~`）被擋掉，
`7Ah` 以下的小寫字母收得進來但最後會被轉成大寫。

## 三處硬編碼

- **第 24 列**（`18h`）——與 spec 932 的底列提示同一列。
- **40 欄**（`28h`）——提示與結果都限長 40。
- **回顯用固定的 `0`／`0Fh`**，不是呼叫端傳進來的前景／背景；
  只有提示那一次用 `arg_2`／`arg_4`。所以**輸入的字與提示的字顏色不同**。

## ⚠ 非阻塞模式下只吃一個鍵

離開條件包含 `byte_2117Ch <> 0`（spec 936 的非阻塞旗標）。
那個旗標立著時，`<sub_16FADh>` 沒按到鍵就回 0，而迴圈條件**無論如何都成立**，
所以整個輸入欄跑一圈就結束、回傳空字串。

## 明確不宣稱

- 沒有宣稱 `<sub_15731h>` 的內部（形狀上是「用某個字元填一段」）。
- 沒有宣稱 `1Bh`（Esc）與 `0Dh`（Enter）離開後呼叫端怎麼區分
  ——本支兩者都回傳緩衝內容，**沒有回傳是哪一個鍵**。
