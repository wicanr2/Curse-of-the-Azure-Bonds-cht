# 937 — 畫字元的分派層：64 個字模、三種顯示模式

- 證據等級：`exact`（逐條讀完）
- 位置：DOS `START.EXE` 的 `15606h`
- 作法見 spec 783

## `15606h`（126 條）—— `retf 0Eh`

```pascal
畫字元(轉大寫 arg_0, 字元 arg_2, 次數 arg_4, 前景 arg_6, 背景 arg_8, 列 arg_A, 欄 arg_C);

if (欄 > 27h) or (列 > 18h) or (dword_22754h = NIL) then 離開;   { 無號 }

if 轉大寫 <> 0 then 索引 := UpCase(字元) mod 40h
else                索引 := 字元;

Move(遠指標(dword_22754h)^[索引 × 8], DS:6598h, 8);              { 取 8 bytes 字模 }

case byte_211A6h of
  0: 重複 次數 次 <sub_16147h>(索引, 前景, 背景, 列, 欄)，每次 inc(欄);
  1: 重複 次數 次 <sub_161E6h>(同上)，每次 inc(欄);
  2: 重複 次數 次 <sub_16246h>(同上)，每次 inc(欄);
end;
```

## ★ 字模只有 64 個

`索引 := UpCase(字元) mod 40h`——**取大寫之後對 64 取餘數**。
ASCII `20h`..`5Fh`（空白到底線）正好映到 `0`..`3Fh`，
小寫先被 `UpCase` 拉到大寫。所以字型檔是 **64 個 8 bytes 的字模，共 512 bytes**，
放在 `遠指標(dword_22754h)`。

**這是中文化最硬的一道限制**：這一層的字型空間只有 64 格，
而且索引直接由字元碼算出，沒有查表可以攔截。要放中文必須換掉整條路
（或在更上層改成 spec 932／934 的其他輸出層）。

`轉大寫 = 0` 那條路不做 `mod`，索引直接是字元碼——
**呼叫端若傳超過 63 的值就會讀到字模表外**。本支沒有夾範圍。

## ★ `byte_211A6h` 是三值，不是旗標

| 值 | 畫字元的實作 |
|---|---|
| 0 | `<sub_16147h>` ＝ **CGA 320×200 四色**（spec 935：`0B800h`／`0BA00h` 交錯半頁、2 bits／像素） |
| 1 | `<sub_161E6h>` |
| 2 | `<sub_16246h>` |

spec 932 記到它 ＝ 0 時顏色要過 `DS:256Dh` 轉換表、
spec 934 記到它 ≠ 0 時每列位元組加倍——**那兩處都把它當成兩值旗標**，
以本支為準它有**三個顯示模式**。兩份規格已改。

## ★ `DS` 的線性基底是 `1C1C0h`

本支把字模 `Move` 到 `DS:6598h`，IDA 把同一個位址命名為 `byte_22758h`：

```
22758h − 6598h ＝ 1C1C0h
```

所以整個常駐執行檔的換算是 **IDA linear ＝ `DS:offset` ＋ `1C1C0h`**。
反過來，spec 932 的 `DS:256Dh` ＝ linear `1E72Dh`、
spec 936 的 `word_1E76Ch` ＝ `DS:25ACh`。

這同時關掉 spec 935 的待答項：**`DS:6598h` 那 8 bytes 就是本支填的字模暫存區**，
`16147h` 逐條掃描線讀的正是它。

## 上界

`欄 > 27h`（39）或 `列 > 18h`（24）就整個跳過——
所以這一層的座標系是 **40 欄 × 25 列**。
spec 934 的 `15772h` 只檢查兩個座標都 `> 27h`，**列的上界比本支寬**
（那裡寫成 `arg_8 > 27h`），兩者不一致；實際生效的是本支這一道。

## 明確不宣稱

- 沒有宣稱 `<sub_161E6h>` 與 `<sub_16246h>` 對應哪兩種顯示硬體。
- 沒有宣稱字型檔（`dword_22754h`）由誰載入。
- 沒有宣稱 64 個字模各對應哪個字元的圖形。
