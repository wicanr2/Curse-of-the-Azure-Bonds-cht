# 873 — 加入隊伍：接到鏈尾並配一個沒人用的圖像編號 0..7

- 證據等級：`exact`（PC-98 側逐條讀完；DOS 側有一處反組譯錯位，由 PC-98 校正）
- 作法見 spec 783

## `overlay-16:035A8h` ↔ `overlay-16:03E8Bh`（兩平台各 98 條）

`overlay-16` ＝ LOADSAVE。`retf 4` ＝ 一個角色遠指標。

```pascal
角色^[143h] := 0FFh;                              { 先標成「還沒配」 }

if 遠指標(DS:650Ah) = NIL then
    DS:650Ah := 角色                              { 空隊伍：直接當鏈頭 }
else begin
    p := 遠指標(DS:650Ah);
    while p^[189h] <> NIL do p := p^[189h];
    p^[189h] := 角色;                             { 接到鏈尾 }
end;
DS:6506h := 角色;                                 { 選中新加入的 }

FillChar(用過[0..7], 8, 0);
p := 遠指標(DS:650Ah);
while p <> NIL do begin
    if <0A54h:08D4h>(合法編號表, p^[143h]) then    { 以 ZF 回報 }
        用過[p^[143h]] := 1;
    p := p^[189h];
end;

q := 遠指標(DS:6506h);
q^[143h] := 0;
while (q^[143h] < 8) and (用過[q^[143h]] <> 0) do   { 無號 }
    inc(q^[143h]);

inc(遠指標(DS:4F9Dh)^[67Ch]);                      { 隊伍人數 ＋1 }

if 角色^[0F7h] > 7Fh then <far 1623h+2>(角色);      { 士氣沒崩才做 }
```

## `+143h` ＝ 圖像編號，有效範圍 0..7

先寫 `0FFh`，掃完全隊之後從 0 往上找第一個沒被佔用的。
**八個都被佔走時 `+143h` 會停在 8**，也就是「配不到」。

這正好接上 **spec 872 的 PC-98 差異**：那邊的
`if 角色^[143h] > 7 then <far 1994h>(...)` 判的就是「編號不在 0..7」
（`8` 或還沒配的 `0FFh`）。兩支互相定界，`+143h` 的值域因此確定。

`+143h` 緊接在外觀配色欄位 `+144h..+14Ah` 之前，所以整段
`+143h..+14Ah` 是**角色外觀**：一個圖像編號 ＋ 七個配色 byte。

⚠ 掃描時只有 `0A54h:08D4h` 對合法編號表回真的才算「用過」，
所以剛設成 `0FFh` 的自己不會把某一格標成佔用。

## ⚠ DOS 側有一條反組譯錯位

DOS 的 `361Bh` 被解成 `hlt`，PC-98 同位置是 `lea di, [bp+var_C]`。
Turbo Pascal 不會產生 `hlt`——**這是 IDA 從指令中間起解**
（`8D 7E F4` 的 `F4` 被當成 `hlt`）。正確的是

```
lea di, [bp+var_C]   ; 用過陣列的位址
push ss / push di / mov ax, 8 / mov al, 0 / call FillChar
```

與後面 `[bp+di-0Ch]` 的用法一致。**這是 spec 783 第 b 類的實例，
由對側平台校正**——單看 DOS 會以為函式中間有一條停機指令。

## PC-98：44 條差異全是位址

`DS:650Ah`↔`9598h`、`+189h`↔`+18Ah`、`DS:4F9Dh`↔`7F09h`，
以及 IDA 對同一批堆疊變數的兩種命名寫法。**沒有邏輯差異。**

## 明確不宣稱

- 沒有宣稱 `far 1623h+2(角色)` 做什麼（只在 `+0F7h > 7Fh`，即士氣沒崩時呼叫）。
- 沒有宣稱合法編號表 `loc_3588` 的內容。
- 沒有宣稱八個編號都被佔用時 `+143h ＝ 8` 由誰處理。
