# 810 — 四張法術進階表對上 AD&D 一版：牧師／聖騎士／遊俠／法師

- 證據等級：`exact`（DOS 側逐條讀完；四張表取自常駐資料段 dump，兩平台逐位元組
  相同）
- 作法見 spec 783

## `overlay-25:0011h`（entry#1，342 條）

`retf 4` ＝ 一個角色遠指標。

```pascal
FillChar(角色^[12Dh], 0Fh, 0);                { 15 bytes ＝ 3 列 × 5 級 }
for c := 0 to 7 do begin
    if <本模組 13BCh>(角色) and (角色^[111h + c] <> 0) then
        L := 角色^[111h + c]
    else
        L := 角色^[109h + c];
    if 有號(L) <= 0 then continue;
    case c of
    0: … 牧師     … 表 DS:42BAh，L 由 2 起
    3: … 聖騎士   … 表 DS:43E3h，L 由 9 起（L ≤ 8 直接跳過）
    4: … 遊俠     … 表 DS:4446h，L 由 8 起（L ≤ 7 直接跳過）
    5: … 法師     … 表 DS:44A9h，L 由 2 起
    end;
end;
{ 裝備加成 }
p := 角色^[14Dh];
while p <> NIL do begin
    if (p^[3Eh] = 81h) and (p^[34h] <> 0) then
        for j := 1 to 3 do 角色^[136h + j] := 角色^[136h + j] + 角色^[136h + j];
    p := p^[2Ah];
end;
```

## 角色記錄：兩組 8 byte 的職業等級

`+109h`..`+110h` 與 `+111h`..`+118h` 是兩個並排的 8 格陣列，索引就是**職業槽**
`c`。`13BCh` 回真且第二組非 0 時取第二組，否則取第一組。

（spec 795 的 `+10Fh` / `+117h` 是這兩個陣列的第 6 格。）

## 三列可記憶數：`+12Dh` / `+132h` / `+137h`

`FillChar` 清的正好是 `+12Dh`..`+13Bh` 共 15 bytes，配合 spec 788 的索引式
`+12Ch + 列 × 5 + 等級`：

| 列 | 範圍 | 誰寫 |
|---|---|---|
| 0 | `+12Dh`..`+131h` | 牧師（c ＝ 0）、聖騎士（c ＝ 3） |
| 1 | `+132h`..`+136h` | 遊俠的德魯伊法術（c ＝ 4，欄 1..3） |
| 2 | `+137h`..`+13Bh` | 法師（c ＝ 5）、遊俠的法師法術（c ＝ 4，欄 4..5） |

## 四張表都是「每等級 5 bytes 的增量」，累計後與 AD&D 一版完全相同

### `DS:42BAh` — 牧師（c ＝ 0，L 由 2 起，基底 `+12Dh := +1`）

累計：`1 / 2 / 2·1 / 3·2 / 3·3·1 / 3·3·2 / 3·3·2·1 / 3·3·3·2 / 4·4·3·2·1 /
4·4·3·3·2 / 5·4·4·3·2 / 6·5·5·3·2`（L1..L12）。詳表見 spec 809。

累加完呼叫 `<本模組 0671h>(角色, 0)` ——就是 spec 809 那支的「只加智慧加成」路徑。

### `DS:43E3h` — 聖騎士（c ＝ 3，L 由 9 起，**寫進牧師那一列**）

| L | 9 | 10 | 11 | 12 |
|---|---|---|---|---|
| 增量 | 1 級 +1 | 1 級 +1 | 2 級 +1 | 2 級 +1 |
| 累計 | 1 | 2 | 2 / 1 | 2 / 2 |

AD&D 聖騎士第 9 級才有牧師法術，這裡的 `L ≤ 8 直接跳過` 與表的起點一致。

### `DS:4446h` — 遊俠（c ＝ 4，L 由 8 起，**一列裡打包兩套法術**）

欄 1..3 寫進列 1（德魯伊），欄 4..5 寫進**列 2 的第 1、2 級**（法師）：

| L | 8 | 9 | 10 | 11 | 12 |
|---|---|---|---|---|---|
| 增量 | 欄1 +1 | 欄4 +1 | 欄1 +1 | 欄4 +1 | 欄2 +1 |
| 德魯伊累計 | 1 | 1 | 2 | 2 | 2 / 1 |
| 法師累計 | — | 1 | 1 | 2 | 2 |

與 AD&D 一版遊俠（8 級起德魯伊、9 級起法師）逐格相符。**欄 4、5 跳到另一列不是
錯誤，是把兩套進階表壓進同一個 5 欄結構的編碼方式**——remake 照抄時不能「修正」
成連續索引。

### `DS:44A9h` — 法師（c ＝ 5，L 由 2 起，基底 `+137h := +1`）

累計：`1 / 2 / 2·1 / 3·2 / 4·2·1 / 4·2·2 / 4·3·2·1 / 4·3·3·2 / 4·3·3·2·1 /
4·4·3·2·2 / 4·4·4·3·3 / 4·4·4·4·4`（L1..L12）——AD&D 一版法師表。

### 四張表都只到 12 級

`L = 13` 之後就是別的資料（看起來是經驗值門檻的小端 word）。四個累加迴圈**都沒有
上界檢查**，角色等級超過 12 就會把後面的資料當增量加進去。

## 「這支法術學得會嗎」的旗標（`+79h` 起 56 格）

牧師（c ＝ 0）與聖騎士（c ＝ 3）在累加完之後掃 `s = 1..100`：

```pascal
p := DS:37DAh + s * 16;
if (p^[0] = 0) and (角色^[12Ch + p^[1]] > 0) { and (s <> 24h) 只有 c = 0 有 } then
    角色^[78h + s] := 1;
```

法師（c ＝ 5）**沒有這段**——法師的法術要靠抄寫（spec 803）才會設旗標。這解釋了
兩種職業取得法術的方式為什麼不同。

### 三個實測出來的落差

法術屬性 `+0` 欄（職業類別）在 56 筆裡的分佈：**`0` 有 24 支、`2` 有 31 支、
`3` 只有 1 支（第 36 號 `Animate Dead`）**。由此：

1. **遊俠（c ＝ 4）那段旗標迴圈的條件是 `byte[37DAh + s*16] = 1`，而 `+0` 從來
   不是 1**——這個迴圈一支法術都設不到。
2. **牧師那段多出來的 `s <> 24h` 是多餘的**：第 36 號的 `+0` 是 `3`，
   `p^[0] = 0` 本來就擋掉了。
3. **迴圈跑到 `s = 100`，但法術表只有 56 筆**——`s = 57..100` 讀的是表外的資料
   （仍在已初始化區，不會當掉，但值沒有意義）。

三點都要在 remake 決定「照抄還是修正」時明確記下來。

## 裝備加成：法師 1–3 級加倍

```pascal
if (物品^[3Eh] = 81h) and (物品^[34h] <> 0) then
    for j := 1 to 3 do 角色^[136h + j] := 角色^[136h + j] × 2;
```

`+34h` ≠ 0 ＝ 裝備中（spec 807）、`+3Eh` 是物品的第三個效果槽（spec 803）。
效果值**剛好等於 `81h`** 才算——不是「最高位為 1」，是**整個 byte 相等**。

加倍的是列 2 的 1..3 級，也就是**法師 1–3 級的可記憶數**。物品鏈上每有一件符合
的裝備就再加倍一次（`x := x + x`），沒有次數限制。

## 明確不宣稱

- 沒有宣稱 `13BCh` 回傳的意義。
- 沒有宣稱列 1 是不是「德魯伊」——只確定遊俠的欄 1..3 寫進去，而它與列 0
  （牧師）、列 2（法師）是不同的三列。
- 沒有宣稱效果值 `81h` 對應哪一件物品。
- 沒有宣稱 `+79h` 那 56 格旗標由誰讀。
