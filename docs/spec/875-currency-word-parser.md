# 875 — 幣別名稱 → 索引 0..6：DOS 看首字母，PC-98 改成整字比對

- 證據等級：`exact`（兩平台各自逐條讀完）
- 作法見 spec 783

## `overlay-21:00B91h`（DOS 125 條）↔ `overlay-21:00B9Bh`（PC-98 219 條）

`retf 8` ＝ 兩個遠指標：`(輸入字串, var 標準寫法)`。回傳 `al` ＝ 索引。

```pascal
緩衝 := 輸入字串;                                  { 0A54h:064Eh，上限 0FFh }
i := 1;
while 緩衝[i] = ' ' do inc(i);                     { 跳過前導空白 }

case 緩衝[i] of
  'G': if UpCase(緩衝[i+1]) = 'E' then begin 結果 := 5; 標準 := 'Gems '     end
       else                            begin 結果 := 3; 標準 := 'Gold '     end;
  'P':                                 begin 結果 := 4; 標準 := 'Platinum ' end;
  'E':                                 begin 結果 := 2; 標準 := 'electrum ' end;
  'S':                                 begin 結果 := 1; 標準 := 'silver '   end;
  'C':                                 begin 結果 := 0; 標準 := 'Copper '   end;
  'J':                                 begin 結果 := 6; 標準 := 'Jewelry'   end;
end;
```

## 索引順序與 spec 858／863 完全一致

| 索引 | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| 本支 | `Copper` | `silver` | `electrum` | `Gold` | `Platinum` | `Gems` | `Jewelry` |
| spec 858 的換算 | ÷200 | ÷20 | ÷2 | ×1 | ×5 | ×250 | ×2200 |
| spec 863 的分配 | 最後分 | | | | | | 最先分 |

**這是那七格順序的第三份獨立證據**（前兩份是 858 的換算係數與
812／773 的 `DS:0773h` 名稱表），而且這一份是遊戲自己印給玩家看的字。

`'G'` 要看第二個字母才能分開 `Gems` 與 `Gold`——**這正是首字母法的極限**，
也是唯一需要看第二個字元的分支。大小寫不一致（`Gems`／`Gold`／`Platinum`／
`Jewelry` 大寫開頭，`electrum`／`silver` 小寫開頭）是原版字串常數本來就這樣。

## PC-98：整字比對，不看首字母

PC-98 把整個 `case` 換成七次「取子字串 ＋ 字串比對」：

```pascal
for 每一組 (長度, 詞, 索引) in
      [(8, '宝石飾り', 6), (4, '宝石', 5), (4, 'ｇｐ', 3), (4, 'ｐｐ', 4),
       (4, 'ｅｐ', 2), (4, 'ｓｐ', 1), (4, 'ｃｐ', 0)] do begin
    子 := Copy(緩衝, i, 長度);                     { 0A65h:067Bh }
    if 子 = 詞 then begin                          { 0A65h:0734h }
        標準 := 詞;  結果 := 索引;  離開;
    end;
end;
```

**日文沒有「首字母」可看**——`宝石` 與 `宝石飾り` 的第一個字相同，
`ｇｐ`／`ｐｐ`／`ｅｐ`／`ｓｐ`／`ｃｐ` 全部以不同全形字開頭但都是兩個字。
所以 PC-98 只能整字比。比對順序也跟著改：
**先比長的 `宝石飾り`（8 bytes）再比 `宝石`（4 bytes）**，否則
「宝石飾り」會先被「宝石」吃掉。

堆疊框從 `102h` 漲到 `802h`：七次 `Copy` 各要一個 256 bytes 的暫存。

### 中文化

**中文必須跟 PC-98 走整字比對**，理由與日文相同。而且要注意兩件事：

1. **長詞先比**：「寶石飾品」要排在「寶石」前面，否則永遠比不到。
2. **標準寫法會被寫回去**（第二個參數是 var），所以譯名同時是「玩家能輸入的詞」
   與「畫面顯示的詞」，兩者不能分開設計。

`ｇｐ`／`ｐｐ` 這種全形縮寫是 PC-98 自己的選擇；中文版可以用
「金幣／白金幣／琥珀金幣／銀幣／銅幣」，但要確認沒有兩個詞互為前綴。

## 明確不宣稱

- 沒有宣稱呼叫端拿這個索引做什麼（形狀上是配 spec 863 的七格錢包）。
- 沒有宣稱首字母比對是不是大小寫敏感——`'G'`／`'P'` 等都是直接比大寫，
  但只有 `'G'` 之後那一格用了 `0A54h:1C62h`（UpCase）。
  **所以輸入小寫 `gold` 會落到第一個分支之外**，本規格不宣稱這是不是原版 bug。
