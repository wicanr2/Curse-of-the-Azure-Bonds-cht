# 982 — 訊息框的實際幾何：戰鬥中只有 16 欄寬

- 證據等級：`exact`（逐條讀完；矩形座標順序沿用 spec 693 已定案的
  `01A0h:04CDh(x1, y1, x2, y2)`）
- 作法見 spec 783

## `dos overlay-24:017D6h`（entry#20，108 條，`retf 0Ch`）

這是全專案被叫得最兇的一支——四種怪物特攻（spec 720／722／723／981）、
攻擊訊息（spec 840）、治療訊息都經過它，但一直沒有判讀過。

`retf 0Ch` ＝ 6 個 word。依 Turbo Pascal 由左至右推疊，宣告順序是

```pascal
procedure 顯示訊息(角色: 遠指標; 訊息: 遠指標; 列: byte; 要停頓: byte);
```

（`角色` 在 `[bp+0Eh]`、`訊息` 在 `[bp+0Ah]`、`列` 在 `[bp+8]`、`要停頓` 在 `[bp+6]`。）

```pascal
限長(訊息^, 本地, 0FFh);

if DS:4FBAh = 5 then begin                                  { 戰鬥中 }
    <01A0h:04CDh>(17h, 列, 26h, 15h);                       { 清框 }
    <本模組 18F3h>(0, 列, 17h, 角色);                        { 畫名字 }
    <0542h:04A4h>(17h, 列 ＋ 1, 26h, 15h, 0Ah, 0, 1, 本地);  { 畫內文 }
end
else begin
    if DS:757Eh <> 0 then y := 12h else y := 11h;
    <01A0h:04CDh>(1, y, 26h, 16h);
    <本模組 18F3h>(0, y ＋ 1, 1, 角色);
    <0542h:04A4h>(1, y ＋ 2, 26h, 16h, 0Ah, 0, 1, 本地);
end;

if 要停頓 <> 0 then begin
    <0542h:0B33h>();                                        { 等玩家 }
    <本模組 18BEh>();                                        { 清掉訊息框 }
end;
```

## ★ 兩種版面的實際格子

`01A0h:04CDh` 的四個參數是 `(x1, y1, x2, y2)`（spec 693 由
`(0, 18h, 27h, 18h)` ＝ 清整個第 24 列定案，畫面是 **40 欄 × 25 列**）。
代進去：

| | 戰鬥中（`DS:4FBAh = 5`） | 非戰鬥 |
|---|---|---|
| 欄範圍 | **23 – 38** | **1 – 38** |
| 列範圍 | 呼叫端給的列 – 21 | 17 或 18 – 22 |
| 寬度 | **16 欄** | 38 欄 |
| 名字畫在 | 第 `列` 列、欄 23 | 第 `y+1` 列、欄 1 |
| 內文起始 | 第 `列 + 1` 列 | 第 `y + 2` 列 |

四種怪物特攻傳進來的「列」**一律是 `0Ah`（10）**，所以戰鬥訊息框實際上是
**欄 23–38 × 列 10–21**——正是 Gold Box 戰鬥畫面右側那一塊。

`18BEh`（spec 585）清的兩個矩形 `(17h, 0Ah, 26h, 15h)` 與 `(1, 12h, 26h, 16h)`
與這裡完全一致，互相印證。

⚠ **非戰鬥時呼叫端給的「列」被完全忽略**，改用 `DS:757Eh` 決定 17 還是 18。
所以同一個呼叫端在戰鬥內外會畫到不同的地方，而且只有戰鬥中控制得了列號。

### 中文化：這是最硬的一道版面限制

**戰鬥訊息框只有 16 欄 ＝ 8 個漢字一行。**
`0542h:04A4h` 是會自動換行的段落繪製（`0542h:0352h` 那一支只畫單行），
可用的高度是列 11–21 共 11 列。所以戰鬥中一則訊息的容量上限大約是
**8 字 × 11 行 ＝ 88 個漢字**，而且**第一行還要和角色名字共用**（名字畫在第 10 列）。

英文原文像 `'<name> throws lightning'` 在 16 欄裡要折兩行；
中文「◯◯◯投出電光」六個字剛好一行。反過來說，
把長句直譯成中文很容易超過 11 行——**戰鬥訊息必須逐句量過寬度**。

非戰鬥的框有 38 欄 ＝ 19 個漢字，寬鬆得多。**同一句話在兩個情境下的
折行結果不同**，中文化不能只看其中一邊。

## 明確不宣稱

- ~~沒有宣稱 `0542h:04A4h` 後三個參數（`0Ah`、`0`、`1`）分別是什麼。~~
  → spec 987：第七個是**「先清框」旗標**（`dos overlay-07:02252h` 只有在剛捲回
  第 17 列時才給 `1`，一般情況給 `0` 接著往下寫）。第五個 `0Ah` 是顏色，
  第六個 `0` 仍不宣稱。同時該支證實非戰鬥框的**可用高度只有 6 列（17..22）**，
  游標在 `DS:65A0h`（欄）與 `DS:65A1h`（列）。
- 沒有宣稱 `DS:757Eh` 是什麼（只知道它讓非戰鬥的訊息框上移一列）。
- 沒有宣稱 `0542h:0B33h` 怎麼等玩家（形狀上是等按鍵）。
- 沒有宣稱 `0542h:04A4h` 的折行規則（是不是斷在空白、超出高度怎麼辦）——
  中文化要真的量出容量，還得把那一支讀完。
- 沒有讀 PC-98 的對應（`overlay-24:019A8h`），所以沒有宣稱 PC-98 的框幾何。
