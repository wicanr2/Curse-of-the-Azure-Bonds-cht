# 865 — 兩支選單小函式：找上一個標題行、等一個合法按鍵

- 證據等級：`exact`（兩支的 DOS 側都逐條讀完；PC-98 側差異逐條列出）
- 作法見 spec 783

## `overlay-26:007FDh` ↔ `overlay-26:009DEh`（兩平台各 52 條）— 找上一個標題行

`retf 8` ＝ 4 個 word：`(上限, 鏈頭, 未用)`。走的是 **spec 859 的顯示行節點**
（`+29h` ＝ 標題行旗標、`+2Ah` ＝ next；PC-98 `+51h`／`+52h`）。

```pascal
i := 0;  p := 鏈頭;  最後 := NIL;
while (p <> NIL) and (有號(i) < 有號(上限)) do begin
    if p^[29h] <> 0 then 最後 := p;
    p := p^[2Ah];
    inc(i);
end;
if (最後 = NIL) and (鏈頭^[29h] <> 0) then 結果 := 鏈頭
else 結果 := 最後;
```

**在前 `上限` 行裡找最後一個標題行**——法術選單捲動時，用來知道
「現在這一頁上面是第幾階」。`DS:0875h` 的 `'1st Level'`..`'9th Level'`
（spec 825）就是那些 `+29h` ≠ 0 的行。

⚠ 那個 fallback 只有在 `上限 ≤ 0` 時才會生效：`上限 > 0` 的話，
鏈頭若是標題行，迴圈第一圈就已經把 `最後` 設成它了。
形狀上是「防 `上限` 傳 0」的補丁。

PC-98 的差異只有節點位移（`+29h`↔`+51h`、`+2Ah`↔`+52h`，spec 859 的
節點放大）與回傳值的取法（DOS 分兩次 `mov`、PC-98 用 `les`），**行為相同**。

## `overlay-26:0112Ah` ↔ `overlay-26:0129Dh`（DOS 52 條／PC-98 61 條）— 問到合法為止

`retf 0Ah` ＝ 5 個 word：`(提示字串, 參數A, 參數B, 參數C)`。

```pascal
緩衝 := 提示字串;                                   { 0A54h:064Eh，上限 28h }
DS:7294h := 2;
repeat
    暫 := 常數字串 ＋ 緩衝;                          { 0A54h:0634h }
    鍵 := <本模組 03D4h>(var 暫存, 0, 0, 參數C, 參數B, 參數A);
until not <0A54h:08D4h>(合法鍵表, 鍵);              { 以 ZF 回報 }
結果 := 鍵;
```

**PC-98 多做一段**（唯一的助憶碼差異）：在迴圈前把 `DS:1602h` 的 10 bytes
指派到 `DS:0A335h`（`0A65h:0262h`，三參數字串指派）。
這與 spec 817／844／599 讀到的模式一致——**PC-98 把熱鍵字元獨立成另一份
ASCII 字串**，因為日文標籤本身不含可按的字母。這是該模式的第四個獨立出現點。

堆疊框 `34h`↔`56h` 同樣是字串緩衝從 40 放寬到 80 的連帶（spec 859）。

## 明確不宣稱

- 沒有宣稱 `本模組 03D4h` 的六個參數各是什麼（形狀上是「畫提示並收一個鍵」）。
- 沒有宣稱 `0A54h:08D4h` 是哪一個 runtime 常式（收一個字串與一個 byte、
  以 ZF 回報，形狀上是 `Pos`）。
- 沒有宣稱 `DS:7294h := 2` 的意義。
- 沒有宣稱 `overlay-26:007FDh` 第三個參數（`arg_0`）的用途——**本體沒有讀它**。
