# 765 — 位元反轉、牆面從兩側各查一次、數字補零

- 證據等級：`exact`（以補洞後的匯出逐條讀完，見 spec 761）

## `PC98-GAME.EXE:13231h` — byte 的位元反轉

`retf 2`，八段展開的直線程式碼：

```pascal
function 反轉(x: byte): byte;
begin
    反轉 := (x        shl 7)     { bit 0 → bit 7 }
          + ((x and 02h) shl 5)  { bit 1 → bit 6 }
          + ((x and 04h) shl 3)  { bit 2 → bit 5 }
          + ((x and 08h) shl 1)  { bit 3 → bit 4 }
          + ((x and 10h) shr 1)  { bit 4 → bit 3 }
          + ((x and 20h) shr 3)  { bit 5 → bit 2 }
          + ((x and 40h) shr 5)  { bit 6 → bit 1 }
          + ((x and 80h) shr 7); { bit 7 → bit 0 }
end;
```

第一項沒有先 `and 01h`——直接 `shl 7` 之後只留 byte，效果一樣。全部用加法而不是
`or`，因為八個位元互不重疊，結果相同。

用途上這是**水平翻轉一個位元組的像素**所需的動作（8 個像素一個 byte），但本輪
沒有追呼叫端，不宣稱。

## `overlay-10:0378h`（兩平台）— 牆面從兩側各查一次

`retf 6`：

```pascal
反向 := (方向 + 4) mod 8;                        { 有號除法 }
a := 巢狀程序 02F6h(方向, y, x);                 { 靜態鏈：push bp }
x2 := x + byte[2694h + 方向];                    { PC-98：489Eh }
y2 := y + byte[269Dh + 方向];                    { PC-98：48A7h }
b := 巢狀程序 02F6h(反向, y2, x2);
結果 := a or b;
```

三件事：

- **方向共 8 個**，`(dir + 4) mod 8` 是正對面。
- `DS:2694h` / `DS:269Dh` 是 dx／dy 表，與 spec 748 裡雲霧形狀用的是**同一對表**
  （那裡是 `byte[2694h + byte[27D7h + k]]`，多一層形狀索引）。兩處合起來確認
  這對表就是「方向 → 位移」的共用查表。
- **同一道牆從兩邊各查一次再取聯集**。這與 spec 761／763 的地圖（16 × 16、每格
  一個 byte、四個方向各 2 bits）一致：一格只記自己四邊的狀態，所以要判「這格
  與鄰格之間有沒有牆」就必須兩邊都問。

`02F6h` 的呼叫多推一個 `bp`——那是 Turbo Pascal **巢狀程序的靜態鏈**，不是
一般參數。兩平台除了那兩個表位址之外，54 條指令完全相同。

## `overlay-20:0549h`（DOS）— 兩位數補零

`retf 2`：

```pascal
<14Dh:0052h>(緩衝A, n);                 { 數值轉字串 }
StoreString(→ 緩衝B, 28h);
if n < 0Ah then begin                    { 無號 }
    緩衝A := concat('0', 緩衝B);         { CS:0547h 就是一個字元的 '0' }
    StoreString(→ 緩衝B, 28h);
end;
<0A54h:0680h>(緩衝A, 緩衝B, 1, 2);
StoreString(緩衝A → 輸出參數, 28h);
```

小於 10 就在前面補一個 `'0'`，最後再取固定寬度。**這是「兩位數欄位」的格式化**
（時鐘、日期一類）。

中文化時要注意：補的是 ASCII 的 `'0'`，如果版面換成全形數字，這裡的寬度計算
會不一致。

## 明確不宣稱

- 沒有宣稱 `0A54h:0680h` 是什麼；只知道它收 `(遠字串, 遠字串, 1, 2)` 四個參數，
  位置與 `Copy(s, 1, 2)` 這類固定寬度取值相符。
- 沒有宣稱 `14Dh:0052h` 的轉換格式（十進位／十六進位／有無正負號）。
- 沒有宣稱 `02F6h` 回傳的「牆」是哪一種（實牆／門／暗門）。
- `dos START.EXE:1507Ah`（`retn 0Eh`，為 `sub_15329h` 備妥一組位移與計數）本輪
  讀完但沒有寫進台帳——它算出來的每個中間值都要靠 `sub_15329h` 才能解釋，
  單獨判讀會變成猜測。
