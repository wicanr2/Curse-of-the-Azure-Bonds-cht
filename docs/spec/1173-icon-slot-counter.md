# 1173 — `DS:7603h` 是**下一批怪物的圖示槽**，`CLEARMONSTERS` 設成 8 而不是清成 0

- 證據等級：`exact`（四個使用點全部讀完；`+143h` 的欄位名取自 PC-98 除錯符號）
- 上游：spec 1145（`1Ch` 把它設成 8）、spec 1104、spec 1146（兩者都把它列為未定項）
- 關掉的未定項：spec 1145「不宣稱 `7603h := 8` 的語意」、spec 1146 同一句

## 四個使用點

| 位址 | 做什麼 |
|---|---|
| `overlay-07:0238h` | 開機初始化：`7603h := 8` |
| `overlay-02:120Eh` | `1Ch CLEARMONSTERS`：`7603h := 8`（**不是 0**）|
| `overlay-02:058Ah` | 放怪物的迴圈裡：`節點^[143h] := 7603h` |
| `overlay-02:07E8h` | 迴圈**結束之後**：`inc 7603h`，緊接著 `8B69h := 1` |
| `overlay-02:053Eh` | `<overlay-33 entry#5>(7603h, 圖片編號, 'CPIC')` |

`+143h` 在 PC-98 的除錯符號裡叫 **`ICONINDEX`**（spec 1164 的 `CHARREC` 版面）。
`overlay-33 entry#5` 拿它與字串 `'CPIC'` 去組檔名——那是戰鬥畫面的怪物圖
（`CPIC1.DAX`..`CPIC6.DAX`）。

## ★ 一批共用一個槽

`inc` 在 `07E8h`，也就是**整個放置迴圈跑完之後**才做一次：

```pascal
for i := 1 to 數量 do begin
    節點^[143h] := DS:7603h;      { 每一隻都拿同一個值 }
    inc(DS:47E6h);
end;
inc(DS:7603h);                     { ★ 這一批用完，下一批換下一格 }
DS:8B69h := 1;
```

⇒ **同一次 `SETUP MONSTER` 放下去的怪物共用同一個圖示槽**，下一批才換。
起始值 8 也就有了解釋：**0..7 是隊伍成員的圖示**，怪物從 8 開始借。

`CLEARMONSTERS` 設成 8 而不是 0，因為 0 不是「空」，而是「第一位隊員的圖示」。

## remake 為什麼不需要它

remake 的每一個戰鬥員自己帶 `SpriteBlock`（由 `MonsterSpawn.IconBlock` 給），
不共用一組 DOS 端的圖示快取槽。可觀察行為相同——**一批共用一張圖**在 remake
這一側是「同一個 spawn 的每一隻拿同一個 `IconBlock`」，本來就成立。

⇒ `7603h` 是**快取索引**，不是遊戲狀態。`1Ch` 把它設回 8 在 remake 沒有對應
動作，也不該有。`1Ch CLEARMONSTERS` 因此從 `partial` 轉 `done`。

## 明確不宣稱

- 沒有宣稱圖示槽的上限，也沒有宣稱一場戰鬥最多幾批（`47E6h` 夾在 `3Fh`，
  但那是怪物**數量**不是批數）。
- 沒有宣稱 `overlay-33 entry#5` 載進去之後放在哪。
- 沒有宣稱 `8B61h`／`8B69h` 之外還有誰讀 `+143h`。
