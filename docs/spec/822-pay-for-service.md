# 822 — 神殿收費的共用常式：句子是拼出來的，先扣角色再扣 Pool

- 證據等級：`exact`（DOS 側逐條讀完，尾端四條由原始位元組手動解碼；PC-98 側的
  差異已逐條列出）
- 作法見 spec 783；錯位的判定方式見 spec 811

## `overlay-04:00F3h`（entry#3，兩平台各 139 條，實質差異 19 條）

這就是 spec 763／785／794／796／820／821 **九項神殿服務全部呼叫的那一支**
`00F3h`。`retf 6` ＝ 3 個 word：`(價錢: word; 服務名: 遠指標)`，回傳 `'Y'` / `'N'`。

### 價錢那句是拼出來的

```pascal
暫存 := 服務名;                                  { 0A54h:064Eh(0FFh, @暫存, 服務名) }
暫存 := 暫存 ＋ ' will only cost ';               { 0A54h:06C1h }
暫存 := 暫存 ＋ Str(價錢);                        { 014Dh:004Dh 轉字串後再接 }
暫存 := 暫存 ＋ ' gold pieces.';
<0542h:04A4h>(暫存, 1, 0, 0Ah, 16h, 26h, 11h, 1);
```

| 片段 | DOS | PC-98 |
|---|---|---|
| 前綴 | `' will only cost '`（16，**前後各一個空白**） | `'は、'`（4 bytes） |
| 後綴 | `' gold pieces.'`（13，**開頭一個空白**） | `'ｇｐでかけてあげましょう。'`（26 bytes，**全形 ｇｐ**） |

拼出來的句子是

```
DOS   : <服務名> will only cost <價錢> gold pieces.
PC-98 : <服務名>は、<價錢>ｇｐでかけてあげましょう。
```

**價錢夾在兩個片段中間**，而兩種語言的助詞／單位位置不同——PC-98 把「gold
pieces」換成前置的全形 `ｇｐ` 並改寫語序。中文版同理：兩個片段要一起翻，不能
逐句對譯。

### 三句獨立的訊息

| | DOS | PC-98 |
|---|---|---|
| 提問 | `'pay for cure '`（13，**結尾一個空白**） | `'かけてもらいますか？'`（20 bytes） |
| 錢不夠 | `'Not enough money.'`（17） | `'お金が足りません'` |
| 成功 | `'is cured.'`（9） | `'は治った'` |

`'is cured.'` 前面接角色名字（`DS:6506h` 一起推進去）。

### 先扣角色身上的，不夠才扣 Pool

```pascal
if 答 = 'Y' then begin
    有 := <00FDh:0057h>(DS:6506h);
    if 價錢 <= 有 then
        <0110h:006Bh>(有 − 價錢)
    else begin
        池 := <0110h:0075h>(@DS:6F70h);          { longint }
        if 價錢 <= 池 then                        { 32 位元有號比較 }
            <0110h:0070h>(低字(池 − 價錢))
        else begin
            顯示('Not enough money.');
            <014Dh:007Fh>();
            答 := 'N';
        end;
    end;
end;
if 答 = 'Y' then begin
    <014Dh:0089h>();
    顯示(名字 ＋ 'is cured.');
    <014Dh:0084h>(1);
end;
結果 := 答;
```

三件事：

- **順序是「先角色、後 Pool」**，而且**不會兩邊湊**：角色身上不夠就整筆改用 Pool，
  Pool 也不夠才失敗。
- Pool 的減法是 **32 位元**（`sub` ＋ `sbb`），但**只把低 16 位傳給
  `0110h:0070h`**。Pool 超過 65535 時高位會被丟掉。
- 成功那一段的 `'is cured.'` 是**寫死的**——不管呼叫端是治病、解毒、解咒還是復活，
  印出來的都是這一句。九項服務共用同一句結尾。

### DOS 側匯出的尾端錯位

`024Bh` 起被解成 `dec bp` ／ `add [bp+si+var_17A], cx` ／ `inc si` ／
`dec [bp+si+var_BA]`。原始位元組是

```
B0 01  50  9A 84 00 4D 01   8A 86 FE FE   88 46 FF   8A 46 FF
mov al,1 push ax call far 014Dh:0084h  mov al,[bp+var_102] ...
```

PC-98 側解對了（`call far 014Ah:0084h` ＋三條搬移）。

## 明確不宣稱

- 沒有宣稱 `00FDh:0057h` 回傳的是哪一種幣別的量（形狀上是「這個角色付得出多少」）。
- 沒有宣稱 `0110h:006Bh` / `0070h` / `0075h` 各做什麼。
- 沒有宣稱 `014Dh:007Fh` / `0084h` / `0089h` 各做什麼。
- 沒有宣稱 `0A54h:064Eh` 的 `0FFh` 是長度上限還是別的。
