# 988 — 三支 PC-98 對側，與豁免類別表補到四格

- 證據等級：`exact`（三支逐條讀完；差異區塊逐條比對）
- 作法見 spec 783

DOS 側都已判讀過，本規格只記 PC-98 側的差異與新增的事實。

## `pc98 overlay-22:06019h` ＝ DOS `05C86h`（spec 735，龍息／吐酸的分歧）

助憶碼序列**只有一個差異區塊**：PC-98 多了 `xor ah,ah / mov cx,7 / imul cx`，
也就是把 DOS 的動畫常數換成 `DS:7F16h × 7`——spec 981 記的通例。
其餘 14 處全是位址：

| DOS | PC-98 |
|---|---|
| `DS:758Dh`（回合計數） | `DS:0A81Fh` |
| `DS:6F95h` | `DS:0A02Fh` |
| `DS:7746h`（選目標的輸出） | `DS:0A9D8h` |
| `DS:72A0h`（分派表） | `DS:0A38Ch` |
| `DS:7559h`／`755Ah` | `DS:0A645h`／`0A646h` |
| `DS:7434h`（戰鬥員數） | `DS:0A520h` |

★ 這裡的 `DS:758Dh` ↔ `DS:0A81Fh` **獨立印證了 spec 981** ——那一支
（電光）在 DOS 用 `DS:758Dh >= 4` 當閘門、PC-98 用 `DS:0A81Fh`，
當時只能從位置推斷兩者對應，現在有第二個呼叫點佐證。

同理 `DS:7434h` ↔ `DS:0A520h`（spec 979 讀 PC-98 群體解除時用的候選表格數）
與 `DS:72A0h` ↔ `DS:0A38Ch`（spec 980 記的間接遠呼叫分派表）也各多一個佐證。

## `pc98 overlay-22:01D0Bh` ＝ DOS `01ABFh`（spec 732，反序效果迴圈）

同樣**只有一個差異區塊**，內容一樣是 `DS:7F16h × 7`。
14 處運算元差異全是位址，其中 `DS:7434h` ↔ `DS:0A520h`、
`DS:7431h + i×4` ↔ `DS:0A51Dh + i×4`（戰鬥員遠指標表，spec 979 已記）。

## `pc98 overlay-22:04DB9h` ＝ DOS `04A8Fh`（spec 724，恐懼）

兩個字串：`CS:4D85h` ＝ `'は恐怖にかられ、逃げ出した。'`、
`CS:4DA2h` ＝ `'は影響を受けなかった。'`。

```pascal
x := <overlay-32 entry#15>(遠指標(DS:9594h));
y := <overlay-32 entry#16>(遠指標(DS:9594h));
<本模組 19B4h>(6, 3, DS:0A646h, DS:0A645h, y, x);

for i := 1 to DS:0A520h do begin                       { 無號 }
    目標 := 遠指標[0A51Dh ＋ i×4];
    r := <overlay-23 entry#8>(目標, 4, 0);              { ★ 豁免類別 4 }
    if r = 0 then begin                                 { 沒擋下來 }
        <overlay-23 entry#21>(目標, r, 1, 1, 0,
                              <本模組 0E75h>(目標, 54h, 8Eh),
                              名字 ＋ 'は恐怖にかられ、逃げ出した。');
        目標^[18Eh]^[10h] := 1;
        目標^[199h]       := 1;
        if 目標^[0F7h] <= 7Fh then 目標^[0F7h] := 0B3h;  { 士氣重設 }
        目標^[18Eh]^[0Ah] := NIL;                        { 清掉目標欄 }
    end
    else
        <overlay-24 entry#20>(目標, 名字 ＋ 'は影響を受けなかった。', 1, 0Ah);
end;
```

`+0F7h` 那一段與 spec 831／836 的士氣處理是同一套（`> 7Fh` 才重設成 `0B3h`）。
`+18Eh^[10h]` ＝ 1 與 spec 834 的 `+18Dh^[11h]`（DOS）同屬戰鬥狀態旗標區。

⚠ `scripts/aligned_diff.py` 在這一支報出一段**明顯是反組譯錯位的「本邊」區塊**
（`or al, 89h` / `in ax, dx` / `retf 0CD82h`）。那是 `module_align` 用的匯出
（未補洞版）造成的，`scripts/annotated_dump.py` 用的補洞版（spec 761）
沒有這個問題，整支 91 條讀得下來。**兩套匯出不一致時以補洞版為準。**

## ★ 豁免類別表補到四格

| 類別碼 | 用途 | 出處 |
|---|---|---|
| `0` | 死亡光線 | spec 842 |
| `1` | 石化光線、麻痺凝視 | spec 842、spec 981 |
| `3` | 分解光線、龍息、吐酸 | spec 842、spec 720／723、spec 981 |
| **`4`** | **恐懼** | **本規格** |

AD&D 1e 的五欄順序是
**麻痺／毒／死亡魔法、石化／變形、法杖／魔杖、吐息武器、法術**。
把觀察到的四格代進去：

- `0` → 死亡魔法 ✔
- `1` → 石化／變形 ✔（石化光線）
- `3` → 吐息武器 ✔（龍息、吐酸）
- `4` → 法術 ✔（AD&D 的 Fear 正是 save vs. spell）

**四格中有三格與 AD&D 完全對得上**，所以類別碼就是 AD&D 的五欄順序。
spec 842「沒有宣稱豁免類別碼對應 AD&D 哪一欄」可以收窄成：
**順序已確定，但引擎有兩處自己的歸類**——

⚠ **麻痺凝視用 `1` 而不是 `0`**（AD&D 的麻痺屬第一欄），
⚠ **分解光線用 `3` 而不是 `4`**（AD&D 的 disintegrate 是 save vs. spell）。

這兩處是引擎的設計選擇，不是判讀錯誤：兩平台都一樣。
remake 照抄即可，但不能用「查 AD&D 表」的方式重新推導。

## 中文化

三支的字串都是 **名字 ＋ 一句話** 的串接，中文語序相同（「◯◯◯陷入恐懼逃走了。」
「◯◯◯沒有受到影響。」），**這一類可以直接換字串，不必動接法**——
與 spec 984 的 `'Drop ' ＋ 名字 ＋ ' forever? '`（要對調）不同。

## 明確不宣稱

- 沒有宣稱 `本模組 0E75h(目標, 54h, 8Eh)` 算什麼（`54h` ＝ 84 與 spec 842 的
  Fear 法術編號同值，但本規格不宣稱兩者相關）。
- 沒有宣稱 `overlay-23 entry#21` 的十個參數。
- 沒有宣稱 `+199h` 是什麼。
- 沒有宣稱類別碼 `2`（AD&D 的法杖／魔杖欄）在哪裡使用。
