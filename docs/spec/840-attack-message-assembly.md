# 840 — 攻擊訊息的組句：PC-98 不是換字串，是改寫句型

- 證據等級：`exact`（兩平台各自逐條讀完；集合常數由原始 bytes 解出）
- 作法見 spec 783

## `overlay-13:0031Dh`（DOS，334 條）↔ `overlay-13:00358h`（PC-98，326 條）

助憶碼相似度只有 **0.597**——這一支**兩平台真的不同**，要各自判讀。

`retf 10h` ＝ 8 個 word。依宣告順序：
`(攻擊者, 被攻擊者, 類型, 扣血, 傷害顯示值, 命中)`。

| 參數 | 用途 |
|---|---|
| 攻擊者 | 遠指標，只拿來配第一句 |
| 被攻擊者 | 遠指標，後續全部的處置對象 |
| 類型 | `1` ＝ 背後、`2` ＝ backstab、`3` ＝ 秒殺無力者、其他 ＝ 一般 |
| 扣血 | `> 0` 時打斷詠唱；另外傳給 `far 157Bh+1`（DOS）／`154Ah+2`（PC-98） |
| 傷害顯示值 | 印在句子裡的數字 |
| 命中 | `0` ＝ 沒打中 |

## 兩份句型並排

| 欄位 | DOS | PC-98 |
|---|---|---|
| 開頭・backstab | `'-Backstabs-'` | `'はバックスタッブを行ない、　'` |
| 開頭・秒殺 | `'slays helpless'` | `'は無力な'` |
| 開頭・一般 | `'Attacks'` | `'は攻撃し、'` |
| 背後 | `'(from behind) '` | `'の背後'`（**前置**於下一格） |
| 助詞 | 無 | `'に'`（**一律加**） |
| 秒殺補語 | `'with one cruel blow'` | `'無慈悲な一撃を加えた。'` |
| 命中 | `'Hitting for '` ＋ n ＋ `' point '`／`' points '` ＋ `'of damage'` | `'命中して'` ＋ n ＋ `'ポイントのダメージを与えた。'` |
| 零傷害 | **沒有這一支** | `'はダメージを受けなかった。'` |
| 落空 | `'and Misses'` | `'にかわされた。'` |
| 打斷詠唱 | `'lost a spell'` | `'は呪文を無駄にした。'` |
| 倒下 | `'goes down'` | `'は倒れた。'` |
| 瀕死 | `'and is Dying'` | `'瀕死の状態だ。'` |
| 死亡 | `'is killed'` | `'そして、死んだ。'` |

## PC-98 的四處句型改寫

### 一、助詞是無條件插入的

DOS 在**不是背後攻擊**時把工作字串**清成空字串**（`mov [bp+var_52], 0`），
PC-98 改成一律先填 `'に'`；背後攻擊時再把 `'の背後'` **接在前面**
（先把 `'の背後'` 寫進另一個緩衝再把工作字串接上去，然後整個搬回來）。

DOS 是「可選前綴 ＋ 後續」，PC-98 是「可選前綴 ＋ 固定助詞 ＋ 後續」。
**同一格插槽，語法角色不同。**

### 二、多出一個「零傷害」分支

PC-98 在**命中**之後多一道 `if 傷害顯示值 = 0 then` → `'はダメージを受けなかった。'`。
DOS 沒有這一支，會照樣印 `Hitting for 0 points of damage`。

**這是行為差異不是翻譯差異**，remake 必須挑一邊（或兩邊都做，用語言旗標切）。

### 三、單複數分支被拿掉

DOS 有 `if 傷害顯示值 = 1 then ' point ' else ' points '`。
PC-98 沒有這個判斷，只有 `'ポイントのダメージを与えた。'`——日文沒有複數變化。

**中文化要照 PC-98 的形狀**：中文同樣不需要單複數，那個分支可以整段刪掉。

### 四、死亡那一句的呈現方式不同

- DOS：`<far 1552h+2>(被攻擊者, 名字 ＋ 'is killed', 行, 0)`——**帶名字的訊息**。
- PC-98：直接把 `'そして、死んだ。'` 送去 `418h:0D17h` 顯示——**不帶名字的獨立一行**，
  跟它處理 `'瀕死の状態だ。'` 的方式一樣。

## 死亡判定是一個 Pascal 集合 `[6, 7, 8]`

```
mov al, es:[di+195h]      { PC-98 是 +196h }
push ax
mov di, offset <集合>
call far ptr 0A54h:8D4h   { PC-98 0A65h:8E4h ＝ 集合成員測試 }
jz  短路
```

集合常數是 32 bytes，兩平台都是 `C0 01 00 …`，解出來是 **{6, 7, 8}**。
對照 spec 834 累積的狀態表：`6` ＝ 死亡、`7` ＝ 石化、`8` ＝ 被摧毀。
**三種都算「is killed」**。

`+195h` ＝ `8` 時還有另一個作用：組完句之後那道 `if 被攻擊者^[195h] <> 8 then 顯示`
會**整段跳過畫面輸出**——被 Turn Undead 摧毀的目標不印攻擊結果。

## 打斷詠唱

```pascal
if 扣血 > 0 then begin                       { 無號 }
    被攻擊者^[18Dh]^[01h] := 0;               { 本回合不能再施法（spec 836） }
    if 被攻擊者^[18Dh]^[00h] > 0 then begin   { 正在詠唱（spec 827） }
        顯示(名字 ＋ 'lost a spell');
        <far 153Fh+1>(被攻擊者, 被攻擊者^[18Dh]^[00h]);
        被攻擊者^[18Dh]^[00h] := 0;
    end;
end;
```

這是 spec 830 那個「DOS 不清 `+00h`、PC-98 會清」的另一面：**受傷打斷詠唱時，
兩平台都會清**。830 記到的差異只發生在**正常結算完**那條路徑上。

`+18Dh^[01h] := 0` 也印證了 spec 836 對這一格的定名。

## 行號是累加出來的

`行 := 0Ch`，印一行 `inc(行)`；中段重設成 `DS:65A1h + 1`（PC-98 `DS:9637h`），
之後每印一句 `行 := 行 + 2`。中文化換行寬度改變時，**這幾個 `+2` 要一起改**，
否則後面的句子會疊到前一句上。

## 明確不宣稱

- 沒有宣稱 `far 157Bh+1`（DOS）／`154Ah+2`（PC-98）做什麼（形狀上是扣血）。
- 沒有宣稱 `far 153Fh+1(被攻擊者, 法術)` 做什麼（形狀上是把記憶中的法術還回去或丟掉）。
- 沒有宣稱 `far 1476h` / `1442h+2(被攻擊者, 0Dh)` / `1944h` 各做什麼。
- 沒有宣稱 `DS:65A1h`（PC-98 `DS:9637h`）裝什麼，只知道它 ＋1 之後當行號用。
- 沒有宣稱 `542h:4A4h`（PC-98 `418h:0E6Ah`）那八個參數的意義。
