# 882 — 載入 8×8 圖磚組：`8x8d<n>.dax`，PC-98 自己算平面大小

- 證據等級：`exact`（兩平台各自逐條讀完）
- 作法見 spec 783

## `overlay-35:00047h`（DOS 112 條）↔ `overlay-35:0004Ch`（PC-98 285 條）

`retf 4` ＝ 兩個 byte：`(組, 編號)`。字串：
`'8x8d'`、`'.dax'`（PC-98 才單獨出現）、`'Unable to load '`、`' from 8x8D'`。

### DOS

```pascal
if not <0A54h:08D4h>(合法組表, 組) then 離開;
Str(DS:5BEEh, 寬度 1, var 磁碟);                  { 磁碟編號 }
Str(編號,     寬度 3, var 編號字);
檔名 := '8x8d' ＋ 磁碟;

<far 0297h:011Bh>(@DS:(65B6h ＋ 組 * 4), 0Dh, 1, 編號);

if 遠指標(DS:65B6h ＋ 組 * 4) = NIL then begin
    <far 0297h:0107h>();
    <0A54h:173Bh>(0, 'Unable to load ', @DS:8DB2h);
    <0A54h:17D1h>(0, 編號);                        { 把編號接上去 }
    暫 := ' from 8x8D' ＋ 磁碟;
    <0A54h:173Bh>(0);   <0A54h:1673h>();
    <far 06EAh:010Dh>();  <far 0297h:0107h>();  <far 06EAh:0000h>();
end;
<far 06EAh:024Ch>();
```

錯誤訊息組成 `'Unable to load ' ＋ 編號 ＋ ' from 8x8D'`——
**`8x8D` 就是資料檔名，`8x8d<磁碟編號>.dax`**。

圖庫表 `DS:65B6h ＋ 組 × 4` 是一張遠指標陣列，每組一個指標。

### PC-98：不用載入器的配置，自己填表頭

PC-98 那 285 條裡多出來的是一整段自己處理圖形記憶體的流程：

```pascal
if 遠指標(DS:65B6h ＋ 組*4) <> NIL then begin
    FillChar(圖^[17h],           0D20h, 0);        { 3360 bytes }
    FillChar(遠指標(圖^[13h])^,  0460h, 0);        { 1120 bytes }

    <far 0723h:0824h>(var 檔案, var 大小, 編號);
    if 大小 <> 0 then begin
        Move(圖^[0], 檔案^[2], 2);                 { 逐欄抄表頭 }
        Move(圖^[2], 檔案^[0], 2);
        Move(圖^[4], 檔案^[4], 2);
        Move(圖^[6], 檔案^[6], 2);
        Move(圖^[8], 檔案^[8], 1);
        if 圖^[8] < 1 then 圖^[8] := 1;            { 無號 }
        圖^[11h] := 圖^[0] * 圖^[2] * 3;           { 寬 × 高 × 3 }
        <far 02A8h:03BDh>(圖, 0Dh, 1, 9, 檔案);
        out 0A6h, 0;
    end;
end;
```

## 三個平面，一個遮罩

`0D20h` ＝ 3360 ＝ **3 × 1120**，而 `0460h` ＝ 1120。
配上 `圖^[11h] := 寬 × 高 × 3`，整組關係就出來了：

| 位移 | 內容 | 大小 |
|---|---|---|
| `+17h` 起 | **三個色彩平面** | 寬 × 高 × 3 |
| `+13h` 指出去 | **一個遮罩平面** | 寬 × 高 |
| `+11h` | 三個平面合起來的位元組數 | — |

這解釋了 **spec 880 的那個平台差異**：那邊 PC-98 的第二次 `Move` 用
`p^[0] × p^[2]`（寬 × 高）而 DOS 用 `p^[11h]`——因為 PC-98 的
`+11h` 是三倍大小、遮罩只有一倍。**兩支互相印證。**

⚠ 抄表頭時 `圖^[0] ← 檔案^[2]`、`圖^[2] ← 檔案^[0]`——**前兩欄是對調的**。
所以檔案裡的欄位順序與記憶體裡的相反，兩平台的資料檔不能直接互換。

## 中文化

`'8x8d'`／`'.dax'` 是檔名，不能翻。
`'Unable to load '` 與 `' from 8x8D'` 是開發期錯誤訊息，
PC-98 原樣保留沒翻，中文版照樣保留即可。

## 明確不宣稱

- 沒有宣稱 `far 0297h:011Bh`／`0723h:0824h`／`02A8h:03BDh` 的完整簽章。
- 沒有宣稱表頭 `+4`／`+6`／`+8` 各是什麼（`+8` 有「小於 1 就設 1」的下限）。
- 沒有宣稱 `out 0A6h, 0` 寫的是什麼（同 spec 878 的收尾）。
- 沒有宣稱 DOS 版的 `0297h:011Bh` 內部有沒有做 PC-98 這一段等價的事。
