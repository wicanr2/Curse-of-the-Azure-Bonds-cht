# 第六百八十九輪：DOS 隊伍名單的繪製（`overlay-24`）

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：DOS `overlay-24` 的 `0795h`（entry#2）。

`0939h`（AC 欄）與 `09C1h`（HP 欄）**先前已在 spec 684 讀完**，本輪重讀只是為了
確認補位表的算法，下面兩節是引用不是新判讀。

## `0795h`：走過角色鏈，一列一個人

```text
if DS:4FBAh = 3 then 直接返回                     ← 這個模式什麼都不畫
x := (DS:4FBAh = 0) ? 1 : 11h                     ← 兩種起始欄位
y := 2
寫 'Name'  於 (x, y)     ← CS:0789h
寫 'AC  HP' 於 (21h, y)  ← CS:078Eh
y := y + 2
p := DS:650Ah 那個 far 指標
while p <> NIL do
    <resident 01A0:04CDh>(x, y, 26h, y)           ← 先清這一列
    if p = arg（傳進來的 far 指標）then
        <resident 0542:0352h>(x, y, 0Fh, 0, p^)   ← 選中者用 0Fh 直接畫
    else
        <0939h 之外的 18F3h>(p, x, y, 0)
    <0939h>(p, 20h + acPad, y)                    ← AC 欄
    <09C1h>(p, 24h + hpPad, y, 0)                 ← HP 欄
    y := y + 1
    p := p^[189h]                                 ← 下一個角色
<resident 01A0:04CDh>(x, y, 26h, y)
retf 4                                            ← 參數是一個 far 指標
```

`p^[189h]` 是鏈結指標，走訪終止用**兩個 word 同時為零**判斷。

## 兩組範圍分桶其實是右對齊補位

`0795h` 裡有兩段看起來像分類的比較鏈：

```text
v := p^[19Ah]                    v := p^[1A4h]
if 0  <= v <= 32h then k := 1    if 0  <= v <= 9   then k := 2
if 33h <= v <= 3Ch then k := 2   if 0Ah<= v <= 63h then k := 1
if 3Dh <= v <= 45h then k := 1   否則                k := 0
否則                k := 0
欄位 := 20h + k                  欄位 := 24h + k
```

`+1A4h` 是目前 HP、`+19Ah` 是 AC 且**顯示值 = 60 − 儲存值**（負號由
`儲存值 > 3Ch` 單獨判斷），兩者都是先前已定案的欄位。把兩個公式代進去：

| `+19Ah` 儲存值 | 顯示 | 字元數 | `k` |
|---|---|---|---|
| `0..32h` | 60..10 | 2 | 1 |
| `33h..3Ch` | 9..0 | 1 | 2 |
| `3Dh..45h` | −1..−9 | 2 | 1 |
| 其他 | −10 以下 | 3 | 0 |

| `+1A4h` | 字元數 | `k` |
|---|---|---|
| `0..9` | 1 | 2 |
| `0Ah..63h` | 2 | 1 |
| `>= 64h` | 3 | 0 |

**兩張表都是「3 − 字元數」**。所以這不是狀態分類，是把數字右對齊在寬度 3 的
欄位裡；`20h` 與 `24h` 是兩欄的左界。表頭字串 `'AC  HP'` 的兩個空白正好對上這
個寬度。

拿分桶邊界去推「50 以下是某種狀態」會整段推錯——邊界是**位數的邊界**，不是
語意的邊界。

## `0939h`：AC 欄

```text
s := Str(|p^[19Ah] − 3Ch|)                        ← 先取絕對值
if p^[19Ah] > 3Ch then s := '-' + s               ← 負號另外接（CS:0937h = '-'）
<resident 0542:0352h>(arg_0, arg_2, 0Ah, 0, s)
retf 8
```

絕對值與正負號是**兩次獨立判斷**：先 `sub` ＋ `neg` 取絕對值，再用一次
`cmp ... 3Ch` 決定要不要接負號。只看 `neg` 會以為在算有號差。

## `09C1h`：HP 欄

```text
if p^[1A4h] < p^[78h] then c := 0Eh else c := 0Ah   ← 未滿血 / 滿血
if arg_0 <> 0        then c := 0Dh                  ← 旗標覆蓋前面兩者
<resident 0542:0352h>(arg_4, arg_2, c, 0, Str(p^[1A4h]))
retf 0Ah
```

`+78h` 是 HP 上限（先前已定案）。

PC-98 的同一支是 `overlay-24:0BD5h`（spec 643），結構相同但**未滿血的顏色是
`6` 不是 `0Eh`**，而且字串後面多接一個空白。顏色常數不能跨平台照抄。

## 明確不宣稱

- `18F3h`（非選中者的名字繪製）、`10CB h`（數字轉字串）內部行為。
- `resident 0542:0352h` 前兩個參數的確切語意（依用法像是欄、列）。
- `DS:4FBAh` 的三種值（0／3／其他）各代表哪個畫面。
- `DS:650Ah` 指向的鏈由誰建立。
