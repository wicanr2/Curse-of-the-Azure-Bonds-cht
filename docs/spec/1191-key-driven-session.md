# 1191 — 按鍵驅動的一場：把輸入那一層納入量測

狀態：`READY`（接縫、守門測試、量測報表都已實作）

## 問題

`TestRealNewGameRunsToTheEnding` 從角色建立打到提朗瑟克斯，spec 1188 又讓真的
前端把那條路線的每個檢查點畫了一張。剩下的缺口是**中間那一層**：戰役測試直接
呼叫 `state.X()`，玩家按的是鍵盤。

前端的 `Update()` 在整條戰役裡**一次都沒有被跑到**。所以「這段劇情按得出來嗎」
在報表上一直是空的——`cmd/player-path-audit` 只能靜態證明「前端**沒有**那條路」
（硬缺口），證不出「有那條路所以玩得到」，方向是不對稱的。

## 接縫

前端原本 152 處直接呼叫 `inpututil.IsKeyJustPressed`／`ebiten.IsKeyPressed`。
全部改走 `keySource` 介面：

```go
type keySource interface {
	JustPressed(key ebiten.Key) bool   // 這一幀剛按下
	Pressed(key ebiten.Key) bool       // 現在按著（修飾鍵）
}
```

`a.keys` 是 nil 就退回真的 ebiten，正式執行路徑不變；測試換成腳本化的來源。

⚠ `JustPressed` 的語意是「**這一幀**剛按下」：同一幀問第二次仍要回 true（前端
同一幀會為不同分支各問一次），下一幀才變 false。讀完就清會讓後面的分支看不到
那一顆鍵。

⚠ **新的直接呼叫會被 `TestFrontendReadsKeysOnlyThroughTheSeam` 擋下來。**
繞過接縫的那一行在按鍵驅動的測試裡永遠不會觸發，而且測試會照樣綠——它根本
走不到那裡。沉默的漏洞比紅燈貴。

## 這一場走到哪

`TestKeysDriveARealSessionFromTheTitle` 從標題畫面開始，**只按鍵**：

| 步驟 | 按鍵 | 結果 |
|---|---|---|
| 標題 → 角色建立 | `Enter` | 模式換成角色建立 |
| 建六名隊員 | `Enter` × 6 | `CreationRoster` ＝ 6 |
| 完成建立 | `D` | 離開角色建立 |
| 開場劇情 | `Enter` | 醒來、枷印、旅店老闆娘、手札第 31 條 |
| 走動 | `M` 轉向、`↑` 前進 | 28 格、走進場所 |

沿路每一句話都套與戰役同一條語系不變量：有漢字就算翻好了，沒有漢字卻有連續
兩個以上英文字母就是**落回原文**，測試紅。目前 0 句。

## 走不遠的原因（已定位，不是未知）

挑方向要**兩輪**：先找「走得通而且沒去過」，找不到才退回「走得通」就好。只有
第一輪的話，走到只剩一條回頭路的死巷會**原地轉圈**——那條路走得通，但因為
去過所以被拒絕。

第二個坑是**門在 `CanMoveDungeon` 眼裡是牆**。只挑「走得通」的方向，隊伍永遠
不會去碰門——而玩家的做法是**撞上去**：`moveDungeonPreview` 發現擋住的是門
（flags 2／3）就開選單。把「沒有新格子可走時朝四個方向各撞一次」補進去之後
7 格 → **19 格**、6 句 → **15 句**。

⚠ 「撞門」不能掛在「四面都是牆」底下：`chooseHeading` 只要有任何一個方向走得通
就會給出退路，那個條件等於永遠不成立，門一次都不會被碰到。要掛在**沒有
「沒去過」的格子可走**時。

停在 28 格。**卡住的原因已經查明，不是選項**：整場沒有出現任何真的選單
（只有「按任意鍵繼續」），也一次都沒撞到門。所以不是「選錯了選項」而是幾何上
到不了——同一段用幾何走訪找得到 83 格（spec 1189）。這兩種成因的處置完全不同，
分不出來就會往錯的方向修。

## 這個數字證明不了什麼

- **不是**「按鍵玩到結局」。它是**開場**那一段。
- 走過 28 格是這一場的實測，不是「只有 28 格走得到」——同一段用幾何走訪找得到
  83 格（spec 1189）。幾何走訪不觸發 ECL，按鍵這一場會，差額是 ECL 的閘。
- 落回原文 0 句只涵蓋這一場演出來的 37 句。

## 從開場擴到整條主線：114 份快照

開場那條證明的是遊戲開得起來、前幾段按得動。主線後面那些段——猶拉什地下、
散提爾堡、眼魔洞穴、密斯卓諾——前端的 `Update()` 從來沒有在那些狀態下被跑過。

主線在各段落存下來的快照就是那些狀態。`TestKeysDriveEveryCampaignSnapshot` 把
每一份**讀進真的 app**，用按鍵推 60 幀，確認推得動、走得動、演出來的字沒有落回原文。

**114／114 推得動，落回原文 0。**

⚠ 這**不是**「按鍵從頭玩到結局」：每一份是各自載入的，不是一條連續的 session。
它證明的是**那些狀態下輸入層是活的**，不是「一路按過去到得了」。

### 它找到的缺陷：讀完存檔沒有通知前端換地圖

第一次跑：**114 份裡有 104 份按什麼都沒反應**。

成因是 `LoadPartyFile` 設了 `GeoMapSet`／`GeoMapBlock`，卻沒有設 `geoMapPending`
——而前端的 `geoGrid` 只有在收到 `ConsumeGeoMapRequest` 時才會換。`geoMapPending`
原本只有 ECL 的 LOAD FILES 那條路會設。

後果：讀檔之後前端拿的還是**上一段的地圖**，牆、門、能不能走全部對不上，
**而且不會有任何錯誤訊息**。前端一開始沒有地圖時更直接——`moveDungeonPreview`
看到 `geoGrid == nil` 就 return，**按什麼都沒反應**。

⚠ 兩個把「沒反應」判錯的陷阱：
- **簽章要帶朝向**：地城裡面對牆時按 `M` 只轉身，座標與訊息都不變，少了朝向會把
  「轉身」判成「沒有反應」——而那是地城裡最常見的一步。
- **測試自己少載資料也會像輸入層壞掉**：沒載 `ITEM*.DAX` 時 `TREASURE` 直接回錯
  （`item block 0x05 for area 2 is not loaded`），看起來像按不動。

### 順帶接上的字

巫師塔光球決鬥那幾句本來落回原文。距離那一頁（`0x1642`）**只有數字是變數**，
所以逐個數字寫規則就接上了（10..70 呎）——又是「列舉不到的東西，用走的走得到」。

⚠ 另一頁（`0x147B`）印的是**玩家自己取的隊員名字**，固定譯文會把名字吃掉，
所以規則層**故意不接**，放進一份故意很短、不會自動長大的豁免清單。

## 這一場的兩個走法教訓

**邊界要記（格子, 進入方向）。** 只記格子的話，第一次從錯的方向踏上樓梯格就把
那一格封死（spec 1193）。改掉之後 19 格 → **28 格**、15 句 → **23 句**，
而且第一次走進了**場所**（城裡的店家）。

**選單一律按第一項。** 試過依幀數輪流選：走過的格子從 28 掉到 27、記到的話從 23
掉到 16——輪到「離開」那一項就真的離開了，整條路被自己切斷。

⚠ 冷走那邊多策略有效，是因為它**每一種策略各跑一趟再取聯集**；這裡是**一條連續
的 session**，換選項不是多一條路，是**換**一條路。同一個技巧在兩種量測上的效果
相反——不要因為在一邊管用就搬到另一邊。

⚠ 600 幀就到頂：跑到 3000 幀還是 28 格。加幀數不會再多。

## 卡住才換選項：23 句 → 36 句

「永遠按第一項」會**卡在同一個選單上**：世界地圖的「進入城市｜繼續旅程｜紮營」
永遠選第一項，隊伍就再也離不開開場那一座城。

折衷是**卡住才換**：同一個選單看到第 6 次還在原地，就往下挪一項。預設仍然是第一項，
所以不會像輪流選那樣自己切斷路線。⇒ 記到的話 **23 → 37 句**。

⚠ 走過的格子仍是 28、走到過的 ECL 段仍只有 `0x01`。**要真的離開開場那一段，
還是得把戰役測試那份路線知識搬過來**——卡住才換只是讓同一段裡多演一些內容。

### 它找到的第二個缺陷：游標沒有夾範圍

`choiceCursor` 是前端自己的狀態，而選項是 ECL 換頁時整批換掉的。商店選單有五十幾項，
挪到第 8 項之後換到只有三項的荒野選單，游標還是 8——按下去 `Select` 直接回
`choice 8 is invalid in mode 1`，**玩家看到的是一行錯誤訊息**。

原本的重設只發生在幾條特定路徑上（選完一項、載入存檔），涵蓋不了所有換頁。
現在 `Update()` 每一幀先 `clampChoiceCursor()`。

### 卡住偵測的簽章只看選項，不看訊息

商店每按一項就換一句回應（「目前沒有可提取的隊伍金幣。」…）。把訊息放進簽章的話
計數永遠歸零，**卡住偵測等於沒有**——而商店的「離開商店」是最後一項，於是整場
session 困在店裡。

### 已經確認**不是**限制的東西

| 調了什麼 | 結果 |
|---|---|
| 幀數 600 → 4000 | 28 格／37 句，不變 |
| 卡住門檻 6 → 3 → 2 | 28 格／37 句，不變 |
| 選單改成輪流選 | **變差**（28 → 27 格、37 → 16 句）|

⇒ **限制不在走法也不在選單策略上。** 要離開開場那一段（ECL `0x01`），缺的是
**路線知識**——戰役測試裡逐段寫死的那一份。再調這些參數不會有任何改變。

## 路線知識：錄下來，不要手抄

按鍵那一場停在 28 格／37 句／只到 ECL `0x01`，而**限制不在走法也不在選單策略上**
（幀數、卡住門檻都試到不動了）。缺的是**路線知識**——戰役測試裡逐段寫死的劇情
決策與移動。

那份知識散在三千多行裡，手抄只會抄錯。與其抄，不如**錄**：

- `State.Select` 是所有玩家層級**選擇**的唯一入口
- `State.MoveDungeon` 是地城裡**移動**的唯一入口

主線跑一次（`COAB_DECISION_LOG`）就錄下 **1607 步：783 個選擇 ＋ 824 次移動**。
重放端（`COAB_ROUTE_JSON`）用**按鍵**把游標挪到那一項、把身體轉到那個方向。

⚠ 錄的是**選項文字**與**起點座標＋方向**，不是索引與終點：索引會隨選單內容錯位，
而樓梯事件是「站對方向踏上去」才觸發的（spec 1193）。

### 只錄選單是不夠的

第一版只錄 `Select`。結果 783 步只用得到 13 步——**主線的決策點要走到那裡才會出現**，
而「走到哪裡」本身就是路線知識的一半。補上移動之後：

| | 沒有路線 | 只有選單 | 選單＋移動 |
|---|---:|---:|---:|
| 走過的格子 | 28 | 28 | **76** |
| 記到的話 | 37 | 37 | **63** |
| 走到的 ECL 段 | 1 | 1 | **2** |
| 照路線按 | — | 13 | **104**／1607 |

### `routeLookahead` 是量出來的

主線與這一場走的路不會完全一樣，所以要**往前找一段**。這個窗口大小兩邊都不是
線性的：

	2  → 28 格／37 句／照路線 0 次（完全跟不上）
	4  → 16 格／14 句／2 次
	8  → **76 格／63 句／104 次，第一次走出 `0x01` 到 `0x02`**
	12 → 72 格／57 句／103 次
	24 → 41 格／37 句／41 次
	100→ 48 格／20 句／62 次

⇒ 8 是實測出來的。改動走法之後要重新量。

⚠ 仍**不是**「按鍵玩到結局」：123／1607 步之後就跟丟了。

## 跟丟之後怎麼重新對齊

主線與這一場走的路不會完全一樣，往前找的視窗一過就對不上。視窗裡找不到時，
拿「**現在在哪一段的哪一格**」去整條路線裡找同樣的起點。

⚠ **一定要帶段號**：不同段的地圖上都有 (7,13)，只比座標會對齊到完全不相干的地方，
然後照著那裡的方向亂走。所以 `move` 紀錄要連 ECL 段一起錄。

三種寫法實測差很多（1500 幀）：

| 寫法 | 格子 | 話 | 照路線 |
|---|---:|---:|---:|
| 不對齊 | 76 | **63** | 104 |
| 對齊＋把指標跳過去 | 41 | 18 | 34 |
| 對齊＋指標不動 | 57 | 47 | 759 |
| 對齊＋用過就記 | **82** | 57 | **123** |

- **把指標跳過去**會把中間還沒用到的步驟整批丟掉。
- **指標不動**會在同一格一直對齊到同一步，於是一直按同一個方向——原地震盪
  （照路線 759 次卻只走 57 格）。
- **用過就記**兩個問題都避開了。

⚠ 代價是話少了 6 句（63 → 57）。**兩邊都不是免費的**，換走法要重新量。
