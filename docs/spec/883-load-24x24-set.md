# 883 — `Load24x24Set`：DOS 的範圍檢查漏了筆數，PC-98 修掉了

- 證據等級：`exact`（兩平台各自逐條讀完）
- 作法見 spec 783

## `overlay-33:0002Eh`（DOS 75 條）↔ `overlay-33:0004Ch`（PC-98 206 條）

`retf 0Ah` ＝ 5 個 word。依推入順序宣告：
`(檔名, 資源編號, 目的起始, 筆數)`——`arg_6` 是遠指標，
`arg_4`／`arg_2`／`arg_0` 是 byte。

錯誤訊息 `'Start range error in Load24x24Set'` **直接給出原始函式名**。

### DOS

```pascal
緩衝 := 檔名^;                                     { 0A54h:064Eh，上限 0FFh }

if 目的起始 > 30h then begin                       { 無號，30h ＝ 48 }
    <far 0297h:0107h>();
    <0A54h:173Bh>(0, 'Start range error in Load24x24Set', @DS:8DB2h);
    <0A54h:1673h>();
    <far 06EAh:0000h>();                           { 收場 }
end;

圖 := NIL;
<far 0297h:011Bh>(var 圖, 0, 0, 資源編號, 緩衝);

搬多少 := 筆數     * 圖^[11h];
放哪裡 := 目的起始 * 圖^[11h];

if 遠指標(DS:65CEh) <> NIL then
    Move(圖^[17h], 遠指標(DS:65CEh)^[17h ＋ 放哪裡], 搬多少);

<far 0297h:1D19h>(@圖);
<far 06EAh:024Ch>();
```

## ⚠ DOS 的範圍檢查漏了筆數

| | 檢查的是 |
|---|---|
| DOS | `目的起始 > 30h`（**無號**） |
| PC-98 | `目的起始 ＋ 筆數 > 30h`（**有號**，`jle`） |

目標區能放 **48 張**。DOS 只擋「起始超過 48」，**不擋「起始 ＋ 筆數超過 48」**
——起始 40、筆數 20 在 DOS 會直接寫出界，而且訊息本身叫
`Start range error`，正好說明作者當初只想到起點。

**PC-98 把它改成檢查總和**，是真的修掉了這個洞（spec 783 第 d 類）。
remake 照 PC-98 的檢查。

⚠ 另外，兩平台的錯誤路徑都**不是 return**：印完訊息後直接呼叫收場常式
（DOS `06EAh:0000h`／PC-98 `07E3h:0077h`），而不是跳過後面的搬運。

## PC-98：三組常駐圖磚固定放在 `E000h` 段

PC-98 多出來的 131 條是一整套自己的記憶體安排：先拿檔名去比對四個字串，
再依結果決定來源。

| 檔名 | 種類 | 來源 |
|---|---|---|
| `'DungCom'` | 0 | `E000h:0000h` |
| `'WildCom'` | 1 | `E000h:2A50h` |
| `'RandCom'` | 2 | `E000h:63D0h` |
| `'tiles'` | 3 | 呼叫 `2A8h:0F5Dh(0, 筆數, 6, 18h)` 現配 |
| 其他 | — | **直接離開，什麼都不做** |

```pascal
if 種類 <= 2 then begin
    if 已載入[種類] = 0 then begin
        <far 02A8h:025Bh>(0, var 暫存, 0, 0, 資源編號, 緩衝);   { 讀檔 }
        out 0A6h, 1;
        <far 02A8h:0601h>(0, @目標, @暫存);
        已載入[種類] := 1;
    end else begin
        <far 02A8h:0F5Dh>(0, 筆數, 6, 18h, var 暫存);
        out 0A6h, 1;
        <far 02A8h:0601h>(0, @暫存, @目標);                     { 反向 }
    end;
end;
out 0A6h, 0;
... 與 DOS 相同的 Move ...
if 種類 = 3 then <far 02A8h:10D5h>(@目標);          { tiles 才釋放 }
<far 02A8h:10D5h>(@暫存);
```

`E000h` 是 PC-98 的擴充記憶體視窗。**三組常用圖磚（地城／野外／隨機）
各自固定一個位移，而且只從磁碟讀一次**，之後靠 `已載入[]` 旗標改走
「從那塊拷回來」的路徑。DOS 沒有這一層，每次都重讀。

`18h` ＝ 24 與 `6` 一起出現在配置呼叫裡，與函式名的 **24×24** 對得上。

## 中文化

四個檔名字串 `'DungCom'`／`'WildCom'`／`'RandCom'`／`'tiles'` 不能翻——
**PC-98 拿它們當 key 做字串比對**，改了就走進「什麼都不做」那條路。
`'Start range error in Load24x24Set'` 是開發期訊息，原樣保留。

## 明確不宣稱

- 沒有宣稱 `圖^[11h]` 在這裡是不是「一張圖的位元組數」
  （spec 882 讀到 PC-98 那一格是寬 × 高 × 3）。
- 沒有宣稱 `遠指標(DS:65CEh)` 那塊 48 張的緩衝由誰配置。
- 沒有宣稱 `E000h` 那三個位移的由來，也沒有宣稱三塊會不會互相覆蓋。
- 沒有宣稱 `out 0A6h` 的 1／0 各切換什麼。
