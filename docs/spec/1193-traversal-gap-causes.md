# 1193 — 走訪未達成的三種成因

狀態：`READY`（分類已實作，數字由 `cmd/cell-reachability` 產生）

## 問題

走訪可達性報表說：259 個分派索引，實跑與冷走的聯集是 204。剩下的 55 個只是
一個數字——看不出**要補路線、要補劇情旗標、還是根本補不了**。這三種的處置
完全不同，混在一起就不知道下一步該做什麼。

## 三種成因

判準用的是**純幾何**（`CanMoveDungeon`），不跑 ECL：走過去又被劇情推回來那種
不算「走不到」——那是內容不是幾何，混進來會讓分類失去意義。

| 成因 | 判準 | 要做什麼 |
|---|---|---|
| 站得上去，但從段入口走不到 | 那個地形碼出現在**某個連通分量**的格子上，但不在入口那一塊 | 補路線：從那一塊自己的入口格另外走一趟 |
| 圖上有，但四面都不通 | 地形碼只出現在**沒有任何可通行邊**的格子上 | 走路永遠站不上去；要嘛靠事件傳送，要嘛它本來就不是玩家會站的格子 |
| 圖上根本沒有這個地形碼 | 分派表有這一格，整張地圖掃過去沒有 | 分母裡的死索引，補不了也不用補 |

目前：**54 / 1 / 0**。

★ **死索引是 0，所以未達成全部都是真的待辦**，不是分母灌水。這一點本來只能猜。

## 走路的上限

「站得上去」的索引有 **258**（259 減掉那個四面不通的）。

★ **那才是走訪這條路的天花板，不是 250。** 把分派索引總數當目標，會讓永遠差的
那一格看起來像還有事情可做。目前的 204 是天花板的 79%。

## 為什麼「站得上去」要另外算

一張圖常常不是一整片。巫師塔每一層在 GEO 上是**獨立的小房間**，層與層之間只靠
樓梯**事件**接（spec 1161）——從入口用走的永遠到不了別層。所以：

- 「從段入口走得到」是**下界**：它看不到那些要靠事件才進得去的房間。
- 「站得上去」是**上限**：只問幾何，不問怎麼進去那一塊。

兩個都要，差額就是「要靠事件才進得去」的那些房間。

## 這個數字證明不了什麼

- 「站得上去」**不表示玩家到得了**：進到那一塊要靠事件，而事件要不要觸發是內容。
  它是上限不是預測。
- 分類完全不看 ECL，所以「站得上去但從入口走不到」裡混著兩種：幾何上斷開的，
  和**門擋著**的。要再分下去得看門的旗標。
- 分母仍然直接取自 `cell-sweep -index-json`，**這一支不重算**——兩邊各自算一定會
  漂（第一版自己算得到 299 而實測是 250，兩個數都自洽，放在一起就是假的覆蓋率）。

## 冷走要跑好幾種策略再取聯集

單一策略的結果**看起來都很合理**，但每一種都會被某一類岔路擋住：

| 策略 | 被什麼擋住 |
|---|---|
| 選單挑第一項 | **收費關卡**（下水道的奧提尤格要食物）——付不出去就進不去 |
| 選單挑最後一項 | 「要離開嗎」那種提示上直接走人 |
| 踏上去被事件搬走時**不從落點繼續** | 等於把「走上樓」記成「走到樓梯口」，靠樓梯才進得去的樓層永遠不會被走到 |

目前跑 8 種（選第 1／2／3／最後項 × 跟不跟傳送）取聯集。效果：

| 走法 | 冷走走得到的索引 | 聯集 |
|---|---:|---:|
| 只選第一項、不跟傳送 | 153 | 178 |
| ＋跟傳送 | 154 | 179 |
| ＋選最後一項 | 165 | 189 |
| ＋選第 2／3 項 | **179** | **193** |
| ＋選第 4 項 | 179 | 193（沒有變化，跑一趟多兩分半 ⇒ 收斂了） |

⚠ **跟傳送單獨看反而更差**：它讓 `ECL6/0x43` 的格子從 191 走到 235，但走訪順序
一變，某些 once-only 事件就在別的地方觸發，**索引反而少踩到兩個**。所以是取聯集
不是換一種——兩種互不涵蓋。

## 「門要劇情旗標」只解釋了其中 3 個

「站得上去，但從段入口走不到」這一類，直覺上的成因是**門要劇情旗標才開得了**：
冷走每一段都開一支新隊伍、沒有旗標，所以那些門對它永遠是牆。

`cmd/campaign-snapshot-walk` 直接驗了這個假設：拿主線在各段落存下來的 23 份快照
（就是一般的存檔格式，帶著那一刻的旗標），在那一段做同樣的多策略廣度優先走訪。

第一版用的是**段界**快照，23 份裡有 7 份讀回來停在荒野或地圖模式（`ECL4/0x22`
眼魔洞穴那一份就是）——那時的結論是「只有 3 個」，但**證據不夠**：走不了的那幾段
本來就沒被驗到。

於是讓主線在**第一次踏進每一段的地城時**也存一份（`captureInsideSegment`），
拿到 13 份**段內**快照，涵蓋 12 個有地形分派的 block **全部**。這一次每一份都
讀得回來也走得動（只有 `0x50` 世界地圖沒有地形分派，如實報出）。

結果：**只有 4 個索引是「非得帶旗標才走得到」的**。

⇒ 結論不變而且證據變強了：剩下的絕大部分**不是門的問題，是幾何**。那些房間要靠
樓梯／傳送事件才進得去，而那個事件要在**劇情的正確位置**才會觸發——不是「隊伍
有沒有旗標」的問題，是「隊伍當下在不在那個位置」。帶著旗標從段內任何一點開始走，
都走不進去。

⚠ 段內快照每一段只存**第一次**進地城的那一刻：存太多份會讓走訪時間乘上份數，
而同一段內旗標的差異對「走得到哪些格子」影響很小。

### 讀存檔取段號的陷阱

`Area.LastECLBlockID` 是存檔格式裡的欄位，但**遊戲跑的時候從來沒有人寫它**，
讀出來是 0——而 0 是一個**合法的 block 編號**，查下去會拿到完全不相干的地圖
而且不會報錯。段要跟 **ECL session** 拿（`State.CurrentECLBlockID`）。

## 邊界要記「(格子, 進入方向)」，不是只記格子

樓梯事件是**站對方向踏上去**才觸發的：`ECL5/0x33:090Ch` 用地形碼查表拿方向，
朝向不對就直接 `EXIT`——**畫面上什麼都不會發生**（spec 1161）。

三支走訪器原本都只用格子當 `seen` 的鍵。於是第一次從錯的方向踏上樓梯格，那一格
就被封死，另外三個方向永遠不會再試 ⇒ **靠樓梯才進得去的樓層永遠走不到**，
而報表只會顯示「那幾格走不到」，看不出是走法的問題。

改成邊界記 `(格子, 進入方向)`、「這一格去過沒有」另外記之後：

| | 修正前 | 修正後 |
|---|---:|---:|
| 巫師塔 `ECL5/0x33`（快照走訪）| 15 格／2 個地形碼 | **207 格／22 個地形碼** |
| 冷走走得到的索引（14 段合計）| 198 | **220** |
| 實跑踏到（250 的分母內）| 177 | **182** |

⚠ 聯集仍是 195：多出來的大部分落在 `0x33`／`0x25` 這些**不在分母裡**的段，
分母內多出來的那幾個又已經被另一把尺涵蓋。**修正是對的，但它不會讓聯集動** ——
這兩件事要分開講，否則下次會以為「走法沒問題，是內容不夠」。

## 分母本來漏了兩段，因為它們「冷進不去」

`cmd/cell-sweep` 是逐格實測，它每一段都**冷開一支隊伍**走進去。有些段的入口是
**一整段過場**——巫師塔是德拉坎德羅斯那一串、`ECL4/0x25` 是魔法商店那一段——
冷走完會停在**世界地圖**而不是地城，於是那些段整段被記成「進不去」，
**它們的格子從來不在分母裡**。

那些格子玩家真的走得到。所以 `cell-sweep` 加了一條路：冷進不去時改從
**主線的段內快照**進（`-snapshots`，`captureInsideSegment` 產生）。

⇒ 分母 **250 → 259**、聯集 **195 → 204**、覆蓋率 78% → 79%。

⚠ 從快照進的段，隊伍**帶著主線那一刻的旗標**，和其他段冷進的隊伍不是同一個起點。
報表在那一段標明，不要混在一起讀成「冷開就走得到」。

### 一個安靜的坑：`note` 是「這一段掃不了」

第一版把來源註記寫進 `blockSweep.note`。但 `note` 的語意是**這一段掃不了**——
渲染時看到它就整段跳過。結果一段**掃得好好的**段從報表裡消失，分母從 259 掉回
250，**而且沒有任何錯誤訊息**。註記要用自己的欄位（`fromSnapshot`）。
