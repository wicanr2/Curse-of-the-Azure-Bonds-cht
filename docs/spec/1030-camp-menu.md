# 1030 — 紮營選單：PC-98 的熱鍵表是整塊複製的，而且保留 DOS 的英文字母

- 證據等級：`exact`（DOS 側 251 條、PC-98 側 288 條，兩邊各自逐條讀完）
- 作法見 spec 783

## `dos overlay-04:00DD6h` ↔ `pc98 overlay-04:00F42h`

兩側原本都是待解讀。這是**營地（Camp）主選單**。

## 流程

```pascal
DS:4FBAh := 1;                                    { 畫面模式 ＝ 1 }
DS:8B54h := ord(遠指標(DS:4F99h)^[1CCh] = 0);
<overlay-24 entry#37>();                          { ⚠ PC-98 沒有這一次重繪 }
DS:8B54h := 1;
<overlay-24 entry#2>(DS:6506h);                   { 畫隊伍名單 }
FillChar(DS:6F70h, 1Ch, 0);                       { 公用池 7 個 longint 清 0 }
DS:7564h := 0;
repeat
    <overlay-21 entry#14>(@有錢, @有第八格);      { spec 773 }
    選項行 := 有錢 ? '…七個選項…' : '…五個選項…';
    鍵 := <overlay-26:003D4h>('', 選項行, 0Dh, 0Ah, 0Fh, 1, 0, @旗標);
    case 鍵 of
      'H': if 旗標 = 0 then <sub_B12>();          { Heal }
      'V': <overlay-19 entry#5>(@旗標);           { View，spec 1028 }
      'T': <overlay-21 entry#8>();                { Take }
      'P': if 旗標 = 0 then <overlay-21 entry#5>();   { Pool，spec 798 }
      'S': <overlay-21 entry#7>();                { Share，spec 858 }
      'A': <overlay-21 entry#19>(@有寶物);        { Appraise，spec 1018 }
      'E': …離開流程…
      'G'／'O': <overlay-19 entry#10>(鍵);        { 換目前角色，spec 794 }
    end;
    if 鍵 in ['B', 'T'] then <overlay-24 entry#37>();
    if (鍵 = 'A') and 有寶物 then <overlay-24 entry#37>();
    <overlay-24 entry#2>(DS:6506h);
until 離開;
```

★ `DS:6F70h` 的 `FillChar(…, 1Ch, 0)` ＝ **7 個 longint**，與 spec 798／858
的公用池同一組，這裡確認每次進營地都會歸零。

## ★★★ PC-98 的熱鍵表是從常駐資料段整塊 `Move` 進來的

DOS 靠**選項字串裡的大寫字母**當熱鍵（spec 1012／1013／1015／1022 同一套）。
PC-98 這裡不是一格一格寫，而是**一次搬 10 bytes**：

```pascal
{ 有寶物 }  Move(DS:055Ch, DS:0A335h, 10);
{ 沒寶物 }  Move(DS:0566h, DS:0A335h, 10);
```

兩塊常數的內容（`workplace/re-sweep/pc98/dseg/pc98-dseg-dseg.bin`）：

| 位址 | 位元組 | 讀作 |
|---|---|---|
| `DS:055Ch` | `48 56 54 50 53 41 20 20 20 45` | `H V T P S A _ _ _ E` |
| `DS:0566h` | `48 56 20 50 20 41 20 20 20 45` | `H V _ P _ A _ _ _ E` |

> ★★★ **PC-98 把選項文字全部換成日文，卻原封不動保留 DOS 的英文大寫熱鍵。**
> 這是既有結論（PC-98 用獨立熱鍵表）的**成因**：正因為熱鍵獨立於文字，
> 文字才可以整段換成雙位元組編碼。
>
> ★ 用不到的選項**不是被拿掉，是被換成空白**（`20h`）——
> 槽位索引固定（Heal 永遠 i ＝ 1、Exit 永遠 i ＝ 10），
> 空白 ＝ 不可選（spec 990）。

## ★★★ 一格選項 ＝ 「長度 byte ＋ 6 bytes 文字」

離開流程的 Yes／No 提示把兩塊常數搬進兩張表：

```pascal
Move(DS:057Ah, DS:0A33Fh, 46h);   { 70 ＝ 10 × 7，選項文字 }
Move(DS:0570h, DS:0A335h, 0Ah);   { 10，熱鍵 }
```

`DS:057Ah` 的 70 bytes 拆成 10 格，每格 7 bytes：

| 槽 | 位元組 | 讀作 |
|---|---|---|
| 1 | `06 20 82CD 82A2 20` | 長度 6，`' はい '` |
| 2..9 | `06 20 20 20 20 20 20` | 長度 6，六個空白 |
| 10 | `06 82A2 82A2 82A6` | 長度 6，`'いいえ'` |

> ★★★ **每一格 ＝ 1 個長度 byte ＋ 6 bytes 內容** ⇒
> **選項文字陣列 `DS:0A338h ＋ i × 7`（i ＝ 1..10）的一格就是
> 「Turbo Pascal 短字串，容量固定 6 bytes」**。
> spec 755／1012／1013／1022／1023／1028 記過的「6 bytes ＝ 3 個全形字」
> 到這裡從觀察升級成結構：**6 是宣告出來的容量，不是碰巧的長度。**
> spec 1032 看到 PC-98 逐格複製時傳的上限參數正是 `6`，再確認一次。
>
> ⚠ 長度 byte 是**實際長度**，不是固定 `06`：這一塊的空槽填「`06` ＋ 六個空白」，
> 但 spec 1031 的空槽填全形空白、spec 1032 的空槽直接填 `00`（空字串）。

對應的熱鍵塊 `DS:0570h` ＝ `59 20 …20 42` ＝ **槽 1 是 `Y`、槽 10 是 `B`**。

## ★★★ DOS 的第二套熱鍵標記法：波浪號

同一個 Yes／No，DOS 側的選項字串是

```
CS:0D52h  8  '~Yes ~No'
```

> ★★★ **`~` 標記熱鍵**——這是 DOS 側**第二套**熱鍵慣例，
> 與 spec 1012／1013／1015／1022／1023／1027／1028 那套「大寫字母」並存。
> ⚠ 中文化時兩套都要處理：波浪號這套不能只掃大寫字母就當作找齊了。

★ PC-98 的對應熱鍵是 **`Y` 與 `B`**，不是 `Y`／`N`——`No` 那一格換了字母。

## 離開流程

```pascal
<overlay-21 entry#14>(@有錢, @有第八格);
if not 有錢 then 離開 := true
else begin
    選項行 := '~Yes ~No';
    印一段(1, 11h, 26h, 16h, 0Ah, 0, 1, 'As you leave a priest says, "Excuse me but you have left some money here" ');
    印一段(1, 11h, 26h, 16h, 0Ah, 0, 1, 'Do you want to go back and retrieve your money?');
    回應 := <overlay-07 entry#20>('', 選項行, 0Dh, 0Ah, 0Fh, 0, 0);
    if 回應 = 1 then 離開 := true                  { ★ 見下 }
    else <far 0542:0B4Ah>(1, 11h, 26h, 16h);       { 收掉視窗，留在營地 }
end;
```

★ **`回應 = 1` 才真的離開**。對照訊息語意（Yes ＝ 回去拿錢 ＝ 留下），
可知這支提示回傳的是**從 0 起算的選項索引**：`0` ＝ 第一個（Yes）、`1` ＝ 第二個（No）。
中斷（回 0）與選 Yes 同路，都留在營地——**這是安全的預設**。

## ★★ Turbo Pascal 傳「暫存字串參數」的產碼慣例

被呼叫端 `dos overlay-26:003D4h` 是 `retf 16h`（22 bytes），
而呼叫端這一段看得到的推入只有 18 bytes。差的 4 bytes 來自更前面：

```asm
0E64  lea  di, [bp+var_31]   ; 目的
      push ss ; push di      ; ← 這 4 bytes 留在堆疊上
0E69  mov  di, offset ''     ; 來源
      push cs ; push di
0E6E  call far 0A54h:0634h   ; 只彈掉來源那 4 bytes
0E73  …接著推第二個字串與其餘參數…
0E8C  call far 167h:2Fh
```

> ★★ **`0A54:0634h` 把來源寫進先前推入的目的位址，只彈掉來源，
> 把目的指標留在堆疊上當外層呼叫的第一個參數。**
> 從被呼叫端的框架回推正好對齊：
> `bp+18h`／`bp+14h` 兩個遠指標（兩行選項）、`bp+12h`..`bp+0Ah` 五個 byte、
> `bp+06h` 一個遠指標（輸出旗標）＝ 22 bytes。
> 同一個慣例在 `overlay-07 entry#20`（DOS 9 word／PC-98 10 word）再出現一次。
>
> ⚠ **只看呼叫端數推入次數會少算 4 bytes**——參數表要從被呼叫端自己的框架回推。

★ 被呼叫端把兩個遠指標各自 `0A54:064Eh` 複製成上限 40 的字串 ⇒
**選單支援兩行選項**，營地這裡第一行固定給空字串。

## 兩平台差異

| | DOS | PC-98 |
|---|---|---|
| 選單函式 | `overlay-26:003D4h`（工具標 entry#3） | `overlay-26:00133h`（工具標 **entry#5**）⚠ |
| 選項行上限 | `28h` ＝ 40 | `50h` ＝ 80（＝ 一整列 80 欄） |
| 開場重繪 | 有 `entry#37` | **沒有** ⇒ `DS:0BDE6h` 的條件計算立刻被 `1` 覆蓋，成了廢碼 |
| 換角色鍵 | `'G'`／`'O'` | `'8'`／`'2'`（spec 794、1023 同一類） |
| Yes／No 提示參數 | 9 word | 10 word（多一個 byte） |

★ 其餘位址對應與既有結論一致：
`DS:4FBAh`↔`7F27h`、`DS:6506h`↔`9594h`、`DS:6F70h`↔`0A00Ah`、`DS:7564h`↔`0A650h`。

## 中文化

七個選項（DOS 39 字元／PC-98 80 bytes 一整列）：

| 功能 | DOS | PC-98 | 熱鍵 | 建議中文 |
|---|---|---|---|---|
| 治療 | `Heal` | 「治療」 | `H` | 治療 |
| 看角色 | `View` | 「ｷｬﾗｸﾀｰ」 | `V` | 人物 |
| 取回 | `Take` | 「金戻す」 | `T` | 取錢 |
| 集中 | `Pool` | 「金集ﾒﾙ」 | `P` | 集資 |
| 分配 | `Share` | 「金分ｹﾙ」 | `S` | 分錢 |
| 鑑價 | `Appraise` | 「見積る」 | `A` | 估價 |
| 離開 | `Exit` | 「やめる」 | `E` | 離開 |

⚠ **每格上限 6 bytes ＝ 3 個全形字**（上面那條結構結論），
所以中文一律 3 字以內；熱鍵不動，沿用 PC-98 的獨立表。

離開時的祭司訊息（DOS 拆成兩句、PC-98 也是兩句）：

| | DOS | PC-98 |
|---|---|---|
| 前句 | `'As you leave a priest says, "Excuse me but you have left some money here" '`（74） | 「きみたちが行こうとすると、僧侶が呼び止めた。「お金をお忘れですよ」」（66） |
| 後句 | `'Do you want to go back and retrieve your money?'`（47） | 「引き返してお金を取りますか？」（28） |
| Yes／No | `'~Yes ~No'`（8，**波浪號標記**） | `' はい　いいえ'`（14）＋ 熱鍵 `Y`／`B` |

⚠ 兩句是**分兩次呼叫印字**的，不是一個字串——翻譯時不能合併成一句。
