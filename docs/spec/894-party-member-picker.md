# 894 — 隊員選擇器，並定出 PC-98 選單陣列的版面

- 證據等級：`exact`（兩平台各自逐條讀完）
- 作法見 spec 783

## `overlay-24:02E6Ah`（DOS 163 條）↔ `overlay-24:0314Bh`（PC-98 180 條）

`retf 0Ah` ＝ 5 個 word：`(提示字串, 可不可以離開, var 選中的角色)`。

| | DOS | PC-98 |
|---|---|---|
| 離開 | `' Exit'` | `'抜ける'` |
| 確定 | `'Select'` | `' 決定 '` |

```pascal
提示 := 提示字串^;                                  { 上限 28h }
鍵 := 20h;  額外 := '';
if 可以離開 then 額外 := ' Exit';

while <0A54h:08D4h>(離開鍵表, 鍵) do begin
    <本模組 0795h>(選中^);                          { 把目前選中的畫出來 }
    模式 := (DS:4FBAh in [2, 6]) ? 1 : 0;
    暫  := 提示 ＋ 常數;
    暫2 := 'Select' ＋ 額外;
    鍵  := <本模組 169Fh>(var 有選中, 模式, 1, 0Fh, 0Ah, 0Dh);

    p := 選中^;
    if 有選中 then begin
        if 鍵 = 4Fh then begin                       { 下一個 }
            p := p^[189h];
            if p = NIL then p := 遠指標(DS:650Ah);   { 繞回第一個 }
        end
        else if 鍵 = 47h then begin                  { 上一個 }
            p := 遠指標(DS:650Ah);
            if 選中^ = 遠指標(DS:650Ah) then
                while p^[189h] <> NIL do p := p^[189h]     { 繞到最後一個 }
            else
                while p^[189h] <> 選中^ do p := p^[189h];  { 找前一個 }
        end;
    end
    else if 可以離開 and ((鍵 = 'E') or (鍵 = 0)) then
        p := NIL;

    選中^ := p;
end;
```

鍵碼 `47h`／`4Fh` 與 spec 871 一樣是 Home／End 的掃描碼。
單向鏈結串列沒有 `prev`，所以「上一個」得從頭走——**繞回最後一個時
還得整條走完**，是 O(n) 的作法。

## PC-98 選單陣列的版面定案

PC-98 這一支把兩塊陣列的 stride 直接寫了出來：

```asm
mov di, 0A37Eh                 ; 標籤欄位
...  mov ax, 6  ...  call 0A65h:0649h    ; 指派，上限 6
mov byte ptr ds:0A33Eh, 45h    ; 熱鍵 'E'

mov ax, [bp+var_83]            ; 欄位索引（1 或 6）
mov dx, 7
mul dx
mov di, ax
add di, 0A338h                 ; ← 標籤陣列基底，每欄 7 bytes
...  mov ax, 6  ...  call 0A65h:0649h

mov di, [bp+var_83]
mov byte ptr [di - 5CCCh], 53h ; ← 熱鍵陣列基底 0A334h，每項 1 byte，'S'
```

程式碼裡寫的是 `0A338h ＋ 7 × 索引` 與 `0A334h ＋ 索引`，
但那個索引是 **1 起算**的。spec 899（`overlay-13:02EBBh`）一次寫出六組
連續的欄位，把 0 起算的真正基底夾了出來：

| 陣列 | 基底（索引 0） | stride |
|---|---|---|
| 標籤欄位 | **`DS:0A33Fh`** | **7 bytes**（`string[6]`） |
| 熱鍵字元 | **`DS:0A335h`** | **1 byte** |

回頭核對先前規格看到的散落位址，**全部對得上**：

| 位址 | 陣列 | 索引 | 出處 |
|---|---|---|---|
| `DS:0A335h`..`0A339h` | 熱鍵 | 0..4 | spec 899（`T N P M C`） |
| `DS:0A33Ah` | 熱鍵 | 5 | spec 879（`'F'`） |
| `DS:0A33Bh` | 熱鍵 | 6 | spec 879／885（`'S'`／`'F'`） |
| `DS:0A33Ch` | 熱鍵 | 7 | spec 885（`'S'`） |
| `DS:0A33Eh` | 熱鍵 | **9** | spec 879／899、本支（`'E'`） |
| `DS:0A33Fh`..`0A35Bh` | 標籤 | 0..4 | spec 899 |
| `DS:0A369h` | 標籤 | 6 | spec 885 |
| `DS:0A370h` | 標籤 | 7 | spec 885 |
| `DS:0A37Eh` | 標籤 | **9** | spec 865／879／899、本支 |

**`Exit` 固定落在索引 9**（熱鍵 `0A33Eh`、標籤 `0A37Eh`），
三支不同的選單都一樣——那是最後一格。

### 中文化的具體規格

PC-98 的選單就是這兩塊平行陣列：

- **標籤欄位每欄只有 6 bytes**（`string[6]`），日文剛好三個全形字。
  中文同樣是三個字。**超過就放不下**。
- **熱鍵是另一塊 1 byte 陣列**，與標籤同索引。
- 選項不可用時**兩邊都寫 0**（spec 885）。

這是前面五、六個規格陸續看到的同一件事，到這裡有了確切的版面。

## 明確不宣稱

- 沒有宣稱 `本模組 0795h`／`169Fh` 的完整簽章。
- 沒有宣稱 `DS:4FBAh in [2, 6]` 決定的那個模式參數是什麼。
- 沒有宣稱標籤陣列與熱鍵陣列各有幾個欄位。
- 沒有宣稱 PC-98 那個 `var_83`（值 1 或 6）怎麼決定。
