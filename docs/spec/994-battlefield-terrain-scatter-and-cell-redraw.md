# 994 — 戰場地形的隨機鋪設，與 PC-98 的整格重畫

- 證據等級：`exact`（兩支逐條讀完；`overlay-10` 的兩平台差異逐條比對）
- 作法見 spec 783

## `pc98 overlay-10:00C95h` ↔ `dos overlay-10:00CA1h`（各 182 條，相似度 **1.000**）

兩邊助憶碼序列**完全相同**，17 處運算元差異只有兩類：
戰場地圖記錄 `DS:9F2Ch` ↔ `DS:6E92h`，以及 IDA 的 `arg_` 命名。
（DOS 側原本標成邊界碎片，其實是完整的一支。）

`retf 10h` ＝ 8 個 word，用到七個：

```pascal
procedure 鋪一格(欄 arg_E, 列 arg_C, w1 arg_A, w2 arg_8, w3 arg_6, w4 arg_4,
                 w5 arg_2, 未用 arg_0);
r := ROLLDICE(1, 100);                                   { overlay-23 entry#9 }
if      r <= w1                          then v := ROLLDICE(1,2) ＋ 39h
else if r <= w1＋w2                      then v := ROLLDICE(1,2) ＋ 2Fh
else if r <= w1＋w2＋w3                  then v := ROLLDICE(1,2) ＋ 2Bh
else if r <= w1＋w2＋w3＋w4              then v := ROLLDICE(1,2) ＋ 36h
else if r <= w1＋w2＋w3＋w4＋w5          then v := ROLLDICE(1,2) ＋ 31h
else 直接離開（不寫）;
遠指標(DS:9F2Ch)^[7 ＋ 列 × 32h ＋ 欄] := v;
```

### ★ 五段累加的機率權重

呼叫端給五個百分比，程式**自己累加**成 `1d100` 的區間邊界。
五種地磚各有**兩個變體**（`ROLLDICE(1,2)` 回 1 或 2）：

| 段 | 基底 | 實際寫入的值 |
|---|---|---|
| 1 | `39h` | `3Ah`／`3Bh`（58／59） |
| 2 | `2Fh` | `30h`／`31h`（48／49） |
| 3 | `2Bh` | `2Ch`／`2Dh`（44／45） |
| 4 | `36h` | `37h`／`38h`（55／56） |
| 5 | `31h` | `32h`／`33h`（50／51） |

⚠ **五個權重加起來不到 100 時，落在剩餘區間的格子完全不寫**——
保留地圖上原本的值。所以呼叫端可以只鋪一部分。

⚠ 第 2 段的高值 `31h` 與第 5 段的基底 `31h` 相同，但第 5 段寫的是
`32h`／`33h`，**不會撞號**。

寫入位置 `地圖^[7 ＋ 列×50 ＋ 欄]` 與既有結論（`overlay-32` 的讀取端：
`輸出 := 地圖^[y×32h ＋ x ＋ 7]`）**索引式完全一致**——
戰場是 **50 欄**、表頭 7 bytes。

## `pc98 overlay-32:002DAh`（184 條，`retf 4`）＝ `dos overlay-32:00320h`（spec 977）

⚠ `aligned_diff` 又判成單邊。但兩支的後半**逐句相同**，是同一支的兩平台版本
（第三次遇到配對工具漏判，見 spec 985／988）。

```pascal
dx := 欄 − 遠指標(DS:9F2Ch)^[2];                { 戰場原點，DOS 是 DS:6E92h }
dy := 列 − 遠指標(DS:9F2Ch)^[3];

{ ── PC-98 多出來的前半：先鋪地磚 ── }
if <本模組 0011h>(@a, @b, 0, 遠指標(DS:9F2Ch)^[5]) then
    if <本模組 0A1Eh>(a ＋ dy, b ＋ dx) then begin
        地圖值 := 遠指標(DS:9F2Ch)^[7 ＋ (a ＋ 列) × 32h ＋ (b ＋ 欄)];
        <overlay-33 entry#3>(0, byte[48AFh ＋ 地圖值 × 4], (a＋dy)×3, (b＋dx)×3);
        if 遠指標(DS:9F2Ch)^[4] <> 0 then
            <overlay-33 entry#6>(19h, 0, 0, a ＋ dy, b ＋ dx);
    end;

{ ── 與 DOS 00320h 逐句相同的後半：畫戰鬥員 ── }
<本模組 07F5h>(@第二平面, @佔用者, 列, 欄);
if 佔用者 > 0 then begin                                    { 無號 }
    p := 遠指標[9DCFh ＋ 佔用者 × 4];
    if <本模組 0A4Fh>(0, p) then
        <overlay-33 entry#6>(byte[9860h ＋ 佔用者],          { 座標 B }
                             byte[98A8h ＋ 佔用者],          { 座標 A }
                             遠指標(p^[18Eh])^[9],           { 模式 }
                             0,
                             p^[143h]);                      { 組 ＝ 圖像編號 }
end;
```

### 跨平台對應（全部是新的）

| DOS | PC-98 | 內容 |
|---|---|---|
| `DS:6E92h` | `DS:9F2Ch` | 戰場地圖記錄（`+2`／`+3` 原點、`+4` 旗標、`+5` 參數、`+7` 起地圖） |
| `DS:6D35h` | `DS:9DCFh` | 戰鬥員遠指標表，每格 4 bytes |
| `DS:67C6h` | `DS:9860h` | 每人一個 byte，貼圖座標 B |
| `DS:680Eh` | `DS:98A8h` | 每人一個 byte，貼圖座標 A |
| `本模組 0509h` | `本模組 07F5h` | 讀戰場兩平面 |
| `本模組 0763h` | `本模組 0A4Fh` | 那道可見性／資格檢查 |
| `本模組 0578h` | 展開成前半那一段 | 鋪地磚 |

（PC-98 位址由負位移還原：`[di−6231h]` ＝ `DS:9DCFh`、
`[di−67A0h]` ＝ `DS:9860h`、`[di−6758h]` ＝ `DS:98A8h`。）

### ★ `DS:48AFh` 是地磚查表，每筆 4 bytes

靜態 bytes 前六筆：`00 FF 01 02`／`00 FF 01 02`／`01 FF 01 02`／
`02 FF 01 02`／`03 01 01 00`／`04 FF 01 02`。
本支只讀 `+0`（拿去當 `overlay-33 entry#3` 的參數），
其餘三個 byte 用途不明。**索引是地圖格上的值**——
也就是 `overlay-10:00C95h` 寫進去的那個 `2Bh`..`3Bh` 之類的編號。

★ 這把兩支接起來了：**`overlay-10` 寫地磚編號，`overlay-32` 把編號查成圖組再畫。**

### PC-98 多出來的前半

DOS 把「鋪地磚」放在 `本模組 0578h` 這支子程序裡（spec 977 未讀），
PC-98 直接展開在同一支裡，而且多了一個 `DS:9F2Ch^[4] <> 0` 才畫的
`19h` 號圖示。`19h` 這個組編號與 spec 979 的 `dos overlay-17:03B99h` 用的是同一個。

## 明確不宣稱

- 沒有宣稱五種地磚（`2Bh`／`2Fh`／`31h`／`36h`／`39h` 五個基底）各是什麼地形。
- 沒有宣稱 `DS:48AFh` 每筆後三個 byte 的用途。
- 沒有宣稱 `本模組 0011h`／`0A1Eh`（PC-98 前半那兩支）做什麼。
- 沒有宣稱 `overlay-33 entry#3` 的四個參數。
- 沒有宣稱 `overlay-10:00C95h` 沒用到的 `arg_0` 是什麼。
