# 第六百四十輪：豁免減半／免疫歸零，以及 `DS:0A02Eh` 是傷害值

狀態：`READY`。日期：2026-08-14
位置：PC-98 `overlay-12` 的 `19B3h`、`19E8h`、`1A34h`。

## `DS:0A02Eh` 是傷害值

等級：`strong inference`。四個獨立的呼叫端把它當同一件事用：

| 位置 | 動作 |
|---|---|
| `17B5h`（[spec 639](639-overlay12-poison-and-race-gates.md)） | **設定**成 `1d12 × 3 + 4 + x` |
| `180Ch`（同上） | `+ 3` |
| `133Fh`（同上） | 條件成立時 **除以 2**，否則歸 `0` |
| `1A34h`（本輪） | 豁免成功且命中免疫表時歸 `0`，其餘**除以 2** |

「擲骰決定 → 依條件減半 → 特定情況歸零」是傷害的標準生命週期。單看任何一支都
只是一個全域 byte，四支放在一起才成立。

## `1A34h`：豁免減半，另有一張免疫表

```text
if (DS:0A02Fh and 1) <> 0 or (DS:0A02Fh and 2) <> 0 then
    if <far 013Eh:0028h>(0, 4, arg_6, arg_8) <> 0 then     ← 豁免成功
        if byte[DS:0A031h × 16 + 61BCh] <> 0 then
            DS:0A02Eh := 0                                 ← 完全免疫
        else
            DS:0A02Eh := DS:0A02Eh div 2                   ← 減半
    else
        DS:0A02Eh := DS:0A02Eh div 2                       ← 豁免失敗也減半？
```

**兩條路徑都減半**：豁免成功但不在免疫表裡 → 減半；豁免失敗 → 也減半。差別只在
「豁免成功 ＋ 在免疫表裡」那一格才歸零。這與 AD&D 慣例的「豁免成功減半、失敗全額」
**不一樣**，是這一支自己的規則，remake 不能照 AD&D 的直覺改寫。

除法是 `cwd` ＋ `idiv 2`（**有號**），所以負值會朝 0 取整。

### `DS:61BCh` 是 16 bytes 一筆的表

```asm
mov  al, ds:0A031h
xor  ah, ah
mov  di, ax
mov  cl, 4
shl  di, cl                 ; 索引 × 16
cmp  byte ptr [di+61BCh], 0
```

索引來自 `DS:0A031h`（本輪多支都用它當索引或參數），每筆 **16 bytes**，這裡只讀
第 0 個 byte。

## `19B3h` 與 `19E8h`：同一個形狀，兩組常數

```text
19B3h:  DS:0A02Fh := 9
        <far 013Eh:0064h>(arg_6^[18Eh]^[0Ah], ROLLDICE(2, 0Ah), 0, 0)

19E8h:  DS:0A02Fh := 10h
        <far 013Eh:0064h>(arg_6^[18Eh]^[0Ah], ROLLDICE(1, 4), 0, 0)
```

兩支逐指令相同，只差 `DS:0A02Fh` 的值（`9` 與 `10h`）與骰子（`2d10` 與 `1d4`）。

`DS:0A02Fh` 在 `1A34h` 是被**當成 bit 遮罩讀**的（`and 1`、`and 2`），這裡卻是
整個覆寫成 `9` (`1001b`) 與 `10h` (`10000b`)。所以它是一個旗標欄位，由前段設定、
後段查詢。

## 明確不宣稱

- `DS:0A02Fh` 各 bit 的意義（只確定 `bit 0`／`bit 1` 在 `1A34h` 被查、
  `bit 5` 在 `176Dh` 被查）。
- `DS:0A031h` 是什麼（在多支裡當索引與參數）。
- `DS:61BCh` 每筆 16 bytes 的其餘欄位。
- `013Eh:0028h`／`013Eh:0064h` 的行為。
