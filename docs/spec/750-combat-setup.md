# 750 — 戰鬥開場程序（`overlay-10:1C3Eh`）

- 平台／模組：DOS `overlay-10`（`1C3Eh`，130 條指令）
- 證據等級：`exact`（逐指令讀完）
- 相關：[`749`](749-combat-teardown-and-battlefield-grid.md)（收尾側）、
  [`748`](748-cloud-effect-dispel-pair.md)（雲霧鏈與地圖索引）

`retf`（無運算元）＝ 不收參數。畫面上打出 `'A battle begins...'`
（`CS:1C2Bh`，18 字元）的就是這一支。

## 流程

```pascal
DS:4FC9h := 0;
<overlay-29 entry#5 @055Bh>(@DS:722Ch);

0297h:1D19h(@DS:726Fh);   DS:726Eh := 0FFh;
0297h:1D19h(@DS:7274h);   DS:7273h := 0FFh;
0297h:1D19h(@DS:728Ch);   DS:7290h := 0FFh;

<overlay-26 entry#4 @07E5h>();
0542h:0B33h();                        { 繪圖 unit，全模組共 25 個呼叫端 }
繪字(0, 18h, 0Ah, 0, 'A battle begins...');   { 0542h:0352h }

DS:75DAh := 0;  DS:758Dh := 0;  DS:758Eh := 0Fh;
DS:6F9Fh := 0;  DS:6E91h := 0;                 { 戰鬥員計數歸零 }
DS:755Bh := NIL;  DS:755Fh := NIL;             { 兩條雲霧鏈 }
DS:650Eh := NIL;
FillChar(@DS:6E59h, 38h, 0);                   { 戰鬥員陣列全清 }
DS:4F9Dh^[666h] := 0;

三支本模組程序();                               { 各自後接 06EAh:0268h() }

0297h:1C59h(@DS:75E0h, 1, 4, 3, 18h);
地圖^[2] := <overlay-32 entry#15 @0C36h>(DS:650Ah) - 3;
地圖^[3] := <overlay-32 entry#16 @0C5Eh>(DS:650Ah) - 3;
<overlay-24 entry#39 @2E05h>();

角色 := DS:650Ah;                               { 隊伍鏈頭 }
while 角色 <> NIL do begin
    <overlay-23 entry#4 @03FEh>(角色, 8);
    <overlay-23 entry#4 @03FEh>(角色, 16h);
    角色 := 角色^[189h];
end;
<overlay-13 entry#25 @2E22h>();
DS:4FBAh := 5;
```

三支本模組程序用的是 `push cs` ＋ `call near` 的慣用法（被呼叫者以 `retf`
結尾，仍在同一 segment 內，所以用近呼叫省一個 word）：`102Fh`（72 條）、
`10DDh`（94 條）、`1800h`（398 條），三支都是 `retf` 不收參數。

## 戰鬥員陣列的容量是 8

spec 748 的存取式是 `[6E52h + i*7]`（`i` 從 1 起），計數在 `DS:6E91h`。
這裡 `FillChar(@DS:6E59h, 38h, 0)`：

```
起點 6E59h = 6E52h + 7 * 1      → 第 1 筆
長度 38h   = 56 = 7 * 8         → 8 筆
終點 6E91h = 6E59h + 56          → 正好是計數 byte
```

三個數字互相咬合，**陣列上限就是 8 筆**，緊接著是計數 byte，再接著是
`DS:6E92h` 的地圖遠指標。8 也正好是 Gold Box 系列隊伍的上限（6 名 PC ＋ 2 名
NPC），但那是外部知識，不是本輪的證據。

## 地圖表頭的 `+2` / `+3`

spec 749 由配置大小推出地圖緩衝區前 7 個 byte 不參與格子索引。這裡寫了其中
兩個：

```
地圖^[2] := entry#15(隊伍鏈頭) - 3
地圖^[3] := entry#16(隊伍鏈頭) - 3
```

兩個 entry 分別回一個 byte（`cbw` 後減 3）。取自隊伍鏈頭、又成對出現、又同時
減 3，形狀符合「以隊伍位置為中心、往回退 3 格當作戰場左上角」。**但 entry#15／
#16 都還沒讀，所以這只是形狀相符，不是結論。**

寫入時 `DS:6E92h` 已經是有效指標，代表緩衝區在此之前就配置好了——可能在
`1800h` 那支或更早，本輪沒追。

## 每個隊員跑兩次 `overlay-23 entry#4`

同一支程序對同一個角色連叫兩次，第二個參數分別是 `8` 與 `16h`(22)。看起來是
「套用／清除某種以編號指定的狀態」，編號的意義要等 `overlay-23:03FEh` 讀完才
能確定。

## 三組 `0297h:1D19h` ＋ `0FFh` 哨兵

| var 參數 | 隨後設 `0FFh` 的位址 | 相對位置 |
|---|---|---|
| `@DS:726Fh` | `DS:726Eh` | 前一個 byte |
| `@DS:7274h` | `DS:7273h` | 前一個 byte |
| `@DS:728Ch` | `DS:7290h` | 第 5 個 byte（`728Ch` ＋ 4） |

前兩組是「哨兵 byte ＋ 4 bytes 的東西」，第三組是「4 bytes 的東西 ＋ 哨兵
byte」，**順序相反**。`0297h:1D19h` 在 DOS 側共 9 個呼叫端，目前全部待解讀
（清單見 spec 749），所以無從反推它做什麼。

## 明確不宣稱

- 沒有宣稱 `0297h:1D19h`、`0297h:1C59h`、`0542h:0B33h`、`06EAh:0268h` 各自是
  什麼。`06EAh:0268h` 全 DOS overlay 只有 4 個呼叫端，其中 3 個在這支裡。
- 沒有宣稱 `DS:4FBAh := 5` 的 5 代表「戰鬥模式」。只知道這支結尾把它設成 5。
- 沒有宣稱繪字的參數確實是 `(0, 24) 顏色 0Ah`。順序沿用 spec 既有的
  `0542h:0352h(x, y, colour, mode, str)`，該順序本身是先前推得、未經實機確認。
- 沒有宣稱這支是戰鬥的唯一入口，呼叫端未追。
