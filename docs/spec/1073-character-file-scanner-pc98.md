# 1073 — PC-98 角色檔掃描器：選單節點 ＝ `string[80]` ＋ next，檔案大小容忍 ±1

- 證據等級：`exact`（PC-98 側 459 條逐條讀完，無匯出破洞）
- 作法見 spec 783

## `pc98 overlay-16:00164h`（`retf 18h`）

原本待解讀。範圍 `164h`..`5F9h`。這是**「掃描磁碟上的角色檔、串成兩條選單鏈」**
的通用副程式，spec 1057／1069 的存讀檔選單、spec 1043 的三種副檔名都靠它。

七個參數（Turbo Pascal 由左至右推疊 ⇒ 先宣告的在高位移）：

| 位移 | 用途 |
|---|---|
| `bp+1Ah`（`arg_14`） | **路徑字串**（上限 `50h` ＝ 80） |
| `bp+16h`（`arg_10`） | **檔名樣式字串**（上限 `50h`） |
| `bp+14h`（`arg_E`） | 名字欄位在檔案內的位移（`Seek`） |
| `bp+12h`（`arg_C`） | 旗標欄位在檔案內的位移（`Seek`） |
| `bp+10h`（`arg_A`） | **預期的檔案長度** |
| `bp+0Ch`（`arg_6`） | `@顯示名鏈頭` |
| `bp+8`（`arg_2`） | `@檔名鏈頭` |
| `bp+6`（`arg_0`） | 本支從未讀取 |

## 主迴圈

```pascal
路徑   := arg_14;   樣式 := arg_10;               { 各上限 80 }
節點1 := NIL;  節點2 := NIL;
FindFirst(路徑 ＋ 樣式, 0, 搜尋記錄);              { 08BD:0112h }
while DS:0BE2Eh = 0 do begin                       { DosError }
    if (Copy(搜尋記錄.Name, 9, 4) = '.SAV')
       and (搜尋記錄.Name[7] = 'K') then goto 下一筆;
    …見下…
    下一筆: FindNext(搜尋記錄);                    { 08BD:0150h }
end;
```

★ `搜尋記錄` 在 `bp−0E1h`，其 `Name` 欄位（Borland `SearchRec` 的 `+1Eh`）
正好落在 `bp−0C3h` ⇒ IDA 的 `var_C3` 就是 `SearchRec.Name`，
`var_BC` 就是 `Name[7]`。這條偏移關係是本支所有字串操作的解讀基礎。

⚠ `Copy(Name, 9, 4)` 取的是**第 9..12 個字元**，只有在主檔名剛好 8 個字元時
才等於副檔名。本規格不宣稱磁碟上那些檔名長什麼樣。

## 每一個檔案的處理

```pascal
Assign(檔案, 路徑 ＋ 搜尋記錄.Name);               { 0A65:186Ah }
Reset(檔案, 1);                                    { 0A65:1898h，recsize 1 }
if (FileSize <> arg_A − 1) and (FileSize <> arg_A)
   and (FileSize <> arg_A ＋ 1) then goto 關檔;     { 0A65:1A32h }
```

> ★★★ **檔案長度接受 `arg_A − 1`、`arg_A`、`arg_A ＋ 1` 三個值。**
> 這正是 spec 1038 那個「DOS 422／PC-98 423」的差 1
> ——**原作自己就把 ±1 當成同一種檔案收下**，
> 所以兩平台的角色檔可以互相讀。⇒ remake 的相容層要照抄這個容忍，
> 不能只認單一長度。

```pascal
GetMem(節點1, 56h);  GetMem(節點2, 56h);           { 081F:0043h，各 86 bytes }
FillChar(節點1^, 56h, 0);  FillChar(節點2^, 56h, 0);

Seek(檔案, arg_E);                                 { 0A65:19EBh }
if DS:0A816h = 2 then begin                        { 檔案類別 2，spec 1043／1070 }
    BlockRead(檔案, 暫存, 10h, 讀到);
    <near 0020h>(轉換緩衝, 暫存);                  { 名字要先轉換 }
    節點1^ := 轉換緩衝;                            { 上限 50h }
end else
    BlockRead(檔案, 節點1^, 10h, 讀到);            { ★ 直接讀進節點的字串欄位 }

Seek(檔案, arg_C);
if DS:0A816h = 2 then 旗標 := 0
else BlockRead(檔案, 旗標, 1, NIL);                { ★ 第 4 個參數推 NIL }

節點2^ := 搜尋記錄.Name;                           { 上限 50h }
```

★ **名字欄位是 16 bytes（`10h`）**，位置由 `arg_E` 指定 ⇒ 三種角色檔格式
（422／285／188）的名字位移不同，全部由呼叫端傳進來。
★ 類別 2 的角色檔沒有 `arg_C` 那個旗標，直接當 0。

## ★★★ 選單節點的版面：`string[80]` ＋ 4 bytes next

串鏈用的是 `節點^[52h]`：

```pascal
if 顯示名鏈頭^ = NIL then begin
    顯示名鏈頭^ := 節點1;  尾1 := 節點1;
    檔名鏈頭^   := 節點2;  尾2 := 節點2;
end else begin
    尾1^[52h] := 節點1;  尾1 := 節點1;
    尾2^[52h] := 節點2;  尾2 := 節點2;
end;
```

| | 字串欄位 | 填補 | next | 合計 |
|---|---|---|---|---|
| PC-98 | `0`..`50h` ＝ `string[80]`（81） | `51h`（1） | `52h`（4） | **`56h` ＝ 86** |
| DOS | `string[40]`（41） | 1 | `2Ah`（4） | **`2Eh` ＝ 46** |

> ★★★ **選單節點 DOS 46／PC-98 86 的 `28h` 差，來源就是字串上限
> 從 `string[40]` 放寬成 `string[80]`。**
> 既有結論只記了「差 `28h`」；這裡第一次看到**差在哪一個欄位**——
> 剛好是雙位元組文字要用兩倍位元組的那 40 bytes。
> ⇒ remake 的中文選單項可以直接沿用 PC-98 的 80 bytes 上限（全形 40 字）。

## `.SAV` 的顯示名是組出來的

```pascal
if Copy(搜尋記錄.Name, 9, 4) = '.SAV' then
    顯示名 := <CS:154h 的 13 bytes 常數> ＋ Chr(搜尋記錄.Name[7] − 1) ＋ ' '
else
    顯示名 := '';                                  { 空字串 }
節點1^ := 顯示名 ＋ 節點1^;                        { 上限 50h }
```

`CS:154h` 的常數是 13 bytes：`83 5A 81 5B 83 75 83 51 81 5B 83 80 87`
＝ 「セーブゲーム」（12 bytes）**再加一個落單的 `87h`**。

> ★★★ **那個落單的 `87h` 是故意的**：`0A65:075Fh` 是 `Chr`（字元轉字串，
> spec 1075／1076 從 DOS 對應的 `0A54:074Fh` 確認），而存檔槽的代號是
> **字母 `'A'`..`'J'`**（spec 1076 的集合常數 `['A'..'J']`）。
> 所以 `Chr(Name[7] − 1)` 產生 `40h`..`49h`，接在 `87h` 後面組成
> **Shift-JIS `8740h`..`8749h` ＝ ①..⑩**。
> ⇒ 顯示名是「セーブゲーム①」..「セーブゲーム⑩」，**兩個 byte 分屬兩個常數**。
>
> ⚠ 這也解釋了上面那條 `Name[7] = 'K'` 的排除規則：**`'K'` 是第 11 格**，
> 超出 `'A'`..`'J'`，換算會落到 `874Ah` 而不是圈號 ⇒ 原作直接把它跳過。
>
> ⚠ **中文化時這一格要整個重寫**（例如「存檔 1」..「存檔 10」），
> 不能只換前半段——半形數字接在 `87h` 後面會變成別的字。

## ★★ 去重：兩邊都補到 15 個字元再比

```pascal
角色 := DS:9598h;                                  { 隊伍鏈頭 }
while 角色 <> NIL do begin
    a := Copy(節點1^ ＋ 填補字串(DS:0BECh), Length(節點1^) − 0Eh, 0Fh);
    b := Copy(角色^  ＋ 填補字串(DS:0BECh), 1,                  0Fh);
    if a = b then break;                           { 找到同名 }
    角色 := 角色^[18Ah];                           { 隊伍 next，spec 1038 }
end;

if (旗標 > 7Fh) or (角色 <> NIL) then begin        { 拒收 }
    FreeMem(節點2, 56h);  FreeMem(節點1, 56h);     { 081F:01A2h }
    節點1 := NIL;  節點2 := NIL;
end;
if 節點1 = NIL then goto 關檔;
if DS:0A816h = 1 then begin <near 0079h>(緩衝, 節點1^); 節點1^ := 緩衝 end;
```

★ 兩條件任一成立就整筆丟掉：**`arg_C` 位置的旗標 ≥ `80h`**、或**名字已在隊伍裡**。
★ `DS:0BECh` 是補位字串，讓長度不足 15 的名字也能整齊比對。

> ⚠ **兩側的取法不對稱**：己方取 `Length − 0Eh` 起（尾端 15 字），
> 隊伍側取第 1 字起（開頭 15 字）。名字欄位只有 16 bytes，
> 所以只有**恰好 16 字元的名字**會因此對不上而漏掉去重。
> 形狀上是原作的邊界瑕疵；本規格不宣稱實機上有沒有踩到。

## Resident RTL 對照（本支一次用滿）

| 位址 | 對應 |
|---|---|
| `08BD:0112h` ／ `0150h` | `FindFirst` ／ `FindNext`（spec 526） |
| `0A65:186Ah` ／ `1898h` ／ `1919h` | `Assign` ／ `Reset` ／ `Close` |
| `0A65:1A32h` ／ `19EBh` ／ `1983h` | `FileSize` ／ `Seek` ／ `BlockRead` |
| `081F:0043h` ／ `01A2h` | `GetMem` ／ `FreeMem` |
| `0A65:1B30h` | `FillChar` |
| `0A65:062Fh` ／ `06BCh` ／ `0649h` ／ `067Bh` ／ `0734h` ／ `075Fh` | 指派（留目的） ／ 串接（留目的） ／ 上限指派（全收） ／ `Copy`（留 `@結果`） ／ 比較（ZF） ／ `Chr`（字元轉字串） |

★★ **`062Fh` 與 `0649h` 的參數順序相反**：`062Fh(目的, 來源)`、
`0649h(來源, 目的, 上限)`。本支同時用到兩者，是分辨的最好對照
（`0179h` 若照 `062Fh` 的順序讀，會變成「把未初始化的區域變數寫回呼叫端」）。

## 中文化

本支沒有可翻的完整句子，只有 `CS:154h` 那個「セーブゲーム＋圈號前半」的常數（見上）與
`CS:14Fh` ＝ `'.SAV'`、`CS:162h` ＝ `' '`。
⚠ `'.SAV'` 是副檔名，不可翻。
⚠ 顯示名的上限是 `50h` ＝ 80 bytes ⇒ **中文全形最多 40 字**。

## 明確不宣稱

- 沒有宣稱 `near 0020h`（類別 2 的名字轉換）與 `near 0079h`（類別 1 的名字轉換）
  各做什麼。
- 沒有宣稱 `arg_C` 位置那個「≥ `80h` 就拒收」的旗標是什麼欄位。
- 沒有宣稱 `DS:0BECh` 那個補位字串的內容。
- 沒有宣稱磁碟上的角色檔名是不是一律 8 個字元
  （`Copy(…, 9, 4)` 只有那樣才等於副檔名；`Name[7]` 是存檔槽字母這件事
  與「第 7 個字元」的位置相符，但本規格沒有直接看到產生檔名的那一支）。
- 沒有宣稱 DOS 側的對應函式是哪一支。
