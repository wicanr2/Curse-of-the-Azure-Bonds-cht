# 第七百一十五輪：Sleep 的 HD 預算表，與被共用的暫存全域

狀態：`READY`。等級：`exact`（流程與數字）／`strong inference`（法術身分）。
日期：2026-08-14
位置：DOS `overlay-22:22B4h`。

## 流程

```text
DS:6F9Dh := 1
預算 := ROLLDICE(4, 4)                      ← 4d4，存進 byte [4CB5h]

for k := 1 to DS:7434h do
    p  := far [7431h + k×4]
    hd := p^[0E5h]
    成本 := 依 hd 查下表                     ← 存進 byte [4CB6h]

    if p^[195h] = 1              then 清掉該格
    elif <overlay-24 entry#27>(p, 35h) 找到 then 清掉該格     ← 已經睡著
    elif 預算 < 成本              then 清掉該格
    else 預算 := 預算 − 成本                                  ← 保留

<sub_F06h>(DS:6F97h, 0, 0, 0, 0, 'falls asleep'（CS:22A7h）)
```

## 成本表

| `+0E5h` | 成本 |
|---|---|
| `<= 1`（含負數，用 `jl`／`jg` 有號比較） | 1 |
| `2` | 2 |
| `3` | 4 |
| `4` | 6 |
| `5` 且 `p^[74h] = 0` | `0Ah`（10） |
| `5` 且 `p^[74h] <> 0` | `14h`（20） |
| 其他 | `14h`（20） |

`4d4` 的總預算配上「每個目標依 HD 扣一個成本」，是 AD&D **Sleep** 的標準做法
（1e 原文是「影響 4d4 HD」）。訊息 `falls asleep` 也對得上，所以法術身分幾乎
確定；本輪沒有從法術表反查編號，仍標為推論。

`5` 這一階要再看 `p^[74h]` 分成 10 與 20 兩種，其餘 HD 沒有這個分支。

## 三件要注意的

**預算用完不會提早跳出。** 迴圈跑完整個目標陣列，`預算 < 成本` 的那些一律被
清成 `NIL`（spec 709 的做法）。所以「前面的目標先被睡到」是**陣列順序**決定的，
不是強弱決定的。

**已經睡著的目標會被清掉。** `entry#27` 查到效果 `35h` 就當作不適用，而且
**不扣預算**——重複施放不會浪費 HD。

**訊息只發一次。** `sub_F06h` 在迴圈**外面**，所以不論睡倒幾個都只顯示一句
`falls asleep`（主詞由 `sub_F06h` 那邊決定）。

## `4CB4h`／`4CB5h`／`4CB6h` 是共用暫存，不是狀態

同一組全域已經被三支不同的函式當成暫存：

| 位址 | 用途 | 出處 |
|---|---|---|
| `4CB4h` | 效果收集表的筆數 | spec 710 `08A1h` |
| `4CB5h` | 擲骰門檻 | spec 705 `30C0h` |
| `4CB5h` | Sleep 的 HD 預算 | 本輪 |
| `4CB6h` | 擲骰門檻的 `base` | spec 705 |
| `4CB6h` | Sleep 的單筆成本 | 本輪 |

**同一個位址在不同函式裡意義完全不同**，而且沒有存檔／還原。remake 若把它們
建成具名的全域狀態會產生假的耦合；正確的做法是各自用區域變數。
反過來說，`08A1h` 那個沒有上界檢查的筆數溢出時會寫壞 `4CB5h`（spec 710），
在原作裡確實會互相影響——這一點要保留。

## 明確不宣稱

- `+0E5h`（用來查成本的那個值）與 `+74h` 的欄位名稱。
- `DS:6F9Dh` 的語意。
- 效果編號 `35h` 的名稱（本輪只確定它代表「已經睡著」）。
