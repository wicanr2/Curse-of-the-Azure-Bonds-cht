# 第七百二十一輪：`DS:72A0h` 是法術分派表，`DS:6F97h` 是編號不是施法者

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：DOS `overlay-22:1552h`（在 `1263h` 內）。

## 分派

```text
DS:6F97h := arg_A                       ← 編號
di := DS:6F97h × 4
call dword ptr [di + 72A0h]             ← 跳到該編號的處理函式
DS:6F97h := 0                           ← 立刻清掉
DS:6F9Dh := 0
```

`DS:72A0h` 是 **far 函式指標陣列，一格 4 bytes**，索引就是 `DS:6F97h`。
`overlay-22` 裡所有那些「法術 opcode」（spec 700..720）都是這張表的項目，
呼叫端不傳參數——要用的東西全部從全域讀（`DS:7431h` 目標陣列、`DS:7434h` 筆數、
`DS:6F97h` 自己的編號）。

## `DS:6F97h` 是編號，不是施法者

先前幾輪把 `DS:6F97h` 當成「施法者」，那是錯的。證據：

- 它在 `1552h` 由參數設定，緊接著被乘 4 當**索引**，回來之後**立刻歸 0**。
  一個施法者不會用完就清掉。
- 各 handler 把它傳給 `overlay-24 entry#36` 與 `sub_E11h`，而那兩支都拿它去查
  `[37DAh + 值 × 16]`——同一張 16 bytes 一格的法術屬性表（spec 705／712／719）。

所以 `entry#36(DS:6F97h)` 是「依這個法術的表格項目與施法者狀態算出來的一個值」，
不是單純的施法者等級。`DS:6506h` 才是施法者。

已更正的地方：spec 717 正文，以及台帳裡把 `DS:6F97h` 寫成施法者的註記。

## 呼叫圖抓不到這一段

`scripts/overlay_call_graph.py` 只解析 `9A`（絕對 far call）。整個工作區的間接
呼叫共 **26 處**：

| 平台／模組 | 處數 |
|---|---|
| dos `overlay-22` | 9 |
| pc98 `overlay-22` | 9 |
| pc98 `PC98-GAME.EXE` | 4 |
| dos／pc98 `overlay-23` | 各 2 |

`overlay-22` 的 9 處全部走 `DS:72A0h`：8 處是 `call dword ptr ds:72A0h`
（固定第 0 項），1 處是 `call dword ptr [di+72A0h]`（本輪這個分派）。

> 數量少到可以逐一處理，但**呼叫圖的覆蓋率敘述要把這 26 處算成缺口**，
> 不能說「解出 3,541 條邊」就等於完整。

## 明確不宣稱

- `DS:72A0h` 那張表的長度與各項對應哪個法術（表本身在 resident 的 DS，
  不在 overlay 裡）。
- `call dword ptr ds:72A0h`（不加索引）那 8 處為什麼固定用第 0 項。
- `DS:6F9Dh` 為何和 `DS:6F97h` 一起清 0。
