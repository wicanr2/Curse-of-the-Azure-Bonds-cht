# 第五百九十七輪：`22h` 的第二個輸出恆為 0

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：PC-98 `overlay-02:16BCh..1757h`。

```text
READVAR(2)
a := 0 ; b := 0 ; c := 0                  ← 三個區域變數都清零
node := DS:9598h
while node <> nil do
    if node^[75h] = 4 or node^[75h] = 0Ah then
        a := 1 ; c := 1                   ← 設的是 a 和 c
    node := node^[18Ah]
STOREVALUE(ADDFNC(operand 1), a)
STOREVALUE(ADDFNC(operand 2), b)          ← 存的是 b
```

**迴圈設定 `a` 與 `c`，但寫出去的是 `a` 與 `b`。** `b` 從初始化之後就沒被碰
過，所以 **`22h` 的第二個輸出永遠是 0**；`c` 被設定卻從未被讀。

兩個變數在 frame 上相鄰（`[bp-6]` 與 `[bp-7]`），形狀像是原始碼裡寫錯了變數
名。無論原因為何，**這是原版的行為**：remake 若「修好」它，帶第二個輸出的
ECL script 會拿到原版沒有的值。

## 這條指令在做什麼

沿角色鏈找有沒有任何一名成員的 `+75h` 等於 `4` 或 `0Ah`，有就把第一個輸出設
為 1。`+75h` 是角色記錄裡的一個分類欄位（職業？種族？），**具體是什麼未定**。

迴圈**不會提早結束**——找到之後仍然走完整條鏈。

## 明確不宣稱

- 角色記錄 `+75h` 的語意，以及 `4`／`0Ah` 這兩個值。
- 第二個輸出原本打算放什麼。
