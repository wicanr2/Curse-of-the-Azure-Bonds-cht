# 859 — 法術選單的清單建構：依等級排序、相同法術併行顯示次數

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側助憶碼完全相同，26 條差異全是位址與節點尺寸）
- 作法見 spec 783

## `overlay-22:005B4h` ↔ `overlay-22:00621h`（兩平台各 291 條）

`retf 2` ＝ 一個 byte（法術碼，**最高位另作旗標**）。

三個字串兩平台**完全相同**（沒有在地化）：`' *'`、`'  '`、`' ('`（配對的 `')'`）。

### 節點與三組平行資料

| | DOS | PC-98 | 內容 |
|---|---|---|---|
| 鏈頭 | `DS:4B44h` | `DS:7C22h` | 顯示行的鏈 |
| 節點大小 | `2Eh` ＝ 46 | `56h` ＝ 86 | `+0` 字串、`+29h`／`+51h` 旗標、`+2Ah`／`+52h` next |
| 次數陣列 | `DS:4B48h` | `DS:7C26h` | 84 格（`0`..`53h`） |
| 法術碼陣列 | `DS:4B9Ch` | `DS:7C7Ah` | 84 格，緊接在次數陣列之後 |

節點 `2Eh` ＝ `string[40]`（41）＋ 旗標（1）＋ far next（4）；
PC-98 `56h` ＝ `string[80]`（81）＋ 1 ＋ 4。**字串上限從 40 放寬到 80**
——一個中文字兩 bytes，這是在地化必要的放寬。

```pascal
p := 鏈頭;
if 鏈頭 = NIL then begin
    FillChar(DS:4B48h, 54h, 0);          { 84 格次數歸零 }
    GetMem(p, 2Eh);  p^[2Ah] := NIL;  鏈頭 := p;
    序 := 0;  上一個等級 := 0;
    DS:4B48h[0] := 1;
end else begin
    序 := 1;  上一個等級 := 0;
    while (p^[2Ah] <> NIL)
          and (有號(等級(arg_0 and 7Fh)) >= 上一個等級) do begin
        if p^[29h] = 0 then                              { 標題行不計 }
            if DS:4B9Ch[序 − 1] <> (arg_0 and 7Fh) then inc(序);
        p := p^[2Ah];
        上一個等級 := 等級(DS:4B9Ch[序]);
    end;

    if DS:4B9Ch[序 − 1] = (arg_0 and 7Fh) then begin      { 已經有這一格 }
        dec(序);
        inc(DS:4B48h[序]);                                { 次數 ＋1 }
    end else begin                                        { 插一個新節點 }
        GetMem(新, 2Eh);
        新^[2Ah] := p^[2Ah];  p^[2Ah] := 新;  p := 新;
        右移(DS:4B48h, 序..53h, 填 1);                    { 次數陣列整段後推 }
    end;
end;

{ 組字 }
if arg_0 > 7Fh then p^ := ' *' else p^ := '  ';
p^ := p^ ＋ 法術名稱[DS:27BDh ＋ (arg_0 and 7Fh) * 29h];
p^[29h] := 0;                                             { 這是法術行不是標題行 }

if DS:4B48h[序] > 1 then                                  { 無號 }
    p^ := p^ ＋ ' (' ＋ <far 1521h+1>(DS:4B48h[序]) ＋ ')';

if DS:4B9Ch[序] <> (arg_0 and 7Fh) then
    右移(DS:4B9Ch, 序..53h, 填 arg_0 and 7Fh);            { 法術碼陣列整段後推 }
```

## `DS:37DBh`（PC-98 `DS:61B5h`）＝ 法術屬性表，每筆 `10h`，`+0` 是等級

`碼 shl 4 ＋ 37DBh` 取出的 `+0` 就是這一支的排序鍵。
往後 dump 到 **索引 100 為止**，第 101 筆的位置已經是時鐘進位表
`DS:3E2Ah`（10／10／6／24／30／12／256，spec 793／802）——
**表的有效範圍與 `DS:27BDh` 名稱表的「共 100 筆」完全一致**，兩張表互相定界。

`+0` 的值對照 AD&D 一版（完整表已收進 `docs/audit/resident-data-tables.md`）：

| `+0` | 索引 | 對照 |
|---|---|---|
| 1 | 1..21、77..80 | 牧師 1 階（1..8）、法師 1 階（9..21）、德魯伊 1 階（77..80） |
| 2 | 22..35 | 牧師 2 階（22..28）、法師 2 階（29..35） |
| 3 | 37..55 | 牧師 3 階（37..44）、法師 3 階（45..55） |
| 4 | 58、66..70、81..89、100 | 牧師 4 階、法師 4 階 |
| 5 | 71..76、90..94 | 牧師 5 階、法師 5 階 |
| 6 | 57、59..65、95..99 | **名稱全是空字串**（保留格） |
| 7 | 36 `Animate Dead`、56 `Restoration` | 有名字，但不在玩家的記憶清單裡 |

抽樣核對：21 `Sleep` ＝ 1、47 `Fireball` ＝ 3、51 `Lightning Bolt` ＝ 3、
84 `Fear` ＝ 4、90 `Animate Dead`（法師）＝ 5、92 `Cone of Cold` ＝ 5
——**與 AD&D 一版逐項相符**，其中 84／55／21 三筆同時回頭確認 spec 842
把 `54h`／`37h`／`15h` 讀成 Fear／Slow／Sleep 是對的。

⚠ 值 6 與 7 那 15 筆**不宣稱是真的等級**：6 那一批名稱全空，
7 那兩支（`Animate Dead` 的牧師版、`Restoration`）有實作
（spec 845 就是 `Restoration`），但等級寫成 7 使它排在所有可記憶法術之後。

## `+29h` ＝ 這一行是不是標題行

走鏈算序號時只有 `+29h` ＝ 0 的行才推進 `序`，而本支寫完文字後固定把它清 0。
`DS:0875h` 的 `'1st Level'`..`'9th Level'`（spec 825 的表）就是那些 `+29h` ＝ 1 的行
——**標題行佔一個節點但不佔法術陣列的一格**。本支不建立標題行。

## 最高位 ＝ 前綴要不要加星號

`arg_0 > 7Fh` 走 `' *'`，否則走 `'  '`（兩個半形空白，讓沒星號的行對齊）。
其餘所有地方都先 `and 7Fh` 才當法術碼用。
**本規格不宣稱星號代表什麼**（呼叫端才知道）。

## 中文化

- 三個標記字串（`' *'`／`'  '`／`' ('` 與 `')'`）PC-98 原樣保留，中文版照抄即可。
- 字串上限 DOS 40 / PC-98 80——**中文版要跟 PC-98 走 80**，
  否則「Protection From Evil, 10' Radius」這種長名字加上 `' (12)'` 會被截掉。
- 排序鍵是等級不是名稱，所以**翻譯不會改變清單順序**。

## 明確不宣稱

- 沒有宣稱屬性表 `+1`..`+0Fh` 那 15 個 byte 是什麼。
- 沒有宣稱 `far 1521h+1(次數)` 的實作（形狀上是 `Str`，把數字轉成字串）。
- 沒有宣稱最高位旗標的語意。
- 沒有宣稱誰呼叫這一支、以及誰負責釋放這條鏈。
