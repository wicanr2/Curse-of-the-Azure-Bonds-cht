## `+0E5h` ＝ 生命骰數（HD）

門檻 `≤ 4` 必死、`5` 帶 `0FCh`（有號 −4）的修正豁免、`6` 不帶修正豁免、
`≥ 7` 完全免疫——**這是 AD&D 一版 Cloudkill 的階梯**：

| AD&D 一版 Cloudkill | 本支 |
|---|---|
| 4＋1 HD 以下直接死亡 | `+0E5h ≤ 4` 直接毒死 |
| 4＋1 ～ 5＋1 HD 豁免否則死 | `+0E5h = 5` 豁免（修正 `0FCh`） |
| 6 HD 以上豁免且有加值 | `+0E5h = 6` 豁免（修正 `0`） |
| — | `+0E5h ≥ 7` 連判定都不做 |

**修正值掛的階跟 AD&D 差一階**（AD&D 給 6HD 以上加值，這裡是 5HD 扣分、
6HD 持平），但高 HD 越容易活下來的方向一致。

### 回頭確認 spec 858

spec 858 的固定值路線是 `遠指標(DS:6506h)^[0E5h] × 64h`，也就是
**經驗值 ＝ HD × 100**——Gold Box 一貫的怪物經驗值算法。
`+0E5h` 定名之後，那條路線讀作「這場戰鬥的經驗值直接由怪物 HD 算」，
不必再走財寶折算。858 的「明確不宣稱」該項可以收斂成這一句。

`+0E5h` 與 spec 834 的 `+0E9h`（不死生物種類 1..10）是**兩個不同欄位**，
不要混用。

## 四種免疫效果碼

`1Fh`、`20h`、`6Fh`、`7Dh` 任一成立就整段跳過。`1Fh` 同時是本支重症時掛上的
效果碼，也在 spec 861 那張「戰鬥結束要清掉的 19 個效果碼」裡；
`20h`／`6Fh`／`7Dh` 目前只在這裡出現過。

輕症掛 `1Eh`、重症掛 `1Fh`，兩者都先用 `far 1577h` 確認已經掛上才叫 `00C9h`。

## `DS:6506h` 是「當前對象」的全域

本支在組訊息前把 `DS:6506h` 換成 `0D07h` 算出來的值，做完再換回去。
spec 858（固定經驗值）與 spec 861（`0F0Dh+2` 的處理對象）也都是讀寫這一格
——**`DS:6506h` 是跨函式的「現在在講誰」暫存，不是常駐資料**。

## 中文化

PC-98 把三句都改成完整日文句（`'は咳きこみ始めた。'` 等），
**沒有沿用英文的動詞短語結構**，與 spec 840 的改寫傾向一致。
`'is killed'` 在 PC-98 側沒有抽到獨立字串；DOS 這一份與 spec 832／840／842
的同名字串**各自獨立，不能用單一取代**。

## 明確不宣稱

- 沒有宣稱 `far 193Fh` 的六個參數各是什麼（只知道回填兩個旗標，碼是 `8`）。
- 沒有宣稱 `本模組 12EBh(角色, 修正, 0)` 是哪一種豁免。
- 沒有宣稱 `本模組 13EEh(…, 37h, …)` 裡 `37h` 的意義。
- 沒有宣稱 `本模組 0D07h` 與 `DS:27D8h`（spec 862 那張佔格形狀表的第 1 筆位址）
  在這裡的用途。
- 沒有宣稱 `20h`／`6Fh`／`7Dh` 三個免疫效果各是什麼。
- 沒有宣稱這一支對應惡臭雲還是毒雲——**兩種訊息與兩種判定都在同一支裡**，
  由 `193Fh` 回填的兩個旗標分流。
