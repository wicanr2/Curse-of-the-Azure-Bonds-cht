# 798 — 把全隊的錢併進 Pool、擲百分比打通牆的兩側

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側的運算元差異已逐條列出）
- 作法見 spec 783

## `overlay-21:0527h`（entry#5，79 條，差異 7 條）— Pool

```pascal
DS:7564h := 1;
p := DS:650Ah;
while p <> NIL do begin
    if (p^[0F7h] = 0) or (p^[0F7h] = 0B3h) then begin
        for j := 0 to 6 do begin
            longint(DS:6F70h + j * 4) := longint(DS:6F70h + j * 4)
                                       + p^[0FBh + j * 2];      { word 零延伸 }
            <本模組 003Bh>(p^[0FBh + j * 2], p);
        end;
        FillChar(p^[0FBh], 0Eh, 0);                             { 14 bytes ＝ 7 word }
    end;
    p := p^[189h];
end;
```

`retf`（無參數）。

### 金錢版面到此完全閉合

- 角色的 `+0FBh` 起是 **7 個 word**（`FillChar` 清 `0Eh` ＝ 14 bytes 直接證實）。
- 隊伍 Pool 的 `DS:6F70h` 起，本支只動 **j ＝ 0..6 共 7 個 longint**；spec 773
  數到的第 8 個不在其中。
- 兩者**索引一一對應**，與 `DS:0F93h` 的七個名稱（Copper / Silver / Electrum /
  Gold / Platinum / Gems / Jewelry，spec 773）同一套。
- 相加時 word 是**零延伸**（`xor dx,dx`）後才加進 longint，所以角色端不可能有
  負數金額。

### `003Bh` / `0057h` 是一對負重增減

三處呼叫互相印證：本支把錢移走後呼叫 `003Bh`；spec 793 的給錢在**給方減完**
呼叫 `003Bh`、**收方加完**呼叫 `0057h`；spec 786 的撿錢加完呼叫 `0057h`。
兩支的參數都是 `(金額, 角色)`。

### 篩選條件

只有 `+0F7h` ＝ `0` 或 `0B3h` 的角色會被收錢。`0B3h` ＝ `80h or 33h`，照 spec 758
的編碼還原就是**上限值 102**；`0` 則是旗標與數值都沒設。中間值一律跳過。

## `overlay-14:05E8h`（entry#8，81 條，差異 17 條）— 擲成功就打通兩側

```pascal
成 := 0;
p := DS:650Ah;
while (p <> NIL) and (成 = 0) do begin
    骰 := <0141h:004Dh>(1, 64h);                   { 1..100 }
    if (骰 <= p^[0EBh]) and (p^[195h] = 0) then 成 := 1;   { 骰是無號比較 }
    p := p^[189h];
end;
DS:7589h := 0;
if 成 <> 0 then begin
    <本模組 0153h>(DS:720Fh, DS:7210h, DS:7211h);
    <本模組 0153h>(DS:720Fh + byte[2694h + 方向],
                   DS:7210h + byte[269Dh + 方向],
                   (方向 + 4) mod 8);
end;
結果 := 成;
```

`retf`（無參數），回傳 `al`。

- **第一個擲中的人就結束**——排在後面的成員連骰都不擲。remake 要對齊亂數序列
  就不能改成「全隊都擲再取最好」。
- 判定用的是角色的 `+0EBh`（百分比）與 `+195h` ＝ 0（狀態正常）。
- 成功時對**同一道牆的兩側各呼叫一次** `overlay-14:0153h`：先是隊伍所在格與
  面向，再是該方向的鄰格與 `(方向 + 4) mod 8` 的對向。方向表 `DS:2694h` /
  `DS:269Dh` 與對向式子都是 spec 758 記過的那一組。
- `overlay-14:0153h` 是 spec 761 裡「**有範圍檢查**」的那一支（同模組的 `003Eh`
  沒有）——邊界上的格子由它擋掉。
- `DS:7589h` 不管成不成功都被清成 0。

隊伍位置的三個全域再一次確認：`DS:720Fh` ＝ x、`DS:7210h` ＝ y、`DS:7211h` ＝
方向（PC-98 `DS:0A2A9h` / `0A2AAh` / `0A2ABh`）。

## 明確不宣稱

- 沒有宣稱 `+0F7h` 的中間值代表什麼，也沒有宣稱為什麼要排除它們。
- 沒有宣稱 `DS:7564h` / `DS:7589h` 由誰讀。
- 沒有宣稱 `+0EBh` 是哪一項能力的百分比。
- 沒有宣稱 `overlay-14:0153h` 清掉的是哪一種牆位元（spec 761 只讀了 `003Eh`）。
