# 1006 — 第一人稱視野的完整幾何：11×11 格、10 個牆位、由遠而近三層

- 證據等級：`exact`（DOS 側 805 條逐條讀完，兩個未反組譯的洞已直接讀原始位元組
  補上；PC-98 對側 825 條，扣掉那兩個洞後助憶碼序列完全相同）
- 作法見 spec 783

## `dos overlay-30:00841h` ↔ `pc98 overlay-30:0078Bh`（`retf 6`）

兩側原本都是待解讀。這是**畫第一人稱迷宮視野的主程序**，spec 976 的畫面更新
每一格都會叫它。整支沒有字串。

### 簽章

三個參數都是 byte。第一個宣告的落在最高位址（`bp+0Ah`），
把它原樣轉給 `sub_6BDh`（spec 778，宣告順序 `(欄, 列, 方向)`）的第一格，
所以三個參數是：

```pascal
procedure 畫視野(欄, 列, 方向: byte);    { bp+0Ah, bp+08h, bp+06h }
```

⚠ 這順序也修正了 spec 781 對 `sub_11h`（自動地圖）的記法：
本支把同樣三個參數原樣轉給它，而 `sub_11h` 也是把第一個餵給 `sub_6BDh` 的
`欄` 位——**`sub_11h` 是 `(中心欄, 中心列, 朝向)`，不是 `(中心列, 中心欄, …)`**。

### 骨架

```pascal
if DS:720Eh <> 0 then begin              { PC-98 DS:0A2A8h }
    <sub_11>(欄, 列, 方向);              { ★ 改畫 11×11 自動地圖，spec 781 }
    exit
end;
<sub_18C>();                             { 視野面板外框，spec 997 }

左 := (方向 ＋ 6) mod 8;                 { 九格方向表，spec 999 }
後 := (方向 ＋ 4) mod 8;
右 := (方向 ＋ 2) mod 8;
cx := 欄 ＋ 2 × dx[方向];                { 先跳到「前方兩格」 }
cy := 列 ＋ 2 × dy[方向];

for 深度 := 2 downto 0 do begin
    case 深度 of 2: …；1: …；0: … end;
    cx += dx[後];  cy += dy[後];         { 每畫完一層就退一格 }
end;
<far 0297h:1316h>();                     { 收尾，把畫好的送上畫面 }
```

★ **由遠而近的畫家演算法**：`深度 2`（前方兩格）先畫，`深度 0`（腳下這一格）
最後畫，近處的牆自然蓋掉遠處的。

## ★★ 10 個牆位與它們在畫面上的位置

每一次貼圖都是 `<sub_448>(欄, 列, 圖號, 牆位)`（spec 780，`retf 8`，
最後宣告的那個參數才是 10 選 1 的形狀索引）。
`欄`／`列` 由**兩張各 10 筆、以牆位為索引的表**給出：

| 牆位 | 起始欄 `DS:0AF6h`（word） | 起始列 `DS:0B0Ah`（byte, 筆距 2） | 寬 `DS:0AE2h` | 高 `DS:0AECh` | 是什麼 |
|---|---|---|---|---|---|
| 0 | 5 | 4 | 1 | 2 | 深度 2 的正面牆 |
| 1 | 4 | 3 | 1 | 4 | 深度 2 的左側牆 |
| 2 | 6 | 3 | 1 | 4 | 深度 2 的右側牆 |
| 3 | 4 | 3 | 3 | 4 | 深度 1 的正面牆 |
| 4 | 2 | 1 | 2 | 8 | 深度 1 的左側牆 |
| 5 | 7 | 1 | 2 | 8 | 深度 1 的右側牆 |
| 6 | 2 | 1 | 7 | 8 | 深度 0 的正面牆 |
| 7 | 0 | 0 | 2 | 11 | 深度 0 的左側牆 |
| 8 | 9 | 0 | 2 | 11 | 深度 0 的右側牆 |
| 9 | 5 | 4 | 1 | 2 | 深度 2 的**接縫柱** |

PC-98 是同樣的兩張表、同樣的值，只是位址不同：
起始欄 `DS:16CAh`、起始列 `DS:16DEh`。

★ **視野是 11 格寬 × 11 格高的磚陣列**——`sub_448h` 的範圍檢查是 `0..0Ah`，
而牆位 7 從第 0 欄起算 2 欄、牆位 8 從第 9 欄起算 2 欄，正好貼滿左右兩邊。
牆位 6（腳下這格的正面牆）是 7 欄 × 8 列，貼在正中間。

★ **寬 × 高 的總和剛好是 156**：
`1×2 ＋ 1×4 ＋ 1×4 ＋ 3×4 ＋ 2×8 ＋ 2×8 ＋ 7×8 ＋ 2×11 ＋ 2×11 ＋ 1×2 ＝ 156 ＝ 9Ch`，
而 `DS:0AD8h` 那張「起始位移」表 `0, 2, 6, 10, 22, 38, 54, 110, 132, 154` 的
逐項差就是上面那十個乘積。
⇒ **每一種牆的圖形資料是一筆 156 bytes 的紀錄，十個牆位的磚依序接在裡面**，
`DS:7202h` 那個陣列的列距 `9Ch` 就是這麼來的。

## 三層各自的掃描

`var_12` 是每一步的橫向位移，加在起始欄上。

| 層 | 起點 | 步數 | 走向 | `var_12` | 畫哪幾個牆位 |
|---|---|---|---|---|---|
| 深度 2 | 中心格 | 4 | 左 | 0, −2, −4, −6 | 0（正面）＋ 9（接縫，欄 ＋1） |
| 深度 2 | 中心格 | 4 | 右 | 0, ＋2, ＋4, ＋6 | 0 ＋ 9（接縫，欄 −1） |
| 深度 2 | 中心格 | 3 | 左 | 0, −2, −4 | 1（左側牆；第一格不減，之後欄再 −1） |
| 深度 2 | 中心格 | 3 | 右 | 0, ＋2, ＋4 | 2（右側牆；第一格不加，之後欄再 ＋1） |
| 深度 1 | 中心往左 2 格 | 3 | 右 | −6, −3, 0 | 3（正面）＋ 4（左側牆） |
| 深度 1 | 中心往右 2 格 | 3 | 左 | ＋6, ＋3, 0 | 3 ＋ 5（右側牆） |
| 深度 0 | 中心往左 1 格 | 2 | 右 | −7, 0 | 6（正面）＋ 7（左側牆） |
| 深度 0 | 中心往右 1 格 | 2 | 左 | ＋7, 0 | 6 ＋ 8（右側牆） |

★ 每一層都是**左右兩趟對稱掃描**，兩趟在中心重疊。
越遠的層掃越寬（4 格），越近的層掃越窄（2 格）——
遠處一個畫面塞得下比較多格，是透視的必然。

★ 深度 1 與深度 0 的每一格都同時查兩個方向：`方向`（正面牆）與
掃描那一側（`左` 或 `右`，也就是朝向畫面中央的那一面）。
深度 2 則把正面與側面拆成兩趟走。

## ★ 牆位 9 是「一段牆結束時的收邊」

深度 2 的正面牆掃描帶一個狀態變數 `上一段`：

```pascal
w := <sub_6BD>(cx, cy, 方向);                       { 這一格的正面牆 }
if (<sub_556>(cx, cy) = 0)                          { ★ 出界（範圍 0..15） }
   and (<sub_6BD>(cx, cy, 內側) = 0) then 上一段 := 0;

if w <> 0 then begin
    if 上一段 > 0 then 畫(牆位 9, 上一段, 欄基準 ＋ var_12 ± 1);
    上一段 := w;
    畫(牆位 0, w, 欄基準 ＋ var_12);
end
else begin
    if (上一段 > 0)
       and (<sub_6BD>(cx − dx[走向], cy − dy[走向], 走向) <> 0) then
        畫(牆位 9, 上一段, 欄基準 ＋ var_12 ± 1);
    上一段 := 0;
end;
```

⚠ 收邊那一問問的是**上一格的走向那一面**（左掃問左、右掃問右；
`8F0h`／`9FAh` 推的方向暫存器分別是 `[bp−1]` 左與 `[bp−2]` 右＝各自的走向），
不是朝畫面中央的內側——內側只出現在上面「出界斷開」那一問。
engine 的 `drawWallFar` 兩處與 asm 相符。

`sub_556h`（spec 754）回 1 表示兩個座標都在 `0..15`。
⚠ 這裡用的是 `= 0`，也就是**出界**且內側也沒牆，才把 `上一段` 清掉——
所以走出地圖邊界時牆會「延續」而不是斷掉。

### 出界讀取的邊界模式由 `CURRENTECL` 決定，但對 CoAB 是死條款

`sub_6BDh` 對出界座標先看 `DS:8B5Eh`＝**CURRENTECL**（spec 1141）：
段編號是 `0` 或 `0Ah` 就直接回 0（地圖邊界不接起來），其他段才做
「`>15→0`、`<0→15`」的夾。⇒ 邊界要不要環繞是**寫死的段編號特例**，
不是資料旗標。實測六個 GEO 檔集的區塊 ID（`02..53h`）**沒有任何一張圖
掛在段 `0x00` 或 `0x0Ah` 底下** ⇒ 這個特例在本作永遠走環繞那一邊，
remake 一律環繞的行為等價（第 726 輪判定）。

## 兩平台差異

只有位址：

| | DOS | PC-98 |
|---|---|---|
| 自動地圖旗標 | `DS:720Eh` | `DS:0A2A8h` |
| 方向表 dx／dy | `DS:2694h`／`269Dh` | `DS:489Eh`／`48A7h` |
| 牆位起始欄／起始列 | `DS:0AF6h`／`0B0Ah` | `DS:16CAh`／`16DEh` |

表的**值完全一樣**，所以兩版的視野幾何相同。

## ⚠ 兩個洞不是缺程式碼

DOS 側的匯出在 `0AF6h..0AFDh`（8 bytes）與 `0B05h..0B2Fh`（43 bytes）沒有反組譯，
IDA 還把前者當成資料命名為 `word_AF6`。直接讀原始位元組：

```
0AF6:  50 b0 09 50 0e e8 4a f9        → push ax / mov al,9 / push ax / push cs / call sub_448
0B05:  83 46 ee 02 …  e9 f8 fe        → add var_12,2 / 走一格 右 / jmp 迴圈頭
```

兩段都是純程式碼，補回去之後 DOS 側 825 條，與 PC-98 一致。

★ 順帶澄清一個會誤導的命名：`mov ax, word_AF6` 的原始位元組是 `a1 f6 0a`
＝ **`mov ax, [DS:0AF6h]`**。overlay 被當成平坦二進位載入時，IDA 會把這個
`DS` 位移解成 overlay 自己的偏移並命名成 `word_AF6`，
**那是假的交叉參照**——真正的目標在常駐資料段。

## 中文化

本支沒有字串，但它定義了**視野面板佔畫面的哪一塊**（11×11 磚）。
中文化若要改字型高度或版面，這 11×11 與 spec 997 的面板外框要一起看。
