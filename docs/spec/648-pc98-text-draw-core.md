# 第六百四十八輪：日文文字輸出的核心迴圈，與兩個不一致的首位元組判準

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：PC-98 `PC98-GAME.EXE` 的 `16966h`、`169B6h`、`169D9h`、`169EDh`、`1546Fh`。

## `16966h`：把字串寫進文字 VRAM

```text
ES := 0A000h                          ← 字元碼平面
while CX <> 0 do
    al := [SI]; SI := SI + 1
    if al = 0 then break              ← 遇到 0 就停
    if <169D9h>(al) 判定為首位元組 then
        ah := al
        al := [SI]; SI := SI + 1      ← 取次位元組
        <169EDh>()                    ← SJIS → JIS
        ah := ah − 20h                ← 区號轉成 VRAM 的內部編號
        暫存 ax
        ES:[DI]   := ah
        ES:[DI+1] := al and 7Fh       ← 左半格：bit 7 = 0
        取回 ax
        ES:[DI+2] := ah
        ES:[DI+3] := al or 80h        ← 右半格：bit 7 = 1
        DI := DI + 4
        CX := CX − 2                  ← 佔兩格
    else
        ES:[DI]   := al
        ES:[DI+1] := 0                ← 半形：高位元組填 0
        DI := DI + 2
        CX := CX − 1
```

這是 PC-98 文字 VRAM 的全形字慣例：**一個全形字佔兩格**，兩格放同一個 JIS 碼，
靠低位元組的 **bit 7** 區分左半與右半。区號要先減 `20h`。

`CX` 是**剩餘格數**不是字數——全形字一次扣 2、半形扣 1。所以傳進來的長度單位是
畫面格數。

字串以 `0` 結尾，或 `CX` 用完為止，**兩個條件先到先算**。

### 對中文化的意含

這是必須整支換掉的地方。中文版走自備字型時，這個迴圈要改成「取 Big5 碼 → 查自備
字庫 → 把字模畫進圖形平面」，而不是把碼寫進文字 VRAM——
[spec 646](646-sjis-to-jis-conversion.md) 已說明漢字 ROM 沒有繁體字集。

「一個字佔兩格、靠 bit 7 分左右半」這個排版慣例本身可以留（中文字同樣是全形），
但**寫入的目標與內容都要換**。

## 判斷首位元組的是哪一支

`16966h` 呼叫的是 `169D9h`（[spec 574](574-pc98-shiftjis-and-text-vram.md) 的
「第二族」，上界 `F7h`），不是 `14342h`（上界 `FCh`）。兩族上界不同這件事 spec 574
已經記過；本輪補上的是**實際畫字的那條路徑走的是哪一族**——是 `F7h` 這一族。

同時確認了旗標方向：`clc` 代表前導。`16966h` 在 `call` 之後用 `jb` 跳往半形路徑，
所以**進位置起 ＝ 非前導**（方向容易記反，以這條 `jb` 為準）。

## 三份完全相同的 SJIS→JIS

`17186h`、`17DA9h`、`169EDh` **三者逐位元組完全相同**。
`169B6h` 與 `17D72h`（屬性平面填色）也逐位元組相同。

同一組顯示常式在 resident 裡被連結了三份（[spec 647](647-pc98-palette-and-attribute.md)
已記到其中兩份），各自服務不同的上游。

## `1546Fh`：字串處理三段式

```text
複製 arg_0 進區域緩衝（<sub_1AC99>，長度 50h）
<sub_142B9>(50h, 0, 18h, 0)
<sub_14E97>(區域緩衝, arg_4, arg_6, 18h, 0)
<sub_18036>()                         ← 回傳值存進區域變數後沒再讀
```

緩衝區 `50h` ＝ 80 bytes，正好是文字畫面一整列（[spec 645](645-pc98-text-layer-primitives.md)
的 `50h` 欄）。兩個呼叫都帶常數 `18h` 與 `0`。

## 明確不宣稱

- `169D9h` 上界為何是 `F7h`（是刻意排除造字區，還是寫錯）。
- 屬性 byte 的 `bit 0`／`bit 2` 對應什麼效果。
- `sub_1AC99`／`sub_142B9`／`sub_14E97`／`sub_18036` 的行為與常數 `18h` 的意義。
