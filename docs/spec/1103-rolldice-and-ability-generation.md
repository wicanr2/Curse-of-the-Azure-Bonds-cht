# 1103 — `ROLLDICE` 的參數是（骰數, 面數）；建角每個屬性擲六次取最大

- 狀態：`READY`
- 證據等級：`exact`（`overlay-23:0137Fh` 逐條讀完；建角側
  `overlay-17:00782h` 的 `1603h`..`16D4h` 逐條讀完；種族調整六個分支全部取出）
- 這一份解掉 spec 1093「明確不宣稱：屬性是用哪一種擲法」

## ★★★ 一、`ROLLDICE` 本體（`overlay-23` entry #9 → 局部 `137Fh`）

```pascal
function ROLLDICE(骰數, 面數: byte): byte;      { retf 4 }
begin
    總 := 0;
    if 骰數 > 0 then
        for k := 1 to 骰數 do
            總 := 總 ＋ (Random(面數) ＋ 1);      { Random ＝ RTL 0A54h:1105h }
    結果 := 總;
end;
```

> ★★★ **參數順序是（骰數, 面數）**。Turbo Pascal 由左而右推堆疊，
> 所以先宣告的參數落在較高的 `bp` 位移：`bp+8` 是迴圈次數（骰數）、
> `bp+6` 是傳給 `Random` 的上界（面數）。
> ★★ 每一顆是 `Random(面數) ＋ 1` ⇒ 值域 `1..面數`，
> **`ROLLDICE(n, s)` 就是標準的 `n d s`**，沒有偏移。
> ⚠ 骰數為 0 時回傳 0（不是恐慌）；回傳型別是 byte，`ROLLDICE(1, 100)`
> 的 100 剛好塞得下，更大的組合會截斷。

### 兩份既有規格的參數順序要以本規格為準

- spec 571 的 `ROLLDICE(1, 20)` ＝ 一顆 d20 ✓ 順序正確。
- spec 1087 原本寫 `ROLLDICE(6, 1)`／`ROLLDICE(100, 1)`，**參數順序寫反了**
  （文字描述「各擲一顆 d6」是對的）。實際位元組是
  `mov al,1; push ax; mov al,6; push ax`（`overlay-02:01730h`）
  ⇒ `ROLLDICE(1, 6)`。已改正。
- spec 1093／1101 引用的年齡表與起始金錢表都是（骰數, 面數），順序本來就對。

## ★★★ 二、建角的屬性擲點：`3d6 ＋ 1`，每個屬性擲六次取最大

`overlay-17:00782h` 的 `1603h`..`16D4h`：

```pascal
for i := 0 to 5 do begin                       { 屬性索引，外層迴圈到 2067h 才收 }
    角色^[11h ＋ i × 2] := 0;
    for k := 1 to 6 do begin                   { ★ 六次 }
        v := ROLLDICE(3, 6) ＋ 1;              { ★ 3d6 再 ＋1 ⇒ 4..19 }
        …套種族調整（見 §三）…
        if 角色^[11h ＋ i × 2] < v then         { ★ 無號比較，取最大 }
            角色^[11h ＋ i × 2] := v;
    end;
    …年齡三個門檻的增減（spec 1093 §五）…
    …夾進種族上下限與職業最低要求（spec 1093 §四）…
end;
```

> ★★★ **底層就是 3d6**——`ROLLDICE(3, 6)` 逐條讀完後沒有任何偏移。
> ★★ 但引擎在上面加了兩層：**每次多 ＋1**，而且 **每個屬性擲六次取最大**。
> 兩者都不是 AD&D 桌上規則，和 spec 850 的「HP 擲兩次取大」是同一類
> ——這個引擎系統性地偏向給玩家較高的值。
> ★ 寫入的是**目前值**（奇數位移 `+11h ＋ i × 2`，spec 1079）；
> 基準值那一組要到名字輸入之後才被抄（spec 1093 §六之二）。
> ⚠ `4..19` 會超過人類的 18 上限，多出來的部分在後面的夾值被切掉；
> 所以 `＋1` 的效果在上限附近會被吃掉，只在中段生效。

### 屬性索引順序

`0` 力量、`1` 智力、`2` 睿智、`3` 敏捷、`4` 體質、`5` 魅力
——與 spec 1093 §三 的種族上下限表同一組順序。

## ★★★ 三、種族屬性調整：七個種族逐條與 AD&D 一版相符

`1636h` 起是一個以 `角色^[74h]` 分派的 `case`，每個分支再比對屬性索引：

| `+74h` | 種族 | 力量 | 智力 | 睿智 | 敏捷 | 體質 | 魅力 | ＝ AD&D 1e |
|---|---|---|---|---|---|---|---|---|
| 1 | 矮人 | | | | | **＋1** | **−1** | ✓ |
| 2 | 精靈 | | | | **＋1** | **−1** | | ✓ |
| 3 | 地精 | | | | | | | ✓ 無調整 |
| 4 | 半精靈 | | | | | | | ✓ 無調整 |
| 5 | 半身人 | **−1** | | | **＋1** | | | ✓ |
| 6 | 半獸人 | **＋1** | | | | **＋1** | **−2** | ✓ |
| 7 | 人類 | | | | | | | ✓ 無調整 |

> ★★★ **七個種族全部命中 AD&D 一版的種族屬性調整**，包括半獸人的
> 力量 ＋1／體質 ＋1／魅力 −2 三項。
> ★ 地精、半精靈、人類走的是 `case` 的 `else`：沒有分支，也就沒有調整。
> ⚠ **半獸人有完整調整但建角選不到**（spec 1102 §一）——
> 與屬性上下限、可選職業、起始年齡一樣，資料齊全而選單不列。
> ★ 調整是**加在每一次擲點上再比大小**。因為是常數位移，
> `max(v_k ＋ 調整) ＝ max(v_k) ＋ 調整`，結果與「取最大之後才調整」相同。

## 對 remake 的意義

- 擲點：`3d6 ＋ 1`，每個屬性擲六次取最大，再套種族調整、年齡增減、夾值。
- 種族調整表要進 game pack JSON，不要寫死在 Go 裡。
- 若要改成純 3d6（不含 ＋1 與六次取最大），那是**偏離原版的設計決定**，
  應該在 remake 的規則文件裡標明，不要當成 RE 結論。

## 明確不宣稱

- 沒有宣稱 RTL `0A54h:1105h`（`Random`）的實作與亂數種子來源。
- 沒有宣稱 `＋1` 與「六次取最大」是刻意設計還是原作的遺留。
- 沒有宣稱 PC-98 對側（spec 1094）這一段是否逐條相同——
  spec 1094 記錄的差異塊裡沒有列到擲點，但本規格沒有實際比對。
