# 1168 — 戰鬥的 `USE` 分成哪幾類：253 件物品逐件盤點

- 證據等級：`exact`（原版物品逐件掃過；卷軸的判準由 spec 1171 讀出原作那一支）
- 前置：spec 905（選單條件）、spec 921（USE 的分派）；下游 spec 1169（九支物品效果 handler）、spec 1170（充能接進 remake）、spec 1171（卷軸）
- 產物：[`docs/audit/combat-item-use.md`](../audit/combat-item-use.md)（`cmd/item-use-audit`）

## 缺口有多大

原版六章 **253 件物品**：

| 類別 | 件數 | 按 USE 會怎樣 |
|---|---:|---|
| 卷軸（**類別表的槽** `0Bh`..`0Dh`）| 12 | 三個槽是三個法術，選一個來唸；非施法職業要擲 |
| 充能物品 | 18 | 效果 ＝ `+3Dh and 7Fh`，一定成功，然後扣充能 |
| 其他 | 223 | 兩條路都不成立，什麼都不會發生 |

充能那 18 件是玩家會實際用到的東西：治療藥水、極效治療藥水、速度藥水、
隱形藥水、巨人力量、魔法飛彈魔杖、粉塵、項鍊、三支法術魔杖。
**沒有 USE 就等於這些東西在戰鬥裡全部是死的。** 兩類都已接完
（充能見 spec 1170、卷軸見 spec 1171）。

## 卷軸的判準

原作判的是**類別表的第一格（裝備槽）**落在 `0Bh`..`0Dh`，不是物品類別
（`overlay-22 entry#6`，spec 1171）。物品類別 `3Ch` 的名字雖然叫 `Scroll`，
它的槽是 `0Ah` ⇒ 原作把它當**充能物品**（效果 `5Fh`／`60h`）。

## 充能物品要的東西全在原版資料裡

充能物品的效果編號就是**法術主表的列**（spec 921：`byte[37E5h ＋ 效果 × 10h]`
就是那張表的 `+0Ah`）。那一列**自帶目標模式**（`+6`，spec 1009）、豁免種類
（`+8`）、效果碼（`+0Ah`）與持續時間係數，骰子在各自的 handler 裡
（spec 1124／1169）。

12 個效果裡有三個是有名字的法術（`2Fh` 火球、`33h` 閃電、`57h` 冰風暴），
另外九個是主表裡**沒有名字的物品效果列**——九支 handler 都在 spec 1169 讀完了。

⇒ 接 USE 不需要新的內容決定：**照原版的列走就對了**。

## 選單

選單是**逐項串接**的（照 spec 905 的形狀）：`使用` 在身上有東西時才顯示
（原作的條件是 `角色^[14Ch] > 0`，有東西就顯示，不管能不能用）。

⚠ 還沒照條件收放的兩項，理由：

- `移動`：原作條件是 `MOVELEFT > 0`（22 bytes 戰鬥狀態的 `+06h`）。remake 沒有
  「這一回合還剩幾格」的模型——進移動模式時才由移動力現算，離開就歸零。
- `施法`：原作條件是三件事同時成立（有記憶法術、`CANCAST`、一個全域旗標）。
  remake 有前者，後兩者沒有對應狀態。

## 明確不宣稱

- 本篇只做分類與計數；兩條路各自的讀法在 spec 1170（充能）與 spec 1171（卷軸）。
