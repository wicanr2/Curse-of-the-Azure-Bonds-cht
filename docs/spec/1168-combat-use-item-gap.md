# 1168 — 戰鬥的 `USE` 還缺什麼：15 件充能物品、9 個沒宣告的效果

- 證據等級：`exact`（原版物品逐件掃過）＋ `derived`（卷軸的判準由資料推出並以
  fail-closed 檢查釘住）
- 前置：spec 905（選單條件）、spec 921（USE 的分派）
- 產物：[`docs/audit/combat-item-use.md`](../audit/combat-item-use.md)（`cmd/item-use-audit`）

## 缺口有多大

原版六章 **253 件物品**：

| 類別 | 件數 | 按 USE 會怎樣 |
|---|---:|---|
| 卷軸（類別 `3Ch`..`3Eh`）| 15 | 三個槽是三個法術，選一個來唸；非施法職業要擲 |
| 充能物品 | 15 | 效果 ＝ `+3Dh and 7Fh`，一定成功，然後扣充能 |
| 其他 | 223 | 兩條路都不成立，什麼都不會發生 |

充能那 15 件是玩家會實際用到的東西：治療藥水、極效治療藥水、速度藥水、
隱形藥水、魔法飛彈魔杖、粉塵、項鍊。**沒有 USE 就等於這些東西在戰鬥裡全部
是死的。**

## 卷軸的判準

原作判斷「是不是卷軸」的那一支（`loc_11DBh+3`）沒有讀出來。從資料推：
物品類別 `3Ch`（Scroll）、`3Dh`（Magic User Scroll）、`3Eh`（Clerical Scroll）。

⚠ 這是推的，所以 `cmd/item-use-audit` **逐件檢查等價關係**——「名字含 Scroll」
⟺「類別在這三個裡」。253 件全部成立；哪天不成立，這支工具會整個失敗，而不是
安靜地把某一件分錯類。

## 擋住 USE 的是資料不是程式

充能物品的效果編號就是**法術主表的列**（spec 921：`byte[37E5h ＋ 效果 × 10h]`
就是那張表的 `+0Ah`）。remake 已經有一條資料驅動的效果施法路
（`combatCastEffectSpell`，spec 1117）：效果碼、持續時間、豁免類別全部查表。

差的是**目標模式**——那一格不在原版的法術主表裡，是 game pack 的
`combat_player_spells` 宣告的。15 件充能物品用到的效果裡，**9 個還沒宣告**。

⇒ 接 USE 之前要先決定那 9 個效果各自的目標模式，而且要有證據。spec 921 提到
`+0Ah` 非 0 時會多呼叫一支「形狀上是要不要選目標」的常式——那是線索，但那一支
還沒讀，不足以直接生成 9 條宣告。

## 這一輪做了什麼

選單改成**逐項串接**（照 spec 905 的形狀），並讓 `使用` 誠實：身上沒有東西就
不顯示（原作的條件是 `角色^[14Ch] > 0`，也就是有東西就顯示，不管能不能用）。

⚠ 還沒照條件收放的兩項，理由：

- `移動`：原作條件是 `MOVELEFT > 0`（22 bytes 戰鬥狀態的 `+06h`）。remake 沒有
  「這一回合還剩幾格」的模型——進移動模式時才由移動力現算，離開就歸零。
- `施法`：原作條件是三件事同時成立（有記憶法術、`CANCAST`、一個全域旗標）。
  remake 有前者，後兩者沒有對應狀態。

## 明確不宣稱

- 沒有實作 USE 的動作本身。
- 沒有宣稱那 9 個效果各自的目標模式。
- 沒有宣稱卷軸那 15 件要怎麼選法術（`sub_3474h` 沒有讀）。
