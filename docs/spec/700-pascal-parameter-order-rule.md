# 第七百輪：Pascal 參數順序，與 16 bytes 物品表的真正基底

狀態：`READY`。等級：`exact`。日期：2026-08-14

## 一、宣告順序 ＝ 先推的在前

Turbo Pascal 由左而右推參數，所以**第一個宣告的參數被最先推入，落在最高位址**。
三支已讀完的函式各自的位移可以互相印證：

| 函式 | `retf` | `[bp+0Ah]` | `[bp+8]` | `[bp+6]` |
|---|---|---|---|---|
| `overlay-24:15FFh` | 8 | 角色（far） | — | 物品（far） |
| `overlay-23:23FBh`（`HEALDUDE`） | 8 | 角色（far） | 治療量 | 只治受傷者 |
| `overlay-07:1148h`（`STORESTRING`） | 6 | 位址 | — | 字串（far） |

所以

```text
HEALDUDE(角色, 治療量, 只治受傷者)
STORESTRING(位址, 字串)
```

呼叫端也對得上：`overlay-22:3F23h` 先推目標角色的 far 指標，再推治療量，最後推
`0`。

**這條要特別寫下來，是因為讀反組譯時看到的順序正好相反**——最後推的那個離
`call` 最近，最先被看到。既有台帳裡有兩筆就是照著閱讀順序寫的，方向反了：

- `HEALDUDE` 原記為 `(only_if_hurt, amount, char)`
- `STORESTRING` 原記為 `(s, addr)`（spec 687 已標為待查，本輪定案）

兩筆的**內容都正確**，只是參數列的順序反了。已改。

寫新註記時：參數順序一律照 `[bp+0Ah] → [bp+8] → [bp+6]`（位址由高到低）列，
不要照 `push` 出現的先後列。

## 二、物品屬性表的基底是 `DS:5CF6h` 不是 `DS:5D02h`

把 DOS 兩個平台所有「`shl di, cl`（`cl = 4`）之後接 `[di+XXXXh]`」的位址掃出來：

```text
5CF6h ×10   5CF7h ×5   5CF8h   5CF9h   5CFBh   5CFCh
5CFDh ×4    5CFFh      5D00h   5D01h   5D02h ×5  5D03h ×4  5D04h ×11
```

最小值 `5CF6h`、最大值 `5D04h`，跨度正好 `0Eh` ——落在同一筆 16 bytes 記錄裡。
所以

> 表的基底是 **`DS:5CF6h`**，一筆 16 bytes；`5D02h` 是格內 `+0Ch`、
> `5D04h` 是格內 `+0Eh`。

spec 691 寫「整張表從 `DS:5D02h` 起」是錯的，已改。索引一律是
`物品節點^[2Eh]`（spec 696 的類別編號）。

目前已知被讀的格內欄位：`+0`、`+1`、`+7`、`+0Ch`、`+0Dh`、`+0Eh`。

## 三、三支治療系 opcode（`overlay-22`）

```text
3F23h：if DS:7434h <> 0 then
           量 := ROLLDICE(2, 8) + 1                    ← 2d8+1
           if HEALDUDE(DS:7435h 的角色, 量, 0) then
               <overlay-24 entry#29>(角色)             ← 顯示 is fully/partially healed

43A7h：同上，量 := ROLLDICE(3, 8) + 3                  ← 3d8+3
```

兩支的差別只有骰子。配上既有的 `1d8` 那支，就是 AD&D 的治療三階
（輕傷 `1d8` ／ 重傷 `2d8+1` ／ 危傷 `3d8+3`）。

目標角色是 `DS:7435h`（低位）＋ `DS:7437h`（高位）組成的 far 指標，
`DS:7434h` 是「有沒有目標」的旗標——為 0 時整支什麼都不做，**連訊息都不顯示**。

`HEALDUDE` 的第三個參數固定 `0`，也就是**滿血的人也照治**（不會因為沒受傷而
回 false）——但 `HEALDUDE` 內部仍會因為狀態不在 `{0,1,4,5}` 而回 false。

## 四、`612Eh`：物品類別落在 11..13

```text
if 物品 = NIL then 回傳 0
v := byte [5CF6h + 物品^[2Eh] × 16]        ← 格內 +0
回傳 (10 < v < 14)                          ← jbe／jnb，兩邊都是無號
```

`0Ah` 與 `0Eh` 是**開區間的兩端**，成立的只有 11、12、13 三個值。

## 明確不宣稱

- `DS:7434h`／`7435h` 由誰設定。
- 格內 `+0` 那個值的語意（本輪只知道 11..13 是一類）。
- `overlay-22:4103h` 的參數切分——它把 `ROLLDAMAGEDICE(2, 4) + 2`、`8`、
  `CS:4102h` 的字串與三個先推的值一起交給 `sub_F06h`，中間還隔著會留殘留的
  `0A54:0634h`（spec 690），本輪不拆。
