# 第六百九十九輪：借用共用緩衝做查詢，用完還原

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：DOS `overlay-24:274Ch`。

## 流程

```text
備份 := Move(DS:6E97h → 區域, 0D8h)                  ← 216 bytes
DS:6E92h^[6] := 1
a := <overlay-32 entry#15>(arg_4, arg_6)             ← byte[973Dh + 4i + 0]
b := <overlay-32 entry#16>(arg_4, arg_6)             ← byte[973Dh + 4i + 1]
c := <overlay-32 entry#17>(arg_4, arg_6)             ← byte[973Dh + 4i + 3]
<overlay-31 entry#6>(a, b, 0FFh, 0FFh, c, DS:6E92h)  ← 這一支會填 DS:6E97h 那片
DS:6E92h^[6] := 0

k := 1
repeat
    idx := byte [6E94h + k×3]                        ← k=1 時就是 6E97h
    p   := far  [6D35h + idx×4]
    if p = (arg_0, arg_2) then 跳出
    if k >= DS:6E96h then 跳出
    k := k + 1

結果 := byte [6E95h + k×3] div 2                     ← cwd ＋ idiv 2，有號
Move(區域 → DS:6E97h, 0D8h)                          ← 還原
回傳 結果
retf 8
```

## 三件要注意的

**共用緩衝是借來的。** `DS:6E97h` 起 216 bytes 在進入時備份、離開時原樣寫回，
中間讓 `overlay-31 entry#6` 填進查詢結果。所以這支對外沒有副作用，但**它執行
期間那片緩衝的內容是壞的**——同一片被別人用時不能重入。

**找不到不會有訊號。** 迴圈的退出條件是「找到」或「`k` 已達 `DS:6E96h`」，
兩種情況都直接往下走，結果一律取 `第 k 筆` 的欄位。所以查不到時回傳的是
**最後一筆**的值，不是錯誤碼。呼叫端無法分辨。

**`div 2` 是有號除法不是右移。** `cwd` ＋ `idiv cx(=2)` 對負數是往零取整
（`−3 div 2 = −1`），寫成 `sar ax, 1` 會得到 `−2`。目前沒有證據說那個欄位會
是負數，但改寫時不能順手換成移位。

## 資料結構

| 位址 | 形狀 |
|---|---|
| `DS:6E97h` 起 | 每筆 3 bytes；`+0` 是索引、`+1` 是要回傳的值、`+2` 本輪沒被讀 |
| `DS:6E96h` | 上面那張表的筆數 |
| `DS:6D35h` 起 | 每筆 4 bytes 的 far 指標陣列，被 `+0` 的索引查 |
| `DS:6E92h` | far 指標；`+6` 被當成「查詢進行中」的旗標 |

`[6E94h + k×3]` 與 `[6E95h + k×3]` 的基底差 1，所以是同一筆的 `+0` 與 `+1`；
基底比表頭小 3，因為 `k` 從 1 起算。

`overlay-32` 那三支（entry#15／#16／#17）在 PC-98 側已讀完：同一個索引函式取
`DS:973Dh` 那張 4 bytes 一格的表的 `+0`／`+1`／`+3`，**`+2` 三支都沒有讀**。

## 明確不宣稱

- `overlay-31 entry#6` 做什麼、它的六個參數各是什麼。
- 兩個寫死的 `0FFh` 代表什麼。
- `DS:6D35h` 那張指標表指向什麼。
- `DS:6E92h^[6]` 這個旗標被誰讀。
