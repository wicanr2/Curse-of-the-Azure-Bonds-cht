# 第六百五十六輪：堆積串列的接上與移除

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：PC-98 `PC98-GAME.EXE` 的 `18810h`、`1883Eh`、`18883h`、`188C8h`。

## 節點是雙向串列

補上 [spec 655](655-heap-block-header.md) 標頭裡沒解出的兩個欄位：

| 位移 | 內容 |
|---|---|
| `+0` | 大小 |
| **`+2`** | **前一個**（segment） |
| **`+4`** | **後一個**（segment） |
| `+6` | 大小副本 |
| `+8` | 魔術數 `818Eh` |

## `18810h`：接到串列尾端

```text
bx := bx − 1                      ← 退回標頭
es := dx
while es:[+4] <> 0 do
    dx := es:[+4] ; es := dx      ← 一路走到尾
es:[+4] := bx                     ← 尾巴接上新節點
（新節點）:[+2] := 舊尾巴
（新節點）:[+4] := 0
```

**每次接尾都要走完整條串列**——`O(n)`。串列長時每次配置都掃一遍。

## `1883Eh`：從串列移除

```text
bx := bx − 1
next := es:[+4]
prev := es:[+2]
es(prev):[+4] := next
es(next):[+2] := prev
```

標準的雙向串列移除，但**兩邊都沒有檢查是不是 0**：

- 移除**頭節點**時 `prev = 0` → 寫入 `0000:0004`
- 移除**尾節點**時 `next = 0` → 寫入 `0000:0002`

`0000:0000` 起是**中斷向量表**。所以移除頭或尾會覆寫 INT 0／INT 1 的向量。

⚠ 這條需要 runtime 驗證再下最終結論。靜態證據只到「沒有 null 檢查」為止——實際
會不會發生，取決於呼叫端是否保證節點永遠在中間，本輪未追。同類標記見
[spec 626](626-goduel-and-charrec-size.md) 與 [spec 651](651-text-draw-wrappers.md)。

## `18883h`：配置並回填

```text
pushf ; std                        ← 設定方向旗標（本體沒有字串指令，是給被呼叫者用的）
ES:DI := arg 指的位置
es:[di] := 0
ax := arg 的大小
<sub_18612>()
es:[di+2] := bx
ax := 0FFFFh
if bx = 0 then                     ← 配置失敗
    ax := 0
    <sub_18862>() ; <sub_18862>()  ← 同一支連叫兩次
popf
```

`std` 之後到 `popf` 之間本體沒有任何字串指令，所以方向旗標是**設給被呼叫者**用的。
失敗路徑把同一支 `sub_18862` 呼叫兩次。

## `188C8h`：取三個值回填

```text
<186FFh>()                         ← 最大可用塊（spec 654）
es:[di]   := AX                    ← 最大值
es:[di+2] := BX
es:[di+6] := DX
```

`+4` 沒有寫——回填的是不連續的三格。

## 明確不宣稱

- `sub_18612`／`sub_18862` 的行為，以及後者為何連叫兩次。
- `188C8h` 回填的那個結構是什麼、`+4` 由誰填。
