# 1019 — 攻擊動作：轉向、耗彈、把射出去的東西掉在地上

- 證據等級：`exact`（DOS 側 268 條、PC-98 側 242 條，兩邊各自逐條讀完）
- 作法見 spec 783

## `dos overlay-13:019D8h` ↔ `pc98 overlay-13:01A59h`（`retf 12h`）

兩側原本都是待解讀。整支沒有字串。

`retf 12h` ＝ 9 word。從堆疊框看：

```pascal
procedure 攻擊(目標:   遠指標;   { bp+14h..17h }
               攻擊者: 遠指標;   { bp+10h..13h }
               旗標:   byte;     { bp+0Eh }
               物品:   遠指標;   { bp+0Ah..0Dh，可為 NIL }
               ?:      遠指標);  { bp+06h..09h }
```

## ★★ DOS 會把朝向正規化，PC-98 不會

DOS：

```pascal
if (攻擊者^[18Dh]^[0Fh] < 2) and (旗標 = 0) then begin
    d := <sub_29A2>(攻擊者, 目標);
    攻擊者^[18Dh]^[9] := (d ＋ 4) mod 8;        { ★ 轉向，取反方向 }
end
else if <overlay-32 entry#12>(0, 攻擊者) then begin
    d := 攻擊者^[18Dh]^[9];
    if 旗標 = 0 then 攻擊者^[18Dh]^[9] := (d ＋ 4) mod 8;
end;
```

PC-98 把兩段 `(d ＋ 4) mod 8` **整個拿掉**——`sub_29F4` 的結果直接當方向用，
`+18Eh^[9]`（PC-98 的對應欄位）在這一段完全沒有被寫。

> ⚠ **這是行為差異，不只是位址不同。**
> remake 要照哪一版是設計決定；本規格只記錄兩邊不一樣。

`sub_29A2`／`sub_29F4` 收兩個遠指標、回一個 0..7 的方向；
本支呼叫它兩次，兩次的參數順序相反（`(攻擊者, 目標)` 與 `(目標, 攻擊者)`）。

## ★★★ 物品節點大小：DOS 63 bytes、PC-98 103 bytes

耗彈那一段在彈藥用完時會**複製一份物品節點掉在地上**：

| | DOS | PC-98 |
|---|---|---|
| `GetMem` 的大小 | **`3Fh` ＝ 63** | **`67h` ＝ 103** |
| `Move` 的長度 | `3Fh` | `67h` |
| 鏈的 next | `+2Ah` | `+52h` |
| 數量 | `+39h` | `+61h` |
| `special(3)` | `+3Eh` | `+66h` |
| `itemptr` | `+2Eh` | `+56h` |

`67h − 3Fh = 28h`。

> ★★★ **物品節點在 PC-98 大 40 bytes，第三次獨立確認**
> （spec 1011 從除錯畫面的 13 個欄位量、spec 1013 從商店清單的
> `next` 位移量、這裡從 `GetMem` 的大小量）。
> 原因是名稱欄位加寬（spec 1013）。

## 流程

```pascal
DS:75E6h := 1;  DS:75E5h := 1;
DS:758Eh := DS:758Dh ＋ 0Fh;
…轉向（上一節）…
<overlay-32 entry#14>(0, 0, d, 攻擊者);              { 重畫攻擊者 }
d := <sub_29A2>(目標, 攻擊者);
<overlay-24 entry#5>(目標);
<overlay-32 entry#14>(0, 1, d, 目標);                { 重畫目標 }
目標^[18Dh]^[0Ah] := 攻擊者;                          { ★ 鎖定目標 }
延遲(100);                                            { PC-98：DS:7F16h × 25 }

if 物品 <> NIL then …依 itemptr ＝ 2Fh 或 65h 走 sub_2BFB…
if (攻擊者^[19Ch] = 0) and (攻擊者^[19Dh] = 0) then exit;

DS:6506h := 攻擊者;                                   { 換「現在在講誰」}
<sub_14E8>(…, 旗標, …);                              { 實際結算 }

if 物品 <> NIL then begin
    if 物品^.數量 > 0 then 物品^.數量 -= DS:75D7h;    { ★ 耗彈 }
    if 物品^.數量 = 0 then
        if <overlay-24 entry#42>(物品) and (物品^.special(3) <> 89h) then begin
            GetMem(新, 3Fh);  Move(物品^, 新^, 3Fh);   { ★ 複製一份 }
            新^.next := 遠指標(DS:6F8Ch);
            DS:6F8Ch := 新;                            { 掛進「地上的東西」}
            新^.ready := 0;
            <overlay-24 entry#17>(…);
            DS:650Eh := …;
        end;
end;
<overlay-24 entry#17>(…);
DS:6506h := <overlay-24 entry#7>(…);                  { spec 1000 的派生數值重算 }
```

★★ **`DS:6F8Ch` 就是 spec 1013 那條「商店存貨鏈」的同一格**——
射出去的箭掛在同一條鏈上，所以那條鏈其實是
**「現在這個地點地上有什麼」**，商店只是它的一種用法。

★ `special(3) = 89h`（137）的東西**射完不會掉在地上**（形狀上是消耗品／魔法飛彈）。
`DS:75D7h` 是「這一次消耗幾發」。

## ⚠ PC-98 的延遲又一次改成 `DS:7F16h × n`

DOS 寫死 `64h`（100），PC-98 是 `DS:7F16h × 19h`（25）。
spec 1015 在另一支看到的是 `× 32h`（50）——**比例逐處重調，不是固定換算**。

## 兩平台位址

| DOS | PC-98 |
|---|---|
| `DS:75E5h`／`75E6h` | `DS:0A877h`／`0A878h` |
| `DS:758Dh`／`758Eh` | `DS:0A81Fh`／`0A820h` |
| `DS:6506h`／`6508h` | `DS:9594h`／`9596h` |
| `DS:75D7h`（耗彈數） | `DS:0A869h` |
| 角色 `+18Dh`／`+19Ch`／`+19Dh` | `+18Eh`／`+19Dh`／`+19Eh`（＋1） |
| 物品欄位 | 全部 **＋28h** |

## 中文化

本支沒有字串。但「射出去的東西會變成地上的物品節點」這件事
決定了 remake 的物品生命週期，**節點大小要照 PC-98 的 103 bytes**
（名稱欄位加寬，spec 1013）。

## 明確不宣稱

- 沒有宣稱 `sub_29A2`／`sub_29F4` 怎麼算方向，也沒有宣稱兩次呼叫參數順序相反的用意。
- 沒有宣稱 `sub_14E8`（實際結算）與 `sub_2BFB` 做什麼。
- 沒有宣稱 `itemptr` ＝ `2Fh`／`65h` 是哪兩種物品。
- 沒有宣稱 `special(3) = 89h` 代表什麼。
- 沒有宣稱 `攻擊者^[19Ch]`／`+19Dh` 這兩格是什麼（形狀上是攻擊次數）。
- 沒有宣稱最後一個參數（`bp+06h` 的遠指標）的用途。
