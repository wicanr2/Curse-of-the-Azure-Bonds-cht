# 908 — 把單位放到地圖上：先備份被蓋住的地形

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側助憶碼完全相同，22 條差異全是位址）
- 作法見 spec 783

## `overlay-32:0115Bh` ↔ `overlay-32:01813h`（兩平台各 197 條）

`retf 0Ah` ＝ 5 個 word：`(旗標, 座標B, 座標A, 戰鬥員遠指標)`。回布林。

```pascal
if DS:4FBAh <> 5 then begin 結果 := 1;  離開 end;   { 不在戰鬥就直接成功 }

結果 := 0;
我 := <本模組 0CAEh>(戰鬥員);

byte[66A6h ＋ 我 * 4] := 戰鬥員^[0DEh] and 7Fh;     { 體型 }
byte[66A3h ＋ 我 * 4] := 座標A;
byte[66A4h ＋ 我 * 4] := 座標B;

<本模組 0D06h>(var 有1Ch, var 最貴地形, var ?, var 撞到誰, 8, 戰鬥員);  { spec 896 }

if (有1Ch <> 0) or (最貴地形 = 0)
   or (byte[26A2h ＋ 最貴地形 * 4] = 0FFh) then begin
    byte[66A6h ＋ 我 * 4] := 0;                     { 放不下 → 體型清 0 }
    goto 收尾;
end;

結果 := 1;
if (旗標 = 0) or (戰鬥員^[18Dh]^[13h] <> 0) then goto 收尾;

{ ① 這個戰鬥員先前的備份都清掉，順便取回原地形 }
for i := 1 to DS:6E91h do                           { 無號 }
    if 遠指標(DS:6E52h ＋ i * 7) = 戰鬥員 then begin
        if byte[6E58h ＋ i * 7] <> 1Fh then
            最貴地形 := byte[6E58h ＋ i * 7];
        FillChar(DS:6E52h ＋ i * 7, 7, 0);
    end;

{ ② 新位置有沒有別人的備份 }
重複 := 0;
for i := 1 to DS:6E91h do
    if (遠指標(DS:6E52h ＋ i * 7) <> NIL)
       and (byte[6E56h ＋ i * 7] = 座標A)
       and (byte[6E57h ＋ i * 7] = 座標B) then 重複 := 1;

if 重複 = 0 then
    遠指標(DS:6E92h)^[7 ＋ 座標B * 32h ＋ 座標A] := 最貴地形;

收尾:
<本模組 03EBh>();
```

## `DS:6E52h` ＝ 被蓋住的地形備份表，每筆 7 bytes

| 格內位移 | 位址寫法 | 內容 |
|---|---|---|
| `+0`（far） | `6E52h` | 蓋住這一格的戰鬥員遠指標（NIL ＝ 空欄） |
| `+4` | `6E56h` | 座標A |
| `+5` | `6E57h` | 座標B |
| `+6` | `6E58h` | 原本的地形碼（`1Fh` 是「沒存」的哨兵） |

筆數在 `DS:6E91h`（**索引 1 起算**，又一次「第 0 筆當 header」的慣例）。

`DS:6E91h` 與 `DS:6E92h`（spec 852／902 的地圖記錄遠指標）相鄰一個 byte——
兩塊是同一組資料的前後段。

移動時先把自己舊的備份清掉並**取回原地形**，再把原地形寫回地圖
（`遠指標(DS:6E92h)^[7 ＋ …]`，每列 `32h` ＝ 50，與 spec 902 一致）。
新位置若已經有別人的備份就**不寫**——避免把別人蓋住的地形覆蓋掉。

## 放不下的判斷靠 spec 896

`本模組 0D06h` 就是 spec 896 的「探一步」，這裡傳方向 `8`（原地，spec 854）。
三個條件任一成立就放不下：

- 有 `1Ch` 那種格（spec 862 的雲之一）
- 最貴地形 ＝ 0（不能通行）
- 地形表 `DS:26A2h ＋ 地形 × 4` 的 `+0` 移動成本 ＝ `0FFh`（也是不能通行）

放不下時把 `byte[66A6h ＋ 我 × 4]`（體型）**清成 0**——
spec 860／888 掃戰鬥員時就是用「體型 ＝ 0」跳過的，
所以清 0 等於「這個單位不在場上」。

## `戰鬥員^[0DEh]` 的最高位另有用途

存進體型時做了 `and 7Fh`，所以 `+0DEh` 的 bit 7 是別的東西。
本規格不宣稱是什麼。

## PC-98：22 條差異全是位址

`DS:66A3h`↔`−68C3h`、`DS:6E52h`↔`−6114h`、`DS:6E91h`↔`9F2Bh`、
`DS:6E92h`↔`9F2Ch`、`+18Dh`↔`+18Eh`。**助憶碼序列完全相同。**

## 明確不宣稱

- 沒有宣稱 `座標A`／`座標B` 哪個是 x 哪個是 y。
- 沒有宣稱 `本模組 0CAEh`／`03EBh` 各做什麼。
- 沒有宣稱 `戰鬥員^[18Dh]^[13h]` 在這裡的意義
  （spec 861 用同一格當「隊伍與怪物的分界標記」）。
- 沒有宣稱哨兵 `1Fh` 為什麼選這個值。
