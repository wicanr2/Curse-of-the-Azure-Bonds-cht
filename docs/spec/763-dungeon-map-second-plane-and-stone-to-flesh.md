# 763 — 迷宮地圖的第二個平面、石化解除，與治療量的三級累加

- 證據等級：`exact`（以補洞後的匯出逐條讀完，見 spec 761）

## 迷宮地圖至少有兩個 256-byte 平面

`overlay-30:07C6h`（DOS，`retf 4`）：

```pascal
if not 本模組 0556h(row, col) then          { spec 754：兩個參數都要在 0..15 }
    if (DS:8B5Eh = 0) or (DS:8B5Eh = 0Ah) then begin 結果 := 0; 離開 end;
{ 在範圍內，或 DS:8B5Eh 不是那兩個值 → 往下環繞 }
if col > 0Fh then col := 0  else if col < 0 then col := 0Fh;
if row > 0Fh then row := 0  else if row < 0 then row := 0Fh;
結果 := DS:7206h^[200h + (row shl 4) + col];
```

同一個 `DS:7206h` 遠指標、同一個 `(row shl 4) + col` 索引，但這裡讀的是
**`+200h`**，spec 761 的清牆讀的是 **`+300h`**。兩個平面各 `10h × 10h = 100h`
bytes，剛好首尾相接（`+200h`..`+2FFh` 與 `+300h`..`+3FFh`）。

另外一個結論：**座標可以環繞**。超出 0..15 時不是錯誤，而是繞到另一邊——
除非 `DS:8B5Eh` 是 `0` 或 `0Ah`，那時候直接回 0。所以 `DS:8B5Eh` 是決定
「地圖邊界要不要接起來」的模式值。

## PC-98 `overlay-04:0B31h` — 石化解除

`retf`，不收參數。兩段訊息把它定住：

| 位址 | 內容 |
|---|---|
| `CS:0AFDh` | `は石になってはいませんよ`（24 bytes） |
| `CS:0B16h` | `ストーン・トゥ・フレッシュ`（26 bytes） |

```pascal
答 := 'Y';
if DS:9594h^[196h] <> 7 then begin
    顯示('は石になってはいませんよ');
    答 := 本模組 0051h;              { spec 760：接著問「それでもかけてもらいますか？」}
end;
if 答 = 'Y' then begin
    顯示('ストーン・トゥ・フレッシュ');
    答 := 本模組 0103h(7D0h);        { 7D0h = 2000 }
    if (答 = 'Y') and (DS:9594h^[196h] = 7) then begin
        DS:9594h^[196h] := 0;        { 狀態回正常 }
        DS:9594h^[197h] := 1;
        DS:9594h^[1A5h] := 1;        { 目前 HP := 1 }
    end;
end;
```

由此定住兩件事：

- **狀態欄位（PC-98 `+196h`，DOS `+195h`）的值 `7` 代表石化**。
- 解除之後狀態歸 0、HP 設成 1，另外 `+197h`（DOS `+196h`）設成 1。

`7D0h` ＝ 2000 是傳給確認程序的數字，位置與金額相符，但**沒有在這支裡看到
扣款**，所以只記「傳了 2000 進去」。

比對用：`DS:9594h` 是「目前選中的角色」（PC-98），對應 DOS 的 `DS:6506h`。

## PC-98 `overlay-13:2D1Eh` — DOS `2EACh` 的對應

與 spec 762 的 `overlay-13:2EACh` 逐條同構：走 `DS:9598h` 隊伍鏈，取指定陣營
（`+198h`）中 `本模組 0124h(p) div 2` 的最大值。PC-98 的欄位是
`+198h`／`+197h`／`+18Ah`。

## PC-98 `overlay-15:2020h` — 三級治療量累加

`retf 2`，唯一的參數是 SS 相對的記錄位址：

```pascal
總量 := 0;
for i := 1 to ss:[p−4] do 總量 := 總量 + ROLLDICE(1, 8);          { 1d8 }
for i := 1 to ss:[p−6] do 總量 := 總量 + ROLLDICE(2, 8) + 1;      { 2d8+1 }
for i := 1 to ss:[p−8] do 總量 := 總量 + ROLLDICE(3, 8) + 3;      { 3d8+3 }
ss:[p−2] := ss:[p−2] + 總量;
```

三個級距 **1d8 / 2d8+1 / 3d8+3**，各自的次數放在 `p−4`／`p−6`／`p−8`，結果
累加到 `p−2`。後兩級與既有記錄的治療階梯（`2d8+1`、`3d8+3`）一致。

**骰出來就直接累加，沒有任何上限檢查**——`總量` 是 word，`ss:[p−2]` 也是
word，次數是 byte（最多 255），三級全滿的理論上限是
`255 × 8 + 255 × 17 + 255 × 27 = 13260`，不會溢位。

## IDA 的 `arg_N` 名稱不可信（再一次）

`overlay-15:2020h` 裡 IDA 把**同一個位移**印成兩種名字：

```
202B  mov di, [bp+arg_2]      8b7e06
20C5  mov di, [bp+6]          8b7e06
```

四處的位元組全都是 `8b7e06`（`[bp+06h]`）。若照名字讀會以為有兩個參數、而且
其中一個超出 `retf 2` 的參數區（誤判成「堆疊殘留當引數」）。**判定參數一律看
位移位元組，不看 IDA 的名字**（同 spec 700）。
