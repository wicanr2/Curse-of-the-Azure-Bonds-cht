# 837 — AI 的移動方向表：六種模式各有五個候選方向

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側**助憶碼完全相同**，22 條差異全是位址；
  兩張表取自常駐資料段 dump）
- 作法見 spec 783

## `overlay-09:00735h`（entry#13，兩平台各 246 條）

`retf 0Ch` ＝ 6 個 word。依宣告順序：`(角色, 候選序號, 基準方向, @結束旗標)`。

```pascal
結束^ := 0;
偏移 := byte[2B6h + 角色^[18Dh]^[15h] * 5 + 候選序號];
d    := (基準方向 + 偏移) mod 8;

<far 193Eh+1>(角色, d, @a, @地形, @b, @c);

if 地形 = 0 then begin 結束^ := 1; 離開 end;        { 走到底了 }
if byte[26A2h + 地形 * 4] = 0FFh then begin 結果 := 0; 離開 end;

if odd(d) then 花費 := byte[26A2h + 地形 * 4] * 3   { 斜向 }
else           花費 := byte[26A2h + 地形 * 4] * 2;  { 正向 }

if a <> 0 then 離開;
if 花費 >= 角色^[18Dh]^[06h] then 離開;             { 無號 }

if b <> 0 then begin
    if not (有效果(20h) or 有效果(1Eh) or 有效果(6Fh)
            or 有效果(7Dh) or 有效果(81h) or 有效果(3Fh))
       and (角色^[18Dh]^[10h] = 0)
       and not <far 1458h>(角色, 0, 0) then
        花費 := 角色^[18Dh]^[06h] + 1;              { 過不去 }
end;

if c <> 0 then begin
    if (有號(角色^[0E5h]) < 7)
       and not (有效果(81h) or 有效果(6Fh) or 有效果(85h))
       and (角色^[18Dh]^[10h] = 0)
       and not 有效果(7Dh) then
        花費 := 角色^[18Dh]^[06h] + 1;
end;

結果 := (花費 <= 角色^[18Dh]^[06h]);                { 無號 }
```

`有效果(碼)` ＝ `<far 1577h>(角色, 碼, @暫存)`。

## `DS:2B6h`（PC-98 `DS:06AAh`）：模式 × 5 的方向偏移表

索引式 `base + 模式 × 5 + 序號`，**序號是 1..5**（用 0 會讀到前一張表的尾巴，
DOS 那裡是 `89 8B 8E 90 1F`、PC-98 是 `0D` × 6，兩邊不同且不在 1..8 範圍內——
這正好反證序號不會是 0）。

模式就是 spec 830 認出來的 `+18Dh^[15h]`（AI 行為模式 1..6）。**兩平台 30 個 byte
完全相同**：

| 模式 | 五個偏移 | 換算成相對方向 |
|---|---|---|
| 1 | 8, 7, 6, 1, 2 | 前、左 45°、左 90°、右 45°、右 90° |
| 2 | 8, 1, 2, 7, 6 | 前、右 45°、右 90°、左 45°、左 90° |
| 3 | 7, 1, 8, 6, 2 | 左 45°、右 45°、前、左 90°、右 90° |
| 4 | 1, 7, 8, 2, 6 | 右 45°、左 45°、前、右 90°、左 90° |
| 5 | 8, 7, 6, 5, 4 | 前、左 45°、左 90°、左 135°、後 |
| 6 | 8, 1, 2, 3, 4 | 前、右 45°、右 90°、右 135°、後 |

換算依據：`d := (基準方向 ＋ 偏移) mod 8`，所以偏移 `8` ＝ 不轉、`1` ＝ ＋45°、
`7` ＝ −45°、`2` ＝ ＋90°、`6` ＝ −90°、`3`／`5` ＝ ±135°、`4` ＝ 180°。

**六種模式的行為就此定名**：

- **1／2** ＝ 直線衝，卡住就先試小角度，一個偏左、一個偏右。
- **3／4** ＝ 斜著切，正前方反而排第三。
- **5／6** ＝ **左手法則／右手法則繞行**——一路往同一邊轉到 180°，是典型的沿牆走。

對照 spec 830 的重骰分佈：模式 1..4 各 7/32、模式 5／6 各 1/16，而且 5／6 **每回合
必重骰**。所以繞行行為只會出現一回合，不會黏住。

## `DS:26A2h`（PC-98 `DS:48ACh`）：4 bytes 一筆的地形表

`+0` 是移動成本，**`0FFh` ＝ 不可通行**。本次 dump 到的區段裡 `+0` 只有 `01h` 與
`0FFh` 兩種值，兩平台逐 byte 相同。

**斜走貴 1.5 倍**：正向 `成本 × 2`、斜向 `成本 × 3`。所以 `+18Dh^[06h]`（移動力，
spec 806）的單位是「半格」——remake 直接照抄這個 ×2／×3 就會對。

## 兩種障礙、兩組豁免效果

| | 觸發 | 豁免條件（任一成立就照走） |
|---|---|---|
| 障礙 A | `b ≠ 0` | 效果 `20h`／`1Eh`／`6Fh`／`7Dh`／`81h`／`3Fh` 之一、或 `+18Dh^[10h] ≠ 0`、或 `far 1458h(角色, 0, 0)` |
| 障礙 B | `c ≠ 0` | **最高職業等級 `+0E5h` ≥ 7**、或效果 `81h`／`6Fh`／`85h`／`7Dh` 之一、或 `+18Dh^[10h] ≠ 0` |

擋不過去的寫法是**把花費灌成移動力 ＋ 1**，讓最後那道 `花費 ≤ 移動力` 必定失敗——
不是直接 return。兩個障礙區塊會依序執行，後面那個會覆蓋前面算出來的花費。

`+0E5h ≥ 7` 用的是**有號**比較（`jl`），其餘門檻都是無號。

## PC-98：全部是位址差

22 條差異：`+18Dh`↔`+18Eh`、`DS:2B6h`↔`DS:06AAh`、`DS:26A2h`↔`DS:48ACh`，
其餘是呼叫目標。**沒有邏輯差異。**

`far 193Eh+1` ＝ `overlay-32 entry#19`，四個回填值與兩個障礙的地形碼
（`b` ＝ `1Eh`、`c` ＝ `1Ch`）見 [spec 1119](1119-combat-terrain-obstacles.md)。

## 明確不宣稱

- 沒有宣稱基準方向那個參數是不是角色的朝向（`+18Dh^[09h]`）——本支只把它當加數。
- 沒有宣稱效果碼 `1Eh`／`20h`／`3Fh`／`6Fh`／`7Dh`／`81h`／`85h` 各是什麼法術效果。
- 沒有宣稱 `DS:26A2h` 那筆記錄的 `+1`／`+2`／`+3` 三個欄位是什麼。
- 沒有宣稱模式 7 那一列（`8, 4, 6, 2, 8`）會不會被用到——AI 模式的範圍是 1..6。
