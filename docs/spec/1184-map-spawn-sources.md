# 1184 — 進場落點是誰決定的：逐張第一人稱地圖的盤點

- 證據等級：`exact`（原版 ECL 控制流走訪 ＋ game pack 宣告值，逐張對照）
- 上游：spec 1183（原作沒有「換 block 的引擎進場放置」）、spec 1172
  （`ViewMirror.Block`）
- 產物：`cmd/map-spawn-audit`、`docs/audit/map-spawn-sources.md`

## 問題

spec 1183 確定原作沒有引擎側的進場放置——落點是**腳本自己寫的**。
於是 `ViewMirror.Block`（擋住舊 block 的座標蓋掉 game pack 宣告的 `spawn`）
就不再是模型問題，而是**逐張地圖的資料問題**：

- 腳本自己寫了進場座標的地圖 ⇒ 該讓腳本贏，宣告值是多餘的。
- 腳本沒寫的 ⇒ 宣告值是 remake 的補值，必須留。

那就去數。

## 結果

| 判定 | 張數 |
|---|---:|
| `script-only`（腳本有寫座標，**沒有**宣告 `spawn`）| 15 |
| `area-default`（沒有 `script_block`，只當同 area 的退回值）| 3 |
| `mismatch`／`declared-only` | **0** |

18 張裡帶 `script_block` 的地圖**全部不宣告 `spawn`**：落點一律由腳本決定。

## 曾經有四張宣告值，第 706 輪判定為冗餘並刪除

`aebffe77`（2026-08-10 大批接圖）曾為四張圖填了 `spawn` 宣告值
（猶拉什 `(0,3,2)`、猶拉什地下二層 `(15,14,4)`、眼魔洞穴 `(5,7,6)`、
巫師塔 `(7,15,6)`）。本規格第一版把它們標成 `mismatch`（沒有一組**靜態可達**的
腳本立即數等於宣告值），並要求用原版判掉。第 706 輪判掉了，判法是**執行期**：

1. **把四張宣告全部拆掉，整套行為測試不變綠**——含 23 段主線
   （`TestRealNewGameRunsToTheEnding`）、47 條 `NEWECL` 交接、
   114 份快照按鍵走訪。主線測試裡釘著的落點斷言
   （地下二層 `(15,14,4)`、眼魔洞穴 E1 `(5,7)`）**在無宣告下照樣成立**。
2. ⇒ 宣告值不是另一個真相來源，**它們是把腳本執行期產生的落點抄了一份**。
   「mismatch」是靜態掃描的盲區：走位迴圈（猶拉什 `192Ah`，spec 332）、
   執行期分派（地下二層）與交接前寫入（巫師塔 `0x32@0549h`）都不會以
   「目的段內的立即數座標」形式出現。
3. 依本規格自己的判準「腳本對就把宣告值刪掉」——四張已刪
   （`gamepack/pack/00-core.json`），schema 測試改鎖「不宣告」。

## 下水道／火刀據點的入口落點：原版落**第 0 列**（第 711 輪 oracle 判定）

自製存檔把原版放到觸發格、往前一步跨界，讀落點：

| 交接 | 觸發 | 腳本寫的 | 原版實測 | remake 現況 |
|---|---|---|---|---|
| 提爾弗頓 `0x02` → 下水道 `0x03` | (10,15) 朝南跨南界 | `y:=0, x:=x−10` ⇒ (0,0) | **(0,0)**（區域地圖隊伍標記在左上角，預測核對 ok；這張圖畫面不顯示座標）| (0,1) |
| 下水道 `0x03` → 火刀據點 `0x04` | (10,15) 朝南跨南界 | `y:=0, x:=x−2` ⇒ (8,0) | **(8,0) 朝南**（畫面座標列直接顯示 `8,0 S`，並接著觸發 (8,0) 的「檢查哨屍體」事件）| (8,1) |

證據截圖在
[`docs/reference/original-dos/entrance-landing/`](../reference/original-dos/entrance-landing/)。
⇒ **原版的落點就是腳本寫的值，沒有「進場後再多走一步」**。remake 先前的
(0,1)／(8,1) 是偏差：交接腳本在 `CALL C01Eh` **之後**才寫最終座標
（`ECL2/0x03:0160h` C01E → `016Ah` y:=0 → `0170h` x:=x−2 → NEWECL），
原作行內執行、後面的寫入蓋掉那一步；remake 把 CALL 副作用延後到執行結束
才套，就把那一步蓋在最終座標上。修法見下節；端到端測試已改釘第 0 列。

## 這對 `ViewMirror.Block` 的意義（第 711 輪已修）

四張宣告值與兩個入口落點都判掉了。擋板從「只認目前 block」放寬成「認**本次
執行跑過的 block**」（`RunResult.SessionRanBlockIDs`）：交接來源段寫好的落點
照原作生效，(0,1)／(8,1) 的偏差消失；猶拉什入口的收尾朝向（走位後
`1991h SAVE 01 C04D`，朝東）也因此接上，與被刪掉的宣告抄本 `(0,3,2)` 一致。
那一格**留著**，剩下的保護只有一件事：更早的執行殘留的舊座標，不可蓋掉
三張 `area-default` 的載檔／直入補值。

## ⚠ 第一版把猶拉什判成 `script-agrees`

`1991h` 那一組**只寫朝向**（`SAVE 01 C04D`，走位收尾）。第一版的比對只看
「有寫的欄位」是否相符，於是 X 與 Y 都是 nil 的那一組**無條件相符**，猶拉什就
被判成「宣告值等於腳本寫的」——正好是最需要被標成 `mismatch` 的那一張。

判準改成「必須同時寫過 X 與 Y」。朝向沒寫仍然不比對：只寫座標、朝向刻意不變
是原作的常見形狀（spec 1157 的 23 處退回上一格）。

## 方法與盲點

- 走訪與 `cmd/ecl-cell-refs` 同一條路（五個生命週期入口 ＋ 跟跳躍）。
  跟不到的碼不會出現 ⇒ **查無寫入不代表不存在**。
- **只收立即數**：`SAVE 4BF0 C04B` 是把別的格子搬進來（退回上一格），
  不是進場放置。
- 位址相差 24 bytes 以內併成同一組（原作那幾組是三條連續的 `SAVE`，各 6 bytes）。
- 這支**不判**哪一組才是「進場」那一組。一個 block 通常有好幾組（進場一組、
  劇情傳送好幾組），要哪一組是進場得看呼叫關係與條件——下水道那一組
  （`ECL2/0x03:00DBh`）就掛在 `IF 4C2A = 1` 底下的 `GOSUB` 裡。

## 進場寫入的三種形狀（靜態掃描各有一個盲區）

原作的進場落點確實都是腳本寫的，但寫它的位置有三種，第一版只掃得到第一種：

1. **目的段內的立即數**（`SAVE <imm> C04B/C04C/C04D`）——`script-only` 那 15 張。
2. **來源段在 `NEWECL` 前寫好**——巫師塔：

   ```
   ECL5/0x32  0513 PRINTCLEAR "YOU ARE HEADING UP INTO THE WIZARD'S TOWER."
              0537 SAVE 07 → C04B
              053D SAVE 0F → C04C
              0543 SAVE 03 → C04D
              0549 NEWECL 33
   ```

   `(7, 15, 3×2 = 6)`。`cmd/map-spawn-audit` 加掃「`NEWECL <目的地>` 前面
   48 bytes 內的座標組」之後看得到這一種（`script-agrees-incoming`）。
   ⚠ 只掃同一個成員：`NEWECL` 的運算元是 block 編號，編號跨成員會重複。

3. **執行期才決定**——走位迴圈（猶拉什 `192Ah` 查表驅動的 `CALL C01Eh`，
   spec 332）與 GETTABLE 分派帶到的寫入（猶拉什地下二層、眼魔洞穴——這三張
   從世界地圖那一側換 area 進來，同成員內沒有任何 `NEWECL` 切入）。靜態走訪
   **結構上跟不到**，只能拿執行期驗（第 706 輪的拆宣告實驗就是這一種證據）。

## 明確不宣稱

- 沒有宣稱 `ViewMirror.Block` 可以整格拆掉——三張 `area-default` 退回值仍靠它
  擋更早執行殘留的舊座標；放寬後的判準是「本次執行跑過的 block」。
- 沒有宣稱三張 `area-default` 的值對過原版。它們只在載檔／直入這類「沒有腳本
  跑過」的路徑上生效。
