# 1184 — 進場落點是誰決定的：逐張第一人稱地圖的盤點

- 證據等級：`exact`（原版 ECL 控制流走訪 ＋ game pack 宣告值，逐張對照）
- 上游：spec 1183（原作沒有「換 block 的引擎進場放置」）、spec 1172
  （`ViewMirror.Block`）
- 產物：`cmd/map-spawn-audit`、`docs/audit/map-spawn-sources.md`

## 問題

spec 1183 確定原作沒有引擎側的進場放置——落點是**腳本自己寫的**。
於是 `ViewMirror.Block`（擋住舊 block 的座標蓋掉 game pack 宣告的 `spawn`）
就不再是模型問題，而是**逐張地圖的資料問題**：

- 腳本自己寫了進場座標的地圖 ⇒ 該讓腳本贏，宣告值是多餘的。
- 腳本沒寫的 ⇒ 宣告值是 remake 的補值，必須留。

那就去數。

## 結果

| 判定 | 張數 |
|---|---:|
| `script-only`（腳本有寫座標，**沒有**宣告 `spawn`）| 11 |
| `mismatch`（有宣告 `spawn`，但沒有一組腳本座標等於它）| 4 |
| `area-default`（沒有 `script_block`，只當同 area 的退回值）| 3 |
| `script-agrees` | **0** |
| `declared-only` | **0** |

★ **沒有任何一個宣告值等於腳本寫過的座標。** 這四個宣告值不是「把腳本的進場
寫入抄下來」，它們是另外一個來源——多半是走位動畫的**終點**或觀察到的位置。

四個對不上的：

| 地圖 | ECL/block | 宣告值 | 腳本寫過的座標 |
|---|---|---|---|
| `original.geo3.block-10`（猶拉什）| 3/`0x10` | `(0,3,2)` | `006Ch`(0,8,6)、`0127h`(1,0,4)、`014Ch`(0,6,2)、`0C7Eh`(2,5,2)、`0D24h`(1,5,2)、`1569h`(5,4,6) |
| `original.geo3.block-11-level-2` | 3/`0x12` | `(15,14,4)` | `0039h`(11,14,4) |
| `zhentil-keep.beholder-cave` | 4/`0x22` | `(5,7,6)` | `0029h`(12,7,6)、`061Bh`(13,1,6) |
| `original.geo5.block-33` | 5/`0x33` | `(7,15,6)` | `022Bh`(3,1,4)、`088Bh`(6,15,—) |

猶拉什那一列自己就解釋了這個模式：`(0,3)` 是護送段**走完四步之後**停的格子
（spec 332），腳本從來沒有把它當立即數寫過。宣告值記錄的是「玩家最後在哪」，
不是「腳本把隊伍放在哪」。

## 這對 `ViewMirror.Block` 的意義

它保護的是**四個還沒被判過的宣告值**，不是 18 張地圖。其餘 11 張根本沒有宣告
`spawn`，落點只能來自腳本，那一格對它們是 no-op。

要拿掉它，得先用原版當 oracle 把那四個判掉：宣告值對就讓宣告值贏（並說明它
為什麼不等於任何一次腳本寫入），腳本對就把宣告值刪掉。

## ⚠ 第一版把猶拉什判成 `script-agrees`

`1991h` 那一組**只寫朝向**（`SAVE 01 C04D`，走位收尾）。第一版的比對只看
「有寫的欄位」是否相符，於是 X 與 Y 都是 nil 的那一組**無條件相符**，猶拉什就
被判成「宣告值等於腳本寫的」——正好是最需要被標成 `mismatch` 的那一張。

判準改成「必須同時寫過 X 與 Y」。朝向沒寫仍然不比對：只寫座標、朝向刻意不變
是原作的常見形狀（spec 1157 的 23 處退回上一格）。

## 方法與盲點

- 走訪與 `cmd/ecl-cell-refs` 同一條路（五個生命週期入口 ＋ 跟跳躍）。
  跟不到的碼不會出現 ⇒ **查無寫入不代表不存在**。
- **只收立即數**：`SAVE 4BF0 C04B` 是把別的格子搬進來（退回上一格），
  不是進場放置。
- 位址相差 24 bytes 以內併成同一組（原作那幾組是三條連續的 `SAVE`，各 6 bytes）。
- 這支**不判**哪一組才是「進場」那一組。一個 block 通常有好幾組（進場一組、
  劇情傳送好幾組），要哪一組是進場得看呼叫關係與條件——下水道那一組
  （`ECL2/0x03:00DBh`）就掛在 `IF 4C2A = 1` 底下的 `GOSUB` 裡。

## 明確不宣稱

- 沒有宣稱四個對不上的宣告值是錯的。它們可能記錄的是原版實機的落點，而腳本
  那一組是別的劇情分支——要跑原版才知道。
- 沒有宣稱提爾弗頓下水道端到端測試裡那個 `(0,1)` 是哪來的。它**不是**宣告值
  （`tilverton.sewers.first-person` 沒有宣告 `spawn`），也不是 game pack 的
  `set_map_position`（area 2 只有一筆，是 `(13,10)`）。還沒查。

## ★★ 四個 `mismatch` 判掉一個：巫師塔的宣告值是對的，證據在**別的段**裡

第一版只掃**目的地那一段**的 `SAVE ... C04B/C04C/C04D`。原作的進場落點確實是
腳本寫的，但寫它的腳本常常在**來源那一段**：

```
ECL5/0x32  0513 PRINTCLEAR "YOU ARE HEADING UP INTO THE WIZARD'S TOWER."
           0537 SAVE 07 → C04B
           053D SAVE 0F → C04C
           0543 SAVE 03 → C04D
           0549 NEWECL 33
```

`(7, 15, 3×2 = 6)` 與 game pack 宣告的 `(7,15,6)` **逐欄相符**。
⇒ `cmd/map-spawn-audit` 加掃「`NEWECL <目的地>` 前面 48 bytes 內的座標組」，
判定多一種 `script-agrees-incoming`。

| 判定 | 張數（第一版 → 現在）|
|---|---|
| `script-only` | 11 → 11 |
| `mismatch` | 4 → **3** |
| `script-agrees-incoming` | — → **1** |
| `area-default` | 3 → 3 |

## 剩下三個為什麼沒有 incoming

它們**根本沒有任何 `NEWECL` 切進來**（走訪得到的碼裡一處都沒有）：

| 地圖 | ECL/block | 全成員裡的 `NEWECL <本段>` |
|---|---|---|
| `original.geo3.block-10`（尤拉什）| 3/`0x10` | 無 |
| `original.geo3.block-11-level-2` | 3/`0x12` | 無 |
| `zhentil-keep.beholder-cave` | 4/`0x22` | 無 |

⇒ 這三張是從**世界地圖那一側**（ECL1 的 `0x50`／`0x51`）換 area 進來的，
不是同一個成員內的 `NEWECL`。`NEWECL` 的運算元是 block 編號，而編號在成員之間
會重複，所以這一支刻意只看同一個成員——跨成員的進場要另一條證據。

⚠ 這不是「宣告值錯」的證明，只是「這條路找不到」。spec 1184 原本對尤拉什的
判讀（宣告的 `(0,3)` 是護送段走完四步之後停的格子，spec 332）仍然成立。
