# 835 — AI 用道具：門檻由 7 往下掃，掃幾輪由 1d7 決定

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側**助憶碼完全相同**，15 條差異全是位址）
- 作法見 spec 783

## `overlay-09:004AAh`（entry#4，兩平台各 122 條）

`retf 4` ＝ 一個角色遠指標。回傳 `al`（有沒有用掉道具）。

```pascal
結果 := 0;
候選 := NIL;
門檻 := 7;
輪數 := <far 145Bh+2>(7, 1);                       { 1d7 }

if 角色^[18Dh]^[02h] = 0 then goto 收尾;
i := <far 1586h>(角色);
if byte[6F90h + i] = 0 then goto 收尾;             { 無號 }
if 遠指標(DS:4F99h)^[1CAh] <> 0 then goto 收尾;    { word }

if 1 > 輪數 then goto 收尾;                        { 無號；1d7 恆 ≥ 1 }
for k := 1 to 輪數 do begin
    p := 角色^[14Dh];                              { 物品鏈頭 }
    while (p <> NIL) and (候選 = NIL) do begin
        e   := p^[3Dh];
        _廢 := byte[5CF6h + p^[2Eh] * 10h];        { 算了但沒用 }
        if (<far 11DAh+4>(p) = 0)
           and (p^[3Eh] < 80h)                     { 無號 }
           and (p^[34h] <> 0)                      { 裝備中 }
           and (e > 0) then begin                  { 無號 }
            if e > 38h then e := e − 17h;
            if <本模組 03B1h>(角色, e, 門檻) then 候選 := p;
        end;
        p := p^[2Ah];
    end;
    dec(門檻);
end;

收尾:
if 候選 <> NIL then begin
    <far 1017h+1>(候選, @暫存);
    結果 := 1;
end;
```

## 門檻掃描：`7, 6, 5, …`，跑 1d7 輪

`本模組 03B1h` 就是 spec 802 認過的**施法前目標閘門**，它的第三個參數拿去跟法術
屬性表的 `+0Dh`（`DS:37E7h ＝ 37DAh + 0Dh`）比：`+0Dh < 門檻` 直接失敗。

所以 `+0Dh` 的語意在這裡定下來了：**AI 眼中的「這個效果值不值得現在用」的分數**。
本支從 **7** 開始要求，每掃完一輪物品鏈就降 1；掃幾輪由 **1d7** 決定，因此最低要求
落在 `8 − 1d7`，也就是 **1..7 之間隨機**。

實務上的意思是：**AI 每回合隨機決定自己肯將就到什麼程度**——運氣好只掃一輪（只肯用
分數 7 的道具），運氣差掃七輪（連分數 1 的都肯用）。

⚠ 內層 `while` 一找到候選就整個停（`候選` 同時是迴圈條件），**外層剩下的輪數會空轉**
（每輪重新走一次物品鏈，但條件恆假），只是白跑，不影響結果。

## 物品要通過的四道檢查

| 檢查 | 意義 | 出處 |
|---|---|---|
| `<far 11DAh+4>(p) = 0` | 未知 | — |
| `p^[3Eh] < 80h` | 第三個效果槽的最高位沒設 | 803 |
| `p^[34h] <> 0` | **裝備中** | 807 |
| `p^[3Dh] > 0` | 第二個效果槽有東西 | 803 |

物品節點的 `+2Eh`（類型）確實被拿去查 `DS:5CF6h` 那張表的 `+0`（類別碼），
但**算出來的值從頭到尾沒被讀過**——是一處死碼。

## `+3Dh > 38h` 時先減 `17h`

`38h` ＝ 56、`17h` ＝ 23。物品效果槽的值大於 56 時要減 23 才拿去當法術編號。
本規格**不宣稱**這個換算的來由——法術表是 100 筆（spec 815），56 與 23 都不是
表的邊界，而 `57 − 23 ＝ 34` 會撞進 1..56 的區間。這是一條待查線索，不是結論。

## 三道前置閘門

- `+18Dh^[02h]` ＝ 0 就不用道具。spec 806 讀到回合初始化時這個欄位固定寫 1，
  所以「被清成 0」是別處的處置。
- `byte[6F90h + <far 1586h>(角色)]` ＝ 0 就不用。`1586h` 回傳一個索引，
  `DS:6F90h` 是一張按該索引查的 byte 表。
- `遠指標(DS:4F99h)^[1CAh]`（word）≠ 0 就不用。

## PC-98：全部是位址差

15 條差異：`+18Dh`↔`+18Eh`、物品節點 `+2Ah/+2Eh/+34h/+3Dh/+3Eh` ↔
`+52h/+56h/+5Ch/+65h/+66h`（節點 DOS `3Fh` ／ PC-98 `67h`，spec 832）、
`+14Dh`↔`+14Eh`、`DS:6F90h`↔`DS:0A02Ah`、`DS:4F99h`↔`DS:7F05h`、
`DS:5CF6h`↔`DS:8D84h`，其餘是呼叫目標。**沒有邏輯差異。**

## 明確不宣稱

- 沒有宣稱 `far 1017h+1(候選, @暫存)` 做什麼（形狀上是「把這件道具用下去」）。
- 沒有宣稱 `far 11DAh+4` / `far 1586h` 判的是什麼。
- 沒有宣稱 `DS:6F90h` 與 `遠指標(DS:4F99h)^[1CAh]` 裝什麼。
- 沒有宣稱 `+3Dh > 38h` 時減 `17h` 的來由（見上）。
