# 959 — ★ PC-98 的音效表：每個音效 20 個頻率值

- 證據等級：`exact`（逐條讀完，來源是 `PC98-GAME.EXE.asm`）
- 位置：`PC98-GAME.EXE` 的 `18930h`
- 作法見 spec 783

## `18930h`（144 行，far，`retf 2`）：播一個音效

spec 951 的 Ctrl-S 用 `word_20ACAh`／`word_20ACCh` 兩個編號呼叫它；
啟動碼（`start+121h`、`start+13Bh`）也呼叫。

```pascal
播音效(編號 arg_0);

if byte_24DE8h = 2 then 離開;                     { ★ 音效關閉中（spec 951） }

if 編號 in [0, 1, 0Dh, 0Eh, 0FFh] then 離開;      { 這五個編號不發聲 }

if 編號 in [2, 4, 6, 9] then begin                { ★ 四個「單音」音效 }
    <sub_19286h>(編號 × 0Ah);                     { 設頻率 }
    <sub_19D1Eh>(0FAh div 編號);                  { 延遲 }
    離開;
end;

if 編號 = 0Fh then 離開;

for i := 1 to 13h do begin                        { ★ 最多 19 個音 }
    v := word[1A3Ch ＋ 編號 × 28h ＋ i × 2];
    if v = 0 then break;                          { 0 ＝ 這個音效結束 }
    if v > 9C4h then                              { > 2500 }
        <sub_19259h>(5)
    else begin
        <sub_19286h>(v);                          { 設頻率 }
        <sub_19D1Eh>(7D0h div v);                 { ★ 延遲 ＝ 2000 ÷ 頻率 }
    end;
end;
```

## 音效表：`DS:1A3Ch`，每筆 `28h`

| | |
|---|---|
| 基底 | `DS:1A3Ch` |
| 每個音效 | `28h` ＝ 40 bytes ＝ **20 個 word** |
| 索引 | 編號 × `28h` ＋ `i × 2`，`i` 從 **1** 起（**`i = 0` 那一格從來不讀**） |
| 終止 | 值為 `0` |
| 上限 | `i` 到 `13h`（19）就停 |

⚠ **每筆的第一個 word（`i = 0`）永遠不會被讀到**——迴圈從 `var_2 := 1` 起。
所以 40 bytes 裡實際只用 38 bytes、最多 19 個音。

## ★ 延遲與頻率成反比

```
延遲 := 7D0h div 頻率        { 2000 ÷ 頻率 }
```

**每個音的持續時間是固定的週期數**（2000 個單位 ÷ 頻率 ＝ 固定圈數），
所以高音短、低音長。這是很省事的作法——不需要另外存時值。

`> 9C4h`（2500）的值不是頻率，改叫 `<sub_19259h>(5)`——
形狀上是**靜音／休止**（值越大越不可能是可聽頻率）。

四個「單音」音效（編號 2、4、6、9）不查表：頻率 ＝ `編號 × 10`、
延遲 ＝ `250 ÷ 編號`——**極低的頻率（20／40／60／90），
形狀上是低沉的敲擊或雜訊，不是樂音**。

## 對 remake 的價值

音效表的位置、版面（每筆 20 個 word、0 終止）、以及
「延遲 ＝ 2000 ÷ 頻率」這條規則都可以直接照做。
**表的內容還沒 dump**（本規格只讀程式碼），
但有了位址與 stride，抽出來是機械工作。

## 明確不宣稱

- 沒有宣稱 `<sub_19286h>`（設頻率）、`<sub_19D1Eh>`（延遲）、
  `<sub_19259h>`（`v > 2500` 那條路）的內部。
- 沒有宣稱 `DS:1A3Ch` 表有幾筆音效。
- 沒有宣稱五個「不發聲」編號（0、1、`0Dh`、`0Eh`、`0FFh`）與 `0Fh`
  為什麼被排除。
- 沒有宣稱頻率值的單位（形狀上是 Hz，但沒有讀設定端）。
