# 876 — 依 `DS:4FBAh` 分派畫面重繪，PC-98 每一支都先清 GDC 文字畫面

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側差異逐條列出）
- 作法見 spec 783

## `overlay-24:02A6Dh`（DOS 113 條）↔ `overlay-24:02CA4h`（PC-98 192 條）

`retf` ＝ 無參數。

```pascal
DS:7580h := 1;
case DS:4FBAh of
  0: <far 1A00h>();

  1: begin
        if DS:8B54h <> 0 then <far 1B35h+1>();
        if DS:728Ah = 50h then
            <far 17B5h>(遠指標(DS:7232h), 1, 3, 3)
        else begin
            <far 17D3h>(DS:4FC6h, DS:4FC5h);
            <far 17CBh+3>(1, 3, 3);
        end;
        <本模組 0795h>(遠指標(DS:6506h));
        <本模組 2BAAh>();
     end;

  2: begin
        <far 1B35h+1>();
        暫 := 常數字串;
        <far 17C4h>(@DS:722Ch, 0, 1Dh);
        <本模組 0795h>(遠指標(DS:6506h));
        <本模組 2BAAh>();
     end;

  3: if DS:728Ah <> 50h then <far 1774h+1>();

  4: begin
        <far 1B35h+1>();  <far 1774h+1>();
        <本模組 0795h>(遠指標(DS:6506h));
        <本模組 2BAAh>();
        DS:8B6Eh := 0;
     end;

  6: begin
        <far 1B35h+1>();
        暫 := 常數字串;
        <far 17C4h>(@DS:722Ch, 0, 1);
        <本模組 0795h>(遠指標(DS:6506h));
     end;
end;
```

`DS:4FBAh` 就是 `overlay-20:00020h`（時間推進，spec 849）用來判斷
「是不是戰鬥中（值 2）」的同一格——**這裡確認它是畫面模式碼**，
有效值至少是 0、1、2、3、4、6（**5 沒有分支**）。

模式 2 與模式 6 走同一段，只差 `17C4h` 的第三個參數（`1Dh` 對 `1`）。

## PC-98：三個分支各多一段清畫面

模式 1、2、4 的開頭各多一段（三處完全相同）：

```asm
FillChar(A000h:0000h, 0FA0h, 0)      ; 文字碼平面填 0
FillChar(A200h:0000h, 0FA0h, 1)      ; 屬性平面填 1
```

`0A000h`／`0A200h` 是 PC-98 的文字 VRAM 與屬性 VRAM，
`0FA0h` ＝ 4000 ＝ **80 欄 × 25 列 × 2 bytes**。
所以那是「把整個文字畫面清成空白、屬性設成 1」。

DOS 沒有對應的動作——**DOS 的文字是畫在圖形畫面上的，PC-98 用硬體文字層**。
這是平台架構差異造成的必然差別，不是遊戲邏輯改動。
remake 只要做一個「清文字區」的抽象即可，不必兩套。

PC-98 還有一處分支結構不同（模式 1 的判斷改成 `jz` ＋ 一個長跳），
與多出來的清畫面段落是同一件事的連帶。

## 明確不宣稱

- 沒有宣稱六個模式各是什麼畫面。
- 沒有宣稱 `DS:7580h`／`DS:8B54h`／`DS:728Ah`（`50h` 這個門檻）／
  `DS:8B6Eh` 的意義。
- 沒有宣稱 `far 17B5h`／`17C4h`／`17CBh+3`／`17D3h`／`1774h+1`／`1A00h`／
  `1B35h+1` 各做什麼。
- 沒有宣稱模式 5 為什麼沒有分支。
