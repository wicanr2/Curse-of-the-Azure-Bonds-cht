# 975 — PC-98 的「はい／いいえ」是十格環狀選單，熱鍵字串就是 `DS:0A334h`

- 證據等級：`exact`（三支逐條讀完；選項字串、熱鍵字串與 32-byte 集合都由原始
  bytes 直接讀出）
- 作法見 spec 783

## `pc98 overlay-17:02B27h`（68 條，`retf 0Ah`）— Y/N 確認

`(arg_0, arg_2, arg_4, arg_6 ＝ 提示字串遠指標)`。

```pascal
限長(提示^, 本地提示, 28h);                      { 0A65h:0649h，40 字 }
repeat
    DS:0A32Eh := 2;
    位元組複製(@DS:11A6h, @DS:0A335h, 0Ah);      { 0A65h:0262h ＝ rep movsb，見 spec 990 }
    r := <overlay-26 entry#5>(@本地提示, CS:2ADEh 的選項行,
                              arg_4, arg_2, arg_0, 0, 0, @暫存);
until r in [ '2', '8', 'N', 'Y' ];               { 0A65h:08E4h，集合在 CS:2B07h }
結果 := r;
```

### 三份原始 bytes

| 位置 | 長度 | 內容 |
|---|---|---|
| `CS:2ADEh` | 40 | `'   はい                       いいえ    '` |
| `DS:11A6h` | 32 | `'    Y   N     K   E     CPH E…'`（只有前 10 個被複製） |
| `CS:2B07h` | 32 bytes | 位元集合，成員 ＝ `32h`／`38h`／`4Eh`／`59h` |

`32h`／`38h` ＝ **`'2'` 與 `'8'`**（PC-98 數字鍵盤的下／上），`4Eh`／`59h` ＝
**`'N'` 與 `'Y'`**。**其他任何鍵一律重問**，而且重問時整個選單重畫
（`DS:0A32Eh := 2` 與熱鍵字串都在迴圈裡）。

### `DS:0A334h` ＝ 選單的熱鍵字串，這一支把 spec 972 的環接上了

spec 972 讀 `overlay-26:00133h` 時看到一道略過迴圈：

```
while byte[0A334h + DS:0A385h] = 20h do DS:0A385h := 表[DS:0A385h].上一格;
```

當時只知道「標籤是空白的格會被跳過」。本支把那個 `0A334h` 的來源補上了：
每次進選單都把 `DS:11A6h` 的熱鍵字串複製到 `DS:0A335h`，**上限正好 `0Ah` ＝ 10**，
與環狀表的十格一一對應。

`0A65h:0262h` 其實是**原始位元組複製（`rep movsb`）**，不是字串指派——
它從 `DS:11A6h` 抄 10 個 byte 到 `DS:0A335h`，**而第一個 byte 是那個字串的長度**。
所以第 1 格拿到的是長度 byte、第 i 格拿到的是第 i−1 個字元（詳見 spec 990）：

| 格 | 熱鍵 | 可選 |
|---|---|---|
| 6 | `'Y'` | ✔ |
| 10 | `'N'` | ✔ |
| 其餘八格 | 空白 | ✘（會被略過） |

spec 825 讀到 PC-98 在戰鬥結束問話前把 `DS:0A385h` 與 `DS:0A386h` **都設成 `0Ah`**
——第 10 格正是 `'N'`，**游標一開始就停在「いいえ」上，而且不需要略過任何一格**。
那兩個 `0Ah` 的意義到此完全閉合。

**接受的四個鍵與這張表也對得起來**：兩個熱鍵（`Y`／`N`）加兩個移動鍵（`2`／`8`）。

### 中文化

- 選項行 `CS:2ADEh` **必須維持 40 個半形格**（`はい` 在第 4–7 byte、
  `いいえ` 在第 31–36 byte）。改成「是／否」時全形字各佔兩格，
  要自己補空白把總長補回 40，否則後面的欄位會位移。
- 提示字串被 `0A65h:0649h` **硬切到 40 個半形格 ＝ 20 個全形字**，超過的直接不見，
  沒有換行也沒有警告。
- **熱鍵 `Y`／`N` 與位置繫在一起**（第 6 與第 10 格）。中文化若要改成別的鍵，
  必須同時改 `DS:11A6h` 的字元位置**與** `CS:2B07h` 的集合，
  兩處不一致會變成「按了有反應但選不動」或「選得動但按了沒用」。

## `pc98 overlay-16:007DCh`（63 條，`retf 2`）— 用 `FindFirst` 找 `*.hil`

```pascal
out 0A6h, 1;                                   { 切到繪圖頁 1 }
r := <本模組 5674h>(arg_0);
out 0A6h, 0;                                   { 切回頁 0 }

路徑 := Copy(DS:8BF6h, 1, 3) + '*.hil';         { 0A65h:067Bh ＋ 0A65h:06BCh }
<08BDh:0112h>(路徑, 0, @搜尋記錄);
if word[DS:0BE2Eh] = 0 then r := 7;
結果 := r;
```

### ⚠ `out 0A6h` 不是 IDA 說的 8259A

IDA 把 `out 0A6h, al` 註成 `Interrupt Controller #2, 8259A`——**那是 IBM PC 的
配置，PC-98 不是**。PC-98 的兩顆 8259 在 `00h/02h` 與 `08h/0Ah`；
`0A4h`／`0A6h` 是圖形 VRAM 的**顯示頁**／**存取頁**選擇。
所以這兩行是「把繪圖切到第 1 頁畫完再切回第 0 頁」——**雙緩衝**。

與 spec 946 的 `int 18h`（IDA 註成 IBM 的 ROM BASIC，PC-98 其實是 CRT／鍵盤 BIOS）
是同一類陷阱：**IDA 的週邊註解在 PC-98 上一律不可信**。

### 三個尺寸把 `08BDh:0112h` 認成 `FindFirst`

`sub sp, 12Ch` ＝ 300 bytes ＝ `string[255]`（256）＋ **44**。
Turbo Pascal 的 `SearchRec` **正好 44 bytes**，`FindFirst(Path, Attr, var F)`
的第二個參數 `0` ＝ 一般檔案。再加上路徑裡有**萬用字元 `*.hil`**——
`FindFirst` 吃得下，`Reset` 吃不下。三件事一致。

`DS:0BE2Eh` 因此是 **`DosError`**：等於 0 代表找到了。

⚠ spec 760 記過「PC-98 用 `Assign`／`Reset` 判斷檔案在不在，DOS 用 `FindFirst`」。
本支證明 **PC-98 兩種都用**：要列舉萬用字元時仍然走 `FindFirst`。
該處的對照仍然成立（那是同一支「檔案存在嗎」的兩平台實作），
但不能推廣成「PC-98 沒有用 FindFirst」。

`Copy(DS:8BF6h, 1, 3)` 取的是路徑前綴的前三個字（形狀上是 `'A:\'` 這種磁碟機
前綴，與 spec 868 的 DOS `DS:5BF0h` 同一個角色）。

## `dos overlay-26:00A56h`（71 條，`retf 4`）— PC-98 `00BFEh` 的 DOS 兄弟

與 spec 973 的 `pc98 overlay-26:00BFEh` 同一個視窗記錄，但畫的是**一段子字串**：

```pascal
p := <本模組 0011h>(項次, 視窗^[16h], 視窗^[14h]);
a := <本模組 09C4h>(p, 視窗);
b := <本模組 0A10h>(p, 視窗, a) − a + 1;
<far 0542h:0352h>(視窗^[1Eh] + a − 1,                    { 欄 }
                  視窗^[1Ch] + (項次 − DS:7292h),        { 列 }
                  0, 視窗^[20h],                          { 顏色 }
                  Copy(p, a, b));
```

`09C4h` 給起點、`0A10h` 給終點，兩者相減 ＋1 是長度；欄位再往右推 `a − 1` 格
——**只重畫變動的那一段，不是整列**。

### 跨平台對應

| DOS | PC-98 | 意義 |
|---|---|---|
| `DS:7292h` | `DS:0A32Ch` | 清單的捲動起點 |
| `0542h:0352h` | `0418h:0D17h` | 印字入口 |

⚠ 本規格原本寫「兩個印字入口是不同的函式、參數順序對調」。**那是錯的**：
`0542h:0352h`（`START.EXE:15772h`）與 `0418h:0D17h`（`PC98-GAME.EXE:14E97h`）
是**同一支函式**，五個參數位置一格不差（spec 983）。
第三與第四個位置是**兩個顏色欄位**，呼叫端把算出來的顏色放在哪一格
決定的是「一般」還是「反白」——`00A56h` 與 `00AF8h` 正是同一個清單的兩種畫法。

### `Copy` 也留 `@結果` 在堆疊上

`0A54h:0680h`（DOS）／`0A65h:067Bh`（PC-98）的 `@結果` 與 spec 916 的
build-string 一樣**不由自己彈掉**，直接當下一個呼叫的參數。
本支的 `call far 0542h:0352h` 前面沒有任何 push 就是證據；
`pc98 overlay-16:007DCh` 的 `Copy` → `concat` → `FindFirst` 也是同一條鏈。

## 明確不宣稱

- 沒有宣稱 `overlay-17:02B27h` 的 `arg_0`／`arg_2`／`arg_4` 各是什麼
  （都是直接轉交給 `overlay-26 entry#5`）。
- 沒有宣稱 `DS:0A32Eh := 2` 的意義。
- 沒有宣稱 `.hil` 是什麼檔、也沒有宣稱回傳值 `7` 代表什麼。
- 沒有宣稱 `overlay-16:05674h`（在頁 1 上跑的那一支）做什麼。
- 沒有宣稱 `overlay-26` 的 `0011h`／`09C4h`／`0A10h` 各做什麼
  （只知道後兩支給出子字串的起訖）。
- 熱鍵字串 `DS:11A6h` 第 10 個字元之後的 `K`／`E`／`C`／`P`／`H`
  屬於別的選單，本規格沒有宣稱它們對應哪一個。
