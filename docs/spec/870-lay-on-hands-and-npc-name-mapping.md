# 870 — 治療某人，順帶挖出 PC-98 的 NPC 名字對照表

- 證據等級：`exact`（兩平台各自逐條讀完）
- 作法見 spec 783

## `overlay-19:036D8h`（DOS 91 條）↔ `overlay-19:037ABh`（PC-98 156 條）

`retf 4` ＝ 一個遠指標。

| | DOS | PC-98 |
|---|---|---|
| 選人 | `'Heal whom? '` | `'誰を回復させますか？'` |
| 有效 | `' feels better'` | `'は気分がよくなった'` |
| 無效 | `' is unaffected'` | `'には影響がなかった'` |

```pascal
<far 15A9h>();
目標 := 遠指標(DS:650Ah);
暫 := 'Heal whom? ';
<本模組 15B8h>(var 目標, 1);                       { 選一個隊員 }

if 目標 = NIL then <本模組 0083h>()
else begin
    r := <far 164Fh+3>(目標, arg_0);
    量 := (r * arg_0^[114h] + arg_0^[10Ch]) * 2;
    if <far 149Eh>(量, 0) then 訊息(目標名 ＋ ' feels better')
    else                       訊息(目標名 ＋ ' is unaffected');
    <far 1464h+3>(arg_0, 8Ch, 5A0h, 0, 0);
    <本模組 0083h>();
end;
```

`+10Ch` 落在 `+109h..+110h` 那八個職業槽等級裡（spec 850／869），
**槽 3 ＝ 聖騎士**。`× 2` 與 AD&D 一版聖騎士「按手治療每級 2 點」相符，
隔壁那一支 `overlay-19:039CAh` 的字串是
`'誰を治療しますか？'`／`'は病気にかかっていない'`（沒有生病）／
`'それでも治療しますか？'`——**驅除疾病，也是聖騎士能力**。
兩支相鄰、字串互補，形狀上這裡是按手治療；
但 `+114h` 與 `far 164Fh+3` 都沒讀，**本規格不定名**。

## PC-98 多出來的那一段：NPC 名字對照

DOS 直接把目標的名字接上訊息；PC-98 在組訊息前先把名字抄進一個
上限 `0FFh` 的緩衝，**目標 `+0F7h > 80h` 時**再做三次字串比對替換：

| 記錄裡的名字 | 顯示成 |
|---|---|
| `ALIAS` | `エイリアス` |
| `DRAGONBAIT` | `ドラゴンベイト` |
| `AKABAR BEL AKAS` | `アーカバー・ベル・アーカッシュ` |

比對用 `0A65h:0734h`（以 ZF 回報），替換用 `0A65h:0649h`（指派，上限 `0FFh`）。
**同一段在隔壁的 `overlay-19:039CAh` 又出現一次**（字串位址 `3961h`／`3967h`／
`3972h`／`397Dh`／`398Ch`／`399Ch`），所以不是單點特例。

### 這對中文化的意義

**角色記錄裡存的是英文名，PC-98 沒有改記錄，而是在顯示層做對照替換。**
Alias、Dragonbait、Akabar Bel Akash 正是《青色枷的詛咒》綁定劇情的三個同伴。

中文版有兩條路：

1. 跟 PC-98 一樣在顯示層加對照表——好處是存檔相容、壞處是每個印名字的地方都要補。
2. 直接把記錄裡的名字換成中文——要確認沒有別的地方用英文名做比對
   （**PC-98 這一段本身就是反例：它就是拿英文名當 key**）。

PC-98 選了第一條路，而且是逐處硬寫，不是集中在一個函式。
中文化若走第二條路，得先把所有「拿名字當 key」的地方掃出來。

## 明確不宣稱

- 沒有宣稱 `far 149Eh(量, 0)` 對誰施加治療（目標沒有被傳進去，
  形狀上是靠 `本模組 15B8h` 設好的全域）。
- 沒有宣稱 `arg_0` 是什麼記錄；`+10Ch`／`+114h` 的名稱都不宣稱。
- 沒有宣稱 `far 1464h+3(arg_0, 8Ch, 5A0h, 0, 0)` 做什麼。
- 沒有宣稱 PC-98 為什麼用 `+0F7h > 80h` 當做名字替換的前提。
- 沒有宣稱這三個名字之外還有沒有第四個對照（本支只有三組）。
