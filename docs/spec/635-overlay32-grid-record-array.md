# 第六百三十五輪：`overlay-32` 的 7×7 格盤與 `DS:973Dh` 記錄陣列

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：PC-98 `overlay-32` 的 `00F4h`、`0111h`、`0A1Eh`、`12EBh`、`1313h`、`133Bh`。

## 座標範圍是 0..6（有號比較）

```asm
cmp  [bp+arg_2], 0
jl   短：不合格            ; 有號
cmp  [bp+arg_2], 6
jg   短：不合格
cmp  [bp+arg_0], 0
jl   短：不合格
cmp  [bp+arg_0], 6
jle  短：合格
```

兩個座標都必須落在 **0..6**，用的是**有號**比較（`jl`／`jg`／`jle`），所以負值會
被擋掉而不是被當成大正數。合格回傳 1、否則 0。7 × 7 ＝ 49 格。

## `DS:973Dh` 是 4 bytes 一筆的記錄陣列

三支只差取哪一個欄位：

```asm
call near ptr sub_1363      ; (x, y) → 索引
xor  ah, ah
mov  di, ax
shl  di, 1
shl  di, 1                  ; 索引 × 4
mov  al, [di-68C3h]         ; 12EBh
mov  al, [di-68C2h]         ; 1313h
mov  al, [di-68C0h]         ; 133Bh
```

負位移換成無號就是基底：

| 位移 | 無號 | 相對基底 |
|---|---|---|
| `-68C3h` | `973Dh` | **`+0`** |
| `-68C2h` | `973Eh` | **`+1`** |
| `-68C0h` | `9740h` | **`+3`** |

所以 `DS:973Dh` 起是**每筆 4 bytes**的陣列，索引由 `sub_1363(x, y)` 算出。三支
分別讀 `+0`、`+1`、`+3`；**`+2` 這三支都沒有讀**——不是沒有這個欄位，是這一批
函式用不到。

索引是 byte（`xor ah, ah` 後才乘 4），配合 0..6 的座標範圍，陣列上限是 49 筆
＝ 196 bytes。

## 兩支對稱的呼叫

```text
00F4h:  <far 02A8h:1392h>(8, 0)   接著  <far 02A8h:1392h>(0, 8)
0111h:  <far 02A8h:1392h>(0, 0)   接著  <far 02A8h:1392h>(8, 8)
```

兩支都是「同一個 routine 連叫兩次、參數對調或成對」。`00F4h` 是 `(8,0)` 與
`(0,8)`、`0111h` 是 `(0,0)` 與 `(8,8)`——看起來是兩條對角線或兩組邊界，但這是
外觀推測，本輪不下結論。

## 明確不宣稱

- `sub_1363` 怎麼把 `(x, y)` 算成索引（是 `y*7+x` 還是別的）。
- `DS:973Dh` 每筆 4 bytes 的欄位各代表什麼，以及 `+2` 由誰使用。
- `02A8h:1392h` 做什麼、`0`／`8` 兩個常數的意義。
