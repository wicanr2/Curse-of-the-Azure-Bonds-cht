# 805 — 戰鬥開場配置戰鬥狀態、初始面向表、暫時改寫攻擊資料

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側的運算元差異已逐條列出；面向表
  取自常駐資料段 dump）
- 作法見 spec 783

## `overlay-10:10DDh`（entry#20，94 條，差異 14 條）— 給每個角色配一份戰鬥狀態

```pascal
p := DS:650Ah;  n := 0;
while p <> NIL do begin
    <far 1510h+3>(p);
    inc(n);
    GetMem(p^[18Dh], 16h);                                  { 22 bytes }
    FillChar(p^[18Dh]^, 16h, 0);
    if n > word(DS:4F9Dh^[67Ch]) then p^[18Dh]^[13h] := 1;   { 無號 }
    p^[18Dh]^[9] := byte[2FAh + (有號(DS:7211h) div 2)];
    if p^[197h] = 1 then
        p^[18Dh]^[9] := (p^[18Dh]^[9] + 4) mod 8;
    m := p^[0F7h] and 7Fh;
    if (p^[197h] = 0) and (p^[18Dh]^[13h] = 1)
       and ((m = 0) or (m > 66h)) then                       { 無號 }
        p^[0F7h] := byte(word(DS:4F9Dh^[58Ch]) + 80h);
    p := p^[189h];
end;
```

`retf`（無參數）。

### 戰鬥狀態記錄 22 bytes 得到第二個獨立證據

`GetMem(p^[18Dh], 16h)` ＋ `FillChar(…, 16h, 0)`。spec 801 是從 `FreeMem` 那一
側量到同一個數字，兩邊對上。**所有欄位開場都是 0**。

### `+13h` 標的是「超編」的成員

`n > DS:4F9Dh^[67Ch]` 的那些成員（走訪順序上排在上限之後）會被設 `+13h := 1`。
spec 801 的收尾正是用 `+13h = 1` 或陣營 1 決定誰留下——兩支對上。

### 初始面向表在 `DS:02FAh`（PC-98 `DS:06EEh`），兩平台相同

索引是**隊伍方向除以 2**（`DS:7211h`，0..7 → 0..3），表的前四格：

| 隊伍方向 | 0 / 1 | 2 / 3 | 4 / 5 | 6 / 7 |
|---|---|---|---|---|
| 初始面向 | `7` | `2` | `3` | `6` |

（`DS:02FAh` 之後還有 `5 4 5 6`，本支用不到。）

**陣營 1 的成員面向再轉 180°**（`(面向 + 4) mod 8`，spec 758 的對向式子）——
所以雙方開場是面對面站的。

### 士氣欄位的補值

只有「陣營 ≠ 1」且「`+13h` ＝ 1」的成員會被補：`+0F7h` 的低 7 位若是 `0` 或
大於 `66h`（102），就改寫成 `DS:4F9Dh^[58Ch] + 80h`。

⚠ 照 spec 758 的編碼（寫入 `(x div 2) or 80h`、上限 102），低 7 位最多是 51，
所以 **`> 66h` 這一半條件到不了**；實際只有「低 7 位 ＝ 0」會觸發。

## `overlay-13:4703h`（entry#31，93 條，差異 10 條）— 暫時改寫攻擊資料

`retf 0Ah` ＝ 5 個 word。依宣告順序：`(角色, 記錄, 旗標)`，前兩個是遠指標。

```pascal
目標 := 遠指標(DS:6D35h + 記錄^[3] * 4);          { 戰鬥員遠指標表，spec 785 }
DS:6FA3h := 目標;
if (旗標 <> 0) or (角色^[196h] = 0) or (目標^[196h] = 0) then begin
    <143Dh+2>(目標, 3Ah, longint 0);
    if 旗標 = 0 then begin
        記錄^[4] := 0;
        <143Dh+2>(角色, 90h, 記錄);
    end;
end else begin
    角色^[19Ch] := 1;
    角色^[19Dh] := 0;
    角色^[19Eh] := 2;
    角色^[1A0h] := 8;
    <本模組 19D8h>(角色, 目標, 1, longint 0, @暫存);
    暫存 := <far 159Ah>(角色);
    if 目標^[196h] = 0 then begin
        <143Dh+2>(角色, 90h, longint 0);
        <143Dh+2>(目標, 3Ah, longint 0);
    end;
end;
```

### 攻擊資料被就地改寫

spec 795 定下角色有**兩組**攻擊資料，以索引 `i ∈ {0, 1}` 取
`+19Dh + i`（擲骰第一參數）、`+19Fh + i`（第二參數）、`+1A1h + i`（加值）。
這一支寫的是：

| 欄位 | 值 | 對應 |
|---|---|---|
| `+19Ch` | 1 | 在兩個陣列之前，spec 795 未涵蓋 |
| `+19Dh` | 0 | 第 0 組的第一參數 |
| `+19Eh` | 2 | 第 1 組的第一參數 |
| `+1A0h` | 8 | 第 1 組的第二參數 |

**第 0 組的第一參數被清成 0、第 1 組被設成 `(2, 8)`**，加值（`+1A1h` / `+1A2h`）
沒有動。這是把角色的攻擊暫時換成另一種——remake 若把攻擊資料當唯讀就會漏掉
這條路徑。

### `143Dh+2` 的形狀與 `0141h:002Fh` 一致

`(角色遠指標, 碼, 4-byte 值)`；第三個參數有時是 `longint 0`、有時是一個遠指標。
spec 796 的移除效果（`0141h:002Fh`）是同一個形狀。本支用到的碼是 `3Ah`（58）與
`90h`（144）。

`DS:6FA3h` 是一個全域的遠指標，開頭就被寫成目標；之後的呼叫都從它讀。

## 明確不宣稱

- 沒有宣稱 `DS:4F9Dh^[67Ch]` 與 `DS:4F9Dh^[58Ch]` 是什麼。
- 沒有宣稱 `DS:02FAh` 第 5..8 格（`5 4 5 6`）屬於同一張表。
- 沒有宣稱碼 `3Ah` / `90h` 各代表什麼效果。
- 沒有宣稱 `+19Ch` 是什麼。
- 沒有宣稱 `+196h` ＝ 0 是哪一種狀態。
- 沒有宣稱 `143Dh+2` 與 `0141h:002Fh` 是同一支常式；只確定參數形狀相同。
