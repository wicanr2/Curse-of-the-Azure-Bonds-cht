# 893 — 法術來源標題：七種來源各一句，PC-98 有兩句合併

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側只差一條 `cbw`）
- 作法見 spec 783

## `overlay-19:03474h` ↔ `overlay-19:034E4h`（DOS 158 條／PC-98 157 條）

`retf 0Ch` ＝ 6 個 word。`arg_A` 是來源碼 0..6。

| 來源碼 | DOS | PC-98 |
|---|---|---|
| 0 | `'in Memory'` | `'記憶内'` |
| 1 | `'in Grimoire'` | `'魔法書上'` |
| 2 | `'on Scroll'` | `'巻物上'` |
| 3 | `'on Scrolls'` | **`'巻物上'`（與 2 同一個字串）** |
| 4 | `'to Choose'` | `'選んでください'` |
| 5 | `'to Memorize'` | `'記憶する魔法を選んでください'` |
| 6 | （第七句） | `'書きこむ魔法を選んでください'` |
| 其他 | 空字串 | 空字串 |

```pascal
case 來源碼 of
  0..6: 標題 := 對應字串;                     { 0A54h:064Eh，上限 28h }
  else  標題 := '';
end;

arg_0^ := <far 11C9h+1>(來源碼);
if arg_0^ = 0 then begin 結果 := 0;  離開 end;

if (有號(arg_4^) >= 0) or (arg_8 = 1) then
    if DS:4FBAh = 5 then <far 1A00h>()
    else if arg_8 = 2 then <far 1C91h+1>()
    else                   <far 1E8Bh+2>();

<far 155Eh>(1, 1, 1, 遠指標(DS:6506h));
訊息(常數 ＋ 標題);
<far 0542h:0352h>(0, 0Ah, 1, 遠指標(DS:6506h)^[0] ＋ 4);
結果 := <far 11C5h>(arg_4, arg_8);
```

## ⚠ PC-98 把 `'on Scroll'` 與 `'on Scrolls'` 併成同一個字串

DOS 為單數／複數各留一個字串常數（`unk_3437`／`unk_3441`），
PC-98 兩個分支都指到 `loc_348Fh`。

**這是 spec 841 那個模式的第三個出現點**：日文沒有單複數變化，
所以 PC-98 把「只差單複數」的兩個 DOS 字串合併成一個。
中文化同理——`'on Scroll'` 與 `'on Scrolls'` 應該翻成同一句。

## ⚠ PC-98 的第 5、6 句是完整句子

DOS 的 `'to Choose'`／`'to Memorize'` 是接在別的字串後面的片語
（`訊息(常數 ＋ 標題)`），PC-98 換成
`'記憶する魔法を選んでください'`／`'書きこむ魔法を選んでください'`
——**整句重寫，不是片語**。與 spec 840 讀到的改寫傾向一致。

中文版要跟 PC-98：前綴常數與這七句要合起來設計，不能逐片語直譯。

## PC-98：只差一條 `cbw`

DOS 把 `arg_A` 零擴充成 `ax` 再 `cmp ax, n`，PC-98 直接 `cmp al, n`。
spec 783 第 c 類，行為相同。

## 明確不宣稱

- 沒有宣稱 `far 11C9h+1(來源碼)` 與 `far 11C5h(arg_4, arg_8)` 各做什麼。
- 沒有宣稱 `arg_8` 的 1／2 分支各是什麼。
- 沒有宣稱 `遠指標(DS:6506h)^[0]` 是什麼（拿來 ＋4 當顯示參數）。
- 沒有宣稱 DOS 第 6 句的內容（`function_strings` 只抽到六句）。
