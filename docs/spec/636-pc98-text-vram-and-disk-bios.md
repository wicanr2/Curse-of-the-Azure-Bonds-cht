# 第六百三十六輪：PC-98 的文字 VRAM 清除與磁碟 BIOS 呼叫

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：PC-98 `overlay-16` 的 `424Ah`、`4E65h`、`5738h`、`574Fh`。

## `424Ah`：清掉文字畫面的下半部

```text
FillChar(0A000h:0A00h, 500h, 0)      ← 字元碼平面
FillChar(0A200h:0A00h, 500h, 1)      ← 屬性平面
```

`0A65h:1B30h` 是 Turbo Pascal 的 `FillChar`。PC-98 的文字畫面是**兩個平面**：
`0A000h` 放字元碼、`0A200h` 放屬性，每格各佔一個 word。

換算這兩個常數：

| | 值 | 換算 |
|---|---|---|
| 起始位移 | `0A00h` | ÷2 ＝ 第 1280 格 ＝ **第 16 列**（80 欄） |
| 長度 | `500h` | ÷2 ＝ 640 格 ＝ **8 列** |

所以這支清的是**第 16..23 列**——畫面下方八列的訊息區。字元碼填 `0`、屬性填 `1`。

### 對中文化的意含

遊戲文字走 **PC-98 文字 VRAM**，不是圖形平面。文字 VRAM 每格一個 word，全形字
靠 JIS 碼配漢字 ROM 顯示。中文化若要顯示 Big5 字，**不能沿用這條路徑**——漢字
ROM 裡沒有繁體字集。需要改走圖形平面自繪，而這支的「清 8 列」也要跟著換成對應
的圖形區域清除。

## `5738h`／`574Fh`：磁碟 BIOS

```text
574Fh:  al := byte at 0C29h:8BF7h
        al := (al − 1) and 0Fh
        al := al or 90h
        CS:576Eh := al                 ← 存進程式碼段裡的一個 byte

5738h:  <574Fh>()
        al := CS:576Eh
        ah := 4
        int 1Bh                        ← PC-98 磁碟 BIOS
        回傳 1；CF 有進位則回傳 0
```

`int 1Bh` 是 PC-98 的磁碟 BIOS。`AL` 的高半 byte `90h` 是磁碟機類別碼，低 4 bit
是機號——由 `0C29h:8BF7h` 那個 byte **減 1** 再取低 4 bit 得到，所以那裡存的是
**1 起算**的機號。

`AH = 4` 的功能本輪不宣稱（PC-98 BIOS 的功能碼表不在手上）。回傳值只看 CF：
沒進位回 1、有進位回 0。

兩支都是**自我修改風格**：`574Fh` 把算好的值寫進 `CS:576Eh`，`5738h` 再從那裡
讀出來。不是傳參數，是共用一個程式碼段內的變數。

## `4E65h`：忙碌等待

```text
repeat
until <sub_B4F>(0) <> 0
<sub_5008>(0, 4Bh)
```

迴圈條件是 `or al, al` ＋ `jz` **跳回迴圈開頭**（`4E68h`，也就是 `mov al, 0`
那一行），所以每一輪都重新推入參數 `0`。中間沒有延遲也沒有讓出——是純忙碌等待。

## 明確不宣稱

- `int 1Bh` `AH = 4` 是讀、寫還是別的動作。
- `0C29h:8BF7h` 那個 byte 由誰設定。
- `sub_B4F`／`sub_5008` 的行為與常數 `4Bh` 的意義。
- 屬性值 `1` 對應什麼顏色／屬性組合。
