# 1053 — 假名／字母 → 字形索引：步長 1／2／3 正好對上濁音與半濁音的結構

- 證據等級：`exact`（PC-98 常駐段 238 條逐條讀完，`objdump` 路線見 spec 1046／1048）
- 作法見 spec 783

## `pc98 PC98-GAME.EXE:14372h`（`retf 4`，600 bytes）

原本待解讀。呼叫端就是緊接其後的那一支（`145CAh`）。
整支是一條**二十段的比對鏈**，把 `bp+08h` 的一個 byte 換算成 `bp-2` 的一個 byte：

```pascal
if 輸入 in [下界..上界] then 結果 := 基底 ＋ (輸入 − 下界) × 步長;
```

★ 輸入涵蓋 **JIS X 0201 的半形片假名區**（`A6h`、`B1h`..`DDh`）
以及 ASCII 的 `'A'`..`'J'`、`'a'`..`'z'`。輸出全部落在 `9Fh`..`F2h`。

## ★★★ 步長就是「這一行有幾個變體」

> ★★★ **`×3` 只出現在 `ﾊﾋﾌﾍﾎ`（以及 `'q'`..`'u'`、`'v'`..`'z'`）
> ——ハ行正是日文裡唯一同時有濁音（バ）與半濁音（パ）的一行。**
> **`×1` 只出現在 `ﾅﾆﾇﾈﾉ`、`ﾏﾐﾑﾒﾓ`、`ﾗﾘﾙﾚﾛ`
> ——ナ行・マ行・ラ行正是完全沒有濁音的三行。**
> 其餘（ア／カ／サ／タ／ヤ行）都是 `×2`（清音 ＋ 濁音）。
>
> ⇒ **輸出是一張「把清音、濁音、半濁音全部攤平」的連續索引**，
> 每個假名在表上佔的格數 ＝ 它有幾種變體。

⚠ 本規格**不宣稱**輸出表的排列順序，也不宣稱 ASCII 那幾段各自對到哪些假名
（`'A'` → `9Fh` 比 `ｱ` → `A0h` 小 1，形狀上像是「同一行的前一格」，但沒有直接證據）。

## 中文化

> ⚠⚠ **這張表是 PC-98 日文版專屬的字形索引。**
> 中文化不會用到它（Big5 不走假名），但**必須知道它存在**：
> 任何把「字元 → 字形」重新導向的改動都要繞過這一支，
> 否則落在 `A6h`..`DDh` 的 Big5 **低位元組**會被當成半形片假名換算掉。
>
> ★ Big5 的低位元組範圍是 `40h`..`7Eh` 與 `A1h`..`FEh`
> ——**後半段與這裡的輸入範圍完全重疊**。

## 明確不宣稱

- 沒有宣稱輸出索引表的實際排列（只確定格數與變體數一致）。
- 沒有宣稱 ASCII 那九段各自代表什麼。
- 沒有宣稱唯一呼叫端 `145CAh` 拿這個索引去做什麼。
- 沒有宣稱範圍外的輸入（例如 `DEh`／`DFh` 的濁點符號）會得到什麼。
