# 1136 — 突襲遮罩是死碼；保留的機會攻擊就是 GUARD 設的

- 證據等級：`exact`（`Area2 + 596h` 與戰鬥狀態 `+07h` 的讀寫由 36 個 DOS overlay
  ＋常駐段全掃，並以相鄰欄位的非零寫入做正對照；PC-98 側同一組位移獨立重掃）
- 上游 spec 1113（突襲遮罩「只有清除、沒有設定」）、spec 817（機會攻擊消費端）、
  spec 804（回合開始的清除）、spec 806（先攻讀遮罩）、spec 1135（回合生命週期的對照）

## 一、突襲遮罩：整個 build 沒有任何地方寫進非 0

先攻的 `−6` 條件是 `((陣營 + 1) and word(DS:4F9Dh^[596h])) <> 0`（spec 806）。
把 36 個 overlay ＋常駐 `START.EXE` 全掃過，`Area2 + 596h` 只有兩個存取點：

| 位置 | 動作 | 是什麼 |
|---|---|---|
| `overlay-13 sub_0` `00CDh` | `and ax, es:[di+596h]` | 先攻讀它 |
| `overlay-08 sub_F3` `0162h` | `xor ax, ax` ＋ `mov es:[di+596h], ax` | **戰鬥主迴圈每輪清 0** |

三條補強，缺一條這個結論都只是「查無」：

1. **正對照**：同一支掃描在相鄰欄位找得到非零寫入——`Area2 + 58Eh` 被寫進
   `81h`／`80h`（`overlay-05`），`Area2 + 5AAh` 被寫進 `1`（`overlay-14`）。
   掃描的形狀抓得到「寫非零」。
2. **指標間接也掃過**：`disp16` 的掃描結構上抓不到 `add di, 常數` 之後對
   `es:[di]` 的寫入（spec 1134 §還開著的 就踩過這個假零）。因此另外掃了
   立即數 `596h` 出現在 `add di/bx/si/ax` 與 `mov di/bx/si/ax` 的所有形狀
   ——**0 次**；以及 `ds:4F9Dh` 的全部載入點，指標算術那一族一律是
   `+800h`（ECL 的 Area2 字陣列），碰不到 `596h`。
3. **第二個平台**：PC-98 build 同一個位移同樣只有兩個存取點，一讀一清 0。

再加上進地圖時 `Area2` 整塊被清成 0（`overlay-11` `0340h`），
**這個遮罩從頭到尾都是 0**。

⇒ **先攻的 `−6` 在這一作走不到。** CoAB 傳 0 不是佔位，是唯一有證據的值。
`TestInitiativeStaysInsideTheNoSurpriseRange` 釘住可觀察的後果：沒有 `−6`，
`1d6 + 敏捷反應調整（−4..+5）` 夾底到 1 之後值域就是 `1..11`。日後有人接上
非 0 的遮罩，這條會紅。

⚠ 這裡**沒有**宣稱「原作沒有突襲」。`22h PARTY SURPRISE` 這條 ECL 指令仍然
在跑（spec 1113 §一：它只回報隊伍裡有沒有遊俠），只是它的結果沒有接到先攻上。

## 二、保留的機會攻擊：設定端是 GUARD

spec 817 讀完了消費端（`overlay-13 entry#5`：掃相鄰者，`+18Dh^[7] <> 0` 的各打
一下，打完歸零），spec 804 讀完了清除端（回合開始清 0），但設定端一直空著。

把戰鬥狀態指標（`+18Dh`）的 514 個載入點全掃過，對 `+07h` 的寫入只有五處，
其中**唯一寫非零的**是 `overlay-24` `288Dh`：

```pascal
{ overlay-24 entry#35（sub_2877），retf 4 ＝ 一個角色遠指標 }
result := sub_2828(角色);          { 清掉 +3、+0、+7、+6：這一輪不再行動 }
角色^[18Dh]^[7] := 1;              { ← 保留一次機會攻擊 }
暫存 := 'Guarding';                { CS:286Eh，長度 8 }
sub_177A();                        { 顯示 }
return result;                     { 常數 1 }
```

字串就是 `Guarding`——**設定端是 GUARD 指令**。整條鏈因此接得起來：

| 階段 | 位置 | 動作 |
|---|---|---|
| 設定 | `overlay-24 entry#35` | `+7 := 1`，同時把先攻 `+3` 歸 0（這一輪不再行動）|
| 消費 | `overlay-13 entry#5` | 相鄰者各打一下，打完 `+7 := 0` |
| 清除 | `overlay-08 entry#4` | 回合開始清 0 ⇒ **防禦撐到自己下一次被選中** |

remake 這一側已經實作且有測試：`State.CombatGuard()` → `Battle.GuardAction()`
設旗標並結束該次行動，`MoveWithFreeAttacks` 在對方進入相鄰時消費它
（先清旗標再攻擊，與原作同序），`TestGuardActionAttacksOnceWhenEnemyEntersAdjacency`
釘住「只打一次」、`TestGuardActionHeldSuppressionAndMissileEligibility` 釘住定身壓制。

## 三、★ 順帶量到：`+0Fh`／`+12h` 是有讀者的

spec 786 讀到 `+0Fh`（動作計數）與 `+12h`（累計轉向，0..7 環狀）怎麼被寫，
但當時寫「沒有宣稱它拿來做什麼」。同一支掃描把讀者找出來了：

| 欄位 | 讀者 | 形狀 |
|---|---|---|
| `+0Fh` | `overlay-13` `0BC4h`／`16B2h`／`19FBh`／`295Ch` | `cmp [di+0Fh], 0`／`1`／`2`／`1` 之後分支 |
| `+12h` | `overlay-13` `16DFh`／`19B7h`、`overlay-23` `1A36h` | `cmp [di+12h], 4`／`12h`、`mov al, [di+12h]` |

**所以它們不是純記帳**，是四道以「這一輪動過幾次」「總共轉了多少」為條件的閘。
remake 目前沒有這兩個欄位。這是回合生命週期真正還開著的一格，
與機會攻擊無關——**把它併進「機會攻擊沒做」是分類錯誤**。

## 明確不宣稱

- 沒有宣稱那四道 `+0Fh`／三道 `+12h` 的閘各自擋住什麼；本規格只證明它們存在。
- 沒有宣稱 `overlay-31` 那幾處 `mov ax, [di+12h]`（word 存取）讀的是同一個記錄。
- 沒有宣稱 `sub_2877` 的回傳值（常數 1）由誰讀。
- 沒有宣稱 `overlay-13 entry#5` 的 `<far 150Ah+4>(q)` 守衛是什麼；remake 目前把
  它實作成「定身就不反擊」，那是解釋不是證據。
- 沒有宣稱 `22h PARTY SURPRISE` 的結果在原作有任何消費者。
