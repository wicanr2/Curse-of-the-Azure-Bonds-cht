# 第七百三十七輪：`overlay-12`（EFFPROCS）的四支小處理程序

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：DOS `overlay-12` 的 `255Ah`、`25BAh`、`2606h`、`2C4Fh`。
（四支都不在 `scripts/decode_gap_scan.py` 的缺口清單裡。）

## `255Ah`：某種武器把傷害**覆寫**成 `1d6+1`

```text
w := DS:6506h^[151h]                         ← 施法者手上的物品
if w <> NIL 且 w^[2Eh] = 55h then
    DS:6F94h := ROLLDAMAGEDICE(1, 6) + 1
```

`mov ds:6F94h, al` 是**指派不是累加**——這個武器類別的傷害是寫死的 `1d6+1`，
把原本算好的值整個蓋掉。

`+2Eh` 是物品類別編號（spec 696）。

## `2606h`：兩種武器類別觸發同一個處理

```text
w := DS:6506h^[151h]
if w <> NIL 且 (w^[2Eh] = 57h 或 w^[2Eh] = 58h) then
    <sub_F39h>(32h, arg_6, arg_8)
```

`57h` 與 `58h` 相鄰，兩者共用一個常數 `32h`。

## `25BAh`：打不到的規則

```text
w := <sub_FAAh>(DS:6506h)
if (w = NIL 或 w^[32h] = 0) 且 (施法者^[74h] > 0 或 施法者^[0E5h] < 4) then
    DS:6F94h := 0                            ← 傷害歸零
```

兩組條件都成立才歸零：**武器不具備某個性質**（`w^[32h]`）**而且**攻擊者達不到
某個門檻。傷害設成 0，不是「不攻擊」——所以流程仍會往下走，只是打不痛。

`+0E5h` 在 spec 715 的 Sleep 是查 HD 成本的鍵，這裡拿來和 `4` 比。

## `2C4Fh`：`+191h` ＝ 兩個職業欄位算出來的分段

```text
if arg_0 <> 0 then
    v := 角色^[10Ch] + 角色^[114h] × <overlay-25 entry#10>(角色)
    角色^[191h] := ((v − 1) div 5) + 1        ← cwd ＋ idiv 5，往零取整
```

`+10Ch` 與 `+114h` 正是 spec 728 那組**相差 8 的平行職業欄位**，而
`overlay-25 entry#10` 在這裡是被 `imul` 的**數值**，不是布林值——spec 728 只把它
測了零，形狀相容但語意要修正成「第二職業的權重」。

spec 705 的 `30C0h` 用 `目標^[10Eh] + 目標^[116h] × entry#10(...)`，是同一組相鄰
欄位的另一對。**三支合起來確認了這個「第一職業欄 ＋ 第二職業欄 × 權重」的算式
模板。**

`((v − 1) div 5) + 1` 對正的 `v` 就是 `ceil(v / 5)`；但 `idiv` 往零取整，
`v = 0` 時算出 `((−1) div 5) + 1 = 0 + 1 = 1`，`v` 為負時會得到大於 1 的值。
**不能改寫成無號的 `(v + 4) / 5`。**

## 明確不宣稱

- 物品類別 `55h`／`57h`／`58h` 是哪些武器。
- `w^[32h]`、`+74h`、`+191h` 的語意。
- `sub_F39h`、`sub_FAAh` 的行為。
- `overlay-25 entry#10` 回傳值的定義域。
