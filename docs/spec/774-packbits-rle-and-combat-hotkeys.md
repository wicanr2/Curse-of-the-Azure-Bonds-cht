# 774 — PackBits 式 RLE 解壓（含兩個會當掉的碼）、戰鬥中的熱鍵

- 證據等級：`exact`（以補洞後的匯出逐條讀完，見 spec 761）

## `START.EXE:16A62h`（DOS）— PackBits 式 RLE

`retf 10h`（四個遠指標）：

```pascal
來源位置 := 0;  目的位置 := 0;
repeat
    n := 有號(來源^[來源位置]);
    if (n >= 0) and (n <= 7Eh) then begin              { 原樣搬 }
        Move(來源^[來源位置 + 1], 目的^[目的位置], n + 1);
        來源位置 := 來源位置 + n + 2;
        目的位置 := 目的位置 + n + 1;
    end
    else if (n >= −127) and (n <= −1) then begin       { 重複 }
        m := −n;
        FillChar(目的^[目的位置], m, 來源^[來源位置 + 1]);
        來源位置 := 來源位置 + 2;
        目的位置 := 目的位置 + m;
    end;
until 來源位置 >= 長度^;                                { 無號比較 }
```

這是 Apple PackBits 的同族格式：**正數 `n` 表示接下來 `n + 1` 個位元組照抄，
負數 `n` 表示把下一個位元組重複 `−n` 次**。

⚠ **`7Fh` 與 `80h` 這兩個值兩條分支都不成立**（`7Fh` 大於 `7Eh` 但當有號看是
`+127`，不落在 `−127..−1`；`80h` 是 `−128`，小於 `−127`）。兩種情形下
`來源位置` 都不會前進，迴圈條件又不會滿足——**會無限迴圈**。原始資料不會出現
這兩個值，但 remake 若要容錯就得自己加判斷。

三個位置參數都是「遠指標指向遠指標」（`les di, [bp+arg]` 之後再 `les di,
es:[di]`），也就是 var 參數傳進來的指標變數。

## `overlay-09:1273h`（DOS）— 戰鬥中的三個熱鍵

`retf 4`：

```pascal
結果 := false;
if not KeyPressed then 離開;
k := ReadKey;
if k = 0 then k := ReadKey;                     { 擴充鍵的第二個位元組 }

if k = '2' then begin
    DS:75DAh := not DS:75DAh;                   { 切換 }
    if DS:75DAh <> 0 then 顯示('Magic On')      { CS:1260h，8 字元 }
                     else 顯示('Magic Off');    { CS:1269h，9 字元 }
end
else if k = ' ' then begin
    角色 := DS:650Ah;
    while 角色 <> NIL do begin
        if (角色^[0F7h] < 80h) and (角色^[195h] <> 1) then
            角色^[198h] := 0;
        角色 := 角色^[189h];
    end;
    if 參數^[198h] = 0 then begin
        參數^[18Dh]^[3] := 14h;
        結果 := true;
    end;
end
else if k = '-' then
    <呼叫>();
<呼叫>();
```

三件事：

- `'2'` 是 **Magic On / Off** 的切換鍵，狀態在 `DS:75DAh`（戰鬥開場 spec 750
  會把它歸零，所以每場戰鬥都從 Off 開始）。
- `'空白'` 會把**士氣旗標未設（`+0F7h < 80h`，見 spec 758）且狀態不是 1** 的
  成員的 `+198h` 清成 0；接著若參數指的那個角色 `+198h` 也是 0，就把它的
  `+18Dh^[3]` 設成 `14h` 並回 true。
- `'-'` 走另一支，結果沒有被使用。

`ReadKey` 呼叫兩次的寫法是 IBM 擴充鍵的標準處理（第一次回 0 表示後面還有一個
位元組），**但第二次讀回來的碼會直接跟 `'2'` / `' '` / `'-'` 比對**——擴充鍵的
掃描碼若剛好等於 `32h`／`20h`／`2Dh` 就會被誤判成那三個鍵。

**中文化要注意**：`'2'` 這個鍵是寫死的字元常數，`'Magic On'` / `'Magic Off'`
兩條訊息長度不同（8 / 9），畫的時候沒有補齊。

## 明確不宣稱

- 沒有宣稱 `DS:75DAh` 的「Magic」開關實際影響什麼行為。
- 沒有宣稱 `+198h` 與 `+18Dh^[3] = 14h` 的語意。
- 沒有宣稱 `'-'` 那一支做什麼。
- 沒有宣稱 RLE 解出來的是哪一種資料。
