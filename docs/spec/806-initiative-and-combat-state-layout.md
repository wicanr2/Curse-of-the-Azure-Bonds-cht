# 806 — 先攻值怎麼算出來的、22 bytes 戰鬥狀態的版面補齊

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側的運算元差異已逐條列出）
- 作法見 spec 783

## `overlay-13:0000h`（entry#1，94 條，差異 9 條）— 每回合的戰鬥狀態初始化

`retf 4` ＝ 一個角色遠指標。

```pascal
c := 角色^[18Dh];
c^[0] := 0;  c^[1] := 1;  c^[2] := 1;  c^[4] := 2;  c^[8] := 0;
<本模組 0DD9h>(角色);
DS:6F96h := 角色^[11Dh];
DS:6F9Ah := 0;
<far 1442h+2>(角色, 12h);
角色^[19Dh] := <本模組 0F12h>(DS:6F96h);
c^[5] := 角色^[0DDh];
if 角色^[196h] <> 0 then begin
    c^[3] := 有號(<far 1524h+3>(角色)) + <far 145Ah+3>(6, 1);
    if 有號(c^[3]) < 1 then c^[3] := 1;
    if ((角色^[197h] + 1) and word(DS:4F9Dh^[596h])) <> 0 then
        c^[3] := c^[3] − 6;
    if (有號(c^[3]) < 0) or (有號(c^[3]) > 14h) then c^[3] := 0;
end else
    c^[3] := 0;
c^[6] := <本模組 0124h>(角色);
```

### `+18Dh^[3]` 是先攻值

三支先前分別讀過的函式在這裡接起來：

| 出處 | 對 `+3` 做的事 |
|---|---|
| spec 791 | 挑「`+3` 最大」的角色，同值時擲 1..100 決勝 |
| spec 804 | 回合開始時 `<= 0` 就不動作；`= 14h`（20）壓成 `13h`（19） |
| 本支 | 算出它 |

算式是 **`<1524h+3>(角色) ＋ 1d6`**，先夾到至少 1，接著在條件成立時 **−6**，
最後 `< 0` 或 `> 20` 一律歸 0。

- `−6` 的條件是 `((陣營 + 1) and DS:4F9Dh^[596h]) ≠ 0` ——`DS:4F9Dh^[596h]` 是一
  個 word 位元遮罩，用 `陣營 + 1` 去 `and`。
- **−6 之後可能變成負數，於是被歸 0**，而 spec 791 選不到 `+3` ＝ 0 的角色。
  所以那個遮罩實質上是「這一邊這回合不行動」。
- 上限 20 與 spec 804 的 `20 → 19` 對得起來：**20 是合法的最大值**，只是回合
  開始時會被壓低一格。

### 22 bytes 戰鬥狀態的版面（累積）

| 位移 | 開場值／內容 | 出處 |
|---|---|---|
| `+00h` | 0（`overlay-08:026Bh` 判它是否為 0） | 本支／804 |
| `+01h` | 1 | 本支 |
| `+02h` | 1 | 本支 |
| `+03h` | **先攻值** | 本支／791／804 |
| `+04h` | 2 | 本支 |
| `+05h` | 角色 `+0DDh` 的複本 | 本支 |
| `+06h` | `overlay-13:0124h`（移動率換算）的結果 | 本支／799 |
| `+07h` | 保留中的機會攻擊（用掉就歸零） | 804／817 |
| `+08h` | 0 | 本支 |
| `+09h` | 目前面向 | 782／805 |
| `+0Ah` / `+0Ch` | 目前目標的遠指標 | 782／790 |
| `+0Fh` | 動作計數 | 786 |
| `+12h` | 累計轉向量（mod 8） | 786 |
| `+13h` | 超編旗標（開場由 spec 805 設定） | 801／805 |
| `+14h` | 本回合已撤退 | 782 |

`+10h` 是 spec 815 的候選條件（必須為 0）、`+0Eh` 是 spec 825 的瀕死回合計數。
還沒看到用途的只剩 `+0Bh`、`+0Dh`、`+11h`、`+15h`。

### `+19Dh` 那組攻擊資料是**每回合重算**的

`角色^[19Dh] := <0F12h>(角色^[11Dh])` ——spec 795 把 `+19Dh + i` / `+19Fh + i` /
`+1A1h + i` 當成角色的兩組攻擊資料，本支證明**它們不是靜態的武器資料，而是每回合
重新填的狀態**（spec 805 的 `overlay-13:4703h` 也會就地改寫它們）。

## 順帶更正 spec 799 的參數順序

spec 799 把 `overlay-13:0D1Ch` 的 `retf 4` 記成「2 個 word」，並把呼叫寫成
`(0FFh, 參數0, 參數2)` 等形式。實際上 `arg_0` / `arg_2` 是**同一個角色遠指標的
兩半**（`arg_2` 是節區），而推入順序決定第一個宣告參數是那個遠指標：

```
1590h(角色, 0FFh)      0124h(角色)      2EACh(角色)      159Ah(角色)
146Bh+1(角色, 3, 'Got Away')
```

spec 799 正文已改寫。

- 沒有宣稱 `145Ah+3(6, 1)` 兩個參數哪個是面數哪個是次數（形狀上是 1d6）。
- 沒有宣稱 `DS:4F9Dh^[596h]` 那個遮罩由誰設定。
- 沒有宣稱 `+11Dh` / `+0DDh` 是什麼，也沒有宣稱 `0F12h` 怎麼換算。
- 沒有宣稱 `DS:6F96h` / `DS:6F9Ah` 由誰讀。
