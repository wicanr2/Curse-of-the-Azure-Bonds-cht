# 749 — 戰鬥收尾程序與戰場格陣尺寸（`overlay-08:004Dh`）

- 平台／模組：DOS `overlay-08`（`004Dh`，62 條指令）
- 證據等級：`exact`（逐指令讀完）；格陣尺寸為由配置大小反推，見下方推導
- 相關：[`748`](748-cloud-effect-dispel-pair.md) 的雲霧鏈與地圖索引式、
  [`719`](719-spell-targeting-mode.md) 的選目標程序

`retf`（無運算元）＝ 不收參數。做四件事：

## 1. 清空兩條雲霧鏈

```pascal
while DS:755Bh <> NIL do begin
    next := DS:755Bh^[4];
    FreeMem(DS:755Bh, 1Eh);      { 傳的是 755Bh 這個變數的位址 }
    DS:755Bh := next;
end;
{ 對 DS:755Fh 重複一次 }
```

節點大小 `1Eh`（30 bytes）與 spec 748 的 `FreeMem` 一致。兩條鏈都清，先 `755Bh`
後 `755Fh`。

## 2. 釋放戰場地圖緩衝區

```pascal
FreeMem(DS:6E92h, 4E9h);
DS:6E92h := NIL;    { 高低字都歸零 }
```

`4E9h` = 1257 bytes。spec 748 的存取式是 `地圖^[y * 32h + x + 7]`，於是：

```
最大索引 = 24 * 50 + 49 + 7 = 1256
配置大小 = 1257
```

**剛好塞滿，一個 byte 不多不少**。因此戰場格陣是 **50 欄 × 25 列**（x 為 0..49、
y 為 0..24），前面 7 個 byte 是不參與索引的表頭。50 = `32h` 直接來自乘數，
25 與 7 是由 1257 這個總量唯一解出來的。

這裡的指標釋放後有歸零；本專案已記錄過數個「釋放後不歸零」的對照點，此處不是
其中之一。

## 3. 兩個尚未辨識的收尾呼叫

| 呼叫 | 參數 | 狀態 |
|---|---|---|
| `0297h:1D19h` | `@DS:75E0h`（var 參數，2 word） | resident，未辨識 |
| overlay-32 entry#5 `@0134h` | 0 word | 未讀 |

`0297h:1D19h` 全 DOS overlay 共有 9 個呼叫端（`overlay-01:0634h`、
`overlay-08:004Dh`、`overlay-10:1C3Eh`、`overlay-14:0BAFh`、`overlay-24:1975h`、
`overlay-29:055Bh`、`overlay-33` 的 `002Eh`／`015Ah`／`0508h`），目前**全部是待
解讀**，所以沒有任何一處可以拿來反推它的語意。

## 4. 把 `DS:72A0h` 換回標準選目標程序

```asm
mov ax, 34h
mov dx, 11Ah
mov ds:72A0h, ax
mov ds:72A2h, dx
```

`011Ah:0034h` 是 VROOMM stub，`(34h − 20h) / 5 = 4` → **overlay-22 entry#4
`@10D2h`**，也就是 spec 719 讀過的「法術選目標模式」程序。

這修正了先前對 `DS:72A0h` 的理解：它不是一張唯讀的分派表，**slot 0 是可換掉的
掛鉤**。戰鬥期間某處會把它指到戰鬥版的選目標程序，收尾時再換回這支通用版。
換掉的那一處尚未找到（本輪沒有掃「誰寫 `72A0h`」）。

## 明確不宣稱

- **沒有宣稱這支就是「戰鬥結束」的唯一入口。** 它做的事符合戰鬥收尾，但呼叫端
  未追；也可能是某個更大流程的一段。
- 沒有宣稱 `DS:75E0h` 是什麼。
- 沒有宣稱 7 個 byte 的表頭裝什麼——只知道索引不會碰到它們。
- 沒有宣稱地圖每格只有 1 個 byte。索引算式是 byte 位移、格距為 1，這點確定；
  但「每格的完整狀態是否還存在別處」未查。
