# 778 — 迷宮地圖的四個平面補齊、PC-98 版「取る：」選單怎麼處理熱鍵

- 證據等級：`exact`（以補洞後的匯出逐條讀完，見 spec 761）

## 迷宮地圖是四個 256-byte 平面

`overlay-30:06BDh`（DOS，`retf 6`，宣告順序 `(x, y, 方向)`）補上了最後兩個：

```pascal
if not 本模組 0556h(x, y) then                     { 0..15 範圍檢查 }
    if (DS:8B5Eh = 0) or (DS:8B5Eh = 0Ah) then begin 結果 := 0; 離開 end;
座標環繞到 0..15;
索引 := (y shl 4) + x;
case 方向 of
    0: 結果 := (DS:7206h^[索引]         and 0F0h) shr 4;
    2: 結果 := (DS:7206h^[索引]         and 00Fh);
    4: 結果 := (DS:7206h^[100h + 索引]  and 0F0h) shr 4;
    6: 結果 := (DS:7206h^[100h + 索引]  and 00Fh);
end;
```

把這一輪與 spec 761／763 合起來，`DS:7206h` 指向的地圖記錄是
**四個 `10h × 10h = 100h` bytes 的平面**：

| 平面 | 內容 | 出處 |
|---|---|---|
| `+000h` | 每格兩個 nibble：高 = 方向 0（北）、低 = 方向 2（東） | 本輪 |
| `+100h` | 每格兩個 nibble：高 = 方向 4（南）、低 = 方向 6（西） | 本輪 |
| `+200h` | 每格一整個 byte | spec 763 `overlay-30:07C6h` |
| `+300h` | 每格四個 2-bit 欄位，方向 0／2／4／6 各一 | spec 761 `overlay-14:003Eh` |

所以**每一格對每個方向有一個 4-bit 的碼（`+000h`／`+100h`）與一個 2-bit 的
旗標（`+300h`）**，另外還有一個整 byte 的屬性（`+200h`）。四個平面共 1024
bytes。

環繞規則與 spec 763 相同：不在 0..15 時，`DS:8B5Eh` 是 `0` 或 `0Ah` 就回 0，
否則繞到對邊。

## PC-98 版的「取る：」選單——熱鍵怎麼處理

`overlay-05:0F0Fh` 是 DOS `overlay-05:0ED7h`（spec 775）的對應版本，結構相同，
但有兩處差異。

### 一、標籤翻成日文，熱鍵**維持 ASCII 字母**

| | DOS | PC-98 |
|---|---|---|
| 提示 | `'Take: '`（6，含尾隨空白） | `'取る：'`（6 bytes） |
| 選項 | `'Money Items Exit'`（16） | `'   お金   ｱｲﾃﾑ                やめる    '`（40 bytes） |

比對的鍵**兩邊都是 `'M'` / `'I'` / `'E'`**——PC-98 版把可見標籤換成
`お金`／`ｱｲﾃﾑ`／`やめる`，卻沒有動熱鍵。這是原始在地化團隊的作法，
**中文版可以照做**：標籤換中文、熱鍵保留英文字母（必要時在標籤裡標出字母）。

選項字串靠**大量半形空白**排版（40 bytes 裡有 22 個空白），不是靠繪字時計算
欄位。中文化要重排版面就得自己數寬度。

### 二、捲動鍵不同

DOS 用 `'G'`（`47h`）與 `'O'`（`4Fh`）——Home／End 的掃描碼。
PC-98 改用 `'8'`（`38h`）與 `'2'`（`32h`）——數字鍵盤的上／下。

兩邊都把按鍵值原樣傳給同一支處理程序。

其餘相同：`'E'` 與 `#0` 一起當離開，每輪結尾更新兩個計數，任一歸零就結束。

## 明確不宣稱

- 沒有宣稱 `+000h` / `+100h` 那 4-bit 碼的值域意義（牆／門／暗門／通道）。
- 沒有宣稱 `DS:8B5Eh` 的 `0` 與 `0Ah` 各代表哪一種地圖。
- 沒有宣稱 PC-98 選單裡 `0A65h:0262h(0Ah, @DS:0A335h, @DS:05DEh)` 那次複製
  搬的是什麼。
