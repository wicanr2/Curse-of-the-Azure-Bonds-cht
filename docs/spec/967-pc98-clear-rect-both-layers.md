# 967 — PC-98 的清矩形：圖形三平面 ＋ 文字兩平面一起清

- 證據等級：`exact`（逐條讀完，來源是 `PC98-GAME.EXE.asm`）
- 位置：`PC98-GAME.EXE` 的 `15647h`
- 作法見 spec 783

## `15647h`（152 行，far，`retf 8`）

`(下 arg_0, 右 arg_2, 上 arg_4, 左 arg_6)`——與 DOS 的 spec 942
（`15F6Ah`）同一個簽章、同一個格線座標系。

```pascal
{ ── ① 圖形：三個平面各清一次 ── }
for 平面 := 0 to 2 do
    <sub_141A0h>(填值 0, 平面, 下, 右 × 2, 上, 左 × 2);   { spec 954 }

{ ── ② 文字：逐列清兩個平面 ── }
for 列 := 上 to 下 do begin
    位移 := (列 × 50h ＋ 左 × 2) × 2;
    寬   := ((右 ＋ 1) × 2 − 左 × 2) × 2;
    <sub_1C180h>(0A000h : 位移, 寬, 0);                   { 字碼平面 }
    <sub_1C180h>(0A200h : 位移, 寬, 1);                   { ★ 屬性平面填 1 }
end;
```

## 兩層一起清

DOS 的 spec 942 只清**圖形**（三種顯示模式各一條路）。
PC-98 版**同時清圖形與文字**——因為 PC-98 的文字與圖形是**兩個獨立的
顯示層疊在一起**（文字在 `A000h`／`A200h`，圖形在 `word_241DEh` 的段），
只清一層會留下另一層的殘影。

這正是 spec 949／956 的三平面貼圖與 spec 950／953 的文字輸出
分屬兩套系統的必然結果。

## 座標換算

- **圖形**：`左 × 2`／`右 × 2` ——格線的一欄對到**圖形的兩欄**。
- **文字**：`(列 × 50h ＋ 左 × 2) × 2` ——`50h` ＝ 80 個文字格一列，
  `左 × 2` 是格線欄轉文字格（spec 950 的同一條規則），
  最後 `× 2` 是每格兩個 byte。
- 寬度 `((右 ＋ 1) × 2 − 左 × 2) × 2` ——含右端點。

**格線的一欄 ＝ 文字的兩格 ＝ 圖形的兩欄**，三個座標系在這裡對齊。

## ★ 屬性平面填 `1`

與 spec 964 的輸入欄一致：**清空的意思是「字碼 0、屬性 1」**，
不是兩個平面都填 0。

## 明確不宣稱

- 沒有宣稱屬性值 `1` 代表什麼顏色。
- 沒有宣稱為什麼圖形只清 0、1、2 三個平面而不是四個
  （與 spec 949 的三平面貼圖一致，第四平面的處理未知）。
