# 950 — PC-98 的格清除（每格佔兩個文字格）與按鍵表的二段轉譯

- 證據等級：`exact`（兩支逐條讀完，來源是 `PC98-GAME.EXE.asm`）
- 位置：`PC98-GAME.EXE` 的 `142B9h`、`16FECh`
- 作法見 spec 783

## ★ `142B9h`（77 行，far，`retf 8`）：清掉幾個格

`(格數 arg_0, 列 arg_4, 欄 arg_6)`。

```pascal
if (欄 > 27h) or (列 > 18h) then 離開;         { 無號；27h ＝ 39、18h ＝ 24 }

位移 := (列 × 50h ＋ 欄 × 2) × 2;
<sub_1C180h>(0A000h:位移, 格數 shl 2, 0);      { 字碼平面 }
<sub_1C180h>(0A200h:位移, 格數 shl 2, 0);      { 屬性平面 }
```

三件事一次對上：

1. **座標上界是 39 欄 × 24 列**——與 spec 937 的畫字元分派層相同，
   也就是那個 **40 欄格線座標系**。
2. **`欄 × 2`**：一個格線欄佔**文字畫面的兩個格**。`列 × 50h` 是
   80 個文字格一列，所以格線的 40 欄剛好鋪滿 80 欄的文字畫面。
   清除長度 `格數 shl 2` ＝ 每格 4 bytes ＝ 2 個文字格 × 2 bytes。
3. **`0A200h` 就是屬性平面**：spec 946 記的是「`A000:0000` 字碼、
   `+2000h` 屬性」，本支改用段基底寫成 `0A200h:位移`——同一個位址的
   另一種寫法（`0A200h × 16 ＝ 0A000h × 16 ＋ 2000h`）。

## `16FECh`（77 行）：按鍵表的第二段轉譯

```pascal
FillChar(ds:29A4h, byte_1ED34h 個 word, 0);
di := 29A4h;   si := 28A4h;   cl := byte_1EB33h;
while cl > 0 do begin
    項 := word(ds:si);   dec(cl);
    if hi(項) <> 0 then begin                          { 雙 byte 項 }
        k := <sub_17148h>(項, ds:2AE2h);
        word(ds:di) := word[2AAEh ＋ (k − 1) × 2];
    end else begin                                      { 單 byte 項 }
        k := <sub_1711Fh>(項, ds:2C52h);
        word(ds:di) := word[2B18h ＋ (k − 1) × 2];
    end;
    di := di ＋ 2;   si := si ＋ 2;
end;
```

spec 949 的 `1705Ah` 把設定字串展開成 `ds:28A4h` 的 word 表，
**本支再把它轉成 `ds:29A4h` 的第二張表**。兩張表用不同的查找來源：

| 項目型別 | 查哪張 | 取值來源 |
|---|---|---|
| 雙 byte（`hi <> 0`） | `ds:2AE2h`（用 `<sub_17148h>`） | `ds:2AAEh` |
| 單 byte | `ds:2C52h`（用 `<sub_1711Fh>`） | `ds:2B18h` |

⚠ 兩支的來源長度不同：`1705Ah` 用 `byte_1ED34h` 當清空長度，
**本支清空也用 `byte_1ED34h`，但走訪迴圈的次數是 `byte_1EB33h`**。
兩者不一致時，`29A4h` 的尾端會留著 0。

所以按鍵對應是 **設定字串 → 第一張 word 表 → 第二張 word 表** 的兩段轉譯，
最後由 spec 945 的 `16E70h` 分派迴圈使用。**全部資料驅動，沒有寫死。**

## 明確不宣稱

- 沒有宣稱 `<sub_1C180h>`（填值）的參數順序細節，只知道第三個是 0。
- 沒有宣稱 `ds:2AAEh`／`ds:2AE2h`／`ds:2B18h`／`ds:2C52h` 四張表的內容。
- 沒有宣稱 `byte_1EB33h` 與 `byte_1ED34h` 的關係。
- 沒有宣稱第二張表 `ds:29A4h` 由誰讀（形狀上是 `16E70h` 那一族）。
