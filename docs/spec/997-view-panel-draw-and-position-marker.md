# 997 — 視野面板的繪製與位置標記（兩平台一次收）

- 證據等級：`exact`（PC-98 側 206 條逐條讀完；DOS 側 274 條由三個差異區塊
  與 30 處運算元差異逐條比對）
- 作法見 spec 783

## `pc98 overlay-30:0018Ch`（206 條）↔ `dos overlay-30:0018Ch`（274 條）

兩側**原本都是待解讀**，這一輪一起收。

```pascal
{ ── 第一段：三（或四）塊定點貼圖 ── }
if DOS 且 DS:4FE6h <> 0 then begin                       { ★ DOS 才有的分支 }
    <貼圖>(2, 10h, 0Bh, 2Bh, DS:720Ah, @圖庫, 畫布);
    <貼圖>(2, 3Bh, 0Bh, 01h, DS:720Bh, @圖庫, 畫布);
    <貼圖>(2, 3Ch, 0Bh, 02h, DS:720Ch, @圖庫, 畫布);
    <貼圖>(2, 3Eh, 0Bh, 2Ah, DS:720Dh, @圖庫, 畫布);
    goto 收尾;
end;
<貼圖>(2, 10h, 高, 2Ch, 第一個值, @圖庫, 畫布);
<貼圖>(2, 3Ch, 高, 02h, 第三個值, @圖庫, 畫布);
<貼圖>(2, 3Eh, 高, 2Ah, 第四個值, @圖庫, 畫布);

{ ── 第二段：位置標記 ── }
if <本模組 0710h/07C6h>(縱, 橫) >= 80h then goto 收尾;
if 第一個值 <> 0Bh then goto 收尾;

x1 := 2; y1 := 2; x2 := 0Ch; y2 := 0Ch;
v := word(遠指標(狀態)^[192h]);

if (v >= 1) and (v <= 5) then begin
    if      方向 = 2 then <貼>(x2 − 3,      y1 ＋ 5 − v, 圖A)
    else if (方向 = 4) and (v > 2) then
                          <貼>(x1 ＋ v − 3, y1 ＋ 5 − v, 圖A);
end
else if (v >= 0Dh) and (v <= 12h) then begin
    if      方向 = 6 then <貼>(x1,          y1 ＋ v − 0Dh, 圖A)
    else if (方向 = 4) and (v < 10h) then
                          <貼>(x1 ＋ v − 8, y1 ＋ v − 0Dh, 圖A);
end;

if 方向 = 0 then <貼>(x1, y1, 圖B);

收尾:
<貼>(2, 7, 圖C);
```

（`<貼>` ＝ `2A8h:077Dh`／`297h:09E4h`，推疊順序 `(欄, 列, 0, 1, 圖, 畫布)`。）

## ★ `DS:4FE6h` 第三次出現，語意收窄

| 出處 | `DS:4FE6h` 的作用 |
|---|---|
| spec 976（`overlay-28:000CCh`） | `<> 0` 走簡化路徑（只設 `DS:720Dh := 8`） |
| spec 979（`overlay-17:03B99h`） | `<> 0` 多畫一對 `19h` 號圖示、且第五參數由 `3` 換成 `0` |
| **本規格** | `<> 0` 走 **四塊** 的貼圖版本，`= 0` 走 **三塊** |

三處都是「顯示內容多寡」的開關，而且**PC-98 一律走 `= 0` 的那一條**
（PC-98 側根本沒有這個分支）。所以

> **`DS:4FE6h` 是 DOS 專屬的顯示模式旗標，PC-98 版把它整個拿掉了。**

本規格仍不宣稱它代表哪一種顯示模式。

## ★ PC-98 的第三個參數正好是 DOS 的兩倍

三次（DOS 四次）貼圖裡，第三個參數 DOS 一律 `0Bh`（11）、PC-98 一律 `16h`（22）。
**其餘三個座標常數（`2`／`10h`／`3Ch`／`3Eh`／`2Ch`／`2Ah`）兩邊完全相同。**

只有一個維度加倍 ⇒ 那一格是**與解析度相關的尺寸**（PC-98 的垂直解析度是
DOS 的兩倍：640×400 對 320×200）。本規格不宣稱它是高度還是行數。

## ★ PC-98 多一層查表

DOS 直接把 `DS:720Ah` 當圖號用，PC-98 是 `byte[169Ch ＋ DS:0A2A4h]`——
**多了一張以視野狀態為索引的轉換表 `DS:169Ch`**。
spec 976 讀 `overlay-28` 時看到 `DS:0A2A4h := byte[164Ch ＋ …]`（DOS `DS:0A88h`），
所以 PC-98 這條路上**同一個值被查了兩次表**。

## 一次補齊六組跨平台對應

| DOS | PC-98 | 內容 |
|---|---|---|
| `DS:25A2h` | `DS:4830h` | 貼圖用的圖庫（spec 979 見過 DOS 側） |
| `DS:4FE8h`／`4FEAh` | `DS:7F56h`／`7F58h` | 目標畫布遠指標 |
| `DS:7220h`／`7222h` | `DS:0A2BAh`／`0A2BCh` | 圖 B |
| `DS:7224h`／`7226h` | `DS:0A2BEh`／`0A2C0h` | 圖 A |
| `DS:7228h`／`722Ah` | `DS:0A2C2h`／`0A2C4h` | 圖 C |
| `0297h:1D8Dh` | `02A8h:1174h` | 定點貼圖（七個參數） |
| `0297h:09E4h` | `02A8h:077Dh` | 貼一張圖（六個參數） |

`DS:720Ah`..`720Dh` ↔ `DS:0A2A4h`..`0A2A7h`、`DS:720Fh`／`7210h` ↔
`DS:0A2A9h`／`0A2AAh`、`DS:7211h` ↔ `DS:0A2ABh`（方向）
在 spec 976／986 已定，這裡是第三個佐證。

## 位置標記的兩段區間

`v` ＝ 狀態記錄 `+192h` 的 word。兩段有效區間 **1..5** 與 **13..18**，
落在區間外就不畫標記。方向（`DS:7211h`／`0A2ABh`）只有 `2`／`4`／`6`
會畫，`0` 走另一張圖（圖 B）畫在 `(x1, y1)`。

方向值是**兩倍刻度**（spec 986：ECL 讀 `C04Dh` 時要 `÷2`），
所以 `2`／`4`／`6` 對應方向 `1`／`2`／`3`。

⚠ **方向 `4` 在兩段區間都有分支，而且各自多一個條件**
（第一段要 `v > 2`、第二段要 `v < 10h`）。方向 `2` 與 `6` 沒有額外條件。
本規格不宣稱那兩個額外條件擋掉的是什麼情況。

⚠ `x2`／`y2`（`0Ch`）被指派卻**只有 `x2` 被用到一次**（`x2 − 3`），
`y2` 從頭到尾沒被讀。兩平台都一樣。

## 明確不宣稱

- 沒有宣稱七參數貼圖（`0297h:1D8Dh`）各參數的意義。
- 沒有宣稱三張圖（A／B／C）各畫什麼。
- 沒有宣稱狀態記錄 `+192h` 存的是什麼（形狀上是視野內的距離或格數）。
- 沒有宣稱 `本模組 0710h`／`07C6h` 回傳什麼（只知道 `>= 80h` 就整段跳過）。
- 沒有宣稱 `DS:169Ch`（PC-98）與 `DS:164Ch`／`DS:0A88h` 三張表的內容。
