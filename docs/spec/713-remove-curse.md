# 第七百一十三輪：解除詛咒——搜尋的欄位和清掉的欄位不是同一個

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：DOS `overlay-22:3599h`。

## 流程

```text
if <overlay-23 entry#16>(目標, 24h) then          ← 身上有效果 24h
    <overlay-24 entry#26>(目標, 1, '<名字> is un-cursed'（CS:3576h）)
else
    found := 0
    p := 目標^[14Dh]                              ← 物品鏈（spec 695）
    while p <> NIL 且 found = 0 do
        if p^[36h] <> 0 then
            found := 1
            p^[34h] := 0                          ← ⚠ 清的是 +34h，不是 +36h
            if p^[3Eh] > 7Fh then                 ← 第三個效果槽的最高位（spec 703）
                DS:7582h := 1
                <overlay-23 entry#2>(p^[3Eh], 目標, p, 1)
                for k := 0 to 5 do <overlay-23 entry#24>(目標, k)
        p := p^[2Ah]
    if found <> 0 then
        <overlay-24 entry#26>(目標, 1, '<名字> has an item un-cursed'（CS:3583h）)
```

## 三件要注意的

**搜尋鍵是 `+36h`，被清掉的是 `+34h`。** 兩個欄位分別是 spec 696 建構子的第 9 個
與第 7 個參數。`+36h` 從頭到尾沒有被改，所以再施放一次會**找到同一件物品**，
訊息也會再出現一次。這可能是刻意的（「被詛咒」的性質留著，只解掉「黏在身上」
那個狀態），也可能是 bug；本輪沒有第二條證據，remake 照抄即可，但要知道它會
重複觸發。

**一次只解一件。** 迴圈條件是 `p <> NIL 且 found = 0`，找到第一件就停。身上有
兩件被詛咒的物品時要施放兩次——而因為上一點，第二次可能仍然解到第一件。

**兩條路互斥。** 身上有效果 `24h` 時走第一條並且**完全不碰物品鏈**；沒有才去
翻物品。所以「角色被詛咒」和「物品被詛咒」是兩套機制，一次只處理一套。

## `entry#2` 的參數形狀再確認

```text
<overlay-23 entry#2>(效果編號, 目標 far, 節點 far, 旗標)   ← 6 個 word，retf 0Ch
```

這裡的第三個參數是**物品節點**（`p`），和 spec 704 `4311h` 傳「找到的節點」、
spec 706 `5590h`／`262Fh` 傳 0 一致。第五個呼叫點，形狀不變。
