# 748 — 雲霧類效果的解除程序（`overlay-12:0C61h` 與 `1CF6h` 雙胞胎）

- 平台／模組：DOS `overlay-12`（`0C61h`、`1CF6h`，各 268 條指令 / 718 bytes）
- 證據等級：`exact`（逐指令讀完 `0C61h`；`1CF6h` 逐位元組與前者比對，差異已窮舉）
- 相關：[`685`](685-bank1-582-movement-budget.md) 的鏈結串列走訪慣用法、
  [`716`](716-nil-check-per-access-site.md) 的 NIL 檢查掃描

## 兩支是同一段原始碼的兩份實例

助憶碼序列 268 條完全相同，位元組不同。扣掉分支目標（位址本來就不同）之後，
**運算元只差 13 處**，全部落在五個常數上：

| 差異 | `0C61h` | `1CF6h` |
|---|---|---|
| 效果鏈頭（far ptr） | `DS:755Bh` | `DS:755Fh` |
| 訊息字串位址 | `CS:0C46h` | `CS:1CDBh` |
| 形狀表基底 | `DS:27D7h` | `DS:27DBh` |
| 迴圈上限（格數） | 4 | 9 |
| 重繪磚碼 | `1Eh` | `1Ch` |

兩處訊息內容相同，都是 26 字元的 `The air clears a little...`——**同一模組內的重複
字串**，中文化時兩份都要改（見 `docs/audit/duplicate-strings.md` 的同類清單）。

形狀表的兩段是連續的：`0C61h` 讀 `27D8h..27DBh`（4 格），`1CF6h` 讀
`27DCh..27E4h`（9 格），合起來 13 bytes，互不重疊。

## 介面

`retf 0Ah` = 5 個 word。參數由左至右推入，**第一個宣告的參數在最高位址**：

```pascal
procedure 解除雲霧(擁有者: 遠指標;   { [bp+0Ch] / [bp+0Eh] }
                   節點:   遠指標;   { [bp+08h] / [bp+0Ah] }
                   未用:   word);    { [bp+06h]，函式本體從未讀取 }
```

## 流程

```pascal
key := 節點^[3] div 16;              { cwd + idiv 10h，取高 4 bits }
p   := 鏈頭;                          { DS:755Bh / DS:755Fh }
while (p <> NIL) and not found do
    if (p^[0..3] = 擁有者) and (p^[1Ch] = key)
        then found := true
        else p := p^[4];              { next 在 +4 }
if not found then exit;

顯示(concat(CS:0C46h, ...));          { 0A54:0634 起頭，overlay-24 entry#19 輸出 }

{ 第一遍：抹掉這個節點佔的格子 }
for k := 1 to 4 do begin              { 1CF6h 是 1 to 9 }
    if p^[10h + k] = 0 then continue; { 這一格沒佔用 }
    x := p^[1Ah] + byte[2694h + byte[27D7h + k]];
    y := p^[1Bh] + byte[269Dh + byte[27D7h + k]];
    if 有生物站在 (x, y) then          { 掃 DS:6E52h 起、每筆 7 bytes 的陣列 }
        地圖[y * 32h + x]^[7] := 1Fh
    else
        地圖[y * 32h + x]^[7] := p^[7 + k];   { 還原存起來的原磚 }
end;

{ 第二遍：把節點自鏈結串列摘掉並釋放 }
… 標準單向串列 unlink …
FreeMem(p, 1Eh);                      { 節點固定 30 bytes }

{ 第三遍：剩下的節點整條鏈重畫 }
q := 鏈頭;
while q <> NIL do begin
    for k := 1 to 4 do
        if q^[10h + k] <> 0 then
            地圖[…]^[7] := 1Eh;       { 1CF6h 是 1Ch }
    q := q^[4];
end;
```

「有生物站在 (x, y)」的判斷：`for i := 1 to DS:6E91h`，每筆 7 bytes，基底
`DS:6E52h`；先檢查 `[6E52h + i*7]` 的遠指標非 NIL，再比 `[6E56h + i*7] = x`、
`[6E57h + i*7] = y`。地圖以 `DS:6E92h` 為遠指標基底，列寬 `32h`（50），
格子的第 7 個 byte 是顯示用磚碼。

## 節點欄位（30 bytes）

| 位移 | 用途 |
|---|---|
| `+00h`（4） | 擁有者遠指標，比對用 |
| `+03h` | 高 4 bits 是 `key`（與參數節點的 `+3` 同一種打包，見前述 `div 16`）|
| `+04h`（4） | 鏈結 next（遠指標）|
| `+07h`+k | 第 k 格被蓋掉之前的原磚碼 |
| `+10h`+k | 第 k 格是否佔用（0 = 否）|
| `+1Ah` / `+1Bh` | 錨點 x / y |
| `+1Ch` | key，配合擁有者一起認節點 |

`+03h` 與 `+1Ch` 同時被讀：`+03h` 讀的是**傳進來的那個節點**（參數），`+1Ch`
讀的是**鏈上候選節點**。兩者是同一個 key 的兩種存法（一個打包在高 4 bits，
一個是整個 byte）——這和 effect node `+3` 三種不同打包的既有觀察一致
（見 spec 728 註記）。

## 兩遍重繪不對稱（實作時要注意）

第一遍抹除時會查生物陣列，有人站著就畫 `1Fh`；第三遍重畫剩餘節點時
**完全不查**，一律畫 `1Eh` / `1Ch`。所以當兩片雲重疊、而重疊格上站著生物時，
第三遍會把第一遍畫的 `1Fh` 蓋掉。這是原版行為，remake 照抄之前建議先以實機
確認畫面，不要當成 bug 逕自「修正」。

## 明確不宣稱

- **沒有宣稱這兩支對應哪兩個法術。** 4 格與 9 格是位元組事實，形狀不是——
  `DS:27D8h..27E4h` 的實際內容位於 resident 資料段，本輪沒有 dump，無從得知
  這 13 個索引指向哪些方向。`2694h` / `269Dh` 的 dx／dy 表內容同樣未讀。
- **沒有宣稱 `1Eh` / `1Ch` / `1Fh` 是哪個圖塊。** 只知道是寫進地圖格 `+7` 的
  顯示碼，以及三者互不相同。
- **沒有宣稱建立側的流程。** 上表六支都沒讀，節點是誰配置、`+07h`+k 的原磚在
  哪裡存進去、`key` 怎麼產生，全部未確認。
- 第三個參數 `[bp+06h]` 在本體內確實沒有任何讀取；但呼叫端為何要推它，
  未追。
