# 第六百五十五輪：堆積區塊標頭與完整性檢查

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：PC-98 `PC98-GAME.EXE` 的 `187AAh`、`187ECh`、`18392h`。

## 區塊標頭

| 位移 | 內容 |
|---|---|
| `+0` | 大小（段落數） |
| `+6` | **同一個大小再存一次** |
| `+8` | 魔術數 **`818Eh`** |

`+2`、`+4` 這兩個 word 在配置時**沒有被寫**（[spec 654](654-overlay-heap-manager.md)
的串列用 `+4` 當 next，所以那是後續才填的）。

## `187AAh`：由上往下切

```text
輸入：AX ＝ 需要的段落數
ax := ax + 1                              ← 多要一段放標頭
dx := word_24188h − ax
if 借位 then return 0                      ← 剩餘不足
word_24188h := dx                          ← 剩餘減少
bx := word_24186h                          ← 這一塊的起點
word_24186h := bx + ax                     ← 下一次從這裡開始
ax := ax − 1                               ← 標頭裡記的是「不含標頭」的大小
es := bx
es:[0] := ax
es:[6] := ax
es:[8] := 818Eh
return bx + 1                              ← 跳過標頭那一段
```

`word_24186h` 是**下一個可用 segment**、`word_24188h` 是**剩餘段落數**。這是單向
推進的配置，**沒有回收路徑**——這支只會往前切。

回傳 `bx + 1`，與 [spec 654](654-overlay-heap-manager.md) 的 `18767h` 一致：呼叫端
拿到的位址已經跳過標頭。

## `187ECh`：驗證區塊

```text
輸入：BX ＝ 呼叫端持有的 segment
bx := bx − 1                               ← 退回標頭
if es:[8] <> 818Eh then 設進位（無效）
else if es:[0] <> es:[6] then 設進位（無效）
else 清進位（有效）
```

兩道檢查：**魔術數**與**大小的兩份副本是否一致**。後者能抓到「往前寫超出前一塊」
的破壞——覆寫 `+0` 而沒有同步 `+6` 就會被發現。

進位置起表示無效（與 [spec 574](574-pc98-shiftjis-and-text-vram.md) 的首位元組判斷
同一種「進位 ＝ 否定」慣例）。

## `18392h`

```text
<sub_1C15D>(arg_2^, @var_4, 4)             ← 搬 4 bytes
<sub_1C15D>(@var_8, @var_2, 2)             ← 搬 2 bytes
<sub_188B1>(var_8)
arg_2^[0..3] := 0                           ← 把來源清空
inc word_280B8h                             ← 計數器加一
```

先把 `arg_2` 指的 4 bytes 搬走，處理完之後**把原處清成 0**——所有權轉移的寫法。

`sub_188B1` 的回傳值存進 `var_109` 後沒有再讀。
