# 849 — 角色記錄的解構子：DOS `1A6h`／PC-98 `1A7h`，一次確認四種節點大小

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側助憶碼序列完全相同，12 條差異全是位址與尺寸）
- 作法見 spec 783

## `overlay-17:0003Eh` ↔ `overlay-17:0003Eh`（兩平台各 79 條，同位址）

`retf 4` ＝ 一個**指向角色遠指標的遠指標**（釋放後要寫回 NIL，所以是 var 參數）。

```pascal
p := 指標^;

if p^[18Dh] <> NIL then FreeMem(p^[18Dh], 16h);        { 戰鬥狀態 }

q := p^[14Dh];                                          { 物品鏈 }
while q <> NIL do begin
    暫 := q;  q := q^[2Ah];
    FreeMem(暫, 3Fh);
end;

r := p^[0F2h];                                          { 另一條鏈 }
while r <> NIL do begin
    暫 := r;  r := r^[5];
    FreeMem(暫, 9);
end;

FreeMem(p, 1A6h);
指標^ := NIL;
```

## 四個尺寸一次到齊

| 對象 | DOS | PC-98 | 先前出處 |
|---|---|---|---|
| 角色記錄 | **`1A6h` ＝ 422** | `1A7h` ＝ 423 | PC-98 側早由 Borland type table（spec 499）與 ECL 的 `New`／`Move`（spec 604／617）確認；**DOS 側到這一支才有直接證據** |
| 戰鬥狀態（`+18Dh`／`+18Eh`） | `16h` ＝ 22 | `16h` ＝ 22 | spec 806（GetMem／FreeMem 兩邊都是 `16h`） |
| 物品節點（`+14Dh`／`+14Eh` 鏈） | `3Fh` ＝ 63 | `67h` ＝ 103 | spec 832 |
| `+0F2h` 鏈的節點 | `9` | `9` | **本支新增** |

**DOS 422 / PC-98 423 這一個 byte 的差**就是全專案到處看到的 `+1` 位移來源：
`+18Dh`↔`+18Eh`、`+195h`↔`+196h`、`+1A4h`↔`+1A5h` 等等。差的那一格插在
`+18Dh` 之前的某處（`+14Dh`↔`+14Eh` 已經差 1，`+0F2h` 兩邊相同），
所以**插入點在 `+0F2h` 與 `+14Dh` 之間**。

## `+0F2h`：一條 9 bytes 的鏈，next 在 `+5`

角色記錄上的第二條鏈結串列，節點只有 9 bytes，`next` 在 `+5`（不是 `+2Ah`）。
**兩平台節點大小相同**，與物品節點（DOS 63／PC-98 103）不同——所以這個節點裡
沒有字串。

**`overlay-20:00020h`（時間推進）給出了用途**：那是**計時中效果的清單**。
節點版面到 spec 862 補齊：

| 位移 | 內容 | 出處 |
|---|---|---|
| `+0` | 效果碼 | overlay-20:00020h |
| `+1`（word） | 剩餘時間 | overlay-20:00020h |
| `+3` | 低 4 bits ＝ 效果等級（`0FFh` ＝ 不可驅散）、高 4 bits ＝ 實例編號 | spec 862 |
| `+5` | next | 本支 |

時間前進時 `+1` 逐一遞減，歸零就叫 `141h:002Fh` 把效果移除。

## 解構子的三個防護

- 戰鬥狀態先檢查非 NIL 才釋放。
- 兩條鏈都是「先抄下一個再釋放目前這個」的標準寫法，沒有 use-after-free。
- 最後把呼叫端的指標寫回 NIL（DOS 寫成 `mov [di], ax` ＋ `mov es:[di+2], ax`，
  PC-98 兩條都帶 `es:` 前綴——**DOS 第一條少了段前綴**，但前一條 `les di,[bp+arg_0]`
  已經把 `es` 設成同一個段，所以行為相同）。
