# 1125 — 收尾不是標準那兩支的法術：逐支讀完的規則

- 證據等級：`exact`（`overlay-22` 的九支 handler 與 `overlay-23` 的四支入口逐條
  讀完；效果 `22h` 的 handler 在 `overlay-12@09A7h`）
- 對應工作項：`ENG-09` 最後 23 支的宣告
- 上游 spec 1111（法術屬性表）、spec 1117（資料驅動施法）、spec 1123（效果修正
  表）、spec 1124（傷害骰）、spec 1119（障礙地形碼）

## 為什麼這幾支要單獨讀

傷害骰表（spec 1124）能機械抽出來的，是「擲一次骰、把值交給標準收尾」那一種。
剩下的十五支**收尾另有出路**——擲出來的東西根本不是傷害：

| 法術 | 表裡抽到 | 那顆骰其實是 |
|---|---|---|
| 火焰護盾 | `1d10` | 電腦操作時挑熱／冷 |
| 解除魔法 | `1d100` | 對抗擲骰 |
| 屠殺活物 | `2d8` | **豁免成功**那一支的傷害 |

照抽到的數字接上去，每一支都會得到「自洽但錯」的規則，而且錯得看不出來。

## 解除魔法（41 牧師／46 法師，`ov22@317Eh`）

同一支 handler。對**半徑 1** 內每個目標走一遍效果串列，每個效果各擲一次 `1d100`：

```pascal
if 施法者等級 > 效果等級 then 機率 := (差) * 5 + 50
else if 施法者等級 < 效果等級 then 機率 := 50 - (差) * 2
else 機率 := 50;
if <1d100> <= 機率 then 移除這個效果;
```

★ **兩個方向的係數不一樣**：高出去每級 ＋5，低下去每級 −2。寫成對稱的 ±5，
低階施法者會解得太少、高階會解得太多，而兩邊都沒有明顯症狀。

`EFFECTREC +3` 為 `0FFh` 的效果**跳過**——那是「解不掉」的標記。

handler 的後半段處理**地形障礙**：目標點周圍九格裡地形碼是 `1Ch`／`1Eh`
（spec 1119 的那兩種）的，把障礙物件身上的 `28h`／`5Bh` 一併對抗掉。

## 移除詛咒（43 牧師／89 法師，`ov22@3599h`）

```pascal
if <overlay-23 entry#16>(目標, 24h) <> 0 then 印訊息並結束;   { 拿掉了就結束 }
走目標的物品鏈（+14Dh 起，+2Ah 串下去）：
    if 物品^[36h] <> 0 then begin                             { 詛咒 }
        物品^[34h] := 0;                                      { 解除裝備狀態 }
        if 物品^[3Eh] > 7Fh then begin
            移除物品帶的那個效果;
            重投影六個衍生欄位;
        end;
        結束迴圈;                                             { 只處理第一件 }
    end;
```

★ 兩步是**有順序**的，而且第一步成功就結束。順序反過來會讓身上有 `24h` 的人
連裝備也一起被解開。

⚠ 它清的是 `+34h`（已裝備），**不是** `+36h`（詛咒旗標）。所以這支法術只是讓人
脫得下來，詛咒本身還在——重新裝上去會再黏住。

`overlay-23 entry#16(目標, 碼)` 是「有就移除並回 1，沒有回 0」。

## 次元門（83，`ov22@48E4h`）

```pascal
if 施法者身上有 3Ah then
    for 半徑 1 內的每個戰鬥員 do
        if 它的 90h 或 8Bh 指回施法者 then 把 90h 與 8Bh 拿掉;
把施法者移到選定的格子;
```

沒有 `3Ah` 就只做移動。解開那兩個標記是必要的：不解的話它們會留在原地指著
已經不在那裡的人。

## 火焰護盾（85，`ov22@4BECh`）

跳選單讓玩家選 `H`（熱）或 `C`（冷）；**由電腦操作時改成擲 `1d10`，大於 5 選熱**。
兩種形態各掛兩個效果：

| 形態 | 效果碼 |
|---|---|
| 熱 | `32h` ＋ `8Fh` |
| 冷 | `36h` ＋ `8Fh` |

第二個是共用的。持續時間由 `sub_E11(55h, 碼)` 算出來。

## 燃燒之手（9，`ov22@1E7Ch`）與寒冰錐（92，`ov22@54EBh`）

兩支的傷害都含施法者等級，所以不在機械表裡（spec 1124）：

```pascal
{ 燃燒之手 }  傷害 := <overlay-24 entry#44>(法術編號);        { 就是施法者等級 }
              旗標 := 09h;                                    { 火 }

{ 寒冰錐 }    等級  := <overlay-24 entry#44>(法術編號);
              半徑  := (等級 + 1) div 2;  if 半徑 < 1 then 半徑 := 1;
              傷害  := <擲 等級d4> + 等級;
              旗標  := 0Ah;                                   { 冷 }
```

★ 寒冰錐的**半徑不在法術屬性表裡**（表裡是 0），是 handler 自己算的。照表用 0
只會打中心那一格。

## 復原術（56，`ov22@3D27h`）：兩個先前未定的角色欄位

```pascal
if 角色^[0E7h] = 0 then 結束;                     { 沒有被吸掉的等級 }
每級HP := 角色^[0E8h] div 角色^[0E7h];
角色^[78h]  += 每級HP;                            { 最大 HP }
角色^[1A4h] += 每級HP;                            { 目前 HP }
角色^[12Ch] += 每級HP;                            { 基準最大 HP }
角色^[0E8h] -= 每級HP;
角色^[0E7h] -= 1;
```

所以 `+0E7h` 是**被吸掉的等級數**、`+0E8h` 是**連帶少掉的 HP 總數**，兩格在
角色記錄台帳裡原本都標「未定」。

還等級時走八個職業（`+109h + 職業索引`），只看**等級不高於目前最佳**且下一級
門檻不為 0 的，取門檻**最小**的那一個，把該職業等級加一，並把角色經驗值補到
那個門檻。兩個條件是同時成立的：只比門檻會挑到高等職業。

## 效果掛效果：疾病（40）

疾病掛的是效果 `22h`，而 `22h` 的 handler（`overlay-12@09A7h`）連續兩次呼叫
「加效果」把 `2Bh` 與 `2Ch` 掛上去。

★ 這是**效果碼的性質，不是法術的性質**。任何來源（法術、怪物能力、物品）掛上
`22h` 都會連帶掛那兩個，所以規則寫在效果那一側（`combat.EffectChainCodes`）。

## 毒（68，`ov22@4289h`）：掛效果的標準三步

```pascal
sub_F06(法術編號, 0, 0, 0, 8, 訊息);              { 傷害 0，只印訊息 }
ds:6F93h := 40h;                                  { 要掛的效果碼 }
CHECKFX(目標, 09h);                               { 這一步可能把它清掉 }
if ds:6F93h = 40h then 加效果(40h, 目標, 來源, 0);
```

★ **中間那一步是閘**：`CHECKFX(09h)` 會讓免疫類效果把碼清掉，清掉就不掛。
少了它，免疫毒的目標照樣中毒。

## 法師版降咒術（100，`ov22@36A7h`）

`sub_F06(法術編號, 0, 0, 0, 0, 訊息)`——傷害 0、旗標 0、屬性表的效果碼也是 0。
**這支在戰鬥中就只消耗法術位並印一句話**，不是 remake 少做。

## remake 這一側

| 法術 | behavior | 實作 |
|---|---|---|
| 41／46 | `dispel_magic` | `combat.CastDispelMagic`／`DispelChance` |
| 43／89 | `remove_curse` | `combat.RemoveCurseAffect` ＋ `freeFirstCursedItem` |
| 83 | `dimension_door` | `combat.CastDimensionDoor` |
| 85 | `fire_shield` | `combat.CastFireShield`／`RollFireShieldHot` |
| 92 | `cone_of_cold` | `combat.ConeOfColdRadius` ＋ `CastAreaDamageDice` |
| 9 | `damage_dice` | `combat.SpellDamageRoll` 的算式表 |
| 56 | `restoration` | `restoreDrainedLevel` ＋ 角色的兩個新欄位 |
| 68 | `apply_effect_codes` | `combat.ApplyEffectCodes`（帶 `CHECKFX(09h)` 閘）|
| 40 | `effect` | 效果 `22h` ＋ `combat.EffectChainCodes` |
| 100 | `message_only` | 只消耗法術位 |

其餘十三支走既有的資料驅動 `effect`。效果記錄現在會記施法者等級
（`EFFECTREC +4`），解除魔法要靠它算對抗。

## 明確不宣稱

- 沒有宣稱 DOS 的 `EFFECTREC +3` 與 PC-98 的 `+3`（spec 434 量到是 `CASTON`）
  是同一個語意。解除魔法讀它的低四位當等級、次元門把它整個當戰鬥員索引——
  這一格顯然按效果種類有不同用法，還沒查清楚。remake 的解除魔法讀的是
  `+4`（spec 434 驗過的施法者等級那一格），不可解除的界線用 `Innate` 表示。
- 沒有宣稱解除魔法後半段的地形障礙那條路已經接上：remake 的障礙只有地形碼，
  沒有帶效果串列的障礙物件。
- 沒有宣稱火焰護盾的熱／冷選單已經接上：remake 兩邊都走那顆 `1d10`，
  玩家還選不了。掛的效果碼與持續時間照原作。
- 沒有宣稱效果 `32h`／`36h`／`8Fh`／`3Ah`／`90h`／`8Bh` 各自做什麼——
  只知道哪一支法術掛上或拿掉它們。
- 沒有宣稱 `sub_E11` 怎麼算持續時間；remake 用法術屬性表的係數。
- 沒有宣稱復原術挑職業那一段與原作逐條相同：原作用的是常駐段的經驗值表
  （`4291h` 起、每職業 63h bytes），remake 用自己那份職業門檻表，
  兩份的索引對應沒有逐格比對過。
- 沒有宣稱有任何東西會吸等級：`+0E7h`／`+0E8h` 目前沒有寫入者，
  所以復原術實際上一定是「沒有可恢復的等級」。**規則對了，來源還沒接。**
