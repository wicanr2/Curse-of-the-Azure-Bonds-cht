# 925 — 套模板：把角色的每一項抬到下限，錢不夠就重發

- 證據等級：`exact`（兩平台都逐條讀完；相似度 0.922）
- 作法見 spec 783

## `overlay-16:01F21h`（DOS 245 條）↔ `overlay-16:026CFh`（PC-98 253 條）

`retf 2` ＝ **巢狀程序**，唯一參數是父程序的 `bp`（Turbo Pascal 慣例，
以 `ss:[di±N]` 存取父層變數）。整支無字串。

父層變數：

| DOS | PC-98 | 內容 |
|---|---|---|
| `ss:[父bp ＋ 0Ah]` | 同址，**多一層間接** | 角色遠指標 |
| `ss:[父bp − 1C4h]` | `ss:[父bp − 1ECh]` | 模板遠指標 |
| `ss:[父bp − 1CAh]` | 同 | 另一個角色遠指標 |

```pascal
{ ① 七組屬性各自抬到下限，兩個副本一起寫 }
if 角色^[10h] < 模板^[14h] then begin
    角色^[10h] := 模板^[14h];   角色^[11h] := 模板^[14h];
end;
if 角色^[1Ch] < 模板^[15h] then begin
    角色^[1Ch] := 模板^[15h];   角色^[1Dh] := 模板^[15h];
end;
for i := 1 to 5 do
    if 角色^[10h ＋ i × 2] < 模板^[15h ＋ i] then begin
        角色^[10h ＋ i × 2] := 模板^[15h ＋ i];
        角色^[11h ＋ i × 2] := 模板^[15h ＋ i];
    end;

{ ② 經驗值 }
if 有號長整數(角色^[127h]) < 模板^[2Eh] then 角色^[127h] := 模板^[2Eh];

{ ③ 錢：不夠就整批換掉 }
if <loc_1024h+3>(角色) < 模板^[28h] then begin        { 有號長整數 }
    for j := 0 to 4 do <loc_1160h+1>(角色, 角色^[0FBh ＋ j × 2], j);   { 全部扣光 }
    <loc_114Dh>(lo(模板^[28h] div 5));
end;

{ ④ 其餘欄位 }
if 角色^[76h] < 模板^[1Eh] then 角色^[76h] := 模板^[1Eh];   { word }

角色^[109h] := (模板^[0B7h] > 0);
角色^[10Eh] := (模板^[0B8h] > 0);
角色^[10Bh] := (模板^[0B9h] > 0);
角色^[10Fh] := (模板^[0BAh] > 0);
角色^[0E5h] := 1;                                     { 生命骰數 }
if 模板^[26h] <> 0 then 角色^[192h] := 1;

遠指標(DS:4F9Dh)^[550h] := 0FFh;                      { word }
DS:7586h := 0;   DS:4FC8h := 1;
repeat <loc_F1Eh>() until DS:7586h <> 0;              { 等某件事完成 }
DS:4FC8h := 0;

DS:6506h := 另一個角色;                               { 換「目前角色」 }
角色^[78h]  := 模板^[21h];
角色^[12Ch] := 角色^[78h] − <loc_F23h>(角色);
角色^[1A4h] := 模板^[20h];
```

## 屬性是「兩個副本」，不是一格

第 ① 段每次都把**相鄰的兩格寫成同一個值**（`+10h` 與 `+11h`、
`+1Ch` 與 `+1Dh`、`+10h＋i×2` 與 `+11h＋i×2`）。

spec 857 由遊俠的三個 prime requisite 定出 `+11h` 力量、`+13h` 智力、
`+15h` 睿智、`+17h` 敏捷、`+19h` 體質，stride 2。本支顯示**每個屬性其實佔
兩個 byte，兩格存同一個值**——`+10h＋j×2` 與 `+11h＋j×2`。
spec 857 讀到的是每一對的後半格。

模板側的對應：

| 角色 | 模板 |
|---|---|
| `+10h`／`+11h`（力量） | `+14h` |
| `+12h`／`+13h`（智力） | `+16h` |
| `+14h`／`+15h`（睿智） | `+17h` |
| `+16h`／`+17h`（敏捷） | `+18h` |
| `+18h`／`+19h`（體質） | `+19h` |
| `+1Ah`／`+1Bh`（魅力） | `+1Ah` |
| **`+1Ch`／`+1Dh`** | **`+15h`** |

模板那七個 byte 是連續的 `+14h`..`+1Ah`，而 `+15h` 插在力量與智力之間，
對應到角色記錄上離其他屬性最遠的 `+1Ch`。
**形狀上是 AD&D 的 18/xx 百分位力量**（緊跟在力量後面、獨立於六屬性序列）。

## 錢不夠就「先扣光再重發」

```
現值 := <loc_1024h+3>(角色);            { 把七格錢包折算成一個長整數 }
if 現值 < 模板^[28h] then begin
    for j := 0 to 4 do 扣款(角色, 目前持有量, j);    { 五格全歸零 }
    <loc_114Dh>(模板^[28h] div 5);
end;
```

`<loc_1160h+1>` 就是 spec 920／922 的扣款函式，這裡把**第 0..4 格全部扣到 0**
（不含第 5、6 格）。然後把「下限 ÷ 5」發回去。

⚠ 這是**先破壞再補**：中途若出錯，錢就沒了。而且 `div 5` 之後只推低位字
（`push ax`），**下限超過 327,675 時高位會被丟掉**。

## 四個職業槽被寫成布林值

`+109h ＋ c` 是既有規格的八個職業槽等級。本支把槽 **0、5、2、6** 寫成
`模板^[0B7h..0BAh] > 0` 的布林結果——也就是**只設「有沒有這個職業」，等級一律 1**。

## PC-98 只差一層間接

五個差異區塊全是同一件事：PC-98 在取角色遠指標時多一次
`les di, es:[di]`，也就是 `ss:[父bp ＋ 0Ah]` 存的是**指向角色遠指標的遠指標**；
模板的父層位移從 `−1C4h` 變成 `−1ECh`。**沒有任何邏輯差異。**

## 明確不宣稱

- 沒有宣稱 `+1Ch`／`+1Dh` 就是百分位力量（只有位置與模板排列的旁證）。
- 沒有宣稱模板記錄的整體版面（只用到 `+14h`..`+1Ah`、`+1Eh`、`+20h`、`+21h`、
  `+26h`、`+28h`、`+2Eh`、`+0B7h`..`+0BAh`）。
- 沒有宣稱 `<loc_1024h+3>`／`<loc_114Dh>`／`<loc_F1Eh>`／`<loc_F23h>` 的內部行為。
- 沒有宣稱 `DS:7586h`／`DS:4FC8h` 那個等待迴圈在等什麼。
- 沒有宣稱 `+76h`、`+78h`、`+12Ch`、`+192h`、`+1A4h`、`遠指標(DS:4F9Dh)^[550h]` 的語意。
