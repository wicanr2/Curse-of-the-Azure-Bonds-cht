# 1037 — 角色圖示編輯畫面：`'xxxx'` 是就地替換槽，不是沒改完的佔位字串

- 證據等級：`exact`（DOS 側 708 條、PC-98 側 687 條，兩邊各自逐條讀完）
- 作法見 spec 783

## `dos overlay-17:03EE3h` ↔ `pc98 overlay-17:045D0h`

兩側原本都是待解讀。這是**角色圖示（icon）編輯畫面**。

## ★★ 角色記錄裡的圖示欄位

| 位移 | 內容 | 範圍 |
|---|---|---|
| `+141h` | **頭／髮型索引** | `0`..`0Dh`（14 種），Next／Prev **環繞** |
| `+142h` | **武器索引** | `0`..`1Fh`（32 種），環繞 |
| `+143h` | 一個顏色（重畫前暫設 `0Ch` 再還原） | |
| `+144h` | **大小**：`1` ＝ Small、`2` ＝ Large | |
| `+145h`..`+14Ah` | **六個部位各一個 byte ＝ 兩個 4-bit 顏色** | 低 nibble 第一色、高 nibble 第二色，各 `0`..`0Fh` 環繞 |

★ 進畫面時把 `+145h` 起的 **6 bytes 整組備份**（`0A54:025Dh`，長度 6），
按 `E`／`#0` 離開時連同 `+141h`／`+142h`／`+144h` 一起還原
——**取消是真的取消**。

部位碼（`+144h ＋ 部位`，所以部位 1..6 剛好落在 `+145h`..`+14Ah`）：

| 鍵 | 部位 | 碼 |
|---|---|---|
| `B` | Body | 1 |
| `A` | Arm | 2 |
| `L` | Leg | 3 |
| **`H`／`F`** | **Hair／Face** | **4** |
| `S` | Shield | 5 |
| `W` | Weapon | 6 |

## 五個子選單狀態

選項行放在 **`DS:721h`，筆距 `29h`（41 bytes）**，`var_8` 就是筆號：

| `var_8` | 選項行 | 長度 |
|---|---|---|
| 1 | `'Parts 1st-color 2nd-color Size Exit'` | 35 |
| 2 | `'Head Weapon Exit'` | 16 |
| 3 | `'Weapon Body xxxx Shield Arm Leg Exit'` | 36 |
| 4 | `' Keep Exit'` | 10 |
| 5 | `'Next Prev Keep Exit'` | 19 |

★ 主選單（1）：`P` → 2、`1` → 3（第一色）、`2` → 3（第二色）、`S` → 4、`E` → 離開。
★ 狀態 4 另外把 `'Small'`／`'Large'` 接在選項行後面顯示目前大小。
★ 狀態 5 是 `Next`／`Prev` 調整（頭、武器、或某個部位的某一色）。

## ★★★ `'xxxx'` 是執行期就地替換的 4 字元槽

```asm
40F9  mov  di, offset loc_79C          ; ＝ DS:79Ch ＝ 選項行第 3 筆
      mov  ax, 0Dh ; mov ax, 4
4106  call far ptr 0A54h:7D0h          ; Delete(選項行3, 13, 4)
410B  mov  di, offset unk_3EA7         ; 'Hair'
4110  mov  di, offset loc_79C
      mov  ax, 28h ; mov ax, 0Dh
411D  call far ptr 0A54h:77Ch          ; Insert('Hair', 選項行3, 13)
```

`DS:721h ＋ 2 × 29h = DS:79Ch` ⇒ 那真的是第 3 筆。
`'Weapon Body xxxx Shield Arm Leg Exit'` 的第 13 個字元起正好是 `xxxx`。

> ★★★ **`'xxxx'` 不是沒改完的佔位字串，是一個「寬度固定 4」的槽**：
> 選 `1st-color` 時被換成 `'Hair'`、選 `2nd-color` 時換成 `'Face'`。
> ⚠ **中文化必須在同一個位元組位置保留同寬度的槽**，
> 否則 `Delete(…, 13, 4)` ／ `Insert(…, 13)` 會切在字的中間——
> Big5 是雙位元組，切一半就是亂碼。
> 要換寬度就得同時改選項行與這兩個位置參數。
>
> ★ 這也解釋了為什麼熱鍵是 `H` 與 `F` 兩個：**同一個槽兩種身分**。

## ⚠ CGA 模式下顏色編輯是關掉的

```pascal
if byte_4FE6 = 0 then begin
    印訊息('Sorry, not in CGA');       { CS:3E95h，17 字元 }
end else begin
    …進入顏色編輯…
end;
```

★ `1st-color` 與 `2nd-color` 兩個入口各有一份同樣的判斷。
⚠ **這是 DOS 版才有的分支**（PC-98 沒有 CGA）。

## 顏色的加減

```pascal
第一色 := 部位byte and 0Fh;
第二色 := (部位byte and 0F0h) shr 4;
if 鍵 = 'N' then 目標 := (目標 ＋ 1) mod 16
else if 鍵 = 'P' then 目標 := (目標 − 1) and 0Fh;
部位byte := 第一色 ＋ (第二色 shl 4);
```

★ 加是 `mod 16`、減是 `and 0Fh`——**兩邊都會環繞**，寫法不同但結果一致。

## ★★★ PC-98 改成逐格寫兩張表，沒有就地替換

PC-98 完全不用 `DS:721h` 那張選項行表，也**沒有任何 `Delete`／`Insert` 呼叫**
（`0A65h:…` 的呼叫統計裡只有 `Move`、字串指派、`@Set@MemberOf`）。
它照 spec 1030／1032 的作法，把每一格的文字與熱鍵分別寫進
`DS:0A338h ＋ i × 7` 與 `DS:0A334h ＋ i`，例如：

| 文字 | 熱鍵位址 | 熱鍵 |
|---|---|---|
| 「  小  」（6） | `DS:0A336h` | `S` |
| 「  大  」（6） | `DS:0A336h` | `L` |

⇒ **PC-98 的圖示編輯選單天生沒有 `'xxxx'` 這個問題**，中文化跟 PC-98 走比較安全。

## 中文化

| DOS | PC-98 | 備註 |
|---|---|---|
| `'old'`（3） | 「古いアイコン」（12） | |
| `'new'`（3） | 「 新しいアイコン」（15） | |
| `'ready   action'`（14） | 「 準備状態　　　　　行動状態」（27） | ⚠ 兩欄之間靠空白對齊 |
| `'Small'`／`'Large'`（5／5） | 「  小  」／「  大  」（6／6） | |
| `'Sorry, not in CGA'`（17） | **沒有** | DOS 專屬 |
| `'Hair'`／`'Face'`（4／4） | — | ★ 就地替換槽，見上 |
| — | 「このアイコンでいいですか？」（26） | PC-98 多的確認句 |

⚠ **`'ready   action'` 中間是三個空白排版**，中文化要重排欄位而不是直接翻。
⚠ 選項行表 `DS:721h` 五筆各上限 40 bytes，中文全形字**一筆最多 20 個字**。
