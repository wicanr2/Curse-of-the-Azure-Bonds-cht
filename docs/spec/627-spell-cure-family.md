# 第六百二十七輪：治療類法術四支，以及骰子參數的順序

狀態：`READY`。等級：`exact`。日期：2026-08-14
位置：PC-98 `overlay-22:434Dh`、`5B2Bh`、`43DAh`、`46CAh`。

## 骰子的參數順序是 `(顆數, 面數)`

`013Eh:004Dh` 是擲骰。順序由兩個呼叫端交叉確定：

| 呼叫端 | 推入順序 | 只有這個解讀說得通 |
|---|---|---|
| `overlay-07:1F66h`（`ROBSTUFF`，[spec 621](621-ecl2-robstuff.md)）| `1`、`64h` | `1d100` |
| `overlay-22:435Bh` | `2`、`4` | `2d4` |

若反過來當成 `(面數, 顆數)`，`ROBSTUFF` 那次就變成「100 面骰擲 1 次」寫成
`(1, 100)`——順序不對；而且偷竊判定用 `roll <= 機率`，機率上限是百分比，
必須是 `1d100`。

Turbo Pascal 由左而右推參數，所以**先推的是第一個參數**。

## `434Dh` 與 `5B2Bh`：同一支法術的兩份複本

```text
if <far 013Eh:008Eh>(t, ROLLDICE(2, 4) + 2, 0) <> 0 then     ← t 是 DS:0A521h
    <far 014Ah:00A2h>(t, 1, 'は回復した。')
```

**參數是交錯推入的**：`t` 先推（它是外層 `013Eh:008Eh` 的第一個參數），接著才推
`2`、`4` 給內層的 `ROLLDICE`，內層回來後再推 `+2` 的結果與 `0`。判讀時不能把
「呼叫前最靠近的那幾個 push」全算給那一個呼叫——巢狀呼叫的參數會夾在中間。

兩支**逐指令相同**，只有字串常數的位址不同（`4340h` 與 `5B1Eh`），而**兩個位址
的內容都是「は回復した。」**。也就是同一段程式碼被編譯了兩次，字串也存了兩份。

`013Eh:008Eh` 的回傳值為 0 時**不印訊息**——治療量算出來了但沒套用（或沒有目標）
的情況，玩家看不到任何回饋。

## `43DAh` 與 `46CAh`：五參數版本

```text
n := <far 013Eh:0052h>(DS:0A031h, 0, 0, C, S) + B
推入 n 與 8，把常數字串複製進區域變數，再呼叫 <sub_F62>
```

`0A65h:62Fh` 是 Turbo Pascal 的字串串接起始（`62Fh` 起始、`6BCh` 追加、
`649h` 收尾，在 [spec 623](623-killthedude-damage-message.md) 的 `KILLTHEDUDE` 裡
三個都用到）。它把常數複製進區域變數，**不是 `sub_F62` 的參數本身**——
`sub_F62` 的完整參數表本輪沒有確定，只確定 `n` 與 `8` 依序推入。

| 函式 | `C` | `S` | `B` | 合起來 |
|---|---|---|---|---|
| `43DAh` | 2 | 4 | 2 | `2d4+2` |
| `4416h` | 2 | 8 | 1 | `2d8+1` |
| `46CAh` | 3 | 8 | 3 | `3d8+3` |

三支除了這三個常數以外逐指令相同。其中兩個級距與 AD&D 完全吻合——
**Cure Serious Wounds `2d8+1`**、**Cure Critical Wounds `3d8+3`**。兩個獨立命中
同一套規則書，所以「這一族是 cure 系列」是 `strong inference`；但個別函式對到哪
一個法術名稱仍未確定（`2d4+2` 不對應標準 cure 級距）。

兩支準備的字串**長度都是 0**（`43D9h`、`46C9h`）——常數本身就是空字串。

## 明確不宣稱

- `013Eh:008Eh` 與 `013Eh:0052h` 各自做什麼（前者回傳 0／非 0 決定要不要印訊息，
  後者吃五個參數並回傳一個 byte，僅此而已）。
- `DS:0A521h:0A523h` 與 `DS:0A031h` 指向什麼。
- 這四支各自對應哪一個法術名稱。
