## ⚠ 第 7 與第 8 項在兩平台是相反的

DOS 第 7 是 `Neutralize Poison`、第 8 是 `Raise Dead`；
PC-98 第 7 是「レイズ・デッド（死者の蘇生）」、第 8 是
「ニュートラライズ・ポイズン（毒の中和）」——**順序對調**。

價格跟著字串走（復活 5500、解毒 1000），而復活本來就該比解毒貴，
**所以字串與價格是自洽的**。問題在分派：本支的 `case` 是**依索引寫死的**
（索引 7 → `0892h`、索引 8 → `063Eh`），兩平台的 `case` 結構相同。

因此只有兩種可能，**本規格不判斷是哪一種**：

1. PC-98 連同 `0892h`／`063Eh` 兩支的內容也對調了（那就沒問題）。
2. PC-98 只換了字串，**選「復活」實際執行的是解毒**（那是在地化 bug）。

要判定得把兩平台的 `0892h` 與 `063Eh` 各讀一遍。**中文化前必須先確認**，
否則照 PC-98 的順序排會踩到同一個坑。

## PC-98 把價格排版進同一格

PC-98 每一筆用全形空白把價格推到右邊對齊（`string[80]`，`51h`）；
DOS 每筆只有 `29h`（`string[40]`）而且**不含價格**——
DOS 的價格顯示在別處。

這是 spec 897 那個「DOS 40 欄／PC-98 80 欄」的直接應用：
PC-98 一行放得下「名稱（說明）　　價格」，DOS 放不下。

**中文化跟 PC-98**：一行 40 個中文字，名稱＋說明＋價格排得下。

## PC-98 多兩格熱鍵

`DS:0A33Fh` ← 標籤、`DS:0A335h` := `48h`（`'H'`）；
`DS:0A37Eh` ← 標籤、`DS:0A33Eh` := `45h`（`'E'`）。
與 spec 899 定出的基底一致（索引 0 與索引 9）。
