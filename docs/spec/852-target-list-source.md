# 852 — `DS:758Eh` 目標清單是怎麼來的

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側助憶碼序列完全相同，12 條差異全是位址）
- 作法見 spec 783

## `overlay-24:02628h` ↔ `overlay-24:0285Bh`（兩平台各 110 條）

`retf 6` ＝ 3 個 word。依宣告順序：`(角色, 半徑)`。回傳筆數。

```pascal
<far 18ADh+1>(<far 192Bh>(角色), <far 192Eh+2>(角色), 半徑, 0FFh,
              <far 1933h+2>(角色), 遠指標(DS:6E92h));
n := DS:6E96h;

留 := 0;
if n > 0 then begin                                     { 無號 }
    要的陣營 := <本模組 25B0h>(角色);
    for i := 1 to n do begin
        q := 遠指標(DS:6D35h + byte[6E94h + i * 3] * 4);
        if q^[197h] = 要的陣營 then begin
            inc(留);
            Move(byte[6E94h + i * 3], byte[6E94h + 留 * 3], 3);   { 往前壓實 }
        end;
    end;
    n := 留;
    DS:6E96h := 留;
end;

for i := 1 to n do
    byte[758Eh + i] := byte[6E94h + i * 3];             { 只抄索引 }
結果 := n;
```

## 兩塊緩衝的關係就此接上

spec 815／833／838 都在走 `DS:758Eh + k` 這張**目標清單**，但一直不知道它從哪裡填。
本支給出答案：

```
far 18ADh+1  →  DS:6E92h 那塊（每筆 3 bytes）
       ↓ 依陣營 +197h 過濾並往前壓實
DS:758Eh + k  ←  只保留每筆的第一個 byte（戰鬥員索引）
```

`DS:6E92h` 那塊的版面（與 spec 846 讀到的一致）：

| 位移 | 內容 |
|---|---|
| `DS:6E92h`..`6E95h` | 遠指標（傳給 `18ADh+1`） |
| `DS:6E96h` | 筆數 |
| `DS:6E97h` 起 | 每筆 3 bytes，`+0` 是戰鬥員索引 |

**`DS:758Eh` 只留索引，另外兩個 byte 被丟掉。**
那兩格由 spec 860（`far 18ADh+1` ＝ `overlay-31:008E3h`）填：
`+1` ＝ 最短距離（半格單位）、`+2` ＝ 方向碼 0..7。所以本支的排序
（`overlay-31:0035h`，依 `+1` 再依 `+2`）讀作**先近後遠、同距離依方向順時針**。

## 壓實用的是 `Move`，不是逐格搬

`Move(來源[i], 目的[留], 3)` 在 `i = 留` 時是自我覆寫，Turbo Pascal 的 `Move`
對重疊區間有處理，所以安全。

⚠ 過濾條件是 `q^[197h] = 25B0h(角色)`——**留下來的是「陣營等於某個值」的戰鬥員**，
那個值由 `25B0h` 決定，可能是自己的陣營也可能是對方。本規格不宣稱是哪一種。

## PC-98：全部是位址差

`DS:9F2Ch/9F2Eh/9F30h↔6E92h/6E94h/6E96h`、戰鬥員陣列 `[di−6231h]↔[di+6D35h]`、
角色 `+198h↔+197h`。**沒有邏輯差異。**

## 明確不宣稱

- 沒有宣稱 `far 18ADh+1` 那六個參數的意義（`0FFh` 落在半徑或遮罩的位置）。
- 沒有宣稱 `本模組 25B0h(角色)` 回傳哪一邊的陣營。
- 沒有宣稱每筆 3 bytes 裡另外兩格裝什麼。
- 沒有宣稱 `far 192Bh`／`192Eh+2`／`1933h+2` 三支各取什麼
  （前兩支形狀上是 x、y，第三支未知）。
