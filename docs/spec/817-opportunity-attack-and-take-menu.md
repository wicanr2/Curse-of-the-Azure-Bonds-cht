# 817 — 機會攻擊（`+18Dh^[7]` 用完就清）、Take 清單；PC-98 把熱鍵與標籤分開存

- 證據等級：`exact`（DOS 側逐條讀完；PC-98 側的差異已逐條列出）
- 作法見 spec 783

## `overlay-13:0666h`（entry#5，DOS 87 條／PC-98 98 條）— 機會攻擊

`retf 4` ＝ 一個角色遠指標（**被打的那個**）。

```pascal
n := <far 1590h>(角色, 1);
for k := 1 to n do begin                              { 無號 }
    if 角色^[196h] = 0 then continue;                 { 每一輪都重查 }
    i := byte[758Eh + k];
    q := 遠指標(DS:6D35h + i * 4);
    if q^[18Dh]^[7] = 0 then continue;                { 沒有保留的機會攻擊 }
    if <far 150Ah+4>(q) then continue;
    <far 1921h>(<far 192Ah+1>(角色), <far 192Dh+3>(角色), 2, 8);
    q^[18Dh]^[7] := 0;                                { 用掉了 }
    <本模組 194Ah>(角色, q);
    <本模組 19D8h>(q, 角色, 0, longint 0, @暫存);
end;
```

### 戰鬥狀態 `+07h` ＝ 保留中的機會攻擊

spec 804 讀到回合開始時 `+18Dh^[7]` 被清成 0，當時不知道它是什麼。這裡看到：
**`+7` ≠ 0 的戰鬥員在別人做動作時可以打一下，打完立刻歸零**——每回合只有一次。

### 攻擊的方向是「q 打 角色」

`19D8h` 的參數順序與 spec 805 的 `overlay-13:4703h` 對照：那裡是
`19D8h(角色, 目標, 1, 0, @暫存)`，本支是 `19D8h(q, 角色, 0, 0, @暫存)`。
第一個參數是**攻擊者**，所以這一支裡 `q` 是攻擊者、傳進來的 `角色` 是被打的。

### 目標狀態每一輪重查

`角色^[196h] = 0` 的判斷在迴圈**內**，而且與 `k` 無關——因為前面幾下可能已經把
它打成那個狀態，後面的就不再打。remake 不能把它提到迴圈外。

### PC-98 多兩道守衛

在 `150Ah+4` 之後、動手之前，PC-98 多問 `<far 14DBh+3>(q)` 與
`<far 158Bh+2>(q)`，任一成立就跳過。DOS 沒有這兩道。

## `overlay-05:0CE6h`（entry#6，DOS 90 條／PC-98 100 條）— Take 清單

| | DOS | PC-98 |
|---|---|---|
| 提示 | `'Items: '`（7，**結尾一個空白**） | `'アイテム'`（8 bytes） |
| 動作 | `'Take'`（4） | `'取る'`（4 bytes） |
| — | — | `' 取る '`（6 bytes，**前後各一個空白**，另外存到 `DS:0A362h`） |

```pascal
旗標 := 1;
<far 01A0h:0000h>();                                  { DOS 才有 }
p := DS:6F8Ch;
while p <> NIL do begin
    <far 14F3h+2>(0, 0, 0, 0, p, longint 0);
    p := p^[2Ah];
end;
輸出^ := <far 16A8h+1>('Items: ', 'Take', 0Dh, 0Ah, 0Fh, 1, 1, 26h, 16h,
                       DS:6F8Ch, 1, @旗標, 參數0, 參數4);
參數8^ := 參數4^;                                     { 遠指標 }
```

`retf 10h` ＝ 4 個遠指標，依宣告順序 `(參數C, 參數8, 參數4, 參數0)`；
結果寫進 `參數C^`（byte）與 `參數8^`（遠指標）。

`DS:6F8Ch` 是一條物品鏈（next 是 `+2Ah`），先整條走一遍餵給 `14F3h+2`，再交給
選單程序顯示。

### PC-98 把熱鍵與標籤**分開存**

PC-98 版在同一個位置多做兩件 DOS 沒有的事：

```
mov byte ptr ds:0A33Ah, 54h        { 'T' — 熱鍵，ASCII }
Move(' 取る ', DS:0A362h, 6)       { 標籤，日文 }
```

先前幾份 spec（794、816）都觀察到「PC-98 標籤翻成日文、熱鍵維持 ASCII」，但都是
**從比較字元沒改推出來的**。這裡是**直接證據**：熱鍵 `'T'` 與標籤 `' 取る '` 被
寫進兩個不同的全域，彼此無關。

中文化照這個模型走即可：**熱鍵表與標籤表分開維護**，標籤長度變動不影響按鍵。
注意 PC-98 的標籤前後各留一個空白（`' 取る '`），是為了置中排版。

## 明確不宣稱

- 沒有宣稱 `far 1590h` 第二個參數 `1` 與 spec 815 的 `0FFh` 差在哪。
- 沒有宣稱 `far 150Ah+4` / `14DBh+3` / `158Bh+2` 各判什麼。
- 沒有宣稱 `far 1921h` 的四個參數（`(r1, r2, 2, 8)`，形狀上像 2d8）。
- 沒有宣稱 `far 01A0h:0000h` 做什麼，也沒有宣稱 PC-98 為什麼不呼叫它。
- 沒有宣稱 `far 16A8h+1` 那 14 個參數各自的意義。
- 沒有宣稱 `DS:6F8Ch` 那條鏈裝的是地上的東西還是背包。
