# 762 — DOS 的 EGA 字元繪製、逐字打字效果，與移動速率欄位的閉環

- 證據等級：`exact`（以補洞後的匯出逐條讀完，見 spec 761）

## `START.EXE:161E6h` — EGA 8 × 8 字元繪製

近呼叫 `retn 0Ah`（5 個 word，第一個宣告的參數在 `[bp+0Ch]`）：

```
ES := 0A000h
DI := 列 * 140h + 位元組欄            { 140h = 320 = 8 列 × 40 }
out 3CEh, 0A05h                       { Graphics Mode 暫存器 := 0Ah → Write Mode 2 }
out 3CEh, 0003h                       { Data Rotate := 0 }
out 3CEh, 0007h                       { Color Don't Care := 0 }
for i := 0 to 7 do begin
    列樣式 := DS:[6598h + i]
    out 3CEh, (列樣式 shl 8) or 8      { Bit Mask := 字模那一列 }
    ES:[DI] := ES:[DI] and 前景色       { Write Mode 2：AL 就是顏色 }
    out 3CEh, ((not 列樣式) shl 8) or 8 { Bit Mask := 反相 }
    ES:[DI] := ES:[DI] and 背景色
    DI := DI + 28h                      { 40 bytes 一列 }
end
out 3CEh, 0005h / 0FF08h / 0003h / 0F07h   { 還原 }
```

一次畫完的資訊量很大：

- 畫面是 **每列 40 bytes、每 byte 8 個像素 ＝ 320 像素寬**的 EGA 平面模式。
- 字元格是 **8 × 8**，垂直位移用 `140h`（320）＝ 8 × 40，所以第一個位置參數是
  **文字列**，第二個是**位元組欄**。
- 字模是 8 個 byte，取自固定位址 `DS:6598h`——**不是由參數傳進來的**，呼叫端
  要先把字模搬到那裡。
- 前景與背景各畫一次（先用字模當遮罩畫前景，再用反相遮罩畫背景），所以這支
  畫的是**不透明的字元格**。
- 第一個 word 參數（`[bp+04h]`）整支沒讀。

**對中文化的意義**：這條路徑一次只處理 8 × 8 一格、字模固定 8 bytes。全形
字要嘛拆成左右兩格各畫一次，要嘛整條路徑換掉。`DS:6598h` 這個中繼緩衝區是
唯一的字模入口，是接手的地方。

## `START.EXE:157F7h` — 逐字輸出＋可調速

`retf 2`，參數是 SS 相對的記錄位址：

```pascal
while ss:[p−103h] <= ss:[p−104h] do begin        { 游標 <= 長度，無號 }
    <繪字>(unk_22760, unk_22761, ss:[p+0Eh], ss:[p+0Ch], 1,
           ss:[p − 100h + ss:[p−103h]], 1);
    if unk_21189 <> 0 then Delay(unk_21169 * 3);
    inc(ss:[p−103h]);
    inc(unk_22760);
end;
```

同一個記錄配置在 spec 754 的 `START.EXE:1586Eh`（跳過開頭空白）也出現過：
`−103h` 是游標、`−100h` 起是內容。這裡多知道一個：**`−104h` 是長度**。

`unk_22760` 是目前欄位、每輸出一個字就 ＋1。`unk_21189` 是「慢速文字」開關，
為真時每個字之間 `Delay(unk_21169 * 3)` 毫秒。

**對中文化的意義**：文字是**一個 byte 一個 byte**送出去的，而且欄位計數
每次 ＋1。全形字在這裡會被拆成兩個 byte 分兩次畫，中間還可能插一段延遲。

## 移動速率欄位的閉環

三支合起來把 `+1A5h`（PC-98 `+1A6h`）定住：

**設定端** PC-98 `overlay-24:021Dh`（`retf 8`）：

```pascal
if byte[(a^[56h] shl 4) − 727Ch] = 2 then begin
    w := a^[5Fh];                          { word，無號 }
    if w <= 96h      then b^[1A6h] := b^[0E4h]     { <= 150：用基礎值 }
    else if w <= 18Fh then b^[1A6h] := 9           { 151..399 }
    else                  b^[1A6h] := 6;           { >= 400 }
    if a^[5Ah] <> 0 then
        if b^[1A6h] <= 9 then b^[1A6h] := b^[1A6h] + 3;
end;
```

**轉換端** `overlay-13:0124h`（spec 758）：讀 `+1A5h`，陣營為 0 時加一個修正，
夾到 1..96h，然後**乘 2** 存進 `DS:6F96h`。

**還原端** `overlay-13:2EACh`（DOS，`retf 4`）：

```pascal
最大 := 0;
p := DS:650Ah;                                  { 隊伍鏈頭 }
while p <> NIL do begin
    if (<呼叫>(參數) = p^[197h]) and (p^[196h] <> 0) then begin
        v := 本模組 0124h(p) div 2;             { 把乘 2 除回來 }
        if v > 最大 then 最大 := v;             { 無號比較 }
    end;
    p := p^[189h];
end;
結果 := 最大;
```

一乘一除中間差的那個 2，正是既有結論裡「距離的單位是半格」的那個 2
（`175Bh` 的範圍參數先乘 2、對角算 1.5 格）。所以 `+1A5h` 是**以格為單位的
移動速率**，傳到距離系統時換成半格。

`overlay-13:2EACh` 回的是「指定陣營中速率最快的那個成員」。

## `overlay-19:3258h`（DOS）— 拿不拿得下

`retf 8`，兩個遠指標參數：

```pascal
<呼叫>(角色);
超過 := false;
if 角色^[14Ch] > 0Fh then 超過 := true;          { 物品數上限 16 }
w := 物品^[37h];                                  { word }
if 物品^[39h] > 0 then w := w * 物品^[39h];       { 數量相乘 }
上限 := <呼叫>(角色) + 5DCh;                      { ＋1500 }
if 角色^[187h] + w > 上限 then 超過 := true;      { 無號 }
結果 := 超過;
```

`+14Ch` 是物品數（既有結論：上限 16），`+187h` 是累計負重（`overlay-21:0073h`
用的是同一個欄位）。物品節點的 `+37h` 是單位重量、`+39h` 是數量。`5DCh` ＝
1500 是加在上限上的固定寬容量。

## 明確不宣稱

- 沒有宣稱 EGA 那支的第一個 word 參數為什麼存在（整支沒讀）。
- 沒有宣稱 `96h`（150）與 `18Fh`（399）這兩個門檻的單位，也沒有宣稱
  `9`／`6`／`+3` 對應哪條規則。
- 沒有宣稱 `a^[56h]` 索引的那張 16-bytes 一筆的表是什麼、值 `2` 代表什麼。
- 沒有宣稱 `unk_21169` 的單位就是毫秒——只知道乘 3 之後交給 `Delay`。
