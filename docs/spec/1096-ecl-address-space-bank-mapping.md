# 1096 — ECL 位址空間的五區映射：ECL 變數不是平坦記憶體，是三層間接到三塊 bank

- 狀態：`READY`
- 證據等級：`exact`（DOS `overlay-07:00735h` 分區函式 22 條、`overlay-07:00D70h`
  寫入端逐條讀完；分區結果與 `ecl-event-catalog` 的 1,355 條指令 operand 統計獨立對上）
- 作法見 spec 783；ECL 主迴圈見 spec 1095；畫面模式見 spec 892／1045
- 對應 P0-RE-1，並直接回答「ECL player-memory window 與 `DS:4F9Dh` bank 的映射」
  （spec 1095 列為不宣稱的那一項）

## 為什麼這件事是前提

ECL bytecode 是**資料**（6 個 DAX，不可改），它用**絕對位址**讀寫遊戲狀態。
把 1,355 條靜態可達指令的 operand 全部取出後，帶絕對位址的有 **956 次**，
其中扣掉程式碼跳躍目標與 external CALL，真正的變數存取是 **674 次**。

這些位址不是 remake 自己定的，是原作寫死在 ECL 資料裡的。
**remake 只要有一格對不上，ECL 就會讀到錯的值，而且不會有任何錯誤訊息**
——因為 ECL 的讀寫都成功了，只是指向了別的地方。

## ★★★ 一、分區函式

```pascal
function 分區(位址: word): byte;          { overlay-07:00735h，retf 2 }
begin
    結果 := 4;                            { 預設：不屬於任何 bank }
    if 4B00h ≤ 位址 ≤ 4EFFh then 結果 := 0;
    if 7C00h ≤ 位址 ≤ 7FFFh then 結果 := 1;
    if 7A00h ≤ 位址 ≤ 7BFFh then 結果 := 2;
    if 8000h ≤ 位址 ≤ 9DFFh then 結果 := 3;
end;
```

★ 四個範圍**依序覆寫**同一個變數，沒有 `else`；範圍互不重疊，所以結果與順序無關。

## ★★★ 二、五區的 bank、算式與寬度

由寫入端 `overlay-07:00D70h`（`寫ECL變數(位址, 值)`）逐條解出：

| 區 | 位址範圍 | 格數 | bank 指標 | **bank 內位移** | **寬度** |
|---|---|---|---|---|---|
| 0 | `4B00h`..`4EFFh` | 1,024 | `DS:4F99h`（bank0） | `(位址−4B00h)×2` | **word** |
| 1 | `7C00h`..`7FFFh` | 1,024 | `DS:4F9Dh`（bank1） | `(位址−7C00h)×2` | **word** |
| 2 | `7A00h`..`7BFFh` | 512 | `DS:4FA1h` | `(位址−7A00h)×2` | **word** |
| 3 | `8000h`..`9DFFh` | 7,680 | `DS:4FA5h`（**ECL 程式碼本身**） | `位址−8000h` | **byte** |
| 4 | 其他 | — | 無 bank | 兩張特例表 | 混合 |

### ★★★ 三個區的常數是 16-bit wrap 的補數，不是額外偏移

組語寫的是 `shl ax, 1` 之後直接加一個常數，沒有先減基底：

```asm
0DCE  mov  ax, [bp+arg_4]        ; 原始 ECL 位址
0DD1  shl  ax, 1
0DD3  les  di, ds:4F99h
0DD7  add  di, ax
0DD9  mov  es:[di+6A00h], dx     ; 區 0
```

這三個常數（`6A00h`／`800h`／`0C00h`）**正好是各區基底 ×2 的 16-bit 補數**：

| 區 | 基底 | 基底×2 | `10000h −` 基底×2 | 組語常數 |
|---|---|---|---|---|
| 0 | `4B00h` | `9600h` | **`6A00h`** | `6A00h` ✓ |
| 1 | `7C00h` | `F800h` | **`0800h`** | `0800h` ✓ |
| 2 | `7A00h` | `F400h` | **`0C00h`** | `0C00h` ✓ |

```
位址×2 + 補數  (mod 10000h)  ≡  (位址 − 基底)×2
```

> ★★★ 三個區同時成立，所以這是**編譯器省掉減法的產碼慣例**，不是段內偏移。
> ⇒ **bank 內位移就是 `(位址−基底)×2`，沒有額外的 `6A00h`。**
> ★ 這也解釋了 spec 1045／1085／1092／1095 一直使用的 `bank0^[1CCh]`、
> `bank0^[1E4h]` 記法為何正確：`4BE6h → (4BE6h−4B00h)×2 = 1CCh`、
> `4BF2h → 1E4h`，與那些規格在引擎側讀到的位移**一字不差**。

### ★★★ 區 3 是 byte，而且指向 ECL 程式碼

```asm
0E26  mov     dl, byte ptr [bp+arg_2]     ; ★ 只取低位元組
0E2C  les     di, ds:4FA5h                ; ★ 與主迴圈取指令用的是同一個指標
0E32  mov     es:[di-8000h], dl
```

> ★★★ **`DS:4FA5h` 正是 spec 1095 主迴圈取指令的那個指標**
> （`DS:75FFh := byte[DS:4FA5h^ + PC − 8000h]`）。
> ⇒ **區 3 的寫入是自我修改程式碼**：ECL 可以改寫自己的 bytecode。
> ★★★ 而且它是 **byte 寬度**，與區 0／1／2 的 word 不同。

### 區 4：沒有 bank 的特例表

以 `0BF68h` 為界分兩張表。低於 `0BF68h` 的部分：

| 位址 | 動作 |
|---|---|
| `0FBh`／`0FCh`／`0B1h` | **丟棄**（跳到出口，什麼都不寫） |
| `3DEh` | `DS:8B4Ch := 值` |
| `0B8h` | `DS:8B4Eh := 值` |
| `0B9h` | `DS:8B50h := 值` |
| 其他 | **靜默丟棄** |

高於等於 `0BF68h` 的部分先減去 `0BF68h`，再依 `0E3h`／`0E4h`／`0E5h`… 分派
（`0E3h` → `DS:720Fh` 並設 `DS:8B68h := 1`；`0E4h` → `DS:7210h` 同樣設旗標）。

⚠ 本規格不宣稱區 4 兩張特例表的完整內容，只確認上表列出的分支與
「未列出的位址一律靜默丟棄」這條行為。

## ★★★ 三、寫入區 0 時的三個副作用

區 0 不是單純的記憶體寫入，寫之前先做三件事（`idx := 位址 − 4B00h`）：

```pascal
if (idx = 0FDh) or (idx = 0FEh) then DS:8B6Ah := 1;

if idx = 0E6h then
    if bank0^[1CCh] <> 值 then begin
        DS:4FBBh := DS:4FBAh;                              { 存下舊畫面模式 }
        if 值 = 0 then DS:4FBAh := 3 else DS:4FBAh := 4;   { ★ 切換畫面模式 }
    end;

word[bank0 + (位址−4B00h)×2] := 值;
```

> ★★★ **`idx = 0E6h` ⇒ ECL 位址 `4BE6h`，它就是 `bank0^[1CCh]`。**
> 寫這一格會**連帶切換畫面模式**，而且用的是與 spec 1045（地城主迴圈）、
> spec 1095（`COMBAT` 收尾）**一字不差的同一條算式**：
> `值 = 0 → 模式 3`、`值 ≠ 0 → 模式 4`。
> ⇒ **`4BE6h` 是「室內／室外」旗標**，ECL 用它切換第一人稱視角的兩種模式。
> ★ 前後兩處獨立證據（引擎側 `bank0^[1CCh]`、ECL 側 `4BE6h`）在此接上。

★ `idx = 0FDh`／`0FEh`（ECL 位址 `4BFDh`／`4BFEh`）會設 `DS:8B6Ah := 1`。
統計裡這兩格各被 `SAVE` 寫 10 次與 11 次。
⚠ 本規格不宣稱 `DS:8B6Ah` 的用途。

★ 區 1 寫入後另外呼叫 `overlay-07:0B6Dh`（帶位址與值），本規格不宣稱其內容。

## 四、統計自洽性檢查

分區表對 `ecl-event-catalog` 的 1,355 條指令做獨立驗證：

| 區 | 統計到的存取次數 | 說明 |
|---|---|---|
| 0（`4Bxx`／`4Cxx`） | 239 | 變數 |
| 1（`7Cxx`..`7Fxx`） | 419 | 變數，最熱的 `7F79h` 佔 167 次 |
| 2（`7Bxx`） | 16 | 變數 |
| 3（`80xx`..`9Dxx`） | 271 | 全部是 `GOTO`／`GOSUB` 目標與自我修改 |
| 4（`2Exx`／`68xx`／`C0xx`） | 99 | 全部是 `CALL` 的外部常式位址 |

> ★ **區 0＋1＋2 ＝ 674 次，恰好等於扣掉 CALL operand 後的變數存取數。**
> 分區表沒有漏掉任何一個實際被用到的位址，也沒有把 CALL 目標誤算成變數。

★ 最熱的三格 `7F79h`／`7F7Ah`／`7F7Bh`（167／42／20 次）落在區 1 的連續位置，
被 `ADD`／`AND`／`COMPARE`／`DIVIDE`／`MULTIPLY`／`RANDOM`／`SUBTRACT` 等
算術指令反覆使用 ⇒ 形狀上是 ECL 的通用工作暫存器。
⚠ 本規格不宣稱這三格的正式語意。

## ★★★ 五、對 remake 的意義

目前 `internal/ecl/runtime.go:466` 用 `map[uint16]uint16` 當 ECL 記憶體。
把上面的三層間接壓成一層平坦 map 之後，有三個結構性後果：

1. **只要 ECL 自己讀自己寫，remake 永遠自洽。**
   ECL 寫 `7F79h`、讀 `7F79h`，map 存取成功，值也對。
   ⇒ **純 ECL 內部計算（工作暫存器、迴圈計數、條件旗標）不受影響**，
   這也是為什麼目前的測試會綠。

2. **但 bank 是引擎與 ECL 的共用記憶體，不是訊息傳遞。**
   `4BE6h` 這一格，引擎在 spec 1045／1095 讀 `bank0^[1CCh]`，ECL 用位址
   `4BE6h` 寫它。兩邊必須指向同一個欄位，否則 **ECL 切換室內／室外視角會失效，
   而且靜默**——map 寫入永遠成功，只是引擎讀不到。
   ⇒ 這類「ECL 寫、引擎讀」或「引擎寫、ECL 讀」的格子才是風險所在。

3. **區 3 的寬度是錯的。** map 一律存 `uint16`，但區 3（`8000h`..`9DFFh`）
   在原作是 **byte**。ECL 若對程式碼位址做自我修改，remake 會寫進一個 word。
   ⚠ 本規格不宣稱現行 ECL 資料裡有沒有實際用到自我修改
   （統計中區 3 的 271 次存取全部來自 `GOTO`／`GOSUB` 的跳躍目標，
   那是控制流不是寫入；**寫入端是否被用到需要另外查**）。

### 目前的量化缺口

把 674 次變數存取的 82 個不重複位址，對 `internal/`／`gamepack/` 非測試碼裡
出現過的 16-bit 常數取交集：

- **13 個位址已在 remake 出現過**（涵蓋 144 次存取）
- **69 個位址從未出現過**（涵蓋 541 次存取）

⚠ 「未出現」不等於「錯」——多數是第 1 點的自洽情形。但它等於
**沒有任何東西保證它們是對的**，而錯誤形式是靜默的。
⇒ 需要的不是逐一猜語意，而是**先把「ECL 與引擎共用的格子」找出來**：
把每個 ECL 位址換算成 `(位址−基底)×2`，再到 overlay 匯出裡搜尋引擎側
對 `DS:4F99h`／`DS:4F9Dh`／`DS:4FA1h` 該位移的存取點，與 ECL 側的
82 個位址做交集。交集之外的格子屬於第 1 點，
自洽即可；交集之內的每一格都必須逐格對上。
