# 1072 — PC-98 `savgam<n>.dat` 載入：16 個區塊、13,214 bytes，角色只存檔名不存內容

- 證據等級：`exact`（PC-98 側 458 條逐條讀完，無匯出破洞）
- 作法見 spec 783

## `pc98 overlay-16:049C6h`（`retf 4`）

原本待解讀。範圍 `49C6h`..`4E62h`。這是**整局存檔的讀取入口**。

參數（Turbo Pascal 由左至右推疊 ⇒ 先宣告的在高位移）：

```pascal
procedure 載入存檔(槽: char; 顯示提示: boolean);   { arg_2 = 槽, arg_0 = 顯示提示 }
```

★ 槽是**字母 `'A'`..`'J'`**，共十格（spec 1076 從 DOS 側的集合常數確認）。

## 檔名與開檔

```pascal
if not <near 0B4Fh>(0) then exit;                { 進門先過一道閘 }

檔名   := 字串(DS:8BF6h) ＋ 字串(DS:0A1Eh) ＋ 'savgam' ＋ Chr(槽) ＋ '.dat';
提示句 := 'ドライブ２にセーブ・ディスクを入れてください' ＋ 字串(DS:8BF6h);
狀態   := <far 0723:01EDh>(檔名, 提示句, 檔案變數, 1);

if 顯示提示 then 印訊息(0, 18h, 0Ah, 0, '読みこみ中です');
DS:7F2Fh := 1;
```

★ 字串是用 spec 1030 那套 **temp-string codegen** 串起來的
（`0A65:062Fh` 指派留下目的、`0A65:06BCh` 串接留下目的、
`0A65:0649h` 上限指派收掉），所以組完的檔名**直接留在堆疊上當開檔的第一個參數**。
⚠ 只數呼叫端的 push 會少算——這是 spec 1030／1031／1032 同一個坑的第四次確認。

## ★★★ 存檔檔案的區塊版面（`0A65:1983h` ＝ BlockRead，12 個呼叫點／16 次執行）

| 順序 | 長度 | 讀進哪裡 |
|---|---|---|
| 1 | 1 | `DS:8BF4h` — 資料片編號（spec 1040 的同一格） |
| 2 | `800h` ＝ **2048** | **bank 0**（遠指標 `DS:7F05h`^） |
| 3 | `800h` ＝ **2048** | **bank 1**（遠指標 `DS:7F09h`^） |
| 4 | `400h` ＝ **1024** | 遠指標 `DS:7F0Dh`^ |
| 5 | `1E41h` ＝ **7745** | 遠指標 `DS:7F12h`^ |
| 6 | 5 | `DS:0A2A9h` |
| 7 | 1 | `DS:7F28h` |
| 8 | 1 | `DS:7F27h` |
| 9..14 | 2 × 6 | `DS:0A2AAh ＋ i × 4` 與 `DS:0A2ACh ＋ i × 4`，**i ＝ 1..3** |
| 15 | 1 | 隊伍人數（區域變數 `var_1F9`） |
| 16 | `148h` ＝ **328** | 角色檔名表（區域緩衝 `var_148`） |

`Close`（`0A65:1919h`）緊接在第 16 塊之後。

> ★★★ **合計 13,214 bytes（`33AEh`）**，而且**版面完全固定**——
> 沒有任何長度欄位、沒有可變長區段。remake 要讀原版存檔就照這 16 塊順序搬。
>
> ★★★ **`800h`／`800h`／`400h`／`1E41h` 四塊就是遊戲狀態的全部**：
> bank 0 與 bank 1 各 2 KB、另外兩塊 1 KB 與 7745 bytes。
> ⇒ 既有結論裡散落的 `bank0^[…]`／`bank1^[…]` 欄位（spec 1029／1040／1041 等）
> 全部落在這兩塊 2 KB 裡，**上限就是 `800h`**。

## ★★★ 角色不存內容，只存檔名：`148h` ＝ 8 × 41

第 16 塊讀進來之後，迴圈用 `var_171 ＋ i × 29h` 取第 i 筆
（i ＝ 1 時正好落在緩衝起點）：

筆距 `29h` ＝ **41 bytes**，而 `148h` ÷ `29h` ＝ **8 筆整除**。
41 bytes ＝ **1 個長度位元組 ＋ 40 字元** ⇒ Turbo Pascal `string[40]`。

> ★★★ **存檔裡沒有角色資料，只有 8 個角色檔名**（隊伍上限 8）。
> 角色本體另外由 spec 1038 那支（`overlay-16:02A6Dh`）從各自的檔案讀進來。
> ⇒ remake 若把角色內嵌進存檔，就會失去原版「角色檔可跨存檔／跨隊伍搬」的行為。

每一筆的處理：

```pascal
for i := 1 to 人數 do begin
    var_1FD := '.';                                   { CS:49BAh，1 字元 }
    <far 0723:048Eh>(var_3FD, var_2FD, 檔名表[i], var_1FD);
    <far 0723:05BDh>();
    var_1F6 := <上一步的結果>;                        { 上限 28h ＝ 40 }

    路徑 := 字串(DS:8BF6h) ＋ 字串(DS:0A2Fh) ＋ var_1F6 ＋ '.sav';
    if <far 0723:0426h>(路徑) <> 0 then begin
        GetMem(角色, 1A7h);                           { 081F:0043，423 ＝ PC-98 角色記錄 }
        <overlay-16:02A6Dh>(var_1F6 ＋ '.sav', @角色, 1, 1);   { spec 1038 的角色讀取 }
        <near 3E8Bh>(角色);                           { 掛進隊伍 }
        if not <near 0B4Fh>(0) then exit;
    end;
end;
```

★ `1A7h` ＝ **423** ＝ PC-98 角色記錄長度（spec 1038），第三次確認。
★ 三個字串常數落在函式起點前的 12 bytes，剛好塞滿：
`CS:49BAh` ＝ `'.'`（1）、`CS:49BCh` ＝ `'.sav'`（4）、`CS:49C1h` ＝ `'CPIC'`（4）。

★★★ **存檔裡的隊伍成員就是存成 `.sav`，內容是現行長度的角色記錄。**
spec 1076 在 DOS 對側看到完全一樣的組法（`GetMem(1A6h)` ＋ `'.sav'`），
兩平台互相印證。⇒ **副檔名不是格式判斷依據，`DS:7584h` 才是**；
spec 1043 那張「副檔名 → 記錄長度」的表只適用於匯入舊角色的掃描路徑。

## 讀完之後的四段收尾

```pascal
{ 一、從 bank 0 拆出三個全域 }
DS:7F2Bh := bank0^[1FEh] div 2;      { ★ 同一個 word 拆成商 }
DS:7F2Ch := bank0^[1FEh] and  1;     { ★ 與餘數 }
DS:7F16h := bank0^[1F8h];
bank1^[67Ch] := 0;                   { spec 1040 的 ECL 位址 7F3Eh 讀的就是這格 }

{ 二、走一次隊伍鏈做後處理 }
節點 := DS:9598h;
while 節點 <> NIL do begin <near 1261h>(節點); 節點 := 節點^[18Ah] end;

{ 三、再走一次載入每個角色的圖示 }
DS:9594h := DS:9598h;
while DS:9594h <> NIL do begin
    if 角色^[0F7h] < 80h then <near 1061h>(1)
    else <overlay-33 entry#5>('CPIC', 角色^[126h], 角色^[143h]);   { 圖組槽載入 }
    DS:9594h := 角色^[18Ah];
end;
DS:9594h := DS:9598h;                { 目前角色回到隊首 }

{ 四、依場景重載美術 }
DS:8BF4h := bank1^[624h];            { ★ 資料片編號再被覆寫一次 }
if bank0^[1CCh] <> 0 then begin      { 3D 場景 }
    if DS:7F27h = 0 then exit;
    if DS:0A2AEh > 0 then <overlay-30 entry#9>(bank0^[18Ah]);      { Load3DMap }
    for i := 1 to 3 do
        if word[DS:0A2AAh ＋ i × 4] > 0 then
            <overlay-30 entry#8>(byte[DS:0A2AAh ＋ i × 4], byte[DS:0A2ACh ＋ i × 4]);
end else
    <overlay-29 entry#9>('y');       { 載入 bigpic }
```

> ★★★ **第 9..14 塊（`DS:0A2AEh` 起的 3 × 2 word）就是三組牆面素材的參數**：
> 存檔存下來，載入後原封不動餵回 `overlay-30 entry#8`（載 `WALLDEF`）。
> ⇒ 存檔要能還原 3D 迷宮外觀，靠的就是這 12 bytes。
>
> ★★ `bank0^[1CCh]` 是**場景型態旗標**：非零走 3D 地圖 ＋ 牆面，零則載 bigpic `'y'`。
> spec 1041 在遭遇選單裡用同一格當「是否顯示 `ADVANCE`」的條件之一，**互相印證**。
>
> ★ **`DS:8BF4h` 被寫兩次**：第 1 塊直接讀進來，收尾又從 `bank1^[624h]` 覆寫。
> ⇒ 真正權威的資料片編號在 bank 1 裡，檔頭那 1 byte 是冗餘的。
> remake 兩邊都要寫，否則舊存檔對不上。

## 明確不宣稱

- 沒有宣稱 `DS:8BF6h`／`DS:0A1Eh`／`DS:0A2Fh` 三個字串常數的內容
  （形狀上是路徑前綴與子目錄，但本支只讀不寫）。
- 沒有宣稱 `0723:01EDh`（開檔）第 4 個參數 `1` 是開檔模式還是重試次數。
- 沒有宣稱 `0723:0426h`／`048Eh`／`05BDh` 三支 resident helper 的介面
  （DOS 對側是 `0636:04FFh`／`0549h`／`0618h`，用途是「檔案存在？」與「用 `'.'` 切檔名」）。
- 沒有宣稱 `DS:7F0Dh`^ 的 1024 bytes 與 `DS:7F12h`^ 的 7745 bytes 各是什麼。
- 沒有宣稱 `DS:0A2A9h` 那 5 bytes 是什麼。
- 沒有宣稱 `DS:7F27h`／`7F28h`／`7F2Bh`／`7F2Ch`／`7F16h`／`7F2Fh` 的語意。
- 沒有宣稱 `near 0B4Fh`（進門與每個角色之後都問一次的閘）判什麼。
- 沒有宣稱 `near 1261h`（隊伍鏈後處理）與 `near 1061h`（`+0F7h < 80h` 的那支）做什麼。
- 沒有宣稱角色 `+0F7h`／`+126h`／`+143h` 三格的語意。
  （★ 位移本身已定案：spec 1076 看到 DOS 側用**同樣的三個位移**，
  ⇒ ＋1 的邊界收窄到 `143h` 與 `14Dh` 之間，這三格兩平台相同。）
★ DOS 對側是 `dos overlay-16:03748h`（spec 1076），十六個區塊同構，只有第 5 塊差 65 bytes。
