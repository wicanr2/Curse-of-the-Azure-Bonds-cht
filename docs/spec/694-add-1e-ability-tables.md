# 第六百九十四輪：AD&D 1e 的力量與敏捷調整表

狀態：`READY`。等級：`exact`（表格內容）／`strong inference`（欄位是哪一項屬性）。
日期：2026-08-14
位置：DOS `overlay-24` 的 `129Ah`、`13FDh`、`117Ah`、`120Ah`。

## `129Ah`：把力量壓成 0..30 的索引

```text
s := 角色^[11h]
if 0 <= s <= 17 then           回傳 s
elif s = 18 then
    p := 角色^[1Ch]
    p = 0        → 18          p = 1..50  → 19        p = 51..75 → 20
    p = 76..90   → 21          p = 91..99 → 22        p = 100    → 23
elif 19 <= s <= 25 then        回傳 s + 5             ← 19→24 … 25→30
```

`18/01`…`18/00` 這六階被攤成索引 18..23，19..25 接在後面成 24..30。整張表的
定義域是 0..30。

> ⚠ **有兩條路徑不會寫入回傳變數**：`s` 落在 0..25 之外（且不等於 18），以及
> `s = 18` 但 `p > 100`。這時回傳的是堆疊上的殘值。移植時要補預設值，
> 不能照抄成「其他情況維持前一個分支的結果」——原碼根本沒有前一個分支。

## `13FDh`：傷害調整，就是 AD&D 1e 的力量表

```text
if 角色^[125h] = 0 then 回傳 0
i := 129Ah(角色)
i = 1..2   → −2       i = 3..5  → −1        i = 6..15 → 0
i = 16     → +1       i = 17    → +1        i = 18    → +2
i = 19     → +3       i = 20..29 → i − 17    i = 30    → +14
```

## 力量有兩組欄位

`129Ah` 讀 `+11h` 與 `+1Ch`；而 `DONEWSTRENGTH`（`overlay-23`，**兩個平台
逐指令對讀過，位移相同**）比的是 `+10h` 與 `+1Dh`：

```text
if 新力量 > 角色^[10h] 或 (新力量 = 18 且 新百分位 > 角色^[1Dh]) then 更新
```

所以角色紀錄裡**力量與百分位各有兩個欄位**，一組給 `129Ah` 算傷害調整、
一組給 `DONEWSTRENGTH` 當比較基準。既有台帳把 `+10h`／`+1Dh` 記成「力量／
百分位」是對的，但那是**其中一組**，直接拿去算傷害會取到另一個值。

哪一組是目前值、哪一組是上限，這兩支函式定不出來，本輪不宣稱。

## 明確不宣稱

- `+11h`／`+10h`、`+1Ch`／`+1Dh` 各自是目前值還是上限。
- `+17h` 是否也有成對的第二個欄位。
- `+125h` 是什麼（`13FDh` 用它當閘門，為 0 時傷害調整一律 0）。
- 屬性在紀錄裡的整體排列——`+11h` 與 `+17h` 相差 6，但「六個屬性各一 byte 連續
  排」的假設**放不進** `+1Ch`／`+1Dh` 這兩個百分位，不要照這個假設推其他屬性。
