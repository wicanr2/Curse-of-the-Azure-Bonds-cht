# 第五百七十四輪：PC-98 的 Shift-JIS 判定與文字 VRAM 定址

狀態：`READY`（限本文件三處判定式與一處定址式）。日期：2026-08-14

## Shift-JIS 前導位元組判定（三處，逐指令相同）

`PC98-GAME.EXE` 的 `18D5Dh`、`18E44h`、`1977Eh` 是同一段判定：

```text
test al, 80h    → 無 bit7：單位元組（ASCII）
cmp  al, 0A0h   → 低於 A0h（即 81h..9Fh）：前導位元組
cmp  al, 0E0h   → 低於 E0h（即 A0h..DFh）：單位元組（半形片假名）
cmp  al, 0FDh   → 低於 FDh（即 E0h..FCh）：前導位元組
否則            → 單位元組
```

這是標準的 Shift-JIS 雙位元組判定。

**對繁中化的意義**：Big5 的前導位元組範圍是 `A1h..F9h`，與 Shift-JIS **不同**
——`A0h..DFh` 在 Shift-JIS 是單位元組（半形片假名），在 Big5 卻是前導位元組。
所以把 PC-98 版改成 Big5 時，這三處是必須改的判定點；沿用原判定會把大量
Big5 首位元組當成單位元組處理。

三處逐指令相同表示原始碼有三個各自 inline 的副本（或同一支被複製），
**改的時候三處都要改**。

## 第二族判定：上界不同

`169D9h`、`17172h`、`17D95h` 是另外三處，形狀不同且**範圍也不同**：

```text
cmp al, 81h  → 低於：非前導
cmp al, 9Fh  → 不高於：前導
cmp al, 0E0h → 低於：非前導
cmp al, 0F7h → 高於：非前導
否則         → 前導

**回傳用進位旗標，而且是 `clc` 代表前導**（`stc` 代表非前導）——與直覺相反，所以
值得寫死：

```asm
169E9  clc      ; 前導
169EA  retn
169EB  stc      ; 非前導
169EC  retn
```

方向由呼叫端確認，不是靠讀這兩行猜的。`16966h`（文字輸出核心，
[spec 648](648-pc98-text-draw-core.md)）在 `call sub_169D9` 之後是
`jb short loc_169A3`，而 `loc_169A3` 走的是**半形**路徑（`es:[di+1] := 0`、
`di += 2`、`cx -= 1`）。`jb` 在進位置起時跳，所以進位置起 ＝ 非前導。
結果以進位旗標回傳（stc = 前導，clc = 非前導）
```

**上界是 `F7h`，不是第一族的 `FCh`。** 也就是說 `F8h..FCh` 這五個前導位元組
在第二族會被判成非前導。原版是否有落在該範圍的字，本輪沒有查；但這代表
**兩族判定不可互相取代**，繁中化時要分別處理，而且六處都要改。

回傳方式也不同：第一族用 `retn` 的路徑分支，第二族用進位旗標。

## 文字 VRAM 定址

`199F5h`：

```text
di := ((di × 50h) + dx) × 2
```

`50h` ＝ 80 欄，`× 2` 是每格兩個位元組（字碼與屬性分平面時的字碼位移）。
`di` 是列、`dx` 是欄。

## 這份規格明確不宣稱

- 三處判定各自的呼叫端與用途（顯示、輸入、字串長度計算都可能）。
- 文字 VRAM 的屬性平面位址與段基址。
- DOS 版是否有對應判定：DOS 版是單位元組 code page，理論上不需要，
  但本輪沒有確認。
