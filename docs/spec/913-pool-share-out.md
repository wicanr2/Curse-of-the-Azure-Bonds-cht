## `+119h` ＝ 性別

`= 0` 走 `'his'`、`≠ 0` 走 `'her'`。**字串直接定名這一格**。

PC-98 把兩條路**合併成同一句** `'は自分の分け前を取り、隠した。'`——
日文的「自分の」不分性別，所以整個分支消失。

**這是「DOS 兩個只差一處的字串在 PC-98 併成一個」模式的第四個出現點**
（前三個：spec 841 的大小寫重複、spec 841／memorize、spec 893 的單複數）。
中文同理——「拿走並藏起自己的那一份」不必分性別。

## `+0F8h` 的低三位 ＝ 份數

`and 7` 之後同時加進「總份」與「人數」。所以：

- 符合條件的人：**份數同時算進分母與分子**。
- 不符合的人：分母 ＋1、分子不變。

七個公用池各自 `每份 := 池 div 人數`，然後扣掉 `每份 × 總份`。
**扣掉的部分沒有寫進任何角色的錢包**——本支只從池子扣，
訊息也只說「拿走並藏起來」。錢實際進了哪裡，本支沒有讀到。

⚠ `+0F8h` 的高 5 位沒有被讀（`and 7` 只取低三位），**最多 7 份**。

## 顯示只列出有份的人

第二個迴圈多一道 `p^[0F8h] > 0`，所以份數為 0 的人不佔一行。
每個人佔兩列（`列 += 2`）。

## PC-98 另外多一段熱鍵字串

結尾多 `指派(DS:0635h+3 → DS:0A335h, 0Ah)`——同 spec 865／871／877／
879／885／906 的模式。

## 池子的尺寸由 spec 917 閉合

`overlay-05:00A7Eh` 的逃跑分支做 `FillChar(DS:6F70h, 1Ch, 0)`——
**`1Ch` ＝ 28 bytes ＝ 七個 longint**，與本支 `for j := 0 to 6` 完全吻合。
那一支同時證明 `DS:6F8Ch` 是戰利品物品鏈。

## 明確不宣稱

- 沒有宣稱扣掉的錢進了哪裡。
- 沒有宣稱 `+0F8h` 高 5 位是什麼。
- 沒有宣稱「總份 ＝ 人數的一部分」這個算法是刻意還是筆誤
  （符合條件的人被算了份數而不是 1）。
