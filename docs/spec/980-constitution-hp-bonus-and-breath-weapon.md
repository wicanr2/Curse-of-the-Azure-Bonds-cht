# 980 — 體質的 HP 加成表（AD&D 1e 逐格全中）與 `DS:3EB9h` 的擲骰等級上限

- 證據等級：`exact`（兩支逐條讀完；`DS:3EB9h` 由 `dseg` 靜態 bytes 直接讀出；
  參數位置由原始 bytes 確認）
- 作法見 spec 783

## `dos overlay-23:017B8h`（103 條，`retf 6`）

⚠ IDA 的 `arg_2`／`arg_4`／`arg_6` 與它自己的命名慣例差 2。原始 bytes
（`8B 7E 06`／`3A 46 08`／`8A 46 0A`）證明三個參數在 `bp+6`、`bp+8`、`bp+0Ah`，
與 `retf 6` 一致。依 Turbo Pascal 由左至右推疊，宣告順序是
**`(職業 bp+0Ah, 等級 bp+8, 狀態 bp+6)`**。

```pascal
if byte[3EB9h ＋ 職業] <= 等級 then                 { 無號 }
    等級 := byte[3EB9h ＋ 職業] − 1;                 { 夾到擲骰上限 }

if 職業 = 4 then begin                               { 遊俠 }
    p := 遠指標 ss:[狀態 ＋ 8];
    if (p^[0E6h] = 0) or (p^[115h] <> p^[0E6h]) then inc(等級);
end;

體質 := ss:[狀態 − 1];
if 職業 in [2, 3, 4] then begin                      { 戰士 / 聖騎士 / 遊俠 }
    if      (體質 >= 0Fh) and (體質 <= 13h) then ss:[狀態 − 0Ah] += 等級 × (體質 − 0Eh)
    else if  體質 =  14h                    then ss:[狀態 − 0Ah] += 等級 × 5
    else if (體質 >= 15h) and (體質 <= 17h) then ss:[狀態 − 0Ah] += 等級 × 6
    else if (體質 >= 18h) and (體質 <= 19h) then ss:[狀態 − 0Ah] += 等級 × 7;
end
else begin
    if      體質 >  0Fh then ss:[狀態 − 0Ah] += 等級 × 2;      { 無號 }
    else if 體質 =  0Fh then ss:[狀態 − 0Ah] += 等級 × 1;
end;
```

### `DS:3EB9h` ＝ 各職業「還在擲骰」的等級上限

靜態 bytes：`0A 0F 0A 0A 0B 0C 0B 13`。程式用的是 **表值 − 1**：

| 職業碼 | 職業 | 表值 | 上限 ＝ 表值 − 1 | AD&D 1e |
|---|---|---|---|---|
| 0 | Cleric | 10 | **9** | d8 到 9 級 |
| 1 | Druid | 15 | **14** | d8 到 14 級 |
| 2 | Fighter | 10 | **9** | d10 到 9 級 |
| 3 | Paladin | 10 | **9** | d10 到 9 級 |
| 4 | Ranger | 11 | **10** | d8 到 10 級 |
| 5 | Magic-User | 12 | **11** | d4 到 11 級 |
| 6 | Thief | 11 | **10** | d6 到 10 級 |
| 7 | Monk | 19 | **18** | d4 到高階 |

職業碼的順序與 spec 857 由 `+75h` 定出的順序**完全相同**。
超過上限的等級**不再拿到體質加成**——這正是 AD&D 「name level 之後改成固定值、
不再擲骰、體質加成也停」的規則。

### ★ 體質加成逐格對上 AD&D 1e

| 體質 | 本作（非戰士） | AD&D 1e | 本作（戰士類） | AD&D 1e |
|---|---|---|---|---|
| ≤ 14 | 0 | 0 | 0 | 0 |
| 15 | **+1** | +1 | **+1** | +1 |
| 16 | **+2** | +2 | **+2** | +2 |
| 17 | +2 | +2 | **+3** | +3 |
| 18 | +2 | +2 | **+4** | +4 |
| 19 | +2 | +2 | **+5** | +5 |
| 20 | +2 | +2 | **+5** | +5 |
| 21–23 | +2 | +2 | **+6** | +6 |
| 24–25 | +2 | +2 | **+7** | +7 |

**十一格全中，兩欄都是。** 戰士類正好是職業碼 `2`（Fighter）、`3`（Paladin）、
`4`（Ranger）——與 AD&D「只有 warrior 類吃得到 17 以上的高階加成」一致。

⚠ **負的體質修正（AD&D 的 CON 3 → −2、4–6 → −1）在這一支裡完全不存在。**
本支只加不減。本規格不宣稱那是別處處理還是原版直接省略。

### ★ 遊俠的額外一個骰

職業碼 `4` 那一段把 `等級` **加 1** 再去乘體質加成——AD&D 的遊俠
**第 1 級就有 2d8**，多的那一顆骰同樣吃體質加成。條件是
`p^[0E6h] = 0` 或 `p^[115h] <> p^[0E6h]`（形狀上是「只有單職業／第一職業是遊俠時才給」），
本規格不宣稱那兩個欄位的意義。

### 狀態記錄的兩個欄位

`狀態` 是呼叫端堆疊框上的偏移，本支只碰三格：

| 位移 | 內容 |
|---|---|
| `−1` | 體質 |
| `−0Ah` | 累計的體質加成（**被 `+=`，所以呼叫端會對多職業各叫一次**） |
| `+8` | 角色遠指標 |

## `pc98 overlay-22:061ADh`（107 條，`retf 0Ah`）— 噴火

字串 `CS:619Eh`（14 bytes）＝ **`'は炎を吹いた。'`**（「噴出了火焰」）。

```pascal
<間接遠呼叫 DS:0A38Ch>(@DS:0A9D8h, 1, 41h);
目標 := 角色^[18Eh]^[0Ah];                       { 戰鬥狀態的目標欄 }
DS:0A03Dh := 目標;

if <overlay-23 entry#9>(64h, 1) > 32h then 離開;  { 1d100 > 50 就不噴 }
if <overlay-24 entry#33>(目標, 角色) >= 2 then 離開;
if 目標 = NIL then 離開;

DS:0A02Fh := 1;
DS:0A9D8h := <overlay-24 entry#34>(角色);
<overlay-24 entry#20>(角色, 名字 ＋ 'は炎を吹いた。', 1, 0Ah);
<overlay-24 entry#24>(17h);
<overlay-24 entry#25>(DS:7F16h × 7, 1,
                      x(目標), y(目標), x(角色), y(角色));   { entry#15／#16 取座標 }
<overlay-23 entry#20>(…, <overlay-23 entry#8>(0, 3, 目標, 2, 7, 目標));
```

★ **`1d100 ≤ 50` ＝ 50% 機率才噴**，而且要先通過 `overlay-24 entry#33` 的
距離／關係檢定（`< 2`）。這與 spec 842 的眼魔眼柄光線是同一種「怪物特殊攻擊」
寫法：先擲、再檢查、印訊息、放動畫、算傷害。

`DS:7F16h × 7` 這個乘 7 在 spec 760 記過（PC-98 `overlay-13:040B8h` 把 DOS 的
常數 `1Eh` 換成 `DS:7F16h × 7`）——**同一個式子在噴火這一支也出現**，
所以那是 PC-98 版通用的動畫參數，不是那一支的特例。

### ⚠ 間接遠呼叫

開頭的 `call dword ptr ds:0A38Ch` 是**經由變數的遠呼叫**（Turbo Pascal 的
procedural variable）。**靜態呼叫圖工具看不到這條邊**——
`docs/audit/overlay-call-graph.json` 這一類產物對這種呼叫是盲的。
本專案目前只在這裡遇到一次，記下來當作判讀陷阱。

### 中文化

`'は炎を吹いた。'` 是 overlay 內嵌常數。DOS 側的對應字串**不在
`dos overlay-22` 裡**（該模組的字串清單沒有 breath／fire），
所以噴火訊息兩平台不在同一個模組，中文化時要各自找。

## 明確不宣稱

- 沒有宣稱 `p^[0E6h]`／`p^[115h]` 是什麼。
- 沒有宣稱負的體質修正在哪裡處理。
- 沒有宣稱 `overlay-24 entry#33` 檢定的是距離還是別的關係。
- 沒有宣稱 `DS:0A38Ch` 那個程序變數指到哪裡、也沒有宣稱 `DS:0A02Fh`／
  `DS:0A9D8h` 的意義。
- 沒有宣稱噴火的傷害怎麼算（`overlay-23 entry#8`／`entry#20` 未讀）。
