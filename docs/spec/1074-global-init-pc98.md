# 1074 — PC-98 全域初始化：spec 1072 那四個存檔區塊就是在這裡配置出來的

- 證據等級：`exact`（PC-98 側 510 條逐條讀完，無匯出破洞）
- 作法見 spec 783

## `pc98 overlay-11:00048h`（`retf`，無參數）

原本待解讀。範圍 `48h`..`500h`。整支是一長串配置與初值設定，只有兩個計數迴圈。

## 一、清畫面與提示

```pascal
<near 07CDh>(DS:8BF2h);
DS:8BE5h := 0（word）;  DS:8BE7h := 0;  DS:8BE9h := 0;  DS:0BE40h := 0;
FillChar(A000h:0000h, 0FA0h, 0);      { 文字碼平面 }
FillChar(A200h:0000h, 0FA0h, 0);      { 屬性平面 }
印訊息(0, 18h, 0Ah, 0, '読みこみ中です');   { 0418:0D17h }
```

★ `0FA0h` ＝ 4000 ＝ 80 × 25 × 2 ⇒ **PC-98 文字 VRAM 的兩個平面整片清掉**。
★ 「読みこみ中です」（14）與 spec 1029／1072 是同一句（各模組各有一份常數）。

## ★★★ 二、七塊堆積配置：與 spec 1072 的存檔區塊一一對上

用 `081F:0217h`（配置，先把遠指標清 NIL 再配）：

| 全域 | 長度 | spec 1072 的存檔區塊 |
|---|---|---|
| `DS:7F05h` | `800h` ＝ 2048 | **第 2 塊（bank 0）** |
| `DS:7F09h` | `800h` ＝ 2048 | **第 3 塊（bank 1）** |
| `DS:7F0Dh` | `400h` ＝ 1024 | **第 4 塊** |
| `DS:7F12h` | `1E41h` ＝ 7745 | **第 5 塊** |
| `DS:9622h` | `0B10h` ＝ 2832 | 不在存檔裡 |
| `DS:0A29Ch` | `924h` ＝ 2340 | 不在存檔裡 |
| `DS:0A2A0h` | `400h` ＝ 1024 | 不在存檔裡 |

> ★★★ **四個長度分毫不差**。spec 1072 是從讀檔端看到這四塊，
> 這裡是從配置端看到同樣四塊——**兩邊獨立對上，存檔版面定案**。
> ⇒ 另外三塊（`9622h`／`0A29Ch`／`0A2A0h`）是**執行期資料，不進存檔**，
> remake 不必序列化。

配置完之後四塊全部 `FillChar(…, 0)`，然後：

```pascal
bank0^[1CCh] := 1;          { ★ 場景型態旗標的初值，spec 1041／1072 }
```

## 三、圖片結構配置（`02A8:0180h(a, b, c, d, @圖)`）

| 目的 | 參數 |
|---|---|
| `DS:7F56h` | `(0A8h, 2Ah, 1, 0)` |
| `DS:7F5Ah` | `(58h, 16h, 1, 0)` |
| `DS:9660h` | `(8, 2, 1, 0)` |
| `DS:0BE08h` | `(8, 2, 1, 0)`，配完 `FillChar(圖^[17h], 圖^[11h], 0FFh)` |
| `DS:964Ch ＋ i × 4`，i ＝ 0..4 | `(8, 2, 46h, 1)` — **五張** |
| `DS:0A2BAh` | `(10h, 16h, 1, 1)` |
| `DS:0A2BEh` | `(18h, 6, 1, 1)` |
| `DS:0A2C2h` | `(30h, 16h, 1, 1)` |

## ★★★ 四、E000h 平面被當成一張圖片緩衝

```pascal
FillChar(DS:9664h, 8, 0);  FillChar(DS:973Ch, 4, 0);
DS:9664h := Ptr(0E000h, 0000h);          { ★ 直接指向 VRAM 第四平面 }
圖^[0]   := 18h;    { 寬 24 }
圖^[2]   := 6;      { 高 6 }
圖^[8]   := 30h;
圖^[11h] := 1B0h;   { 432 }
圖^[13h] := NIL;  圖^[15h] := NIL;
```

> ★★★ `1B0h` ＝ **432 ＝ 24 × 6 × 3**，正好對上 spec 880／overlay-35 記的
> 「`+11h` ＝ 寬 × 高 × 3」。⇒ **圖片結構的 `+0` 是寬、`+2` 是高**（本規格新增），
> 而且**三個色彩平面**的說法在這裡第二次獨立成立。
>
> ★★★ **這張圖的像素資料直接落在 `E000h` 段**。PC-98 在 8 色模式下
> 第四張（亮度）平面閒置，原作把它當成免費的 32 KB 緩衝用。
> ⇒ remake 若照抄記憶體版面會踩空；這是**平台專屬的省記憶體手法**，
> 要在移植層換成一般配置。

## 五、螢幕列首偏移表

```pascal
for i := 0 to 0C7h do word[DS:8836h ＋ i × 2] := i × 50h;
```

★ `50h` ＝ 80 bytes／列、`0C8h` ＝ 200 列 ⇒ **640 × 200 的列首查表**。
（`[di−77CAh]` 就是 `DS:8836h`。）

## ★★★ 六、三組牆面參數的初值：與 spec 1072 的存檔第 9..14 塊同一張表

```pascal
FillChar(DS:0A2A9h, 5, 0);
DS:0A2A9h := 7;  DS:0A2AAh := 0Dh;  DS:0A2ABh := 0;
FillChar(DS:0A81Ah, 3, 1);
DS:0A2AEh := 0;   DS:0A2B0h := 1;                  { i ＝ 1 }
for i := 2 to 3 do begin
    word[DS:0A2AAh ＋ i × 4] := 0FFFFh;            { ＝ 0A2B2h、0A2B6h }
    word[DS:0A2ACh ＋ i × 4] := 0FFFFh;            { ＝ 0A2B4h、0A2B8h }
end;
```

> ★★★ **`DS:0A2AEh` 起的三組 (word, word) 就是 spec 1072 存進存檔的那 12 bytes**，
> 初值是「第 1 組 ＝ (0, 1)、第 2／3 組 ＝ (`FFFFh`, `FFFFh`)」。
> `FFFFh` ＝ 未使用 ⇒ spec 1072 那裡的 `if word > 0 then 載入 WALLDEF`
> 判斷式，擋掉的就是 `FFFFh`（有號負值）。**兩支互相印證**。

## 七、其餘初值

```pascal
DS:0BDF0h := 0;   DS:7F2Ch := 1;   DS:7F2Bh := 1;   DS:7F16h := 4;
DS:8B5Ah := 1;    DS:0BE01h := 0;  DS:7F21h := 8000h（word）;  DS:7F29h := 0;
DS:0A2BAh/0A2BEh/0A2C2h/0A2C4h… 先整組清 NIL 再配置（見上表）;
FillChar(DS:964Ch, 14h, 0);
```

★ `DS:7F2Bh`／`7F2Ch`／`7F16h` 正是 spec 1072 讀檔後從 bank 0 重算的那三格
——**這裡是它們的出廠值**。

## 八、載入固定素材

```pascal
<overlay-35 entry#2>(0CAh, 4);          { 8×8 圖磚組 }
<overlay-35 entry#2>(0CBh, 0);
<resident 02A8:002Ch>('sky', 0FAh, 1, 0Dh, @DS:0A2BAh, 1);
<resident 02A8:002Ch>('sky', 0FBh, 1, 0Dh, @DS:0A2BEh, 1);
<resident 02A8:002Ch>('sky', 0FCh, 1, 0Dh, @DS:0A2C2h, 1);

開檔('ITEMS', DS:485Ah, 0, @檔案DS:7B02h);   { 0723:01EDh，回傳存 DS:7AD6h }
Reset(檔案, 1);
Seek(檔案, 2);                                { ★ 跳過 2 bytes 標頭 }
BlockRead(檔案, DS:8D84h, 810h, DS:9620h);    { ★ 2064 bytes }
Close(檔案);

<overlay-22 entry#10>();   { spec 1071 的分派表初始化，101 筆 }
<overlay-12 entry#1>();    { spec 705 的效果分派表，141 筆 }
<near 0508h>();
```

> ★★ **`ITEMS` 檔跳過 2 bytes 標頭後讀 `810h` ＝ 2064 bytes 進 `DS:8D84h`**。
> `810h` ＝ 2064 ＝ 16 × 129，也 ＝ 8 × 258——本規格不宣稱它的筆數與筆距。
> ★ `'sky'` 三張（編號 `0FAh`／`0FBh`／`0FCh`），尺寸各 `(10h, 16h)`／
> `(18h, 6)`／`(30h, 16h)`。
> ★ 開檔的參數順序 `(檔名, 提示句, 模式, @檔案)` 與 spec 1072 的
> `('…savgam….dat', 提示, 1, @檔案)` 一致——**兩支對照可以定案這個順序**。

## 明確不宣稱

- 沒有宣稱 `near 07CDh(DS:8BF2h)` 與 `near 0508h` 做什麼。
- 沒有宣稱 `02A8:0180h` 五個參數的語意（只由 `E000h` 那組推出前兩個是寬與高）。
- 沒有宣稱 `02A8:002Ch` 六個參數的語意。
- 沒有宣稱 `overlay-35 entry#2` 的 `(0CAh, 4)`／`(0CBh, 0)` 哪個是組、哪個是編號
  （DOS 側簽名是 `(組, 編號)`，但兩個值都在合理範圍內）。
- 沒有宣稱 `ITEMS` 那 2064 bytes 的版面。
- 沒有宣稱 `DS:9622h`（`0B10h`）／`DS:0A29Ch`（`924h`）／`DS:0A2A0h`（`400h`）
  三塊各裝什麼。
- 沒有宣稱 `DS:8BE5h`／`8BE7h`／`8BE9h`／`0BE40h`／`0BDF0h`／`8B5Ah`／
  `0BE01h`／`7F21h`／`7F29h`／`0A81Ah` 的語意。
- 沒有宣稱 DOS 側的對應函式是哪一支。
