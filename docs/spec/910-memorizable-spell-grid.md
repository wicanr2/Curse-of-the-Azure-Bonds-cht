# 910 — 可記憶法術數量表：`+12Ch` 起 3 × 5 的格子

- 證據等級：`exact`（PC-98 側逐條讀完；DOS 側尾端有反組譯錯位，由 PC-98 校正）
- 作法見 spec 783

## `overlay-15:005CAh` ↔ `overlay-15:005CCh`（兩平台各 207 條）

`retf` ＝ 無參數。回布林（有沒有東西可顯示）。

| | DOS | PC-98 |
|---|---|---|
| 標題 | `'can memorize:'` | `'は次の数だけ呪文を記憶できる。'` |
| 第 0 列 | `'    Cleric Spells:'` | `'　　　僧侶魔法：'` |
| 第 1 列 | `'     Druid Spells:'` | `'ドルイド僧魔法：'` |
| 第 2 列 | `'Magic-User Spells:'` | `'　魔法使い魔法：'` |

```pascal
有 := 0;
for r := 0 to 2 do begin
    這一列有 := 0;
    for c := 1 to 5 do begin
        格[r*3 ＋ c*9] := <far 1522h>(<本模組 0282h>(r, c, @緩衝));  { 上限 2 }

        end else

if 有 = 0 then begin 結果 := 0;  離開 end;

訊息(名字 ＋ 'can memorize:');   <far 1554h>(0, 0Ah);

列 := 3;
for r := 0 to 2 do begin
```

## `+12Ch` 起 ＝ 每個施法類別 × 五個法術等級

索引是 `12Ch ＋ 列 × 5 ＋ 欄`，列 0..2、欄 1..5，
所以實際用到的是 **`+12Dh`..`+13Bh` 共 15 格**。

| 列 | 施法類別 |
|---|---|
| 0 | **Cleric**（僧侶） |
| 1 | **Druid**（ドルイド僧） |
| 2 | **Magic-User**（魔法使い） |

欄 1..5 ＝ **法術等級 1..5**。每一格是這個角色**該等級能記幾個**。

三列的標題在 DOS 用空白補到同寬（`'    Cleric Spells:'` 前面四格、
`'     Druid Spells:'` 五格、`'Magic-User Spells:'` 零格），
PC-98 用全形空白做同一件事（`'　　　僧侶魔法：'`）——**兩邊都在對齊冒號**。

這一格緊鄰 spec 907 的 `+12Bh`（職業遮罩）。

## 顯示只佔五欄、每欄寬 3

格子字串上限是 **2 個字元**，欄位從 `13h ＋ 1` 開始、每欄 `+3`。
所以「能記幾個」最多兩位數；五欄佔 15 個字元。
沒有東西可記的列**整列不畫**（`有列[r] = 0` 就跳過），列號才會往下推。

## ⚠ DOS 尾端反組譯錯位

DOS 從 `0790h` 起被解成 `inc si` / `mov ds:8003h, ax` / `movsw` 之類，
PC-98 同一段是正常的迴圈收尾：

```asm
add [bp+var_5D], 3          ; 欄 += 3
cmp [bp+var_5C], 5
jnz 內圈
inc [bp+var_5E]             ; 列 ++
cmp [bp+var_5B], 2
jz  結束
jmp 外圈
mov al, [bp+var_5F]         ; 回傳「有沒有東西」
```

**這是第四支由 PC-98 校正 DOS 錯位的函式**（前三支見 spec 873／884／…）。
單看 DOS 會以為函式尾端寫進了 `DS:8003h`。

## 明確不宣稱

- 沒有宣稱 `本模組 0282h(列, 欄, @緩衝)` 怎麼算出那個數字。
- 沒有宣稱為什麼只顯示 5 個法術等級（AD&D 的牧師到 7、法師到 9）。
- 沒有宣稱格子陣列 `r*3 ＋ c*9` 那個位移算法的容量。
