# 758 — `+0F7h` 的存取閉環，以及 VROOMM 區塊搬移

- 證據等級：`exact`（逐條讀完；顯示位移可疑者回查原始 bytes）

## `+0F7h`：bit 7 是旗標，低 7 位是「一半」

三支互相咬合，把這個欄位的編碼補完：

**寫入端** `overlay-02:2DA9h`（DOS，`retf`，不收參數）：

```pascal
<呼叫>(2);
a := <呼叫>(1);   <呼叫>(a);
b := <呼叫>(2);
b := (b div 2) or 80h;              { 有號除法 }
DS:6506h^[0F7h] := b;               { DS:6506h 是「目前角色」 }
<呼叫>(DS:6506h);  <呼叫>(DS:6506h);
```

**讀取端** PC-98 `overlay-09:13A5h`：

```pascal
if p^[0F7h] <= 7Fh then 離開;                   { bit 7 沒設就不做 }
DS:0A03Ch := (p^[0F7h] and 7Fh) * 2;            { 還原成原值 }
if DS:0A03Ch > 66h then DS:0A03Ch := 0;
```

`div 2` 存、`* 2` 讀，**bit 7 當作「這個值有效」的旗標**。上限 `66h`（102）與
除以 2 的關係一致：低 7 位最大 `7Fh` ＝ 127，乘 2 是 254，超過 102 就當 0。

**計數端** `overlay-21:05F9h`（spec 756）數的是 `+0F7h = 0` 或 `= 0B3h` 的成員；
`0B3h` ＝ `80h or 33h`，也就是「旗標已設、原值 ＝ 102」——正好落在上面那個上限
的邊界上。

## `overlay-13:0124h`（兩平台）— 加成後夾制再乘 2

`retf 4`：

```pascal
v := p^[1A5h];                                 { PC-98：+1A6h }
if p^[197h] = 0 then v := v + DS:4F9Dh^[6E4h]; { 陣營 0 才加這個修正 }
DS:6F9Ah := 1;
if (v < 1) or (v > 60h) then v := 1;           { 無號，夾成 1 }
DS:6F96h := (v * 2) and 0FFh;
<呼叫>(p, 12h);
DS:6F9Ah := 0;
結果 := DS:6F96h;
```

`60h` ＝ 96，乘 2 之後 192，塞得進 byte。注意**超出範圍不是夾到邊界而是設成 1**。
`DS:6F9Ah` 是包住那個呼叫的旗標（進去前設 1、出來設 0）。PC-98 對應
`DS:0A034h` / `DS:0A030h`。

## `overlay-10:09A8h`（DOS）／`099Ch`（PC-98）— 在地圖上補兩格

`retf 6`，三個參數只用後兩個（`x` 在 `[bp+8]`、`y` 在 `[bp+0Ah]`）：

```pascal
if x < 31h then 地圖[y * 50 + (x + 1)] := 40h;
if (y < 18h) and (x < 31h) then 地圖[(y + 1) * 50 + (x + 1)] := 41h;
```

`31h` ＝ 49、`18h` ＝ 24 就是 50 × 25 格陣的最後一欄／列索引，**第三次獨立
印證**格陣尺寸（spec 749 由 `FreeMem 4E9h`、spec 756 由 `FillChar 4E2h`）。
比較是有號的。第一個參數整支沒讀。

## `overlay-16:0020h`（兩平台）— C 字串轉 Pascal 字串

```pascal
n := 0;  while p^[n] > 0 do inc(n);      { 無號，找 0 結尾 }
Move(p^, 緩衝, n);
長度 byte := n;
StoreString(長度 byte 起, 目的, 0FFh);
```

緩衝區前一個 byte 就是長度 byte（`var_101` 與 `var_100` 相鄰），所以組出來就是
一條 Pascal 短字串，上限 255。這是 PC-98 `overlay-18:1951h`（spec 754，Pascal →
C）的反向。

⚠ `retf 4` 只宣告 2 個 word，但函式讀了 `[bp+0Ah]` 的目的指標——**超出參數區**，
是既有記錄的「堆疊殘留當引數」慣用法。原始 bytes 已確認（`C4 7E 0A` ＋
`CA 04`），不是匯出誤差。

## `overlay-29:06E1h`（DOS）／`05F9h`（PC-98）— 兩種畫法的分岔

`retf 6`：

```pascal
if 第一個參數 <> 0 then begin
    本模組 0091h(y, x, 遠指標@DS:726Fh);
    本模組 00B3h(y, x, 遠指標@DS:7274h);      { spec 754 那支 }
end else
    本模組 000Ch(y, x, 0, 遠指標@DS:726Fh);
```

`DS:726Fh` 與 `DS:7274h` 正是 spec 754 記錄的兩個「哨兵 byte ＋ 4-byte 指標」
結構（哨兵在 `726Eh` / `7273h`）。這裡確認了那 4 bytes 確實當遠指標用。

## `overlay-19:35F1h`（DOS）／`3658h`（PC-98）— 與 `3656h` 成對的判斷

前三個條件與 spec 756 的 `overlay-19:3656h` 逐字相同；差別在最後一項：這一支
不是比 `p^[191h] > 0`，而是呼叫 `<overlay>(輸出參數, 8Ch, p)` 並要求它回 0。
兩支是同一組條件的兩個變體。

## PC-98 `overlay-17:0115h`

`retf`，不收參數：隊伍鏈頭 `DS:9598h` 為 NIL 就離開；`DS:7F05h^[3FAh]` 非 0 也

## `START.EXE:1A495h` — 搬移 overlay 區並改寫 stub

```
新段 := word_2096C;  舊段 := es:10h;  es:10h := 新段
沿 [bp+0] 的鏈把每個 [bp+4] 等於舊段的節點改成新段
把 es:8 個 bytes 由舊段複製到新段（std，反向搬，處理重疊）
cx := es:0Ch;  di := 23h
重複 cx 次：stosw（寫入新段）；di += 3      { 每格前進 5 }
```

配合 spec 757 的 `1A4E3h`（每格 5 bytes、`CD 3F` ＋ 3 bytes），可以確定
**stub 陣列從 `+20h` 起、每格 5 bytes、格數在控制區塊的 `+0Ch`**。

但兩支寫的位置有重疊：`1A4E3h` 寫 `+0..+4`（`CD 3F`、2 bytes 描述子、1 個 0），
`1A495h` 寫 `+3..+4` 的 word。**本輪不宣稱 stub 內部三個 byte 的欄位切法**——
兩支的寫法無法在不做動態觀察的情況下調和。
