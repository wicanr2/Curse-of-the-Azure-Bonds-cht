# 讓新一代華文玩家享受 Golden Box：重製與中文化設計指南

Golden Box 的魅力不只在 AD&D 規則，也在「閱讀、想像、探索、戰術」
反覆交替的節奏。重製的目的不應是把老遊戲套上一層現代選單，而是降低
操作與語言門檻，同時保留原作要求玩家閱讀、判斷與自行想像的空間。

## 1. 先保存原作，再談美化

畫面至少應有兩種可切換的 presentation：

- **原版忠實模式**：依 DOS 實機畫面量測版面，以原始素材、EGA 色盤、
  邊框像素、最近鄰整數放大重建。這是行為與視覺驗收基準。
- **美化模式**：沿用相同資料與 layout contract，改善材質、動態效果與
  可讀性；不能改寫規則、事件條件或把原版資產永久取代。

兩種模式共用引擎與 JSON。美術 theme 只決定 renderer，不應把城鎮名稱、
怪物、事件或戰鬥配置 hardcode 在畫面程式裡。

## 2. 640×480 不是把所有東西放大

DOS 原版的 320×200 圖像可用 nearest-neighbour 2× 呈現，但 640×480 多出的
解析度應用來改善中文，而不是把每個字放到 24×24：

- 原始圖像：整數 2×，避免模糊與 AI 補點破壞像素風格。
- 一般中文：倚天 16×15 點陣字，必要時水平加粗一像素。
- 標題與強調：才使用約 24px 字級。
- 數值、隊伍名單、戰鬥狀態與指令列：一律採緊密字級。
- 行距約 18–20px，讓一個敘事區仍能容納足夠句子。

PC-9801 日文版的 640×400 畫面證明，高解析度的價值是讓雙位元組文字清楚
而密集，不是讓字占滿畫面。它可作為華文排版密度參考；DOS 版仍是邊框、
區塊比例與素材位置的主要 oracle。

## 3. 文字很多的遊戲，困難在閱讀流程

只翻譯字串不等於完成中文化。閱讀介面需要：

- 依標點與語意斷行，不以固定 byte 數切斷 Big5/Unicode。
- 長文分頁，每頁保留明確的「繼續」提示與頁數。
- 可調整逐字速度，並允許一鍵立即顯示整頁。
- 對話選項與敘事分層；玩家不能因翻頁誤選答案。
- 人名、地名、法術、裝備採一致詞彙表，必要時保留英文索引。
- 手札、日誌與劇情提示可重讀，避免要求玩家抄寫整段文字。
- 重要規則詞可開啟簡短說明，但不在正文中塞入長篇教學。

翻譯 JSON 應保留 stable ID、原文、繁中、來源 block/offset、譯註與狀態。
這讓校對、重新翻譯與其他 Golden Box 遊戲共用工具成為可能。

### 攻略也可以像小說

Golden Box 的優秀攻略常把路線、人物與戰役寫成一篇冒險紀行。中文知識庫
應同時保留三個閱讀層次：

- **冒險紀行**：以流暢敘事重述旅程，保留氣氛、人物動機與世界背景。
- **逐區攻略**：提供地圖座標、事件條件、戰鬥與寶物，方便卡關時查閱。
- **無雷提示**：只給下一步方向與規則提醒，不提前揭露劇情。

翻譯時不能把有文學性的段落全部改成命令清單。攻略條目應標示章節、地點、
劇透程度、對應 journal entry 與遊戲資料 ID，讓讀者能在「讀小說」和
「查答案」之間自由切換。

## 4. 讓老規則容易接近，而不是偷偷改掉

年輕玩家通常不熟悉 THAC0、AC 越低越好、記憶法術與回合制移動。適合的
改善方式是「可選的解釋層」：

- 第一次遇到規則時顯示短提示，之後可在百科查閱。
- 同時顯示原始數值與白話結果，例如「AC 2（較佳）」。
- 提供快捷鍵提示、滑鼠/手把映射與可重綁按鍵。
- 戰鬥預覽可說明移動成本、射程與有效目標，但結果仍由原版規則決定。
- 快速存檔、自動存檔與文字速度是可用性改善，不是降低遊戲難度。

若提供重新平衡、導航輔助或降低難度，必須是獨立選項，且忠實模式預設
不啟用。

## 5. 圖像應填滿原作指定的舞台

第一人稱場景、事件圖、人物 HEAD/BODY 與戰鬥 sprite 都有不同座標規則。
renderer 應先裁切到 panel，再以 cover/contain contract 放置：

- 原作要求整格場景時用 **cover**：等比例放大並裁掉溢出，不留大黑邊。
- 必須看到完整圖像時用 **contain**：允許 letterbox，但邊框仍保持原位。
- HEAD/BODY 是分層素材，頭像不能縮進身體框或任意置中。
- 戰鬥小人依 24×24 原生格與 footprint 定位，不能用一般圖片置中邏輯。

## 6. 知識庫與引擎的分工

共用 `golden-box-remake-engine` 應保存：

- DAX、GEO、ECL、SAVE、字型與圖片 codec。
- 版面座標、戰鬥格、角色規則及可重用 renderer contract。
- JSON schema、資料驗證器與 deterministic test fixtures。

遊戲 repo 保存：

- 本作原始檔的 hash/來源說明（不任意散布受版權保護的完整資料）。
- 本作事件、地圖、怪物與翻譯 JSON。
- 每項反組譯結論的證據、地址、截圖與 confidence。
- 原版對照、remake 實機截圖與尚未完成的差異。

## 7. 完成標準

一個畫面不能只因「能顯示」就算完成。每個 milestone 至少要回答：

1. 原版 DOS/PC-98 或反組譯證據是什麼？
2. 哪些部分 exact、nearby、layout-only 或仍是假設？
3. 中文在真實長文與最長名稱下是否仍可讀？
4. 鍵盤操作能否完成一段真正玩家路徑？
5. 截圖是否同時顯示原作魅力與重製的可讀性？

這樣做，重製才不只是懷舊截圖，而是一條讓沒接觸過 DOS、也不熟 AD&D
的華文玩家真正走進故事的路。
